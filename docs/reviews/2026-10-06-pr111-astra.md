## Review of #111 (Astra, 2026-10-06)

Verdict: GO with changes

No Critical/High findings. Reviewed commit `e36fa1f` against the revised scope in [PR #112](https://github.com/ekaynac/auto-dev-cycle/pull/112).

1. **Startup order and refusals — PASS with M1 below.** Resource groups are schema-validated before decoding can discard fields; unsupported semantics fail closed. State-directory type, owner and permissions are checked before and after locking. The lock precedes both stores; full-chain/trusted-head verification and capacity-history checking precede system-actor creation and pending-effect transitions. Failure cleanup closes the store before releasing the lock; readiness follows successful startup. `CheckHistory` precedes domain writes, although opening stores already performs initialization and blob-temp cleanup. Projection comparison and version rejection remain PR 1b obligations.
2. **`SubmitTrusted` — safe in the current call graph; narrowing recommended.** Its sole production caller creates the system actor. Validation, transactional append and projection remain intact, including the projector’s first-actor/self-creation restriction. No listener exposes it, and the daemon’s store field is private. However, the exported method itself does not enforce its documented restriction; see M3.
3. **Replay before authorization — acceptable for this PR.** I reproduced ordinary `Submit` replaying the startup result under refuse-all: `Apply` never runs and the log does not advance. Keep authenticated replay in PR 2b, strictly before listeners: HTTP authentication plus transactional identity recheck **before the cached-result branch**. Random idempotency keys are not authorization. Comments should say “every **new** command is refused.”
4. **Reasons and exits — mappings correct; diagnostics need refinement.** Configuration errors return 64; `could_not_run` returns 2; `failed/log_integrity_broken` returns 1; clean shutdown returns 0. Lock contention correctly uses `controller_already_running`. See M2 and L1 concerning reason semantics.
5. **Size — acceptable under D41.** Confirmed 493 added-plus-deleted handwritten non-test lines. The documented cohesive-package justification is reasonable. Keep the resource-group loader with startup validation. Deferring unused `--run-dir` would be sensible housekeeping, but neither extraction is required for approval.

**Medium**

- **M1 — Direct `Start` callers can silently bypass a supplied trusted head.**  
  [internal/daemon/config.go:76](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-daemon/internal/daemon/config.go:76) validates directories and groups, but trusted-head validation exists only in `LoadConfig`. I confirmed that `Config{TrustedHead: &eventstore.Head{Seq: -1, Hash: "invalid"}}` passes validation and starts successfully: verification handles zero and positive sequences, silently ignoring negative ones. The CLI rejects this input, limiting present exposure.  
  **Fix:** validate nonnegative sequence and hash syntax in `Config.Validate`; test direct `Start` rejection before state-directory creation.

- **M2 — Capacity read/decode failures are misreported as historical incompatibility.**  
  [internal/daemon/startup.go:41](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-daemon/internal/daemon/startup.go:41) captures every `CheckHistory` error while returning nil from the view callback. Consequently, SQL/read/JSON errors receive `ambiguous_state` and the definitive claim that a lease predates capacity wiring. A malformed lease projection reproduced exactly that diagnostic. Startup still refuses.  
  **Fix:** give historical incompatibility a distinguishable error type/sentinel; map only that error to the historical refusal, and propagate read/decode failures as `store_unreadable`.

- **M3 — The trusted submission API is broader than its sole authorized operation.**  
  [internal/eventstore/writer.go:239](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-daemon/internal/eventstore/writer.go:239) accepts arbitrary commands and callbacks with authorization disabled. Its startup-only restriction is documentation, not an enforced boundary. This is nonblocking because no current public request reaches it.  
  **Fix:** expose a constrained initialization operation or startup-scoped capability, retaining the private shared submission implementation. Simply making the method unexported would require restructuring its cross-package caller. Add tests rejecting unrelated operations through the narrowed interface before listener integration.

**Low**

- **L1 — Startup uses broaden existing reason definitions without updating their contracts.**  
  [internal/daemon/daemon.go:51](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-daemon/internal/daemon/daemon.go:51) uses `check_unloadable` for registry loading, while its registered description concerns source-code checks. Likewise, `ambiguous_state` describes duplicate live records, but startup also uses it for missing system identity and incompatible capacity history.

## Review of b94e553 on #113 (Astra, 2026-10-06)

Verdict: GO with changes

No Critical/High findings.

- **Medium — refused startup append: FIXED for valid stores.** Restoring unconditional `markPending` makes the regression test fail. Normal writes cannot create effects without events/commands, and Bootstrap checks those tables atomically. Tampered stores expose the gap below.
- **Medium — replay classification: FIXED in implementation.** All six Tx SQL methods correctly distinguish storage faults from projector refusals, including translated errors. Validation errors and missing records do not become storage faults. Restoring the old daemon mapping makes its test fail.
- **Low — composition coverage: FIXED.** Seeding still uses production composition, but independent record counts and drift assertions prevent circular success. Removing identity, grants, leases, capacity, or ledger individually makes tests fail.

**New findings:**

- **Medium — “fresh” does not guarantee an empty effects table**, `internal/daemon/daemon.go:104`, `internal/eventstore/writer.go:262`. I reproduced successful startup with an orphan pending effect in an otherwise empty initialized store; the effect remains pending. This requires direct database tampering or an inconsistent restore, rather than ordinary writes/crashes. Bootstrap checks only events and commands; verification/replay never checks effects. **Fix:** require `effects` to be empty inside Bootstrap’s transaction, before appending the actor, and add this regression case. A retained nonempty trusted head detects history truncation, but does not establish this effects invariant.

- **Low — storage-fault tracking lacks regression protection**, `internal/eventstore/rebuild_test.go:259`. Disabling **all** `Tx.fault` recording leaves both package suites green: the test’s cancellation independently prevents `ErrReplayRefused`. **Fix:** inject non-cancellation SQL failures and assert they remain operational errors, including when the projector translates the error. My in-memory probes passed for all six methods and failed with tracking disabled.

`make ci` passed; local lint skipped unavailable shellcheck. Both requested race suites passed outside the sandbox using the pinned Go toolchain on PATH. Mutation/probe tests used anonymous-memory overlays; no source files changed, and the working tree is clean.
