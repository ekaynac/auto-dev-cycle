### High: BLOCKING

**H1. Restarting without `--sandbox-root` leaves work already placed with no hold, and its lease is never released.** `internal/daemon/wiring.go:111`, `internal/reconcile/reconcile.go:778-790`
- **Cause:**
  - `no_sandbox` is raised only by `Place`, for a node not placed yet.
  - With no runner, the loop still decides `Run` for a granted lease, `Accept` and `Gate` for claimed nodes, and `Ending`/`Reseal`.
  - `Executor.Run` turns each into `errNothing` when the Runner or Acceptor is nil, so nothing is logged.
  - The start sweep does not run without a runner either (5c-2c L4).
- **Probe:** a start with a sandbox root places the build (lease `granted`), then adcd restarts with no runner. After 12 passes:
  - the build is still `claimed` with no hold;
  - the lease is still `granted`, holding its reservation;
  - the log says nothing.
  - Read from the code, a claimed accept or gate behaves the same.
- **Scope:** this is exactly the configuration #226 entry 171 was opened for, and adcd's own start line says "never stuck without a hold".
- **Fix:** with no runner, decide what a runner would have run, and hold it instead:
  - a granted lease: release it, then hold the build `no_sandbox`;
  - a claimed accept or gate: hold it `no_sandbox`.
  - Use `noSandbox` in the executor, so `Run`, `Accept`, `Gate`, `Reseal` and `Ending` raise the hold instead of `errNothing`.
  - Or refuse a start without `--sandbox-root` when the store holds live leases or claimed nodes.
  - Add the probe as a row: grant, restart without a sandbox root, held, lease released.

**H2. With `launch` active and `review` inactive, as the plan intends (§3: "Review stays inactive on its P31 Pending"), every task stops after its gate with no hold. No later task is ever admitted.** `internal/reconcile/reconcile.go:575-580`
- **Cause:** `Reviewable` is computed only when `Gates.Reviews` is true. So with review inactive, a completed gate records no review, and nothing else acts on it:
  - `CandidateGo` is never true, so there is no `task.done`;
  - no hold is raised.
- **Probe:** `TestLaunchThroughAdcdsOwnLoop`'s world, then 12 more passes after the gate completes. The task is admitted, the card shows `ready` with the admitted badge, there are 0 holds and no `ending_blocked`, and the start log's "review stays inactive" is the only trace.
- **Fix:** make the wait visible and clearable, reusing what exists:
  - Hold the completed gate's task on a registered hold: either a `review_inactive` hold with signal `capability: review`, cleared when a start derives review active (the clearer pattern `no_sandbox` uses), or the existing `reviewer_unavailable` on a recorded review node, whose clearer `reviews.Unheld` already exists.
  - Add it to #400's table.
  - Add a row for the probe above.
  - Or state in the plan and the PR that launch is not activated before review, and gate `launch` on review in the table.
