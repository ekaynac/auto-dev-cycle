## External review of #233 (Astra, 2026-10-13)

Verdict: NO-GO

Reviewed head `417890e`, the diff against `origin/main`, the PR description including Round 1, issue #226 and the scope documents. Read-only; no tests or exploit reproductions run. **H1 blocks.**

1. **High — Local-path validation still permits run-written repositories.** `internal/sandbox/git.go:99`

   `filepath.Clean` runs before symlink resolution, but Git receives the original path. For workspace `/srv/sbx/runs/a/workspace`, a run can create `link -> d/e/f/g/h` and a repository at `workspace/repo`. The input:

   ```
   /srv/sbx/runs/a/workspace/link/../../../../../repo
   ```

   is checked as `/srv/repo`, outside the forbidden root. Kernel traversal of the original path instead reaches `workspace/repo`. This requires only writes inside the run’s workspace.

   Independently, checking `p` does not check Git’s `p/.git`, `p.git/.git`, `p.git` or gitfile targets. Git explicitly performs this discovery, including when local filesystem copying is disabled. Both `Clone` and explicit fetch/pull URLs are affected. This breaks the promised invariant that controller Git never opens run-written repository metadata. [Git repository discovery](https://github.com/git/git/blob/v2.43.0/path.c)

   **Fix:** reject noncanonical local spellings; resolve and authorize the actual repository target, including suffixes and gitfiles, before invoking Git. Pass the verified target and revalidate local remote targets when used. Add discriminating clone and fetch fixtures for the workspace-only symlink/`..` example and each indirect repository form.

2. **Medium — Global Git options bypass the fetch/pull guard.** `internal/sandbox/git.go:161`

   The guard recognizes only `args[0] == "fetch"` or `"pull"`. For example, `["--no-pager", "fetch", "--upload-pack=<command>", "origin"]` bypasses both the option refusal and URL validation. Global options are already part of this API’s supported usage—the existing tests prepend `-c` settings.

   **Fix:** expose typed fetch/pull operations, or separate validated global options from the subcommand and apply the guard after parsing them. Prevent caller options from overriding containment settings. Add the global-option-prefixed case to the fault evidence before a caller passes run-influenced arguments.

3. **Medium — The Git feature floor is incorrect.** `internal/sandbox/git.go:43`

   Git **2.41**, not 2.40, introduced the general attribute-source mechanism and `GIT_ATTR_SOURCE` handling. A stock 2.40 passes this check while ignoring the intended protection. Raising `minGit` to 99 in the test proves the comparison works, not that the chosen floor supports the feature. [Git 2.41 release notes](https://github.com/git/git/blob/v2.41.0/Documentation/RelNotes/2.41.0.txt), [2.41 attribute implementation](https://github.com/git/git/blob/v2.41.0/attr.c)

   **Fix:** require at least 2.41, update the diagnostic and comment, and add version-boundary fixtures or a behavioral capability check. The SHA-1 check otherwise covers the only usable `Repo` constructor; subsequent configuration changes are snapshot-checked.

4. **Medium — The post-run “disk bound” measures apparent size, not allocated storage.** `internal/sandbox/run.go:153`

   A run can use `fallocate(FALLOC_FL_KEEP_SIZE)` on ext4/XFS to reserve substantial storage while leaving `st_size` zero. The attempt can therefore pass `within` while retaining more allocated space than `Limits.Disk`. The dedicated filesystem protects the ledger under the stated host prerequisites, but the advertised post-run storage bound does not hold. [Linux fallocate semantics](https://man7.org/linux/man-pages/man2/fallocate.2.html)

   **Fix:** bound allocated blocks as well as logical bytes, with overflow-safe accounting, or enforce a filesystem quota. Add a preallocated, zero-length file fault; retain the existing success and failed-run cases.

5. **Medium — Teardown reintroduces the unbounded directory listing.** `internal/sandbox/run.go:321`

   Measurement and copy-out now use batches, but teardown still uses `filepath.WalkDir`, which reads and sorts an entire directory. A hostile wide directory rejected promptly by `within` is then loaded into controller memory during cleanup. The probe holds its global lock throughout this cleanup.

   **Fix:** use bounded-memory traversal for permission repair and deletion, with a bounded cleanup worker or cancellation strategy. Add a fault that reaches teardown after an entry-cap refusal, and evidence that rejects unbounded `ReadDir` calls—not merely a small fixture with a lowered batch size.

6. **Medium — Probe time budgets remain inconsistent.** `internal/client/reads.go:129`; `internal/api/sandbox.go:82`

   The CLI uses the ordinary transport: a **10-second response-header timeout** and **30-second overall timeout** (`internal/client/client.go:30`). The handler sends its response only after probing and cleanup, so a legitimate slower probe is cancelled despite the new three-minute server write deadline.

   Conversely, image inspection uses only the request context. A stuck inspection with a connected client can retain the probe lock beyond the write deadline; setting a write deadline does not impose an execution deadline.

   **Fix:** give the probe an explicit end-to-end execution budget and matching client header/overall timeouts, retaining bounded independent cleanup. Add delayed-response, stuck-inspection, cancellation and lock-release fixtures.

7. **Medium — Mounting a filesystem directly at `runs/` produces false probe violations.** `internal/sandbox/probe.go:161`

   The new prerequisite expressly supports a filesystem mounted at `<root>/runs`. Its workspace mountinfo root is then `/a…/workspace`, but the classifier requires `/runs/a…/workspace`. A correctly isolated installation therefore reports a forbidden host mount.

   **Fix:** derive expected mount roots relative to the actual backing mount, rather than requiring the literal `/runs/` component. Exercise a real mount directly at `runs/`. The existing positive validation test and live tests do not establish this configuration works end to end.

8. **Low — Forbidden paths and residual-risk wording need completion.** `internal/daemon/config.go:110`; `internal/sandbox/sandbox.go:105`

   The list omits configured TLS key/certificate paths and a non-default runtime-directory Podman socket. Also, accepting a directory on shared `/dev/shm` does not establish that filling its filesystem affects “only other runs”; unrelated host users can share it.

   **Fix:** include configured sensitive paths and the actual Podman socket location, and document or enforce exclusive, operator-sized backing storage. Keep thin provisioning as an explicit operator prerequisite. Fixed-text refusals themselves are sound.

The route authenticates and checks operator status before Podman work; the image reference is passed after `--`, and execution uses the resolved image ID. I found no additional direct bypass in the refused `file://`, scp-like or `transport::` forms; SSH command execution is disabled by `core.sshCommand=false`.

Round 1’s device/type checks, failed-run measurement and copy caps are useful, but their evidence does not cover the cases above. **Repair H1 before merge.** Track the Medium findings against the first affected consumer, with disk accounting, cleanup and Git handling resolved before P14/P15/P32 process hostile workspaces.
