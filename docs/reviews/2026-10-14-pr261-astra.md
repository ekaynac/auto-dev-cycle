1. **High — A planted lift-name collision makes cleanup loop forever.**  
   **Location:** `internal/adapterhost/exchange.go:149`, `:125`; `internal/recovery/orphans.go:85`.

   Create `T/a/b/c`, obtain `c`’s inode number `N`, then rename `T` to `refused-lift-N` under the exchange parent. During the sweep, `c` reaches depth 3. Its lift destination is now its own ancestor, `refused-lift-N`; the rename fails and leaves the tree intact. A directory cannot replace a nonempty destination directory. [Linux rename documentation](https://man7.org/linux/man-pages/man2/rename.2.html)

   Nevertheless, line 149 returns that destination in `lifted`. `RemoveAt` enqueues the same root again, repeats indefinitely, and accumulates errors without bound. It cannot observe cancellation. This needs only a small planted tree, no continuing writer, and survives every restart. Killing orphan adapters beforehand does not close it. Steps 2–4 finish, but the required prelaunch stage never returns.

   **Fix:** enqueue a lifted name **only after a successful rename**. Use collision-resistant destinations with `RENAME_NOREPLACE` and bounded retries; leave unsuccessful sources for later cleanup. Add a regression for this exact ancestor collision, asserting bounded return and memory.

2. **Medium — Cleanup still has no cancellation or total-work bound.**  
   **Location:** `internal/adapterhost/exchange.go:123`, `:161`, `:165`; `internal/recovery/orphans.go:85`.

   `RemoveAt` takes no context. The stage’s outer checks cannot interrupt one removal. Reading 256 names at a time bounds the read buffer, but `lifted` and `todo` retain arbitrarily many subtree names, and joined errors also accumulate. A wide static tree can consume substantial memory and delay launch; a continuing writer can prolong traversal despite cancellation. Depth and descriptor bounds do not bound these costs.

   **Fix:** pass a context through cleanup, check it within traversal, and impose a shared per-start work budget plus bounded pending names and diagnostics. Preserve unfinished trees under sweepable names. Add cancellation-during-removal and wide-directory fixtures; the existing depth-chain test does not discriminate these failures.

3. **Medium — A mode-000 directory at the lift boundary cannot be removed.**  
   **Location:** `internal/adapterhost/exchange.go:143`, `:152`.

   For `exchange-<att>/out/a/b`, make `b` mode 000. At depth 3, the code attempts to move `b` before chmodding its pinned inode. An unprivileged controller needs write permission on a directory moved between parents, so this fails. [Linux rename documentation](https://man7.org/linux/man-pages/man2/rename.2.html)

   The source remains, and every later sweep encounters the same failure. This requires access only to the adapter’s own output tree and also affects live `exchange.remove`.

   **Fix:** chmod through the pinned descriptor before taking the lift branch. Test mode-000 directories exactly at, and beyond, the depth boundary under a non-root uid.

4. **Medium — `stop_reason` includes attempts whose host already recorded refusals.**  
   **Location:** `internal/recovery/orphans.go:114`; `internal/adapterhost/submit.go:243`; `internal/lease/submit.go:56`.

   Sequence: stop an attempt; the host refuses its declared output and commits its final transaction; crash before `x.remove()`. `LoseRunning` leaves a stopping attempt unchanged, so `StopReason` remains set. Restart recovery selects it and records another refusal for the same output under the recovery key. That key deduplicates subsequent recovery commands, not the earlier host transaction.

   **Fix:** use durable host-finalization evidence to distinguish unfinished stops, or suppress already-recorded output refusals while retaining coverage for genuinely unrecorded entries. Add the stop → host final commit → crash-before-removal case alongside the existing unfinished-stop test.

5. **Medium — Rename failures bypass the refusal-volume cap.**  
   **Location:** `internal/recovery/orphans.go:75`, `:154`, `:167`; `internal/recovery/orphans_test.go:268`.

   Refusals commit before rename, but a root consumes a slot only after rename succeeds. Consequently, many roots with failing renames can each append up to 65 events in one start, exceeding the intended 16-root recording bound. The new one-slot test explicitly expects two roots’ refusals; it proves progress after failure, not bounded recording.

   **Fix:** separate the budget for newly committed refusal records from cleanup progress. A committed refusal consumes recording budget even if rename fails; replayed commands should not consume new-record budget. Add successful-overflow and repeated-rename-failure cases.

6. **Medium — A transient storage failure can permanently discard detailed refusal evidence.**  
   **Location:** `internal/recovery/orphans.go:155`; `internal/eventstore/writer.go:496`.

   Every detailed-command error triggers the fallback. If the first transaction rolls back on a transient storage fault and the fallback succeeds, the summary permanently occupies the same idempotency key. Later attempts replay it; successful cleanup deletes the source evidence. The comment that a storage fault necessarily makes the fallback fail too is incorrect.

   This preserves fencing and a refusal marker, but silently weakens the promised per-entry record. It is nonblocking, but should not be described as storage-fault retry behavior.

   **Fix:** restrict fallback to identified deterministic representation/validation failures. Preserve the root and return storage failures for retry. Add a one-shot storage-fault fixture proving that the next attempt retains detailed records.
