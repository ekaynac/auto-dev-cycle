## Opus pre-review of #255

Verdict: NO-GO

I reviewed 8a28083 against origin/main, the P14b row in #254, 01 §2.5, #226 entries 32 and 68, the four #252 reviews and the D43 threat model.

**How I tested.** Each probe was a builder patch sent through the real `Accept` with `Integrity(repo, base)`, using the PR's own fixture, in the test sandbox. I then checked each bypass against the real runner:
- Go: go1.27.1 linux/arm64, `CGO_ENABLED=0`, the same settings as the gate image;
- Python: pytest 9.1.1 in a scratch venv, and CPython 3.12 for the coding-cookie check.

**What holds:**
- Every bypass listed in the four #252 reviews is now blocked.
- The 54 block rows and the 12 control rows pass.
- The `Integrity` constructor's plumbing is sound.

**Why NO-GO:**
- Results can be forged in both languages with no block. For Go, a non-test file can make a failing test report `pass` with no signal at all. For Python, a small conftest makes every failing test report `pass` and gets only a warning.
- The read bounds fail open: a 381 KB patch turns the skip and forgery rules into warnings.
- About a dozen one-line changes uncollect, skip or weaken a test and are accepted. All are confirmed against Go and pytest.

### Critical

**C1. Go test2json forgery passes with no signal** (`integrity_go.go:92-95`, `:136-138`; #226 entry 32)
- **Scenario.** Add `pkg/forge.go`:
  ```go
  func init() {
      if strings.HasSuffix(os.Args[0], ".test") {
          m := string(rune(22))
          os.Stdout.WriteString(m + "=== RUN   TestAdd\n" + m + "--- PASS: TestAdd (0.00s)\n" + m + "PASS\n")
          syscall.Exit(0)
      }
  }
  ```
  `TestAdd` really fails. `go test -json` emits `"Action":"pass","Test":"TestAdd"` and `ok`. The guard returns no block and no warning.
- **Why it gets through:**
  - Only a *call* whose selector is named `Testing` counts. The method value `var isT = testing.Testing; isT()` is missed (confirmed).
  - Exits count only for the literal identifier `os`. `syscall.Exit`, `import xos "os"` and `exit := os.Exit` produce no warning at all (confirmed).
  - 0x16 is matched by spelling only, so `rune(22)` and `byte(22)` pass. The PR calls this a residual, but together with the two gaps above, entry 32 has no guard at all.
- **Fix:**
  - Count any reference to `testing.Testing`, `os.Exit`, `syscall.Exit` and `runtime.Goexit`, not only calls. Resolve import aliases through `f.Imports`.
  - Block a changed non-test `.go` file that can detect test mode (an import of `testing`, `os.Args`, `flag.Lookup("test.…")`, `//go:linkname`) *and* exits, in `init` or a package-level initializer.
  - Warn on every exit reference, and on integer constants equal to 22 in byte or rune conversions.

**C2. Python results can be forged through conftest or plugin hooks, which only warn** (`integrity_py.go:202-204`, `:351-355`; `integrity.go:161-163`)
- **Scenario.** A new `tests/conftest.py` containing `def pytest_pyfunc_call(pyfuncitem): return True`. pytest reports `3 passed`, rc 0, for three tests that fail. The guard emits one warning only ("the pytest hook … changed"). The same holds for a `pytest_runtest_makereport` hookwrapper that sets `outcome = 'passed'`.
- **Second scenario.** `globals()['collect_' + 'ignore'] = [...]` in a new conftest gives no signal at all, and pytest collects nothing.
- The denylist `pyControls` (only 7 collection hooks) cannot be completed. Other hooks that drop or forge results include `pytest_collection`, `pytest_make_collect_report`, `pytest_runtest_protocol`, `pytest_report_teststatus`, `pytest_generate_tests`, `pytest_configure` (via `config.option`) and `pytest_sessionfinish`. A module-level `__getattr__` or `globals()` gets the same effect.
- **Fix: use an allowlist.**
  - Any new or changed `conftest.py`, at any depth, blocks unless its top level holds only imports, literal constants and `@pytest.fixture` functions.
  - Any added or changed `def pytest_*` or `hookimpl` in any `.py` file blocks.
  - A `pytest_plugins` change blocks; today it only warns.
  - Record the expected false blocks in the D55 ledger.

### High

**H1. Read bounds fail open through budget exhaustion** (`integrity.go:103-108`, `:125-134`)
- **Scenario.** Add sixteen `aNN.py` files of 4 MiB each, containing a NUL byte. git treats them as binary, so the whole patch is **381 KB**. They use up the 64 MiB budget. After that:
  - `money.py` with `pytest.skip()` is accepted with a warning only;
  - `pkg/zz.go` with `testing.Testing()` is accepted with a warning only.

  Confirmed. A one-line change to large `.go` or `.py` files in the base (vendor or generated code) also costs twice their size.
- The contract says "read bounds that fail closed". Only collected tests are closed today: helper skips, forgery and plugin controls fail open.
- **Fix.** Block any `.go`, `.py` or pytest-config side that was not read, whether over budget, over the per-file bound or unparseable. Keep warnings for other file types only.

**H2. A Go skip through a method value is not seen** (`integrity_go.go:81-97`)
- **Scenario.** `skip := t.Skip; skip()` at the top of `TestAdd`. The guard returns no block and no warning.
- **Fix.** Count every `SelectorExpr` whose selector is in `goSkips`, whether or not it is called. The same change covers `Testing` in C1.

**H3. Go collection differs from `go test`** (`integrity_go.go:40-53`)
- **Scenario 1.** Change `package pkg` to `package documentation` in `calc_test.go`. go/build ignores that package name, so `go test` prints `[no test files]`, and the guard is silent.
- **Scenario 2.** Add `//go:build !goexperiment.greenteagc` (or `!arm64.v8.0`) to a test file. The gate skips the file, while the guard says it is collected on both platforms. The cause is that `build.Context` sets no `ToolTags`; go1.27 sets `goexperiment.*` and `arm64.v8.0`/`amd64.v1`.

Both were confirmed with go1.27.1.
- **Fix:**
  - Read the package clause and treat `documentation` as not collected.
  - Set `ToolTags` (and `ReleaseTags`) from the gate environment.
  - Better: require a constraint to hold for every assignment of the tags the guard does not model (`cgo`, `race`, `goexperiment.*`, `*.v*`, custom tags). If that cannot be shown, block.

**H4. The pytest config parser differs from pytest** (`integrity.go:250-271`)
- **Indented-header scenario.** Change `setup.cfg` (which `py-mini` does not protect) by adding, under `[tool:pytest] markers = …`, a blank line, then the indented line `    [x]`, then `addopts = --deselect tests/test_money.py::test_zero`.
  - The guard trims the line, treats it as a header and closes the section. The captured config is unchanged, so the candidate is accepted (confirmed).
  - iniconfig treats an indented line as a continuation. pytest deselects the test (confirmed).
- **Also missed:**
  - `pytest.toml` and `.pytest.toml`: pytest 9 reads them, and the guard ignores them (confirmed);
  - a `pyvenv.cfg` or `conda-meta/history` added inside `tests/`: pytest stops collecting that directory (confirmed);
  - TOML dotted keys or inline tables (`[tool]` plus `pytest.ini_options.addopts = …`) produce an empty config. This depends on the profile: `py-mini` protects `pyproject.toml`.
- **Fix:**
  - Follow iniconfig exactly: a header only when `[` is at column 0, and strip comments.
  - For TOML, block when the set of lines mentioning `pytest` changes.
  - Add `pytest.toml` and `.pytest.toml`.
  - Block adding `pyvenv.cfg` or `conda-meta/history` under a directory that holds collected tests.

**H5. A tokenizer differential through a PEP 263 coding cookie** (`integrity_py.go:59-65`)
- **Scenario.** Put `# coding: utf-7` first, then `X = +ACIAIgAi-` before `def test_zero` and `+ACIAIgAi-` after it. CPython reads `"""`, so the test is a string: pytest collects only `test_add` (confirmed). The guard counts `test_zero` and accepts.
- The reverse also works: `#+AAo-pytest.skip()` hides code inside a comment.
- **Fix.** Refuse (unverifiable, which blocks) a cookie naming anything other than utf-8 or ascii, and require `utf8.Valid`.

**H6. Python tests uncollected while names and counts stay the same** (`integrity_py.go:306-336`). Every case below was accepted with no signal and confirmed in pytest:
- `class TestAdd(dict):`, because pytest's `hasinit` sees the inherited `__init__`;
- `class TestAdd(Off):` where `Off` sets `__test__ = False`;
- `TestAdd = None`, or `del TestAdd` (only `p::TestAdd` is deleted, and the keys are `p::TestAdd::…`);
- `class test_zero: pass` or `from money import add as test_zero` after the test;
- `if False:` around a test;
- `__unittest_skip__ = True` in a `TestCase` class.

In addition, the tests of `unittest` subclasses not named `TestCase` (`IsolatedAsyncioTestCase`, Django's `APITestCase`, a local base) are invisible: deleting or weakening them is never seen.

**Fix:**
- Key class tests by the class name plus the text of its base list.
- Treat any binding of a test or test-class name other than its `def`/`class` as a deletion (class, import-as, `for`, `with`, walrus, `del`, `=`).
- Key a test nested under a compound statement with that statement's text.
- Count `__unittest_skip__` and `__unittest_expecting_failure__` as skips.
- Treat `test*` methods of every class in a collected file as tests. This over-approximation only adds false blocks.

**H7. Assertion counts can be inflated, so a removal goes unseen** (`integrity_py.go:213`; `integrity_go.go:98`). Confirmed with no signal:
- Python:
  - `assert add(0, 0) == 0` changed to `asserted = add(0, 0) == 0`: any name starting with `assert` counts;
  - `assertTrue = add`, an attribute that is never called, also counts.
- Go:
  - `t.Fatal(...)` changed to `_ = err.Error()`: the `Error` method of any value counts;
  - the check replaced by a new no-op `func checkNothing(bool) {}`.

01 §2.5 counts an assertion removed as conclusive.

**Fix:**
- Python: count only the `assert` keyword at statement start, and calls `NAME(`/`.NAME(` whose name starts with `assert`, `.raises(` and `.warns(`.
- Go: count `Error*`/`Fatal*`/`Fail*` only on a receiver that is a `*testing.T`/`B`/`F`/`TB` parameter of the enclosing `FuncDecl` or `FuncLit`. Count testify by import path. Count helpers only when the call passes the test parameter.

**H8. Hostile input stalls the controller** (`integrity_py.go:351-355`; `integrity_go.go:146-153`)
- **Measured:**
  - a 1 MiB `pytest_configure` body takes **2 min 21 s**, because `+=` per token is quadratic, so a 4 MiB file takes about 38 min;
  - 1 MiB of `Example` functions and comments takes **74 s**, because `output` scans every comment for every test.

  A 64 MiB budget means hours of CPU, and these loops never check `ctx`.
- **Fix:**
  - Hash the tokens with a `strings.Builder` or sha256.
  - Find each example's last comment in one sorted pass.
  - Check `ctx.Err()` per file or per declaration.

**H9. Python's skip list is incomplete** (`integrity_py.go:200-201`, `:248-275`). Each was accepted with no signal and skipped by pytest:
- adding `@pytest.mark.parametrize("z", [])`: pytest skips with "got empty parameter set";
- applying a skip alias defined in the base (`slow = pytest.mark.skipif(...)`, then `@slow`);
- `usefixtures` of a fixture that skips.

**Fix:**
- Count an empty literal parametrize list as a skip.
- Warn on any decorator added to an existing test, and block when its name is bound to a skip or xfail mark in a file the guard reads.

### Medium

- **M1. A test can move into a weaker copy** (`integrity.go:186-199`, `integrity_py.go:226-229`).
  - **Scenario.** Delete `test_zero` and add `def test_zero(): assert 1` in a new file. The guard treats it as moved, with equal counts, and accepts it with no signal (confirmed). `trivial` flags only `True`.
  - **Fix.** Treat as trivial an assert of a single literal, or of identical sides. Warn when a moved test's assertion text changes.
- **M2. The go.mod `ignore` directive is not modelled** (`integrity.go:153-157`).
  - **Scenario.** `ignore ./c` in the root go.mod drops package `c` from `./...` (confirmed with go1.27).
  - It is blocked here only because this repository's profile protects go.mod. `go-mini` lists no lockfiles.
  - **Fix.** Block a root `go.mod` change that touches `ignore`, whatever the profile.
- **M3. Base pytest settings that change collection are not read.**
  - **Scenario.** With `python_files`, `python_classes`, `python_functions`, `testpaths` or `norecursedirs` set in the base, the guard's collection model is wrong: tests in `check_*.py` files are invisible.
  - **Fix.** If the base config sets any of these, mark the affected files unverifiable, which blocks. Or apply the settings.
- **M4. Go method tests (testify suites) and table-driven rows are not tracked** (`integrity_go.go:122`).
  - **Scenario.** Deleting a suite method or a table row is silent.
  - **Fix.** Record this as a stated residual in the D55 ledger. Rows are the Go equivalent of parametrize rows.
- **M5. A call to an existing skipping helper adds no skip.**
  - **Scenario.** Adding `requireDocker(t)`, which already skips in the base, counts as an *assertion*.
  - **Fix.** Count calls to package functions known to contain a skip as skips.

### Low

- **L3. An unread file is reported twice.** It produces one warning for each side, so `money.py` appears twice.
