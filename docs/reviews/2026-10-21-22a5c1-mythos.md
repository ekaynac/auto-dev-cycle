### Answers to the four questions

**1. Fail-open in the reservation or the rails: none found.**
- **Overflow:** `mulSat` bounds `attempt_cap` at `maxAmount`; `tokensFor` divides in `big.Int` and saturates; `left = max(cap − spent, 0)` cannot overflow since both are non-negative; a saturated `spent` (`unaffordable`) gives `left` 0, so the fit is 0 and the match is refused on that rail.
- **Rounding:** `fit = ⌊left·10⁶/p⌋` and `usdRail` re-prices with `ledger.PriceTokens`, which is `⌈tokens·p/10⁶⌉` at the same `max(input, output)` rate, so `⌈fit·p/10⁶⌉ ≤ left` always and the two checks never disagree. The 2,401 → 600 row pins the direction.
- **A zero:** a rail of 0 leaves 0, fit 0, refused. A price of 0 (both rates) is free: `tokensFor` returns `maxAmount`, the reservation is `attempt_cap`, `reserved` prices it at 0. `context_tokens` and `expected_turns` are at least 1 by schema, checked at `registry.New`, so `attempt_cap ≥ context_tokens` and a granted reservation is never below one turn.
- **Missing or negative price:** nil is unpriced, as on main. A negative rate cannot load (`Amount` min 0, validated at `Load`/`New`); if one did, `priced` would return `unaffordable` and `usdRail` would refuse with the hold.
- **The boundary at the prior:** `fit < context_tokens` refuses; `fit == context_tokens` grants exactly one turn (the "exactly one turn" row, and `TestUSDTaskRail`'s raise to 6,000 micros).
- **Both rails:** `spend.fit` keeps the strictly smaller room, rails ordered task then day, so a tie names the task's. `usdRail` then checks each rail independently with the same `next`, so a reservation that fits the tighter fits both.
- **Liabilities:** `spent` and `cost` are unchanged from main; a hostile zero final still counts (`TestUSDTaskRail`), and a clipped liability is `unaffordable`.
- **A refused launch:** `RefuseStart` moves the lease to `releasing`, which `cost` counts as live at its reservation until released, and `occupied` keeps the unit placed; the node is held. Conservative, not open.
- **No rails / no prior:** both refuse before any lease event (`TestUSDNoRails`, `TestMatchRefusesBeforeReserving`), holding the node on the profile or the executor. A priced local endpoint still reserves a slot and is still checked by `usdRail` (nil spend, computed there); its zero footprint is admitted by the lease schema (`Amount` min 0).

**2. Waiting forever with no hold, or a spin: no spin; two unstated waits (M1, M2).**

### Medium

**M1. A `source_invalid_config` hold the loop raises has no clear path in adcd: the build stays held after the operator fixes the configuration.** `internal/daemon/place.go:60`, `internal/dispatch/reserve.go:177`
- **Input:** a profile with no `per_day_usd`; the build is held `source_invalid_config` on `profile <id>`. The operator adds the rail and restarts. The build stays held: `schemas/vocab/holds.yaml:20` resumes this hold on `config_change`, and nothing in the tree emits it. `graph.Clear` is called only by `Reopened` (day rail), `ClearRail` (task rail) and a fixture; there is no hold-clear command.
- **Why it matters:** not a fail-open, and the hold is visible on `GET /v1/holds` and the board. But the body says the hold is "the operator's", and the operator has no action to clear it; the only route today is a new node. With launch inactive it does not reach (a).
- **Fix:** state it in "Not here" as the obligation it is (the `config_change` signal, or a clear action), or have the placer clear its own `source_invalid_config` holds in a `ClearRail`-like action once `card` and the checks admit the node again.

**M2. A granted lease nothing launches never ends: the build waits placed, with no hold, and its reservation counts against both rails.** `internal/daemon/place.go:115`, `internal/dispatch/dispatch.go:171`
- **Input:** launch active; 22a-5c-2's attempt run fails after `Match` and before `placer.launch` (say, `Prepare` fails). The lease stays `granted`; `occupied` keeps the unit placed; `cost` counts the reservation as live spend on the task and the day, forever. The lease's `Deadline` (now + 1 h) is recorded and enforced by nothing: `lease.expired` is in the transition table but only `fakesched` emits it.
- **Why it matters:** outside 5c-1's promise (launch is inactive), but it is the one way a node waits forever with no hold in the composed system, and it also shrinks every later build's fit.
- **Fix:** state it as 5c-2's obligation: a failure between the grant and the launch revokes and settles (or releases) the lease in the same run. Or give the loop an expiry action on `Deadline`.
