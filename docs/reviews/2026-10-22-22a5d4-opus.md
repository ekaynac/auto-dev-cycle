### Medium (OBLIGATION)

**M1. A podman client that never starts is recorded as the candidate's `failed/unsafe_output`.**
- **Where:**
  - `internal/adapterhost/session/container.go:61`: on a spawn failure, `Remove` never runs, so the attempt stays unsafe;
  - `internal/sandbox/interactive.go:101`: `Within` returns `ErrSpec` ("may still be running");
  - `internal/daemon/run.go:300-306`: the runner takes any `Within` error as a breach of the bound.
- **Input:** the runner's world, with the real `containerAdapter` and the real `sandbox.Host`, and `Podman: /nonexistent/podman`. The log says `adapterhost: spawn: fork/exec /nonexistent/podman: no such file or directory`. The build node is **completed** with `failed/unsafe_output`, detail "the run left more than its disk bound, or what cannot be measured". A host fault thus completes the unit and blames the candidate.
- **Already before this PR:** this was already true at 0b3d0ca. With `Within` disabled, the same probe gives `failed/unsafe_output` from the diff path, because `CopyTree` refuses the unsafe attempt. I missed it in #393.
- **Fix:**
  - On a failed spawn, `StartContainer` (or the session) should still call `Remove`. With no cid file, `Remove` checks only that the name is gone, and clears `unsafe`.
  - The runner should then map a session spawn error to `could_not_run`, which is retried as a host fault, never a candidate result.
  - Add a row: a podman that does not exist gives `could_not_run`, and the node is not completed.

### Low (OBLIGATION)

**L1. The runner does not tell `Within`'s two errors apart.**
- **Where:** `internal/daemon/run.go:300-306`. Any `werr` sets `over`, then the attempt is torn down. `Within`'s `ErrSpec` means "the container may still be running" (`interactive.go`); only `ErrLeft` is a breach.
- **Input:** none can reach it with a live container today (question 3). It is safe by the argument above, not by construction.
- **Fix:** set `over` only on `errors.Is(werr, sandbox.ErrLeft)`. Treat any other `Within` error as unverified: `Keep` and `ambiguous_state`. Together with M1's fix, the spawn-failure case stays correct.

**L2. The `out/` bound is never applied in production.**
- **Where:** `internal/adapterhost/attempt.go:202` (`Prepared.Run` removes the exchange on return), and `internal/daemon/run.go:298-306` (`Within` runs after that).
- So `Within`'s `out/` (`interactive.go:55-58`, "its exchange's out/ included") always measures a removed directory, counted as empty by this PR's fix. Only ingestion's own checks apply to `out/`.
- [INFERENCE, from `remove.go:20-23` and `exchange.go:93-108`; not run] Removing an `out/` of more than `MaxWork` (65,536) entries stops partway, so the run's output stays on the runs filesystem under the exchange's own name or `refused-*` until adcd's next start sweeps it. The run is not failed for it.
- **Fix:** measure `out/` before the host removes it (a hook in `adapterhost` before `x.remove`), or drop the claim from the doc comment and the I17 row. Either way, add a row with an `out/` over `MaxWork` entries.

**L3. `devOf`'s climb is not pinned to `EACCES` by any row.**
- **Where:** `internal/sandbox/sandbox.go:141-150`.
- **Input:** a mutation that climbs on **any** error (`ENOTDIR`, `ELOOP`, `EIO`) survives every row. A forbidden path whose stat fails for another reason would then be measured as an ancestor's device.
- **Fix:** add a row where `devOf(p, true)` keeps the error, for a path under a regular file (`ENOTDIR`). State in the comment the one case the climb misses: a mount strictly below an unsearchable directory.

**L4. Two gaps in the live row's checks.**

- **Fix:** have the lead's command set `ADC_LIVE_ADAPTER_RELEASE` to the dist `lib/adc` of the image's commit, or make the row require it. Add `runs/` to the check that directories are empty.
