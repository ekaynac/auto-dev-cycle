## High

### H1. `make ci` is red: shellcheck SC2015 in php-mini/check.sh
- **Where:** `fixtures/t0/php-mini/check.sh:177` and `:181`: `present="$( (cd "$task_dir/hidden" 2>/dev/null && find . -type f -printf '%P\n' || true) | sort)"`.
- **Problem:** the PR now shellchecks `fixtures/t0/*/check.sh` (Makefile `SHELL_SCRIPTS`). The CI's shellcheck reports SC2015 (A && B || C) on these two lines, so `make lint` exits 1 and the "make ci" job fails on both architectures (run 37112560120). The PR's claim "all four clean" was not verified locally, because shellcheck is not installed on the controller host (lint prints "skipped locally").
- **Failure scenario:** merging turns main red, and every later PR inherits the failure.
- **Fix:** write it as `if [[ -d "$task_dir/hidden" ]]; then present="$(cd "$task_dir/hidden" && find . -type f -printf '%P\n' | sort)"; else present=""; fi` (same for `visible`). Then run shellcheck locally (or in a container) before claiming it is clean.

### H2. failing_then_green: ts-mini, go-mini and php-mini never check that the hidden tests fail at base (fail-open)
- **Where:**
  - `fixtures/t0/ts-mini/check.sh:287-293`
  - `fixtures/t0/go-mini/check.sh:153-155`
  - `fixtures/t0/php-mini/check.sh:224-225`
- **Problem:** "base with hidden" only checks that the gate fails overall. For failing_then_green the visible overlay already fails at base, so that check passes whatever the hidden tests do. Rule 1 ("the hidden tests catch the missing behaviour", PR acceptance criterion 1) is unenforced for this kind in three of the four fixtures. py-mini does this correctly: `check.sh:280-285` requires a failure inside a hidden file and nothing new elsewhere.
- **Failure scenario:** I verified this on scratch copies. Replacing `ts-mini-failing-then-green-1/hidden/test/money-negative-hidden.test.ts` with `it("trivial", () => assert.equal(1, 1))` still gives "OK ts-mini: 4 tasks well-formed". The same mutation in go-mini (`func TestHiddenTrivial(t *testing.T) {}`) still gives "go-mini: all checks passed". A later edit that weakens these hidden tests would pass CI. The cycle would then accept a builder that special-cases the one visible input, for example by hard-coding `-1234 -> "-$12.34"`. Catching exactly that is the job of a failing_then_green hidden test. php-mini has the same structure, judging by the code (not run).
- **Fix:** attribute the base failures to files, as py-mini does. Parse the junit (`classname` or `file` attribute) or the go test2json (`Package`/`Test` events, mapped to the hidden test function names that `test_names` already extracts). Require at least one failing test from a hidden file and no new failures outside hidden ∪ visible_added. A simpler alternative: run the base-hidden gate a second time with the visible overlay removed, and expect `fail` there too.

## Medium

### M1. Offline enforcement (rule 4) is inconsistent; go-mini has none
- **Where:**
  - `fixtures/t0/go-mini/check.sh:25,78`
  - `fixtures/t0/ts-mini/check.sh:103-115`
  - `.github/workflows/ci.yml` (fixtures job)
- **Problem:**
  - (a) go-mini runs the gate with the host network. Its only offline measure is `GOPROXY=off`, which stops module downloads but not network use by test code or the toolchain. Yet the check labels say "(offline)", and the PR's acceptance criterion 3 says "Every gate runs offline (bubblewrap `--unshare-net` or `--network none`)".
  - (b) ts-mini falls back to SKIP and still passes when bwrap is unusable, unless `ADC_T0_REQUIRE_OFFLINE=1` is set. CI does not set it. py-mini does the opposite: it fails unless `ADC_FIXTURE_ALLOW_NETWORK=1`.
  - (c) ts-mini does not probe that the network is actually gone. py-mini does (`check.sh:107-117`).
- **Failure scenario:** if the AppArmor sysctl step stops working on a future runner image, bwrap fails. py-mini then fails loudly, while ts-mini goes green with an online gate. A go-mini hidden test that needs the network would pass the check here and then fail in the real offline gate (M1+).
- **Fix:** move the offline wrapper and its probe into one shared helper (or copy py-mini's pattern) and use it in go-mini as well (`bwrap --dev-bind / / --unshare-net -- go test -json ./...`, with GOCACHE/GOPATH writable). Make it fail closed everywhere, with one opt-out variable name for all four fixtures.

### M2. py-mini refactor hidden test over-fits on source text
- **Where:** `fixtures/t0/py-mini/tasks/py-mini-refactor-1/hidden/tests/test_hidden_rounding_module.py:36-41` (`assert "ROUND_HALF_UP" not in text`).
- **Problem:** the requirement says money.py "must no longer define the rounding itself". It does not ban the token `ROUND_HALF_UP`. A correct refactor that leaves `from decimal import ROUND_HALF_UP` behind (a typical leftover) fails, and so does one that mentions it in a docstring or re-exports it for compatibility. The structural property is already proven by behaviour and identity checks: `money.round_money is rounding.round_money`, `money.CENT is rounding.CENT`, and `round_money.__module__ == "invoicekit.rounding"`.
- **About note 11:** for fixture hidden tests, a structural check is legitimate when a refactor cannot be told apart by behaviour. It should still assert only what the requirement states, and it should prefer identity or AST checks over substrings. go-mini and php-mini do this right: they use no source text.
- **Failure scenario:** the cycle grades a correct builder solution as failed, which skews M1 evaluation.
- **Fix:** drop `test_money_module_no_longer_defines_rounding`. If something must stay, use an `ast` check that money.py has no `FunctionDef` named `round_money` and no `Assign` to `CENT`.

Drop it or match `^export function taxCents` only.

The behaviour change is small but real for a "behaviour-preserving" reference. Drop the `__all__` line; the re-export comment is enough.
- **L3** Gate "pass" ignores skipped tests in all four checkers: py `check.sh:171`, ts `junit_summary`, php `run_gate`, go counts only fail events. An after-patch hidden test that skips (for example through `pytest.importorskip` or `t.Skip`) counts as green. Treat skips as an error, at least in the after run.
- **L4** `Makefile` `fixtures-check`: if `$(wildcard fixtures/t0/*-mini)` is empty (a rename, or a fixture without the `-mini` suffix such as the planned `multi-service`), the loop runs nothing and succeeds. Fail when `T0_FIXTURES` is empty, or glob `fixtures/t0/*/check.sh`.

- **L7** `fixtures/t0/php-mini/tasks/php-mini-feature-1`: allocate on a negative amount is unspecified and unguarded. The reference returns parts that do not sum to the amount (intdiv truncation, and the loop is skipped while the remainder is negative). - **L8** The checker conventions differ: PASS/ok prefixes, exit codes 1 vs 2, opposite offline env knobs, and where `dependency_recipe` lives in fixture.json. The PR acknowledges the fixture.json part as M1 schema work. The env knob part belongs with M1 in this PR (CI depends on it).
