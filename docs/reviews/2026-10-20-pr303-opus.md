## Opus pre-review of #303 (2026-10-20)

Verdict: GO with changes

I found no way for a pytest setting to be dropped. The lexer only removes statements whose key path, including the table they sit in, cannot name pytest. Every form it does not lex makes it read the whole file, as main does. The changes requested below are about licensing, not about the guard.

### What I checked
- **Tests:** `go test -count=1 -run 'TestPy' ./internal/accept/` passed in a copy: 27 tests passed and none failed, including the 16 forge mutations in `pyTOMLForges` and the three real files.
- **Probe:** I ran 20 extra inputs through `pyTOML` and through Python 3 `tomllib`. Nineteen parse in `tomllib` with the pytest setting present, and `pyTOML` keeps the setting in all 19. The one input `tomllib` rejects (a leading BOM) makes `pyTOML` return false, so the file is read whole. The inputs were:
  - dotted keys under `[tool]`, with spaces and quotes around the dots (`"pytest" . ini_options . addopts`);
  - multi-line strings ending in `\"""`, in four quotes, and `'''…'''''`;
  - arrays holding inline tables, with `]`, `}` and `#` inside strings and a comment inside the array;
  - dates with a space, `-inf`, `0x1F`;
  - `[project.entry-points.pytest11]` and `entry-points = { pytest11 = … }`;
  - root `tool.pytest = {…}`;
  - pytest 9's native `[tool.pytest]` after `[[tool.x]]`;
  - `[tool.'pytest'.ini_options]`, and tabs around `=`.
- **Unicode escapes:** `[tool."py\u0074est".ini_options]` returns false (whole file), because `tomlKey` refuses any `\` in a quoted key. An escape inside an inline table is kept (`strings.Contains(st, "\\")`, `internal/accept/integrity_pytoml.go:60`).
- **Line endings and BOM:**
  - CRLF is normalised to LF.
  - A lone CR or BOM is a stray character, so `pyTOML` returns false. `tomllib` rejects both anyway.
- **What the lexer accepts beyond TOML:** newlines inside inline tables, and anything at all in the scalar branch. Neither shifts a statement boundary on TOML that `tomllib` accepts, so neither drops anything.
- **INI and `setup.cfg`:** handling is unchanged. The diff to `internal/accept/integrity_pyguard.go` only adds the `pyTOML` call inside the `.toml` case. The `pytest.*` files and the `.ini`/`.cfg` paths are byte-identical to main.
- **Regression against main:**
  - `configured` can now be false for a `pyproject.toml` that mentions pytest only as a dependency or classifier. Line 125 then blocks adding or removing that file. That is stricter, not looser.
  - The `pyPathKey` and `addopts` splits now run on concatenated statements. A `pythonpath` value can run on into the next quoted-key statement. That gives more paths, so it can only block more.

### Findings

**Medium: the BSD-3-Clause and MIT fixtures carry no copyright notice or licence text**
- `internal/accept/testdata/pyconf/networkx-3.3.pyproject.txt:1` and `internal/accept/testdata/pyconf/setuptools-72.1.0.pyproject.txt:1` are copied verbatim with no header. The only attribution is a Go comment (`internal/accept/integrity_pytoml_test.go:12-19`), and `NOTICE` names nothing third-party.
- **Input:** a source or release tarball redistributes these two files without the copyright notice that BSD-3-Clause §1 and MIT require.
- **Fix:** give each file a REUSE-style `<file>.license` sidecar with the upstream copyright line and `SPDX-License-Identifier` (`BSD-3-Clause`, `MIT`), plus `LICENSES/BSD-3-Clause.txt` and `LICENSES/MIT.txt` (or a `testdata/pyconf/README` holding the upstream licence texts), and add a line to `NOTICE`. The other option is to replace these two files with minimal synthetic fixtures that reproduce the classifier and `--dirty` lines.

**Low: the arrow fixture's licence is stated but not in SPDX form**
- `internal/accept/testdata/pyconf/arrow-17.0.0.pyproject.txt:1` keeps the ASF header, which is enough for Apache-2.0, but there is no machine-readable SPDX tag.
- **Fix:** add an `arrow-17.0.0.pyproject.txt.license` sidecar with `SPDX-License-Identifier: Apache-2.0` and the upstream copyright, to match the first finding.

- **Input:** a mutation that removes the `k < 2` extra-quote loop, or the `j++` escape skip, would survive the current tests.
- **Fix:** add forges such as `x = """a\""""\n[tool.pytest.ini_options]\naddopts = "-p forge"\n` and `x = '''a'''''\n…`.
