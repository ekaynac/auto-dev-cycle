### Medium: OBLIGATION

**M1. `outstanding_usd_micros` undercounts the outstanding liability, and can read 0.** `internal/api/tasks.go:163-187`
- **Cause:** an unsettled call is priced at its usage so far (`StandingOf().Usage`), at the split input and output rates.
- **What the USD rail counts instead** (`internal/dispatch/usd.go:170-229`, `cost`):
  - while the lease is live: `max(reservation, usage)` at the higher token rate;
  - once it has ended: the liability its settlement kept (`capacity.LiabilitiesOf`).
- **Input:** an uncertain call with zero-token deltas (#226 entry 69's hostile zero report) on a priced lease. The read shows `outstanding_usd_micros: 0`, while the rail counts the whole reservation. Even an honest call reads below its liability until it settles.
- **Fix:** price the outstanding part with the rail's `cost` (export it, or share one function), so the read and the rail agree. Or rename the field to "reported so far" and add the liability apart. Add a row: a zero report on a live priced lease must give at least the priced reservation.

**M2. Nothing stops two adcd sharing one sandbox root, and the sweep would then destroy the other's live runs.**
- **Cause:** no lock is taken on `--sandbox-root`. Each sweep:
  - removes every `adc-att_*` and `adc-<24hex>` container (`RemoveStale`);
  - removes every `exchange-*` directory its own store does not name as cut (`recovery/orphans.go:88`).
- **Input:** two adcd with different `--state-dir` and the same `--sandbox-root`. The second one's start kills the first one's running containers and deletes its live exchanges.
- **Fix:** take an exclusive `flock` on `<sandbox root>/.adcd.lock` at `Start`, held for the daemon's life, and refuse to start without it. Or at least state "one adcd per sandbox root" in the config doc and the PR body.

**M3. Run directories and clones a crash left are never removed, and the rule keeps them for good.** `internal/daemon/sweep.go:76`
- **Cause:**
  - At start nothing runs, so a run directory without a `kept-attempt` marker is a crash's leftover. Yet it is "the run's own teardown", which will never happen; `TestAKeptDirectory…` even asserts it stays (`own`).
  - `<state>/clones/<attempt>` and `<attempt>.tree` are not swept either.
- **Effect:** every crash during a run leaves a full checkout on the `runs/` filesystem (sized by the operator) and a clone in the state directory. Repeated crashes fill `runs/`, and later runs fail.
- **Fix:**
  - When `RemoveStale` returns no error, its container listing was complete, so no run directory has a live container. Tear them all down then (skip `runs/exchange` and `runs/gateway`), kept or not.
  - Remove `clones/*` at the sweep.
  - The PR's stated residual (a kept directory whose container vanished unnamed) also goes away with this.

**M4. Two of the sweep's promises are unpinned.**
- **Mutants that survive:**
  - S3: a completed attempt whose lease is still active is not ended (`sweep.go:151-152`). No row covers it.
  - S1: the left attempt is sealed with no diff (`sweep.go:160`). `TestAFinishingAttemptIsEndedAtStart` does not check the seal's `partial_diff`, so "sealed with its own result's patch" is unproven.
- **Fix:**
  - Add a row for a completed attempt with an active lease: the sweep must complete and settle the lease.
  - In the finishing row, assert that the sealed record's `partial_diff` equals the result patch's `ContentDigest`.

### Low: OBLIGATION

**L1. A reseal or sweep seal differs from the run's own seal.** `internal/daemon/sweep.go:156-162`
- **Effect:**
  - `ignored` is not carried, so `accept` loses its ignored-file warnings (`accept.go:226`).
  - A finishing attempt with a failed `unsafe_output` result (no `Value`, but a diff the run would have sealed) is sealed as "changed nothing".
- **The patch digest is the right one:** `graph.Build` sets the patch's `ContentDigest` to `facts.Diff`, the controller's own diff. So no foreign diff is sealed, and accept reads the patch from the result anyway.
- **Fix:** read `ignored` from the result's facts if they are recorded, or state the loss. Also state that a failed result's diff is not kept.

**L2. The reseal clock is set once and only cleared after a reseal.** `internal/daemon/sweep.go:192,210`
- **Cause:** `waiting[node]` is deleted only after a reseal succeeds. On the normal path (the run's own seal lands), it stays. Mutant S2 survives.
- **Effects:**
  - The map grows by one entry per accept node ever seen unsealed.
  - A node claimed and seen unsealed again later is resealed at once, racing a live run's seal. That race is benign: the seal's expected revision lets one win, and `endActive` is a no-op on an ended lease.
- **Fix:** delete `waiting[node]` when `Observe` stops listing the node, for example by pruning in `Reseal`'s caller each pass. Or key the clock by `(node, attempt)`.

**L3. A seal that never lands keeps its lease active until a restart, and the restart does not lift the hold.**
- **Probe:** after `maxTries`, the attempt is `finishing` and the lease `active`. Its reservation (and its USD cost while live) stays counted.
- **After a restart:** the sweep seals the attempt and ends the lease. But the accept node stays held `runner: failed`, which `cleared` never lifts (`run.go:708`).
- **Fix:** state both. Or have the sweep clear a `runner: failed` hold whose cause was the input's seal once that seal lands.

**L4. The sweep runs only when a runner is configured.** `internal/daemon/daemon.go:247`
- **Input:** adcd crashes with a runner, then is restarted without `--adapter` or `--sandbox-root`.
- **Effect:** the `finishing` attempts are not ended, their leases stay active, and orphaned exchange output is not refused, until a start with a runner.
- **Fix:** run `endLeft` and `RefuseOrphans` whenever the store holds such attempts (neither needs the sandbox), or state it.

### The five questions
1. **Can the sweep remove what is not a dead run of ours, or end a live lease or attempt?**
   - **Containers:** `RemoveStale` lists only through the sandbox root's own podman environment (its own `HOME`, XDG directories and storage). So the operator's other containers are out of reach. Two daemons sharing a root are the exception (M2).
   - **Directories:** only directories under `<root>/runs` are touched. They must not be symlinks, must hold a marker the controller wrote, and their attempt must be one `RemoveStale` removed.
   - **At start nothing of this store runs:** the sweep runs in `Run` before the loop and before `serve`. The state lock excludes another adcd and the offline commands. Restart recovery has already lost every running attempt.
   - **At runtime:** `Reseal` touches only a `finishing` attempt whose result is committed, past its run's commit step.
2. **Can the sweep or the reseal record a result the attempt did not produce, or seal the wrong diff?**
   - **Results:** no. The kept result is the attempt's own (`AttemptResult`). With none, `could_not_run/ambiguous_state` is recorded with no attempt, after the seal, as the `isolated` fold requires.
   - **The diff:** it is the patch's `ContentDigest`, which is the controller's own diff. But `ignored` is lost, a failed result's diff is not kept (L1), and no row pins the diff (M4).
3. **Can the charge read zero when unknown, or undercount?**
   - **Unknown is null, never zero:** with no price, or with a settled call whose usage is unknown, saturated or inconsistent, the settled figure is `null`.
   - **The outstanding figure undercounts,** and can read 0 (M1).
4. **The builder's three points:**
   - **A kept directory whose container vanished unnamed:** acceptable as stated, but superseded by M3's fix.
   - **The in-memory reseal clock:** fine across a restart, since the sweep covers the attempts left. It leaks and can fire early (L2).
   - **The inventory row "kept + GAP":** right, because `launch` stays inactive.
5. **Regression, spin or unstated false block?**
   - **No regression:** the full daemon package passes.
   - **No spin:** a `Reseal` that is not due returns `errNothing`, which nudges nothing, and a held node leaves `Observe`'s `Unsealed`.
   - **Unstated blocks:** a lease left active after a seal that never lands (L3); the sweep not running without a runner (L4).
   - **The image hold's check:** its 5 s resolve inside the Unblock command is stated.
