**2. S5 as a relaxation (CPython 3.12.3, audit hook plus `sys.setprofile`):**
- **Type parameters on a def:** `def f[T, U](x: T) -> U` imports nothing. The only frame it runs is the compiler's `<generic parameters of f>`. The same holds for `[T: int]`, `[*Ts]` and `[**P]`, and the guard still blocks those three.
- **Type aliases:** `type X = 1` and `type Pair = tuple[int, int]` import nothing and run no frame. The value is lazy: `type X = undefined_name` builds fine, and `NameError` comes only on `__value__`.
- **Scoping:** decorators and defaults are evaluated outside the annotation scope (probe: both saw the outer `T`). So a type parameter named `pytest` or `SKIP` cannot shadow a decorator or a condition. Controls that still block: `x=g()`, `x: g()`, `-> g()`, `[T = int]`, `type A = (lambda: g())`, `type X = pytest.skip('y')`, `type X[T] = …`.
- **Forcing the lazy value:** `type A = feature.flags.SKIP; B = A.__value__` now passes. It is equivalent to `B = feature.flags.SKIP`, which the assignment branch already accepts, and `pyConst` still bars calls in the value.
- **A truthy alias:** `type SKIP = False` makes `SKIP` truthy (a `TypeAliasType`). A skipif reading it still blocks: "may be a string" when local, "rebinds" when it shadows an import or sits in `cfg.py`.
- **`type pytestmark = pytest.mark.skip`:** now passes. pytest's `normalize_mark_list` raises `TypeError` on it, so collection fails closed [INFERENCE: pytest is not installed here]. Plain `pytestmark = pytest.mark.skip` passes on both main and the PR anyway, and `type pytestmark = pytest.mark.skipif('x')` still blocks.
- **Docstrings:** `"a" "b"` and `b'a' b'b'` run no code.

**4. The claimed equivalent mutation for S4:** CPython 3.12's `ast.parse` requires `!`, `:` or `}` after a top-level `=` in a field.
- Rejected: `f"{x = 1}"`, `f"{a<=}"`, `f"{a ==}"`.
- Accepted: `f"{a!=b}"`, `f"{a<=b}"`, `f"{a=:}"`, `f"{a=!r:>10}"`.

So `pyDebug` matches exactly the debug specifier on valid source. The mutant (`pyDebug` always true) only also drops the `=` characters of comparison operators, and those bind nothing. The two differ only on source CPython rejects, such as `f"{x = 1}"`, which pytest cannot import anyway. A walrus cannot sit at a field's top level, because `:` starts the format spec. I accept the claim.
