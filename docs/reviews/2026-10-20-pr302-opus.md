### High

**H1. One hostile usage report stops every placement in the project, with no hold.**
- **Where:** `internal/dispatch/usd.go:160`, `:167`, `:173`, which reach `Match` through `spent` at `:110-112`.
- **Input:** another task of the same project has a call with one `adapter_report` delta of `in: 3_000_000_000_000_000` tokens. Its lease settles with that call as a liability. Probe result:
  - `cost` returns `ledger: the price overflows the contract's integer range`.
  - `Match` returns that as a plain error, not a `*Refused`. This happens for every node of the project for the rest of that UTC day, and for every node of that task with no end date.
  - No `budget_rail` hold is named, and `task.raise_rail` cannot clear it.
- **Same result from an inconsistent standing:** `ledger.StandingOf` returns `In: maxAmount`, and any price above $1/Mtok overflows `PriceTokens`. P17 plan §3 says an inconsistent standing counts as unaffordable, meaning refused.
- **Also:** in the loop at `:171-175`, `err` is overwritten for each group, so an error on any group but the last one is lost and that group costs 0.
- **Fix:** price with saturation, the way the liability ledger already does ("no input wedges a lease or a group"). A price overflow, or an `Inconsistent` standing, becomes a cost past every rail. `Match` then refuses with `budget_rail_reached` and names the hold. Use saturating adds in `spent`. Add rows for the huge delta and for the inconsistent standing.

**H2. With no `Rails`, a priced executor is not checked (the lead's decision; the builder is fixing it).**
- **Where:** `internal/dispatch/usd.go:50-53`, and the `r.cap < 0` skip at `:72`.
- **Input:** `Dispatcher{Registry: reg}` with a cash-priced builder places a lease whatever the spend. A `Rails` that returns `graph.DefaultCaps` (`NoUSDRail`) does the same.
- **Fix:** refuse when `e.Price != nil` and either `Rails` is nil or the cap is below 0. Update the doc comment at `usd.go:25-26`, the `Dispatcher.Rails` comment and the PR body's "`DefaultCaps` has none… does not check USD" bullet. Add a row.

### Medium

**M1. Spend is priced at today's registry, not at the grant.**
- **Where:** `internal/dispatch/usd.go:126-131`.
- **Inputs:**
  - The operator retires an executor (removes it from the registry). Every `Match` of any task that ever leased on it then errors with "is not registered", forever for that task and for that grant day for the project. This is the same kind of stall as H1.
  - An executor re-registered at a lower price, or as `free`/`local`, reprices past spend downward. For example, $5 spent at $1/$4 drops to $0, so the spend is undercounted.
- **Fix:** carry the executor's declared price on the lease at grant (in the lease record, or with the grant time in `lease_grants`), and price from that. An executor missing from the registry then cannot stop placement, and a price edit cannot rewrite spend. If that is out of scope here, refuse with the hold rather than erroring, and record the repricing as a residual.

### Answers to the six questions

1. **Undercount.** Apart from H2 and M1, I found no spend that escapes.
   - **Hostile zero or negative final:** it counts at the liability, 1,000 tokens in the fixture and in `TestUSDTaskRail`. Negative amounts are refused by `priced` and clamped to 0 by `saturated`.
   - **Reported cost:** never read; `PriceMicros` prices tokens at the declared price.
   - **Lease settled between match and launch:** its settled figure is never above the live figure it was counted at.
   - **Replaced attempt:** the old lease settles first and stays on the same node and task.
   - **Superseded review:** the predecessor node keeps its task, so its leases still count.
   - **Call with no usage:** a live lease counts its reservation; an ended one counts its liability, which is at least the reservation.
   - **UTC day crossed mid-lease:** charged to the grant day (L7).
   - **Arithmetic:** integer micros through `big.Int`, rounded up, no floats; each cost is at most 2^53.
2. **The raise.**
   - `to_usd` cannot lower a cap: `to <= cur` is refused in both the logic and the fold, and `Rails` takes the larger value.
   - `to_usd` cannot set a count rail; `raisedTo` refuses it.
   - `per_day_usd` is kept out by the schema enum, the logic and the record schema.
   - Replay runs `raisedTo` and the cap-in-force check.
3. **Launch without the budget re-check:** safe.
   - One writer connection (`_txlock=immediate`), so each `Match` sees earlier grants' reservations. Two leases that each fit alone cannot both pass together.
   - The Destinations re-check at launch digests the executor, price included, so a price change between grant and launch is still a miss.
4. **`lease_grants`:** its time is `ev.At`, which equals `tx.Now()`, the time `Match` used to pick the day. A rebuild replays it the same way.
5. **The fixture:** green unmutated and red under `rails.usd-settled-only`, as observed above. See L5.
6. **No regression against #295:** all five packages pass under `-race`. The edited tests only add the USD caps, and the `ClearRail` test now uses an unknown rail. The only new failure mode is H1.
