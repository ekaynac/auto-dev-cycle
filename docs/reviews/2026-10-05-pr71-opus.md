### Does it prove the exit-check row?

Yes. The row reads: "`adcd`, `adc`, `adc-agent` install into an empty prefix; `adc version` reports the schema-set
digest", run "against installed artifacts ..., never the source tree". The script:
- refuses a prefix that already holds anything;
- installs from `dist/<os>-<arch>` with `install -m 0755`, which copies the target when the source is a symlink;
- runs each installed binary by absolute path, from a fresh `mktemp -d` working directory, under `env -i` with a
  scratch `HOME`;
- requires each binary to report its own name, this platform, a commit, and a well-formed `sha256:` set, with one
  commit and one set across all three, equal to `--expect` when given.

The schema set is computed from embedded bytes (`internal/buildinfo`), and builds use `-trimpath`, so nothing in
`version` can read the source tree. The `make ci` line now matches note 01. `install-check` depends on `dist` and
`build`, and make runs each of those once per invocation, so `make ci` does not rebuild. Platform mapping:
`x86_64` gives amd64 and `aarch64` gives arm64, and `dist` builds both linux platforms, so both CI runners resolve to an
existing `dist/linux-*`.

Fooling attempts that **failed** (good):
- A pre-populated prefix, or a regular file as the prefix, is refused.
- A symlink to an empty directory is accepted; it really is empty, so that is correct.
- A dangling symlink makes `mkdir -p` fail.
- A symlinked dist binary is copied, not linked.
- `sed` field extraction fails closed:
  - pretty-printed JSON, or a missing key, gives an empty field and the script dies;
  - two matching lines produce a value that does not compare equal;
  - escaped quotes inside a JSON value cannot match `"key":"`.

### High

None.

### Medium

- **M1 — `Makefile:77`: an empty `--expect` silently turns off the expect comparison.** The expected value comes from a
  `$(... | sed ...)` substitution inside an argument, so neither `set -e` nor `pipefail` sees it fail. If `bin/adc version
  --json` fails, or its output shape changes so the sed matches nothing, the script receives `--expect ""`. Its line 60
  (`[[ -z "$expect" || ... ]]`) then skips the check, and the target still passes without the "matches the source build"
  guarantee the PR describes. I confirmed this: `install-check.sh --expect "" P` passes. Fix options:
  - make the script refuse an `--expect` value that does not match `^sha256:[0-9a-f]{64}$`; or
  - capture the value in a variable in the recipe and test that it is non-empty before calling the script.

  The recipe's `sed` also duplicates the script's `field()` (line 47), so the same parsing decision lives in two
  places.
- **M2 — `test/installcheck/installcheck_test.go:71`: the test checks mode with `os.Stat`, which follows symlinks.**
  If the script's `install` line is replaced with `ln -s <dist>/$b $prefix/bin/$b`, the test still passes. In the real
  case `dist/` is inside the source tree, so that mutation means the installed binaries live in the source tree, which
  is exactly what the exit check forbids. The script is correct today; the test just would not catch the regression.
  Fix: use `os.Lstat` and require `fi.Mode().IsRegular()`. A `cmp` against the dist file is also cheap. Replacing
  `install -m 0755` with plain `cp` also survives, because the fakes are written 0755. Writing the fakes 0700 and
  asserting 0755 after install would catch that.

### Low

- **L1 — `test/installcheck/installcheck_test.go:36`: the "outside the source tree" proof is narrow.** The fake binary
  only refuses `pwd == <the test package directory>`. Mutating the script to `cd "$(dirname "$0")/.."` (the repo root)
  survives. A stronger fake would refuse any working directory under the module root, by prefix-matching the caller's
  module root.
- **L2 — `scripts/install-check.sh:54`: the test does not pin the digest length.** Weakening the regex to `^sha256:`
  survives, because the only malformed case tested is `sha1:00`. Add a `sha256:abc` case.
- **L3 — `scripts/install-check.sh:50`: scrubbing `HOME` is not tested.** `HOME="$HOME"` survives. The marker variable
  covers `env -i` itself, so this is minor.
- **L4 — `scripts/install-check.sh:36`: the `-d` part of the emptiness test is never exercised.** Dropping it survives,
  although `mkdir -p` would fail on a regular file anyway. Add a regular-file prefix case if you want the refusal message
  pinned.
- **L5 — `scripts/install-check.sh:55`: the commit is checked only for being non-empty and agreeing across the three.**
  `unknown` (the Makefile's fallback with no git) passes, and nothing compares the commit with `git rev-parse HEAD`. In
  CI the checkout is a real git tree, so this only matters for a stale `dist/` used directly via `make dist &&
  scripts/install-check.sh` across commits. Optional: add `--expect-commit` and pass `$(COMMIT)` from the Makefile.
  Dirty builds are not refused either: `VERSION` carries `-dirty` but is not checked. The exit check does not require
  that.
- **L6 — `scripts/install-check.sh:50` against docs/design/m0/00:46 ("clean sandboxed prefix"): the run is scrubbed
  but not filesystem-isolated.** It uses `env -i` and a scratch working directory, not a mount namespace, so the
  binaries could still reach the source tree by absolute path. With embedded schemas and `-trimpath` this is enough for
  `version`. It is worth a sentence in the script header, or running under bwrap later when the installed
  `adc dev fixtures --contract` row reuses this harness.

### Nits

- `scripts/install-check.sh:35-38`: a prefix beginning with `-` reaches `ls -A` and `mkdir -p` as an option. Using
  `ls -A -- "$prefix"` and `mkdir -p -- "$prefix/bin"` costs nothing.
- `scripts/install-check.sh:18-24`: `--dist` or `--expect` as the final argument with no value falls through to the
  usage error. That is acceptable, but `install-check.sh --expect` alone treats `--expect` as the prefix.

### Lead notes (applied before merge)

- **M1:** a given `--expect` must be a `sha256:` digest. An empty or malformed one (a failed `bin/adc version` upstream) is now an error instead of skipping the comparison. Both cases are tested.
- **M2:** the script checks that each installed file is a regular file, not a symlink, and the test checks the same with `Lstat`. The fake binaries are written 0700, so a plain `cp` would not produce 0755.
- **Lows:**
  - The fakes refuse to run anywhere in the repository tree or with the caller's HOME, so a scrubbed HOME and a scratch working directory are both tested.
  - A short schema set and a non-hex commit (`unknown`) are refused and tested. The commit must be 7 to 64 hex digits.
  - `ls` and `mkdir` take `--`, so a prefix starting with `-` is handled.
- **Noted, not changed:**
  - A dirty build is not refused, because `make ci` must run in a dirty local tree. CI builds a clean checkout.
  - The "sandboxed prefix" is met by environment scrubbing, not filesystem isolation. The binaries' `version` reads only embedded data.
  - The installed commit is not compared with git HEAD; the source build's schema set is.
