### High

**H1. A failure while the facts are gathered leaves the attempt and its lease live, with no runner.** This answers judge items 1 and 6.
- `complete` returns before any command when any of these fail:
  - `r.stopped` (`internal/daemon/run.go:356`);
  - `r.diff` (`:365`);
  - the blob `Put` (`:371`).
- That breaks the promise that every step is tried whatever an earlier one returned.
- **Probe:** the builder edits, then the clone vanishes before the diff. The controller git refuses ("the controller repository's configuration changed"). The end state: attempt **finishing**, lease **active**, node claimed, no result.
  - Restart recovery skips `finishing` ("the completion path's"), so this stays stuck even across restarts until 5c-2c lands.
  - A live lease means the unit is neither unplaced nor granted, so the loop never touches the task again. Admission stays held.
- **Shutdown probe:** I cancelled the daemon context during the run. The end state: attempt **lost**, lease **active**, no result.
  - `stopped` and `started` read through `View(ctx)`, which fails on a cancelled context.
  - `internal/daemon/daemon.go:285` says "each run ends with ctx, its completion recorded". That is false.
  - The same applies to the launch-error path at `run.go:215`. If the launch committed but `started()` fails on the context, `endLease` does nothing (the lease is active), and the started attempt is left behind.
- **Fix:**
  - Read under `context.WithoutCancel(ctx)` everywhere after the launch: `started`, `stopped`, and `accept.Diff` with a bound of its own.
  - When the facts cannot be gathered, still run the steps: lose if running, seal, record `could_not_run` (e.g. `ambiguous_state`/`store_unreadable`) with no attempt, then `endActive`.
  - Correct the comment at `daemon.go:285`.
  - Add rows: the diff fails after a submit, and a context cancelled mid-run. Each must end with the attempt sealed and the lease settled.

**H2. A persistent failure before the launch spins the loop with no bound.** This answers judge item 6, unbounded work.
- The cycle:
  1. The run fails before the launch.
  2. `endLease` releases the lease.
  3. `r.done()` (`run.go:142`) nudges the loop. `Executor.Run` returned nil (`ran++`), which nudges it too.
  4. The next pass matches again, grants a new lease, and starts a new run with a **fresh clone**.
- No rail counts it, because no attempt starts.
- **Probe:** `TestAFailureBeforeTheLaunchEndsTheLease`'s setup (exchange root missing) under `Loop.Run` produced **78 leases granted and released in 3 s**. Each one cloned the repository and appended about 4 events. That is roughly 9 M events a day.
- Realistic triggers: an unreachable repository URL, a broken sandbox root, an unwritable exchange root, a bad profile.
- **Fix:**
  - Raise a node hold on a failure before the launch. `source_invalid_config` with a runner signal fits, cleared like 5c-1's placement holds; or apply a bounded backoff.
  - At the least, do not nudge after a failed run.
  - Add a row: N passes under a persistent pre-launch failure create at most one lease.

### Medium

**M1. The adapter's jail is `--dev-bind / /`, with no network or mount namespace** (`internal/adapterhost/session/process.go:120`). It runs as adcd's own user. This bears on judge items 4 and 5.
- **What the adapter process can reach:**
  - the event store, so it could write the SQLite file directly, which makes `attempt.finish`'s system-action check moot for it;
  - the blob store, including the acceptance blobs (the I18 path);
  - the controller's secrets file;
  - the clone's `.git` under `<state>/clones`, which the controller's `accept.Diff` later runs git on;
  - the network, bypassing the gateway.
- Today the only confinement is the adapter's own code. http-chat's `workspace.ts` is careful: `O_NOFOLLOW`, a realpath check, symlinks refused. But `--adapter PATH` runs any binary.
- `runnerOf`'s comment (`internal/daemon/wiring.go:104`) says "apart from the state directory a run must never see". That holds for the exchange and the sockets, not for the adapter process.
- Option A is the accepted design, and I17 stays GAP. But the jail is cheap to tighten now:
  - `--ro-bind` only `/usr`, `/lib*`, `/bin` and the adapter's directory;
  - `--bind` the workspace, the exchange and the socket;
  - `--tmpfs /tmp` and `--unshare-net` (the gateway is a unix socket);
  - nothing from the state directory.
- Otherwise, state the residual in the PR body and the inventory.

**M2. A panic in a run kills adcd.**
- The run goroutine (`run.go:133`) has no `recover`. The loop recovers panics in its actions, but `Executor.Run` only starts this goroutine, so the protection does not reach it.
- A panic in `graph.Build`, `accept.Diff` or the host takes down the controller with the attempt mid-run.
- **Fix:** recover in the goroutine. Treat a panic like H1's fact failure (lose, seal, end the lease), log it, and keep `live` cleanup in a `defer`.

### Low

**L1. A nested `.git` is silently dropped from the patch.** `CopyTree` skips every entry named `.git` at any depth (`internal/sandbox/run.go:268`).
- **Probe:** the builder wrote `sub/.git/config` (with `fsmonitor`) and `sub/x.go`. The result was `found`, and the patch held `sub/x.go` only.
- `.GIT` is `unsafe_output`, but a real `.git` is not.
- That is safe, but the patch is then not exactly what the workspace holds.
- **Fix:** treat any `.git` below the root as `unsafe_output`, as its look-alikes are. A top-level `.git` file can stay ignored, since the workspace has none of its own.

**L2. A symlink pointing outside the tree is committed as `found`.** **Probe:** `evil -> /etc/passwd` was recorded as a mode-120000 patch.
- No escape happens here, because CopyTree copies links as links.
- **Fix:** state that the accept or integrity guard (5c-2b) refuses symlinks whose targets leave the tree, or refuse them here as `unsafe_output`.

### Judged and found sound
- **Two runners (item 2):** the in-memory `live` set covers the whole run, `Run` returns false while it is set, and the launch command rechecks the lease's revision. I found no path that starts two runs on one attempt.
- **The gateway (item 3):** `end` unbinds once (`sync.Once`), outside any transaction, and settles under `WithoutCancel` within `settleBound`. The run ends it after `Run` and before the result. A launch miss or an early failure ends it through the `defer`, and no adapter ran there.
- **`attempt.finish` (item 5):** it is now in `systemActions`, `authorizeSystem` requires a system actor, and the identity recheck needs the in-process system principal, so an API caller cannot forge it. The adapter has no store handle except the filesystem (M1).
- **No regression:**
  - `newEgress` fails only on missing fields, so building it unconditionally adds no false block at start;
  - the placer's credentials are now the gateway, still inert while launch is inactive;
  - `Executor.Run` for `Run` takes no command, and with no runner it gives `errNothing`.
- **Prepare** spawns nothing (the probe runs over the exchange only), so a launch miss leaves no process.
