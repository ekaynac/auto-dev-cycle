# PR #52 (adapter notifications): Astra reviews

## Review of #52 (Astra, 2026-10-04)

Verdict: NO-GO

1. **High — Usage requires an authoritative ID the adapter cannot obtain.** [schemas/adapter/event.json:109](/tmp/claude-1000/-home-mega-auto-dev-cycle/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ad/schemas/adapter/event.json:109) references the persisted `UsageMeasurement`, requiring `id: msr_…` and `lease: lea_…`. Note 09’s methods provide neither a measurement-ID allocation mechanism nor the lease. A conforming adapter must therefore invent controller-owned data or rely on an unspecified protocol. The three deferred adapterhost checks do not resolve this. Schema probes confirm that an adapter-chosen measurement ID passes and omitting it fails.

   **Fix:** Define an adapter usage payload containing measurement facts and sequence; have the controller mint the measurement ID and derive the lease and authoritative call identity. Reuse common measurement fields without importing the persisted record’s identity requirements. Constrain this payload to deltas and define how reported provenance becomes trusted `source_of_truth`. Add refusal and round-trip cases for that boundary.

2. **Medium — Turn numbering conflicts with the coverage records it feeds.** [schemas/adapter/event.json:23](/tmp/claude-1000/-home-mega-auto-dev-cycle/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ad/schemas/adapter/event.json:23) permits `0..9007199254740991`, while `manifest-delivery.json:12` requires `1..1000000`; finalized coverage also uses one-based turns. The adapter fixtures explicitly start at zero. Valid adapter notifications therefore cannot necessarily become valid manifest evidence, and no translation rule is specified.

   **Fix:** Align the domains, or document a deterministic adapterhost mapping, including turn scope across sub-calls and overflow behavior. Test a first-turn notification through manifest delivery/finalization.

All 14 kinds otherwise match note 09’s notification table. The sub-call label choice preserves controller authority; the error hints cover the specified conformance classes. Closed objects prevent an extra outcome field, and handle names exclude raw paths. The mediated-result/null-handle and complete/empty-unobservable conditions are correct.

The remaining checks properly need runtime state: bind envelopes to the originating attempt/call; validate handle ownership and safe ingestion; verify delivered handles against actual controller supplies; preserve declarations as declared-only; make compaction/internal tools reduce coverage; and accept stale-attempt usage without accepting stale outputs. The conformance kit must exercise these behaviors—schema validation alone does not establish them. The explicitly deferred delta-kind check is also necessary: `final` and `provider_reconciliation` currently pass the notification schema.

`make ci` **passed**, including tests, sandbox self-tests, generation checks and cross-builds. Shellcheck was skipped because it is not installed locally. No tracked files changed.
### Lead notes on round 1 (applied)

- High: the `usage` event carries a report, not the persisted record: `sub_call`, `sequence` (per call, from 0),
  `tokens`, `turns`, `milliseconds` and `cost`. The controller mints the measurement id, takes the lease and attempt
  from the envelope it fenced, records kind `delta`, and sets `source_of_truth` itself (`gateway_count` when its
  gateway counted the call, `adapter_report` otherwise). The token and cost shapes are reused from
  `records/usage-measurement.json`, now as its named `$defs` with the same Go type names. Naming a measurement id,
  a lease, a kind or a source is refused.
- Medium: adapter turns are 1-based, `1..1000000`, the same domain as `manifest-delivery` and `manifest-finalized`;
  a test keeps the two domains equal, and a zero turn is refused.
