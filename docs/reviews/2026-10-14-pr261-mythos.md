Reviewed `0404f26` (the diff from `ac2c049` and the full branch from the merge base `57210c9`), the Astra and Opus reviews, and the PR's Round 3. Read-only; no tests or mutations run. No Critical or High finding. Astra's H1, M2, M3, M5 and M6 are closed in the code, and M4 is the accepted residual. Four Low findings follow, none blocking.

### Answers to the questions

**1. H1 and M2 are closed.**
- `internal/adapterhost/remove.go:100-108`: a lifted name is returned only after `Renameat2(..., RENAME_NOREPLACE)` succeeded. EEXIST retries at most 3 fresh names; any other errno breaks and the source stays. `RemoveAt` (`remove.go:70-74`) appends only those names, so the queue holds only subtrees that were actually moved out, each a distinct directory. The loop is finite without the budget and bounded by it.
- A pre-planted name in the 24-hex space needs 96 bits from `crypto/rand`. Astra's planted ancestor now yields EEXIST three times and the subtree stays, as `TestALiftCollisionEnds` asserts (4 visits, not 65,536).
- Budget and cancellation: `Visit()` is charged at the top of every `removeTree` call and per entry of the sweep; `c.stop()` is rechecked per batch of 256 (`remove.go:122`). `lifted` and `todo` are bounded by visits, since each lift cost one. Descriptors: at most two per level over depths 0 to 2 plus the parent; stack depth 4. Only the first error is kept. `refuseRoot` returns `(false, nil)` once the budget is spent (`internal/recovery/orphans.go:128`), so remaining claimed roots wait rather than being swept.
- Budget exhaustion leaving the next start stuck: for a static tree every visit on a regular file or an empty directory is progress, and a lift costs one visit and moves one directory, so a tree of any width or depth converges in ⌈entries/65,536⌉ starts. The one non-converging case is L1 below. It needs the strongest D43 attacker and affects garbage only.

**2. M3 is closed.** `remove.go:96` chmods through `/proc/self/fd/<fd>` of the `O_PATH|O_NOFOLLOW` descriptor before the `depth == maxDepth` branch. The magic link resolves the pinned inode, never a name, so a rename swap cannot redirect it. Every depth is covered: the root at 0, `in/` (0555) and `out/` at 1, their entries at 2, a lift at 3, and a lifted directory again at 0. `TestModeZeroAtTheLiftBoundary` exercises depth 3 and depth 4 as non-root. The lift also needs write on the depth-2 parent, which was chmodded on its own visit, and on `top`, the controller's directory.

**3. M5 and M6.**
- The recording bound is real: `recorded = decided && err == nil` (`orphans.go:157`) is computed before the rename, so a committed refusal takes a slot even when the rename fails. A replay never runs `decide`, so `decided` stays false. At most 16 roots × 65 events per start. Roots past the cap are still `claimed`, so the sweep leaves them (`orphans.go:88`).
- `*contract.Error` is exactly the deterministic class. It is produced only by `contract.validate` (embedded schemas: unknown schema, parse, schema violation) and by `Decode`/`Encode` marshal mismatches. Storage faults go through `Tx.io` as SQL errors, and the writer wraps them without a contract error (`internal/eventstore/writer.go:553`). The store wraps the validation failure with `%w` (`store.go:528`), so `errors.As` reaches it, which the passing `a_refusal_the_store_rejects` subtest confirms. A validation failure cannot surface as something else: with the clamp in place and the handle schema `^[^\x00]*$` at maxLength 1024 (names are at most 255 bytes, invalid UTF-8 is replaced by `json.Marshal`, the detail is truncated by `lease.Refusal`), the detailed refusal cannot fail validation at all. The fallback is reachable only through the test seam, which is fine for a safety net.

**4. Round-2 regressions.** None found. The clamp (`orphans.go:183-188`), the `Run` independence assertion (`orphans_test.go:243-249` runs `Run` with `Exchanges` set and checks the root is untouched), idempotency (same key and input `{attempt}` for the detailed and summary commands; the first rolls back before the command row is written, so the key is free), the `O_PATH|O_NOFOLLOW` root open with the `fstat` uid and 0700 check, `out/` opened beneath the root descriptor, `fstatat(AT_SYMLINK_NOFOLLOW)` on entries, and a leftover `refused-<name>` symlink being unlinked rather than followed all hold. The bounded-descriptors test moved to `remove_test.go` intact. The "failing root takes no slot" property changed deliberately under M5: a root failing at commit (non-contract) takes none (`TestAStorageFaultKeepsTheDetailedRecord`); a root failing at rename takes one once, and replays are free.

**5. Size.** 383 added + 17 removed = 400, at the ceiling. Nothing is padding. The only non-load-bearing code is the `may still publish` assertion (`orphans.go:147-149`, 3 lines), kept on purpose per Round 1 L5. The `liftName` and `submitRefusal` seams are needed by the H1 and M6 regressions.

### Findings

**L1 (Low). The sweep charges the budget for entries it never removes.** `orphans.go:85-88`: `c.Visit()` runs before the prefix test, so every entry of the exchange directory costs one visit. An adapter with write access to `Host.Root` (D43's strongest attacker) that plants more than 65,536 entries with neither prefix spends the whole budget on junk at every start. On tmpfs readdir is newest-first, so junk planted after the roots is read first. Refusals are unaffected because the roots loop runs first, and `refuseRoot` charges ENOENT roots nothing. Only `refused-*` garbage is never collected, and `errWork` is reported each start. Fix: charge the visit only for a name the sweep acts on (move `c.Visit()` inside the `if`), and check `c.stop()` once per batch for cancellation. Net zero lines.

**L2 (Low). `RENAME_NOREPLACE` is EINVAL on file systems without rename2 flags.** `remove.go:102-105`: on NFS, 9p and FUSE daemons without `rename2`, the first lift returns EINVAL, the loop breaks, and a subtree past depth 3 is never removed. The root stays, with an error at every start. Only a hostile adapter builds depth above 3, since design note 09 forbids subdirectories in `out/`. The daemon already requires `RENAME_NOREPLACE` for its token file (`internal/daemon/recover.go:180`), and tmpfs, ext4, xfs, btrfs and overlayfs (runtime-created upper directories) all support it. Fix: either fall back to plain `Renameat` on EINVAL (the 96-bit name makes an overwrite negligible, and a non-empty destination still fails), or record `Host.Root`'s file-system requirement next to the `/proc` one in #226 entry 81.

**L3 (Low). Reading on after unlinking within the same directory descriptor.** `remove.go:116-121` and `orphans.go:83-91` keep reading batches from a descriptor whose entries the batch just unlinked. Go's `os.RemoveAll` reopens the directory after each batch because some file systems skip entries after mid-iteration unlinks (Go issue 20841). Here the consequence is a `rmdir` ENOTEMPTY that is reported and finished at the next start, with progress made each start. No loop. No change needed at the ceiling; note it beside the `/proc` limit if a later PR touches `Cleanup`.

**L4 (Low). P22a obligation: authorise `recovery.refuse_output` for the system actor.** If the Authorize hook refuses the command, the store commits a refused disposition under the key `recovery.refuse_output/<root>`. Every later start then replays `ErrNotApplied`, the root is never renamed, and it is reported at each start without taking a slot. The tests' authorizer accepts it, so nothing in this PR detects a missing wiring entry. Fix: add `ActionRefuse` to the P22a list in #226 entry 81 next to the three step actions.

### Cut set (M4)

`cutAttempts` (`orphans.go:102-119`) selects `lost_reason == controller_restart` regardless of status, so a sealed-from-lost attempt is still in the set, and a `running` attempt still refuses the stage. A stopping attempt's root is unclaimed and swept with no event, as Round 3 says. The residual in #226 entry 80 is the right place for it.
