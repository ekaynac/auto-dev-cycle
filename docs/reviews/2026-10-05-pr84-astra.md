# PR #84 (conformance kit, part 2a): Astra reviews

## Review of #84 (Astra, 2026-10-05)

Verdict: NO-GO

The requested sandbox command passed: **15 tests and TypeScript checking**. Additional in-memory adapter probes reproduced the false greens below. No repository files were modified.

### High

1. **A missing `tool.response` acknowledgement passes.**  
   `adapters/conformance/src/kit.ts:451–454`

   Removing the acknowledgement from `tool-clean`, while preserving its exact delivery report, produces `[]`. At EOF, `Session.request()` returns `null`; `if (reply && !empty)` silently accepts it. The background exchange is never required to finish successfully.

   This leaves #81 round-1 finding 4 partially unresolved: non-empty acknowledgements fail, but absent acknowledgements pass.

   **Fix:** report a missing acknowledgement, track outstanding exchange tasks, and settle their validation before finalizing findings. Add controls for missing acknowledgements, including EOF and shutdown while one remains pending.

2. **`toolRoundTrip` passes without exercising a delivery round-trip.**  
   `adapters/conformance/src/kit.ts:473–474`, `:498–505`

   A raw adapter can emit a valid `tool.request`, immediately return a valid `could_not_run/attempt_stopped` run result, and acknowledge shutdown. With neither a tool acknowledgement nor a delivery report, the result is `[]`.

   Independently of finding 1, acknowledging `tool.response` but never reporting its delivery also passes when the run returns `could_not_run`. The completion guard skips every unreported delivery, and the exercise check requires only a request.

   **Fix:** require at least one fully validated acknowledgement-and-delivery exchange for `toolRoundTrip`, independently of the run outcome. An interrupted case that never exercises that exchange must report incomplete exercise. Keep `cancelDuringTool`’s separate allowance for stopping without a delivery.

### Medium

3. **Policy enforcement ignores reported harness-internal tools.**  
   `adapters/conformance/src/kit.ts:437–440`, `:467–468`

   Both new cases return `[]` when an otherwise conforming adapter additionally reports a harness-internal `Shell` result and correctly declares partial coverage. The supplied policy allows only `RunTest`; `Shell` appears in neither policy list.

   The new checks enforce policy on `tool.request` only. Correctly marking coverage partial does not authorize the reported tool.

   **Fix:** validate reported harness-internal tools against `tool_policy.allowed`, alongside mediated-request validation. Add this negative control to both cases.

### Other checks

The random challenge, structural handle comparison, turn/tool attribution and single-use delivery tracking address the demonstrated forged, guessed, replayed and mis-attributed delivery failures. Non-empty acknowledgements are rejected.

The reply-waiter change passed probes with two outstanding tool requests and reversed acknowledgements. Delayed invalid tool/cancel replies were still validated. Deadline expiry settled concurrent waits promptly; missing cancel acknowledgements were reported.

`cancelDuringTool` now sends cancel after a valid tool request while withholding its response. It accepts both completion and stopping, validates the run independently, and rejects invented delivery evidence. Those aspects resolve #81 finding 5.

The [mutation claim](https://github.com/ekaynac/auto-dev-cycle/pull/84) is defensible **under its stated unguessability assumption**: an exact unpredictable handle establishes that the adapter learned the delivery. Removing the timestamp comparison is therefore computationally redundant, though not unconditional semantic equivalence. The early-result control uses an incorrect guessed handle, so it does not independently test ordering. The reported mutation score does not cover the missing-acknowledgement and unexercised-exchange failures above.

## Second review of #84 (Astra, 2026-10-05)

Verdict: GO with changes

No Critical/High findings remain.

- **Round-1 High 1 — fixed.** Missing acknowledgements fail at EOF and deadline. A completed first exchange does not conceal a second missing acknowledgement.
- **Round-1 High 2 — fixed.** Request-only and acknowledged-but-unreported runs fail. Acknowledging one delivery and reporting another cannot satisfy the exercise check.
- **Round-1 Medium 3 — fixed for the reported bypass.** Harness-internal `Shell` results fail in all three cases. Policy construction has the nonblocking issue below.

**Medium — the advertised policy disagrees with enforcement and can violate its schema.**  
[adapters/conformance/src/kit.ts:328](/tmp/claude-1000/-home-mega-auto-dev-cycle/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-kit/adapters/conformance/src/kit.ts:328), with enforcement at line 491.

The schema describes `allowed` as harness-owned tools and `mediated` as controller-mediated tools. The kit advertises `allowed: ["Edit", "RunTest"]`, but rejects a correctly declared harness-internal `RunTest` result as unauthorized.

Additionally, `toolRoundTrip(adapter, "Edit")` sends `allowed: ["Edit", "Edit"]`, violating `uniqueItems`. An adapter validating `prepare` rejects this; the permissive raw adapter passes with `[]`.

**Fix:** construct distinct policy lists, excluding mediated names from the harness list, and validate harness results against the exact policy sent. Add a schema-validating `prepare` control and an `Edit` collision control.

Additional probes confirmed:

- Concurrent requests with reversed acknowledgements pass; delayed invalid tool acknowledgements fail.
- Missing cancel replies fail at EOF and deadline. Delayed invalid replies fail; delayed valid replies pass.
- A completed run with a second unreported delivery fails. A stopped run with one complete exchange and another acknowledged-but-unreported delivery passes, consistent with the explicit allowance for interrupted runs.

Both surviving mutation claims are defensible within their stated limits:

- **Ordering:** computationally redundant under unguessable delivery digests, not unconditional semantic equivalence. Removing the comparison in memory preserved the tested outcomes. The guessed-handle control still fails handle matching; it does not independently test ordering.
- **`settle()`:** equivalent in the current runner. `wake()` releases pending waits, and the surrounding awaited shutdown/end paths let exchange validation finish before findings freeze. Removing the call in memory preserved the EOF, deadline, split-exchange and cancel probe outcomes. Keeping it makes the guarantee explicit.

The requested sandbox command passed: **16 tests and TypeScript checking**. Probes and mutations ran in memory; no repository files were modified, and the worktree remains clean.
