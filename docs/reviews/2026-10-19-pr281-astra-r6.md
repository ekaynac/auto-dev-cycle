**Medium M1 — An accepted pytest decorator can execute a repository function at import.**

Location: `internal/accept/integrity_pyimport.go:385`.

Concrete input:

```python
# cfg.py
ENABLE = False

# flags.py
SKIP = False

# conftest.py
import pytest
import cfg
import flags

def park(f):
    flags.SKIP = cfg.ENABLE
    return f

@pytest.mark.usefixtures(park)
def unused():
    pass

# tests/test_z.py
import pytest
import flags

@pytest.mark.skipif(flags.SKIP, reason="r")
def test_z():
    assert False
```

Change only `cfg.ENABLE` to `True`.

The grammar accepts the proven pytest root and bare-name argument. `park`’s body is excluded from import-time inspection. However, a mark called with one function and no keywords marks and returns that function. Consequently, decorator application calls `park(unused)` during import and writes `flags.SKIP`. Both closures miss that execution. This follows directly from [pytest’s `MarkDecorator.__call__`](https://docs.pytest.org/en/stable/_modules/_pytest/mark/structures.html#MarkDecorator).

**Fix:** bluntly reject mark-decorator calls with one positional argument and no keywords unless the argument is syntactically guaranteed non-callable; retain explicit `.with_args(...)`.

This is **nonblocking under the stated accepted-form/pytest residual**: the syntax is expressly listed by the grammar, and I found no regression against main. It does invalidate unconditional semantic inertness for that listed form.
