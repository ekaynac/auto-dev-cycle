### Medium — The entry rule also rejects ordinary parent directories

**Location:** [docs/design/m0/07-project-profile.md:133](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-b2b/docs/design/m0/07-project-profile.md:133)

“Other non-blob entry … at any of its parent components” includes Git **tree** entries. Literally implemented, this refuses every nested declaration, such as `config/required.json`, despite the general repository-relative path contract.

**Fix:** Require each parent component to be a directory/tree entry and the terminal entry to be a regular-file blob. Explicitly reject symlinks and gitlinks in either position. Add fixtures accepting an ordinary nested path and rejecting a parent replaced by a symlink **only in the prospective tree**.

### Medium — Reading and validating hostile declarations has no resource bound

**Location:** [docs/design/m0/07-project-profile.md:139](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-b2b/docs/design/m0/07-project-profile.md:139)

The accepted format permits arbitrarily large arrays and strings. Deeply nested JSON is invalid, but the contract does not require rejection before a general decoder allocates or traverses it. A repository contributor can therefore supply input whose rejection consumes excessive memory or processing time. Neither profile-document limits nor note 09’s adapter-output ingestion bounds explicitly cover these Git reads.

**Fix:** Specify bounded blob reading and parsing, including a byte limit and early rejection of nested values. Bound key count/string length directly or through the byte budget. Exceeding a bound must return `could_not_run`, preserve the hold, and avoid crashing the reader. Add oversized and deeply nested fixtures.

### Medium — Adoption validation lacks an explicit base-head concurrency binding

**Location:** [docs/design/m0/07-project-profile.md:142](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-b2b/docs/design/m0/07-project-profile.md:142)

Validation runs before adoption (`07:172`). It can validate head A, then a merge under the still-disabled mechanism can remove the declaration at head B before adoption applies. Note 04 binds the profile revision and approval’s expected state; it does not explicitly bind this newly introduced Git-head precondition. Note 13’s expected-base CAS protects **merge**, not profile adoption.

This creates an unusable adoption, rather than an approval bypass: subsequent comparison against B still fails closed.

**Fix:** Record the validated base commit and declaration identity as adoption preconditions. Coordinate adoption with base updates and refuse/revalidate if the head changes before application. Add a fixture moving the base between validation and adoption, including removal of the declaration.

### Remaining requested edge cases

- **Unicode normalization:** Byte-for-byte lookup excludes implicit NFC/NFD normalization. Canonically equivalent spellings remain distinct Git identities, and neither redirects the declaration read. An NFC/NFD fixture would help preserve this property; checkout aliasing is not a demonstrated bypass of this reader.
- **Candidate-only parent symlink:** Explicitly rejected in the prospective tree. The fixture requested above should exercise it.
- **Delete and re-add within one candidate:** The final prospective tree controls. Different final bytes require integrity approval; identical final content and mode introduce no declaration change. Final absence remains `could_not_run` and cannot be waived by an integrity answer.
- **Attributes, filters and LFS:** The raw-blob contract excludes smudge/text conversion and LFS dereferencing. A normal LFS pointer fails JSON validation. Clean-filter output already committed to Git is the authoritative blob. Add an attribute-only-change fixture to guard against accidental transformed reads.
