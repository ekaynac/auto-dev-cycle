## Opus pre-review of #235

Verdict: **GO with changes**

I ran `go test ./internal/results/... ./internal/sandbox/... ./internal/profile/...` at e1e5488 and all three packages passed. I removed the scratch worktree afterwards. I built no images, so I could not check the base digest against the registry.

### High

**H1. Packages that never run read as a pass.** `internal/results/gotest.go:98-106, 196-202`
- `go test ./...` has no end-of-run event. The adapter only knows about packages that appear in the stream.
- A run killed between packages leaves a clean stream: a gate timeout while the next package is still compiling, or the `go` process being killed. `Passed()` is then true. Only the expected tests become `Missing`.
- A `TestMain` that narrows `-test.run` has the same effect: every test that passed at the base and did not run is invisible.
- This is the F case ("a missing test read as a pass") one level up, and the PR leaves it to P15.
- P15's row (§5.2) and its fault column do not promise this. The verdict may not use the exit code (I13), so nothing catches it today.
- **Fix:** give the adapter the base's results, for example `ParseGoTestJSON(stream, expected, base *Report)`. Mark every base package or test that is absent at head as `Missing`.
- Add a fault test: a stream cut at a package boundary must not pass.

**H2. An unexpected skip passes the report, and the backstop the PR names is not contracted.** `gotest.go:12-18, 104-105` (deviation 2)
- The builder relies on P15's baseline and on accept's `fault-test-deletion-skip`. Neither is merged.
- `fault-test-deletion-skip` is specified only for pytest (`@pytest.mark.skip` in py-mini, §2.6 line 439). Nothing says P14's integrity guard detects Go `t.Skip`.
- Even if it did, a guard that reads the diff misses skips caused by non-test code: a helper or init that makes `testing.Short()`, an environment check or a precondition skip.
- `ReasonGateTestFailed` only covers a test that *failed* relative to the baseline, not one that *skipped*.
- As written, a test that passes at the base and skips at head is `Passed()`.
- **Fix:** the same base-aware API as H1. A test is a pass only if it is `pass`, or it was `skip` at the base too. This keeps the 3 root-only skips green, because they skip at the base, and removes the dependency on P14 and P15.
- Alternatively, keep `Passed()` strict (any skip fails) and add a separate baseline-relative verdict.
- At minimum, record the obligation in P15's row and in #226 with a fault case ("pass at base, then skip at head, then gate failed"), and rename `Passed()` so P15 cannot use it naively as the gate verdict.

### Medium

**M1. "Output text is never parsed" overstates the guarantee.** `gotest.go:22-23`
- test2json builds the Action events from the test binary's stdout. I checked this on go1.27.1:
  - Code in a non-test file, `init(){ if testing.Testing() { fmt.Print("\x16=== RUN   TestHidden\n\x16--- PASS: TestHidden (0.00s)\n\x16PASS\n"); os.Exit(0) } }`, produced `run`/`pass` for `TestHidden` and a package `pass` with exit 0. The real `TestHidden` calls `t.Fatal`.
  - A test that prints `\x16--- PASS: TestGhost` also creates a `pass` for a test that never ran.
- Worst-wins does not help when the real test never runs. The hidden test's name can be read at runtime from the package directory.
- No adapter-only fix exists, because the attacker runs in the same process.
- **Fix:**
  - Correct the comment to name the limitation.
  - Add the case to §2.7's hostile-repo list or #226, with P14's integrity guard as owner: `testing.Testing()` or `os.Exit` in non-test code, and `\x16` written to stdout.
  - Note it for the independent review.

**M2. The profile's gate was never run in the image.** `fixtures/m1/profiles/auto-dev-cycle.json:23`
- The gate is `./...`, but only `./internal/{cli,api,results}/...` was run in the image.
- The whole repository's test link step under a 256 MiB `/tmp`, together with tests that need podman or root behaviour under `--network=none` as uid 0, has not been tried.
- Deviation 1 (narrowing by a not-yet-built overlay) is acceptable as a placeholder, but it should not be the only record.
- **Fix:**
  - Either run `go test -json ./...` once in the built image and report the counts (failures and skips per package), or use `./internal/cli/...` for the first target as §2.3 literally says.
  - Record the narrowing as a P24/P25 driver obligation in #226.

**M3. #226 entry 30 is still open, and the image baseline will differ from the host baseline.**
- `fixtures/m1/issues/170/baseline.json` (#234) records 0 skipped on the host. In the image, as uid 0, `internal/cli` has 3 skips: `TestTokenOutSystemErrorCouldNotRun`, `TestVerifyLogReadOnlyState` and one more.
- These are permission tests, unrelated to #170 item 3 (independent-review output). So they do not undermine the target, provided the hidden tests do not depend on file-mode refusals.
- **Fix:** state in the PR or in #226 entry 30 that the re-record will show `skipped: 3`. Do it in the pinned image once the digest exists.

### Low

- **L1. The working tree is hashed, not the base.** `scripts/prepare-go-image.sh:27-37, 48` hashes the lockfiles in the working tree, not at the base commit. A dirty tree or the wrong checkout yields a label P9 later refuses (this fails safe). **Fix:** refuse when `git -C "$repo" status --porcelain -- go.mod go.sum` is not empty, and print the HEAD commit in the build message.
- **L2. The NAME check is weaker than P9's.** `prepare-go-image.sh:47` accepts `adc/prepared`, which `Resolve` refuses (the registry needs a `.` or `:`, or must be `localhost`). **Fix:** apply the same rule as `sandbox.Resolve`.
- **L3. The label does not bind the base.** `Containerfile:12` makes `ARG BASE` overridable, and the label binds only the toolchain key and the lockfiles, not the Go version or the base digest. A `--build-arg BASE=…` build carries a valid label. **Fix:** drop the `ARG` (hard-code the `FROM`), or add the base digest to the label. Extending P9's check would be a later item.
- **L4. Possible gaps in `protected_paths`.** "Security configuration" and "the test sandbox" in 04 §3 are vague. Consider adding `internal/testguard/**`, `internal/profile/**` (the protected-path matcher itself) and `internal/contract/**`. None is required by criterion 2.
- **L5. Expected subtest names.** Go rewrites spaces as `_` in subtest names. P15 should normalise expected subtest names the same way, or reject them with spaces.

### Confirmed sound
- **Adapter:**
  - Package `fail`, `build-fail` (including a bare one) and a panic all fail the report.
  - A cut mid-test is `incomplete`.
  - Worst outcome wins, and the `(package, name)` key separates duplicate names across packages.
  - An expected test that is skipped or missing fails.
  - An expected test removed by `-run` filtering becomes `Missing`.
  - An empty stream, blank lines, non-JSON, `null`/`{}`, an unknown action, a missing package and oversize lines are all `ErrUnreadable`.
  - A stream of skips only does not pass.
- **Profile:**
  - `https` URL (#226 entry 28) and a fully qualified pin (entry 19).
  - Every criterion-2 path and every contract package is covered, plus the lockfiles (§8 item 2) and the recipe and adapter.
  - The digest pin is a placeholder (entry 7), which is acceptable with the operator steps given.
- **Image recipe:**
  - The base is pinned by digest. I could not verify that it is the multi-arch index digest.
  - `go mod download` with no arguments covers go.mod's pruned requirement list, which is enough for `go test` of the main module. `go mod verify` runs before `GOPROXY=off`.
  - The warm cache is content-addressed: a stale `warm.txt` costs only time.
  - `GODEBUG=goindex=0` affects only cmd/go's module index.
  - The label is JSON parsed by the same `Manifest` struct. `TestPreparedManifestMatchesP9` proves the generator agrees with `CheckManifest`, and refuses when `go.sum` differs.
- **Credentials:** none are used, printed or baked in. The build context holds only `go.mod`, `go.sum` and `warm.txt`; there are no build args or secrets; nothing is pushed.
- **Fault evidence:** discriminating for an *expected* test that is skipped or missing. It does not cover a non-expected test that passes at the base and then skips or goes missing (H1, H2).
- **Deviations:** 3–6 are acceptable. 1 and 2 are acceptable only with the fixes above.
