# PR #100 (adapter host ingestion boundary): Astra reviews

## Review of #100 (Astra, 2026-10-06)

Verdict: NO-GO

Reviewed PR #100 at `10b38e2`, including its description, lead plan, design 09, blobstore, implementation, and tests. The current head contains two commits.

1. **High — PR #100: a racing hard link bypasses the boundary.** [internal/adapterhost/ingest/ingest.go:231](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah4/internal/adapterhost/ingest/ingest.go:231)

   Link count is checked only during initial inspection. Neither the reopened-file check nor the final check validates it. On sandbox tmpfs, creating an outside hard link at the `checked` hook published successfully with **`nlink=2`**, on both paths, on the first attempt. Unchanged ctime defeats detection; the digest cannot detect another link.

   **Fix:** require `Nlink == 1` on the reopened descriptor and final fstat. Add this race as a refusal test under both paths, asserting no blob or temporary file remains.

2. **High — PR #100: pathname reopening can open a substituted special file.** [internal/adapterhost/ingest/ingest.go:174](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah4/internal/adapterhost/ingest/ingest.go:174)

   After checking the `O_PATH` descriptor, the code resolves the attacker-controlled name again with `O_RDONLY`. Replacing the inspected regular file with a FIFO produced an **`IN_OPEN` event before refusal**, under both paths. The subsequent inode comparison is too late to prevent opening it. A reachable device replacement similarly reaches device-open handling; `O_NONBLOCK` is not a general device safety boundary. [Linux open documentation](https://man7.org/linux/man-pages/man2/open.2.html)

   **Fix:** obtain the readable descriptor from the pinned, verified regular-file descriptor through a trusted mechanism, without resolving the attacker’s pathname again. Test substitutions for special files, including absence of I/O opens.

3. **High — PR #100: fallback does not enforce the same mount boundary.** [internal/adapterhost/ingest/ingest.go:118](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah4/internal/adapterhost/ingest/ingest.go:118)

   Equal `st_dev` does not establish equal mounts. In a rootless test namespace, a same-filesystem bind-mounted outside file had link count one and passed the fallback, publishing successfully. Native `openat2` rejected it. Different-device mounts were rejected by both paths.

   This requires the mount to be visible in the ingester’s namespace; an adapter’s private mount alone does not establish that. Nevertheless, the advertised fallback equivalence fails: `RESOLVE_NO_XDEV` rejects bind mounts too. [Linux openat2 documentation](https://man7.org/linux/man-pages/man2/openat2.2.html)

   **Fix:** compare descriptor mount identities, including the reopened descriptor, and fail closed when equivalent verification is unavailable. Add same-device bind tests.

4. **Medium — PR #100: refusal categories misidentify two failures.** [internal/adapterhost/ingest/ingest.go:176](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah4/internal/adapterhost/ingest/ingest.go:176), [ingest.go:194](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah4/internal/adapterhost/ingest/ingest.go:194)

   An unchanged mode-000 file returns `replaced`, although it is merely unreadable. Separately, corruption of an existing stored blob becomes adapter `unsafe_output/digest`, because blobstore uses `ErrDigestMismatch` for both incoming and stored content. Both cases were reproduced.

   **Fix:** classify access/I/O failures as `unreadable` unless replacement is established. Distinguish incoming digest mismatch from stored-blob corruption and propagate the latter as a store error.

The requested command passed with Go 1.27.1, `GOTOOLCHAIN=local`, and `CGO_ENABLED=1`, including a fresh run through `scripts/test-sandbox.sh`:

Additional review conclusions:

- Single-component validation and no-follow resolution protect against supplied path traversal, ordinary symlinks, and magic-link traversal. The held directory descriptor survives replacement of `out/`.
- Zero bytes, exactly the bound, bound+1, malformed digests, partial reads, and EPERM fallback passed additional probes. Go retries interrupted reads; interrupted opens currently refuse safely.
- Observed refusals published no new blob and left no temporary file. Blobstore aborts reader/digest failures before rename. Its later durability errors can occur after publication and are separate store errors.
- The documented same-size rewrite limitation preserves the digest of the copied stream, **not snapshot consistency or metadata invariants**. A same-tick move outside `out/` after reopening also escaped change detection in a probe.
- Existing tests meaningfully exercise both paths, but miss the failures above. Their “during copy” payload fits in one copy buffer, so they do not exercise mutation between data chunks.
- The hard-link mutation is honest: disabling only that check through a temporary overlay made the unchanged hard-link refusal tests fail on both paths.

### Lead notes on round 1 (applied)

- High 1 (hard-link race): the link count must be 1 on the inspected O_PATH descriptor, on the reopened descriptor and in the final statx after the copy. At inspection a count above 1 is `hard_link`. On the reopened descriptor and after the copy, any failed check (link count included) is `replaced`. New table cases create an outside hard link at the `checked` hook and during the copy, and unlink the file during the copy. All are refused as `replaced` under both paths, with no blob and no temp file left.
- High 2 (pathname reopen): the attacker's name is resolved exactly once, to the O_PATH descriptor. The readable descriptor comes from `/proc/self/fd/<n>` of that pinned, verified regular inode (`O_RDONLY|O_NOCTTY|O_CLOEXEC`, without `O_NOFOLLOW`), so whatever now sits at the name is never opened. Without /proc, Ingest fails closed with `ErrUnsupported` (see the last note). `TestFIFOSubstitutionNeverOpened` replaces the checked file with a FIFO at the hook and watches it with inotify `IN_OPEN`. It sees no open under either path, and it confirms that the watch does catch a real open.
- High 3 (mount boundary): statx mount ids (`STATX_MNT_ID_UNIQUE`, else `STATX_MNT_ID`; the held descriptors pin their mounts, so a plain id cannot be reused) of out/, the O_PATH descriptor and the reopened descriptor must match. A mismatch at inspection is `special_file` (`replaced` on the reopened descriptor). A kernel that does not report the id fails closed with `ErrUnsupported`. `TestBindMountRefused` uses bwrap to bind an outside file over `out/res` on the same device in a rootless namespace. It runs both paths inside, and is skipped without bwrap. Switching off the mount comparison makes its fallback case ingest, which reproduces the finding (checked locally, then reverted). `TestSameMount` unit-tests the comparison.
- Medium 4 (categories): a reopen failure on the pinned inode (EACCES, EIO) is `unreadable`, so a mode-000 file is refused as `unreadable`. The blob store adds `ErrDeclaredDigest`, which Put wraps together with `ErrDigestMismatch` only when the incoming bytes miss the declared digest. Ingest maps only that error to `digest`. A corrupt stored blob stays a store `ErrDigestMismatch` (tested in blobstore and in ingest).
- The during-copy tests now use a payload of several copy buffers (about 205 KiB), so their mutations land between chunks. A same-size in-place overwrite during the copy is refused as `replaced` or `digest`. The Ingest doc comment states what the checks prove and what the digest does not: it covers the copied stream, but it is not a snapshot of the file's state between reads.
- Alignment with 09 (#101): a host that cannot verify the boundary (statx reports no mount id, or `/proc/self/fd` is missing) has a capability gap; the adapter is not at fault. Ingest returns `ingest.ErrUnsupported`, which is not an `*Unsafe`, so the host refuses to start attempts (`could_not_run`) and never marks one untrustworthy for it. `ingest.Supported()` is a cheap probe the host calls before it starts an attempt: an O_PATH open of `/`, statx, and a /proc reopen. Tests cover both gaps through Ingest and through Supported.

## Second review of #100 (Astra, 2026-10-06)

Verdict: GO with changes

Reviewed `6e7d3b8` and `10b38e2..HEAD`. No Critical/High findings remain.

1. **Handled — link count.** Inspection, reopened-descriptor validation, and final validation require `nlink == 1`. Later violations become `replaced`. Hard-link creation and unlink races pass refusal/cleanup tests under both paths.
2. **Handled — pinned reopen.** Only the initial `O_PATH` open resolves the supplied name. Type validation precedes the `/proc/self/fd/<pfd>` readable open. The FIFO substitution test confirms no `IN_OPEN`, with a positive control proving the watch works.
3. **Security fix handled; classification incomplete — mount identity.** Directory, inspected, and reopened descriptor mount IDs are compared. Requesting both ID flags prefers the unique ID, consistent with the [kernel implementation](https://github.com/torvalds/linux/blob/v6.11/fs/stat.c#L231-L242). Same-device bind mounts are refused under both paths. Missing result fields return `ErrUnsupported`; syscall failures have the gap below.
4. **Handled — failure categories.** Mode-000 files become `unreadable`; incoming mismatches become `digest`. Clarification: `ErrDeclaredDigest` identifies **incoming** mismatches. Stored corruption correctly propagates `ErrDigestMismatch` **without** `ErrDeclaredDigest` or `*Unsafe`.

New findings, all non-blocking:

- **Medium — unavailable `statx` is classified as adapter failure.** [internal/adapterhost/ingest/ingest.go:130](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah4/internal/adapterhost/ingest/ingest.go:130): every syscall error becomes `unreadable`, including `ENOSYS`. `Supported()` wraps this as unsupported, but `Ingest()` does not. **Fix:** classify unavailable boundary-verification capabilities as `ErrUnsupported`, preserving genuine file I/O failures as `unreadable`. Add injected syscall-error tests alongside missing-mask tests.

- **Low — maximum bound overflows.** [internal/adapterhost/ingest/ingest.go:306](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah4/internal/adapterhost/ingest/ingest.go:306): the pre-existing `bound+1` overflows for `math.MaxInt64`, making `LimitReader` immediately return EOF and falsely refusing valid nonempty files. **Fix:** use overflow-safe limit arithmetic and add a small-file/maximum-bound test. This does not permit excess copying.

- **Low — package documentation overstates stability.** [internal/adapterhost/ingest/ingest.go:9](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah4/internal/adapterhost/ingest/ingest.go:9) promises a file “stayed the same.” The `Ingest` comment correctly disclaims snapshot consistency. **Fix:** align the package summary with those sampled checks; also clarify that an undetected rename outside need not move back.

Additional verification:

- All owned descriptors have cleanup on ordinary error returns; the caller retains its directory descriptor.
- Copying is bounded, subject to the overflow issue above. Boundary failures occur before publication; temporary files are closed and removed. Refusal tests assert empty blob and temporary directories.
- Mutation payloads are **210,000 bytes**, spanning multiple 32-KiB copy buffers.
- Both requested commands passed using Go 1.27.1. Fresh `-count=1` runs also passed for both race-tested packages and the sandbox suite. The verbose sandbox run had **no skips**, including bind-mount and unreadability tests.

Suggested additional tests: missing mount metadata at each later descriptor check; legacy-only mount IDs; `EPERM` fallback; descriptor-leak checks after repeated failures; zero/exact-bound/growing-past-bound files; and corrupt-store cleanup under both paths, asserting unchanged stored bytes and no temporary file.

No checkout files were modified.

### Lead notes on round 2 (applied)

- Medium (unavailable statx): a syscall error that means the capability is missing (ENOSYS, EOPNOTSUPP), from statx, from the name resolution or from the /proc reopen, is `ErrUnsupported`, as is a missing /proc and any required statx mask field missing at any of the four descriptor checks (out/, the O_PATH fd, the reopened fd, after the copy). Genuine file failures (EIO, EACCES) stay `unreadable`. `TestStatxFailuresAtEachCheck` injects ENOSYS, EOPNOTSUPP, EIO and a missing mount id or size at each of the four calls, under both paths, and asserts that nothing is published.
- Low (bound overflow): the copy limit is the declared size plus one (size never exceeds the bound), computed without overflow at `math.MaxInt64`. `TestBounds` covers an empty file, a file of exactly the bound, a small file under the maximum bound and a file that grows past the bound during the copy.
- Low (package documentation): the package summary now describes sampled metadata checks rather than a snapshot. The Ingest comment says an undetected same-tick rename out of out/ need not move back.
- Suggested tests: legacy-only mount ids (`TestLegacyMountID`), EPERM fallback (`TestEPERMFallback`), no descriptor leak after 30 refusals per path (`TestNoFDLeak`), and corrupt-store cleanup under both paths with the stored bytes unchanged and no temp file left (`TestCorruptStoredBlobIsStoreError`).
