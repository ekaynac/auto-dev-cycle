### High

**H1. `review.Parse` accepts keys that differ only in case, and they can flip the verdict.** `internal/review/review.go:106-121`
- **Cause.** `contract.ReadStrict` finds duplicate keys only when they match exactly. `contract.UnmarshalStrict` then uses `encoding/json`, which matches field names without regard to case. So `DisallowUnknownFields` passes a key like `"Decision"`, and the last of the matching keys sets the field.
- **Probed inputs:**
  - `{"decision":"no_go","summary":"","findings":[],"Decision":"go"}` parses as `go`. `Result` then records `empty/completed_clean`, a GO.
  - `{"DECISION":"go","summary":"","findings":[]}` parses as `go`.
  - `…"findings":[{"severity":"high","title":"t","detail":"d","Severity":"low"}]` parses with severity `low`.
- **Why it matters.** `defaultDecisionSchema` has `additionalProperties: false` and is case-sensitive, so a reader that follows the schema refuses all three. A reader that takes the first key reads `no_go`. The PR promises "no unknown field", read by the controller, which "never trusts the adapter's check". This is a parser differential on the verdict itself. In M1 it is mitigated only by the adapter's own ajv check.
- **Fix.** Walk the tree that `ReadStrict` returns and require the top level's keys to be exactly `{decision, summary, findings}` and each finding's to be exactly `{severity, title, detail}`. Or decode from that tree instead of the raw bytes. Add `TestParse` rows for `"Decision"` beside `"decision"`, and for a finding's `"Severity"`.

### Medium

**M1. An empty contributor set counts as independent at the commit.** `internal/graph/contributors.go:37-65`, `:78-87`
- **What happens.** A build whose result was recorded with no lease (graph `Commit` without an attempt; `attemptBound` is optional) has a proposer of unknown family. `Contributors` returns `[]`, so its review is claimed and its GO committed. The PR's own test does exactly this: `internal/graph/repair_test.go:65` and `:83` commit a GO review of `other`, a build that never had a lease.
- **Why it matters.** This contradicts 06 rule 3 and `receipt.Independent` (`internal/receipt/applies.go:124-126`, "no families to compare against … is not independent"). The PR's residual covers only the claim-time case ("no builder attempt yet"), but the commit check is meant to close exactly that.
- **Fix.** In `Contributors`, count `receipt.UnknownFamily` for a build node of the task that has a recorded result and no lease on its unit. Add a row: a GO review of a build with no lease is refused at the commit.

**M2. The repair round feeds the builder a review result whose lineage is empty (I18, #289, #226 entry 91(3)).** `internal/review/review.go:237-239`, `internal/graph/repair.go:38`, `:52-55`
- **The chain.** `findings-<n>` gives the repair builder the reviewer's decision. The reviewer's context includes the gate report built with the acceptance overlay. Entry 91(3) lets only the reviewer take that report, through declassification, "never the builder". Yet `seal` records `Lineage: []`, so #289's `intent.Builder` walk (`graph.Records`, built on `Ref.Lineage`) sees no acceptance edge.
- **Input.** A no_go whose finding title names an acceptance test id seen in the sanitised gate report, such as `"TestAcceptanceHidden fails"`. It reaches the repair builder's request.
- **Why not High.** Every producer on main seals `Lineage: []`, and entry 91 already gives truthful lineage to P22a. So this follows main's convention, but P16b adds the first edge from a review into a build.
- **Fix.** Add to the residual, and to entry 91's P22a list:
  - `review.Result` takes the review's claimed input ref ids (for example a `Facts.Inputs` field) as the lineage of its decision and report refs;
  - a decision is recorded on whether a repair builder may take findings derived from a declassified gate report. Either the controller derives a builder-safe findings view, or `intent.Builder` refuses and the repair stops.

  Otherwise the first truthful lineage makes every repair round refuse its intent, or quietly declassifies to the builder.
