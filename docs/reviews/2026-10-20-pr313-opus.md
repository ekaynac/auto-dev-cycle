## Opus review of #313 (2026-10-20)

Verdict: GO with changes

Basis: I read the PR, `git diff origin/main...HEAD`, §2.3, §2.8 and the P25 row. I ran probe tests and the PR's mutation script in a scratch copy of the worktree at `911b9ed`, then deleted the copy. All the results below were seen in that run. To look for test gaps I also ran 12 extra mutations through the same harness.

### High

**H1. A call the gateway counted can show as zero outstanding, and a zero or too-low final counts as settled.** This breaks §2.8's "never as zero" and §2.3 item 7.
- **Where:** `internal/bench/bench.go:193-216`. It sorts calls into charge or outstanding using only `ledger.Call.Uncertain` and adds up `c.Usage`. It ignores `Counted`, `Seen` and `Floored`, and it does not use `ledger.StandingOf`. The ledger itself says a final settles a call only as `StandingOf` trusts it (`internal/capacity/ledger/ledger.go`, the `Call` doc).
- **Input 1:** a call whose only report is the gateway's (`gateway_count`, delta, in 5000, out 500). This happens whenever an adapter dies before it reports. The review stage records tokens `0/0/0/0` and outstanding `{cash, "", 0 micros, 1 call}`: a liability listed as zero. The schema allows it, because its currency pattern accepts an empty string (`schemas/records/benchmark-run.json:88`).
- **Input 2:** an adapter `final` of 0/0/0 plus a `gateway_count` of 5000/500. The call is recorded as settled, `charge=[{cash USD 0 1}]`, with tokens 0. The ledger would hold it as an unsettled liability at 5000/500.
- **Fix:**
  - For each call, take `st := ledger.StandingOf(usage, id)`.
  - Put the call under charge only if `st.Settled`.
  - Take tokens from `*st.Usage`, which includes the gateway's count.
  - Price an unsettled call whose adapter cost is missing or lower with `ledger.PriceMicros`. `Meta` would need each route's registry price.
  - Refuse an outstanding amount of 0 with an empty currency, and drop `^$` from the currency pattern.
  - Add rows for both inputs.

### Medium

**M1. One call reported under attempts of two stages is counted twice.**
- **Where:** `bench.go:136-143`. Measurements are grouped by `u.Attempt`, not by `u.Call`, and each stage runs its own `Reconcile`. The usage-measurement schema accepts reports "from any attempt".
- **Input:** call C has a delta (1000/100, 3000 micros) on a build attempt and a final (1000/100, 3000 micros) on a review attempt.
  - Build records 1000/100 tokens and 3000 micros outstanding. Review records 1000/100 tokens and 3000 micros charge.
  - The call is really 1000/100 at 3000 micros, so tokens are doubled and the charge is both settled and outstanding.
  - If the final is in EUR, the two-currency refusal does not fire, because the reports never meet in one `Reconcile`.
- **Fix:** map each call to a stage first. Refuse a call whose measurements' attempts map to two stages, then reconcile per stage.

**M2. `Record` silently accepts inputs it cannot attribute.** Each of these was seen in the probe run:
- **Unknown intervention stage** (`bench.go:152-154`, `175-189`): `{Stage:"", Kind:Approval}` and `{Stage:"deploy", Kind:"nudge"}` are dropped without an error. The stage loop never visits them, so even the unknown kind is not refused.
  - Fix: before the stage loop, check every intervention: kind must be approval, answer, rail_raise or rescue, and the stage must be in `Stages` unless it is a rescue.
- **Zero `Claimed` with `Done` set** (`bench.go:126`, `171`): accept's `wall_ms` becomes 9223372036854, about 292 years, and it passes the schema.
- **Zero `Approved` with `Closed` set** (`bench.go:113-117`): the task's `wall_ms` gets the same value.
  - Fix for both: refuse `Approved.IsZero()` and `Claimed.IsZero()`. A node with neither time is now counted as "unfinished", but the schema defines unfinished as "claimed and not finished".
- **Bad closure state** (`bench.go:112-121`):
  - Closed and held: the hold is dropped.
  - Neither closed nor held: the task is recorded as "open".
  - Closed with an empty outcome or reason: `Record` returns no error, but `json.Marshal` of the run then fails.
  - Fix: refuse all three.
- **Run-level checks** (`bench.go:97-107`):
  - An empty run gives `tasks: []`, no error.
  - Two tasks with the same ID, attempt and call are both accepted, which double counts the call across tasks.
  - Fix: refuse `len(tasks)==0`. Check task IDs, attempts and calls across the whole run.
- **No schema check on output:** `Record` never validates what it returns (for example `routes` needs at least one item, and `hold` must be a `Name`).
  - Fix: run the result through `contract.Decode` before returning it.

**M3. The basis depends on report order, so output is not deterministic.**
- **Where:** `bench.go:197-200`, `cmp.Or(basis[u.Call], u.Cost.Basis)`: the first basis seen wins.
- **Input:** one call with a `delta` at basis `cash` and a `final` at `subscription_equivalent`. In one order it records `cash`; in the reverse order, `subscription_equivalent`.
- Live, every call also has gateway reports, which always say `USD`/`cash` (`internal/modelcall/modelcall.go:411`). So a subscription route's charge flips depending on the order reports arrive in. `Reconcile` itself is order-independent.
- **Fix:**
  - Take the basis from adapter and provider reports only (skip gateway reports, i.e. `counts(m)`).
  - Refuse a call with two bases, as currencies already are.
- Everything else is deterministic:
  - every map is sorted before output;
  - node times in another time zone give the same figures;
  - `RecordedAt` is converted to UTC. No test covers that conversion, though: removing it survived a mutation, because the test time is already UTC.

### Low

- **L1. Gaps in `Compare` and `Summary`.**
  - `Compare` never compares `unfinished` (`internal/bench/compare.go:292-296`). Adding an unfinished build node produced no delta.
  - `total()` adds micros across currencies (`compare.go:329-335`), so a rise in one currency can hide behind a fall in another. Compare each basis and currency pair instead.
  - `Summary` leaves out `unfinished`, interventions and sources.
  - `Summary` does not escape the hold (`compare.go:353`); a hold of `a|b` breaks the table.
- **L2. The template asks for output that has no renderer.** `docs/design/m1/exit-record-template.md:31` says "paste `bench.Compare`'s output", but `Compare` returns `[]Delta`. Add a Markdown renderer for deltas, or say how to render them.
- **L3. The file name gets a slash from `arch`.** The schema's `arch` pattern requires `linux/arm64` (`schemas/records/benchmark-run.json:13`), and the file name is `benchmarks/m1/<date>-<arch>-<checkpoint>.json` (`docs/design/m1/00-slice-plan.md:530`, template line 29). That yields a `linux/` subdirectory. Write the name with `GOOS-GOARCH`.
- **L4. Schema tightening (Q5).** Integer milliseconds with min 0 and max 2^53 is correct. Also add:
  - in `BenchmarkTask` (line 40), an `oneOf`: either (`outcome`, `reason`, `wall_ms`) are all set and `hold` is null, or all three are null and `hold` is set;
  - `uniqueItems` on `sources` (line 63);
  - a non-empty `currency`, as in H1;
  - a check of whether `hold` (line 48) should reference the hold or reason vocabulary rather than the free `Name` pattern.
- **L5. Test gaps.** The PR's 17 mutations all die (17/17 killed, all six copies clean). These extra mutations survive:
  - approvals not counted (`bench.go:181`);
  - basis ignored (`bench.go:212`);
  - a stage with only interventions dropped (`bench.go:179`);
  - `RecordedAt` without `.UTC()` (`bench.go:98`);
  - `Compare` ignoring rescues (`compare.go:279`);
  - `Compare` ignoring outstanding, interventions, attempts or rounds (`compare.go:292-296`).

  Add an approval intervention, a basis other than cash, a non-UTC `RecordedAt`, and `Compare` rows for each of those metrics.
- **L6. The size is acceptable.** Non-test code is 376 lines (`bench.go` 234, `compare.go` 142) plus a 104-line schema, against the row's estimate of 350. The fixes above may add about 60. The doc comment's list of refusals (`bench.go:19-21`) is out of date; it should match the refusals once they are fixed.

### Holds

- **Q4, `Compare` never gates:** true, and it is stated. `Compare` returns only `[]Delta` and no error. The same is said in the package doc, the schema description, §2.8 and the template.
- **Overlapping nodes in one stage:** their wall times are added (two 30 s review nodes running side by side give 60 s). That follows §2.8's "summed over the stage's nodes", so it is faithful. A sentence noting it would help.
- **Negative token figures:** `Reconcile` raises them to 0, so no negative figure comes out.
