## Opus pre-review of #290 (2026-10-19)

Verdict: NO-GO

There is one blocker: a regression against main. With this PR, `go test ./internal/gate/` fails on every amd64 host because `TestGateIssue170` breaks. The fix is one line in a test. No input reads as a pass when it should not. The other findings are Medium or Low. They are false holds (`runner_fault`) on real pytest output and on Python layouts, plus some strictness that falls short of what the PR says.

**What holds:**
- **Test run:** `go test -count=1 -race ./internal/gate/... ./internal/results/...` passes in a copy (gate 4.7 s, results 11.5 s).
- **The adapter's limits work.** It rejects a DTD or directive, an entity (`Entity` is an empty map and `Strict` is on), a namespaced element, an unknown element, a second root element, a document cut short (the decoder reports an unexpected EOF), a document with no testcase, a count that is not a number, and a document past `MaxStream`. The `lr.N <= 0` check fires on every token after the read limit is crossed. The decoder refuses UTF-16.
- **Skips and errors stay apart.** A `<skipped>` alone gives Skip. A `<failure>` or `<error>`, with or without a `<skipped>`, gives Fail. At the gate, a Skip is never clean unless the test also skipped at the base and is not expected, and it counts as the candidate's (`judge`: `x.Outcome == Skip`).
- **Merging duplicate testcases cannot hide a failure.** A merged result is always `worse(prior, Fail)`. Any duplicate other than one holding a lone `<error>` is unreadable. I checked this against pytest 9.1.1's `junitxml.py`: when a call fails and teardown then errors, pytest writes two testcases and counts both in `tests`. That matches what the adapter counts.
- **Mutation spot-check.** I applied A7 ("any duplicate merged") in a copy. `TestJUnitStrict` caught it ("one identity twice", "…then a failure"), and so did `TestFixturesAreGreen`. Line 131 ("pytest's teardown shape": a pass, then a lone error, must give Fail) would catch a merge that keeps `prior`.
- **No input found reads as a pass while pytest reported a failure or a skip.** A forged document can only come from code running inside the test process, which the P14c items cover. See Low L5.
- **Registration and the baseline shape check.** An unknown adapter gives `ErrSpec`. The check works both ways: a `go_test_json` baseline has package outcomes and is refused under `junit_xml`; a junit baseline has none, so under `go_test_json` every result fails the package check.
- **`arch: any`** relaxes only `rt.Arch`. Operator precedence is correct (`… || rt.Arch != img && rt.Arch != "any"`). `rt.Os` is never relaxed. The host check sits in `check` itself, and `Resolve` (`image.go:82`) also enforces it.
- **No change to the Go path apart from H1.** For a Go gate, `argv` builds the same command as main, the copy-out bound is still `maxResults`, and `touched` gives the same answers because the `.py` branch only runs under `JUnitXML`. Moving the missing-test logic into `assemble` behaves the same as before for `ParseGoTestJSON`. With main's `gate.go` and `gate_test.go` in a copy, the whole gate suite passes as amd64. With the PR's, only `TestGateIssue170` fails.
- **The two fixtures through the gate.** `fault-lying-runner` (a failure, or a setup error, with `echo "5 passed"; exit 0`) gives `found/gate_test_failed`. `fault-unreadable-results` gives `runner_fault` ("never wrote"). The probe check runs before the results are read, and in that row the stub's Python leaves a record.
- **Real pytest 9.1.1 through the gate.** The PR lists "the collection marker is not exercised" as a residual. I ran real pytest through the gate in a copy:
  - a test that does `monkeypatch.chdir(tmp_path)` came out `empty/completed_clean`, so a chdir after collection is allowed;
  - `cd tests && pytest --rootdir=..` was invalidated.

### High

**H1. A regression against main: `TestGateIssue170` fails on any host that is not arm64.** `internal/gate/gate_test.go:530-532`, caused by `internal/gate/gate.go:354`.
- **Cause:** `check` now requires `in.Image.Arch == runtime.GOARCH`. The #170 baseline was measured on linux/arm64, and the row builds `In` from it.
- **Input:** `GOARCH=amd64 go test -count=1 ./internal/gate/` on this host (run through binfmt):
  - with the PR: `FAIL TestGateIssue170: … refused: the image is linux/arm64, the host linux/amd64, the environment linux/arm64`;
  - with main's `gate.go` and `gate_test.go`: `ok`.
- **Why CI misses it:** the CI runner is self-hosted (`[self-hosted, homelab]`), so this does not show there. It does break `make ci` for amd64 contributors to the open-source release.
- **Fix:** the production behaviour is right; only the row needs to change. Either:
  - skip the `check` half when `runtime.GOOS/GOARCH != b.OS/b.Arch`, with a `t.Skipf` that names the platform the baseline was measured on; or
  - split `check` into a host part and a binding part, and run only the binding part in this row.

### Medium

**M1. The count check counts testcases that hold a child; pytest counts the children. Real pytest 9.1.1 output is then unreadable.** `internal/results/junit.go:143-145`.
- **Input:** real pytest 9.1.1 output for a test whose fixture fails in setup while another fixture's finalizer raises:

  ```python
  @pytest.fixture
  def a(): yield; raise RuntimeError("teardown")
  @pytest.fixture
  def b(a): raise RuntimeError("setup")
  def test_both(b): pass
  ```

  pytest writes one `<testcase>` with two `<error>` children and declares `errors="4"`. The adapter counts 3.
- **Result:** `ParseJUnitXML` returns "testsuite declares 4 errors, holds 3", which the gate reports as `could_not_run/runner_fault`. A real failure is not read as `found`.
- **Older pytest:** pytest 8.3.5 to 9.0.0 still subtract `cnt_double_fail_tests` after a failed call followed by a teardown error. Pass followed by a teardown error is miscounted there too. On those versions every teardown error is unreadable, and the py-mini profile does not pin a pytest version.
- **Fix:**
  - Count children: `failures`, `errors` and `skipped` each add the number of child elements, not `b2i`.
  - Add the document above as a testdata sample.
  - Pin pytest ≥ 9.1 in the py-mini image, or name the version the count rule assumes in `junit.go`'s decision comment.

**M2. The attribute bound also covers free-text `message`. A real failure with a long message is then unreadable.** `internal/results/junit.go:94`.
- **Input (real pytest 9.1.1):**
  - `def test_x(): raise ValueError("x" * 5000)` gives `<failure message="…">` of 5,012 bytes;
  - a parametrize id of 5,000 bytes gives `name` of 5,014 bytes.
- **Result:** "an attribute beyond 4096 bytes", which gives `runner_fault` instead of `found`. Payload errors, `CalledProcessError` output and JSON decode errors commonly run this long.
- **Why the bound adds little:** Go's decoder has already materialised the whole value before the check runs, and `MaxStream` bounds memory anyway. The `message` value is never kept.
- **Fix:** apply `maxName` only to the attributes that are read (`classname`, `name` and the count attributes). Leave the rest to `MaxStream`. Add the 5,012-byte row.

**M3. In Python, a collection error caused by the candidate is attributed to the environment.** `internal/gate/gate.go:383-386` and `:406`. The row at `gate_py_test.go:84` asserts this outcome.
- **Cause:** a Python test module never shares a module with the code it tests. Changing `money.py` therefore never touches `tests.test_money`. If the change breaks that module's import, the report holds a Fail testcase `{"", "tests.test_money"}` (pytest's collection error), and `test_add` and `test_sub` are Missing. Those two count as "theirs", and `theirs > 0` takes precedence.
- **Input:** `Changed=[money.py]`, results: only the collection-error testcase.
  - Result: `could_not_run/runner_fault: 2 results missing … outside the candidate's packages (and 1 of the candidate's)`.
  - The same happens with `tests/conftest.py` or `tests/__init__.py` changed. `tests.conftest` names no test module.
- **Impact:** §2.6 routes `runner_fault` to a `wrong_owner` hold on the environment's owner. The commonest Python builder failure, an ImportError or SyntaxError in the code under test, then becomes an operator hold instead of a repair round.
- **Comparison with Go:** in Go the direct case works, because a test lives in its code's package directory. The cross-package case behaves the same way in Go.
- **Fix:**
  - In `judge`, count a missing test as the candidate's when the report holds a collection-error result (Package `""`, Fail) whose Name equals the missing test's module or is a dotted prefix of it.
  - Map a changed `conftest.py` or `__init__.py` to its dotted directory as a prefix.
  - Update the row so that `money.py` changed plus a collection error gives `found`.

**M4. Under `junit_xml`, Python that a test starts in another directory invalidates every run, baselines included.** `internal/gate/cwd/sitecustomize.py:23` and `gate.go:259`. This is #286's M3 again, now for Python projects.
- **Input:** a test runs `subprocess.run([sys.executable, …], cwd=tmp_path)`. CLI tests commonly do this.
- **Result:** in the copy, `invalidated: 1 … of 3 recorded (the cwd contract)`. No baseline can ever be recorded, which is a permanent hold.
- **Scope:** the P15 row's contract covers "pytest …, wrappers and workers included". It does not cover a test's own subprocesses.
- **Fix:** take the option #286 M3 offered. Buffer records in `sitecustomize`, and flush them only in processes that load the plugin (`pytest_configure`). Keep a pre-pytest record only for a process that later execs pytest, or record `start` from the plugin. Add the `cwd=tmp_path` row.

### Low

**L1. "Content after the root" covers only elements.** `junit.go:87`.
- **Input:** `<testsuite><testcase classname="m" name="t"/></testsuite>5 passed`, or a processing instruction or comment after the root, reads as a pass.
- **Impact:** the result cannot change, but the PR body claims more than the code does.
- **Fix:** after `rootDone`, refuse any `CharData` that is not whitespace, and any `ProcInst` other than the declaration. Otherwise, narrow the claim.

**L2. Attributes are not checked for duplicates or namespaces.** `junit.go:93-97`.
- **Input:**
  - `<testcase classname="m" name="t" name="u">` reads as test `u`;
  - `<testcase classname="m" name="t" x:name="u"/>` with an unbound prefix also reads as test `u`.
- **Why it matters:** XML forbids duplicate attributes, but Go's decoder does not check for them.
- **Fix:** refuse an attribute whose `Name.Space != ""`, and any repeated `Name.Local`.

**L3. The error text says "go test -json stream" for JUnit.** `junit.go:60` wraps `ErrUnreadable`, whose text is `results: unreadable go test -json stream`, so a JUnit error reads "unreadable go test -json stream (junit_xml): …". The gate's `Why` is unaffected.
- **Fix:** make `ErrUnreadable`'s text neutral ("results: unreadable results").

**L4. The probe's environment replaces the profile's and the image's `PYTHONPATH`.** `gate.go:442`.
- **Input:** `sh -c 'PYTHONPATH=src python3 -m pytest … --junitxml="$0"'`.
- **Result:** `of 0 recorded (the cwd contract)`, an invalidation. Any image `ENV PYTHONPATH` is dropped silently in the same way.
- **Fix:** prepend instead of replacing (`sh -c 'PYTHONPATH=dir${PYTHONPATH:+:$PYTHONPATH} exec "$@"'`). Also state in the residual that a profile setting its own `PYTHONPATH` is unsupported.

**L5. The test identity is `classname` + `name`, and pytest's xunit1 family lets a test rewrite both.**
- **Cause:** `record_xml_attribute` changes user attributes, and `record_testreport` applies them over the computed ones.
- **Input:** a candidate adds `junit_family = xunit1`, a passing test that renames itself to the acceptance test's identity, and a deselect of the real test.
- **Result:** the hidden test reads as present and passing.
- **Why Low:** this needs code running inside the test process, which is P14c-2a3/P14c-2b's territory. This PR does not open it, but its residual should name it.
- **Fix:** name it in the residual. Optionally, when xunit1's `file` attribute is present, refuse a testcase whose `classname` does not start with `file`'s dotted form.

**L6. `violations` resolves run-chosen paths on the host.** `gate.go:471` and `:478`.
- **Cause:** in container mode every record should equal `/workspace`. Even so, each record that does not match runs `filepath.EvalSymlinks` on a host path the run picked: up to roughly 1 MiB of log lines, each walked on the controller's filesystem, automounts included.
- **Fix:** resolve `ws` once. Call `sameDir` only for the in-place `Runner`, or only when the record is already under `ws`.

**Mutations:** I re-ran A7 only. The rows named for A1–A13, G1–G13 and F1–F2 exist and assert the stated outcome. G4–G6 rely on the stub, which never loads the plugin. My real-pytest run shows the plugin works, so a row that uses real pytest when it is available would let G5 and G6 cover the collection marker.
