# PR #64 (event store views): review

## Review of #64 (Opus subagent, 2026-10-05)

Verdict: GO

Scope: commit `fcba2d4` on `7976178` (lifecycle.go +15, writer.go +13/-1, view_test.go +101). I worked on a copy at
`scratchpad/rv64`. gofmt and vet are clean. `go test ./internal/eventstore` passes, and `-race -count=3 -run TestView`
passes. I ran the probes as a temporary in-package test (`zz_probe_test.go`, since removed) and mutated the code with a
sed harness.

### What holds (verified by probe)

- **No write path.** A view's `Tx` exposes `Get`, `Keys`, `SubjectVersion`, `Put`, `Delete`, `IntendEffect` and
  `Replaying`, and it offers no SQL. `Put` and `Delete` return `ErrReadOnly` before any statement runs.
  `IntendEffect` is refused because `t.store == nil` (effects.go:76), and the intents slice is consumed only by
  `Submit` anyway. The database refuses writes too: with the guard bypassed, `Put` on the read pool gives
  `attempt to write a readonly database (8)`. The same happens after `PRAGMA query_only=0`, because `mode=ro` still
  applies. `CREATE TEMP TABLE` is refused as well.
- **A view never sees rebuild scratch state.** `temp.proj_rebuild` lives in the writer connection's temp schema, and
  the rebuild always rolls back. A view taken while a rebuild was paused inside the Project hook got
  `no such table: temp.proj_rebuild` and saw the pre-rebuild live values. It also did not block (about 0.4 ms).
- **A view never sees half-applied state.** A view taken while `Submit` was paused inside Project (after the append
  and the proj_kv writes, before commit) saw the previous committed state for both `kinds` and `SubjectVersion`. After
  the commit, the next view saw all of it.
- **Checkpoints do not break the snapshot.** I kept a view open across 50 commits plus PASSIVE, FULL and TRUNCATE
  checkpoints on `s.w`. The snapshot stayed at version 1 throughout, and a later view saw 51. FULL and TRUNCATE waited
  out `busy_timeout` (5 s) and returned `busy=1`, which is correct reader protection. No production code issues
  FULL or TRUNCATE (grep finds no `wal_checkpoint` calls). Only auto-checkpoint (PASSIVE) runs.
- **Close and file identity.** `View` goes through `do`. Admission is refused with `ErrClosed` once closing has begun.
  Close waits for an open view. The device/inode and sidecar checks run before each view. A panic in `fn` still runs
  the deferred `Rollback` and the decrement in `do`. A `Tx` that escapes `fn` gets `sql.ErrTxDone`. A cancelled `ctx`
  fails `BeginTx`, and reads inside the view fail.

### Findings

No High findings.

**Medium 1: the snapshot starts at the first read, not when `View` is called. The doc comment and PR claim are
imprecise.** (lifecycle.go:120, with modernc tx.go:22)
The read DSN has no `_txlock`, and with `ReadOnly: true` modernc issues a plain deferred `begin`. SQLite takes the
WAL read snapshot at the first statement that reads the database, not at `BEGIN`.

Probe P1 shows the effect. Inside `View`, `fn` submits command B first and only then calls `SubjectVersion` and
`Keys`. Both report B (version 2, keys `[00000001 00000002]`). So "a command committed while the view is open is not
in it" is false for any commit that lands between `BeginTx` and `fn`'s first read. `TestView` passes only because
`Get` runs before `submit("two")`.

Nothing in the current API makes this observable as a correctness bug. No head or seq is exposed, so a reader cannot
pair "as of X" with the data. That is why this is not High.

Fix: force the snapshot in `View` right after `BeginTx`, for example `SELECT 1 FROM meta LIMIT 1` (it must touch a
table). Alternatively, reword the comment and PR to "consistent from its first read". Then add a test that commits
before the first read.

**Low 2: the effect-refusal test passes for the wrong reason.** (view_test.go:417)
`IntendEffect(id, "k", ...)` uses an unregistered kind, and the test store configures no `Effects`. Mutant M8 sets
`store: s` on the view's `Tx`, and it survives: the call is refused as `unregistered effect kind "k"`, not because
this is a view. With a registered kind, that mutant silently accepts the intent into a slice nobody reads, so `fn`
would believe an effect was declared. Fix: register an effect kind in the test, and assert the specific refusal (a
sentinel error would help).

**Low 3: "always rolls back" is untested.** (lifecycle.go:124)
Mutant M2 deletes the deferred `Rollback`, and it survives. Mutant M3 turns it into `Commit`, and that is equivalent.
Without the rollback, every view leaks a read-pool connection that holds an open read transaction. That pins a WAL
read mark forever, so auto-checkpoint can never reset the WAL: the WAL grows without bound, and connections pile up
in the unbounded read pool. A test could check `s.r.Stats().InUse == 0` after `View` returns, or check that a TRUNCATE
checkpoint succeeds after a view.

**Low 4: one claimed mutant is equivalent, and the pool mutant is killed only by the global test timeout.**
- Mutant M1 changes `&sql.TxOptions{ReadOnly: true}` to `nil`, and it survives. It is equivalent: the read DSN has no
  `_txlock`, so the driver issues `begin` either way. The PR's "read-only flag" kill presumably refers to the
  `readOnly` struct field (mutant M4, killed). The option is harmless, but it is not tested and does nothing today.
- Mutant M10 swaps `s.r` for `s.w`. It is killed only by deadlock, through `go test -timeout`. The Makefile sets no
  timeout, so under `make ci` the default 10 minutes applies before the failure is reported. A bounded `ctx` on the
  in-view submit would turn that into a quick, legible failure.
- Mutant M9 makes `BeginTx` ignore `ctx`, and it survives. That is minor.

**Low 5: follow-up PRs could trip on the following. These are advisory, not defects in this diff.**
- **Authorization for commands must stay on the writer `Tx`.** A `View` called from inside a hook reads committed
  state, not the writer's uncommitted state. Probe P5: the writer saw `kinds=2` while a nested view saw `1`. The
  identity PR must not reuse a View-based lookup inside `Authorize`. A View is right for authenticating a request, but
  the authority check in 03 step 2 must re-run on the writer `Tx`. Otherwise you get a TOCTOU, for example a grant
  revoked between the two reads.
- **The SSE `/v1/events` endpoint needs a log reader.** The view `Tx` cannot list events, only `SubjectVersion`, even
  though the comment says "snapshot of the live projections and the log". That PR has to add an event reader. If it
  keeps one View open for a whole stream, it pins the WAL (see Low 3) and makes Close wait on the stream. Use one
  short view per batch instead.
- **Close waits on a view whose `fn` blocks.** Read handlers should pass a request-scoped `ctx` and never block inside
  `fn` on anything other than store reads. `fn` must never call Close (documented for `do`).
- **`fn` can hide a cancellation.** If `fn` swallows the `context canceled` error from `Get` and returns nil, `View`
  returns nil. Handlers should propagate the errors from `Get` and `Keys`.
- **Per-view cost.** Each view runs about six `lstat` calls (`checkDBFiles` plus `fileIdentity`) before reading. That
  is cheap, but it applies to every authenticated request.

### Lead notes (applied before merge)

- Medium (snapshot timing): `View` reads once right after `BeginTx` (`SELECT 1 FROM events LIMIT 1`), so the snapshot is taken when `View` begins rather than at `fn`'s first statement. The new test commits inside `fn` before any read and requires it to be invisible.
- Low (effect test): the view's effect intent now uses a registered kind, so a view `Tx` given a store would be caught.
- Low (rollback): `TestViewReleasesItsConnection` checks that the read pool has no connection in use after a view, whether `fn` succeeds or fails.
- The comment now says what a view covers: live projections and subject versions. It also says a view sees committed state only, so a decision that must hold at commit (authorization) runs on the writer's `Tx`, and that views should be short because an open view pins the write-ahead log and Close waits for it. The event stream will need its own event reader.
- Mutation: 8 points, all killed. The pool swap is caught by a 60-second test timeout. `TxOptions{ReadOnly}` to nil is equivalent and not counted.
