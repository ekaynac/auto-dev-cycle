### High

Each platform's `typedOn` group holds one TestMain, so no redeclaration and no shape check. ### Medium

**M1. `mentions` is exponential on an alias DAG and checks no context: a 12-line candidate hangs the guard.** Not a crash, and on main too, but it is the remaining unbounded walk the brief asks about, in the function the PR bounds.
- **Where:** `integrity_go.go:370-384`. `mentioned` holds only the current path (set at `:375`, deleted at `:377`), so a right-hand side reached twice is walked twice; nothing memoises a finished alias, and no `ctx.Err()` is checked inside the walk.
- **Input:** `type A0 = func(A1, A1, A1, A1, A1, A1, A1, A1) A1` … `type A11 = func(A12, …) A12`, `type A12 = int`, in any analysed file. `count` calls `mentions(x.Type)` for each alias (`:425`) and `mentions(f)` for the file (`:605`): 8^12 visits, each with an `alias` call of eight iterations. Hours. `Integrity`'s `recover` and the run's context cannot interrupt it; the controller's goroutine spins until the process is killed.
- **Fix:** memoise per right-hand side (`map[ast.Expr]int8`: visiting, false, true; a cycle stays "mentions", fail closed), which makes the walk linear; or charge each visit to `r.work` against `maxWork` and fail closed past it. Row: the chain above, expected a verdict within seconds.

**M2. `shapes` does not compare variadic-ness, so `func f(a ...int)` and `func f(a []int)` match.** `integrity_types.go:554-561` reads each parameter's type expression; `info.TypeOf` of an `*ast.Ellipsis` is the slice type. The two gate builds then differ in how calls compile, which the guard types against the first declaration only. I found no fact that hides behind it (a call that compiles under one declaration does not under the other, and the gate fails), so Medium for the gap, not for a route. Fix: append whether the last parameter is an `*ast.Ellipsis` to the shape, or use `types.TypeString(info.TypeOf(d.Name))` for the whole signature (it prints `...`), which also covers the receiver.

**L1. A new declaration whose type holds an exported or embedded path to a testing struct is now a fact, in test and non-test code alike.** `integrity_types.go:676` fires `fillable` on every var and type name definition. `type suite struct{ *testing.T }` (embedding T for its methods), `type Holder struct{ T *testing.T }`, any new parameter `h *Holder` of an existing holder, `var ts []*testing.T`, `map[string]*testing.T`. #268's `carries` fired on calls only, so this is a new false-block class, inside the contract (a false block is acceptable) and absent from the replay; record it so the first legitimate refusal is not mistaken for a forgery.

**L2. `fillable` residual: an interface-typed slot filled by `encoding/gob` with a registered `*testing.T`.** `var zt *testing.T` is not a fact (`testingPtr` excludes it, `:756`), `gob.Register(zt)` has no rule since the outside-call rule was removed, and `struct{ V E }` with `E interface{ Error(...any) }` is not fillable (interfaces end the path, `:742-753`). A hand-written gob stream carrying a struct type named `*testing.T` with one ignored field makes `decAlloc` allocate a fresh `testing.T` into `h.V`. Using it without a fact needs the text layer's pre-existing residual in L3, so this is outside the PR's promise; note it with the `fillable` residuals in #226 (a `gob.Register`/`RegisterName` call with a `*testing.X` argument is a cheap rule).

**L3. Text-layer residual, on main: a bound testing value is never unbound.** `tvals` is per object (`:576`); `var x interface{ Errorf(string, ...any) } = t; x = fake{}; x.Errorf(...)` keeps `x` a testing value, so the call counts as the test's assertion while it reaches an own type's no-op `Errorf`. Zero facts in either layer (`E(t)` is a conversion to an interface, skipped at `:685`). **L4. `go:build ignore` files are "maybe built" and type-checked with the package.** `holds` treats `ignore` as a free tag (`:155-163`), so an ignored generator in `package pkg` joins both passes and both `typedOn` groups; its imports must list, or the package is unverifiable. ### Checked and sound

- **The bool-const exception (question 1).** No guard rule reads a bool constant's value: the constant rules at `:537-544` read strings and 22-valued integer kinds, and Go has no constant conversion from bool to any other kind, so a bool pair cannot change a string, rune, byte or array length. Control flow is never evaluated by `count` (`if strict { t.Errorf(...) }` counts as an assertion whichever platform's declaration the text pass resolves, exactly as `if false { … }` does on main). A typed-vs-untyped or differently-named bool pair differs in `TypeString` and is unverifiable. Sound.
- **M2 (question 2).** A type argument that reaches testing only through an unexported field, a signature or a non-failing interface cannot be filled by code outside the package and cannot fail a test without a method call that is itself an assertion or an instantiation fact. `as[*testing.T]` (`testingPtr`), `as[**testing.T]`, `as[[]*testing.T]`, `as[chan *testing.T]`, `Box[*testing.T]`, `atomic.Pointer[testing.T]` (`fillable`/`holds`), `as[testing.TB]` and `as[interface{ Error(...any) }]` (`failing`, identical signatures), a union constraint `*testing.T | *testing.B` at its instantiation, and an inferred `fail(t)` are all facts. `*testing.TB` is not, and cannot hold a fake (the unexported method). A `v.(T)` inside a generic is not a fact and need not be: the instantiation is.
- **Per-platform type checking (questions 3, 7).** One typer per module and platform (`:227-233`); `builds` takes the platform and sets each platform's default level tag (`:337-343`); `untyped` is keyed by package and the first platform's reason is kept (`:512-520`), so a failure on either platform blocks. Facts carry file, platform and function (`:532`). The run bound (64, cached hits included) and the one deadline are shared across versions and platforms; past either, every later `need` marks its paths "not listed", every import of them fails, and the package is unverifiable: a candidate can block itself, never leave a package unchecked. A platform with no built file is skipped, and the gate builds nothing there either.
- **Declared twice (question 4).** `twice` needs a platform on which `holds` of the two files' tags is non-zero and both files are built by name (`:511-519`); `x_amd64.go`/`x_arm64.go` and `amd64`/`arm64` tag pairs are exempt and never share a group; a tag pair under one platform, a tagless file beside a tagged one, `ignore`, `cgo`, `race` beside a tagless twin, and a local redeclaration all block. A file no gate platform builds (`windows`, `!linux`, `go1.99`) is dropped before grouping and cannot shadow a built one.
- **Redeclarations under unmodelled tags.** `declare` records no `Defs` entry for the second declaration but keeps it in `objMap`, so its type and value expressions are checked and `shapes` reads them; positions in the error texts are the name positions `shapes` keys on; a leftover or doubled "redeclared" and a field-versus-method collision fail closed; the every-declaration (`:594-600`), weakest-test (`:658-660`) and every-callee (`:697-701`) rules are the right direction.
- **`fillable` (question 5).** Embedded fields promote (`:745`), including an embedded pointer to an unexported struct (json refuses that case, so fail closed); `encoding/binary` and `csv` cannot fill pointers or structs with pointers; `text/template` and `iter.Seq` make no values; `unsafe` is a flag and every `reflect` maker is a fact with tests anywhere; a defined `type MyT testing.T` is caught through its embedded `common`.
- **Recursive walks (question 6).** `holds`, `slot`, `plainData`, `typedOn`'s `reaches` and `need`'s walk carry visited sets; `alias` and `root` are bounded loops; an alias cycle in `mentions` is a mention and fails closed; the nil alias key is gone. Panics reach `Integrity`'s `recover` and block.
- **Regressions against #268 (question 8).** Everything `carries` caught that `fillable` does not (unexported fields, signatures behind a pointer) is a target no decoder can fill. The narrower `redeclared` regexp sends "already declared through dot-import" to `typeErr`, which is fail closed. Round 2's fixes for Opus H2 and H3 and L1, L2 read as described.
- **Size:** 354 non-test lines against main, as stated.
