## Opus pre-review of #256

Verdict: NO-GO

There is one blocking High finding, and its fix is contained. The redaction work, the Content-Type allowlist, the schema value and the hostile-zero-final fixture are sound for a call with a single request. But the gateway's count is not fail-closed, and multi-request calls are the normal case (the http-chat adapter runs a turn loop). A missing count, a failed count or a count still in flight lets an adapter `final` settle a call on a partial count. That breaks the PR's own invariant ("a request it sent is never counted at zero"), and P11b is the launch gate.

Reviewed at b005feb. `go test ./internal/gateway/ ./internal/capacity/... ./internal/modelcall/` passes. Both mutations I reran (M3, M10) turn the claimed tests red. Probes ran in a scratch worktree, which has since been removed.

### High

**H1. A sent request has no durable count until after its response is forwarded, and a missing count is invisible to the ledger. A final then settles on a partial count.** This confirms the security review's "fail-open-state-drift" flag, and the root of its gateway.go "logic" flag.
- **Where:** `internal/gateway/count.go:52-58` (`count`: the sequence is consumed, then `Counts.Count`; an error is only `observe`d as `count_unrecorded`); `internal/gateway/gateway.go:208-216` (the count is committed only after `io.Copy` and `Close` have handed the adapter the whole response); `internal/capacity/ledger/ledger.go` `trusted` (it settles when `Counted` is non-nil, unfloored and covered, with no notion of a sequence the gateway used but never committed).
- **Scenario A (store fault or crash, both in D43 scope):** request 0 is counted at 300/30. Request 1 (for example 5000/500) is sent and forwarded, but `Recorder.Count` fails, or adcd crashes between forwarding and commit. The adapter's final is 300/30. `Counted` is just request 0, nothing is floored, and the final covers it, so the call is settled and the lease's reservation returns. My ledger probe `StandingOf([final 300/30, gateway_count seq0 300/30])` returns `Settled=true`. `count_unrecorded` reaches only the exit map. Nothing in the ledger ever sees it.
- **Scenario B (hostile adapter, no fault):** the adapter starts request k (a long generation), then at once sends its run result with a final equal to the sum of counts 0..k-1. `finish` commits the final while request k is still in flight, so the call reads as settled. If P22a settles the lease then, the reservation is released and admission grants against it. `lateUsage` corrects this only once request k's count commits. If the process crashes or `Count` fails in that window, the under-charge is permanent. Nothing in P11b gives P22a a way to know a call's counts are complete (`Unbind` does not wait for requests in flight).
- **Fix:** make the count fail-closed per request, as intent-before-egress already is:
  1. Before `client.Do`, durably commit a `gateway_floor` delta at the request's sequence (the request-size floor). If that fails, refuse the send (`count_unrecorded` → 503).
  2. After forwarding, commit the observed `gateway_count` at the same sequence.
  3. In `Reconcile`, let a `gateway_count` supersede the `gateway_floor` at the same `(call, seq)`. `Floored` then means "some sequence has only a floor". Today any floor at all sets `Floored`, and my probe confirms that a floor and a count at seq 0 stay unsettled.

  With this change a failed post-count, a crash, or a final committed during a request all leave a floor that blocks settlement. Add fixtures for "Count fails for request 1 of 2: the call stays uncertain" and "a final committed while a request is in flight does not settle". The cost is one fsync per request, the same as the intent costs per binding.

### Medium

**M1. The JSON-escape forms are a fixed set of six spellings, not every JSON escaping.** `internal/gateway/gateway.go:267-291` (`forms`).
- **Scenario:** a probe through `redacting` let each of these through unredacted, with `hit=false`:
  - `.NET System.Text.Json` escaping `+` as `+`, against a base64-alphabet key (AWS secret keys contain `+` and `/`);
  - Gson escaping `=` as `=` (base64 padding);
  - `/` escaped as `/`;
  - only one of `<>&` escaped;
  - mixed-case hex within one string;
  - any letter escaped as `\uXXXX`.

  Escapes split across writes, the Go and PHP forms, and a cut inside an escape at EOF are all caught.
- **Fix:** replace the enumeration with an escape-aware matcher. At each secret byte, accept the raw byte, `\uXXXX` with any-case hex, the short escapes `\/`, `\"` and `\\`, or `\b \f \n \r \t` where they apply. Hold back 6×len−1 bytes. This covers every form, including per-character mixes, at the cost of one scanner.

**M2. Output tokens are taken entirely from the upstream, with no floor.** `internal/gateway/count.go:62-68`.
- **Scenario:** an upstream (hostile, or a misreporting proxy) reports `completion_tokens: 0` while it streams a large reply, and the adapter's final reports 0 output. The final covers the count, so the call settles with `Out=0`. Input has the ÷16 floor; output has nothing. #226 entry 69 records Astra's point that "relabelling upstream counters is not enough against a hostile upstream", and suggests request-size and `max_tokens` bounds. The PR defers this to P20 in prose only.
- **Fix:** either add an output floor, or have the lead record this residual explicitly in #226 entry 69 before P17 and P22a rely on the gate. Possible floors:
  - the forwarded body's content bytes ÷ 16 (for a stream, the summed `delta.content` lengths, not the SSE framing);
  - `max_tokens` as the output figure whenever usage is unread.

### Low

- **L1. The EOF tail rule gives false positives on public key prefixes.** `gateway.go:263, 329-343`. `sk-proj-` is exactly 8 bytes, and `sk-ant-api03-` is 13. A response or stream cut that ends in that public prefix is redacted and recorded as `credential_echoed` (probe confirmed). Fix: count `minTail` from after the key's non-secret leading prefix (for example `^[a-z]+(-[a-z0-9]+)*-`). Keys under 9 bytes are never detected at EOF; that is acceptable, but should be stated.
- **L2. Every non-USD adapter is flagged `inconsistent_usage`.** `ledger.go:97-101`. `StandingOf` computes `mixed` over all reports, including gateway counts, which are always `USD`. Probe: an honest `EUR` final or delta next to a count gives `Inconsistent=true`. Fix: skip `gateway_count` and `gateway_floor` when computing `mixed`.
- **L3. The schema is not strict about the gateway sources.** `schemas/records/usage-measurement.json:20-24`. `kind: final` with `source_of_truth: gateway_count/gateway_floor` validates, and `Reconcile` silently treats it as a count delta. Fix: add `allOf`: gateway sources → `kind: delta`. Separately, `docs/design/m0/05-leases-attempts-fencing.md:234` still lists the enum without `gateway_floor`. The new value is otherwise compatible with old stores: nothing ever wrote `gateway_count`, and replay is order-independent (per-sequence max, then sum).
- **L4. Two meanings of "settled".** `ledger.go:271` (`Reconcile` clears `Uncertain` on any final) versus `trusted`. Today only `internal/fixtures` reads `Call.Uncertain`. No path releases a liability on the weaker meaning: `Settlement`, `checkSettlement` and `owe` all go through `StandingOf`. Fix: document that `Call.Uncertain` is not settlement, or rename it, so that P17 and P20 use `StandingOf`.
- **L5. `model_call.count` is not yet authorised.** `modelcall.go:55, 355-389`. It has no authority matrix entry, so P22a's row must list it next to `model_call.intend`. It cannot be forged by a non-gateway caller: the only producers of `usage.measured` are adapterhost (always `adapter_report`) and the Recorder, and the binding check in `ledger.Project` holds. Its `IdempotencyKey` is a fresh id, so it is not idempotent at the command level, but the ledger deduplicates by `(call, seq)`. It is durable on return, but committed after forwarding (H1).
- **L6. The count state is in memory and never cleaned.** `g.seq` (`gateway.go:109, 119`) is never pruned: one entry per call for the daemon's life. Sequences are unique across restarts only because a lost attempt never resumes; state that in the code.
- **L7. Honest calls are over-held as floors, until P20 reconciles them.** The cause is `count.go:98-108` and `gateway.go:450-452`:
  - `kept` keeps the first 8 MB, so a long stream whose usage is in its last event becomes a floor (keep a rolling tail for streams instead);
  - a dial failure that never sent is counted as a floor;
  - a 429 or 4xx with no usage is a floor;
  - a floor above an honest `prompt_tokens` (images, whitespace runs) also marks an honest final `inconsistent_usage` (`ledger.go:133`).

### Checked and fine

- **Content-Type allowlist:** complete and safe. It emits only fixed strings. When the header is dropped, Go sniffs a fixed type from the redacted body. Only the Content-Type and the status reach the adapter.
- **Encoding:** gzip is decoded by the transport before redaction, and any other `Content-Encoding` is refused and counted as a floor.
- **Splitting:** escapes split down to 1-byte writes are caught.
- **Residual statement:** acceptable for base64, URL-encoded, masked and SSE-split echoes, which only a hostile upstream that already holds the key makes. It is not acceptable for the honest-encoder forms in M1.
- **Settlement direction:** "final ≥ count" is the right direction.
- **Sequences:** gateway and adapter sequences live in separate maps, so they cannot collide.
- **Late counts:** a count after the final recomputes the liability through `lateUsage`, and the result does not depend on order.
- **The ÷16 floor:** it binds only when the upstream reports less than it. It can over-hold an honest call, but an adapter cannot use it to under-count.
- **Inertness:** confirmed. adcd wires `ledger.Project` and capacity, but registers no `model_call` projection, so `BoundTo` is empty and the stricter rule changes nothing live.
- **Fault evidence:** M3 (a floor does not block a final) turns `TestAHostileZeroFinalKeepsAConservativeCharge` and `TestAFinalSettlesOnlyOnTheGatewaysCount` red. M10 (the raw key only) turns `TestAnEscapedOrCutEchoNeverReachesTheAdapter` and `TestTheFormsScannedFor` red. Both match the PR. No test covers a count that fails partway through a call, or a final committed while a request is in flight (H1).
