**On the four questions**
1. **Image and adapter:** a build cannot start on an image that is not the pinned, checked one.
   - A tag is refused by the profile schema's `PinnedImage` pattern and again by `Resolve`.
   - A missing label leaves the toolchain empty, which is `ErrManifest`.
   - An adapter for another platform only, or with another digest, is `ErrAdapter`.
   - The container runs `--pull=never <ID>`, and the ID is content-addressed, so it binds both the label and the layers.
   - `prepare-go-image.sh:301-309` checks at build time that `/opt/adc/lib` in the image has the label's digest.
2. **Confinement:** it is 5d-1's. The interactive command comes from the same `args()`, and my probe of the real command shows nothing else is mounted.
3. **Lifetimes:** every failure between `Prepare`, `Ready` and the launch discards the exchange and ends the lease. No container exists before the session opens. `ws.Close` tears the attempt down even though `Ready` left it marked unsafe, which is correct because no container ever ran. The one weak path is M2.
4. **The removal:** nothing still needed was dropped. `Jail` had no users outside `daemon` and `session`, and the `qualify` and `harness` packages pass. No doc or script names `--adapter`. The plan is to run the reviewer in the container as well (#226 entry 143).

### Medium (OBLIGATION for 5d-4)

**M1. The design's end-to-end live row is missing.** `internal/sandbox/interactive_live_test.go:356-391` only runs `describe` and `shutdown`, under the test's own `probeLimits`. It does not go through `containerAdapter`.
- The design (`p22a5d-design.md`, Rows, "End to end (with 5d-3)") promised more: prepare with `/workspace`, `/exchange/in` and `/exchange/out` reached through `Path`, a run through the gateway on the attempt's socket, the builder's edits in `/workspace`, `patch.diff` ingested from `out/`, and `CommitAttempt`. It also promised a refusal before `Prepare` for an image with another adapter.
- **Input:** none of the I17 effect path has been run live.
- **Fix:** add the row: the stub provider, `containerAdapter.Start` and `Ready` over a real host, then `Prepare` and `Run`, then ingestion. Run it before the activation PR flips I17.

**M2. A breach of the disk bound is treated as "the container may still run", and its directory is kept.**
- **Where:**
  - in `internal/sandbox/interactive.go:85-93`, `Remove` returns `a.within(disk, out)`'s error after the container is seen to be gone (`unsafe` is false);
  - in `internal/adapterhost/session/container.go:111`, any removal error becomes `ErrUnverified`; the code there notes "a bound breach is not a live tree";
  - in `internal/daemon/run.go:214-218,298`, the runner then calls `ws.Keep()` and abandons the attempt as `ambiguous_state`.
- **Input:** a builder writes more than `maxTree` (1 GiB) into `/workspace` or `/exchange/out`. Its directory and exchange are kept until a sweep that is not wired. One such attempt can fill the runs filesystem, so every later attempt fails.
- **Fix:** keep the two causes apart. Have `Remove` (or the session) return a distinct bound error, which is not `ErrUnverified`. On that error, the runner tears the attempt down and records `failed`/`could_not_run` with a tree-over-bound reason. Keep `Keep()` only for a container not seen gone. Add a row for each.

**M3. `--sandbox-root` is refused on this host (this already happens on main; it blocks activation).**
- **Where:** `internal/sandbox/sandbox.go:124-129,137-145`, read with `internal/daemon/config.go` `controllerPaths` (which includes `/run/podman/podman.sock`).
- `devOf(p, up=true)` climbs only on `ENOENT`. `/run/podman` is `drwx------ root`, so `stat` gives `EACCES`, and `Validate` refuses any `--sandbox-root`. That is why `TestSandboxConfig` fails outside the test sandbox.
- With this PR, the runner exists exactly when `--sandbox-root` is set, so on this controller host adcd cannot run a build at all.
- **Fix:** have `devOf` also climb on `EACCES` (a path the controller cannot stat is one its rootless runs cannot reach either). Add a row with a 0700 directory owned by another user. Alternatively, leave the root Podman socket out of `Forbidden` when it is unreachable.

### Low (OBLIGATION for 5d-4)

**L1. The release's digest is computed late, cached even when it fails, and has no row.** `internal/daemon/adapter.go:93-96,155-162` and `internal/daemon/wiring.go:112-125`.
- It is computed at the first `Start`, not when adcd starts, as the design said. A failure is cached by `sync.Once` until restart, and no row covers `releaseLib`; mutation X1 survives.
- An adcd that runs from `bin/` without `lib/adc` starts fine, then holds every build `errConfig`. An in-place upgrade before the first lease makes `want` the new `lib/adc`'s while the old adcd runs.
- **Fix:** compute `want` in `runnerOf` and fail adcd's start on an error. Add a row with a planted `<root>/bin/adcd` and `<root>/lib/adc`.

**L2. A short-name pin is retried instead of held.** `internal/sandbox/image.go:71-73`; the schema pattern `^[^@…]+@sha256:…$` allows `name@sha256:…`.
- **Input:** a profile that pins `adc-prepared@sha256:<64 hex>` (no registry). `Resolve` returns `ErrImage`, so the runner retries five times and ends "failed" rather than holding on the profile.
- **Fix:** make the "not fully qualified" refusal `ErrManifest` or `errConfig`, or tighten the schema's pattern to require a registry.

**L3. A `sandbox.ErrSpec` from `Ready` is held on the profile.** `internal/daemon/run.go:600-603`; the row is "a container not made" (`run_test.go:429`).
- An `ErrSpec` from `Interactive` (a mount overlapping a forbidden path, or a leftover cid file) is a host fault. A re-pinned profile does not clear it.
- **Fix:** hold host refusals on the environment owner (`wrong_owner`), or give `Ready`'s `ErrSpec` its own signal.

**L4. Survivors and a stale comment.**
- **X2:** no row uses an image label without lockfiles. Add one to `TestTheAdapterContainerRefuses`, so that a manifest skipped for that case is caught.
- **X3:** `Path`'s row lists only some of the paths it must refuse. Also assert that `""` comes back for the socket's directory and for the exchange's parent.
- The header at `run.go:20-21` says "its image resolved and checked before anything else". The workspace clone and the gateway come first, which the lockfile check needs. Reword it.
