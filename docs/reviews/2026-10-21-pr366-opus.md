### Answers to the four questions

**1. The gateway.**
- **Every forwarded request:** yes. `forward` (`internal/gateway/gateway.go:525-526`) is the gateway's only `client.Do`.
- **Redirects:** `CheckRedirect` refuses them (`egress.go:50`), so the headers never reach a redirect target.
- **Set after injection:** yes, so the adapter and the injector cannot override them. No inbound header is forwarded, and the row catches an injector that sets either header. A non-canonical key written by an injector is an exception (L2).
- **Secrets:** none. The call id is a checked `cal_…` id (`Bind` runs `ids.Check`), so it carries no CR/LF, and it is not the token, which is a separate random value. The sequence does reveal some information (L1).
- **Refusal paths:** unchanged. The headers are set after every refusal, right before the send.

**2. The stub `Query` and the stub provider.**
- **Every unexpected answer fails closed:**
  - a 404 or `pending > 0` gives "not found";
  - any other status, an answer past 4 KiB, malformed JSON, an unknown field, a missing `pending` or usage, a negative figure, `requests < 1`, or another call's id gives an error.
- **No answer leaves the liability with a figure.** The one exception is the stub's own window (M1).
- **Cancellation:** honoured. The request carries the context, and the mutation that drops it is caught.
- **X3:** in process, the effect stays `uncertain` (not found) while the request is held. After release it is `completed`, with exactly one provider reconciliation of 400/220, and the settled standing is asserted.
  - Mutation 5 catches the request being listed twice under its call.
  - No row calls `Reconcile` a second time after completion. The code would not ask again, because `ask` is false once settled (`modelcall/reconcile.go:139`), but no test pins it.

**3. The USD row:**
- **Without a Query:** `Ended`, then `Reconcile`, give `uncertain` with `no_query` both times, and the next lease is refused at `per_day_usd`.
- **Contrast:** a Query answering the gateway's count completes the call, and the next lease is placed.
- **The amount:** the 4,000-micro figure is not asserted directly. The day rail of 2 × reserved − 1 refuses only if the liability is counted.

**4. Timing:**
- **The Go rows:** event-ordered, with 1-minute watchdogs only for a hang.
- **The node row:** it has two 2-second polling windows (L3).
- **A stub default:** the barrier gives up after 120 s by default. Under extreme load, that would make X3 fail, not pass.

### Medium

**M1. The stub's per-call answer can call itself complete while one of the call's requests is still being read.** `fixtures/m1/stub-provider/server.mjs:181-194`
- **Cause:** the request joins `byCall` and `inflight` only after `await read(req)` (`:181`) and after it is logged (`:187-194`). While its body is still arriving, the request is in no call's usage.
- **Probe:** request A of `cal_1` was served (7/3). Then request B of `cal_1` was opened with its headers sent but its body unfinished. The stub answered `{"call":"cal_1","requests":1,"pending":0,"usage":{7,3}}`.
  - `stubQuery` reads that as found and complete.
  - The reconciler would complete the call at the larger of 7/3 and the gateway's observed counts (`ledger.trusted`). B's floor would be replaced, and B would never be counted.
- **Reach:** not in today's in-process X3, because `cutRequest` waits until the stub holds the request at its barrier. It does matter for an installed X3 (P24), where the kill can land mid-body on a call with earlier requests. That is exactly what the answer's `pending` field exists to guard against.
- **Fix:**
  - Read `x-adc-call` from `req.headers` at the start of the handler.
  - Add the request to `byCall` and `inflight` before `await read(req)`, keeping the existing `finally` delete.
  - Add a node row: headers sent, body unfinished, then `pending: 1`.

### Low

**L1. `X-Adc-Call-Seq` carries a counter shared by the whole gateway to every provider.** `internal/gateway/gateway.go:505-506`, `:526`
- **Cause:** `g.seq` counts every request across calls and destinations.
- **Effect:** provider A, from the gaps in its sequences, learns how many requests the gateway sent elsewhere, including to provider B, since the last restart. The call id also lets a provider link one call's requests, but it can largely do that through the key already.
- **Nothing secret** is exposed, and the residual already says real providers ignore the headers.
- **Fix:** stamp only destinations that opt in to a usage query (the stub's), or send a sequence counted per call. Or state the volume leak in the residual.

**L2. An injector writing a header key that is not canonical produces a duplicate on the wire.** `internal/gateway/gateway.go:525`
- **Probe:** `h["x-adc-call"] = cal_injector`, then `Header.Set("X-Adc-Call", …)`, sends both `X-Adc-Call: cal_bound` and `x-adc-call: cal_injector`.
  - [INFERENCE] Node joins duplicate custom headers with ", ", so the stub would file the request under another call's key.
- **Why it is only Low:** injectors are trusted code in the repository.
- **Fix:** before `Set`, delete every key whose `http.CanonicalHeaderKey` equals either header. Or state that injectors write only canonical keys.

**L3. The node row polls in 2-second windows.** `fixtures/m1/stub-provider/test/server.test.mjs:165`, `:170`
- **Cause:** each loop runs 100 × 20 ms, then goes on regardless.
- **Effect:** under load, the abort can land before the barrier is reached, or the release check can run before the barrier releases. Either one fails the row. Neither can make it pass falsely.
- **Fix:** wait on the event (the logged `barrier` entry, and then `pending === 0`) with a bound of 60 s, as the Go side does. Fail explicitly if the bound is hit.

**L4. "Counted once" is not pinned across a second reconciliation.** `internal/recovery/stubquery_test.go:287-305`
- **Cause:** the row calls `Reconcile` once after release.
- **Fix:** call `rc.Reconcile` again and assert that there is still exactly one provider reconciliation, and that the state is still `completed`.

### Judged as sound
- **Header placement:** the headers are set last, on the only send path, and redirects are refused.
- **Refusals and the floor:** no refusal path changes, and the count floor is still durable before the send.
- **Fail-closed parsing:** `stubQuery` covers 404, pending, malformed, oversize, negative, unknown-field, another-call and server-error answers. It honours its context and reads a bounded answer.
- **The USD row:** no Query keeps the liability and refuses at the day rail, and a query that answers settles it.
- **The mutations:** the four I re-applied are caught, as the table claims.
