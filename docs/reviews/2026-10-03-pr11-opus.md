## Medium

### M1. A git failure is masked and the check passes with 0 files (fail-open)
- **Where:** `scripts/check-spdx.sh:17`, `mapfile -t files < <(git -C "$repo_root" ls-files | grep -E "$source_re")`
- **Problem:** `set -e` and `pipefail` never see the exit status of a process substitution. If `git ls-files` fails, `files` is empty and the script prints `check-spdx: 0 file(s) carry the header` with exit **0**. Reproduced outside a repository: git printed `fatal: not a git repository`, the script still exited 0.
- **Failure scenario:** git cannot read the repository. Examples: a later containerised CI job running as a different uid (`detected dubious ownership`), a `make lint` from an exported source tarball, or git missing from the image. The licence gate then goes green while checking nothing.
- **Fix:** run git outside the substitution and check its status. Also refuse an empty selection in default mode:
  ```bash
  listing="$(git -C "$repo_root" ls-files -z)" || { echo "check-spdx: git ls-files failed" >&2; exit 2; }
  # ...select from it (see M2)...
  [[ ${#files[@]} -gt 0 ]] || { echo "check-spdx: no source files selected" >&2; exit 2; }
  ```
  A bash variable cannot hold the NUL bytes that `-z` produces, so in practice write the listing to a temporary file, or use `mapfile -d ''` from a temporary file, then filter.

### M2. Non-ASCII paths are silently skipped (fail-open)
- **Where:** `scripts/check-spdx.sh:17`
- **Problem:** with the default `core.quotePath=true`, `git ls-files` C-quotes any path with non-ASCII bytes, for example `"\303\274.sh"`. The trailing `"` stops `source_re` (anchored at `$`) from matching, so the file is never checked. Reproduced: a tracked header-less `ö.go` passed with exit 0.
- **Failure scenario:** a contributor adds `internal/i18n/çeviri.go` or `docs/örnek.sh` without a header, and lint stays green. This is likely in a project whose operator writes Turkish.
- **Fix:** read the list with `git ls-files -z` and `mapfile -d ''`, and filter in bash (`[[ $f =~ $source_re ]]`) rather than with line-based grep. A smaller fix is `git -c core.quotePath=false ls-files`, but that still breaks on names containing newlines; `-z` is the robust choice.

## Low

### L1. A tracked file deleted in the working tree is reported as missing its header
- **Where:** `scripts/check-spdx.sh:23`
- **Problem:** `git ls-files` lists files from the index. If a tracked file is deleted but the deletion is not staged, `head` prints `cannot open ...` and the script reports it as missing the header.
- **Failure scenario:** the developer gets a confusing local `make lint` failure halfway through a refactor. It fails closed, so CI is unaffected.
- **Fix:** in default mode, `[[ -e $f ]] || continue`. Alternatively, in explicit-argument mode, report a nonexistent file as "not found" rather than "missing header".

### L2. Some kinds of source file are not covered
- **Where:** `scripts/check-spdx.sh:12` (`source_re`)
- **Problem:** the check does not select:
  - extensionless executables with a shebang (for example a future `scripts/adc-dev`);
  - `*.bash` and `*.mk`;
  - `Dockerfile` and `Containerfile`;
  - `*.py` and `*.toml`;
  - `go.mod`, which does accept `//` comments.

  None of these exist in the tree today, so this does not block. As the repository grows, though, the "source files" rule in the design note will quietly stop being enforced for them.
- **Fix:** take one of these approaches:
  - add `bash|mk|py|toml` and `(^|/)(Dockerfile|Containerfile)` now;
  - also select tracked files whose executable bit is set or whose first line starts with `#!`;
  - write down the exact covered set in the design note so that extending it is a deliberate decision.

### L3. The header match is a plain substring anywhere in the first five lines
- **Where:** `scripts/check-spdx.sh:23`
- **Problem:** any line containing the text passes, for example `SPDX-License-Identifier: Apache-2.0 OR MIT`, or the text inside a string literal.
- **Failure scenario:** this is unlikely in practice. The cost is that a dual-licence header slips through.
- **Fix (optional):** anchor the match to a comment line ending in the identifier, for example `grep -qE '^(//|#|/\*) ?SPDX-License-Identifier: Apache-2\.0( \*/)?$'`.

### L4. The PR description says 8 files; the script reports 9
- **Where:** PR #11 body, AC 2
- **Problem:** `scripts/check-spdx.sh` counts itself. The criterion as written does not match what the code observably does.
- **Fix:** change the body to say 9.

## Not an issue (checked)
- Paths with spaces: handled correctly. The script reads one path per line, keeps the array elements quoted, and uses `head -n 5 -- "$f"`.
- Empty array under `set -u` (`"${files[@]/#/...}"`): safe on bash 4.4 and later, including ubuntu-24.04. On bash 3.2 (macOS `/bin/bash`), `mapfile` is missing and the script exits non-zero, so it fails closed. That is acceptable because the controller is Linux-only.
- Where the check sits in `make lint`: after `go vet` and `mod tidy -diff`, before shellcheck. It runs from the repository root, which Make's working directory guarantees, and the script resolves `repo_root` itself in any case.
