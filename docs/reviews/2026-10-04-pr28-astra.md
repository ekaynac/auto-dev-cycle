# PR #28 (typed reasons): Astra reviews

## Review of #28 (Astra, 2026-10-04)

Verdict: NO-GO

### High

1. **The validation hooks can be replaced without a finding.**  
   `gen/go/types/helpers.gen.go:31`, `internal/contract/contract.go:147`

   Ordinary product code can disable both vocabulary boundaries:

   ```go
   allow := func(string, bool) error { return nil }
   types.ReasonCheck = allow
   contract.SetReasonCheck(allow)
   ```

   **Reproduced:** zero source findings, followed by successful contract decoding and encoding of a complete receipt containing `typo_override`. An untyped document also encoded successfully with an unregistered reason and, separately, a deprecated reason. No reflection or unchecked constructor was needed.

   The nil-hook behavior fails closed, but hook ownership is unenforced.

   **Fix:** restrict installation and replacement to the actual vocabulary package, protecting references and indirect calls too, or remove the replaceable production API. Add end-to-end tests proving unauthorized replacement cannot pass the source check and disable validation.

2. **Accepted `adc-reason` schema forms generate unchecked strings.**  
   `internal/schemagen/gen.go:416`, `internal/schemagen/gen.go:484`, `internal/schemagen/gen.go:537`

   Opaque generation happens only in `declare`. An inline property with:

   ```json
   {"type":"string","format":"adc-reason"}
   ```

   becomes `string`. A `$ref` to a plain string with sibling `"format":"adc-reason"` also retains its unchecked string type.

   **Reproduced:** generation succeeded; the generated package compiled; ordinary JSON decoding and encoding both accepted `"unregistered"` in those fields. The current reference to `common/defs.ReasonCode` works, but the amended grammar accepts other forms that violate its mandatory boundary.

   **Fix:** handle reason semantics throughout type generation, including inline and refined schemas, or explicitly reject unsupported placements. Add compiled read/write tests for each accepted placement.

### Medium

3. **Function values bypass both static call rules.**  
   `internal/vocab/check.go:148`, `internal/vocab/check.go:184`

   These pass with zero findings:

   ```go
   construct := types.ReasonCodeOf
   bad := construct("typo_indirect")

   parse := vocab.ParseReason
   _, _ = parse("stale_attempt")
   ```

   **Reproduced:** the first constructs an unregistered reason; the second parses a constant successfully. With intact hooks, marshaling the unregistered value remains blocked, so this is a source-contract failure rather than an independent emission bypass.

   The constructor exemption also trusts `pkgName == "vocab"` instead of package identity, allowing an unrelated package with that name.

   **Fix:** guard references to the unchecked constructor, resolve or conservatively restrict parser aliases, and identify trusted packages by their actual import paths. Test function values, higher-order uses and unrelated same-named packages.

4. **Generated values are mutable through implicit address-taking.**  
   `internal/vocab/check.go:160`, `internal/vocab/check.go:170`

   ```go
   vocab.ReasonCompletedClean.UnmarshalText([]byte("stale_attempt"))
   ```

   **Reproduced:** zero findings and successful replacement of the package-level generated value. Go implicitly takes its address for the pointer receiver; the scanner only recognizes explicit `&` and assignment syntax. Capturing the pointer-receiver method value exposes the same mutation capability.

   **Fix:** detect implicit address-taking through method selections and method values, or expose generated reasons through an immutable API. Add regressions verifying the generated value cannot be changed through either form.

5. **Null and omitted reasons bypass read validation.**  
   `gen/go/types/common_defs.gen.go:38`, `internal/vocab/vocab.go:198`

   Both documents decode successfully into `vocab.Result` with an empty, unregistered reason:

   ```json
   {"outcome":"empty","detail":""}
   {"outcome":"empty","reason":null,"detail":""}
   ```

   `encoding/json` does not call `UnmarshalText` for null or an absent field. `Result.UnmarshalJSON` checks only the outcome afterward. Such a result also passes `RequireEmpty`. A standalone null reason decodes successfully even without the hook installed.

   **Fix:** reject null through JSON-specific reason decoding and validate reason membership after decoding a result, including omission. Preserve deprecated-code readability; do not substitute the writer’s deprecation check. Add null, missing-field and absent-hook read tests.

### Low

6. **New helper names are missing from collision detection.**  
   `internal/schemagen/gen.go:36`

   Only `decodeStrict` is reserved. **Reproduced:** a schema definition named `ReasonCheck` generates successfully alongside the helper variable of the same name, producing an invalid Go package.

   **Fix:** reserve every helper declaration, including `ReasonCheck` and `checkReason`, and test collisions.

7. **The committed tests do not establish all stated evidence.**  
   `internal/vocab/boundary_test.go:79`, `internal/entry/entry_test.go:118`

   The deprecation test reads a historical receipt and parses its reason, but does not decode a historical `Result`. The bootstrap test exercises a missing root with a healthy registry, not an actual registry-load failure. The adversarial cases above are also absent.

   **Fix:** add those cases and the regressions attached to each finding. Mutation tests establish sensitivity to the exercised enforcement points; they do not establish coverage of omitted paths.

I independently ran **`make ci`: passed**, reporting **34 reasons, 14 holds, zero findings**. Shellcheck was unavailable and skipped locally. Review probes ran in isolated sandbox copies; no tracked files changed. The opaque type fixes the earlier direct string/conversion bypasses, but the two High findings leave the claimed enforcement contract incomplete.

**High**

1. **The shared registry lets product code disable validation without replacing either hook.**  
   `internal/vocab/vocab.go:83`, `:96`, `:105`

   `Load()` returns the actual cached registry, including its writable maps:

   ```go
   reg, _ := vocab.Load()
   code := "typo_mutated_registry"
   entry := reg.Reasons["completed_clean"]
   entry.Code = code
   reg.Reasons[code] = entry
   reason, err := vocab.ParseReason(code)
   ```

   **Reproduced:** zero source findings; successful parsing and JSON emission of the previously unregistered code; successful contract decoding and both typed and untyped encoding of a complete receipt containing it. The same API permits clearing deprecation metadata.

   **Fix:** keep validation’s authoritative registry private and immutable. Expose read-only accessors or detached, deep copies—including nested pointers and slices. Add external-package tests proving mutations of returned data cannot change parsing or emission decisions.

2. **An unrelated package ending in `/internal/vocab` passes both installer authorization and source checking.**  
   `gen/go/types/helpers.gen.go:42`; `internal/contract/contract.go:153`; `internal/vocab/check.go:149`; template in `internal/schemagen/gen.go`

   A package at:

   ```text
   github.com/ekaynac/auto-dev-cycle/tools/hookprobe/internal/vocab
   ```

   can reference the unchecked constructor and install permissive checks in both runtimes.

   **Reproduced:** zero findings. With the real vocabulary package absent, both installations succeeded and JSON emitted `"typo_foreign_vocab"`. Direct calls, closures, returned closures, generic functions and generic methods behaved consistently with inlining enabled and disabled.

   **Fix:** authorize the exact vocabulary import path, shared consistently by the scanner and both installers. If the generator supports other modules, supply the expected full path explicitly. Test nested and foreign packages with the same suffix.

3. **Reason-formatted map keys still generate unchecked strings.**  
   `internal/schemagen/gen.go:624`, `:642`

   Both forms are accepted:

   ```json
   "propertyNames": {"type":"string","format":"adc-reason"}
   ```

   ```json
   "propertyNames": {"$ref":"#/$defs/R"}
   ```

   Here `R` is a declared `adc-reason` string. Both maps become `map[string]…`, bypassing the opaque type.

   **Reproduced:** generated packages compiled, and ordinary JSON decoding and encoding accepted `{"typo_unregistered":"x"}` without any vocabulary installed. This preserves the first review’s unchecked-string failure through another accepted placement.

   **Fix:** reject reason-formatted `propertyNames`, including reference chains, or generate checked opaque keys. Add compiled read/write regressions for both placements.

**Medium**

4. **Range assignments mutate generated values without a finding.**  
   `internal/vocab/check.go:194`

   ```go
   for _, vocab.ReasonCompletedClean = range []vocab.Reason{
       vocab.ReasonStaleAttempt,
   } {}
   ```

   **Reproduced:** zero findings; afterward `ReasonCompletedClean.String()` returned `"stale_attempt"`. Range targets belong to `ast.RangeStmt`, so the assignment rule misses them.

   **Fix:** inspect both range targets when `Tok == token.ASSIGN`, using the same generated-value check. Cover slice values, map keys/values and channel receives.

5. **The constructor rule protects only the name `ReasonCodeOf`.**  
   `internal/vocab/check.go:177`; `internal/schemagen/gen.go:475`, `:483`

   The generator accepts a reason definition named `Why` and emits `WhyOf`, but the scanner does not protect that constructor.

   **Reproduced:** product code constructed `types.WhyOf("typo_other_constructor")` with zero findings. Its intact marshaling check rejected emission, so this is an unchecked-construction gap rather than an independent emission bypass.

   **Fix:** identify every generated unchecked reason constructor through generated metadata or type information, or explicitly restrict reason declarations to the single supported canonical type.

### Lead notes on round 2

- H1: the registry behind every decision is private (`authoritative`); `Load` returns a deep copy, so changing
  what it returns changes no decision. Tests mark deprecation through a test-only hook (`export_test.go`).
- H2: exact import paths. The generated helpers and the contract runtime authorise exactly the vocabulary package
  (`ownsReasonCheck`; the generator takes the path, `GenerateFor`); the scanner derives the vocabulary, generated-types

  by the scanner; an unrelated `contract` namesake is no longer flagged (L6).

- M4: range assignment targets are checked. M5: a reason code is declared once, as `ReasonCode`, so `ReasonCodeOf`
  is the only unchecked constructor.
- Regressions for each; the round-2 fixes are mutation-tested.

## Third review of #28 (Astra, 2026-10-04)

Verdict: NO-GO

- **H1 — Mutable shared registry: fixed.** `Load` returns detached maps, slices and pointers. Independent mutation probes preserved parsing and typed/untyped emission checks, including deprecation. `DeprecateForTest` is excluded from production builds.
- **H2 — Suffix-based package trust: fixed.** Both installers authorize the exact owner; `GenerateFor` embeds the supplied path. The scanner derives exact paths from the scanned module. Same-suffix outsiders are rejected.
- **H3 — Reason-formatted map keys: partially fixed.** Explicit string schemas and the tested reference chains are refused; an implicit-string form still bypasses rejection.
- **M4 — Range-assignment mutation: fixed.** Both targets are checked. Additional map-key, map-value and channel-receive probes produced findings.
- **M5 — Other constructor names: fixed.** Alternate reason declaration names are refused, leaving `ReasonCodeOf` as the guarded constructor.
- **L6 — Contract namesake false positive: fixed.** Installer detection matches the exact contract package.

**High — Remaining H3 bypass: enum-only reason map keys generate unchecked strings.**

`internal/schemagen/gen.go:685`, with the predicate at `:491–493`.

This accepted schema bypasses the new guard:

```json
{
  "$defs": {
    "M": {
      "type": "object",
      "propertyNames": {
        "enum": ["typo_unregistered"],
        "format": "adc-reason"
      },
      "additionalProperties": {"type": "string"}
    }
  }
}
```

`isReasonString` requires an explicit `"type":"string"`, while `keyNames` accepts a string enum without it. Generation therefore succeeds and emits `map[string]string`.

**Reproduced:** the generated package compiled; ordinary JSON decoding and encoding both accepted `{"typo_unregistered":"x"}` without any vocabulary installed. This violates the amended prohibition on reason-formatted map keys and remains blocking.

**Fix:** reject `format: adc-reason` in `propertyNames` independently of an explicit `type`, retaining reference-chain checks. Add a rejection regression for the enum-only form.

No additional Critical/High problems were confirmed in the other changes. Independently ran **`make ci`: passed**, with **34 reasons, 14 holds, zero findings**; shellcheck was unavailable and skipped locally. Additional probes ran in disposable sandbox copies. No tracked files changed.
### Lead notes on round 3: split (04 §2, three NO-GOs)

Round 3 confirmed every second-round fix but one: an enum-only `propertyNames` with `format: adc-reason` still
generated unchecked keys. After three NO-GOs, #28 is split along runtime and static enforcement:

1. **Runtime boundary** (this PR's successor): the opaque reason type and its generator rules, the guarded check
   installers in the generated types and the contract runtime, and the private vocabulary registry,
   `ParseReason` and installation. The remaining High is fixed at its root: the generator refuses
   `format: adc-reason` anywhere but the one `$defs/ReasonCode` string declaration (inline, enum, map key, item
   or refinement alike), and a `$ref` to it as a map key stays refused.
2. **Static check** (stacked on 1): the generated `vocab.Reason*` values (`tools/vocabgen`), `CheckSource`,
   `adc dev vocab check` and its `check_unloadable` bootstrap, and the `make vocab-check` gate.
