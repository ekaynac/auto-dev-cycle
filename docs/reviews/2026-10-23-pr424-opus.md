### Answers to the five questions

**1. Production behaviour, cost, and parallel tests.**
- **Reads:** no production code reads a counter. `Load` appears only in `_test.go` files.
- **Cost:** every counter is an `atomic.Int64` with one uncontended `Add` per line, prefix, directory, statement, name or package. That allocates nothing. Beside the map lookups and `strings.Join` at the same points it is negligible, and no lock is added.
- **Behaviour: changed, in form (M1).** Six of the `Add`s sit inside a verdict predicate, and one return value can make one of those predicates false.
- **Parallel tests:** `internal/accept` has no `t.Parallel`.
- **Background work that could inflate a count:**
  - `outTypeChecks`: before the H1 row, `waitWorkers` drains every live or dropped worker, and the row checks again that none is left.
  - `aliasReads` and `pySteps`: these are reached only synchronously.
  - An abandoned `typeCheck` runs on after its row, but it calls neither `mentions` nor the Python guard, so it never adds to these counts.
  - `typeChecksLive` is the exception: it can go down by itself (L2).

**2. Each converted row still catches its finding, except the star row.**
- **The spot checks:**
  - **Mythos #269 M1 (alias DAG):** the exponential walk is exactly the counted read.
  - **Opus #317 M1 (struct chain):** shown by mutation A. An event replaces the clock, and the property (the guard returns at its deadline, not when the check ends) is the event's.
  - **Astra #281 r4 M2 and r5 M1 (seeding, deep directory):** killed at three to four orders of magnitude over the bound.
  - **Astra #272 r3 M1 (star expansion):** not caught (M2).
- **The coverage lost:** the old rows bounded the whole run's time, so a superlinear step anywhere showed. The new rows see only the counted steps. The body states this limit; I accept it as stated.

**3. "At most 3× from n to 2n" is sound for linear work, but looser than exact counts need (L1).**
- **Linear work passes:** for $c(n) = a + bn$ with $a \ge 0$, $c(2n)/c(n) \le 2$. A small negative $a$ (names gaining digits) gives the star row's 2.06.
- **What a quadratic term can do:** a term $qn^2$ passes the ratio while $qn^2 \le 2a + bn$, that is, while it is no larger than the linear part at n.
- **Worked case, the star row:**
  - c(n) = 255,296 at n = 10,000, and c(2n) = 525,296;
  - the per-unit limit of 64 allows 1.28 M at 2n;
  - so an added $qn^2$ with $q \le 1.9 \times 10^{-3}$ passes, which is up to 755 k more steps at 2n, more than the whole linear count.
- **What the rows still catch:** a whole extra pass per unit, $q \approx b$, fails at both checks. That is how every quadratic regression these rows were written for looked, and every one in the body's table and in mine was killed by a wide margin.
- **What they miss:** a quadratic step with a small coefficient passes at these sizes, and grows tenfold at Astra's original sizes.

**4. The star row's survivor is a real gap, larger than stated. Fix it now (M2).** The body says this row never reaches `across`. In fact no Python row does: mutation D (`across`'s bound never trips) survives all 26 `TestPy*` functions. So Astra #272 r2 M1 and r3 M1's bound has no test anywhere. The gap predates this PR, so it is not a regression. But this PR rewrote the row and kept a name that claims the bound.

**5. Reuse and regressions: none beyond the findings below.**
- **One helper:** `linear` is the only new one, and `within`, `ordinary` and `unitGo` are gone with no caller left.
- **`pySteps` beside the work charge:** it is a second count next to `pb.r.work`, and that is justified. The work charge is the bound under test, so a count read from it would hide a forgotten charge.
- **The rows kept on the clock:**

  - "a go over time": 30 s per uncut call, against 15 s of slack.

### Medium

**M1. Six `Add`s are inside verdict predicates, so a test counter's value takes part in the guard's decisions. OBLIGATION.**
- **Where:**
  - `internal/accept/integrity_py.go:145` (`>= 0 &&`);
  - `internal/accept/integrity_pyimport.go:44` (`> 0 &&`);
  - `internal/accept/integrity_pyreach.go:335`, `:432`, `:592` and `:603` (each `> 0 &&`).
- **The failing case:** `Add(0)` returns the counter unchanged. At `:335` and `:432`, an empty prefix (`len(n) == 0`) while `pySteps` is still 0 makes the predicate false. At `:432` that skips `return p, nil`, the refusal of an opaque, ambiguous, non-source or `__pycache__` module: a fail-open path.
- **Why it is not reachable today:** the lexer counts first, and a dotted name with an empty component does not reach the closures. But the PR promises test-only counters, and these make the counter part of the decision. A reset, a future `Store`, or a reordering would change verdicts with nothing to catch it.
- **Fix:** make each `Add` a statement of its own, before the `if` or in the loop body. The `if` conditions are then exactly main's.

**M2. `across`'s work bound has no test, and the row named for it asserts either of two verdicts. OBLIGATION (fix now; test-only).** `internal/accept/integrity_pyguard_test.go:1013-1031`
- **Cause:**
  - the row accepts "over the guard's work bound" or "a module a condition reads is unread";
  - `big.py`'s absolute star imports make it not inert, so the run always takes the second verdict before any expansion;
  - mutation D survives every `^TestPy` test.
- **Fix:**
  1. Give the row a fixture that `across` expands. For example, put the star imports in a package as `from .sN import *` over plain, inert `sN.py` files, which `starCheck` admits.
  2. Require only "over the guard's work bound".
  3. Keep the `linear` count.
  4. Confirm that mutation D is then killed.

### Low

**L1. The ratio limit of 3 is a holdover from timing noise, and exact counts allow tightening it. OBLIGATION.** `internal/accept/integrity_test.go` (`linear`: `c2 > 3*c1`)
- **The measured ratios:** 2.00 to 2.06, with map-order variation of a few steps (16,220 or 16,225).
- **Fix:** use 2.25. At the star row's sizes, that cuts the quadratic coefficient that can pass about sevenfold (Q3).

**L2. The struct-chain event compares a counter that also goes down. OBLIGATION.** `internal/accept/integrity_types_test.go:402-404`
- **Cause:** `after <= live` fails spuriously when an earlier abandoned check finishes inside the window. One such check comes from `integrity_loader_test.go:433`'s own struct chain. In a full run, the Python tests run between the two, but a `-run` selecting both can overlap them.
- **Fix:** before reading `live`, wait for `typeChecksLive` to reach 0, as `waitWorkers` does for the out layer. Or count abandons with a counter that only goes up.

**L3. `TestOutTypedBounded` sets a global with no cleanup. OBLIGATION.** `internal/accept/integrity_out3_test.go:240-247`
- **Cause:** it sets `maxListTime` to 90 s and restores it only after the guarded run. A fatal stop in between would leave 90 s for the rest of the package.
- **Fix:** restore it with `defer` or `t.Cleanup`, as the new `work(...)` rows already do.

### Judged as sound
- **The counters:** each is incremented at exactly the step that its row's finding concerns, and the counts are deterministic to within a few steps.
- **`linear`:** it runs every row at two sizes and still checks each row's verdict at both.
- **Where the clock stays:** only the two rows whose property is wall time keep it, each bounded by a deadline plus a fixed slack, not by a multiple of a baseline.
- **The removed helpers:** `within`, `ordinary` and `unitGo` are removed whole.
