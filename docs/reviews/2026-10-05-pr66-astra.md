# PR #66 (actor and token events, authentication): review

## Review of #66 (Astra, 2026-10-05)

Verdict: NO-GO

**Critical:** None found.

**High — Liveness alone permits privileged identity creation and token issuance.**  
[internal/identity/identity.go:193](/tmp/claude-1000/-home-mega-auto-dev-cycle/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ide/internal/identity/identity.go:193), also lines 223–229.

The accepting contract permits:

- A fresh self-created system actor at any time after bootstrap.
- A system actor **created by a supervisor**, despite the stated self-creation rule.
- A supervisor creating an operator or issuing a token for an existing operator.

I reproduced these accepted transitions and authenticated the resulting system/operator tokens. System actors then cannot be revoked. `Project` discards the event’s actor when calling `apply`; payload `created_by` supplies the provenance being checked. There is also no projected bootstrap-consumption state establishing the first-operator exception.

The probes used the fixture’s permissive authorizer: this proves an admission-contract gap, **not a remotely reachable exploit**. Note 04 assigns authorization to `internal/authority`, but this PR supplies no identity-specific enforcement or explicit trusted-caller contract that closes these paths.

**Fix:** bind creator/issuer provenance to trusted command identity; enforce actor-kind creation and token-issuance permissions in the writer’s authority integration. Constrain system creation to controller-owned identities and represent the one-time bootstrap transition durably. Add refusal tests for these sequences. General grant evaluation need not move into the projector.

**Medium — The decoy does not establish the claimed timing equivalence.**  
[internal/identity/identity.go:259](/tmp/claude-1000/-home-mega-auto-dev-cycle/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ide/internal/identity/identity.go:259), also lines 229 and 280–283.

The first unknown-token request performs Argon2 during `mint`, then again during verification; a known-token wrong-secret request performs it once. Additionally, the new projector admits schema-valid hashes that verification rejects before hashing. A probe committed `m=0`; authentication failed in approximately 121 μs. Accepted hashes can also specify different costs.

**Fix:** prepare a fixed-policy decoy outside request handling and enforce supported hash parameters at issuance admission. Ensure invalid stored hashes receive equivalent verification work. Test verification-path/work counts, including cold initialization; error equality alone does not prove timing behavior. Rejecting malformed bearer syntax early does not itself disclose hidden token state.

**Medium — The refusal tests do not prove their rollback claim.**  
[internal/identity/identity_test.go:220](/tmp/claude-1000/-home-mega-auto-dev-cycle/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ide/internal/identity/identity_test.go:220).

The tests assert only that submission returns an error. They do not inspect surviving projections/events or retry the same idempotency key. The rebuild test submits events individually, so it does not exercise the batch-versus-single-event fold requirement.

**Fix:** add a batch with a valid identity transition followed by a rejected transition; verify complete rollback and key reuse. Add dependent batched creation/issuance followed by rebuild. My temporary probes confirmed batched rebuild and projection rollback work, but the committed suite does not establish these claims.

**Low — The wrong-secret test can accidentally test malformed syntax.**  
[internal/identity/identity_test.go:118](/tmp/claude-1000/-home-mega-auto-dev-cycle/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ide/internal/identity/identity_test.go:118).

XOR can turn a valid base64url character into an invalid one, bypassing secret verification.

**Fix:** deterministically replace a nonfinal secret character with a different valid base64url character.

The three decisions:

- **Self-created, irrevocable system actors:** acceptable only for explicitly controller-owned identities; the current admission rule is too broad.
- **Actor revocation invalidates tokens during authentication:** sound. Retained records prevent same-ID resurrection. Authentication correctly rejects missing/revoked holders and revoked tokens. Writer decisions must use the writer’s current transaction.
- **Secret-first checking and a decoy:** sound direction, subject to the timing fixes above.

The projector is otherwise a deterministic fold over validated events and projected records. Existing identity, event-store, and schema tests passed; temporary adversarial overlays confirmed the findings and batched-fold behavior. `make ci` was not run. The checkout remains unchanged.
### Lead notes on round 1 (applied)

The branch was rebuilt on #65's current head, because the fixes need its canonical PHC parser.

- **High (admission):**
  - **Provenance:** the store now refuses a command event that names an actor other than the command's (`TestCommandEventsAreTheCommandActors`), so the projector takes the event's actor as who did it. A record's `created_by` must equal that actor.
  - **Kind rules,** from the projections alone:
    - the system actor is the very first actor and creates itself;
    - the system actor creates exactly one operator, the first;
    - operators create operators and supervisors; supervisors create nothing;
    - only operators revoke actors; the system actor is never revoked;
    - tokens go to operators and supervisors only, never the system actor;
    - operators issue tokens, and the system actor issues exactly one: the first operator's first;
    - an operator, or the token's own holder, revokes a token.
  - **Bootstrap:** the one-time step is durable, in `identity_bootstrap` (`operator`, `token`). Grant evaluation stays with `internal/authority`.
  - **Tests:** `TestBootstrapOrder` covers an empty store: a non-system first actor, a system actor created by another, the system actor creating a supervisor, and the system actor issuing its token to another operator. `TestProjectorRefuses` now has 35 refusals, including every sequence Astra reproduced.
- **Medium (timing):**
  - The decoy is a constant hash of the issuance profile, so no hashing happens at first use.
  - Issuance admits only the issuance profile.
  - A stored hash that cannot be parsed is verified against the decoy, so every well-formed bearer costs exactly one argon2id computation.
  - `TestAuthenticationWork` counts them through an injected `idKey`: valid token, wrong secret, unknown token, revoked token, revoked holder and damaged stored hash each cost 1, and a malformed bearer costs 0.
- **Medium (rollback):** `TestRollbackAndBatches` checks a command with a valid creation followed by a refused one. It leaves no actor, and its idempotency key then succeeds with the valid event alone. A batched creation plus issuance in one command rebuilds with no difference.
- **Low:** `wrongSecret` replaces a non-final secret character with another valid base64url character.
- **Mutation:** 35 points across the projector, `Authenticate` and the store's actor check, all killed.
