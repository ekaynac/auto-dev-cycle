### Medium

**M1. `/exchange/out` is outside `Limits.Disk`.**
- **Where:** `internal/sandbox/interactive.go:71-78`. `Remove` checks `a.within(disk)` on the attempt directory only, and the exchange is outside it, under `runs/exchange`. The `Remove` doc comment (`interactive.go:42-47`) says "what the run left is within Limits.Disk".
- **Input:** a run with `head -c 8388608 /dev/zero > /exchange/out/big` and `Disk` 1 MiB. Result: `Wait` is nil, `out/big` holds 8,388,608 bytes, and `CopyTree` succeeds.
- **Fix:** have `Remove` measure the exchange's `out/` against the bound as well, alone or together with the attempt directory, and fail on excess. Add a CI row that writes past the bound into `out/`.

**M2. The removal works by name, so it can kill another run's container.**
- **Where:** `internal/sandbox/interactive.go:58,83-91`.
- **Input:** a second `Interactive` for an attempt id whose container is still running. Its client exits 125 ("the container name … is already in use"). Its `Wait` then calls `Remove`, and `rm --force adc-<att>` removed the **first, live** container: it was listed no more afterwards.
- **Who can hit it:** any relaunch or retry that reuses the attempt id, or a held container that `keep` keeps while 5d-3 starts the same attempt again.
- **Fix:** start with `--cidfile=<attempt dir>/cid` and remove by that container id. With no cidfile (the client never created a container), remove nothing and verify only the listing. Alternatively, refuse in `Interactive` when `podman container exists adc-<att>`.

**M3. The start sweep misses the batch runs a crash leaves.**
- **Where:** `internal/sandbox/interactive.go:117-136` and `run.go:153-171`.
- **The gap:** `RemoveStale` skips `adc-<24 hex>` on purpose. But a batch run's deadline is enforced only on the client's side (`context.WithTimeout` around the podman call). After an adcd crash, a gate container keeps running under conmon with no bound, and nothing removes it.
- **Fix:** add `--timeout=<Limits.Timeout seconds>` to `args()`, so conmon enforces the deadline for batch and interactive runs alike, including after a crash. Also sweep `^adc-[0-9a-f]{24}$` at start: no batch run survives a restart.

### Low

**L1. `Kill` starts the removal before the signal, and the result is cached.**
- **Where:** `internal/adapterhost/session/process.go:333-337` (`stop()` before `signal()`) and `container.go` (the `sync.Once`).
- **The risk:** if the removal finishes before the container exists and the client survives the signal ("a client no signal reaches"), the waiter reuses that early "gone" after the client exits.
- I did not observe this: the client is a single process, so SIGKILL lands before `rm` even starts.
- **Fix:** after `cmd.Wait()`, always run a fresh check that the container is no longer listed. Do not reuse the result from the `Kill`-time removal.

**L2. The live rows lack the design's lifetime rows.**
- **Where:** `internal/sandbox/interactive_live_test.go`; `p22a5d-design.md` "Live" lists them.
- **Missing:**
  - the deadline removing the container;
  - a `Kill` with a real removal that leaves nothing listed after `Wait`;
  - the owner of `out/` files on the host;
  - a dial to a loopback port the test opened.
- My probes show the first two hold today; add them as rows.
- Two more gaps:

  - The probe's `allowed()` does not check that `/exchange/in` is mounted `ro`; only the EOF row's `touch` proves that.

**L3. Detach keys.** They are inert in podman 4.9.3 without a tty. Controller JSON escapes U+0010/U+0011 anyway, but `--detach-keys=` would make this independent of the podman version.
