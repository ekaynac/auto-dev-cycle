### Answers to the seven questions

1. **H1 is resolved.** No git the controller runs through `Clone` or `Repo.Git` can execute a command the repository or the run chose. The controller's clone defines no filter, diff or merge driver, hook path, fsmonitor, gpg program, editor or pager, and the `-c` overrides, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM`, `GIT_ATTR_SOURCE=<empty tree>` and a fully replaced environment mean nothing from the controller's env, global config or work tree can add one. `GIT_DIR` is explicit, so no discovery, no ceiling and no `safe.directory` path applies. The copy tree drops `.git` at every depth, whether file or directory, copies symlinks as links and never descends them, so neither a `gitdir:` file nor a nested repository is ever opened. The snapshot's race window has no writer: only the controller can reach the clone, and none of the ten commands writes `config` or `info/`. The one residual exec path is in the *serving* repository, not the controller's: `git-upload-pack` runs in whatever local path `Clone` or `fetch` is pointed at and honours that repository's own config (`core.alternateRefsCommand` when `objects/info/alternates` exists). That is safe only while callers never pass a run-written path. See M5.
2. **Containment holds.** Network none, in a new netns, so abstract sockets are scoped too. No host path reaches the container except the attempt's `workspace`, `results` and, in build mode, one socket. Podman's HOME, XDG, storage and runroot are private, `--env-host=false`, and no controller env var reaches Podman. Mount sources are resolved through symlinks and compared against resolved forbidden paths and Podman's dirs; the attempt must be exactly `<resolved root>/runs/<id>/{workspace,results}`. There is no exploitable TOCTOU: the only hostile writer under `runs/` is a container confined to the *contents* of its own two directories, which cannot replace those mount points or reach a sibling attempt.
3. **The probe can stay green on a wrong *source* for an allowed *point*** (M1). The lead's finding is correct. The residual whole-tmpfs gap is acceptable: it needs a controller args defect, the Go side checks sources, and the forbidden-path, socket and HOME checks still cover the controller paths that matter.
4. **A different image cannot run.** `Resolve` refuses a ref not pinned by digest, requires the digest in `RepoDigests`, and the run starts the content-addressed image ID, whose config pins the layer diff IDs and the manifest label. Storage is private.
5. **Copy-out is sound** against symlinks, FIFOs, devices, type-swap races (`os.Root` plus `O_NOFOLLOW` plus `fstat`) and byte size. Hardlinks cannot cross the bind mounts. Entry and depth caps are the stated P9b deferral. One correctness gap: the copy drops the executable bit (M4).
6. **Fault evidence is discriminating and live.** Ten injected faults turn the probe red in both modes, the git test has a positive control, and the Go boundary refuses fifteen cases with zero Podman calls. Gaps: no `.gitmodules` case (L2) and no "own mount from the wrong source" fault (M1).
7. **The P9b deferrals are acceptable** because this package is inert (nothing calls `Start`, `CopyTree` or `Probe` yet), on one condition: P9b's disk bound and copy caps land before P14, P15 or P32 run a real workspace through this package. See L5 on what a bound "in Validate" can and cannot bound.

### Findings

No Critical or High.

**Medium**

- **M1. The in-container mount classifier accepts by point and type, never by source.** `internal/sandbox/probe.go:163-166`. Confirms the lead's items 1–4, with refinements below. A workspace, results or gateway bound from the state directory, a host device bound under `/dev/`, or a host file bound at `/etc/hosts` from any path containing `/userdata/` all pass. Failure: in the live fault set, drop the real workspace mount and add `--mount=type=bind,src=<state>,dst=/workspace`. Today the verdict is green unless a socket happens to sit in the state dir. Fix:
  - *own*: `Probe` passes the attempt id; require `strings.HasSuffix(m.Root, "/runs/"+id+"/workspace")` and `.../results`. Mountinfo's root is relative to the mount's own filesystem, so a suffix, not a prefix, is the robust check. For the gateway require `path.Base(m.Root) == path.Base(gateway)`.
  - *pseudo*: the lead's `Root == "/null"` is too narrow for rootless. runc and crun bind the default devices from the host when `mknod` is impossible, so a clean rootless run also shows `/dev/zero /zero devtmpfs`, `/dev/full`, `/dev/random`, `/dev/urandom` and `/dev/tty`. Pin: devtmpfs allowed iff `Point == "/dev"+Root` and base ∈ {null, zero, full, random, urandom, tty}, or `Point` under `/proc/` with `Root == "/null"` (a mask); proc allowed iff `Point == "/proc"+Root` (a read-only rebind of the container's own proc). Take the exact list from the full live output the PR elided.
  - *podmanFiles*: require `Root` to match `/overlay-containers/[0-9a-f]+/userdata/<basename>$` where basename is the expected file for that point (`.containerenv`, `hostname`, `resolv.conf`, `hosts`). A runroot prefix would break when the sandbox root is its own filesystem.
  - *whole*: pin the points: `/` overlay; `/proc`, `/dev`, `/dev/pts`, `/dev/mqueue`, `/dev/shm`, `/sys`, `/sys/fs/cgroup`, `/tmp`, `homeDir`; plus tmpfs masks under `/proc/` and `/sys/` from the live list. Flag any other whole mount.
  - Add the live fault "workspace from the state dir" and a unit case per rule. Replace the trimmed `clean` fixture with the full live mountinfo so the pins are exercised.
- **M2. A `podman run` client that dies for any reason other than the timeout leaves the container running with no bound.** `internal/sandbox/run.go:131-139`. Only `run.Err() != nil` triggers the forced removal. If the client is killed (OOM, a controller restart, a signal) the attached container keeps running under conmon, its workspace stays live, `unsafe` is not set, and copy-out proceeds. Fix: on any non-nil error from `podman run` (and cheaply on success too) run `rm --force --ignore --time=0 name`, and set `unsafe` if that fails. In P9b, run `podman rm -af` in the private storage at daemon start, since every container there is ours.
- **M3. A non-root image `USER` breaks teardown, HOME and copy-out.** `internal/sandbox/run.go:101-106`. Under the default rootless map, files the process creates as a non-zero uid land on the host as subuid-owned. `Teardown`'s chmod and `RemoveAll` then fail on their subdirectories, 0600 files are unreadable to `CopyOut`, and the root-owned 0700 tmpfs HOME is unwritable. The PR assumes images run as root but never enforces it. Fix: add `--user=0:0` to the run args, and give `Teardown` a fallback through `podman unshare rm -rf <attempt>` when `RemoveAll` fails.
- **M4. `CopyTree` drops the executable bit, so every executable in the base shows as a mode change.** `internal/sandbox/run.go:227`. All files are created 0600. With `core.filemode=true`, the controller's `add --all` plus `commit` records 100755→100644 for every script in the base and loses `+x` on new ones, polluting the candidate diff P14 will compute. Fix: from the `fstat` already taken, create 0700 when `st.Mode()&0o111 != 0`, else 0600, for the tree copy.
- **M5. "Never run git on a run-written repository" is a caller convention, not a check.** `internal/sandbox/git.go:58-64, 99-108`. `Clone` and `Repo.Git(…, "fetch", url)` accept any URL. A local path under `<root>/runs/` would run `git-upload-pack` inside the run's `.git`, where that repository's own config applies (alternates plus `core.alternateRefsCommand`, which to my knowledge is not limited to protected config the way `uploadpack.packObjectsHook` is). Nothing in this PR passes such a path, so this is not High, but it is the invariant 01 row 239 promises. Fix: make `Clone` a `Host` method that refuses a URL whose resolved local path overlaps `h.Root` or any forbidden path with `ErrSpec`; state in `Repo.Git`'s doc that `fetch` and `pull` URLs follow the same rule; add a test.

**Low**

- **L1. The probe checks `CapEff` only.** `internal/sandbox/probe.go:36, 171`. Add `CapPrm`, `CapBnd`, `CapAmb` (a non-root USER with the default cap set has `CapEff` 0 and a full bounding set) and `cpu.max` for `--cpus`. Cheap and more discriminating.
- **L2. The hostile fixture lacks the `.gitmodules` with a `file://` URL that 00 §2.7 names.** `internal/sandbox/git_test.go:60-66`. Add it, pointing at the run's own `.git` path, and assert no fetch of it across the same ten commands.
- **L3. `GIT_ATTR_SOURCE` carries the SHA-1 empty tree.** `internal/sandbox/git.go:44`. A sha256-format remote makes every command die with "bad GIT_ATTR_SOURCE" (fail-closed but opaque), and git below 2.40 ignores the variable silently. P9b's version check should also refuse `extensions.objectFormat=sha256` in the snapshot, or pick the empty tree per format.
- **L4. Unnormalised pins are refused.** `internal/sandbox/image.go:66`. `RepoDigests` holds `docker.io/library/debian@…`, so a profile pin `debian@sha256:…` fails closed. Document that pins are fully qualified, or normalise before comparing.
- **L5. A disk bound "in Validate" cannot bound a running container.** `internal/sandbox/run.go:105-107`. `/tmp` and HOME are size-limited tmpfs; the workspace and results are not. A run can fill the filesystem it shares with the state directory and wedge the event store. P9b should bound at the source: `runs/` on its own filesystem or project quota, or a sized tmpfs workspace with copy-out through `podman cp`, plus a post-run `du` refusal.
- **L6. The in-container `homeDir` `/home/adc` collides with a plausible controller home.** `internal/sandbox/sandbox.go:43`, `probe.go:79, 155`. If the controller runs as a service user named `adc`, the probe reports `controller path present: /home/adc` forever. `Validate` should refuse `Home == homeDir`, or pick a non-colliding path such as `/var/sandbox/home`.
- **L7. The cgroupfs manager needs delegation.** `internal/sandbox/sandbox.go:107`. Under a systemd system service, limits apply only with `Delegate=yes`; otherwise the probe goes red, correctly. Document it in P9b's config refusal text.
- **L8. Trust note.** `internal/sandbox/probe.go:17-25`. Confirms the lead's item 5. State in the doc comment that the probe proves the runtime's configuration given an honest, controller-prepared, digest-pinned image, and consider a static controller-provided probe binary mounted read-only in P9b.
