## Opus pre-review of #229

Verdict: NO-GO. One High finding (hardened git). The rest are fixes that can land later.

Tested on host git 2.43.0 with `scratchpad/probe-git.sh`, which reproduces the PR's exact `-c` list and environment. I did not run `go test`: there is no Go toolchain on PATH here. I skipped the live Podman tests.

### High

**H1. Hardened git still runs repository commands: `internal/sandbox/git.go:15-33`. This is reachable.**
- **Why it is reachable.** The `hostile-git-dir` case in §2.6 has the controller diff "a copy of that workspace", `.git` included. `TestGitIsHardened` itself plants keys in the copy's `.git/config`. So repo-local config and `$GIT_DIR/info/*` are attacker-written.
- **Why ownership checks don't help.** Rootless container root is the controller's uid. Every file the run writes passes git's ownership check, so `safe.directory` protects nothing.
- **Still executes** (canary created under the PR's `Git` setup):
  - `.git/info/attributes` with `* filter=evil` plus `filter.evil.clean`/`smudge`: runs on `add` and on `checkout -- a.txt`. These are exactly the operations the test claims are safe. `GIT_ATTR_SOURCE` replaces only the in-tree `.gitattributes`; `info/attributes` is still read.
  - `core.attributesFile` plus `filter.*.clean`.
  - `merge.<drv>.driver` via `info/attributes`, on `merge`.
  - `diff.<drv>.command` when `diff` runs without `--no-ext-diff`. The doc comment at `git.go:25-26` says `Git` passes that flag; it doesn't, callers must.
  - `include.path` pulling in a `filter.*` section. A command-line `-c` still beats an included key such as fsmonitor, but wildcard keys like `filter.*` get through.
  - `gpg.program` plus `commit.gpgsign` on `commit`.
  - `core.editor` on a commit without `-m`.
  - `remote.<x>.uploadpack` on a `fetch` of a local path.
- **Did not execute here:** `core.pager` (no tty), `log.showSignature` on an unsigned commit, an `ext::` remote, `alternateRefsCommand` on status, `textconv` once `--no-textconv` is passed.
- **Separate bug:** `-c diff.external=` (empty) makes a plain `git diff` fail with "cannot run : No such file". It fails closed, but it is a trap for callers.
- **Fix.** A denylist can't be completed, because `-c` and `GIT_CONFIG_COUNT` can't neutralise wildcard keys (`filter.*`, `merge.*`, `remote.*.uploadpack`, `include*`, `credential.<url>.helper`). Instead:
  1. Never run git with a `.git` the run wrote. Copy the workspace tree without `.git`.
  2. Run with `GIT_DIR` set to a controller-made repo (a fresh clone of the base) and `GIT_WORK_TREE` set to that copy. Set `GIT_CEILING_DIRECTORIES` too.
  3. Before each use, assert that this repo's `config` and `info/` hold only what the controller wrote.
  4. Keep belt-and-braces settings:
     - `-c` overrides: `core.attributesFile=/dev/null`, `commit.gpgSign=false`, `tag.gpgSign=false`, `gpg.program=false`, `core.editor=false`, `sequence.editor=false`, `core.pager=cat`.
     - Environment: `GIT_EDITOR=false`, `GIT_PAGER=cat`.
     - Have `Git` itself pass `--no-ext-diff --no-textconv` for diff.
  5. Extend the test to plant `info/attributes`, `core.attributesFile`, an `include.path` with a filter, gpg, editor and uploadpack. Add `commit`, `merge` and a local `fetch` to the operations it runs.

### Medium

**M1. Mount checks are lexical: `run.go:56-65`, `sandbox.go:155`.**
- A symlinked `Workspace`, `Results` or `Gateway` path (or one with a symlinked parent) gets past `overlaps`; Podman then resolves it to the target.
- It is also a denylist: mounting the controller's HOME or `~/.config` is not refused.
- **Fix:**
  - Allowlist `Workspace`/`Results` to `h.Root/runs/*/{workspace,results}`. Better, take an `Attempt` rather than free paths.
  - `EvalSymlinks` every mount and every `Forbidden` entry, check the resolved paths, and pass the resolved path to Podman.
  - `Lstat` the gateway and require a socket.

**M2. The probe can report green while containment is broken: `probe.go:25-36`.**
- Presence is checked only at the forbidden paths' own names. The state directory bind-mounted at `/mnt/x` passes. Only sockets are found anywhere.
- `--privileged`, a dropped `--cap-drop=all`, or `seccomp=unconfined` all leave the probe green.
- The `test -S` fix itself is sound: `[ -S ]` stats the mount target, and the probe walks bind mounts.
- **Fix:**
  - Emit the root and source of each `/proc/self/mountinfo` mount, and refuse any bind outside {workspace, results, gateway}.
  - Emit `CapEff`, `NoNewPrivs` and `Seccomp` from `/proc/self/status` and check `CapEff=0`, `NoNewPrivs=1`, `Seccomp=2`.
  - Add a live fault for `--cap-add=ALL` or `--privileged`.

**M3. Resource limits are not shown to be in force: `run.go:73`.**
- With rootless `--cgroup-manager=cgroupfs`, limits may not apply when the cgroup is not delegated, and `TestLiveProbeContained` doesn't check that they do.
- **Fix:** have the probe read `/sys/fs/cgroup/memory.max` and `pids.max` and compare them with the limits requested.

**M4. No disk bound on the bind mounts: `run.go:76-77`.**
- A run can fill the filesystem shared with the state directory, which is a denial of service against the controller's ledger.
- **Fix:** put `runs/` on a quota'd or tmpfs filesystem, or make that a host prerequisite that `Validate` checks.

### Low

- **L1. Copy-out: `run.go:139-175`.**
  - No cap on the number of entries or the depth (an inode or time bomb).
  - `root.Open` on an entry swapped for a FIFO blocks if the container outlived a failed `rm --force` (`run.go:104`).
  - **Fix:** cap entries and depth; open with `O_NONBLOCK` and `fstat` to confirm a regular file; refuse `CopyOut` when the `Start` cleanup errored.
  - Symlinks, devices, `..` and size are handled correctly.
- **L2. Cleanup can hang or fail.**
  - The cleanup `rm` uses `WithoutCancel` with no deadline (`run.go:104`). **Fix:** add a short timeout.
  - `Teardown` uses `RemoveAll` and fails on directories a run set to mode 000. **Fix:** chmod during the walk first.
- **L3. `GIT_ATTR_SOURCE` needs a recent git.** On an older git it is silently ignored. **Fix:** check `git version` once and refuse an old one.
- **L4. `Clone` of a local path uses the filesystem copy (`git.go:44`).** With the host's 2.43 the hostile source's config and attributes did not carry over and nothing ran, but CVE-2024-32021-class object tricks apply. **Fix:** pass `--no-local` or require `file://`. `protocol.file.allow` defaults to `always`, which is fine.
- **L5. Size.** Non-test code is 641 lines against P9's 600 (04 §2). The overrun is acknowledged; the lead should confirm it.

### Sound as written

- **Image pinning:**
  - an exact `RepoDigests` match;
  - the run starts the resolved ID with `--pull=never`;
  - the label is covered by the manifest digest, so the image can't change it without changing the digest;
  - lockfiles are read through `os.Root` with an `Lstat` check.
- **Podman's environment:** `env -i`, with everything under `Root`.
- **The 1 MiB output cap:** an error when exceeded, not a silent cut.
- **`--network=none`:** a new network namespace, which also isolates abstract sockets.
- **Mount option injection:** commas are refused.
- **The `testguard` exemption:** narrow. It covers the exact directory `internal/sandbox`, non-test files only, and only the string-literal rule; the `Setenv` rule still applies.
- **Fault evidence:** discriminating for network, path, socket and HOME. It is missing caps, a mount at another path, and limits (see M2 and M3).
