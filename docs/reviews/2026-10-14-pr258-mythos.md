### High

**H1. The floor-age guard is read before the fence goes up, so `Ended` can query while a request is in flight.** `internal/modelcall/reconcile.go:115`, `:126`, `:136`, `:196`.
- `run` takes its snapshot in `read` (a View), then records `uncertain`, then calls `query` with the snapshot's `v.young`. The floor fence in `sends` (`internal/modelcall/modelcall.go:433`) only starts refusing floors once the `uncertain` transition commits. A floor that commits between the View's snapshot and that commit is invisible to `v.young`, and its request is sent.
- Sequence: snapshot sees no young floor; the gateway commits floor N and sends; `uncertain` commits; `query` asks the provider now; the answer omits request N; the reconciliation records and the effect completes. If N's usage is read, its count lands and the max raises the figure. If it is not read, which an adapter forces by hanging up before the response is forwarded whole (`internal/gateway/gateway.go:224`, `whole` false), floor N is released against an answer that never saw it.
- The PR's Round 2 claim that the floor's age "subsumes `Serving` in process" is false in this window. Round 1 read `Serving` live, after the transition; Round 2 reads a snapshot taken before it. `Reconcile` on an already uncertain effect is fine: the fence is up before its snapshot. Only `Ended`'s pending path is exposed.
- The completed-path recheck does not help: with a reconciliation present, `StandingOf` is `Settled` whatever the floors.
- Fix: after the `uncertain` transition commits, re-read before querying (`v, err = r.read(ctx, call)` after line 126, or compute `young` only in a View taken after the fence). Test: a floor-only call whose `Now` hook, as in `TestARunEndRechecksTheStanding`, records a second floor inside the first View; expect `ObservedYoung` and zero questions. That test is red today.

**H2. A found answer settles a floor-only call at zero, unflagged, and the upstream chooses which requests are floor-only.** `internal/capacity/ledger/ledger.go:146-151`, `internal/gateway/count.go:94`.
- `trusted` bounds a reconciliation by `Seen` only. `Seen` is nil when no request has a `gateway_count`. A found 0/0 then settles the call at 0/0 with `Below` false and `Inconsistent` false. Without a query the same call was a liability at the larger of its reservation, delta sum and floors. The query lowers it to zero.
- A hostile upstream reaches that state for every request, not just the honest cases the lead's decision names. Two in-band moves do it: omit `usage`, so `result` is not ok and the floor stands; or report `completion_tokens: 0` while streaming content, so `Observed` is false at `count.go:94` and the count is recorded as a floor. Then answer the usage query with found zero. The gateway sent the request bytes itself and forwarded the content itself, and both observations are discarded. This is the entry 69 bypass through the one report the upstream fully controls, now reopened for the floor half of P11b.
- The existing F test never tries a found zero over a floor-only call: `TestAnUncertainCallIsNeverReleasedAtZero` releases it with 30/20, and `TestAFoundZeroNeverSettlesUnderTheCount` has a count. No mutation covers this path.
- Fix, minimum in this PR: in `trusted` and `StandingOf`'s overflow path, set `Below` and `Inconsistent` whenever the reconciliation does not cover `Counted` (floors included), so a zero against a nonzero floor is never silent, and add the test. Fix for the lead to decide, since it touches the floor-release decision: keep a call uncertain, at `max(reservation, floors)`, when a found answer is below the input of its floors, since the sent bytes are the gateway's own observation; or have P11b record a content-outweighed count under a distinct marker so `Seen` can keep its observed part. Record the chosen residual in #226 either way.

### Medium

**M1. A call settled `Below` is re-queried on every sweep, and every answer is appended, without bound.** `internal/modelcall/reconcile.go:130-137`, `:233-257`.
- `Reconcile` on a completed call with `Below` asks again and `reconciled` records a new reconciliation at `seq+1` even when the answer is unchanged. Nothing bounds it.
- Permanently `Below` is reachable with an honest provider: the count's input is `max(prompt_tokens, sent/16) - cached` (`count.go:94`), so any request whose body exceeds 16 bytes per upstream-counted prompt token (images, base64, long unicode) makes an honest usage answer below the count for good. A hostile upstream answering low gets one log event and one outbound query per call per sweep.
- This also conflicts with X3's assertion (a), "Σ settled = served-usage log, exactly", whenever the stub's `prompt_tokens` is under `bytes/16`: the settled figure is the count, not the log. Flag this to the lead for P21.
- Fix: re-query a `Below` call only when a `gateway_count` was recorded after the latest reconciliation (compare counted sequences, or store the `Seen` figure covered at the last reconciliation), and skip recording an answer equal to the latest one. Add a test that two sweeps with the same low answer record one reconciliation and ask once.

**M2. `Transition.Check` receives a writable transaction.** `internal/eventstore/effects.go:273-277`.
- `&Tx{ctx: ctx, tx: tx}` has `readOnly` false, so a `Check` can `Put` or `Delete` inside the transition's transaction with no event behind it. That is a projection change no rebuild reproduces. The comment "It writes nothing" is not enforced, in a contract package.
- Fix: build it as `View` does, `&Tx{ctx: ctx, tx: tx, readOnly: true, owner: s}`, and add a test that a `Check` calling `Put` gets `ErrReadOnly`.

**M3. `Ended` waits without its context, and the query it waits on has no bound.** `internal/modelcall/reconcile.go:89-95`, `:296`, `:216`.
- The runner's `q.Usage` runs under that runner's context only; a provider that never answers pins the call's runner, and every later `Ended` blocks in `done.Wait` regardless of its own context. P22a's run-end hook would hang with it.
- Fix: wait on a per-call channel with a `select` on `ctx.Done()`, and run `q.Usage` under a reconciler-owned deadline constant, so the lock is always released.

### Low

**L1. Reconciliation sequence is the count of reconciliations, not max+1.** `reconcile.go:251`, `:260-268`. Contiguous today only because the L1 action check leaves the reconciler as the sole writer. If any reconciliation ever carries a higher sequence (an operator settlement, a migration), later answers at `seq = count` are ignored by `latest` until the count catches up. Use `max(Sequence)+1` and check that in `reconciled`.

**L2. A wall-clock step forward defeats the grace.** `reconcile.go:196`. `r.Now` is `time.Now`; a step forward of more than `FloorGrace` during an in-flight request makes its floor look old, and if that request's usage ends unread its floor is released against an early answer. Rollback and skew the other way are conservative, as are a missing or forged time (floors are stamped by the store clock, never from input). Record as a residual in #226.

**L3. `Tx.Action` and the commit-only check are adequate.** `internal/eventstore/writer.go:176`, `internal/capacity/ledger/record.go:63`. The log is the trust root, `RebuildProjections` sets `Replaying`, the transition path projects effect events only, and the daemon authorizer fails closed on unwired actions, so `model_call.reconcile` cannot be forged today. Entry 60 now names it, system actor only. The adapter path fixes `source_of_truth` itself (`internal/adapterhost/submit.go:317`), so gateway sources cannot be forged either. One note for P22a: `modelcall.Project` is not in `internal/daemon/wiring.go:133` yet, and both the fence and the floor-age read depend on it.

**L4. A slow-reading adapter outlives the deadline, harmlessly for accounting.** `gateway.go:224`. `http.Client.Timeout` cancels the body read, but the blocked write to the adapter is not cancelled, so the handler goroutine lingers. The floor stands, ages past the grace, and the provider is asked, so no figure is affected. P22a's server needs a write timeout.
