### 1. Can a case pass when the product misbehaves?
**What holds (I traced each assertion to its read):**
- **Holds:** `holds` is compared exactly over the non-review nodes (`[]` included), so an extra or missing hold fails.
- **Results:** each kind in `nodes` must show at least one selected result, and every round must match. An absent field reads as `undefined !== null` and fails. `absent` fails a node whose `claimed_at` is absent as well as one that was claimed.
- **Merge:** a merge node fails, and so do the `merge-local` or `merge-github` capabilities if they are missing or active.
- **Approval and the stream:** `approval.recorded/v1` must come before the first `node.claimed/v1`, and the event stream must be gapless. The kinds match the product's `Transition + "/v1"` (`internal/lease/wiring.go:169`).
- **Requests:** the stub logs each request's whole body (`fixtures/m1/stub-provider/server.mjs:195`), so a hidden test name in a builder request fails. My probe confirmed it: "canary TestHiddenTransferToSelfIsRejected in a builder request".

### 3. Cleanup and the sweep: sound
- The driver's `cleanup` kills only the stub, adcd and the events reader, the PIDs it started.
- The sweep kills only PIDs that a dead driver recorded in `.pids`, and only while each PID's start time still matches (`owner_of`). It removes only directories that are:
  - owned by the user;
  - matching `adc-cycle.*` or `/tmp/adc??????`;
  - carrying an `.owner` whose PID and start time are gone.

  Kept directories and given roots carry no `.owner`. No other repository code makes those names.
- Work directories are swept before roots, so adcd is stopped before its root's storage is reset.
- A killed run's private root is never reused: each run makes a fresh `mktemp` root.
- The set runner's root is swept only once its own shell is dead.
- Small edges are listed under L2.
