### Findings

**B1 (BLOCKING). `ErrUnmeasured` is read as the candidate's.**
- `workloadFailed` (`internal/accept/integrity_loader.go:235-236`) returns true on any `ErrLeft`.
- But `within` joins `ErrUnmeasured` to `ErrLeft` exactly when the cause is *not* the candidate's: an I/O error, or a missing directory (`sandbox/run.go:66-71, 286-293`).
- **Fix:** `case errors.Is(err, sandbox.ErrLeft): return !errors.Is(err, sandbox.ErrUnmeasured)`.

**B2 (BLOCKING). A signal is read as `go list`'s own exit.**
- `sandbox.workload` maps 128-255 to `WorkloadExit` (`run.go:60`), and `workloadFailed` takes any `WorkloadExit`.
- A process killed by a signal (an OOM kill, or a kill from outside) is a resource or host fault, not a finding about the candidate's code (entry 168). A candidate that drives `go list` into the 2 GiB limit fails closed either way: `could_not_run`, five retries, then `runner: failed`.
- **Fix:** in `workloadFailed`, take only `w.Code >= 1 && w.Code <= 124`.

**B3 (BLOCKING). The list script's own commands are read as `go list`'s.**
- `listScript` (`integrity_loader.go:62-75`) runs under `set -eu`, so a failure of `go env`, `mkdir`, `awk`, `xargs cp` or `rm` exits the shell nonzero. That becomes a `WorkloadExit`, which `boxList` (`:187-188`) refuses.
- The line promises "`go list`'s own nonzero exit", and this is not that.
- **Fix:** the script records `go list`'s status itself and leaves `set -e` only around it. For example:

  ```sh
  set +e
  go list ... >"$r/list"
  echo $? >"$r/golist"
  set -e
  ```

  Then every other failure exits with one fixed status. `boxList` refuses only when `$r/golist` exists and is nonzero; any other `WorkloadExit` is `ErrGuardRun`.

**H1′ (High; the lead's call: it amends entry 168's line). `go list`'s own nonzero exit can be the host's.** With `-e`, package errors are recorded and `go list` exits 0. It exits nonzero only for fatal, module-level causes:
- an image whose module cache lacks a module the **base** requires (`GOPROXY=off`, `-mod=readonly`);
- an unreadable GOROOT;
- `-export` running out of the 256 MiB `/tmp` tmpfs on the cold-cache relist (script line 69) [INFERENCE: not reproduced].

Each would cost the same paid rounds, on every task of the project.

There is existing evidence that makes the line safe. The guard lists both the base's and the candidate's versions on each platform (`maxRunCopy`: "both versions' typers"). So: **refuse only if the base's listing on the same platform succeeded**, and otherwise return `ErrGuardRun`. The places to change:
- `integrity_proc.go:481-485`: `serve` classifies the listing; it needs the version (base or candidate) and the platform of the request, and the base's outcome;
- `integrity_loader.go:187-188`;
- `integrity_types.go:189-190` (`LocalLister`'s `goList`, the same rule).

A second, weaker piece of evidence: write `go list`'s stderr into `$r` and refuse only when it names a path under a directory the candidate changed. Podman's `--log-driver=none` drops it today.

This is the same class as #410's H1 (host fault, candidate's cost). I recommend it lands before `launch` activates. If the lead keeps entry 168's line as it stands, the residual's text in `integrity_loader.go:13-16` must say "up to the rounds rail", not "one repair round".
