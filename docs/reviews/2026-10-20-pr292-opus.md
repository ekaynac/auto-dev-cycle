## Opus pre-review of #292 (2026-10-20)

Verdict: NO-GO

Reviewed head 5a69f32 against base c9898b9. I ran `go test -count=1 -race -run 'Cases|AcceptsAndWarns|RealTypes' ./internal/accept/` in a copy and it passed (`ok … 92.9s`). The probes below ran as throwaway tests in the same copy. Each was also run against the base's `internal/accept` files to separate PR behaviour from main's. The copies have been deleted.

### High

**H1. A literal table row can be removed with no block and no warning.** `internal/accept/integrity_cases.go:134` and `:178`.
- **(a) A local table reassigned.** `lits` only records the `:=` definition. A later `tests = tests[:1]` or `tests = nil` placed before `for _, tc := range tests` keeps every base identity, so the result is silent. Probes `truncLocal` and `nilLocal`: blocks `[]`, warnings `[]`.
- **(b) A row moved to another table in the same test.** A row's identity is `"row " + prefix + name` and does not say which table it came from. Take `{"zero", 0, 0}` out of the asserting table and add, in the same test, `for _, tc := range []struct{…}{{"zero", 0, 0}} { t.Run(tc.name, func(t *testing.T) {}) }`. The identity, the row text, the counts and the print are all unchanged, so the result is silent (probe `moveRow`).
- **Fix:**
  - For (a), treat a local table as opaque (no identities) when it is assigned anywhere besides its definition (`=`, op-assign, `append`), when its address is taken, or when it is passed to a call. A reassigned table then reads as "unverifiable".
  - For (b), scope a row's identity to its loop, for example by prefixing it with the print of the loop body. A row moved under a loop that checks something else then counts as removed.
  - Add rows for both cases.

**H2. A new call to a skipping helper can go uncounted.** `internal/accept/integrity_cases.go:80-88`.
- **(a) A direct call.** `skipCall` requires a `live` argument, and `live` excludes any variable that is ever rebound. So `x := t; requireDocker(x); x = nil` adds a real skip that is not counted (probe `skipRebound`, silent). On main, `live` was only used for assertions, where counting too few is the safe direction. For skips, counting too few is the unsafe direction.
- **(b) Through a function value or an interface.** Each of these, using a helper the base already has, was silent:
  - `[]func(*testing.T){requireDocker}[0](t)` (probe `skipSlice`);
  - `struct{ f func(*testing.T) }{requireDocker}.f(t)` (probe `skipField`);
  - `with(t, requireDocker)`, where `with` is an existing runner (probe `skipWith`);
  - `var r req = h{}; r.require(t)` (probe `skipIface`);
  - `skipIt(t)`, where `var skipIt = func(t *testing.T) { t.Skip() }` (probe `skipClosureVar`).
- **Mitigation:** the gate refuses a test skipped at head (`internal/gate/gate.go:20-21`), but only when the skip actually fires in the gate's environment.
- **Fix:**
  - Count a call to a skipping function whatever its arguments are, or at least whenever any argument mentions a testing value; drop the `rebound` filter for skips.
  - Count any use of a skipping function as a value inside a test (not as a call's `Fun`) as a skip. This covers slices, fields, runners and aliases in one rule.
  - Treat a call to an interface method as a skip when a package method of that name is skipping.
  - Treat a package `var` holding a `FuncLit` whose body skips as skipping.

**H3. `testPrint` uses memory quadratic in nesting depth and none of it is charged to the work bound.** `internal/accept/integrity_cases.go:253-291`, called at `internal/accept/integrity_go.go:716`.
- Every assertion writes the conditions of all the statements around it. A test of n nested `if x != i { t.Error()` blocks is measured below.

| Nested ifs | File size | Main | This PR |
|---|---|---|---|
| 1,000 | about 26 KB | not measured | 223 MB allocated |
| 2,000 | 53 KB | 43 MB, 1.1 s | 816 MB, 2.2 s |

- That is ×3.7 per doubling. By extrapolation, a file of about 500 KB (`maxFile` is 4 MiB) would hold about 2.3 GB of print per scan. There are four scans (two platforms, two versions), all kept in `pkgFacts`.
- **Fix:** charge `len(print)` to `r.work` as it is built and stop at `maxWork`. Better, record per assertion a hash of (call, innermost condition, depth), or the conditions once per block rather than once per assertion.

### Medium

**M1. Gaps in the M9 warning (warn only).**
- `internal/accept/integrity_cases.go:269,272,285`: `types.ExprString` drops the contents of composite and function literals. Changing `if !slices.Equal(got, []int{1})` to `[]int{2}`, or `!func() bool { return Add(1, 1) == 2 }()` to `return true`, gives no warning (probes `sliceLit`, `funcLit`).
- `internal/accept/integrity.go:384`: the row-text check sits inside the equal-counts case. Editing `{"zero", 0, 0}` to `{"zero", 0, 1}` and also adding any assertion gives no warning (probe `rowEditPlusAssert`). The promise says "a row edited under the same name warns" without the equal-counts condition.
- The `Init` of an `if` statement is not part of the print.
- **Fix:** print the source text of conditions and calls with whitespace normalized, as `rows` already does. Compare `rowsChanged` whenever nothing blocks, whatever the counts. Include `Init`.

**M2. New blocks on edits main accepts.**
- `internal/accept/integrity_cases.go:237`: a row with no string literal is identified by its raw source text, with only whitespace collapsed.
  - Running gofmt on `{0,0}` to make it `{0, 0}` blocks with "1 test cases removed (row {0,0})" (probe `namelessFmt`; main accepts it).
  - A comment inside the row, or changing between one line and several, does the same.
- `internal/accept/integrity_cases.go:190-192`: `t.Run(otherName, …)` with `const otherName = "other"` reads as "unverifiable: 1 test cases … (run outer/other)" (probe `subConstName`; main accepts it).
- The replay did not hit either case.
- **Fix:**
  - Build a nameless row's identity from a canonical print of the expression without comments (`go/printer`), or identify nameless rows by count only and keep their text for M9.
  - Resolve constant subtest names through `info.Types[arg].Value`.

**M3. "Every declaration skips" is the unsafe direction.** `internal/accept/integrity_go.go:649`.
- With `requireX` skipping in `//go:build race` and empty in `//go:build !race`, a new `requireX(t)` is silent (probe `skipRaceVariant`).
- Requiring every declaration is correct for `asserting`, where counting too few is safe. For a skip, any one declaration should be enough.
- **Fix:** a name is skipping when any of its declarations skips.

**M4. A table whose loop calls a local closure is not followed.** `internal/accept/integrity_cases.go:104-107`.
- In `check := func(a, want int) { … t.Errorf … }; for _, tc := range []T{…} { check(tc.a, tc.want) }`, `drives` is false. The table is neither identities nor opaque, and removing a row is silent (probe `closureRowRemoved`).
- **Fix:** let `drives` follow calls to local `FuncLit` variables whose body asserts, skips or runs subtests.

**M5. Other work that is not charged.**
- `drives` calls `count` on each `RangeStmt`, so nested ranges cost quadratic time. With 2,000 nested ranges: main 0.31 s, this PR 0.99 s.
- `isDead` is a linear scan per call or selector, over every dead range.
- **Fix:** charge `count` calls inside `testCases`; skip dead subtrees while walking instead of scanning `s.dead`.

### Low

- **L1. Mutations no test catches.** I applied each of these in the copy and the whole package still passed (277 s):
  - removing the else-branch dead range (`integrity_cases.go:46`);
  - removing the `"else of if "` distinction (`:267`);
  - replacing the `min` merge of a test declared twice with plain assignment (`integrity_go.go:719`).

  The merge also drops `old.rows`. Add rows for `if true {} else { t.Fatal() }`, for an inverted `if`/`else`, and for a race/`!race` test that loses a row in one variant.
- **L2.** `internal/accept/integrity_go.go:608`: `rebound` is set during the first of the two passes and never cleared. A package variable assigned from another variable that only becomes a testing value later stays rebound, so the result depends on declaration order. **Fix:** set `rebound` only in the second pass.
- **L3.** `rebound` is syntactic: `x = fakeOf(t)` mentions `t`, so `x.Errorf` still counts (probe `reboundWrap`). Either state this as a residual or resolve the callee's result type.
- **L4.** `testCases` ignores `isDead`. `if false { t.Run("other", func(t *testing.T) {}) }`, with the subtest's assertion moved into its parent, keeps the identity silently (probe `subDeadKeep`; the assertion still runs).
- **L5.** `internal/accept/integrity_cases.go:251-252`: the comment says a range "over a table by its name only" is part of the print, but no `RangeStmt` is recorded at all. Fix the comment, or record the name.
- **L6.** Skips are matched by selector name, so a helper that calls some other type's `.Skip()` (for example `xml.Decoder.Skip`) is now "skipping". A new call to it would block falsely.

### Judged as sound
- These all block as promised:
  - generic skipping helpers and generic methods;
  - method expressions;
  - `defer requireDocker(t)`;
  - `t.Skip` through an interface variable;
  - renaming a row's name;
  - nested and map subtests;
  - a table moved to a package variable;
  - a computed `t.Run` name.
- Replacing `t` with `new(testing.T)`, `&testing.T{}`, or a `W{t}` wrapper is already blocked by the types layer.
- Where "unverifiable" fires, it changes only the message: a missing identity blocks either way. The risk of false blocks therefore lies in how identities are built (M2), not in the opaque flag.
- The PR's 22 rows and 13 mutations are as described. Most of the missing coverage is H1, H2, M3 and L1.
