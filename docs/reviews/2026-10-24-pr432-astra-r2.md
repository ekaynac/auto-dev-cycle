- **Concrete input:** a completed candidate has build attempts A1 → A2, with both leases settled and A2 carrying measured usage. Change only `unit_attempts[unit]` from A2 to A1. A1 still correctly records `superseded_by: A2`.
- **Failure:** `AttemptsOn` checks `SupersededBy` only after the first iteration. It accepts A1 as the current attempt and returns its history alone. All returned records belong to the correct unit, so the ownership checks pass.
- **Production consequence:** `benchOf` collects leases only from those returned attempts (`internal/api/taskbench.go:74`, `:79`). A2, its calls and its measurements disappear. The healthy closing review remains; `benchInputs` and `bench.Record` accept the shortened inventory and write a successful benchmark with understated attempts, tokens and charges.
- **Fix:** require the indexed current attempt to have no successor. Also validate chain termination against fencing-token evidence, and reconcile an absent current index with the existing first-attempt evidence. Do not equate the first-attempt index with the chain root: M3 below explains why.

**High — H5. A missing call-index entry silently removes a settled call despite contradictory settlement evidence.** `internal/api/tasks.go:307`

- **Concrete input:** a completed candidate has a settled lease L whose `Settlement.Calls` contains C, with C’s binding and positive usage intact. Delete only `model_call_leases[L/C]`.
- **Failure:** `ledger.BoundTo` returns an empty list. `attemptLease` validates only entries it receives; it never compares that inventory with L’s settlement. Every subsequent check passes.
- **Production consequence:** `benchLease` emits `calls: []` and zero settled liability (`internal/api/taskbench.go:157`, `:174`). `ledgerOf` accepts this because no positive liability remains (`internal/cli/bench.go:375`, `:382`). The recorder writes the candidate successfully without C’s tokens or charge.
- **Fix:** for a settled lease, require the bound-call inventory to equal the union of `Settlement.Calls` and `Settlement.Liabilities`. Extract and reuse the inventory comparison already implemented at `internal/capacity/liability.go:98`. Do not reuse its historical settled/unsettled classification check wholesale: late usage can legitimately change a call’s standing.

Both findings concern damage encountered after startup. Replay detecting that damage on a later restart does not prevent the incorrect exit benchmark.

**Medium — M3. The new first-attempt check rejects a healthy store allowed by main’s ordering rule. Regression against main.** `internal/api/tasks.go:261`

- **Concrete input:** A1 and its successor A2 have equal recorded start times, with A2’s ID sorting before A1’s. This can occur in production after a backward clock step: event time clamps to the previous event’s time (`internal/eventstore/store.go:362`), while attempt IDs come from the UUIDv7 wall-clock generator (`internal/daemon/run.go:665`, `internal/ids/ids.go:170`). For example, step the clock backward immediately after A1 starts, then recover and replace it while recorded time remains clamped.
- **Failure:** main’s `lease.first` deliberately chooses the earliest start, then the smallest ID (`internal/lease/wiring.go:631`), so it correctly indexes A2. The new check rejects A2 because `Supersedes != nil`.
- **Consequence:** the one-task read fails, the list reports `damaged_record`, and `task wait` retries the failed read until timeout. The store can replay correctly; there is no damaged row to repair. This is a visible read regression, not a healthy-loop stall.
- **Fix:** retain the ID/unit checks and remove the unsupported “supersedes none” requirement. Any stronger validation must use the existing time-and-ID ordering rule.
- **Reuse search:** `rg 'FirstOn|FirstProjection|Supersedes|first attempt' internal/lease internal/api` identifies the existing rule and `TestFirstOnKeepsTheEarliest`. The new condition implements a different definition of “first.”
