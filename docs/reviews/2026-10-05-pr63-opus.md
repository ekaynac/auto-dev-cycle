# PR #63 (TypeScript contract generation): review

## Review of #63 (Opus subagent, 2026-10-05)

Verdict: NO-GO

One High finding blocks: `make ci` fails on a clean CI runner at its first TS step (`ts-deps`) because of how corepack picks the pnpm version. The fix is one line. Everything else is Medium or Low.

Method: a copy without VCS metadata at `scratchpad/rv63/`, with dependencies reinstalled from the lockfile (`pnpm install --frozen-lockfile`).
- Differential probe of the three formats: Go (`checkTime`, `CheckTypeID`, `checkReason(…, false)` through a test-only export) against `gen/ts/formats.cjs`, on 56,059 time strings, 220,013 TypeIDs and 11 reasons.
- Regex-engine probes: santhosh-tekuri v6 against Ajv.
- Byte-level corpus probes.
- 38 mutations of `formats.cjs` against the corpus.
- 7 mutations of `gen/ts` against `make gen-check`.
- `strictTypes` enumeration, plus Go `schemagen` mutations.
- `check-spdx` before and after the fix.
- The TS step inside `scripts/test-sandbox.sh`.
- Corepack resolution with a fresh `COREPACK_HOME`.

### High

**H1. `make ts-deps` resolves the wrong pnpm under corepack, so `make ci` fails on a clean runner.** `Makefile:82` runs `pnpm --dir adapters install --frozen-lockfile --reporter=silent` from the repository root.
- Corepack chooses the package-manager version from the **current directory**, and it does not read `--dir`. The root has no `package.json`, so corepack takes its "last known good" pnpm. On a fresh home that is the registry's latest, pnpm 12.9.1 today.
- pnpm 12 then reads `adapters/package.json` (`packageManager: pnpm@10.33.0`) and refuses: `ERR_PNPM_BAD_PM_VERSION … pnpm does not switch versions when running under corepack`.
- The CI step `corepack enable && cd adapters && pnpm --version` downloads 10.33.0 but does **not** set last-known-good to it. Verified: after that step, `lastKnownGood.json` still says 12.9.1.
- Reproduction with the runner's own toolchain (Node 22.23.2 from the hosted tool cache, corepack 0.34.6, `CI=true`, an empty `COREPACK_HOME`): `(cd adapters && pnpm --version)` prints `10.33.0`, then `make ts-deps` exits 2 with `ERR_PNPM_BAD_PM_VERSION`.
- `gen-check` (and `gen`, `test`) depend on `ts-deps`, so `make ci` stops at `gen-check`. It passes on the author's machine only because `~/.cache/node/corepack/lastKnownGood.json` already pins pnpm 10.33.0.
- Fix: run the install from inside the workspace, `cd adapters && pnpm install --frozen-lockfile`. Verified: it exits 0 with the same fresh corepack home. Alternatives are a root `package.json` with `packageManager`, or `corepack install -g pnpm@10.33.0` in CI. Any future recipe that calls pnpm from the root has the same trap.

### Medium

**M1. Patterns with `\s`/`\S` do not mean the same in Go and in Ajv.**
- Where: `schemas/config/project-profile.json:22` (`^refs/heads/\S+$`), `:285` (`^\S+/$`, `vocabulary.branch_prefix`) and `:313` (`^[^@\s]+@sha256:…`, `PinnedImage`).
- santhosh-tekuri v6 compiles patterns with Go RE2, where `\s` is ASCII `[\t\n\f\r ]`. Ajv uses a JS `u` RegExp, where `\s` is Unicode whitespace plus `\v`.
- Probe on `^\S+/$`: `"a b/"`, `"a\vb/"`, `"a﻿b/"`, `"a b/"` and `"a　b/"` are all **valid in Go and invalid in TS**.
- Failure scenario: a profile with `branch_prefix: "adc /"` (pasted from a document) passes `contract.Validate` but fails the TS validator. The reverse holds for `base_ref` and image digests.
- The formats agree, but "TS validators classify like Go" is false for these three schemas.
- Fix: replace the classes with explicit ASCII ones (`[^ \t\n\r\f]`, or `[!-~]` where printable ASCII is meant), and add corpus cases. Better still, have one of the generators refuse `\s \S \w \W \d \D \b` and `.` in patterns, the constructs whose meaning differs between RE2 and ECMA `u` mode.

**M2. The TS validators check parsed values, so none of `contract.Validate`'s byte-level rules apply on the TS side.**
- `contract.go:234-262` refuses, before the schema runs: non-integer spellings (`10.0`, `1e1`), `-0`, duplicate keys at any depth, unpaired surrogate escapes, invalid UTF-8 and trailing data. Note 01 and the spike make this a cross-language rule ("`3.0` … is refused by `Decode` as non-canonical, so Go and TypeScript agree on identity").
- Through `JSON.parse` followed by the generated validator, all of these are accepted.
- Demonstrated: I appended four `lease` cases to `fixtures/contract/cases.json`, each marked `valid: false` (`"priority": 10.0`, `"priority": 1e1`, `"fallback_step": -0`, a duplicated `priority` key). `go test ./schemas/` passes. The TS test fails on the first of them (`lease: priority spelled 10.0: null`, which means it was accepted).
- Failure scenario: the adapter SDK reads JSON-RPC from stdio with `JSON.parse`, validates and accepts. adcd refuses the same bytes, and vice versa for anything the SDK writes after a parse round-trip.
- Not blocking for this PR, but it should be stated in the description as a known limit. The SDK PR then needs a strict byte-level parse (or `@adc/contract` should export one, e.g. `validateBytes(schema, text)`), and the corpus can only carry such cases after that.

**M3. The corpus does not prove the claims it is cited for.**
- Scope: 31 cases on **2 of 26** schemas (`records/actor` ×24, `records/lease` ×7), 8 valid. There is no `oneOf` union, `allOf` envelope, `unevaluatedProperties`, `if/then`, `uniqueItems`, typed map or array-or-literal case: the shapes where Ajv and santhosh most plausibly differ, and the ones the spike's 72 cases covered.
- Mutation of `gen/ts/formats.cjs`: **21 of 24** single-entry changes to the month-length table survive. Only Feb ±1 and Apr +1 are caught: there is no valid Jan 31 / Mar 31 / … case and no Jun/Sep/Nov 31 case.
- Also surviving: dropping the length check, the first-character check, the underscore check, and turning "no regex match" into `true`. Those four are shadowed by the schema pattern, as the PR says.
- The code is correct today: the differential probe found **zero** in-pattern disagreements (56k times, 220k TypeIDs). But "every adc format edge" is overstated, and a regression in the table would pass CI.
- Fix: add the last valid day and the first invalid day of every month, and at least one case per union and envelope shape (the spike's cases can be ported). "Step 12 grows it" is fine for the rest.

### Low

**L1. `formats.cjs` disagrees with Go outside the schema pattern.** `time()` (`gen.mjs:58`) accepts `"2026-01-01T00:00:00"`, `"…00:00:00Zjunk"`, `"…00:00:00.Z"` and `"…00:00:00z"`, which Go refuses. That is harmless inside the validators, where the pattern is ANDed. But `gen/ts/package.json` has no `exports` map, so `@adc/contract-gen/formats.cjs` can be imported directly, and its header says "as internal/contract checks them". Anchor the regex (`(\.\d{1,9})?Z$`) or say that the pattern is required.

**L2. Reader-direction reasons (decision 2): acceptable.** `adapter/event.json` has no `ReasonCode` and no registered code is deprecated, so nothing changes behaviour today. When a TS writer of `receipt`/`attempt`/`lease` appears (the fake adapter or the conformance kit), it needs a writer build: a second standalone output whose `adc-reason` refuses deprecated codes. Add a deprecated-code corpus case with the first deprecation.

**L3. `strictTypes: false` (decision 1): acceptable, with a count nit.**
- I verified the compensating claim. Removing `"type": "string"` from `actor.name` makes schemagen fail (`unsupported shape: no type`). `minimum` on a string schema is refused (`keyword "minimum" is not supported on a string schema`). Both are things only `strictTypes` would catch in Ajv.
- Today's `strictTypes: "log"` output is exactly 66 `pattern` and 2 `minLength` warnings (the PR says 62), all in the forms explained.
- Optional hardening: run `strictTypes: "log"` in `gen.mjs` and fail on any warning outside those two forms.

**L4. `allErrors: false` (decision 3): acceptable.** SDK error reports will carry only the first error, so diagnostics in the conformance kit will be thinner than Go's.

**L5. Packaging the SDK will trip on:**
- `gen/ts` is `@adc/contract-gen`, with no `main`, `exports` or `types`. Note 01 line 32 says `gen/ts` is "published as @adc/contract", but here `@adc/contract` is the generator package and exports nothing.
- `validators.cjs` has no `.d.ts`, so each export is `any`, not a `ValidateFunction<T>` type guard.
- The types are `.ts` sources (importing them needs `allowImportingTsExtensions` or type stripping). Cross-file `$ref`s are dereferenced, so `TypeID`, `Time` and `ReasonCode` are plain `string`, every module carries its own copy, and there are artifacts like `Argv1` (`project-profile.ts:36`).

Decide the public entry point and add a typed wrapper before the SDK PR builds on deep paths.

**L6. `--reporter=silent` hides why `ts-deps` failed.** With a drifted lockfile (`yaml` changed in `adapters/contract/package.json`), the only output is `make: *** [Makefile:82: ts-deps] Error 1`. In CI the cause is invisible. Use `--reporter=append-only`, or keep the default and silence only on success.

**L7. PR text.** There are 26 schema files and type modules, not 24. The `strictTypes` count is 66, not 62.

**L8. Schema discovery differs between the two sides.** The TS generator and coverage test walk all of `schemas/**.json`. Go embeds an explicit directory list (`schemas/schemas.go:23`). A new top-level schema directory would get a TS validator and no Go one, and the coverage test only compares TS with the file tree, so it would not notice.

### TestPatternsArePortable

The test is sound for its purpose.
- Reverting `branch_prefix` to `^\S+/$` fails it with the `\s and \S` message. Putting a bare `.` in the `Time` pattern fails it with the line-terminator message.
- The built-in probes cover `\S`, `\s` inside a class, a bare `.`, an escaped `.`, `.` inside a class, and the explicit class.
- Escapes are stripped before classes, so `\\.` (an escaped backslash followed by an unescaped dot) is still flagged correctly. The remaining imprecision is conservative: a literal `\\s`, or a `]` first in a class, gets flagged rather than missed.
- The other RE2/ECMA divergences I checked fail loudly at generation or compile time rather than silently mismatching. These were `\pL`/`\p{Greek}`, `(?i)`, `\z`/`\A`, `\Q…\E`, `\x{…}`, POSIX `[[:alpha:]]`, `[]a]`/`[^]…]`, backreferences and lookaround.
- `\d`, `\w` and `\b` are ASCII in both engines here, since there is no `i` flag.
