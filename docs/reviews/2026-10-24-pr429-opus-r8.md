### OBLIGATION

**L1 (Low). `go/doc.Examples` is quadratic, and the gate runs it twice per gate run with no deadline.**
- **Where:** `AcceptanceTests` calls `doc.Examples` once per test file (`internal/gate/acceptance.go:182`). That function rescans the file's comment list for every example (`lastComment`), and for an external `_test` package it also walks every declaration per example (`playExample`).
- **Measured:**
  - examples-only external file: 2000 / 4000 / 8000 examples in 74 / 176 / 632 ms;
  - one 1 MiB file: 9.4 s of examples, 13.3 s of examples mixed with commented declarations;
  - fifteen 1 MiB example files (within `MaxOverlay`): 2 min 14 s.
- **Effect:** `AcceptanceTests` runs in `overlayOf` (`internal/daemon/gate.go:361`) and again in `gate.Run` (`internal/gate/gate.go:214`). Neither checks `ctx`, so an operator's acceptance at the bounds costs about 4–5 min of one core per gate run, repeated for each repair round's gate. The cost is bounded, fails nothing and holds nothing, and only the operator can author an acceptance. The go command does the same work inside the container, under the gate's limits.
- **Fix:** run `AcceptanceTests` once per gate run (`overlayOf` already has the list; pass the expected tests into `gate.In` instead of recomputing them). Then bound it: refuse an acceptance with more than, say, 1000 functions per file as the task's (a fixed text), or run the check under `ctx`. Alternatively, state the bound in `acceptance.go`'s boundary comment.
