### High

**H1. A state directory, sandbox root or shared run directory under a system directory is inside the jail, read-only.** `internal/daemon/config.go:182-197`, `internal/daemon/adapter.go:28-29`
- **Cause:** `adapterPath` keeps the *adapter's* directory apart from the state directory, the home, `/run`, the sandbox root, the shared run directory, `/proc`, `/dev` and `/tmp`. Nothing keeps those paths apart from `systemDirs` (`/usr`, `/lib`, `/lib64`, `/bin`, `/sbin`), which `hostAdapter.Start` binds whole (`--ro-bind-try /usr /usr`, …). `sandbox.Host.Validate` does not forbid a root under `/usr` either: `ownDisk` only asks that `<root>/runs` be its own tmpfs/ext4/xfs device, apart from the home's and the forbidden paths'.
- **Input:** adcd at `/usr/local/bin/adcd` (so the release root is `/usr/local`), `adcd run --state-dir /usr/local/var/adc --sandbox-root /usr/local/sbx --adapter /usr/local/lib/adc/run`, with `/usr/local/sbx/runs` a mount of its own. Every check passes: the adapter's directory `/usr/local/lib/adc` overlaps none of the apart paths. The jail then holds, read-only, `/usr/local/var/adc` (the event store, the blobs, the secrets file, the clones with their `.git`) and `/usr/local/sbx/runs/*` (every other attempt's workspace, exchange and gateway socket). A read-only bind does not stop `connect()` on a unix socket (the kernel's `sb_permission` exempts sockets from the read-only check; flatpak relies on this, binding its sockets with `--ro-bind`), so another attempt's gateway, and its credential, is reachable too. The same holds for the shared run directory. This contradicts `adapter.go:35-37`'s unconditional "Nothing of the controller's state directory … is in its namespace", and judge question 1 answers "yes" for this configuration.
- **Fix (Decision A, fail closed):** in `adapterPath`, after building `apart`, refuse any `p` in it (resolved) for which `overlap(p, s)` holds for some `s` in `systemDirs`; or do the same in `hostAdapter.Start` against `jail.ReadOnly` before spawning (`Writable` paths and the state directory must not lie under any `ReadOnly` path). Make `systemDirs` settable by a test, like `runTree`, and add a row to `TestTheAdapterIsTheReleases` with a state directory under a planted "system" directory. Refuse both directions with `overlap`.

### Low

**L1. A sandbox root under `/tmp` passes every check and the jail then hides the attempt's own binds.** `internal/daemon/config.go:182`, `internal/adapterhost/session/process.go:67`
- `sandbox.Host.Validate` accepts `--sandbox-root ` when `/tmp` is a tmpfs mount of its own. The jail binds the workspace, the exchange and the socket under it, then mounts `--tmpfs /tmp` over them. Every attempt fails at the adapter's first dial. Fail closed, but opaque, and at every attempt rather than at load.
- **Fix:** when `--adapter` is set, refuse a sandbox root that overlaps `/tmp` in `adapterPath`, with a row.

**L2. The home rule is void when `HOME` is unset, and differs from the sandbox's.** `internal/daemon/config.go:136,183-185`
- `userHome` is `os.UserHomeDir` (`$HOME`); on an error the home is silently left out of `apart`. The sandbox uses `home()` (`config.go:222`, the passwd entry) and refuses when there is none. A system service without `HOME=` gets no home check.
- **Fix:** use `home()` and refuse an empty one (Decision A), as `sandbox.Host.Validate` does.

**L3. Nothing checks who may write the release's `lib/adc`.** `internal/daemon/config.go:160-180`
- The allowlist proves the adapter is a regular executable under the release's resolved `lib/adc`, neither `lib` nor `lib/adc` a symlink. It does not check ownership or group/other write bits. A jailed adapter cannot write it (bound read-only), so only the controller user or the operator can; `install-check.sh` verifies `SHA256SUMS` at install. Defence in depth: state it, or refuse a `lib/adc` writable by group/other.

A symlink inside `lib/adc` to elsewhere resolves outside the prefix and is refused. `go test`/`go run` binaries have no `lib/adc` and are refused.
