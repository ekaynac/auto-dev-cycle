### Judgement on the asked points

- **Real wiring.** Yes. The fixture uses the real event store, the real writer (`Submit`) and the real `lease.Projector` as the Project hook, with the vocabulary's holds. Setup goes through the production command helpers (`RequestLease`, `ChangeLease`, `StartAttempt`). The stop goes through `ChangeAttempt`, and the projector re-derives and admits the closed-publication attempt. `FenceOutput` then reads the `unit_attempts` and `attempts` projections inside a writer transaction. Every refusal the setup or stop could produce, other than `*lease.Stale`, becomes a fixture error rather than a step. This holds for the projector's derivation errors and for `StaleRecord`. A broken setup therefore cannot pass as a green step.
- **Mutation site** (`internal/lease/attempt.go:149`).
  - Off: `!mutation.Is(...)` is the constant `true` in ordinary builds, so the case is identical to before and compiles away.
  - On: only the publication branch falls through to `nil`. The id and token branches are untouched.
  - The cross-matrix confirms that the fixture turns red only because of that branch.
- **Step mapping** (`internal/fixtures/fixtures.go:145`). Mapping `errors.As(err, new(*lease.Stale))` to `failed/stale_attempt` is correct. `Stale.Reason()` is `vocab.ReasonStaleAttempt`, and 05 names exactly that refusal. The writer wraps hook errors with `%w`, so `As` reaches the value. The case is ordered after the `eventstore` sentinels, which is harmless because the types are disjoint.
- **Units stand-in** (`internal/fixtures/lease.go:18-23`). It cannot hide a defect here. `Projector.Units` is read only in `checkpoint`, on `attempt.sealed`, and this fixture never seals. See Low-1.
- **Leaks, order and parallel safety.**
  - Each run gets its own `os.MkdirTemp`, removed by `Run`.
  - The lock and the store are released by `defer`.
  - All ids are fresh, and there is no package-level mutable state.
  - The mutation switch is `t.Setenv`, which forbids `t.Parallel` in that test, so parallel mutation runs cannot cross-talk.
  - The shuffle and race runs are clean.

### Findings

**High:** none.

**Medium:** none blocking. One scope note, kept as Medium-informational because the PR and the golden are honest about it:

- M-1 `fixtures/contract/m0/revoked-attempt-late-result.json:3`, `internal/lease/wiring.go:225-239`.
  - 05 says a stale output is "refused with `failed/stale_attempt` **and recorded**". The fixture proves the refusal half only. `FenceOutput` returns an error, so the transaction rolls back and nothing is recorded. The golden's invariant text does not claim the recording either.
  - `FenceOutput` has no production caller yet (grep shows only the fixture). The fixture therefore proves the fence and its projection lookup, not an output-landing command path, and there is none to prove yet.
  - Recommendation: when result submission or patch landing is wired (the `attempt.result_submitted` companion record), either route this fixture through that command or add a step asserting that the refusal is recorded. Track it as a follow-up; it does not block this PR.

**Low:**

- L-1 `internal/fixtures/lease.go:18-23,45`. `oneTask` is dead in this fixture. Passing `Units: nil` would be stricter: if a later edit added a seal, `checkpoint` would refuse loudly instead of binding against a made-up project and task. Optional.
- L-2 `internal/fixtures/lease.go:38,49`.
  - `defer lock.Release()` and `defer s.Close()` drop their errors.
  - The previous commit `e3b88b1` made `secondDaemon` report release errors. The shared `store()` helper (`eventstore.go:36`) drops them in the same way, so this is consistent with the framework, but the stack is inconsistent with itself.
  - Consider a named-return `errors.Join` here or in a shared helper.
- L-3 `internal/fixtures/lease.go:91-98`. Step 2 folds the stop command and the late output into one step. If the stop were refused with an `eventstore` sentinel, that refusal would be reported as step 2's result, not as a fixture error. The fixture would still go red with the wrong reason, so no defect can be hidden; only the diagnostic text is muddier. Making the stop a setup action (error means the fixture could not run) and step 2 the output alone would be cleaner.
- L-4 `internal/fixtures/lease.go:86`. The token `1` is hard-coded. It is correct, since `Start` mints token 1, but naming it or reading it from the projected attempt would keep the fixture honest if first-token minting ever changes.
- L-5 `internal/fixtures/lease.go:116`. The fixed `Deadline` (`2026-10-04T14:00:00Z`) is already in the past. Nothing checks it today. If lease admission later compares deadlines with a clock, this fixture breaks for an unrelated reason. Consider the fake clock or a far-future constant.
- L-6 `internal/fixtures/mutation_test.go` (framework, not this diff). The mutation test asserts only "not green". The property "only the targeted step changes" holds today (verified above), but no test checks it. A per-golden expected-under-mutation sequence would pin it.

output is a command that fences and appends one event (`fixture.output/v1`, registered beside the lease kinds), so a
