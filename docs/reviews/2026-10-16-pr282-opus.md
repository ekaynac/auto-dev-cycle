But `typer.parse` keeps the files it appended before a failure: a second package name, a later file that does not parse, or a later file that cannot be read. `need` also parses even when `ty.why` is set. The base guard then fails every import of that package (`integrity_types.go:497-503`) and never type-checks those files. The layer checks them at `:105-115`.

- **Results of probe A:**

### Medium

**M1. "No slot" waits until the run's deadline instead of stopping, and a worker is started after the deadline. Rule 4 says that with no slot the layer gives the stop warning.**

- **Where:** `internal/accept/integrity_out3.go:175-185` (the slot is polled every 10 ms until `listEnd`) and `:192-211` (no check of the deadline before `go func`).
- **Probe B:** the slot is held (`outWorkers.Add(1)`), `maxListTime` is 6 s, and the change is an ordinary `tool/x.go` change. Main: 0.18 s. Head: 6.02 s, plus the stop warning. In production that is up to 5 min for every run, and for every concurrent run while a peer's long check runs.
- **Also:** if the run's last check began after `listEnd`, a free slot still starts the worker. It is dropped at once and keeps the slot for its whole run time.
- **Even with H1 fixed:** when main uses more than half of `maxListTime`, the layer's check is dropped. Its remaining run time (up to one of main's checks) then delays later runs.
- **Fix:**
  - Count dropped workers (`outDropped atomic.Int32`, plus 1 on a drop, minus 1 when that worker ends).
  - If `outDropped > 0`, give the stop warning at once, with no wait.
  - Wait only for a live peer's check, and within a short bound measured from the run's own start.
  - Return false before starting a worker when `!time.Now().Before(deadline)`.
- **Residual:** state it in the residual. While a dropped worker runs, a later run that changes a libc-importing file of a tested package is **blocked** (probe D). Today the residual says only "gives the stop warning". This cross-run block follows from rules 4 and 5. The lead should confirm it.

**M2. Must-pass row Opus #280 L1 is not closed for its own probe. The PR's row uses `F.Stat()`, whose name happens to be in `osRead`.**

- **Where:** `internal/accept/integrity_out3.go:332`. `sensitive(pkg+"."+name)` classifies function names, and is applied here to method names.
- **Probe C** (Opus's input):
  - `osr2/r.go`: `func rd(f *os.File) int { b := make([]byte, 1); n, _ := f.Read(b); return n }`.
  - Change `1` to `2`.
- **Results:** the head warns "osr2/r.go: changed bodies that use os (1: func rd)". Main (a03c3af) is silent. `(*os.File).Read` maps to `sensitive("os.Read")` = 1, because `Read` is not in `osRead`. `ReadAt`, `Readdir`, `Seek`, `Name` and `Fd` warn the same way.
- **Fix:**
  - Classify methods by their receiver: treat the read methods of `*os.File` and `os.FileInfo` (Read, ReadAt, ReadDir, Readdir, Readdirnames, Stat, Name, Seek) as inert, as `osRead` does for functions.
  - Or key `sensitive` by `os.(*File).Read` with its own list.
  - Change the L1 row to Opus's `f.Read` probe.

### The security flag "dos-control-bypass" (rule 4)

**Real.** The parts are H1 (the layer checks syntax main refused, which gives an hours-long dropped worker from a small input) and M1 (a held slot makes every later or concurrent run wait until its deadline, and a worker can start after the deadline).

The other routes I checked are bounded:
- The slot never leaks and is never freed early.
- The wait honours ctx.
- `maxOutExport` is one counter for each run, charged before each open. A dropped worker's later charges reach nothing.
- Node and name bytes are charged on the run's goroutine (`typedIn`, `methodName`, `typeName`).
- Repetition per platform and version is charged by file bytes and nodes to the run's one node bound, and bounded in time by the deadline.
- `forTest`'s re-checks are bounded by main's parsed own packages (≤ `maxPkgs`). They run inside the worker under the deadline, at parity with main's own external-test view.
