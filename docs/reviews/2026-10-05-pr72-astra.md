# PR #72 (contract-fixture framework): Astra reviews

## Review of #72 (Astra, 2026-10-05)
Verdict: NO-GO

**High — Release builds can accidentally include active mutation sites.**  
`internal/mutation/on.go:3`, `Makefile:23`, `Makefile:31`

Exporting `GOFLAGS=` does **not** suppress flags persisted through `go env -w`. With persisted `GOFLAGS=-tags=adcmutation`, the ordinary build and `dist` commands select `on.go`. Those binaries behave normally until `ADC_MUTATION` enables a bypass.

I reproduced this: a build with no explicit mutation tag, using the Makefile’s empty `GOFLAGS`, produced a binary whose stale-state fixture turned red under `ADC_MUTATION`. The ordinary-build test cannot catch this: its `!adcmutation` constraint excludes it from contaminated builds, and sandboxed tests use separately sanitized flags.

**Fix:** make release builds ignore persisted Go configuration and explicitly control build tags. Add a build-level regression test using a hostile Go environment file, then verify the resulting release binary remains green under every named mutation.

**Medium — The fixture observations do not prove the full stated invariants.**  
`internal/fixtures/eventstore.go:48`, `internal/fixtures/eventstore.go:113`

`submit` discards `Outcome`, so the idempotency fixture cannot verify replay identity, stored result equality, or that the callback did not execute again. A replay returning an incorrect result still passes. Neither fixture checks the absence of writes after refusal; the stale-state fixture obtains the next expectation from whatever head exists, potentially accommodating an erroneous write.

Existing writer unit tests cover some of these properties, but the installed fixture does not establish its own golden’s claims.

**Fix:** retain outcomes and assert replay identity, callback counts, and committed state after each step. Report violated assertions as fixture failures, distinct from setup errors. This distinction will also support the remaining usage, reservation, and lineage fixtures.

**Medium — CI does not perform the installed-artifact contract check.**  
`Makefile:143`, `scripts/install-check.sh:57`

The green run uses `bin/adc` with the repository mounted. Installation checking only invokes `version`. Embedding makes source-independent execution plausible, but CI does not prove the installed `dist` artifact satisfies the contract-fixture exit check.

**Fix:** run the installed `adc dev fixtures --contract` inside a clean sandboxed prefix with the source tree unavailable.

**Medium — Golden validation accepts incompatible outcome/reason pairs.**  
`schemas/testing/contract-fixture.json:22`, `internal/fixtures/fixtures.go:70`

The loader validates the outcome and reason independently. For example, `empty/idempotency_key_reused` passes these checks even though the vocabulary restricts that reason to `failed`. Future runners and goldens could therefore agree on an invalid pair.

**Fix:** validate each expected pair against the vocabulary’s allowed outcomes, and add a refusal test using a registered reason with an incompatible outcome.

The four decisions are otherwise reasonable:

- Compiled-out sites are suitable once release builds are protected. Both current sites preserve behavior when off; their arguments are constants without side effects.
- The golden contains all three elements required by §11. `empty/completed_clean` is defensible as **admission-check success**; document that interpretation and preserve native outcomes for components that already return them.
- Embedded goldens appropriately support installed execution.
- One fixture per PR is workable. The runner interface accommodates additional real components, but future fixtures need component-specific observations and assertions. The remaining fixtures are not blockers for this explicitly partial PR.

Validation passed: ordinary tests for fixtures, mutation, CLI, and eventstore; tagged fixture tests; fresh ordinary/tagged binary runs; and each mutation producing exit 1 with both sequences reported. The tagged test correctly rejects execution errors rather than counting them as successful red proofs. Full `make ci` was not run. No repository files were changed.
### Lead notes on round 1 (applied)

- High (release builds and the mutation tag): the Makefile now exports `GOENV=off`, so a persisted `go env -w`
  configuration cannot reach any build. Independently, `scripts/check-release-binary.sh` reads the build settings Go
  records in each binary (`go version -m`) and refuses any `-tags` that includes `adcmutation`. `make build` and
  `make dist` run it on every artifact, whatever set the tag. `make release-guard` (in `make ci`) is the build-level
  regression: it builds under a hostile go env file (`GOFLAGS=-tags=adcmutation`), checks the result carries no tag,
  and requires the guard to refuse the real mutation build. Removing `GOENV=off`, removing both layers, and a guard
  that accepts everything are each caught.
- Medium (fixture invariants): each runner returns its steps and the assertions it found violated. A violation fails
  the fixture and is reported, distinct from an error that kept it from running.
  - The idempotency fixture checks that the first command is applied as seq 1, and that the repeat is a replay naming
    the first command's id with the stored result. The result carries the event's fresh id, so a re-run result would
    differ.
  - Both fixtures check the log's head and the count of apply callbacks after every step: a refusal runs nothing and
    writes nothing.
  - The stale-state fixture's third command expects version 1, the one the first made, never "whatever the head is".
  - Writer mutants are each caught with their violation named: a replay returning a fresh result, a new command id,
    or no replay mark.
- Medium (installed artifact): `scripts/installed-fixtures.sh` runs after `install-check.sh` on the same prefix. The
  installed `adc dev fixtures --contract` runs under bubblewrap with only the prefix (at `/p`) and a private `/tmp`
  mounted, so no source tree, home or network is reachable. It is green, and stays green under each fixture's named
  mutation, which proves the release binary has no live mutation sites.
- Medium (outcome/reason pairs): every expected step must pass the vocabulary's writer check (`Registry.Check`), so
  the reason must be current and allowed with that outcome. `empty/idempotency_key_reused` is refused in a test.
  The schema documents the reading you suggested: an admitted command, applied or replayed, is
  `empty/completed_clean`, and a component that returns its own result triple is expected with that triple.
- Mutation: eight further points, all killed.
- Rebuilt as one commit on main `2cd9503`.

## Second review of #72 (Astra, 2026-10-05)

Verdict: NO-GO

- **High — Release mutation contamination: partially fixed; still blocking.** Persisted and environment `GOFLAGS` are neutralized by normal Make builds. Plain command-line `GOFLAGS` and explicit `GOBUILD` tags are rejected, but the guard has the bypass below.
- **Medium — Fixture observations: partially fixed.** Callback counts, fixed sequence expectations, replay marking, and violation reporting work. A remaining comparison weakness is described below.
- **Medium — Installed-artifact CI check: fixed.** Fresh installed artifacts passed under bubblewrap; contaminated artifacts failed. A probe using the same mounts could not reach the checkout or home, including through `/proc` roots or inherited source descriptors.
- **Medium — Incompatible golden pairs: fixed.** `Registry.Check` enforces writer-compatible pairs; the incompatible-pair refusal test passes. The admission interpretation is documented.

**High — Quoted build metadata bypasses the release guard.**  
`scripts/check-release-binary.sh:20`, `Makefile:64`, `Makefile:78`

Reproduced without changing checkout files:

```sh
make build BIN_DIR=/tmp/pr72-repro 'GOFLAGS=-tags=adcmutation,x"'
ADC_MUTATION=eventstore.expected-state-unchecked \
  /tmp/pr72-repro/adc dev fixtures --contract --only stale-expected-state
```

The build exits **0**; the fixture exits **1** with the stale command incorrectly admitted. Go accepts the additional tag and records `-tags="adcmutation,x\""`. The guard searches the quoted text without decoding it, so its comma-delimited match misses `adcmutation`.

The same override successfully produced contaminated artifacts through host-platform `make dist`. The installed-fixture check catches them, but neither `build` nor `dist` requires that check.

**Fix:** parse decoded build settings using `go version -m -json` or `debug/buildinfo`, then inspect individual tags. Add regression cases covering quoted metadata through both Make overrides and directly built artifacts.

**Medium — Replay comparisons can agree on equally incorrect outcomes.**  
`internal/fixtures/eventstore.go:140`, `internal/fixtures/eventstore.go:149`

Using temporary Go overlays, I separately changed `Submit` to clear every successful outcome’s `Result`, and to clear every successful outcome’s `CommandID`. Both mutants leave `TestFixturesAreGreen` passing. The first returned outcome is treated as authoritative without checking it against the command ID and result generated by the fixture.

**Fix:** retain the submitted command ID and callback-produced result independently. Assert that the first outcome matches those values, then validate replay against those established expectations. Add both counterexamples as regression controls. This is nonblocking.

The hostile-build regression is faithful for its current case: its recipe passed unchanged, failed when `GOENV=off` was removed, and failed when both protections were disabled. Its coverage misses the quoted-tag bypass.

Focused fixtures, mutation, CLI, and eventstore tests passed, including tagged fixture tests. Direct builds outside Make still inherit persisted flags; the guard rejects their ordinary mutation-tag metadata. Full `make ci` was not run. The checkout is unchanged.
### Lead notes on round 2 (applied)

- **High (quoted build metadata):**
  - `scripts/check-release-binary.sh` is replaced by `tools/releasecheck`. It reads the decoded build settings
    (`debug/buildinfo`) and refuses **any** `-tags` on a release binary, since release builds use none. Its test builds
    tiny binaries with no tags, `adcmutation`, `adcmutation,x"`, `x",adcmutation` and `other`, and checks a file with

  - The Makefile's Go settings are now `override export`, so a command-line `GOFLAGS=` (your reproduction) cannot

  - `make release-guard` now also builds with that quoted command-line `GOFLAGS` (no tags may result), requires

    only a plain `adcmutation` each turn `release-guard` red.
- **Medium (replay against equally wrong outcomes):** the fixture keeps the command id it submitted and the result its
  apply produced, apart from what the store answers. It checks the first outcome against them, then the replay
  against them. Your two counterexamples, every successful outcome's result cleared and every command id cleared,
  each turn the fixture red with the violation named.

## Third review of #72 (Astra, 2026-10-05)

Verdict: NO-GO

- **Round-2 High — Quoted metadata bypass: fixed.** Quoted command-line `GOFLAGS` now produces clean binaries through both `make build` and host-platform `make dist`. A separate release bypass remains below.
- **Round-2 Medium — Equally incorrect replay outcomes: fixed.** Both Submit overlays now fail `TestFixturesAreGreen`, naming the incorrect result or command ID.

**High — Erasing build settings bypasses the release guard.**  
`tools/releasecheck/main.go:37`, `tools/releasecheck/main.go:41`, `Makefile:37`

`buildinfo.ReadFile` succeeds when `runtime.modinfo` is empty, returning no settings. The checker accepts that as evidence of no tags.

Reproduced:

```sh
make build BIN_DIR=/tmp/pr72-r3-build \
  GOBUILD='$(GO) build -trimpath -tags adcmutation -ldflags "$(LDFLAGS)"' \
  LDFLAGS='-s -w -X runtime.modinfo='

ADC_MUTATION=eventstore.expected-state-unchecked \
  /tmp/pr72-r3-build/adc dev fixtures --contract --only stale-expected-state
```

The build exits **0**; the fixture exits **1**, admitting the stale command. The same overrides through `make dist`, restricted to this host’s `linux/arm64`, also produce accepted, contaminated artifacts. Injecting tags through a `GO` environment wrapper combined with this `LDFLAGS` override also bypasses `build`.

Dist does invoke the checker on all three host artifacts and rejects ordinary tagged builds. Its artifact enumeration is working; the checker’s acceptance condition is insufficient.

**Fix:** reject missing module identity/build settings, prevent release linker options from replacing `runtime.modinfo`, and add this counterexample through both release targets.

**Medium — `release-guard` does not protect dist’s checker integration.**  
`Makefile:166`, `Makefile:169`, `Makefile:173`

Using temporary Makefiles and checker overlays, the isolated regression recipe:

- Passes unchanged.
- Fails when GOENV protection, command-line override protection, or build’s checker invocation is removed.
- Fails with a blind checker or one recognizing only plain `adcmutation`.
- **Still passes when dist’s checker invocation at `Makefile:80` is removed.**

Thus, the tested build layers are faithful, but dist integration has no corresponding regression.

**Fix:** add host-platform dist cases for hostile settings and injected tags, asserting refusal by dist itself. Verify that removing dist’s checker turns the regression red.

Focused fixtures, mutation, CLI, eventstore, and releasecheck tests passed, including tagged fixture tests. Full `make ci` was not run. Checkout files remain unchanged.
### Lead notes on round 3 (applied; round 4 waits for the operator's split decision)

- **High (erased build information):** `tools/releasecheck` refuses a binary whose build information is missing or
  erased: no main module, or no `GOOS`, `GOARCH` or `-compiler` setting. A release build always records these, and an
  empty `runtime.modinfo` removes all of them. Its test builds with `-ldflags=-X=runtime.modinfo=`, with and without a
  tag. Removing either check alone is covered by the other; removing both turns `release-guard` red on your exact
  reproduction.
- **Medium (dist integration):** `release-guard` now runs both `GOBUILD` injections (a plain tag, and a tag with the
  build information erased) against `make build` and against host-platform `make dist`, and requires each to refuse
  what it built. Removing dist's checker turns the regression red.
- **Scope, for the operator:** the remaining class, deliberately overriding make variables (`GOBUILD`, `LDFLAGS`, `GO`)
  on the command line, is treated as equivalent to editing the Makefile. It is out of scope for "a release build cannot
  accidentally carry live mutation sites". A forged `runtime.modinfo` that claims clean settings falls in that class.
