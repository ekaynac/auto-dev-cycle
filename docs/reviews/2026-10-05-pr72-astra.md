# PR #72 (contract-fixture framework): Astra reviews

## Review of #72 (Astra, 2026-10-05)
Verdict: NO-GO

**High — Release builds can accidentally include active mutation sites.**  
`internal/mutation/on.go:3`, `Makefile:23`, `Makefile:31`

Exporting `GOFLAGS=` does **not** suppress flags persisted through `go env -w`. With persisted `GOFLAGS=-tags=adcmutation`, the ordinary build and `dist` commands select `on.go`. Those binaries behave normally until `ADC_MUTATION` enables a bypass.

I reproduced this: a build with no explicit mutation tag, using the Makefile’s empty `GOFLAGS`, produced a binary whose stale-state fixture turned red under `ADC_MUTATION`. The ordinary-build test cannot catch this: its `!adcmutation` constraint excludes it from contaminated builds, and sandboxed tests use separately sanitized flags.

**Fix:** make release builds ignore persisted Go configuration and explicitly control build tags. Add a build-level regression test using a hostile Go environment file, then verify the resulting release binary remains green under every named mutation.

**Medium — The fixture observations do not prove the full stated invariants.**  
`internal/fixtures/eventstore.go:48`, `internal/fixtures/eventstore.go:113`

`submit` discards `Outcome`, so the idempotency fixture cannot verify replay identity, stored result equality, or that the callback did not execute again. A replay returning an incorrect result still passes. Neither fixture checks the absence of writes after refusal; the stale-state fixture obtains the next expectation from whatever head exists, potentially accommodating an erroneous write.

Existing writer unit tests cover some of these properties, but the installed fixture does not establish its own golden’s claims.

**Fix:** retain outcomes and assert replay identity, callback counts, and committed state after each step. Report violated assertions as fixture failures, distinct from setup errors. This distinction will also support the remaining usage, reservation, and lineage fixtures.

**Medium — CI does not perform the installed-artifact contract check.**  
`Makefile:143`, `scripts/install-check.sh:57`

The green run uses `bin/adc` with the repository mounted. Installation checking only invokes `version`. Embedding makes source-independent execution plausible, but CI does not prove the installed `dist` artifact satisfies the contract-fixture exit check.

**Fix:** run the installed `adc dev fixtures --contract` inside a clean sandboxed prefix with the source tree unavailable.

**Medium — Golden validation accepts incompatible outcome/reason pairs.**  
`schemas/testing/contract-fixture.json:22`, `internal/fixtures/fixtures.go:70`

The loader validates the outcome and reason independently. For example, `empty/idempotency_key_reused` passes these checks even though the vocabulary restricts that reason to `failed`. Future runners and goldens could therefore agree on an invalid pair.

**Fix:** validate each expected pair against the vocabulary’s allowed outcomes, and add a refusal test using a registered reason with an incompatible outcome.

The four decisions are otherwise reasonable:

- Compiled-out sites are suitable once release builds are protected. Both current sites preserve behavior when off; their arguments are constants without side effects.
- The golden contains all three elements required by §11. `empty/completed_clean` is defensible as **admission-check success**; document that interpretation and preserve native outcomes for components that already return them.
- Embedded goldens appropriately support installed execution.
- One fixture per PR is workable. The runner interface accommodates additional real components, but future fixtures need component-specific observations and assertions. The remaining fixtures are not blockers for this explicitly partial PR.

Validation passed: ordinary tests for fixtures, mutation, CLI, and eventstore; tagged fixture tests; fresh ordinary/tagged binary runs; and each mutation producing exit 1 with both sequences reported. The tagged test correctly rejects execution errors rather than counting them as successful red proofs. Full `make ci` was not run. No repository files were changed.
### Lead notes on round 1 (applied)

- High (release builds and the mutation tag): the Makefile now exports `GOENV=off`, so a persisted `go env -w`
  configuration cannot reach any build. Independently, `scripts/check-release-binary.sh` reads the build settings Go
  records in each binary (`go version -m`) and refuses any `-tags` that includes `adcmutation`. `make build` and
  `make dist` run it on every artifact, whatever set the tag. `make release-guard` (in `make ci`) is the build-level
  regression: it builds under a hostile go env file (`GOFLAGS=-tags=adcmutation`), checks the result carries no tag,
  and requires the guard to refuse the real mutation build. Removing `GOENV=off`, removing both layers, and a guard
  that accepts everything are each caught.
- Medium (fixture invariants): each runner returns its steps and the assertions it found violated. A violation fails
  the fixture and is reported, distinct from an error that kept it from running.
  - The idempotency fixture checks that the first command is applied as seq 1, and that the repeat is a replay naming
    the first command's id with the stored result. The result carries the event's fresh id, so a re-run result would
    differ.
  - Both fixtures check the log's head and the count of apply callbacks after every step: a refusal runs nothing and
    writes nothing.
  - The stale-state fixture's third command expects version 1, the one the first made, never "whatever the head is".
  - Writer mutants are each caught with their violation named: a replay returning a fresh result, a new command id,
    or no replay mark.
- Medium (installed artifact): `scripts/installed-fixtures.sh` runs after `install-check.sh` on the same prefix. The
  installed `adc dev fixtures --contract` runs under bubblewrap with only the prefix (at `/p`) and a private `/tmp`
  mounted, so no source tree, home or network is reachable. It is green, and stays green under each fixture's named
  mutation, which proves the release binary has no live mutation sites.
- Medium (outcome/reason pairs): every expected step must pass the vocabulary's writer check (`Registry.Check`), so
  the reason must be current and allowed with that outcome. `empty/idempotency_key_reused` is refused in a test.
  The schema documents the reading you suggested: an admitted command, applied or replayed, is
  `empty/completed_clean`, and a component that returns its own result triple is expected with that triple.
- Mutation: eight further points, all killed.
- Rebuilt as one commit on main `2cd9503`.
