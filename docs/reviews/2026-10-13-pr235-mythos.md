## External review of #235 (Mythos, 2026-10-13)

Verdict: GO with changes

One High, with a two-line fix. Everything else is Medium or Low. The adapter's base-aware verdict, the pinned recipe, the manifest label and the credential handling hold up. Tests for `internal/results`, `internal/sandbox` and `internal/profile` pass locally on go1.27.1.

### High

**H1. A `go.work` in the candidate tree redirects a dependency offline, bypassing `go.mod`, `go.sum` and the module cache.**
`fixtures/m1/images/go/Containerfile:36` and `fixtures/m1/profiles/auto-dev-cycle.json:37`.
The image sets `GOFLAGS=-mod=readonly`, `GOPROXY=off` and `GOTOOLCHAIN=local`, but not `GOWORK=off`. A builder's patch can add `go.work` with `use ./x` or `replace github.com/dep => ./x` next to an in-tree module, and the gate then compiles the tests against that code. The protected paths cover `go.mod` and `go.sum`, not `go.work`, `go.work.sum` or `vendor/`. I reproduced it under the image's exact flags: a test importing a module absent from `go.mod` passes with `go.work` present and fails `[setup failed]` with `GOWORK=off`. This breaks §8 item 2's promise that a candidate changing a dependency manifest is refused, and it is reachable through the ordinary builder path. The repo already uses `GOWORK=off` in `fixtures/t0/go-mini/check.sh`.
Fix: add `GOWORK=off` to the final `ENV` block of the Containerfile; add `go.work`, `go.work.sum` and `vendor/**` to `protected_paths`; assert them in `TestSelfProfileProtectedPaths` (`internal/profile/selfprofile_test.go:83`).

### Medium

**M1. `Blocking()` can be empty while `Clean()` is false.** `internal/results/gotest.go:115` and `:126`.
`Clean` refuses a package that is `fail`, `incomplete` or `missing`, and a report with no pass at all. `Blocking` lists only test results. A build failure in a package with no base or expected tests, a package `start` with no end, a base package without tests that never ran at head, or a stream of only no-test-files packages all give `Clean() == false` with `Blocking() == nil`. P15 rendering "blocking findings" from `Blocking` would show nothing for a failed gate, which is the "failure text never reaches consumers" path it must get right.
Fix: either make `Blocking` return a package-level pseudo-result for each package not `pass`/`skip`, or add `BlockingPackages() map[string]Outcome`, and add a test asserting `Clean() == (len(Blocking())==0 && len(BlockingPackages())==0 && anyPass)` for the build-fail and no-tests streams.

**M2. The #170 baseline is not re-recorded in the image and its shape cannot be a `base`.** `fixtures/m1/issues/170/baseline.json` on `main`; backlog #226 entry 30 names P32 as the trigger.
The fixture stores counts only (`tests_passed: 72, skipped: 0`, host toolchain). `ParseGoTestJSON` needs a `Report` (results with names and outcomes, packages). The PR measured the image baseline (3 root-only skips) but did not record it. Without a `Report`-shaped base, P15 either parses strictly, where the 3 skips make the head fail, or has to invent its own record. The gate for the first target is therefore not yet runnable from the fixtures as they stand.
Fix: commit the image run's `Report` JSON (the adapter's own encoding) as `fixtures/m1/issues/170/baseline-report.json` recorded at the fixture's `base` commit, note the 3 skips and the command used, and set `provisional: false`; or state explicitly in the PR and the README that P22a records it at task creation and that P32 does not close entry 30.

### Low

**L1. No `-count=1` in the gate command.** `fixtures/m1/profiles/auto-dev-cycle.json:23`. Today the read-only cache makes cached test results impossible, which I verified locally with a `chmod a-w` cache: the run passes and never reuses results. If the cache ever becomes writable (the PR's own deviation 3 contemplates it for `internal/entry` and `internal/vocab`), a cached `(cached)` pass would be replayed as fresh events. The #170 fixture's command already has `-count=1`. Add it to the profile so the two agree.

**L2. Git 2.39 in the image: confirmed harmless for the gate, not for the package recipe.** `fixtures/m1/images/go/Containerfile:20` and `fixtures/m1/profiles/auto-dev-cycle.json:12`. The controller git runs on the host through `exec` with `PATH=/usr/bin:/bin` (`internal/sandbox/git.go`), and the sandbox mounts only workspace and results, so no controller git runs inside the image. `go test` never stamps VCS, so the gate never calls the image's git. The package recipe `go build ./cmd/...` does default to `-buildvcs=auto`, which runs the image's git on whatever `.git` the workspace holds. Add `-buildvcs=false` to `GOFLAGS` so the image's git is never on any path.

**L3. A single output line over 1 MiB makes the whole stream unreadable.** `internal/results/gotest.go:54` and `:167`. `bufio.Scanner` fails on the long line and the gate reports `ErrUnreadable`, a false block from a test that prints a large diff. Since output events are never read, consider a reader that skips an over-long line when its prefix parses as an `output` event, or raise `MaxLine` with a stated reason.

**L4. No "green baseline" predicate for P15.** `internal/results/gotest.go:115`. `Clean()` with no base is strict, so the image baseline with 3 root-only skips is not `Clean`. §2.2 criterion 4 needs a different predicate: every result `pass` or `skip`, every package `pass` or `skip`, at least one pass. Add `Report.Green()` (or similar) so P15 does not derive it ad hoc.

**L5. The Opus pre-review is not saved in the PR.** `docs/reviews/` has no `2026-10-13-pr235-opus.md`; 04 §3 says reviews are saved in the PR itself, and #233 did so. Add it with this review.

### Confirmed

- **Adapter edge cases.** A test renamed or removed between base and head is `missing` and blocks (conservative, needs a baseline re-record as the only remedy). An expected test that skips never counts, even if it skipped at base. Names are keyed by package, so duplicates across packages are distinct. Subtests are separate results, so a parent that passes over a skipped subtest still blocks unless the subtest skipped at base. Worst outcome wins across repeated reports. A base that is itself incomplete only narrows what the head is checked against, which is P15's recording obligation, not the adapter's.
- **Target fit.** Narrowing to `./internal/cli/...` with a `Report` base recorded by the same command in the image gives an honest gate: the 3 uid-0 skips gave no coverage at base and count only because they skipped there too, while the 5 acceptance tests are expected and must pass. M2 is what stands between this and a runnable gate.
- **Recipe.** `FROM` is hard-coded with the index digest and no `ARG`. `go mod download` plus `go mod verify` under the lockfiles, and the warm list includes test-only third-party deps via `go list -deps -test`. The label's JSON matches `sandbox.Manifest` and `CheckManifest`, with the profile test proving the agreement and the refusal. The read-only cache with `GODEBUG=goindex=0` works empirically. The script's build context holds only the two lockfiles and `warm.txt`, it never pushes, and it prints no credential.
- **Profile.** Protected paths cover every §2.2 criterion 2 path and every 04 §3 contract package, plus the lockfiles, the recipe and the adapter. The URL is https, which `Host.refused` accepts. The pin is registry-qualified with a stated all-zeros placeholder.

Add a protected-path assertion for `go.work` (H1) and a Clean/Blocking consistency test (M1) to the set.
