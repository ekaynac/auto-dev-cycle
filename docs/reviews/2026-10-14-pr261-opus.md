## Opus pre-review of #261

Verdict: GO with changes

There is no Critical or High finding. The PR closes #259's H1, M1, M2, M3, M6 and L3 in the code. I found two Medium findings. M1 is a one-file fix and I recommend it before merge. M2 is a missing test.

**What I checked.** I ran the probes and mutations in a scratch worktree and removed it afterwards.
- `recovery`, `adapterhost/...`, `lease`, `harness` and `fixtures` all pass on the clean tree.
- The probes confirmed the behaviour described below.
- The two mutations I reran (question 6) give the result the PR claims. One more mutation, which re-couples `Run` to the stage, survives every test (M2).

### Medium

**M1. One sparse file makes a root fail for good, and 16 such roots starve every later cut attempt.** Location: `internal/recovery/orphans.go:150` (size), `:116-143` (no rename after a failed submit), `:63-67` (cap counting).
- **The cause.** `listOut` records the `lstat` size as it is. The schema's `Amount` maximum is 2^53-1.
- **The attack.** The adapter runs `truncate -s $((1<<54)) out/x`. This uses no disk space and works on tmpfs, XFS and btrfs. It does not work on ext4, whose file size limit is 16 TiB.
- **What happens.** The refusal command fails schema validation (`/handle/size: maximum`), so the root is never renamed.
- **Probe A.** On three starts in a row: the same error each time, 0 refusals, and `exchange-<att>` still in place.
- **The spread.** A root that fails still counts as `found` toward `maxRoots`. The cut set is in key order, oldest first, so 16 such roots use up the cap at every start. Every later cut attempt then gets no record and no cleanup.
- **Probe B.** With `maxRoots` patched to 1, the second cut attempt's root was never visited and stayed in place on every start.
- **Who can do it.** A confined adapter that writes only its own `out/` can do this. That is the weakest attacker in D43. With access to `Host.Root`, it can also plant such roots for older cut attempts (see L1).
- **Why Medium, not High.** Steps 2-4, the fence, accounting and placement are not affected. The harm is lost refusal records and roots that are never removed.
- **Fix:**
  - Clamp the size to 2^53-1 and say so in the detail.
  - On any refusal-command error that is not a storage fault, fall back to a single refusal with handle `out`, size 0 and a fixed detail. Then still rename the root.
  - Stop a root that keeps failing from holding a cap slot. For example: count only roots that succeed, go newest-first, or rotate the start point.
  - Add a test with a 2^54 sparse file on tmpfs.
  - Add a cap test with `maxRoots` as a variable in `export_test.go`. This also closes "the 16-root cap has no test".

**M2. No test detects a re-coupling of `Run` and the orphan stage (the #259 H1 regression).** Location: `internal/recovery/orphans_test.go:178-222`, `model_test.go`.
- **Mutation.** I made `Run` call `r.RefuseOrphans(ctx)` after step 1 and return its error. The whole recovery suite stays green.
- **Why.** The tests' `w.recovery()` has `Exchanges == ""`, so `RefuseOrphans` does nothing inside `Run`.
- **The model does not cover it either.** D62's new action is a model flag that the real code never reads. The `coupled` fixture shows that I6 detects coupling in the model only, not in `Run`.
- **Fix.** In `TestTheOrphanStageNeverBlocksRecovery`, run `Run` on a `Recovery` whose `Exchanges` holds the hostile root (mode 000, or the M1 sparse file). Assert that L1 is settled before calling `RefuseOrphans`.

### Low

**L1. The binding residual is real, but the PR describes it too narrowly.** Location: `orphans.go:60-69`.
- **Renaming is not needed.** A planted 0700 directory is enough. It works for any cut attempt whose idempotency key was never used, that is, an attempt whose root was missing or whose `out/` was empty at its own stage.
- **Probe C.** A cut attempt had no root at its first start. At a later start, a planted `exchange-<att>` got a `stale_attempt` refusal recorded on that attempt.
- **An inode alone does not close the gap.** Rename keeps the inode, but ext4 and tmpfs reuse inode numbers after a delete. Record a file handle (`name_to_handle_at`, which includes the generation) or the inode plus `statx` btime.
- **Why Low under D43.**
  - A host-side adapter at the controller's uid can already hide any record: it can chmod its own root to 0755 or empty other roots' `out/`.
  - It can also write the store file directly.
  - Nothing is read, and the fence is not involved.
- **Cheap partial fix.** At an attempt's first stage, record the refusal command for every cut attempt, as an applied command with no events. The key is then used, and later plants replay as no-ops. Only same-start renames remain.
- **Fix.** State the planting form and the inode-reuse point in #226.

**L2. The work at start has no bound.** Location: `internal/adapterhost/exchange.go:113-139`, `orphans.go:71-77`.
- **Descriptors.** `RemoveAt` holds one descriptor per tree level.
- **Measured on tmpfs.** 200k levels took 3.7 s. Past `RLIMIT_NOFILE` (here 500k) it fails with EMFILE and removes nothing. It does this again at every start, about 10 s each time, with all the process's descriptors in use.
- **Crash risk.** A Go stack overflow, which is fatal and would block start, needs more than about 1.5M levels. That is possible only if nofile is raised above the default `nr_open`.
- **Other unbounded parts.**
  - `Readdirnames(-1)` in `RemoveAt` and in the parent sweep has no bound.
  - `ctx` is never checked in either loop.
  - A bad-mode root under a claimed name whose removal fails also adds to M1's cap starvation.
- **Fix.**
  - Cap the depth: 09 forbids subdirectories in `out/`, and the controller's own tree has depth 2.
  - Past the cap, use `renameat` to lift the deep subtree to a flat `refused-…-N` name beneath the pinned parent. Each start then makes progress with a fixed number of descriptors.
  - Read directory names in batches, and check `ctx`.

**L3. The order guard sees only `running` attempts.** Location: `orphans.go:91-92`.
- **The gap.** Between `newExchange` and `attempt.started`, the root has no record.
- **Scenario.** If P22a ever runs the stage during a launch (for example, from the reconcile loop), the sweep deletes that root. The prelaunch probe then fails, and the result is `start_refused{precondition_failed}`: a false environment hold.
- **Fix.** Make this a P22a obligation, ideally enforced in code. For example: sweep only unclaimed roots older than the process start, or have `Host` refuse to make exchange roots until the stage has returned.

**L4. The cut set.**
- **Correct cases.**
  - Silent removal of a `finishing` attempt's root is correct (M3).
  - It is also correct for `lost{agent_disconnect|stream_dead}`. The host's final transaction already recorded those refusals together with the loss. A leftover root means only that a crash fell between that transaction and the removal, so recording again would duplicate.
- **The gap: `stopping` (preempt or drain) at the crash.**
  - Usually the final transaction never ran, so a still-running adapter's late output gets no record.
  - A `stale_attempt` refusal would be true: publication is closed and there is no admitted result.
- **Fix.** Add attempts with `StopReason` set (stopping, or sealed from stopping) to the cut set, or record this as a residual in #226. X3 does not require it.

**L5. P22a obligations to add to #226 entry 81.**
- Kill orphaned adapter trees *before* `RefuseOrphans`, not just at start. Until then, a live adapter can:
  - add entries after the listing;
  - recreate a non-empty `refused-<name>` so that the rename fails (that root then holds a cap slot);
  - grow the tree under `RemoveAt`.
- `RefuseOrphans` returns before the first `Host.Run`.
- `Exchanges` is the same value as `Host.Root`. A wrong path gives ENOENT, which returns nil without a word (`orphans.go:52-53`).

**L6 (nits).**
- **Rename collision.** A pre-existing `refused-<name>` makes the rename fail. Remove it first with `RemoveAt`, or rename to a unique name.
- **Handle collision.** An entry named `out` gets the same handle as the truncation marker.

### Answers to the questions
- **Q1: forge or hide.**
  - **TOCTOU is safe.**
    - The root is pinned with `O_PATH|O_NOFOLLOW` and checked with `fstat`.
    - `out/` is opened beneath the pinned root's descriptor, and entries are checked with `fstatat(AT_SYMLINK_NOFOLLOW)`.
    - A swap before the rename by name only moves the swapped object to `refused-*`, and the sweep removes it without following symlinks.
  - **Hard links:** only the link is unlinked. The size of a linked same-uid file is recorded, and nothing is read.
  - **FIFOs** are never opened. **Device files** cannot be made without privilege.
  - **Entry count:** at most 65 per root and 16 roots, so about 1,040 events per start.
  - **Can it still forge or hide a record?**
    - Forging: L1 (cut attempts only).
    - Hiding other attempts' records: M1.
- **Q2: symlinks and `/proc/self/fd` chmod.**
  - Chmod through `/proc/self/fd/N` reaches the pinned inode, never a name, so a swap cannot redirect it.
  - `RemoveAt` can be led only to directories the adapter could already modify. Moving a foreign directory in needs write access on it, and a rename across mounts fails with EXDEV. So there is no privilege gain.
  - The depth limit is L2.
- **Q3: steps 2-4 and later starts.**
  - `Run` does not call the stage, and the stage's error is separate. H1 holds in the code, but no test protects it (M2).
  - A later start is delayed only by L2. It is never blocked.
  - Called before `Run`, the guard returns an error and touches nothing (tested). The launch-window gap is L3.
- **Q4: idempotency.**
  - The key from the root name is safe. A decide error rolls back without using the key: the command row is written only on commit. The key is under 256 bytes, and the input `{attempt}` is stable.
  - A crash between commit and rename replays the command (tested).
  - Two starts in a row record nothing (tested).
  - A root that comes back replays as a no-op and is removed.
  - The only gap is a key that was never used (L1).
- **Q5: the cut set.** See L4.
- **Q6: D62 and the mutations.**
  - `IdempotencyKey` set to the command id: red in `TestTheOrphanStageNeverBlocksRecovery/a_failed_rename`, as the PR claims.
  - `O_NOFOLLOW` dropped from the root's open: red in `TestARootIsBoundThroughTheStore/symlink_true`, as the PR claims.
  - The D62 action reflects the decoupling only as modelled; nothing ties it to the real `Run` (M2).
- **Q7: inertness.**
  - Confirmed: nothing outside tests constructs `Recovery`.
  - The live changes are the exclusive 0700 `exchange-<att>` root (with an `ids.Check` on the id) and `RemoveAt` in `exchange.remove`.
  - `harness` and `fixtures` pass with the new name.
  - P22a's list needs L5.
  - #226 entry 80's items are all covered. Chmod through `/proc/self/fd` takes the place of `Fchmod`, which an `O_PATH` descriptor does not support, and it is equally safe.
