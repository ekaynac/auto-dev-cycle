### High

**H1. The import-edge rule decides "own module" and "standard library" by string prefix, not by how the import resolves. A new edge into another module whose path sits under the main module's path gives no signal.** `internal/accept/integrity.go:384-386`. The PR promises "every new import edge outside the standard library and the module warns", so this silent route is inside the promise.
- Probe 20: the base vendors the module `example.com/m/evil` (go.mod requires it; `vendor/modules.txt` lists it). The candidate adds `pkg/probe.go` with `import "example.com/m/evil"` and `func p() { evil.Exit() }` in the tested package.
  - head: accepted, 0 blocks, 0 warnings.
  - main: accepted, 0 blocks, 0 warnings.
  - The types layer loads the package from `vendor/` (`typer.local` checks `ty.vendor[p]` first, `integrity_types.go:345`). The edge rule then calls it own because it has the prefix `example.com/m/`.
- Same cause, module-cache mode (from reading the code; not probed, because the gate is offline): in a repository with nested modules, the root requires its sub-module `example.com/m/api vX`, which has its own go.mod. `typer.local` returns not-own for a nested module and loads it from export data. The edge rule again calls it own. Multi-module repositories commonly have this layout.
- Probe 42: the candidate changes go.mod's module line to `module example.com` and imports the vendored `example.com/mx`.
  - head: accepted, no warning, no block.
  - main: same.
  - Cause: `mod` is read from the candidate's go.mod only.
- A path with no dot in its first element is treated as standard library. A replaced module with no dot in its path (`require evil v0`, `replace evil => host/x vN`) would then give no edge warning when the module is in the image's cache. I did not probe this, because the test lister fails it closed.
- **Fix:** decide own-ness with the loader's own rule on both trees. For example, an import is own only if `_, ok := ty.local(p); ok && !ty.vendor[p]` holds for the base typer and for the candidate typer. Decide standard library by go list's `Standard` field (add it to `Listed`), not by "no dot". Add rows for probes 20 and 42.

### Regressions against main a639412

None found. The PR only adds signals:
- **S list:** `sPkg` is a strict superset of main's list. The per-name classes for the old packages are unchanged.
- **libc:** class 2 is a new case placed before the default.
- **Types-layer method references:** they add new keys to `refs`. Their `sensitive` value is always 0, so they cannot turn a block into a warning.
- **`Selections`:** only `typedOn` reads `Info.Selections`. go/types only records into it, so no earlier types-layer result, timing or bound changes.
- **Dot imports:** a dot import of a newly-S package now flags in both trees, so base files do not gain new findings.
- **testing, reflect, unsafe:** excluding them from the method rule removes nothing main gave.
  - reflect `Call`/`Method`/`Set*` through a value are still facts (`valueMakes`).
  - Testing values keep their own rules.
  - `unsafe` has no methods.
  - `testing/...` subpackage methods do count.
- **Ignore files:** the exclusion only narrows the new edge set (L2).

On all 34 probes, the head's findings include all of main's. One caveat: the report keeps at most 1000 warnings within a byte budget. More method warnings can push an older warning past that cap in a very large change. The cut is counted in `truncated`, and the replay's largest count is 54.
