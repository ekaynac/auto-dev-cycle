## Opus pre-review of #233

Verdict: **NO-GO**. Two High findings block it. Each fix is small, so this becomes GO once they land.

Tests: `go test ./internal/sandbox/... ./internal/daemon/... ./internal/api/...` passes at 39d491c (live Podman tests skipped). The scratch worktree has been removed.

### High

**H1. Parser differential (confirmed): a percent-encoded `file://` URL gets past `Host.refused`.** `internal/sandbox/git.go:85-102`.
- `refused` checks the raw `rest` with `filepath.Clean` and `resolve`, but git percent-decodes every URL-form remote (`connect.c` `parse_connect_url`: `if (is_url(url_orig)) url = url_decode(url_orig)`).
- I ran `refused` itself in the scratch worktree with Root `/srv/sbx` and Forbidden `/srv/state`:
  - `file:///srv/ok/%2e%2e/sbx/runs/a` → `refused=false`. Git opens `/srv/ok/../sbx/runs/a`, a repository a run wrote.
  - `file:///srv/%73bx/runs/a` → `false`.
  - `file:///srv/%73tate` → `false`, so the state directory can also be reached.
  - The plain `/srv/ok/../sbx/runs/a` is correctly refused.
- **Limit on verification:** the bash guard hook blocks git subcommands in this environment, so I could not run git itself with `GIT_TRACE`. The decode step comes from git's source, not a live run.
- The same hole applies to the fetch/pull guard (`git.go:164`), which calls `r.refused`.
- **Fix:** refuse any `file:` URL whose path contains `%`, or drop the `file://` form entirely, since absolute paths already cover local clones. Add the three URLs above to `TestURLTightening`.

**H2. The "runs/ on its own filesystem" check is unsound on btrfs, ZFS and overlay.** `internal/sandbox/sandbox.go:96-124`.
- Comparing `st_dev` catches a bind mount (same device), so that case is handled.
- But each btrfs subvolume and each ZFS dataset reports its own `st_dev` while drawing on the same pool. Overlayfs reports its own device while writing to its upper directory's filesystem.
- On a Fedora default install (`/` and `/home` are btrfs subvolumes of one pool), `runs/` on `/` and the state directory under `/home` pass the check. A run can then fill the state directory's disk.
- The comment "it cannot fill the state directory's" and the PR's residual-risk text are therefore wrong on such hosts.
- **Fix:** `syscall.Statfs` on `runs/`, accepting only an allowlist of `f_type` values (tmpfs, ext2/3/4, xfs) and refusing the rest with the fixed text. Or downgrade the guarantee in the docs and the PR to "an operator-asserted separate filesystem; device IDs are a heuristic". Mention thin LVM as a residual risk either way.

### Medium

**M1. The fetch/pull guard can be bypassed by a remote-name-shaped path or an option.** `git.go:162-166`.
- Any `^[A-Za-z0-9_-]+$` argument is trusted as a remote name. If no such remote is configured, git treats it as a path relative to the command's working directory. That directory is `tree`, the run-written `CopyTree` copy, so `fetch ws` opens `tree/ws`. A bare repository there survives the copy, because only names equal to `.git` are skipped.
- Options are not screened either: `fetch --upload-pack=<cmd> origin` runs `<cmd>`.
- This is safe today only if callers never pass run-influenced arguments.
- **Fix:** accept a name only if `remote.<name>.url` exists in the controller repository (it is snapshot-protected). Refuse `-u`, `--upload-pack`, `--receive-pack` and `--exec`, or expose a typed `Fetch(remote, refspec)` instead of raw arguments.

**M2. Huge directories are listed in full before any cap applies.** `run.go:657` (`within`) and `run.go:232` (`copy`).
- `filepath.WalkDir` and `fs.WalkDir` call `ReadDir(-1)`, reading and sorting the whole directory before the first callback. One directory with millions of entries (bounded only by the inodes of `runs/`) is fully loaded into controller memory before `maxEntries` stops the walk.
- **Fix:** walk with `f.ReadDir(1024)` batches and count as you go.

**M3. The probe can outlive the response write deadline.** `internal/daemon/server.go:42` sets `WriteTimeout` to 30s, while `probeLimits.Timeout` is 1 minute plus image start.
- A probe that runs past 30s finishes, but its report is lost and the client sees EOF.
- **Fix:** in `SandboxProbe.ServeHTTP`, call `http.NewResponseController(w).SetWriteDeadline(time.Now().Add(probeLimits.Timeout + margin))`, as the events route does.

**M4. The disk bound is checked only after a successful run.** `run.go:146`.
- `within` is skipped when the run exits non-zero or times out. A failing run's attempt keeps any amount of data, and its results may still be copied out.
- **Fix:** always measure, and join the result into the returned error.

**M5. A symlinked sandbox root passes the overlap check.** `sandbox.go:85-88` uses lexical `overlaps(f, h.Root)`.
- If Root is a symlink into the state directory, the check passes. Podman's `storage/`, `r/` and `home/` then live inside the state directory. `runs/` is only rescued when its device matches, and not when it is its own mount.
- **Fix:** require `filepath.EvalSymlinks(Root) == Root`, or compare the resolved paths, as `refused` already does.

### Low

- **L1. Size sum can overflow.** `run.go:663`: `size += info.Size()` wraps when a sparse file of nearly 2^63 bytes is present (tmpfs permits it). Fix: `if info.Size() > disk-size { refuse }` before adding.
- **L2. Questions 1–6 are fine as checked.**
  - Probe route: the operator check comes before any parameter use. `image` must match `pinned` and goes after `--`; `mode` is enum-checked. `TryLock` with a deferred `Unlock` is error- and panic-safe, and cancellation flows from `r.Context()`.
  - Placeholder gateway: a fresh 0700 `MkdirTemp` directory. The socket is never accepted, so a run can at most fill its backlog.
  - Refusal texts are fixed and never echo paths.
  - URL forms that are safely refused or inert: `file:` without `//`, `ext::`, `fd::`, scp-like `host:path` and drive-letter forms, and `.`-relative paths are all refused. `ssh://-oProxyCommand…` passes `refused` but is inert: git ≥2.40 rejects dash hosts, and `core.sshCommand=false`. `HTTPS://` passes `refused`, but git routes it to a nonexistent `git-remote-HTTPS` helper and fails. The test asserting it "passes" proves only the classifier.
  - Version parse: the regex takes major.minor from `2.43.0.windows.1` and `2.39.3 (Apple Git-146)` correctly.
  - Object format: checked in `Clone`, the only constructor of a usable `Repo`. A later `extensions.objectFormat` edit is caught by the snapshot.
- **L3. The git floor is not a security floor.** 2.40 is chosen for `GIT_ATTR_SOURCE` and admits gits with the 2024 local-clone CVEs (CVE-2024-32004/32465). Distributions backport fixes, so state that the version check is not a security floor.
- **L4. `gitOnce` caches a transient failure for the life of the process.** Acceptable, but say so.
- **L5. The forbidden list omits some sensitive files.** The `--https-key`/`--https-cert` files and a non-default `XDG_RUNTIME_DIR` Podman socket are not forbidden. The latter is already disclosed. Runs mount only `runs/<id>`, so this is minor.
- **L6. Git's suffix probing.** For a local path git also tries `<p>.git`, `<p>/.git` and gitfile pointers, which `refused` does not resolve. Only non-run-writable locations can plant them, so this is minor.

### Fault evidence
The evidence discriminates per check, except two gaps:
- `TestURLTightening` has no percent-encoded case (H1).
- No test covers a run-failure path for the disk bound (M4).
