# PR #67 (adapter method schemas): Astra reviews

## Review of #67 (Astra, 2026-10-05)

Verdict: NO-GO

Three High findings block approval. The individual schemas pass their tests, but they do not yet compose into a complete adapter contract.

### Critical

None.

### High

1. **Failed controller-mediated tools cannot complete a valid notification round-trip.**  
   `schemas/adapter/tool-response-params.json:22` requires `delivered: null` for `failed` and `could_not_run`. However, `schemas/adapter/event.json:101–103` requires a non-null handle whenever `mediated_by_controller` is true. The newly tested “tool that could not run” response therefore cannot produce the corresponding honest `tool.result`. The generated validator confirms this contradiction.

   **Fix:** Define failure delivery consistently across both messages. Prefer supplying a controller-authored diagnostic content handle even when the tool fails; the run artifact’s null-result rule need not apply to tool feedback. Alternatively, explicitly support mediated results without delivered content and define their coverage treatment. Test request → response → result for all four outcomes.

2. **Unavailable final usage has no valid representation.**  
   `schemas/adapter/run-result.json:53–74` requires every token counter, turns, milliseconds, and cost. Yet `describe.telemetry.usage` may be false, and `AUTHORING.md:47–48` explicitly permits unknown usage and prohibits invented numbers. An adapter lacking final billing information must fabricate figures or fail validation. Treating placeholder figures as a final is consequential: `internal/capacity/ledger/ledger.go:142–147` clears the uncertain-liability flag when a final exists.

   **Fix:** Permit an explicitly unavailable final report, and define how partially known usage is represented. Specify that unavailable usage must not produce a final measurement that clears uncertainty. Add cases for unavailable telemetry and interrupted runs with incomplete usage.

3. **Tool identifiers accepted by the methods are rejected by notifications.**  
   `schemas/adapter/event.json:34–37` introduces `AdapterLabel`, used by `tool_surface`, both tool-policy lists, and `tool.response`. But `tool.request` and `tool.result` still reference the lowercase-only receipt `Name` definition (`event.json:93,100`). Thus the PR’s own `Read` tool label is valid in policy but invalid in its result notification; a mediated `RunTest` response is valid although its request is invalid.

   **Fix:** Use one shared tool-name definition throughout describe, prepare, requests, responses, and results. Add shared cases exercising uppercase and punctuation-bearing labels through the complete exchange.

### Medium

4. **The reusable-process description contradicts the required process boundary.**  
   `schemas/adapter/describe-result.json:45` says a process may serve several attempts. Design 09:8 requires one adapter process per attempt, explicitly including adapters declaring `reusable_process`. Fresh sessions alone do not satisfy that process rule.

   **Fix:** Describe reuse as a capability that does not override the controller’s per-attempt process lifecycle, or explicitly revise the normative design before permitting reuse.

5. **The referenced “Semver” definition is not a semver contract.**  
   `schemas/adapter/describe-result.json:29–33` references a pattern accepting only three digit strings. The generated validator rejects `1.0.0-rc.1` and `1.0.0+build.1`, while accepting `01.0.0`.

   **Fix:** Use a complete semver definition, or explicitly document and agree on a narrower version grammar. Test prerelease, build metadata, and forbidden leading zeros. Major-version compatibility remains a host check.

6. **Gateway validation accepts strings that are not usable HTTP URLs.**  
   `schemas/adapter/prepare-params.json:134–137` checks only a scheme prefix and selected whitespace. I verified that `http://#fragment`, `http:///path`, and an HTTP string containing NUL pass the generated validator.

   **Fix:** Require a valid HTTP(S) URL with a nonempty authority and reject control characters, using equivalent Go/TS validation. Add these counterexamples to the shared corpus.

7. **Cross-language coverage omits five new message schemas.**  
   `fixtures/contract/cases.json:1089` onward adds seven cases, but all cover only `prepare-params` and `run-result`. There are no shared cases for describe, run params, fenced params, outcome, or tool response. `schemas/adapter_methods_test.go:38` validates documents individually and does not round-trip the new generated Go types or compose method messages with events.

   **Fix:** Share the positive and negative method cases across both validators, add generated-type round-trips, and add the exchange checks above. Killing individual schema mutations does not establish protocol consistency.

### Low

None.

The handle shape, bounded fencing tokens, result kinds, non-empty detail rules, and run’s failure/null rule are sound. Label sets, telemetry booleans, `{path, writable}`, bounded limits, and separate native/mediated tool lists are reasonable choices once their domains agree. Keeping controller-owned measurement metadata out of `usage_final` is also appropriate.

Schema acceptance does **not** establish confinement or credential safety. Attempt equality, current-token/publication checks, safe M9 ingestion, read-only host snapshots, disabled repository configuration/subagents/model switching, and M11 credential-copy scoping and teardown remain host/SDK/conformance obligations. Their absence from these schema tests is not independently a blocker for this contract-only PR.

Validation passed: Go smoke tests, TypeScript corpus tests, TypeScript compilation, and fresh generation compared with committed outputs. The checkout was unchanged.

  `tool.result` reports exactly that handle. `TestToolExchange` composes request → response → result for all four
  outcomes.
- High (unavailable usage): `run.usage_final` is `null` or complete. Null records no final, so the call stays an
  uncertain liability at the sum of its deltas; the description forbids invented figures. A null case is in the shared
  corpus and round-trips through the generated type.
- High (tool names): `tool.request` and `tool.result` use `AdapterLabel` like describe, the policy lists and
  `tool.response`; the exchange test runs an uppercase, punctuation-bearing label through the policy and all three
  messages.
- Medium (reusable_process): the description now says reuse never overrides one adapter process per attempt.
- Medium (semver): a new `AdapterVersion` holds the semver 2.0.0 grammar (prerelease, build, no leading zeros) for the
  adapter and contract versions; the registry's three-number `Semver` is unchanged.
- Medium (gateway URL): a host (name, IPv4 or bracketed IPv6), an optional port and an optional path without control
  characters, spaces or a fragment. `http://#fragment`, `http:///path`, NUL, a fragment and `ftp://` are refused.
- Medium (coverage): every method case is now in `fixtures/contract/cases.json`, so both validators run all seven
  schemas (59 method cases); the generated Go types round-trip each message.

## Second review of #67 (Astra, 2026-10-05)

Verdict: GO with changes

No Critical or High blockers remain in this schema-only PR.

- **High — Failed tool delivery: RESOLVED.** Both validators accept request → response → result for all four outcomes with a delivered handle. Null mediated delivery is rejected; native results still require null.
- **High — Unavailable final usage: RESOLVED at the schema/type boundary.** Both validators accept null and reject incomplete objects; Go preserves null through round-trip. See the accounting clarification below.
- **High — Tool-name mismatch: RESOLVED.** `RunTest.v2/x+y` passes the complete exchange in both validators; describe and policy use the same definition.
- **Medium — Reusable-process description: RESOLVED.** It explicitly preserves one adapter process per attempt.
- **Medium — Semver grammar: RESOLVED.** Both validators accept prerelease/build versions and reject leading-zero core versions and numeric prerelease identifiers.
- **Medium — Gateway URL validation: PARTIALLY RESOLVED.** All original reproductions are rejected, but the replacement pattern has acceptance and compatibility gaps.
- **Medium — Shared corpus and round-trips: RESOLVED.** All seven method schemas have shared coverage; generated Go round-trips and the exchange test pass.

### Medium

1. **Gateway validation rejects usable addresses and accepts malformed ones.**  
   `schemas/adapter/prepare-params.json:136`

   Reproduced identically against Go and TS:

   | URL | Validators | Problem |
   |---|---|---|
   | `https://gateway.internal./v1` | Reject | Valid hostname with trailing root dot |
   | `http://[::ffff:127.0.0.1]:7801/v1` | Reject | Valid IPv4-mapped IPv6 address |
   | `http://[abcd]/v1` | Accept | Invalid IPv6 literal |
   | `http://[:::]/v1` | Accept | Invalid IPv6 literal |
   | `http://h:99999/v1` | Accept | Unusable port |

   **Fix:** Use equivalent URL-aware validation in both runtimes, or a precisely specified common subset that supports these legitimate host forms and validates IPv6 and port bounds. Preserve the control-character/fragment rejection and add these cases to the shared corpus.

2. **Null usage does not itself guarantee an uncertain-liability entry.**  
   `schemas/adapter/run-result.json:54`; `internal/capacity/ledger/ledger.go:140`

   With existing deltas and no final/reconciliation, the ledger preserves their sum with `Uncertain=true`; null therefore avoids the original fabricated-final problem. However, `Reconcile(nil)` returns an empty map. A telemetry-disabled call with no measurements has no ledger entry, so the description’s unconditional promise is too strong. A provider reconciliation also legitimately resolves uncertainty despite an unavailable adapter final.

   **Fix:** Specify that null creates no final measurement; the controller must retain the recorded call and its best available liability estimate when measurements are absent. Add a no-telemetry/no-deltas integration case when that wiring is implemented. This is a contract clarification, not a demonstrated budget-release path introduced by this PR.

Validation passed: Go schema, contract, ledger and schemadoc tests; TS corpus and compilation; independent Go/TS adversarial probes; fresh Go/TS generation and schema documentation comparisons. The link-check adjustment caused no observed regression. Repository files remain unchanged.
### Lead notes on round 2 (applied)

- Medium (gateway): the host is now an exact grammar. It is a DNS name (labels of up to 63 characters, the last
  starting with a letter, an optional trailing root dot), a dotted IPv4 address with octets up to 255, or a bracketed
  RFC 3986 IPv6 address (IPv4-mapped included, no zone). The port is 1–65535. A generator in the lead's scratchpad
  checked the IPv6 part against Python's `ipaddress` over 200,000 random strings with no disagreement. All five rows of
  the review's table are in the shared corpus, with the reviewer's verdicts, plus the highest port, port 0, an
  out-of-range IPv4, two double colons, empty, hyphen-ended and 64-character labels, a zone and userinfo (14 cases; the
  corpus is now 127). Seven mutations of the pattern's parts are all killed.
- Medium (null usage): the description now says that null creates no final measurement, and that the controller keeps
  the call recorded with its best available liability estimate (the sum of its deltas, held uncertain, or its
  reservation when there are none) until a provider reconciliation resolves it. The no-telemetry, no-deltas
  integration case belongs to the capacity wiring and is recorded for it.
