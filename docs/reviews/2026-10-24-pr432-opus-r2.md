### BLOCKING

**H1′. A damaged unit index still takes the benchmark facts to another task's attempt, lease, calls and liability. BLOCKING.** `internal/api/taskbench.go:68`, `internal/lease/submit.go:105`
- **Cause:** the fix checks each node's task and project (`internal/api/tasks.go:160`). But `benchOf` then follows `lease.AttemptsOn(tx, graph.UnitOf(node))`, which:
  - loads the attempt the unit row names;
  - never checks that the attempt's `Unit` is that unit;
  - is followed by `benchLease`, which reads that attempt's lease, every call `ledger.BoundTo` lists, each call's measurements, and its liability.

  No hop checks task or project.
- **Probe A, a concrete input:** `lease_units[UnitOf(done's plan)]` was set to `running`'s attempt. `done`'s one-task read then returned a placed card with `bench.leases` holding 1 lease: `running`'s, with its call and measurements. On main's data it holds 0.
- **Effect:** the probe stays inside one project. The code has no project check at any hop, so a row naming an attempt of a task in another project discloses that project's lease, calls and liability under the caller's read kinds for the first project. That is the same class and rating as Astra's H1.
- **The same gap, one hop further:** `benchLease` uses the `ledger.BoundTo` index and `ledger.Binding` (`taskbench.go:155`), but never checks `binding.Lease == id`.
- **Fix:** check each hop against its source, and treat a mismatch as the task's damage (the one-task read fails, as M1 does):
  - the attempt's `Unit` equals the node's unit;
  - the lease's `Unit` equals it too;
  - each call's binding names this lease;
  - add a row for each hop beside `TestATasksDamagedFactsAreItsOwn`.

### Low

**L1. A released reuse leaves its times behind, so the stage's wall time is wrong. OBLIGATION.** `internal/graph/events.go:363` (`stamp(…, true, true)`), with `reuseReleased`
- **The waiting interval:** `node.reuse_released` drops the node's claim and result, and returns it to waiting. Its times row keeps the first reuse's claim and selection, so during that interval `bench` shows a waiting node with `claimed_at` and `selected_at`.
- **After a later reuse or run:** `claimed` stays the first reuse's time ("the first claim"). Probe B: `b`'s times span 04.263 to 04.429, the released interval included, although a reused node "took no time of its own".
- **Fix:** clear the row in `reuseReleased`. Or stamp the claim at the latest reuse when the previous one was released, and add the release to the row in `TestNodeTimesAgainstTheirEvidence`.
- **How likely:** unreached in production today (above), hence Low.
