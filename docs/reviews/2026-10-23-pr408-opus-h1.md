### Medium: OBLIGATION

**M1. When `Endable` names a unit that `end` cannot act on, `End` "succeeds" every pass: no backoff, no log, a nudge every time, and the task stays admitted.** `internal/daemon/sweep.go:212-231`
- **Cause:** the two sides cover different states.
  - **`Endable`** reports any open-index entry on any of the task's units (`lease.Unended`: a lease not ended, an attempt not sealed: running, stopping, lost, finishing).
  - **`end`** acts only on the unit's *current* attempt, and only when `leftAt` covers it: finishing, or sealed/completed with an active or settling lease.
  - **Otherwise** `todo` is empty and `err` is nil, so the entry is deleted, `start` nudges the loop, and the next pass decides `Ending` again at once.
- **Probe:** after `candidateRun`, add an open-index entry for the build's unit naming its own completed attempt. That stands in for a lost-unsealed attempt, or a granted lease left with no attempt. Result after 10 passes: still admitted, 10 tries, 10 nudges, an empty log. In adcd each nudge starts the next pass, so this is a hot loop.
  - The card does show `ending_blocked`.
  - A real input was not built; a lost attempt whose seal failed on `record`'s not-submitted path is the likeliest.
- **Fix:**
  - Have `end` return an error, counted, backed off and logged once, when it found nothing to end while `Endable` still refuses: re-read `Endable` after the try.
  - Better, act on the entry `ErrEnding` names: seal a lost or finishing attempt; release or end a lease left with no attempt.
  - Add the row above.

**M2. A decided candidate that is still ending, whose approval is then revoked, is never ended at runtime.** `internal/reconcile/reconcile.go:611-615`
- **Cause:** `Decide` puts `Abandon` before `Ending`. `AbandonTask`'s `endable` refuses with `ErrEnding`, and nothing decides `End` for an abandoned task.
- **Probe:** `unsealedReview(t, -1)`, then revoke the operator, then 12 passes:
  - still admitted, with 0 `End` tries;
  - the loop logs `reconcile.abandon refused: … attempt … is finishing` once;
  - the card shows `ending_blocked`.
- **Effect:** logged and visible, but with no retry: the task holds admission until a restart's sweep.
- **The same holds for an uncandidated task:** for example a build whose seal never lands and is then revoked. It gets the log only, with no card state, because `endingOf` needs `CandidateGo`. That part predates this PR: the refusal used to be stale and silent.
- **Fix:** in `Observe`, decide `Ending` for any admitted task whose `Endable` refusal, as candidate or as abandoned, is `ErrEnding`, whether it is revoked or decided. Have `endingOf` show it whenever `ErrEnding`, not only for a decided candidate.

### Low: OBLIGATION

**L1. `endable` returns at the first node with an open unit, before it has seen a later node that is claimed or held.** `internal/authority/admit.go:185-194`
- **Effect:** `Observe` then decides only `Ending`, and evaluation of that claimed node waits until the unit ends. This is bounded, because `End` ends it, except in M1's case.
- **Fix:** check every node for claimed or held first, then for open units.
