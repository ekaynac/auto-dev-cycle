### Judgement on the six questions
1. **Start order.** It is correct.
   - Inside `start`, before recovery, only these write: the system actor's `Bootstrap` (fresh store only) and `MarkPendingUncertain`.
   - The only other commands at start come from `openBootstrap`, which runs after recovery.
   - `purgeUploads` starts in `Run`, after `Start` returns.
   - Offline commands skip recovery by design; they are identity-only.
   - A start goes on with a cut attempt that is not fully converged only when steps 2–4 fail. That attempt is already `lost` with publication closed, so the fence holds (I8). This is #226 entry 81's "cleanup never blocks start".
   - The `running` check is the right test. Publication is open exactly while an attempt is `running` (`lease.ApplyAttempt`).
2. **Accounting.**
   - `modelcall.Project` now feeds `ledger.BoundTo`, so the settlement keeps the uncertain call as a liability (row (c), and S6).
   - Each call is named once per settlement, so there is no double charge.
   - The order relative to `ledger.Project` does not matter: both handle `Measured` and write disjoint tables.
   - Entry 70's start check is covered structurally. `checkProjections` refuses a store whose persisted bindings differ from a replay.
   - A second start appends no event. It does record one empty command row (L4).
3. **Authority.**
   - `authorizeSystem` admits only a principal whose actor kind is system.
   - `identity.Recheck` requires the store's system claim, which only `SystemPrincipal` holds.
   - `Authenticated` never makes a system principal, so no token holder can issue these actions.
   - Before this PR these actions fell through to `az.Authorize`, which returns `ErrActionNotWired`. The authority grew from nobody to the system actor.
4. **The fresh-store change is safe and stated** (PR body and `TestFailedRestartTransitionRefused`).
   - A crash between `systemActor` and `openBootstrap` could already leave the same state: one system actor and no bootstrap record.
   - The next start loads that actor and issues the secret.
5. **Regression against main:** none found.
6. **Rows and mutations:** the rows hold, and all 8 named mutations are caught. The gaps are in M2 and L5.

### Medium

**M1. A recovery failure that does not refuse the start throws away its cause.** (`internal/daemon/startup.go:189`)
- **Input:** a cut store where step 3 fails, for example `Blobs.Publish` returns EACCES.
- **What happens:** `rerr` names the attempt, the step and the errno. The note says only "restart recovery left work for the next start". The operator cannot tell which attempt is stuck, or why.
- **Why it matters:** the #259 Opus record (L1 fix) asked for the cleanup failure to come back separately "so P22a can log it". The generic engineering rules also forbid swallowing errors silently.
- **Fix:** add `rerr` to the note, for example `fmt.Sprintf("adcd: restart recovery left work for the next start (it resumes there): %v", rerr)`. The error holds ids, actions and errnos, not secrets. Extend `TestStartRecoveryFailures` to assert that the injected text appears in `d.note`.

**M2. The headline order, "recovery before any other command", is not pinned by any row.** (`internal/daemon/daemon.go:162-171`, `internal/daemon/recovery_test.go:84-113`)
- **Input:** mutation X1 moves `recoverAtStart` after `openBootstrap`. On `cutStore`, `openBootstrap` then issues the bootstrap secret before `attempt.lost`.
- **Result:** every row passes.
- **Why it matters:** the code is correct today, but 22a-4 adds work at start, and nothing would catch a reorder.
- **Fix:** in `TestStartRecoversACutAttempt`, read the log after the first `Start` and assert that the seq of `attempt.lost{controller_restart}` is below the seq of every event this start appended under any other action (here, the bootstrap secret's record).

- **Fix:** use `vocab.ReasonAmbiguousState` when the `View` succeeded and `running` is true. Keep `store_unreadable` for a failed `View`.

**L4. Every start records one empty `recovery.lose` command row.** (`internal/recovery/recovery.go:93`; `internal/eventstore/writer.go:607`)

- **Fix:** either state it in the PR body and the test comment, or skip the submit when a pre-`View` finds no unit with a `running` attempt. The command still decides again in its transaction.
