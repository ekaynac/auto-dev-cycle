## Opus pre-review of #260

Verdict: NO-GO

I reviewed dfc9409 in a scratch worktree, which I have since removed. CPython 3.12.3 was the reference, used through `python3 -I -m tokenize` and `compile(bytes)`. The tests run with Go 1.27.1 and `-run PyTokens` pass. I also ran the PR's own `golden()` converter on 13 extra sources that compile under CPython. Two of them show real differences, and a third finding breaks H8. All three would land in P14c-2 unchanged, so I am blocking on them now. Today the tokenizer is inert: nothing outside `integrity_py.go` and its test calls `pyTokens`.

On the two background security flags:
- **Parser differential: confirmed.** See H1 and H2.
- **Unbounded recursion: confirmed.** See H3. The 65-level limit is checked only on entry to `pyString`. The recursion into format specs never checks it.

### High

**H1. A backslash continuation at column 0 sets the wrong indentation. CPython nests the block; the tokenizer puts it at module level.**
- **Where:** `integrity_py.go:106-119` (the indent loop stops at `\`) and `:134-137`.
- **Cause:** CPython 3.12 keeps scanning indentation across `\`+newline at the start of a line. It uses the column of the first backslash (`cont_line_col`), but only when that column is not 0. At column 0 it uses the column of the continued line. `pyLex` always uses the column where the backslash sits, so it gets 0.
- **Input:**
  ```
  if False:
      pass
  \
      def test_zero():
          assert 1 == 2
  ```
  - CPython levels: `[0 1 1 2]`. `test_zero` is inside `if False:`, and running the file confirms `test_zero` is not defined.
  - `pyTokens` levels: `[0 1 0 1]`. `def test_zero` is at module level.
  - A form feed before the backslash (`␠␠\f\` then a newline) does the same, because it resets the column to 0.
- **Impact:** P14c-2 would see a kept test that CPython never defines. This is exactly the H6 "`if False:` uncollection" bypass that the guard exists to catch.
- **Fix:** In the indent loop, read `\`+newline as a continuation and keep reading whitespace. Track `contCol` the way CPython does: set it at the first backslash, and if it is 0 use the final `col`. Simpler and fail-closed: return unverifiable when a logical line starts with a backslash continuation. Add `bs0` and the form-feed case as goldens.

**H2. Binary and octal literals take in hex letters, so `and`, `else` and `for` after them are misread.**
- **Where:** `integrity_py.go:195-198`. All three prefixes (`0x`, `0o`, `0b`) use the hex digit set.
- **Cause:** CPython ends `0b1`/`0o1` at the first letter that is not a valid digit. It then accepts a following keyword with only a SyntaxWarning, and the file compiles and runs.
- **Input:** `assert check() if 0b0else True`, `y = [0b1for i in range(2)]`, `z = 0o1and 0`.

  | Source | CPython | `pyTokens` |
  |---|---|---|
  | `0b0else` | `0b0` `else` | `0b0e` `lse` |
  | `0b1for` | `0b1` `for` | `0b1f` `or` |
  | `0o1and` | `0o1` `and` | `0o1a` `nd` |

- **Impact:**
  - The first line is an always-passing conditional assert, and the guard sees no `else`.
  - `for` turns into an `or` that is not there.
  - H7 (assertion inflation) reads exactly these keywords.
- **Fix:** Use the hex set only for `x`/`X`. For `o`/`b`, scan `[0-9_]` only; reading invalid digits greedily is safe, because CPython rejects them. Add the three lines above as a golden.

**H3. Format-spec nesting recurses without a limit or a context check (H8).**
- **Where:** `integrity_py.go:262-263` and `:270-271`. The depth check is only at `:227`, in `pyString`.
- **Cause:** In `pyField`, a `{` inside a spec calls `pyField(depth+1, false)`, and a `:` calls `pyField(depth, true)`. Neither checks `maxNest`, and nothing checks `ctx`. There are 2 Go stack frames per 2 bytes of input.
- **Input and measurements:**
  - At the 4 MiB per-blob cap (`maxFile`): `"x = f'" + "{:"×2,097,148`, unterminated. With a 1 ms deadline, `pyTokens` ran for 815 ms (about 815× over) and the process peaked at 880 MB RSS. The goroutine stack is one doubling below Go's 1 GB limit.
  - At 40 MB: `f'` + `{a:`×10M + `}`×10M gives `fatal error: stack overflow`. `recover()` cannot catch this, so the controller process dies.
  - CPython already rejects 4 nested spec levels ("expressions nested too deeply").
- **Fix:** Put `need(depth <= maxNest)` at the start of `pyField`, and pass `depth+1` on the `:` spec descent. A lower spec limit (CPython allows 3) is also fine. Add a `{:`-nesting row to `TestPyTokensBounded`, including a short-deadline check.

### Medium

**M1. One golden does not compile, against the PR's claim that every `.pysrc` compiles.**
- **Where:** `testdata/pytoken/joining.pysrc:17`, `w = 0x1for_ = 1`.
- **Cause:** `compile()` raises "SyntaxError: invalid hexadecimal literal". `python -m tokenize` runs in its liberal extra-tokens mode, so the golden records a split CPython never makes when it runs code.
- **Fix:**
  - Drop or replace that line.
  - Make regeneration fail unless `compile(open(f,'rb').read(), f, 'exec')` succeeds.
  - Make `golden()` fail on token types it does not know (today `ERRORTOKEN` is dropped silently, at `integrity_py_test.go:58-82`).

**M2. The golden corpus is too narrow to catch differentials.**
- **Where:** `integrity_py_test.go:108`.
- **Cause:** The comparison itself is sound: kinds, boundaries, logical lines and levels. But the corpus has no case for H1 or H2, and both pass the suite today.
- **Fix:** Add the inputs from this review. Also add a dev-only differential test that runs `python3 -I -m tokenize` on generated inputs and is skipped when there is no python3. Feed it with the "Judge" list: prefixes, number/keyword joins, backslashes in indentation, f-strings with nested specs.

### Low

**L1. Version pinning.**
- **Where:** `integrity_py.go:14-21`.
- **Cause:** The goldens are CPython 3.12.3. `cont_line_col` and PEP 701 are 3.12 behavior. t-strings are read as f-strings, but 3.12 reads `t'..'` as a name followed by a string.
- **Fix:** P14c-2 should record which interpreter it assumes, and refuse t-strings unless the target is 3.14 or later.

**L2. Memory.**
- **Where:** `integrity_py.go:25-35`.
- **Cause:** Each `ptok` takes about 24 bytes, so a single 4 MiB logical line of 2.8M tokens holds about 70 MB, more while the slice grows. This is bounded by `maxFile`, so acceptable.
- **Fix:** Optional: store offsets instead of strings, and pre-size the slice.

**L3. Differences where the tokenizer accepts and CPython rejects.** I found these; they are benign because the file does not compile, so nothing runs:
- a comment in a single-quoted f-string field;
- a quote or newline in a single-quoted spec;
- `\}` in a literal;
- mismatched bracket types;
- brackets inside fields not counted toward MAXLEVEL;
- `0b2`, `1e+x`, `1__0`, stray `$`/`\v`, and inconsistent tabs.

They are fine to keep as they are, but P14c-2 must not treat "tokenizable" as "compiles".

### Refuted or clean
- **Encoding gate (H5): no bypass found.**
  - The cookie regex matches CPython's `get_coding_spec`: whitespace and form feed before `#`, a case-sensitive `coding[:=]`, the first non-empty name wins, and `vim: fileencoding=` is caught.
  - Lines are split after CR/CRLF normalization, as `translate_newlines` does.
  - A BOM with a non-utf-8 cookie is an error in CPython. A BOM with `utf-8-sig` decodes as UTF-8 in both.
  - A cookie on line 2 is checked even after code, which is stricter than CPython.
- **These matched CPython exactly:**
  - nested and quote-reusing f-strings, `!r`, `=`, nested specs, `\{`, `\N{}`;
  - triple quotes with escapes before the close;
  - U+2028 and U+0085 in strings and comments;
  - tabs, and a form feed in mid-indentation;
  - comments holding brackets inside brackets;
  - `1.0.real`, `1..real`, `0x_f`, `1_0j`, `1e+5`.
- **Goldens:** I regenerated all 10 `.tok` files, including `cr.tok`, and they are byte-identical. The `cr.tok` process is sound: universal-newline decode equals `translate_newlines`, and `cr.pysrc` compiles from bytes.
- **Fault evidence:** I reran M4 (no bracket limit), which fails the 201-bracket row in `TestPyTokensRefuses`, and M8 (a lone CR not a line end), which fails `TestPyTokensMatchCPython` on `cr.pysrc`. Both discriminate, and the file was restored afterwards.
- **Inertness:** confirmed. There are no production callers, and P14b's fail-closed rule for Python stays.
