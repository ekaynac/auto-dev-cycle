I reviewed 61ea133 (`git diff origin/main...HEAD` and the PR body) against Opus and Mythos #266 H2, Mythos r2 (M1, M3, L1, L2, L4, L5), Mythos r3, #226 entry 84 and decision A.

How I tested:

- I ran end-to-end forgeries under pytest 9.1.1 with `python -I`. In each one, `add` returns `a - b`, so the tests should fail.
- I measured the condition rule on 1,304 real test files: numpy, sympy, networkx, setuptools, pyarrow, torch and others.
- `go test ./internal/accept -run PyGuard` passes. Both worktrees are removed. I changed and pushed nothing.

The PR has no effect yet, because P14b's fail-closed rule still blocks every Python change. I block for two reasons:

- The L5 restriction lets through a submodule shadow that #266 (main) blocks today.

Both fixes are small. A lead re-verify should be enough.

### High

**H1. A `skipif`/`xfail` mark built in an application module and applied by name in a test module gets past the rule. There is no block and no warning.** (`integrity_pyguard.go:321`, `if judged && pySkipString(code)`)
- **Input, two files.**
  - `money.py`: `import pytest`, the faulty `add`, then `SKIP = pytest.mark.skipif("<Opus #266 H2 payload> and False", reason='r')`.
  - `tests/test_money.py`: `from money import add, SKIP`, then `pytestmark = SKIP`, then the two tests.
- **Why it passes.**
  - `money.py` is not judged, so the rule does not run on it.
  - Its import code is an allowlisted `pytest.mark.NAME` call of constants, so it raises no warning either.
  - In the test module, `pytestmark = SKIP` binds a plain name to a constant.
- **Result.** The guard reports blocks `[]` and warnings `[]`. pytest reports `2 passed` and `failures="0"`.
- **The promise.** It is in judged files only. But H2's threat is "a string condition is code pytest runs". Decision A requires at least a warning for each application file, and this route raises none. `pytest.param(marks=SKIP)` and a class-level `pytestmark = SKIP` work the same way.
- **Fix.** Run `pySkipString` on every `.py` file. Block in judged files (as now) and in application modules too, because application code that builds a `skipif`/`xfail` mark is almost never legitimate. If that is too strict, the minimum is a warning under decision A. Add the two-file row.

**H2. The L5 restriction lets a namespace-package submodule shadow through, and #266 blocks this today.** (`integrity_pycond.go:83-87` `onPath`; `:96-97` compares only the first dotted segment)
- **Input.**
  - Base: `lib/core.py` (no `lib/__init__.py`), a root `conftest.py`, and `tests/test_money.py` with `from lib.core import add`.
  - Candidate: makes `lib/core.py` faulty and adds `tests/lib/core.py` with a correct `add`.
- **Result.** The guard reports blocks `[]`. pytest reports `2 passed`, both under `python -I -m pytest` and under the `pytest` command. Without the shadow, it reports `2 failed`.
- **Why.**
  - pytest puts `tests/` at the front of `sys.path`. Both `lib` directories are namespace portions, and `tests/lib` comes first.
  - `onPath("lib")` is false, so the base-module rule skips `lib/core.py`.
  - The import rule compares `m = "core"` against `lib`, the first segment of `lib.core`.
- **#266 on main** blocks this input: "shadows a base module, or its __init__.py moved". The common layout `from src.money import add`, with no `src/__init__.py`, is exposed the same way. Third-party namespace packages are exposed too: `tests/google/protobuf.py` against `from google.protobuf import …`.
- **Fix.**
  - Block when the added path ends with a base module's path (`strings.HasSuffix(c.Dst, "/"+q)`, and the same for a package `__init__.py`).
  - In the import rule, compare every dotted suffix of the added file's path (`core`, `lib.core`) with each imported dotted name and its prefixes.
  - Add a row for the input above.

### Medium

**M1. `<<` and `>>` count as comparisons.** (`integrity_pycond.go:54`) The tokenizer gives one-byte operators, so `strings.Contains("<>=!", k.text)` is true for each `<` in `<<`.
- **Input.**
  - `money.py`: `class _Z:` with `def __rlshift__(self, o): return "<payload> and False"`, then `ZERO = _Z()`.
  - Test module: `@pytest.mark.skipif(1 << ZERO, reason='r')` on both tests.
- **Result.**
  - The guard shows no block. It shows one warning: "code run at import outside the allowlist ([ZERO = _Z ( )])".
  - pytest reports `2 passed` and `failures="0"`.
- **What this means.** This is r2 L4's attack again. The PR closed L4 by adding `__lt__` and the other ordering dunders to class `f`, and `__rlshift__`/`__rrshift__` skip around that.
- **Fix.** In `pyBool`, do not count `<` or `>` when the token next to it is the same character. Add a row.

**M2. The rule exempts any `pytest.xfail(…)`/`pytest.skipif(…)` because of its spelling, so a local name `pytest` can hold `pytest.mark`.** (`integrity_pycond.go:27`)
- **Input.**
  ```python
  @pytest.fixture(autouse=True)
  def fx(request, pytest=pytest.mark):
      request.applymarker(pytest.xfail("<payload> and False"))
  ```
- **Result.** The guard reports blocks `[]` and warnings `[]`. pytest reports `2 passed` and `failures="0"`. The xfail mark is evaluated when the call phase starts.
- **Same route.** `N.pytest.xfail(…)` gets past the same way, where application code holds `class N: pytest = _p.mark`.
- **Scope.** This happens in bodies only: at import, the allowlist blocks the call. The slice plan gives `add_marker`/`applymarker` to 2a2 and `getattr(pytest.mark, 'xfail')(…)` to 2a3, so this does not block. But the PR's "H2 applied in a body" row suggests bodies are covered.
- **Fix.**
  - Exempt only `pytest.xfail` when the file binds `pytest` nowhere except `import pytest`, or block a parameter, comprehension target or attribute named `pytest` in judged files.
  - State the body forms in the ledger as 2a2's and 2a3's: `getattr`, `pytest.MarkDecorator(pytest.Mark(…))` and `xfail(False)("…")` all get past.

**M3. The import-line regex misses imports that share a line with other code.** (`integrity_pycond.go:16`)
- **Inputs.** A base test holds `try: import yaml`, `import os; import requests`, or `import json, \` with `toml` on the next line. Adding `tests/yaml.py`, `tests/requests.py` or `tests/toml.py` gives blocks `[]` in each case.
- **Fix.** Read the import statements from `pyTokens` (each statement after `;` and after a compound statement's `:`) instead of a line regex. If the tokenizer refuses the file, block. Add one row.

**M4. The rule blocks pre-existing `skipif` lines that the candidate does not touch, so false blocks cost much more than the ledger says.** (`integrity_pyguard.go:321`, `find(…, true)`)
- **Why.** The finding is strict, so `passes` never lets it through. An unchanged `@pytest.mark.skipif(IS_WINDOWS, reason='w')` blocks any edit to its file. Probe: a new test added at the end gives two blocks.
- **Corpus (1,304 judged files).**
  - 138 files use `skipif`/`xfail`, and 76 of them (5.8% of all files) would be blocked on any edit.
  - 222 of 458 mark lines are flagged: 133 bare names (`IS_WASM`, `NO_MYPY`), 61 legitimate string conditions (setuptools, networkx), 24 calls (`running_on_musllinux()`, `os.environ.get(…)`) and 4 others.
- **Fix.**
  - Under D55, let an unchanged condition statement pass when the base line binding each of its names is also unchanged, and the imports are unchanged.
  - At the least, state the cost of untouched lines in the ledger with these numbers, for 2a-widen.

### Low

- **L1. `pythonpath` parsing.** (`integrity_pyguard.go:141-144`)
  - **TOML escapes.** With a base `pythonpath = ["src"]`, `src` is not in `paths`. An added `src/fractions.py` that shadows the stdlib module the tests import gives blocks `[]`, while pytest reports `1 passed`; without the shadow it reports `1 failed`. With a plain `"src"`, the same change blocks.
  - **Relative entries.** These are resolved against the root. pytest resolves them against the config file's directory (`tests/pytest.ini` with `../lib` is missed).
  - **Quoting.** INI values use shlex quoting.
  - Because the base configuration is trusted, these matter only for unusual bases.
  - **Fix.** Treat a `\` in a TOML `pythonpath` as unread. Join each entry with `path.Dir(p)`.
- **L2. Mutation survivors.** I re-ran X2: it is killed by both `p :=` rows. Two new mutations survive, so no row tests these clauses:
  - dropping the `d == "."` clause of `onPath`;
  - dropping the clause for a directory holding a test file (`:84`).
  - Add a row for each, without a root conftest in the base.

4. **and 5. Unnamed.** The two remaining routes are H1 (a mark built in an application module, with no warning) and H2 (the namespace-package regression).

Fail-closed checks I verified:
