- **Result:** accepted, with no block and no warning, at head and on main.
- **Cause:**
  - `check`'s only base referrer is `wrapper`, which is removed, so `replaced` finds no new function.
  - `wrapper` itself is renamed, but it held 0 assertions, so `!ok && bl == 0` skips it.
  - `TestNamed`'s text does not change, so no print warning fires either.
- **Why it blocks:** this is round 1's H1 (a callback renamed weaker, behind a `var`) one hop further, and it is not stated.
- **Fix:** follow the removed referrers. When a referrer of a removed function is itself removed, take its own base referrers, transitively over removed functions only, then collect the new functions those still-declared referrers reference at the head, transitively over new functions only. Charge each step.
  - Or, if a removed function's referrers are all removed, block it as unverifiable ("a helper's callers renamed too").

**H2. The rename rule does uncharged quadratic work, a regression against main.** `internal/accept/integrity_helpers.go:248-263`
- **Cause:** `replaced` walks each referrer's head references once for every removed function that referrer referred to. Nothing of it is charged.
- **Input:** n helpers `h_i`, each with one assertion (`t.Error()`), called by one `TestAll`. The head renames every one to `g_i`.
- **Measured:** one guarded run:

| n | Head | Main |
|---|---|---|

| 4,000 | 5.8 s | 1.3 s |
