## External review of #249 (Astra, 2026-10-14)

Verdict: NO-GO

**High — H1. An active lease does not prove its attempt is still running.** `internal/modelcall/modelcall.go:106`; `internal/gateway/gateway.go:280`, `:361`.

A supported sequence bypasses both checks:

1. Bind a token to running attempt A, active lease L and call C.
2. Commit `lease.StopRunning(A, preempt)`, as `graph.SupersedeMoving` does at `internal/graph/supersede.go:215`.
3. Send a **new** request using that token before teardown unbinds it.

The stop changes A to `stopping` and closes publication, but leaves L active and `L.Attempt == A` (`internal/lease/wiring.go:454`). Both gateway and recorder therefore accept the request. C’s first request can create a durable intent and reach the provider **after A stopped**. Subsequent requests also pass, with the intent cache skipping the recorder.

This requires only the adapter’s existing token and ordinary controller transitions. It contradicts the promised running-attempt admission check. It also exposes a gap in P11’s reviewed assumption that checking the lease fences stale attempts. Issue #226 entry 59 covers requests already admitted before unbinding; this sequence admits new requests after the stop.

**Concrete fix:** In `modelcall.Intend`, read the attempt and unit’s current-attempt projection inside the writer transaction. Require the bound attempt to be current, running, and bound to this lease and unit. Enforce equivalent eligibility on **every gateway request**, including cached tokens. Preserve acceptance of late usage separately.

Add regression cases using real lease/attempt projectors: commit a stop while leaving the lease active, then attempt both a first request and a later request on an already-intended token. Both must produce zero additional upstream requests. The current lease-only fixtures cannot detect this defect.

The remaining inspected paths support the contract:

- **Intent ordering:** first and concurrent first requests await the recorder’s committed transaction. Failures do not populate the cache. Rebinding after `Unbind` reaches the recorder and cannot change an existing call’s binding.
- **Recovery:** `RestartMarked` becomes true only after successful commit and resets on reopening. Pending effects become uncertain; re-intending and retrying an uncertain call are refused. The fresh-store requirement is correctly tracked in #226 entry 64.
- **Schema and replay:** the schema rejects extra fields and bounds unique groups. The fold checks immutable effect identity, command, target and digest, without depending on the effect’s changing state. Orphan and mismatched bindings fail. A controller manufacturing both a matching effect and binding remains outside D43’s attacker scope.
- **Accounting:** the durable binding survives recovery. Liability transfer and measurement-binding enforcement remain P12b/P20 obligations; this PR alone does not establish complete charging correctness.
- **Compatibility and inertness:** P11’s routing and credential checks remain intact. P13’s `refuse()` header addition is compatible. No daemon registration activates this kind.
- **Fault evidence:** the listed ordering, state and binding mutations have discriminating assertions. The crash fixture preserves an active lease, so its recovery refusal reaches the intent check. It simulates the boundary with a clean close/reopen; it does not independently prove abrupt-process durability.
