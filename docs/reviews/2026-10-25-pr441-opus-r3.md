### 1. Can a scan report success without searching what it promises?
Not through the scans themselves:
- **`scan`:** grep's failure (2 or more, or a signal) dies. `-r` skips FIFOs and sockets, it does not follow symlinks, and anything it cannot read fails closed.
- **`root_scanned`:** without the sentinel, the status is 3. The sentinel is always the last line, so neither a file name nor file content can forge it.
- **`runs_required`:** see above.
- **`canary_path`:** both `find`s are checked.
- **Mounts:** inside the userns, DAC override reads every mapped uid's files, so a mount only adds files to search.
- **Races:** nothing removes the run's files before its scans. A second signal during the EXIT trap only leaves leftovers, owner-stamped for the next sweep.

Through the caller's environment, yes: see H1(b) (`TMOUT`) and H1(c) (an imported `grep`).

### 2. Can a name outside the allowlist reach adcd, or a secret reach an argv?
**adcd's environment:** no. `clean_exec` reads the child's real environment, NUL-delimited (r2's table holds). `SHELLOPTS` is readonly, so it is refused there, and the launch fails closed.

**Argv:** no secret is in any argv (unchanged since #440 r2).

**But stderr, H1(a):** with `SHELLOPTS=xtrace` inherited, the driver traces every expansion *before* `clean_exec` refuses. My probe drove the stub route on a fake prefix to adcd's start, and the trace printed:

In #441 the stub route's secrets are throwaway. The live route (PR 2) would trace the real provider credentials the same way: the `${!var}` reads and the exports.

### Findings
- **H1** (BLOCKING under entry 202: an operator-environment input whose outcome is fail-open). The issue predates this PR and is on main as well, but it sits inside #441's promises: "no secret printed", "a scan that did not search everything never succeeds" and "the environment exactly its allowlist". Three inherited pieces of shell state cause it:
  - **(a) `SHELLOPTS=xtrace`** (also `BASH_XTRACEFD` and `PS4`) traces every expansion to stderr or to a chosen file, including every secret the driver reads, mints or exports. Probed above.
  - **(b) `TMOUT=N`** makes every `read` time out after N seconds. Probe: `TMOUT=1`, with a producer slower than 1 s, read 0 of 2 names, and the script continued with exit 0. In the drivers this silently ends:
    - the `canary_paths` loop (`scripts/installed-cycle.sh:387`): no canary path is checked;
    - `known`'s loop (`scripts/lib/secrets.sh:65`): fewer forms are registered, so redaction is incomplete;
    - the overlay check (`:218`) and the `.pids` loop.
    
    Each needs a producer slower than `TMOUT`. That is rare at the usual hardened values (600–900 s), but not impossible on a loaded host with small values.
  - **(c) An exported function** (`BASH_FUNC_grep%%=() { return 1; }`) is imported and shadows the command. Probe: `grep -q` no longer found the match, so `scan`, `root_scanned`'s caller-side checks and every `grep -q` guard would read "clean".

  **Fix:** a prelude at the top of both drivers, before sourcing anything:
  - `set +o xtrace +o verbose`;
  - `unset TMOUT BASH_XTRACEFD PS4 CDPATH GLOBIGNORE`;
  - unset every imported function (`while read -r f; do unset -f "$f"; done < <(declare -F | …)`, before the drivers define their own);
  - `shopt -u` the `BASHOPTS` that change globbing and matching.
  
  Better, re-exec under `env -i` with the allowlist the drivers already use for their children (`HOME`, `PATH`, `TMPDIR`, `XDG_RUNTIME_DIR`, `SECRETS_TAG`; for PR 2, the named `ADC_CREDENTIAL_*` variables), plus `bash --noprofile --norc`.

  **Rows:** run a driver row with `SHELLOPTS=xtrace`, `TMOUT=1` and an exported `grep` function, and require that no secret appears on stderr, that every canary is checked, and that a planted leak is still found.

  `BASH_ENV` executes before the script and cannot be guarded from inside it. That is operator code, so state it as the trust boundary, along with `PATH`.
- **L1** (OBLIGATION, Low): the drivers' secret-holding globals (`boot`, `tok`, `stub_cred`, and the stub `canary`) keep an inherited export attribute when the caller exported the same name. Their values then reach the environment of every child not started under `env -i` (`node` for `json`, `git`, `curl`, `sha256sum`). That is visible to the same uid only (`/proc/PID/environ` is mode 0400). `export -n` them as `secrets.sh` now does for its own, or let H1's `env -i` re-exec cover it.
- **L2** (OBLIGATION, Low): `cleanupProblems` still accepts `"$(...)"` with any content, so `root="$(printf %s "$root")"` keeps the inherited value and passes. Allow only command substitutions that read no variable, or drop the form; no current input uses it.
- **L3** (OBLIGATION, Low; no path today): `root_secret_scan`'s inner `grep -f -` treats an empty pattern stream as "nothing found", that is, clean, because grep exits 1. `forms` always prints the secret, and a real podman's `unshare` passes stdin (r1 found a planted leak through it), so nothing produces it. Still, pass the form count as an argument and refuse inside when fewer patterns were read, so that a stdin lost in some future launch path fails closed.
