**High — blocking**

1. **#108: Exchange setup failures panic instead of cleaning up.**  
   [internal/adapterhost/attempt.go:271](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah6/internal/adapterhost/attempt.go:271)

   `x` is a named return value. After allocating it, each subsequent `return nil, err` assigns `nil` to `x` **before** the deferred closure calls `x.remove()`. A mkdir, prompt-write, chmod, or directory-open failure therefore dereferences nil, potentially crashing the controller and leaving the exchange behind.

   **Fix:** Capture the allocated exchange in the deferred cleanup, independently of the return variable. Report cleanup failures instead of silently ignoring `RemoveAll` errors. Add fault-injection tests after each setup operation, asserting no panic, leftover directory, or descriptor.

2. **#108: Cancellation prevents the final state and accounting transaction.**  
   [internal/adapterhost/submit.go:33](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah6/internal/adapterhost/submit.go:33)

   When the caller cancels `ctx` during a session, the runner closes/waits for the process, then passes that same cancelled context into `finish`. The event-store transaction cannot complete. The dead adapter’s attempt remains `running` with publication `open`; collected usage and refusals are not recorded. Cancellation during the first fence can also return directly without finalization.

   **Fix:** Once `attempt.started` commits, use a bounded controller-owned cleanup context for finalization, independent of caller cancellation. Route every post-start exit through it. Test cancellation during describe, prepare, run, and immediately before submission; assert closed publication and durable collected usage.

3. **#108: Declared final-output handles are discarded, allowing incomplete admission.**  
   [internal/adapterhost/attempt.go:193](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah6/internal/adapterhost/attempt.go:193)

   The notification callback retains only usage. For example, a schema-valid `error.raw_excerpt` naming a same-attempt symlink or missing file is ignored. A subsequent valid result can still be published and submitted, with no refusal and `Untrustworthy == false`. Design 09 explicitly includes handles declared by run events among final outputs.

   **Fix:** Collect adapter-produced final handles, deduplicate them, and validate all after process-tree exit before publishing the admitted output set. Check controller-delivered handles against delivery records separately. If those notifications remain outside this increment’s scope, fail closed on receiving them rather than silently accepting the run. Documenting the omission does not satisfy this admission contract.

**Medium — nonblocking**

4. **#107: Measurement projection can silently lower usage through an ID collision/reuse.**  
   [internal/capacity/ledger/record.go:51](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah6/internal/capacity/ledger/record.go:51)

   `tx.Put(call+"/"+measurementID)` overwrites an earlier measurement. Two recorded deltas with the same measurement ID and sequence, first 100 then 50, leave only 50 available to `Reconcile`. Reconciliation over both events would retain 100 and flag inconsistency. Rebuilding reproduces the overwrite, so the rebuild test does not detect this semantic loss.

   **Fix:** Make measurement IDs immutable: identical replay is harmless; conflicting reuse must be rejected. Alternatively retain every event and let the existing reconciliation rules resolve duplicates. Test identical and conflicting duplicates, with both reused and distinct measurement IDs.

5. **#108: A second-fence refusal leaves a published blob.**  
   [internal/adapterhost/attempt.go:210](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah6/internal/adapterhost/attempt.go:210)

   `ingest.Ingest` calls `blobstore.Put`, which renames/fsyncs the blob before `finish` checks the second fence. Stop the attempt at the existing `"ingested"` hook: submission is correctly refused, but the blob remains in CAS. The stale-attempt test never checks this.

   This does **not** admit a stale result into the event log; it violates the stronger “nothing published on refusal” claim and 09’s publication ordering.

   **Fix:** Stage the verified copy, then check the fence and publish before appending the result event inside the writer operation. Discard staging on refusal. Separately document that filesystem publication cannot be rolled back atomically with SQLite on arbitrary transaction failure.

6. **#108: Invalid paths become protocol errors without output-refusal records.**  
   [internal/adapterhost/session/methods.go:140](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah6/internal/adapterhost/session/methods.go:140)

   A result handle such as `../patch.diff` fails schema decoding before reaching ingestion. The host records loss, but no `attempt.output_refused{check:path}`; it also cannot give a stale fence precedence. The refusal schema deliberately permits recording invalid handle names, so this is an unreachable intended refusal path.

   **Fix:** Preserve a bounded, structurally decoded output declaration for refusal classification, while keeping strict validation for admission. Test stale-plus-invalid-path and foreign-plus-invalid-path precedence, as well as ordinary path refusal.

7. **#108: A foreign result handle discards otherwise valid final accounting.**  
   [internal/adapterhost/attempt.go:154](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah6/internal/adapterhost/attempt.go:154)

   The session successfully decodes the result, then rejects its foreign handle. The host consequently calls `finish` with a nil result and drops `usage_final`. A final substantially larger than the deltas is lost because of an output failure. Keeping the call uncertain avoids claiming settlement, but does not preserve the available measurement.

   **Fix:** Expose schema-valid accounting independently of output admission. Record the final while refusing the handle. Test a foreign result whose final exceeds its deltas.

8. **#108: Ingestion errors can expose adapter-controlled handle names.**  
   [internal/adapterhost/attempt.go:217](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah6/internal/adapterhost/attempt.go:217)

   Non-`Unsafe` ingestion errors are returned unchanged. The merged ingester includes the handle name in `stat` diagnostics, including `ErrUnsupported` when a required statx field disappears. Thus the session’s fixed-text error guarantee does not extend through `Host.Run`.

   **Fix:** Return fixed-text host error wrappers that preserve error classification without rendering the underlying adapter-derived text. Add sentinel-secret assertions for postlaunch capability and I/O failures.

**Contract decisions and verified behavior**

- **Keep `result` on the existing lease-event envelope.** That envelope already represents attempt transitions, and the event’s subject is the attempt. Carrying the admitted result directly makes the transition self-contained; a companion record would introduce an unnecessary consistency relationship.
- **#107’s publish-before-reference prerequisite is enforced during the writer transaction.** Registering `"blob"` in `BlobFields` reaches the nested result digest; event append checks its presence before acceptance. Physical blob creation happens earlier—distinct from transactional event acceptance.
- **`start_refused` transitions are correct:** granted → releasing, no attempt; released subsequently returns reservations through the existing capacity projector. The new test checks states, but does not exercise actual capacity return.
- **Refusal recording and `Untrustworthy` are sound for refusals that reach the writer.** Refusals do not transition attempts; the count is a replayable projection. Usage recording is unfenced, and distinct-ID measurements retain the existing ledger’s deduplication behavior.
- **Both seams are appropriate.** `SupportedIn` probes the actual exchange directory and closes/removes its probe resources. `Foreign()` preserves the rejected handle without inserting it into session error strings.
- **`lost` is reasonable for a broken session, but it is not terminal in 05.** It closes publication and still requires sealing/completion and lease settlement. Using it for “adapter exited without an admissible result” is a defensible intermediate state; document that interpretation rather than presenting an unsafe output as an actual agent disconnect. The refusal event should remain the authoritative explanation.
- The runner correctly places the capability check before `attempt.started`, launches only after that transaction commits, and waits before ingestion. `ErrUnverified` prevents ingestion. The second fence and `result_submitted` share a writer transaction. These guarantees do not cover the gaps above.

**Test coverage and removal sensitivity**

The tests do **not** establish that every check is independently necessary.

| Area | Assessment and missing test |
|---|---|
| First fence | Removing it can leave the stale integration test green: the second fence still refuses. Assert no ingestion/publication occurred at the first fence; combine stale state with unsafe/foreign handles. |
| Second fence | The existing `"ingested"` case detects losing refusal behavior, but misses the already-published blob. Assert CAS and temporary-store contents. |
| Process-tree exit | Lower-level process tests are strong. Add a host-level child that keeps writing after the run/shutdown reply; the current replacement scenario does not independently prove waiting for descendants. |
| File checks | Integration covers symlink, FIFO, hard link, digest and foreign handle. `unsafe-replaced` exercises **digest**, not post-copy replacement detection. Add host cases for path, size bounds by kind, unreadable/missing files, and actual concurrent replacement. |
| Mutation evidence | The merged ingester explicitly demonstrates hard-link-check sensitivity. No equivalent proof exists for every runner check. I did not modify code to run additional mutations. |
| Lifecycle/resources | Add spawn/describe/prepare/protocol/heartbeat failures, cancellation, unverified exit, setup failures, and cleanup assertions on every host exit. Existing lower-level FD tests do not cover exchange cleanup. |
| Records | Add start-refusal capacity return, refusal after a genuinely terminal attempt, conflicting measurement replay, and exact submitted-result payload assertions. |

**Size:** I would **not split #108 solely for being 439 lines**; its runner and submission flow belong together. Keep these lifecycle fixes together. Separate substantial live-tool handling into another PR, with unsupported paths explicitly refused meanwhile.

### Lead notes on round 1 (applied)

- **`result` stays on the lease-event envelope**, as the review agrees: `attempt.result_submitted` carries the admitted
  result itself; no companion record.
- **Medium 4 (#107, measurement ids):** a measurement id is immutable. An identical replay changes nothing. Another
  report under a used id (other figures, or another call) is refused, never written over the first. A second
  projection, keyed by the id alone, sees reuse across calls. Distinct ids for one `(call, sequence)` are kept and
  reconciled as before (the larger kept, flagged). Tests cover all four cases.
- **Missing #107 tests added:** a refused start returning its reservations at `released` (capacity projector), a
  refusal after a completed attempt, and the exact `attempt.result_submitted` payload.
- **`attempt.lost` for "exited without an admissible result"** is documented in 05 and 09 as intermediate, not
  terminal: it closes publication, and the attempt still seals and completes. The refusal events are the
  authoritative explanation.
- **High 1 (#108, exchange setup):** the cleanup holds the allocated exchange itself, not a named return. A removal
  failure is reported, with a fixed text. Each setup step is fault-injected; the tests assert no panic, no leftover
  directory and no leaked descriptor.
- **High 2 (#108, cancellation):** after `attempt.started` commits, every exit goes through one finalisation. It runs
  under a bounded controller-owned context (`context.WithoutCancel` plus `FinalizeTimeout`), and shutdown has a
  bounded context of its own. Tests cancel before describe, before prepare, during the run and just before the
  submission. Each asserts closed publication and durable usage.
- **High 3 (#108, declared outputs):** every final output the run's events declare (`error.raw_excerpt`), deduplicated,
  is checked after process-tree exit with the result's handle. One refusal blocks the submission. This increment
  serves no mediated tool, so a `tool.request`, or a `tool.result` naming a delivered handle (no delivery record can
  match it yet), refuses the run (fail closed).
- **Medium 5 (#108, staging):** the verified copy is staged in the blob store's `tmp/`. It is published inside the
  writer operation only after the second fence passes, and discarded on any refusal. 09 states that publication cannot
  roll back with the transaction. Only the result's copy is published; the other declared outputs are verified and
  discarded, since no record references them yet. This is a separate stacked PR (see sizes).
- **Medium 6 (#108, invalid paths):** the session keeps a bounded, structurally decoded declaration of a refused
  result. The host classifies its handle by fence, foreign handle and path, in that order, and admission stays strict.
- **Medium 7 (#108, foreign result accounting):** a schema-valid result refused for a foreign handle still has its
  `usage_final` recorded.
- **Medium 8 (#108, error texts):** host faults after launch return fixed-text errors (`ErrIngest`, `ErrRecord`,
  `ErrExchange`). They keep the `ingest.ErrUnsupported` and context classifications. Sentinel-secret tests cover
  postlaunch capability and I/O faults.
- **Missing #108 tests added:** first-fence stale combined with an unsafe output (nothing read); CAS and temp-store
  assertions for both fences; a host-level descendant that would write after the shutdown reply (nothing writes once
  the tree is seen to exit); path, size-by-kind and unreadable host cases; a missing event-declared excerpt.

**High — #108: the finalization deadline expires during the adapter run.**  
[internal/adapterhost/attempt.go:172](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah6s/internal/adapterhost/attempt.go:172)

`FinalizeTimeout` starts before `session.Open` and `converse`. A run lasting over two minutes therefore reaches finalization with an expired context, regardless of its permitted process deadline.

I reproduced this with a heartbeat-producing adapter running for 121 seconds, then cancelled upon receiving its usage event. The result was **`running`, publication `open`, zero durable measurements**, and `ErrRecord`. Thus round-1 High 2 remains unresolved.

**Fix:** Start the bounded finalization context when finalization begins, after conversation and process cleanup; create it separately for spawn failure. Add a long-run cancellation regression asserting closed publication and durable usage.

**Medium — #108: shutdown protocol errors still permit submission and publication.**  
[internal/adapterhost/attempt.go:181](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah6s/internal/adapterhost/attempt.go:181)

**Fix:** Preserve shutdown/session failures through finalization, refuse submission on protocol failure, and retain valid collected accounting. Add a valid-result-then-malformed-shutdown regression.

**Medium — #109: staged-copy deletion failures are silently discarded.**  
[internal/adapterhost/attempt.go:268](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah6s/internal/adapterhost/attempt.go:268)

### Lead notes on round 2 (applied)

- **#107** is GO and merges as it is; these notes are carried on #108's branch.
- **High (#108, the finalisation deadline):** the finalisation's bounded context is created when finalisation begins.
  For a failed spawn that is right at the failure; otherwise it is after the conversation, the shutdown and the wait for
  the process tree. It is never created before `session.Open` or the conversation. `finalizeTimeout` is a test seam.
  The other contexts were audited:
  - the conversation uses the caller's context, on purpose;
  - the shutdown's 5 s bound starts at the shutdown;
  - the start and start-refusal commands precede the attempt and use the caller's context;
  - the retry without a submission reuses the finalisation context.

  Regression: a heartbeating run four times longer than the finalisation timeout, cancelled late, ends `lost` with
  publication closed and its usage durable. On the round-1 code it fails with `ErrRecord` and the attempt left running.
- **Medium (#108, shutdown failures):** a failed shutdown, or a session end other than the clean close after shutdown,
  is kept through finalisation. It refuses the submission, so nothing is published, and the result's valid accounting
  (its deltas and final) is still recorded. The host waits for the session's end (`Session.Done`) once the tree is
  gone, so a line after the shutdown reply is seen too. Regression: a valid result, then a schema-invalid shutdown
  reply, ends `lost` with nothing submitted or published and both measurements recorded. On the round-1 code it
  submitted.
- **Medium (#109, discard failures):** failures to remove staged copies are aggregated into a fixed-text host cleanup
  error (`ErrCleanup`). A copy whose removal failed stays tracked. Test: `tmp/` made unwritable before a second-fence
  refusal, so nothing is published, the leftover is reported, and the run returns `ErrCleanup`.
- **Fail-closed table:** added a malformed shutdown reply and a run outlasting the finalisation timeout, cancelled late,
  on #108, and a staged-copy removal failure on #109.
