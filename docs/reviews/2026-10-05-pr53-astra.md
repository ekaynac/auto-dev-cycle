# PR #53 (lease and attempt events): Astra review

## Review of #53 (Astra, 2026-10-05)

Verdict: GO with changes

No Critical or High findings. The contract supports the deferred wiring; the following changes are nonblocking.

- **Medium — Document versioning for the lease changed by `attempt.started`.** `schemas/records/lease-event.json:5,22`: the attempt subject is reasonable, but `internal/eventstore/writer.go:159` computes versions from events whose **subject** matches. Starting an attempt therefore changes the lease without advancing `SubjectVersion(leaseID)`. A command expecting the granted lease’s version can pass that check after activation. **Fix:** specify that wiring tracks and compares a projection revision or digest for every affected record, including both records in `attempt.started`. Test rejection of a lease command carrying its pre-start expectation.

- **Low — The seal fixture is not a valid AttemptRecord.** `internal/lease/events_test.go:135`: the published blob contains only `attempt`; mandatory checkpoint fields are absent. The test correctly proves publish-before-reference, but does not prove that the published object is an AttemptRecord. **Fix:** use a complete, schema-validated fixture and explicitly document that blob presence does not validate its contents or identity.

The 19 registered kinds match note 05. Payloads retain the required transition data: holds and signals, restore receipts, settlement calls/liabilities/publication, stop/loss reasons, completion outcome/reason, and reciprocal supersession references. Revocation and restore-failure reasons are required separately because their resulting lease records do not retain them. The nullable-record rules correctly distinguish lease events, attempt events, and the combined start.

Resulting records are a sound choice for rebuilding projections by folding events. They require these explicit wiring guarantees before commands can write them:

- **Bind and derive:** require `event.Kind == transition + "/v1"` and the correct record ID as subject. Check lease/attempt/unit relationships. Derive the complete resulting records from current projections and authorized command inputs; never validate by applying the transition to a caller-supplied “current” record. The shared schema intentionally does not bind a transition to its resulting state.
- **Enforce transaction boundaries:** stop/close publication before active-lease revocation, preemption or expiry; require terminal-attempt completion where specified. Validate and write both supersession events, reciprocal IDs and the controller-issued increasing token in one transaction. Publish the accepted draft as a controller action alongside settlement, only from `settling_verified`.
- **Preserve companion facts:** `attempt.result_submitted` does not identify the submitted result. Its accepted draft must be durably recorded by a companion result event so recovery can identify it. Likewise, reservations, ledger changes and publication must be reconstructible from logged facts.
- **Validate checkpoints:** `BlobFields: ["checkpoint"]` correctly finds the nested digest, including on later snapshots retaining it. Wiring must additionally validate AttemptRecord contents, bind its attempt/token/base/project/task/contract, and ensure its referenced blobs are published.
- **Keep replay independent:** project both records on start and replay supersession events individually. Command-level pairing checks must not make the projector depend on receiving the entire transaction together.

These checks are feasible with the shapes and companion records; no blocking schema redesign is needed.

Validation: `make ci` passed, as did the sandboxed `go test -count=1 -run 'Event|Seal' ./internal/lease`. Local CI skipped unavailable shellcheck. Checkout remains unchanged at `0549407`.
