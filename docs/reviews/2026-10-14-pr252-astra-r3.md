1. **Medium — Process-group signalling can race with reaping and PID reuse.**  
   `internal/accept/drain.go:51`, `:57`

   `cmd.Run()` can reap git before its output-copy goroutines finish. An overflow callback can therefore execute `syscall.Kill(-cmd.Process.Pid, SIGKILL)` after the original group has disappeared. If that numeric ID has been reused for another process group, the signal can kill unrelated processes owned by the controller user. Both streams can independently invoke this callback. This is a narrow lifecycle race, not a demonstrated candidate-controlled exploit. The ordering follows [Go’s `Cmd.Wait` implementation](https://go.dev/src/os/exec/exec.go).

   **Fix:** coordinate draining, signalling, and reaping so the group leader remains unreaped until all possible group-signal callbacks finish, while retaining a deadline for inherited pipes. Deduplicate termination requests. A `ProcessState` check or `sync.Once` alone does not close the reuse race.
