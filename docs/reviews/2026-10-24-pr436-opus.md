### Answers to the six questions

**1. Each field, from its event.**

| Field | Event, then fold | The read (`benchResults`, `taskbench.go:138`) |
|---|---|---|
| `id`, `outcome`, `reason`, `attempt` | `result.recorded` → `graph_results[id]` (`ResultRecorded`) and `graph_task_results[task/id]` (`lifecycle.go:205`) | `graph.ResultsOf` → `taskResults`: the result's own fields, no derivation |
| `selected` | `result.selected` → the node's `State.Result` | `n.State.Result == r.Result.ID`, from the node record `TaskNodes` read |

- **`selected` is exactly the node's own selected result.**
  - A reused node's `State.Result` is its holder's result (`reuse.go:104`). That result is indexed under the holder, so the reused node lists no result of its own as selected. `TestResultsOfTheTask` shows none for `b`. The holder lists it as selected.
  - After a release or a renewal, `State.Result` is nil (`reuse.go:131`, `renew.go:122`), so earlier results are listed as unselected.
- **`attempt` is null exactly when the result was recorded by `graph.Commit` (no attempt), not by `graph.CommitAttempt`.** In adcd, that is:
  - the controller's own results (plan, accept, gate);
  - `abandon`;
  - **and a build's or review's result whose attempt did not submit**: the host lost it (`agent_disconnect`), and `runner.record` then commits with no attempt (`run.go:1186`).

  So a null `attempt` does not mean no attempt ran (L1).
- **The mapper:** `bench record` only checks the field (`selectedAgrees`). It records nothing from it.

**2. The five new reads are checked against their sources.** The table's rows 38–42 hold:
- **The key range:** `graph_task_results`, prefix the authorised task, at most `maxTaskResults` keys.
- **The result:** each result is size-checked, and its record's `Result.ID` must equal the key's id (new: `ErrIndexDamaged`).
- **The node:** the result's node is size-checked, and its record must be that node's under its own id (new) and of the task (`ErrIndexDamaged`).
- **What is used:** `benchOf` uses only the results of nodes that `TaskNodes` returned, whose project `taskRead` has already checked. Results of any other node are ignored.
- **The attempt:** each non-null `attempt` must be in the node's unit chain (`lease.AttemptsOn`, checked hop by hop), else `damagef`. A healthy result always passes, because:
  - `attemptBound` requires the attempt's unit to be the node's;
  - `startNext` / `SupersedeAttempt` keep every attempt of a unit in one chain (`wiring.go:784-812`).
- **Conclusion:** the field cannot carry another task's or project's result or attempt.

**4. The mapper: right for every shape I could build.**

### Low

**L1. "Null for a result the controller recorded with no attempt" reads as "no attempt ran". OBLIGATION (state it).** `schemas/api/task.json` (`BenchResult.attempt`)
- **The two meanings:** a lost build or review attempt's result is also recorded with no attempt, and its reason then comes from the exit map.
- **Fix:** say so in the description, so D1 and later readers do not take `attempt: null` as "the controller's own node".

**L2. The gate row does not pin `selected`. OBLIGATION (test).** `internal/daemon/gate_test.go:298`
- **Cause:** it asserts `Selected == (v.State.Result == got[0].Result.ID)`, which holds whatever the selection rule is.
- **Fix:** assert `Selected == false` (could_not_run is never selected), and the same for `TestAProviderRefusalHoldsTheBuild`'s results. These are the facts D1 relies on.

- **Size:** `results[]` adds about 150 bytes per result to the one-task read's 1 MiB bound (#432's stated per-task bound). That is unlikely to matter at (a), but state it beside that bound.
