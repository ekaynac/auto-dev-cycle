### High

**H1. A found zero (or low) answer from the provider releases a call below the gateway's own counts. The probe confirms it.** (`internal/modelcall/reconcile.go:162-170`, `reconciled` at :175-205; `internal/capacity/ledger/ledger.go:287-291`, `trusted` at :130)
- **Scenario.** The gateway forwards a response with 3200 bytes of content and in-band usage of 300/200. It records `gateway_count` 300/200. The route's usage query goes to the same upstream, and it answers `found: true` with zero. `Ended` records a `provider_reconciliation` of 0/0. The effect becomes `completed (the provider's usage is recorded)`. The lease settles the call with **liable 0**. The control run is the same call with no query: it stays `uncertain` with **liable 500**.
- **Why it matters.** `ledger.Reconcile` lets the reconciliation replace every other report, including the gateway's byte-based bounds. Nothing in the reconciler compares the answer with the counts.
  - So the one report a hostile upstream fully controls now lowers the charge below what the gateway measured itself. That is the bypass #226 entry 69 closed for the adapter's final ("relabelling upstream counters is not enough against a hostile upstream").
  - It also contradicts Q8's "never dropped and never assumed zero".
  - It inverts P11b's own design note in `internal/gateway/count.go` ("an upstream under-reporting its usage past these floors is beyond any count: the provider's reconciliation (P20)"). P20 was meant to catch under-reporting, and here it enables it.
  - An honest provider can cause the same loss: usage APIs lag, so an early answer can omit the last requests.
- **Fix.** A reconciliation may replace adapter reports and unobserved floors, but never observed gateway counts.
  - In `trusted`/`StandingOf`, settle a reconciled call at `maxOf(reconciliation, sum of gateway_count at observed sequences)`, and flag `inconsistent_usage` when the provider is lower. Floors still release (images, 4xx/429 without usage, unread usage), which keeps the PR's stated purpose.
  - The minimum alternative is in `reconciled()`: refuse to record an answer that does not `cover` the observed counts. Keep the effect `still_uncertain` with a new observation.
  - Add an F test: a found zero after a counted 300/200 keeps a liability at or above the count. Add a matching mutation. Today none of the 8 mutations covers this.

**H2. Late usage is swallowed for good once the answer is recorded. `Serving` only covers requests of the same, live gateway. The probe confirms it.** (`internal/modelcall/reconcile.go:157`, :199; `internal/gateway/gateway.go:237`; `internal/capacity/ledger/ledger.go:130`)
- **What the probe showed.** I gave the reconciler a `Serving` that does not see the in-flight request, which is what a restarted gateway is.
  - It asked while the upstream still held the request and recorded 10/0.
  - The request's own `gateway_count` (3000/1000) then landed at its floored sequence. It was accepted (entry 59), but the call stays `Settled` at 10/0.
- **Why it can never be corrected.** `trusted` returns at once when `c.Reconciled` is set. `reconciled()` refuses a second reconciliation once the call is settled.
- **Concrete failure (X3 `kill-mid-build`).** After `kill -9`, the effect is marked `uncertain` and the new gateway's `Serving` is false. Meanwhile the stub still holds A1's request at its barrier, which the driver releases only after `attempt.output_refused`. P21 step 4 settles the call by the query before that release. The provider's answer leaves out the held request, so X3's assertion (a) fails, "Σ settled = served-usage log" (or charges are silently lost).
- **Why the guard does not help after a crash.** The fence and the `Serving` counter are correct inside one process: `serve++` precedes the floor, and the count is durable before the deferred release. After a crash or restart, though, "no request served" says nothing about the upstream.
- **Fix.**
  - (a) Do H1's max over observed counts in the ledger. A count that lands after the reconciliation then raises the figure instead of vanishing.
  - (b) For a floor with no count, do not query until a durable condition holds: the floor is older than a pinned upstream request deadline. Note that the gateway client has no overall request timeout today, only dial and TLS, so add one. Alternatively, make the `Query` contract per request: pass the call's floored sequences and upstream request ids, and return `found` only when the provider accounts for each as finished.
  - (c) Let a later reconciliation supersede an earlier one, so a re-query after the grace can correct upward.
  - If the lead prefers, the floor-only grace in (b) can move to P21 with a #226 entry, but (a) belongs here.

### Medium

**M1. `Ended` can lose the run-end transition.** (`internal/modelcall/reconcile.go:101-103`)
- **Scenario.** A sweep's `Reconcile` holds the claim on a still-`pending` effect, briefly, during its `View`. The run-end hook's `Ended` gets `ErrRunning` and does nothing. The effect stays `pending` until the next restart's `MarkPendingUncertain`, unless P22a retries.
- **Two Reconciler instances.** Two instances, for example one built by P21 and one by the run-end hook, both query. The store stops a double record (I checked: under M1 only one reconciliation is recorded), but the provider is asked twice.
- **Assessment.** The claim is otherwise sound: it lives in memory, a crash releases it, and the deferred release runs on a panic. The `flock` keeps one adcd per store, and the store refuses a transition out of a settled state.
- **Fix.** Make `Ended` wait for the running runner (a per-call mutex) instead of failing, keep `ErrRunning` for `Reconcile` only, and state "one Reconciler per store" as a P22a requirement.

**M2. The standing read is stale.** (`internal/modelcall/reconcile.go:117`, :124, :139)
- **Stale settlement.** `st` is read before the transition. A floor that commits between the `View` and `record(observed)` leaves the effect `completed (the call's usage settles)` while the call is now floored and unsettled. The liability is kept, but nothing calls `Reconcile` again.
- **Mislabelled observation.** With `st` stale and unsettled, `query()` asks anyway. `reconciled()` may then record nothing because the call is already settled, yet the observation says `ObservedQueried`.
- **Fix.** Recheck the standing in the transition's transaction (a `SubmitApplied` that loads the standing and applies the transition). Have `reconciled()` report whether it recorded anything.

**L3. A hostile adapter can pin `Serving` true** (`internal/gateway/gateway.go:237`)
- By reading the response slowly, an adapter keeps the call's over-held floors from ever being released.
- It errs on the safe side (the liability is kept), but it is an unbounded hold.
- Bound it with the request deadline from H2(b).

**L4. `Recorder.Count` change: nothing legitimate breaks** (`internal/modelcall/modelcall.go:400-416`)
- These are still accepted:
  - the dial-failure zero count;
  - a "count that stays a floor" at its own sequence;
  - late counts.
- The exemption keys on gateway sources only, so an adapter delta cannot open a sequence.
- A call with no effect fails closed, which is correct: the intent always precedes the floor.
- A restart resets `seq`, but bindings are lost too, so a reused sequence cannot occur.
- Cost is O(n) measurement reads per request, which is acceptable.
