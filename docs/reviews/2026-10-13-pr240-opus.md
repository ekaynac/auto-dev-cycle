## Opus pre-review of #240

Verdict: GO with changes

I found nothing Critical or High. The tests pass at head 78f9276: `go test` over graph, lease, capacity, api, daemon and harness, and `make fixtures-contract`. The new mutation `graph.supersession-admits-running-attempt` turns `unlisted-running-attempt-refused` red. I created the scratch worktree and removed it afterwards.

What holds up under attack:
- **Binding.** Each id is a fixed-length TypeID with the prefix `nod_` or `unt_`, so `UnitOf` and `NodeOf` are a bijection. There is no prefix collision, and no node id parses as another node's unit.
  - `Projector.start` refuses when there is no `Units` binding (fail closed). It also calls `Startable`, which only admits a claimed node, for a first attempt and for a successor.
  - It reads log-derived graph projections. `adcd` folds the lease projector before the graph for each event, so replay gives the same answer.
  - Starting twice is still refused, by the existing current-attempt-per-unit check. A superseded or completed node starts nothing.
- **Supersession.** A successor needs a sealed predecessor, so the only attempt that can be running is the unit's current one. `runningAttempt` therefore derives the complete list.
  - `stoppedAttempts` (`graph/supersede.go:399`) refuses three things: a supersession that leaves that attempt running, a list other than the one attempt this command stopped for preemption, and the same attempt listed twice (through `PreemptedProjection`).
  - Moving away from 13:173 ("the caller names the attempts") is sound. That note text was explicitly temporary, "until M1 binds attempts to nodes".
- **Re-sealing.** It is impossible: the attempt state machine has no transition out of `sealed` on a seal event.
- **Holds read.** The lease hold's project comes from its node, and the `Project` callback re-reads it the same way. A lease on a unit with no node stays installation-wide.
- **Inert.** Nothing is activated before P8b or P22a: no wired action starts an attempt.
- **`soleUnit` in `internal/harness`.** It admits only the harness run's own unit, which is a random id, and binds no project, so no seal is possible. It does not weaken production.
- **#226 entry 4 deferred to P8b.** Acceptable. Hold `id` and `since` belong with the lease placement records that P8b owns, and P8a writes nothing new to `lease.waiting`.

### Medium

1. **The seal reason and "no continuation" are only built, never checked** (`internal/lease/wiring.go:570-592`).
   - `Projector.checkpoint` checks attempt, token, base tree, contract revision, project and task. It does not check `seal.reason`, `pinned`, `failing_tests` or `builder_notes`.
   - So a seal built without `SealMinimal` passes with any reason, with `pinned: true`, or with a continuation payload. L1's "the reason is derived" and "no continuation" therefore hold only inside the `SealMinimal` builder.
   - **Fix:** in `changeAttempt` for `Sealed`, compute `SealReason(prev)` and refuse unless `r.Seal.Reason` matches. For M1, also refuse unless `!r.Pinned && len(r.FailingTests)==0 && r.BuilderNotes==nil`. Add a named mutation or a test case for a forged reason.
   - Note that the checkpoint check is skipped on replay. That predates this PR, but say so in the decisions block.
2. **`attemptBound` checks where an attempt ran, not whether its result may be published** (`internal/graph/content.go:94`, `units.go:attemptBound`).
   - A `result.recorded` naming an attempt of the same node that was stopped, lost or superseded is admitted by the fold. That happens on replay too.
   - A result with no `attempt` skips the binding entirely. Evidence nodes are the only kind that must name one, and `could_not_run` is exempt even there.
   - #226 entry 3 as written is satisfied. But under I8, the fold should also require that the attempt submitted its result (`finishing`, or sealed/completed from `finishing`).
   - **Fix:** either add that status check now, or register a #226 entry to require it, and to require `attempt` on build/review/evidence results, owned by P8b/P14, before those actions are wired.
3. **#226 entry 13 asked for a project-isolation test; this PR does not add one** (`internal/daemon/graph_test.go:~93`).
   - `TestHoldsList` only reads with the operator's every-project reveal.
   - **Fix:** add a reader scoped to another project and assert that it does not see the bound lease hold, while a reader scoped to the node's project does. Otherwise keep entry 13 open and do not mark it closed.

Record that P8b's `match` must check the unit's node and project before reserving. This fits #226 entry 39.
