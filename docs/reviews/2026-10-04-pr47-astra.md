# PR #47 (lease-family records): Astra reviews

## Review of #47 (Astra, 2026-10-04)

Verdict: NO-GO

1. **High — `restore_failed` cannot carry its required hold.**  
   **Location:** [schemas/records/lease.json:99](schemas/records/lease.json#L99).  
   This conditional requires `hold: null` everywhere except `waiting`. Note 05 explicitly requires `evidence_restore_pending` in `restore_failed`; note 02 requires its concrete signal instance. A validation probe confirmed that a restore-failed lease carrying this hold is rejected. Part 2 cannot faithfully project that state without changing this contract.  
   **Fix:** Permit and require the restore hold in `restore_failed`, constrain its code to `evidence_restore_pending`, and retain its signal instance. Clear it when restore is verified. Add positive and negative tests for this state.

2. **Medium — Evidence targets are not constrained to exclusive capacity.**  
   **Location:** [schemas/records/resource-group.json:34](schemas/records/resource-group.json#L34).  
   The evidence-target conditional enforces only the release rule. A target with two slots passes validation and generated-type round-tripping; the positive fixture even uses unknown capacity. Notes 12/13 require capacity 1 to guarantee exclusive use.  
   **Fix:** Require evidence targets to have known capacity of one slot. If nested conditions exceed the generator’s grammar, explicitly assign this invariant to a tested Go semantic validator and correct the positive fixture.

3. **Medium — Attempt reasons permit impossible projected states.**  
   **Location:** [schemas/records/attempt.json:47](schemas/records/attempt.json#L47).  
   The conditions require reasons in `stopping` and `lost` but never prohibit contradictory reasons. Probes accepted a `running/open` attempt carrying both `stop_reason: revoke` and `lost_reason: controller_restart`, and a sealed attempt carrying both. No path through note 05’s state machine produces these records. The publication/status guard itself is correct.  
   **Fix:** Require both reasons to be null in `running` and `finishing`; prohibit the opposite reason in `stopping` and `lost`; permit at most one retained reason after sealing. Preserve valid historical reasons through terminal states.

4. **Medium — Placement checks omit the non-empty-detail invariant.**  
   **Location:** [schemas/records/lease.json:113](schemas/records/lease.json#L113).  
   A check with `outcome: could_not_run`, `reason: quota_unknown`, and `detail: ""` passes validation, decoding and encoding. Note 02 requires non-empty detail for every non-`empty` result.  
   **Fix:** Add the supported outcome-dependent `minLength: 1` conditional and a regression test. Explicitly require the forthcoming Go placement validator to check outcome/reason compatibility through the vocabulary.

The other contract choices are sound: bounded integer amounts, explicit money/time units, a digest referencing the sealed AttemptRecord, projected records with events deferred, and settlement references without duplicated amounts. AttemptRecord contains note 05’s fields. UsageMeasurement provides the identities and distinctions needed for deduplication, stale-attempt accounting and reconciliation; enforcing that usage never decreases without reconciliation properly belongs to the ledger. The stated Go responsibilities remain enforceable from these shapes.
