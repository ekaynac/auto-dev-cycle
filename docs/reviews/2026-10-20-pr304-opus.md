### Medium

**M1: `base_remote` commits a partial tree when a copy fails.** `scripts/lib/base-remote.sh:19-21`
- **Why:** the three `cp -R` calls are not checked. The commit only runs inside a `( … )` that inherits the caller's errexit. The natural call forms, `tree="$(base_remote …)"` (bash command substitution does not inherit `-e`) and `base_remote … || die`, both turn errexit off.
- **Input:** a `repo/` holding `b.txt` at mode 000, run as `set -euo pipefail; tree="$(base_remote repo task "" remote.git)" || …`. `cp` prints "Permission denied", yet `base_remote` returns 0 and prints tree `08585692…`, whose `main` holds only `a.txt`.
- **Fix:**
  - `cp -R … || { rm -rf "$work"; return 1; }` on each of the three copies, or move the copies into the subshell and start it with `set -e`;
  - run `rm -rf "$work"` on every path;
  - add a `TestBaseRemote` row with an unreadable file that expects a non-zero exit.

**M2: `scan` passes silently when `SECRETS_ROOT` is missing.** `scripts/lib/secrets.sh:44`
- **Why:** with `pipefail`, `grep -r` exits 2 on a missing root, the second `grep` exits 1, and `|| true` hides both. `leaks` is empty, so the scan passes. The old code always used `/tmp`, which always exists in the sandbox, so this is new surface. It matters for P24b's driver, which sets the root itself and may not run under `env -i`.
- **Input:** `known "$S"; SECRETS_ROOT=/tmp/typo scan "" "$S"` returns 0, after one "No such file or directory" per form, even though a leak sits under the intended root.
- **Fix:**
  - in `scan`, `[[ -d ${SECRETS_ROOT:-/tmp} ]] || die "no scan root"`, and treat a `grep` exit of 2 as a failure rather than `|| true`;
  - better, take the roots as arguments (`scan OWN SECRET DIR…`, as the P24 plan's `secrets_scan DIR…` did) instead of an inherited environment variable, since the driver must scan the state, the logs and the stub's log.

**M3: the usage log does not show what was actually served.** `fixtures/m1/stub-provider/server.mjs:57,104-108,86-89`
- **Why:** the PR and the plan promise "every served usage" in the log, for exact charges. But:
  - (a) `usage` defaults to 100/20 for any reply form, a non-2xx one included. It is then logged as served and answered by the usage query, though the adapter drops a non-2xx body without reading its usage.
  - (b) a `partial` reply logs `kind: usage` before it cuts the body, so the log cannot tell "delivered in the body" from "available only through the query".
  - (c) `GET /v1/usage/{id}` itself is never logged, so a charge the gateway took from the query leaves no trace.
- **Input:** `{"say": "x", "status": 402}` serves usage `{100, 20}`, logs it as served, and `GET /v1/usage/req-1` answers 200. Likewise `{"say": "cut", "partial": 5}`: the client gets `UND_ERR_SOCKET`, yet the log and the query both report usage.
  - This would distort `fault-provider-402`, `-429` and `fault-usage-no-delta`'s accounting expectations.
- **Fix:**
  - default `usage` to null when `status` is not 2xx;
  - log `{kind: "usage", request_id, delivered: "body" | "cut"}`;
  - log each usage query: `{kind: "usage_query", request_id, status}`.

**M4: a per-attempt "persistent" builder cannot be written.** `fixtures/m1/stub-provider/server.mjs:94-97`
- **Why:**
  - Replies are indexed by a per-model counter global to the server, and a script is either `persistent` (one reply) or a finite list.
  - A builder needs at least 2 calls per attempt: a `write` and then a `say`, because the adapter only ends its loop on a reply with no tool call (`adapter.ts:260`).
  - §2.6's `fault-lying-runner` ("in every round (persistent)"), `fault-protected-path`, `fault-test-deletion` and `fault-provider-402`/`-429` ("after one applied edit (persistent)") must therefore be unrolled for the exact number of attempts and rounds. One unexpected extra attempt shifts every later reply, or reaches the 500 at the end of the list, and the case fails for the wrong reason.
- **Input:** `{"replies": [write, 402]}` with rails 2/3/2: attempt 2 gets the end-of-list 500, not `write`.
- **Fix:** index a `turns: [REPLY…]` script by the request's conversation position (the number of `assistant` messages in `doc.messages`), so each attempt replays the same sequence. Alternatively add `cycle: [REPLY…]`. Add a test with two simulated attempts.

**M5: misspelt reply keys are silently ignored.** `fixtures/m1/stub-provider/server.mjs:44-60`
- **Why:** `body()` falls through to `say ?? ""`, so a typo turns a fault into a plain reply. P24b adds about 15 fault scenarios.
- **Input:** `{"stauts": 400}` or `{"stall": 150}` serves 200 with empty content. The builder ends with an empty patch, and the case fails or passes on `empty/completed_clean` rather than on the fault.
- **Fix:** in `start`, check every script and reply against an allowlist of keys (`write`, `delete`, `say`, `decision`, `body`, `usage`, `status`, `stall_ms`, `trickle_ms`, `partial`, `barrier`), check the exactly-one-form rule and `name`, and refuse to start otherwise. Add a test row.

### Low

**L1: loopback is not enforced.** `fixtures/m1/stub-provider/server.mjs:127-129`
- **Input:** `--listen 0.0.0.0:0` serves on every interface. `--listen :0` also serves (its host is empty) and prints `http://:45051/v1`, which is not a usable base URL. M9 survives.
- **Fix:**
  - accept only `127.0.0.1`, `::1` or `localhost` as the host, or a socket path;
  - unlink a stale socket before listening;
  - assert `base` starts with `http://127.0.0.1:` in a test.

**L2: the log has no bound.** `fixtures/m1/stub-provider/server.mjs:78`
- **Why:** each request body is logged in full, up to 8 MiB. The adapter resends the whole history every turn, so the log grows quadratically with the number of turns.
- **Fix:** keep a total byte cap. Once past it, refuse further requests with a 500 and log a `log_full` entry. Do not truncate, because the canary check needs whole bodies. Also add a test of the 8 MiB refusal, since M10 survives.

**L3: the fault timings are not pinned by tests.** `fixtures/m1/stub-provider/test/server.test.mjs:71-95`
- **Why:** M7, M8 and M11 all survive. The test for `trickle` checks only the total time (≥ 100 ms), the test for `partial` only that the JSON fails to parse, and the test for `stall` only the delay. `fault-call-stop` needs bytes to keep arriving (so there is no idle cut), and `fault-idle-cut` needs nothing sent before the stall.
- **Fix:**
  - use a raw `http.request` and assert several `data` events for `trickle`;
  - assert a socket reset (`ECONNRESET` or `UND_ERR_SOCKET`) for `partial`;
  - assert that no response headers arrive before `stall_ms` elapses.

**L4: §2.6's `fault-usage-duplicate` cannot be reached through `http-chat`.** Not this PR's code: `adapters/http-chat/src/adapter.ts:207,238`
- **Why:** the adapter uses `stream: false` and numbers the usage sequence itself (`usages.length`), so no stub reply can report "equal deltas at two sequences" or "one sequence twice".
- **Fix:** P24b should state this. Either re-express the case at the gateway level, or defer it, as the plan already does for the py-mini-specific cases.

**L5: `TestBaseRemote` does not check where `visible/` files land.** `internal/fixtures/baseremote_test.go:63-66`
- **Why:** it only asserts the tree differs from `base_tree`. P1b, which copies `visible/` nested instead of at its path, survives. The PR description says "each file landing at its path".
- **Fix:** assert `git show main:<path>` for one of `go-mini-failing-then-green-1`'s `visible/` files, as the overlay row already does with `conftest.go`.

**L6: the no-go scenario is loaded by no test.** `fixtures/m1/stub-provider/scenarios/go-mini-feature-1-no-go.json`
- **Why:** its builder part duplicates `go-mini-feature-1.json` (byte-equal today). A drift or a schema-invalid finding would surface only in P24b.
- **Fix:**
  - have the http-chat row loop over both scenarios, asserting a `no_go` decision with 1 finding;
  - or derive the no-go scenario's builder part from the go scenario.

**L7: `base_remote` passes the caller's `GIT_*` variables on to git.** `scripts/lib/base-remote.sh:22-29`
- **Why:** `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` and `GIT_OBJECT_DIRECTORY` all reach git. A driver run from a git hook or with `GIT_DIR` set would point `init`, `add` and `commit` at another repository.
- **Fix:** `unset GIT_DIR GIT_WORK_TREE GIT_INDEX_FILE GIT_OBJECT_DIRECTORY GIT_ALTERNATE_OBJECT_DIRECTORIES` inside the subshell.

**L8: the smoke chooses its secrets library from the environment.** `scripts/installed-smoke.sh:35`
- **Why:** on the host, an inherited `ADC_SMOKE_SANDBOX=1` plus an existing `/secrets.sh` makes the outer smoke source that host file.
- **Fix:** select `/secrets.sh` only when `"${1:-}" == --inside` (and the sandbox marker is set). Otherwise always use `$(dirname "$self")/lib/secrets.sh`.

**L9: the barrier has no deadline.** `fixtures/m1/stub-provider/server.mjs:99-102`
- **Why:** the barrier polls forever and is announced only on stderr. `close()` does not stop a held handler, so a test that fails before writing the release file hangs its process: a mutation I ran that broke the reply path hung the node test runner until I killed it. The JSONL log also has no barrier entry to order it among the requests.
- **Fix:** add an optional `barrier_timeout_ms` (default, say, 120 s), then reply 500. Have `close()` abort held handlers. Record `{kind: "barrier", request_id}` in the JSONL log as well.
