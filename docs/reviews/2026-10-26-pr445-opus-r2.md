- **Stub route:** `--routes stub` with `--repo-mirror` is a usage refusal (`-z …$mirror`). `live_mirror` runs only from `live_setup`.
  - Without a mirror, `repo_label` is "GitHub main". The profile keeps its URL (`if (mirror)` is false), and `repo_url` is read from `$work/profile.json`, which is the same URL.
  - The stub cases never reach this code.
- **Refusals (exit 2, `cannot`):** each fails closed. They cover: not a directory owned by the caller; not bare (the tool’s own `--is-bare-repository` must answer `true`, so a non-repository refuses); no `refs/heads/main`; `baseline.json` with no 40-hex `base`; the base object absent.
  - The tool runs under `env -i` with no system or global configuration. It reads only the mirror’s own config, and the mirror is the caller’s, per `-O`.
- **What is printed:**
  - The mirror path appears in the refusals, and in `$work/profile.json` and adcd’s state, as the run’s `repo.url`. It is an operator path, not a credential or the canary.
  - Every line still goes through `cannot`/`die` redaction.
  - No credential or canary reaches the mirror code: it gets only the path and the base SHA.
  - [INFERENCE] Whether `repo.url` appears in any provider request is not checked here; it is not a secret under #226 entry 202.
- **`main` before and after:** both are read from the mirror by `ls-remote -- "$repo_url"` (`--` guards it; the path is absolute after `pwd -P`). A move fails the run (die, exit 1, before `live_write_bench`).
  - With a mirror, GitHub `main` is no longer read. The run has no route to GitHub (no forge credential, merge disabled), so the assertion still covers what the run can reach.
- **Exit 0 against the wrong tree: not opened, but loosely bound (R1).**
  - The task is created on the mirror’s `refs/heads/main` (the profile’s `base_ref`). `live_mirror` checks only that the base commit object exists (`cat-file -e "$base^{commit}"`). It does not check that `main` is the base.
  - A mirror made with `--mirror`, or one fetched after the base, holds the base object while its `main` is another commit. The run then builds and gates on that tree, and the gate’s baseline is measured on the attempt’s own base (`internal/daemon/gateneed.go:82`), not on `baseline.json`’s.
  - Only the image-label check (the task base’s lockfiles must match the pinned image’s) narrows this.
