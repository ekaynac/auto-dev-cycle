### High: BLOCKING

**H1. A decided candidate whose review attempt is still finishing, or whose lease is still live, is never ended and gets no hold. The loop drops the refusal silently.** `internal/reconcile/reconcile.go:447,565,587`; `internal/authority/admit.go:157,185`; `internal/reconcile/reconcile.go:943`
- **Cause:** the two places decide "nothing of the task still runs" differently.
  - **`Observe`'s `settled`** checks only that no node is claimed or held.
  - **`DoneTask`'s `endable`** also needs every lease on the task's units ended and every attempt sealed (`lease.Unended`).
  - **How a refusal is reported:** `done` wraps any `endable` refusal as `ErrStaleExpectedState` (`admit.go:157`), and `Pass` drops stale refusals silently (`reconcile.go:943`).
  - **What the loop does meanwhile:** `Decide` returns only `Done` while `Candidate` holds (`:587`), so no other action of the task's is ever decided.
- **Input:** the review's run commits its go result, which completes the node (`run.go:443` → `record`). Then its seal step fails, for example a failed blob publish or command.
  - The review attempt stays `finishing` with its lease active.
  - At runtime nothing reseals a review's attempt: `Reseal` covers accept inputs only (`sweep.go:220`).
  - From then on every pass decides `Done`, `DoneTask` refuses, the loop logs nothing, and the task stays admitted. The next task is never admitted, and no hold is raised.
  - The board shows `done_candidate`, because it reads `CandidateGo` and not `task.done`.
  - Only a restart's sweep (`endLeft`) ends it.
- **Fix:** reuse what exists; do not add a third rule.
  - In `Observe`, decide `Candidate` only when `endable`'s full predicate holds. Export it as `authority.Endable(tx, task, as)` and call it from both places.
  - When the candidate is decided and a unit is still unended with nothing claimed, have the runner end it at runtime, as 5c-2c's `Reseal` does for a build: `endOne` with bounded tries, then hold the review node `runner: failed`.
  - Stop wrapping `endable`'s refusal as stale, so a refusal that persists is logged.
  - Add a row: a review whose seal fails once and then works, and one whose seal never lands. The task must end, or be held, at runtime.

### Low: OBLIGATION

**L1. 6d's round-1 accept, gate and review are the graph's convention, not a defect. Two readers keyed on a node's round are misled by it.**
- **Why it is a convention:** the `node.recorded` fold requires a node with no predecessor to be round 1 (`graph/events.go:424-430`). The repair's accept, gate and review are new nodes, not successors (`daemon/reviews.go:161-200`; `graph.Checked`, `reviewNode`). So "round" counts the build's successor lineage only.
- **Readers that handle it correctly:**
  - the rounds rail, which reads builds only (`graph/rails.go:180-186`);
  - `RoundAttempts`, which follows `Replaces` and not the round (`rails.go:145`);
  - `LastBuildRound` and `OfLastRound` (`repair.go:32-60`);
  - the review report's `candidate_round`, taken from the build (`daemon/run.go:465`, `review/review.go:108`);
  - the repair prompt's `findings-n` and `candidate-n`, taken from the build's round (`repair.go:114-118`);
  - supersede's same-round check (`supersede.go:568`).
- **Readers that are misled:**
  - **The board's node card** shows `Round: 1` on a repair's accept, gate and review beside a round-2 build (`api/board.go:232`).
  - **`bench`'s per-stage `rounds`** (`bench/bench.go:377,387`) would count 1 for the verify and review stages whatever the number of repairs, if P25 fills `bench.Node.Round` from `Node.Round`.
- **Fix:**
  - Give the board card the candidate's round (the producing build's) for accept, gate and review.
  - State in P25's row that a stage's round is its candidate's.
  - Document the convention at `graph.Checked`.

### The five questions
1. **Can `task.done` be recorded with no go in the last build round?** No:
   - **A newer round in flight:** its build raises `LastBuildRound`, so an earlier go is not of it.
   - **A rail hold:** it is also a held node, so the task is not `settled`.
   - **A superseded review:** its state is not `completed`, though no row pins this (M1).
   - **A no_go after a go:** there is one live review per round, a repair records the next round, and a renewed review is claimed.
   - **A revoked approval:** `Abandon` wins (E4 is caught).
2. **Twice, or never?**
   - **Twice:** no. The expectation is on the task's version, and `endable` requires the task to be admitted. The rows count one `task.done`.
   - **Never:** yes, silently, in H1's case.
3. **6d's round 1:** a forced, harmless convention for every gate, rail and label that matters. The board card and the future benchmark misread it (L1, with the lines named there).
4. **The leak row:** it covers every CLI read except the stream (L2). `task wait` prints the same record as `task show` (`printTask`). Gate details and badges cannot carry a test name.
5. **Reuse and regression:**
   - **Reuse:** `Observe`'s `settled` is a second, weaker copy of `authority.endable` (H1's cause). `Repairable` now shares `OfLastRound`.
   - **Regression:** none against main. The board's old `done_candidate` (the highest round of current nodes) never showed a repaired task's go, because the round-2 build made "latest" 2 while its review was round 1. This PR fixes that.
