### Medium

**M1. The result frame's bounds are tighter than what the in-process guard returns for a change it accepts. This blocks inputs that main accepts (a regression against main).**
- **Where:**
  - `internal/accept/integrity_proc.go:212-214`: each list holds at most `maxMsgEntries` (65,536) entries, a Path at most 4,096 bytes and a What at most 64 KiB.
  - `internal/accept/integrity_proc.go:48`: a frame is at most `maxFrame` (16 MiB).
  - `internal/accept/integrity_proc.go:451`: the child clips only the error text before it sends.
- **Cause:**
  - On main, the guard's warnings are bounded only by the input. `Verdict.Report` clips and truncates them later (`result.go:21-25`).
  - A child whose honest result is too big writes a frame that `readFrame` refuses. `converse` then returns `ok=false`, and the run gets "unverifiable: the guard's process ended without its result ()".
- **Inputs, probed:**

  | Input (`newGuardFixture`, a new package with no tests) | In this process (main's guard) | In the child |
  |---|---|---|
  | `tool9/long.go`: `func f<5000 × a>() { fmt.Println(1) }` | accepted, 1 warning (the Path is longer than 4,096 bytes) | blocked: "ended without its result" |
  | `tool8/many.go`: 70,000 lines `func fN() { fmt.Println() }` (2.2 MB, under `maxFile`) | accepted, 70,000 warnings | blocked: "ended without its result" |

  The same applies to any result over 16 MiB, for example many warnings with long paths, and to a new-import warning whose import path is longer than 64 KiB.
- **Fix:**
  - In `child`, fit the result to the frame before sending it, in a way the report cannot tell apart:
    - cut Path and What to the frame's field bounds, keeping valid UTF-8. The report already clips them to `maxField` (1,024 bytes), so its entries stay the same;
    - keep, per rank (base, additive, typed), the first `maxReported` entries of each list. The report never shows more than that, in the same order;
    - pass the number of entries dropped so the report's `truncated` count stays main's. Alternatively, state that count as a relaxation.
    - Keep at least one block whenever the guard returned blocks.
  - Add both probe inputs to the `TestIntegrityProcess` equality loop: the same `Accepted()` and the same report entries.

**M2. A healthy run is refused when other healthy runs hold every slot, not only when calls are stuck.**
- **Where:** `internal/accept/integrity_proc.go:358-362`. The slot is taken with a non-blocking `select … default`.
- **Input, probed:** `serviceSlots` set to 2, and three concurrent `converse` runs whose Reader is honest (it sleeps 500 ms, then answers). Result: `["true []" "true []" "true [: unverifiable: every guard service is held by a call still running]"]`.
  - With 16 slots, a 17th concurrent run is refused the same way whenever 16 others are in a listing, and each listing takes seconds.
- **Why it matters:**
  - The residual says "a Reader or Lister that ignores its context is the cause". Ordinary concurrency is a cause too.
  - Main has no such limit. This is not a regression in production yet, because nothing outside the tests wires up `Integrity`. But the out3 comment hands the bound on concurrent runs to the caller without saying what it must be.
- **Fix (pick one):**
  - Wait for a slot until the run ends: `select { case slots <- struct{}{}: case <-ctx.Done(): return nil, nil, nil, false }`. The bound still holds. With every slot stuck, a run ends at its deadline as unverifiable, which is still fail-closed. Adjust `TestProcServiceSlots` to match and add a concurrent-healthy row.
  - Or keep refusing, document that the caller must run at most `serviceSlots` guard runs at once, and apply L1 below.

### Low

**L1. A slot is freed after the reply is sent, so one run can briefly hold two slots.**
- **Where:**
  - `internal/accept/integrity_proc.go:365-366`: the deferred `<-slots` runs after `served <- s.serve(...)`;
  - `internal/accept/integrity_proc_test.go:233`: `len(serviceSlots) != 0` is checked right after a served run, so it can fail if that goroutine has not yet run its deferred release.
- **Fix:** `m := s.serve(ctx, c); <-slots; served <- m`. `serve` already recovers its own panics.

**L2. The run's directory is removed while a left-behind service may still be copying into it.**
- **Where:**
  - `internal/accept/integrity_proc.go:272`: `defer os.RemoveAll(dir)`;
  - `internal/accept/integrity_proc.go:370`: `converse` returns on a done context.
- **Input:** the caller's context is cancelled while `boxList`'s `CopyOut` runs. `CopyOut` takes no context. `RemoveAll` then races with the copy, fails with "not empty", and leaves files under the sandbox root's `runs/`, up to `maxRunCopy` per occurrence.
  - Main never removed the directory while a listing was running, because the listing was synchronous.
- **Fix:** when `converse` returns with a call in flight, hand the directory's removal to that call's goroutine, to run after `serve` returns.

**L3. `TestProcServiceSlots` uses a fixed 200 ms deadline for rows that need no deadline.**
- **Where:** `internal/accept/integrity_proc_test.go:207`.
- **Risk:** under `-race` or load, the fake child's first frame can miss the deadline. The refused and served rows then fail with `ok=false`.
- **Fix:** keep the 200 ms deadline only for the two stuck runs. Give the refused rows and the final served row `context.Background()`.

**L4. A binary that runs `Integrity` without calling `RunChildIfAsked` re-runs itself as the child.**
- **Where:** `internal/accept/integrity_proc.go:72-79`.
- **Input:** a future test package outside `accept`, with no `TestMain`, that calls `Integrity`. Its test binary, started with the child argument, runs its whole test suite as the "child", and those tests may start more. The result still fails closed, but at that cost.
- **Untested:** the `Getppid` check is not covered by any row.
- **Fix:** have `RunChildIfAsked` set a package flag. If the flag is unset, `isolated` returns "unverifiable: this binary does not dispatch the guard's process" without starting anything.

### Judged and holding
- **#1, the service slots:**
  - A slot is taken before the service goroutine starts and freed only when `serve` returns, so at most 16 calls can be stuck at once.
  - A refused run starts nothing.
  - With every slot held, `converse` returns an unverifiable block with `ok=true`. The deferred kill and `Wait` still reap the child. It fails closed.
  - A stuck call keeps only its run's `service` (file map and changes), which is bounded by the slot count.
- **#2, presence:**
  - `opt()` carries absent, present-empty and present `go.mod`/`go.sum` across the frame as they were. This is checked both ways.
  - On main the production Reader returns a non-nil empty slice for an empty blob: `drain` copies with `io.Copy`, which goes through `bytes.Buffer.ReadFrom`, which allocates. So the child keeping an empty read present matches main.
  - Probed: gob keeps a non-nil `*struct{Err string}` whose `Err` is empty. The loader's empty-error fix (Astra r2 #4) survives the trip to the child.
  - `LocalLister`'s key fix is correct and unambiguous: −1 is written with no bytes after it. On main the bug reaches only the local Lister, not the production Lister. `TestListerKeepsPresence` catches the mutation.
- **#5, the listing latch:**
  - `LocalLister`, `goList` and `boxLister` return either a nil map with an error, or a map with no error.
  - Every package `need` lists comes from a file that a type check then imports. If the listing failed, `typedOn` records an untyped entry, and `compare` (`integrity.go:358`) turns every untyped entry into a block.
  - out3 never lists: it reads only the base typers' listings.
  - So, like the builder, I found no input where the latch blocks something main passes.
- **#6, flags:** `bit()` refuses values above 1, and error text with a false error flag is refused. Both rows bite.
- **Frame protocol:**
  - The length and the run's budget are checked before the buffer is allocated.
  - Each count is checked against what is left of the frame before its slice is allocated.
  - Unknown ops, leftover bytes, unregistered reasons and block flags above 3 are refused.
  - No controller-only field exists in `childMsg`.
  - A read's `max` is limited to `maxFile` and the run's read budget, and the blob allowlist and request bound hold.
  - `readErr`, `failed` and `listFailed` are latched, and `Integrity` checks `ctx`, then `runCtx`, before it accepts a result.
- **The stated relaxation:**
  - Dropping the abandoned-check cap is sound: a killed child takes its abandoned type checks with it.
  - A Reader's error now becomes `Accept`'s error rather than a typer block. That is M4's latch, accepted on #287, and it still fails closed.
- **Init order:**
  - `RunChildIfAsked` is the first call in `cmd/adcd`'s `main` and in `TestMain`.
  - No file in the package, tests included, has an `init`, and `TestNoInit` enforces it.
  - `pyClass` is built in a variable initializer.
  - The three Python inputs are in the equality loop.
- **Tests:** the deadline rows are relative to a measured baseline. The H3 rows check reaping and that the run's directory is removed.
