3. **High — H2’s shared byte budget still lets new blocks erase main’s warnings.**  
   `internal/accept/integrity.go:392`; `internal/accept/result.go:55`

   Using the existing vendored-libc fixture, add 1,000 ordinary functions in a tested package, each calling `libc.X_Exit(nil, 0)`. Give each function a distinct approximately 1,500-byte name. Add a `fmt.Println` function with a similarly long name in `pkg/z.go`.

The remaining budget is smaller than another such block; the output warning has the same clipped path length and a longer explanation, so it cannot fit.

   **Fix:** preserve main’s blocks and warnings when allocating report capacity, including the shared byte budget. Additive blocks need explicit reporting priority or a separate bounded allocation; warning ordering alone cannot provide the promised preservation.

4. **High — H3 still permits multiplicative work through long names before truncation.**  
   `internal/accept/integrity_types.go:895`; `internal/accept/integrity_types.go:884`; `internal/accept/integrity_types.go:669`


   Each selection constructs the complete megabyte-sized `pkg.Name` in `namedOf`, then copies it into `" via …"`. Only afterwards does `ref` cut the key to 300 bytes.    **Fix:** bound or cache names before concatenation, use bounded declaration identities in reference keys, and charge string construction and aggregation work. Truncating the completed key is too late.
