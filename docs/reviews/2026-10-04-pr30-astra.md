# PR #30 and #33 (project profile loader): Astra reviews

## Review of #30 (Astra, 2026-10-04)

Verdict: NO-GO

Reviewed only `4e6b30a..d90e05e`. Two High findings block approval.

1. **High — Coverage can claim protection that the glob does not provide.**  
   `internal/profile/profile.go:192`  
   Matching a document pattern’s **spelling** does not establish containment. Confirmed: `protected_paths: ['docs/a?.md', deploy/*.yaml]` accepts `protected_documents: ['docs/a*.md']`, although `docs/abc.md` is unprotected. The identity fallback also incorrectly accepts topology filename `deploy/[ab].yaml` under protection pattern `deploy/[ab].yaml`; that pattern matches `a.yaml` or `b.yaml`, not the literal bracket filename.  
   **Fix:** Separate literal-path matching from glob containment. Topology paths must use actual matching without identity fallback. For document globs, implement sound containment or conservatively accept only demonstrably covering patterns. Add both counterexamples as regressions.

2. **High — Glob matching permits exponential validation time.**  
   `internal/profile/profile.go:181`  
   Every `**` recursively retries the remaining suffix without memoization. A **1,997-byte profile**, using `strings.Repeat("**/a/", 16)+"z"` against 33 `a` segments, exceeded a three-second test timeout inside `globMatch`. Increasing these small inputs multiplies the work, allowing profile validation to monopolize execution.  
   **Fix:** Use bounded dynamic programming or memoize pattern/path positions; also bound pattern length and segment count. Test adversarial nonmatches, including separated `**` segments.

3. **Medium — Collection tags and mapping-key anchors bypass strict conversion.**  
   `internal/profile/yaml.go:49`, `internal/profile/yaml.go:66`  
   Confirmed accepted: `forge: !custom`, `outputs: !custom [dist/service]`, `outputs: !!str [dist/service]`, and `&hidden priority: 10`. Collection branches ignore tags, while mapping keys bypass `plain` and its anchor check. Explicit YAML types can therefore be silently discarded.  
   **Fix:** Validate every node’s anchor and kind-compatible tag, including keys. Permit ordinary mapping/sequence tags, reject custom or incompatible tags, and test these cases.

4. **Medium — Numeric conversion changes values before schema validation.**  
   `internal/profile/yaml.go:78`  
   Confirmed in both YAML and JSON: priority `1000.0000000000000001` becomes `1000`; `1e-1000` becomes `0`; `-0` becomes `0`. All load successfully, although direct contract validation rejects the JSON originals. Float conversion and remarshalling erase evidence needed by validation.  
   **Fix:** Validate numeric spelling before conversion. These contracts need only integers: reject floating-point scalars and enforce the contract’s integer grammar without passing through `float64`.

5. **Medium — Valid JSON containing surrogate-pair escapes is rejected.**  
   `internal/profile/yaml.go:21`  
   A complete JSON profile with `name: "\ud83d\ude00"` passes `contract.Validate` but fails `Load` with an invalid Unicode escape error. Routing all JSON through this YAML parser breaks the advertised JSON support.  
   **Fix:** Route syntactically valid JSON directly through strict contract decoding; retain duplicate-key, numeric and Unicode validation there. Add a supplementary-Unicode JSON regression.

6. **Medium — Document parsing has no size bound before allocation.**  
   `internal/profile/yaml.go:20`  
   The loader constructs the YAML tree, another generic tree and JSON before schema rejection. A 200,003-byte flat numeric sequence allocated approximately **58 MB** in the probe. Neither document has a byte limit; the parser’s nesting limit does not bound breadth.  
   **Fix:** Enforce a documented byte limit before decoding, with bounded reading at the future CLI/API boundary. Add node/depth limits where needed and oversized-input tests.

`make ci` passed; shellcheck was skipped locally because it is unavailable. Temporary review probes were removed, and the checkout is clean.

The remaining semantic checks are substantially aligned with the contract. Repository-path checks enforce lexical Unix containment; filesystem/symlink containment requires repository access. Deferring base-ref existence to step 9 and installation-policy compatibility to M2 is reasonable for this delta, provided adoption incorporates those checks when available.

### Lead notes on #33 round 1

- H1: the coverage checks of a whole profile are budgeted together before any of them runs: the sum over every
  (pattern, document) and (pattern, topology file) pair of (segments+1)·(segments+1) positions is at most 2^20, or
  the profile is refused with the count. Matching fills one bottom-up table per pair, exactly that many positions,

### Lead notes on #33 round 2

- The budget now counts byte comparisons, not table cells: matchWork(g, s) = weight(g)·weight(s), where weight
  adds one per segment and per byte. That bounds the whole table including each cell's path.Match call, which
  never backtracks across stars and so costs at most about (len(pattern segment)+1)·(len(name segment)+1). The
  limit is 2^22. Both reproductions (topology files and protected documents) are refused in milliseconds.
- Regressions for both routes; the byte weighting is mutation-tested.

## Third review of #33 (Astra, 2026-10-04)

Verdict: NO-GO

**Second-round High — Fixed.** `weight(g)·weight(s)` bounds matching work **up to a constant factor**, including `path.Match`, for inputs admitted through `Load`. Each star-free chunk is scanned linearly per attempted filename position; chunks are not revisited after advancing past their star. Character classes and UTF-8 decoding fit this byte-dependent bound. Summing over cells gives the weighted product. Both coverage routes are charged, and no integer overflow was identified under the 64 KiB boundary. This is an asymptotic work bound, not the exact byte-comparison count claimed by the comments. See [Go’s matcher implementation](https://go.dev/src/path/match.go).

1. **High — Unbudgeted regex compilation permits memory exhaustion.**  
   `internal/profile/profile.go:162`

   `Check` compiles `vocabulary.task_id_pattern` without a complexity budget, then discards the compiled result. Confirmed on the pinned toolchain: replacing the fixture’s pattern with

   ```go
   "(" + strings.Repeat("a", 3000) + "){1000}"
   ```

   produces an **accepted 4,889-byte profile**. One `Load` allocated approximately **649 MiB cumulatively**, reached **326 MiB sampled live heap**, and took **481 ms**. Counted repetitions expand into millions of instructions; the profile-size and coverage limits do not constrain this allocation. [Go’s repetition expansion](https://go.dev/src/regexp/syntax/simplify.go) explains the amplification.

   **Fix:** Since only syntax validation is needed here, use `syntax.Parse` with `syntax.Perl` and a modest pattern-length limit. If compilation is required, enforce a conservative expanded-program budget before simplification/compilation. Add a full-loader regression.

2. **Medium — Computing the coverage budget itself performs unbudgeted quadratic work.**  
   `internal/profile/profile.go:195`

   `coverageWork` traverses every pair and recomputes both weights, even after exceeding the limit. A **59,610-byte profile** containing `p0` through `p4999` in both protection arrays performs 25 million document-pair calculations before refusal; measured `Load` time was **79 ms**. This is nonblocking at the current input limit, but remains an unnecessary super-linear path.

   **Fix:** Calculate each collection’s total weight once, then use:

   ```text
   sumWeights(protected) × (sumWeights(documents) + sumWeights(files))
   ```

   Use checked or saturating arithmetic against the limit.

`make ci` passed, including sandbox checks and cross-builds; shellcheck was unavailable and skipped locally. Temporary probes were removed; the checkout is clean. **The regex finding is the sole blocker.**
### Lead notes on #33 round 3: split (04 §2, three NO-GOs)

Round 3 confirmed the byte budget and found two more problems: unbudgeted regex compilation of
`task_id_pattern` (High) and quadratic work computing the coverage budget (Medium). After three NO-GOs, #33 is
split:

1. **Profile input and checks** (from main): strict input conversion and every semantic check except glob
   coverage. The regex High is fixed: the pattern is parsed with `regexp/syntax` (Perl flags) under a 256-byte
   limit and never compiled, so counted repetitions are not expanded; Go's parser refuses expansions that are too
   large.
2. **Protected-path coverage** (stacked on 1): glob compilation, sound containment, the bounded matcher and the
   coverage budget, now computed in linear time as sum(weights of protected) × (sum(weights of documents) +
   sum(weights of topology files)) with saturating arithmetic.
