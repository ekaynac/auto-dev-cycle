### High

**H1. `first_attempt.outcome`/`reason` come from the node's selected result, which may belong to a later attempt.** At `internal/api/tasks.go:109` (`Outcome: n.Outcome, Reason: n.Reason`), `n` is the `graph.NodeView`. `internal/graph/history.go` fills it from the node's *selected* result, whatever attempt produced it. A node gets later attempts by supersession:
- `lease.StartNext` (`internal/lease/wiring.go:276-292`) supersedes a sealed attempt;
- `stopping`, `finishing` and `lost` attempts can all be sealed (`internal/lease/attempt.go:43-45`).
- **Input:** the restart path (`LoseOnRestart`, P24's `kill-mid-build`). Attempt A1 is lost on restart, sealed, and superseded by A2. A2 submits `found` and its result is selected. The read then reports `{attempt: A1, status: "superseded", outcome: "found", reason: <A2's>}`. That is the opposite of assertion 5's "the first attempt's `(outcome, reason)`" (slice plan §2.3).
- The current test commits a result with no attempt at all (`taskread_test.go:142-145`) and still credits it to the first attempt. The test therefore asserts the wrong thing.
- **Fix:**
  - Results already carry their producer (`ResultRecorded.Attempt`, set at `internal/graph/content.go:84`). Credit an outcome only if it was recorded by `f.attempt.ID`; otherwise null.
  - Better: add a small fold index from attempt to its recorded result, and read the first attempt's own result even when it was not selected.
  - Rows needed:
    - a superseded first attempt whose successor's result is selected shows null, or its own result;
    - a result with no attempt is not credited to the first attempt.
  - Supersession can be tested now with `lease.SealMinimal` and `lease.SupersedeAttempt`, as `internal/fixtures/content.go:78-83` does. "Arrives with 22a-5" in the PR body is not quite right.

**H2. `--until` takes board columns, but the specified command is `--until closed|held`.**
- Slice plan §2.1 step 5 (every case runs it) and W18 name `adc task wait $T --until closed|held --timeout 60m --json`. The P22a plan's live driver step names `--until closed`.
- At `internal/cli/tasks.go:130-136`, `--until closed` is a usage error (exit 64).
- `held` cannot be expressed at all: a held node keeps its stage's column (`running`/`verifying`) and only gains hold badges (`internal/api/board.go:20-21, 210`).
- **Input:** `admission-held` or `launch-missing-credential` with `--until running` returns 0 at once, whether or not the task is held. With `--until done_candidate,done` it hits the timeout (exit 5) after 60 min, not 0.
- Polling also misses short-lived columns. `--until verifying` on a task that passes through `verifying` within one `--every` interval exits 6.
- **Fix:** accept the specified states:
  - `closed`: the task is terminal (`done_candidate`/`done`);
  - `held`: any card node carries a hold badge.
- Keep the column names only if the plan is amended. Document that a column counts only when a read sees it.

### Medium

**M1. Attempt and model-call data are served under the `board` read kind.** `internal/api/tasks.go:32` sets `Domain: boardDomain`.
- A grant whose read kinds are only `["board"]` now gets attempt ids, attempt status, start times, result outcome/reason and token counts.
- `adc events` withholds exactly these events from such a grant. Domains come from the kind prefix (`ReadScope.Reads`, `internal/authority/grants.go:273-281`): `attempt.*`, `model_call.*`.
- The board's own contract (`internal/api/board.go:33-40`) limits a board read to task and hold data. Its precedent for extra data is per-field gating: `owner_ref` is sent only when the caller also reads `hold`. W18 asks for "the task read domain".
- **Input:** a supervisor granted `kinds: ["board"]` on project A runs `adc task show tsk_A --json` and gets `first_attempt.tokens`.
- **Fix:** gate fields the way `owner_ref` is gated:
  - `first_attempt` needs `ReadsRecord("attempt", project)`;
  - `tokens` also needs `model_call`.
  - Alternatively, define a `task` domain.
- Add a supervisor-scope row; today both new tests read as the operator only.

**M2. Rows prove neither the waiting nor the earliest-start rule.** All three mutations survived both new tests:
- X1: `case !time.Now().Before(deadline)` changed to `case true` at `internal/cli/tasks.go:154`;
- X2: the `time.After(...)` case changed to `default:` at `internal/cli/tasks.go:162`, which busy-polls;
- X3: `at.Before(f.at)` changed to `f.at.Before(at)` at `internal/api/tasks.go:99`.

Every wait row (`internal/daemon/taskread_test.go:191-196`) decides on its first read.
- **Fix:**
  - Add a row where the task changes column during the wait: wait `--until ready`, and commit the plan result after about 300 ms. It must exit 0.
  - Add a row with a counting `Reader` that bounds the number of reads per `--every`.
  - Add a superseded-attempt row for the earliest start and for the start recorded on a supersession (`wiring.go:516`), using the fixtures path from H1.

### Low

**L1. `first_attempt` can come from a node in another project.** `firstAttempts` (`internal/api/tasks.go:94`) maps an attempt to `byNode[node].Task` without comparing the node's project to the task's. The board marks such a card unplaced (`node_in_another_project`), but the task read still attaches that node's attempt, status, outcome and lease tokens.
- **Input:** a damaged store where task A's node is pinned to project B. A reader of A then sees B's lease tokens.
- **Fix:** skip a node with `n.Project != t.Project` (or leave `first_attempt` null on an unplaced card).

**L2. Upgrade:** a new projection (`attempt_starts`, `internal/lease/wiring.go:27`) makes any existing store that holds `attempt.started` events fail the startup replay comparison (`internal/daemon/startup.go:142-153`, `ambiguous_state`).
- **Input:** a state directory where `adc dev fixtures`' lease/content contracts started attempts, opened by this build.
- **Fix:** say so in the PR and changelog. I infer no such store has been deployed; if one may exist, give a rebuild step.

**L3. The wait's bounds:**
- each read uses the caller's `ctx` only, so a hung read can run up to the client's 30 s command timeout past `--timeout` (`internal/cli/tasks.go:64`);
- one transient read error ends a 60-minute wait with exit 2;
- an unplaced card (column `""`) just waits out the timeout.
- **Fix:** read under `context.WithDeadline(ctx, deadline)` and map its expiry to 5. Decide (and document) whether read errors are retried until the deadline. Optionally treat an unplaced card as exit 6.

**L4. The charge (W18, assertion 5) is deferred to #302.** That is stated in the PR. Keep a tracked follow-up, so assertion 5 is not counted as met by 22a-7 alone.

### Judged and found sound
- **Exit codes:**
  - 5 and 6 are new and collide with nothing;
  - both are in the single table (`docs/design/m0/08-controller-api-and-cli.md:82-83`, `internal/entry/entry.go:24-25`);
  - a task already in an asked column returns on the first read;
  - the wait loop sleeps `min(--every, time left)`, with a 100 ms floor;
  - cancelling the context gives 2.
- **First-attempt determinism:** the earliest start wins, ties go to the smaller id, and a start time comes from the event's own time, so replay gives the same result. An attempt with no result yet gives null outcome/reason.
- **No leaks:**
  - no spec requirement, acceptance payload or attachment: the card is built by the board's `boardCard`, and the schema has `additionalProperties: false`;
  - `Fields` limits the top-level keys;
  - the project filter is applied in `List` and again in `Reads.Resource`.
- **Generated code:** `TaskRead`/`FirstAttempt`/`Tokens` match `schemas/api/task.json`. The inventory and parity tests pass.
- **CLI JSON:** `--json` prints the server's field-filtered object as returned (keys sorted).
- **#319 not regressed:** the diff does not touch the reconcile or bootstrap code. The race run passed in every touched package; the one failure is the sandbox-config test above.
