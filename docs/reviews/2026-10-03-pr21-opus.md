# PR #21 (controller ids): review

Mechanical PR; reviewed by a fresh Opus subagent (04 §3). Every finding was applied before merge:

- **Registry (Medium):** it is decided by the definition's shape, not by an exact `$ref` match. Any `$defs` entry that mentions `TypeID` or carries a prefix pattern must be exactly `{"$ref": "#/$defs/TypeID", "pattern": "^<prefix>_"}`, or parsing fails.
- **Duplicate keys (Low):** `defs.json` goes through `contract.Validate`, which refuses duplicate keys.
- **One suffix check:** `ids.Check` uses the schema's own suffix check, `contract.CheckTypeID` (exported for this), so the two cannot drift apart.
- **Tests added:**
  - the reviewer's four silently-dropped definitions (mistyped ref, file-qualified ref, ref inside `allOf`, a plain string with a prefix pattern);
  - a prefix that is too long, an extra keyword, duplicate keys;
  - an uppercase suffix;
  - the registry-load error path for `New`, `Check` and `Prefixes`.
- **Mutation checks:** disabling the ref check, the duplicate-key check or the suffix check each fails the tests.

The dependency (`go.jetify.com/typeid` v1.3.0, Apache-2.0, plus `gofrs/uuid/v5`, MIT) is kept, since note 02 names the jetify TypeID standard.

## Review of #21 (Opus, 2026-10-03)

Verdict: GO with changes

The reviewer checked the code against the spec directly, not only through the PR's tests:
- 2,000 minted ids per prefix were checked against both `ids.Check` and the schema's check.
- A test schema that refs every entity definition accepted the minted ids and refused other prefixes.
- A differential test over about 4M strings found 0 disagreements between `Check` and the schema.

**Medium**
1. A definition whose `$ref` is not exactly `#/$defs/TypeID` is skipped silently, which drops its prefix. Examples: a mistyped ref, a file-qualified ref, a ref inside `allOf`, a plain string with a prefix pattern.

**Low**
2. Duplicate JSON keys in `defs.json` are settled silently: the last one wins.
3. Untested claims:
   - that minted ids pass the schema check;
   - agreement between the two suffix checks;
   - an uppercase suffix on its own (the whole-id case fails on the prefix first);
   - the registry-load error path.
4. The dependency is acceptable but optional.
