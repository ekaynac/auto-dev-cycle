1. **High — LIVE crashes on its successful path.** `scripts/installed-cycle.sh:434`

   **Input:** A valid LIVE run reaching candidate, successful verification, restart, and benchmark recording, with no exported `stub` variable.

   Only the stub branch assigns `stub` (`:330`). LIVE reaches `kill "$stub"` under `set -u` and aborts with an unbound-variable error, before the scans and final benchmark publication. An inherited numeric `stub` instead targets a process this run never started.

2. **High — `clean_exec` does not enforce the environment allowlist; this also regresses stub isolation.** `scripts/lib/secrets.sh:71`

   **Input:** Launch the driver from Bash after exporting a function containing private configuration, for example `caller_helper() { : PRIVATE_VALUE; }; export -f caller_helper`.

   `compgen -e` enumerates variables, not exported functions. The function survives as `BASH_FUNC_caller_helper%%` in adcd’s environment. Failed `unset` operations are also ignored. Both starts use this helper (`scripts/installed-cycle.sh:364`); main used `env -i`, which removed these entries. Opus r2 already records the exported-function escape, but the supplied severity floor makes this an isolation deviation, not a Low obligation.

   **Fix:** Remove exported functions as well as variables, and refuse execution if anything outside the explicit allowlist remains. Verify the actual exec environment for both routes.

3. **High — a failed sandbox scan can report success.** `scripts/lib/sandbox-root.sh:164`

   **Input:** At the final scan, `podman unshare` fails with status 1 and no stdout—for example, a namespace-launch failure.

   The function accepts statuses 0 and 1 as grep outcomes, although the status belongs to the entire `root_podman` invocation. With empty `found`, it returns success. `scripts/installed-cycle.sh:461` consequently accepts an unperformed scan. This is the recurring “unreadable treated as success” class.

   **Fix:** Translate grep’s no-match status to success *inside* the namespace command, and propagate every outer launch failure as a scan error. Require evidence that the inner scanner completed. Add a row where the Podman wrapper fails before executing grep.

4. **High — the escaped-canary repair still misses production mixed escaping.** `scripts/lib/cycle-expect.mjs:43`

   **Input:** An acceptance canary such as `<TAB>const q7vCanary = "ADC-<q7v>-0123456789"` appearing inside a JSON string carried by a conversation message—for example, a `write_file` call’s JSON argument string.

   The adapter serializes the outer request at `adapters/http-chat/src/gateway.ts:45`. The production gateway then marshals its `json.RawMessage` fields at `internal/gateway/egress.go:140`, applying Go’s HTML escaping. This produces the equivalent of `goEsc(esc(canary))`: doubled inner escapes, but a single `\u003c`/`\u003e` for the angle brackets.

   The enumerated forms include `esc(esc(s))` and `goEsc(goEsc(s))`, but omit that composition. The gateway captures these exact outgoing bytes at `internal/gateway/gateway.go:485`; `live_after` searches them with the incomplete patterns at `scripts/lib/cycle-live.sh:203`. The leak can therefore evade the confidentiality check.

   **Fix:** Check decoded JSON string values, including nested JSON strings, or implement a shared escape-aware matcher. Cover the actual adapter → gateway → capture transformation, rather than testing JavaScript and Go escaping separately.

5. **High — LIVE can sweep another run’s containers.** `scripts/installed-cycle.sh:308`

   **Input:** A LIVE invocation with `--sandbox-root /tmp/adcABC123`, naming an existing root used by another active run.

   LIVE accepts the shared root without checking exclusive ownership. Cleanup selects `sandbox_root_sweep` at `scripts/installed-cycle.sh:223`, which executes `podman rm --all --force --time 0` at `scripts/lib/sandbox-root.sh:215`. It removes containers this invocation did not create. The stale-owner protection does not guard this explicit-root path.

   **Fix:** Require a newly created private root for LIVE, as promised. If shared LIVE roots are intended, require exclusive ownership and scope removal to recorded container IDs. Preserve the separately authorized stub-set sharing behavior.

6. **High — canary confidentiality is not checked across the promised output artifacts.** `scripts/lib/cycle-live.sh:203`

   **Input:** An otherwise successful run whose `out/adcd-2.log` contains the acceptance canary, while captures, `show.json`, and `events.jsonl` are clean.

   `live_after` searches only captures for the canary. The checker searches only the two saved operator reads (`scripts/lib/cycle-expect.mjs:205`). Work/root scans receive credentials, not the canary. Consequently this log leak is unchecked.    **Fix:** Scan logs and other non-authorized artifacts for all canary forms, with explicit exclusions for intentional acceptance/canary storage. Route every LIVE excerpt through the same redaction implementation, redacting before truncation.

   Findings 3, 4, and 6 remain independently relevant after fixing finding 1; an inherited empty `stub` also lets the current script reach those checks.
