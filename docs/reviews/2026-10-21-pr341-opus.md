## Opus pre-review of #341 (2026-10-21)

Verdict: GO with changes

The design holds for the cases asked about. Partial rows, a renamed key and rows moved to another projection name are all still refused. The transaction is atomic. The frozen list is exact on this PR's base. Two problems remain. The branch is out of date with main and goes red once merged. And one forged `_built` row, which is outside the two stated leaks, turns off the assumed list.

**Checks run** (on copies of the worktree, now deleted):
- `go test -count=1 -race ./internal/eventstore/ ./internal/daemon/` on the PR head: `eventstore` passes; in `daemon` only `TestSandboxConfig` fails (ignored on this host).
- Merged copy (PR head plus `b29be8a..origin/main`): `TestProjectionsRegistered` fails with "projection unit_open is not registered".
- Probe tests on both copies, and mutations switched on by an environment variable. Results are cited in the findings below.

### High

**H1. The branch is behind main, and main gained two projections.**
- **Where:** `internal/daemon/wiring.go:246-252`, `internal/daemon/startup_test.go:344`, `docs/design/m1/01-invariant-inventory.md:288`.
- **Input:** the PR is based on `b29be8a`. Main is now `db3e613`, which includes #333. #333 adds `lease.OpenProjection` (`unit_open`) and `graph.TaskNodeProjection` (`graph_task_nodes`).
- **What happens:**
  - Main's changes apply cleanly, but `TestProjectionsRegistered` then fails: `unit_open` is not registered.
  - I registered both projections in the merged copy. A store from before #333, simulated by deleting `unit_open` and `graph_task_nodes`, then starts. Main refuses that store, as #333's "Upgrade" paragraph says. So that paragraph becomes wrong. Stores with an approved Ready task are still refused, because the `admissible/` keys sit inside the held `tasks` projection.
  - The doc comment on `builtBeforeRecord` says it lists "every projection projector folded then". Read literally, that puts both new projections in the frozen list, so they would never be built. The PR text says to append them to `projections` only. These two contradict each other.
- **Fix:**
  - Rebase onto main.
  - Append both projections to `projections` only, not to `builtBeforeRecord`.
  - Update the expected list in `TestProjectionsRegistered`.
  - Extend Residual 2 to cover `unit_open` and `graph_task_nodes`.
  - Change the doc comment to "frozen at the PR's base".
  - Rewrite the #333 "Upgrade" text in `01-invariant-inventory.md`.

**H2. Inserting one `_built` row into a store written before the record turns off the whole assumed list.** This leak is not one of the two stated, and it gets past `capacity.CheckHistory`.
- **Where:** `internal/eventstore/build.go:104-115`. The assumed list is applied only when `len(recorded) == 0`.
- **Input 1:** a `leaseStore` (no `_built` rows yet). Delete all `capacity_reserved` rows and insert `('_built','lease_grants','{"version":1}')`. The start succeeds and `capacity_reserved` is rebuilt; `_built` ends with 50 rows. Main refuses this store.
- **Input 2:** a store holding a lease granted before capacity was wired, which main refuses with `ErrGrantedBeforeWiring`.
  - Delete every row except the identity ones and insert `('_built','actors','{"version":1}')`.
  - `checkCapacityHistory` passes on the now-empty `leases`, and `checkProjections` passes.
  - The build writes `capacity_granted` for the lease capacity never admitted, so `CheckHistory` passes from then on.
  - The PR argues that "the result still equals the log". That argument does not hold here: the checks that run before the replay (capacity, graph history) exist precisely because a replay can produce a state the log cannot justify.
- **Fix:** always count the assumed projections as recorded:
  ```go
  for _, name := range assumed { recorded[name] = true }
  ```
  - This is sound. Every successful build records every registered projection, and the assumed list is a subset of the registered ones, so a legitimate recorded store already holds all of them.
  - The `record` calls in the pre-record branch become redundant: the final loop records everything, and a refusal rolls back.
  - Tested in a copy: the whole `eventstore` suite and the PR's daemon rows still pass, and both inputs above are refused again.
  - Add both inputs as test rows. Narrow Residual 1 to projections outside `builtBeforeRecord`.

### Medium

**M1. `TestProjectionsRegistered` only notices a forgotten registration if the full history writes rows for that projection.**
- **Where:** `internal/daemon/startup_test.go:315-327`.
- **Input:** in the merged copy, the full history writes 0 `graph_task_nodes` rows, so leaving that projection unregistered goes unnoticed. Only `unit_open` was caught.
- **Effect:** at runtime this fails closed. An unregistered projection is compared but never built, so main's refusal comes back, which is the very bug this PR fixes.
- **Fix:** check against something that doesn't depend on the history. For example, gather every exported `*Projection` constant through a list kept next to `projector`. Or, in a test, assert that every name in `temp.proj_rebuild` after a full replay is registered, and extend the history to cover graph projections.

### Low

**L1. A stray `_built` row for an unknown name is accepted; main refuses it.**
- **Where:** `internal/eventstore/build.go:150-171` and `internal/eventstore/rebuild.go:92`.
- **Input:** `('_built','zzz','{"version":1}')` → the start succeeds. `adc dev rebuild-projections` no longer shows anything under `_built`.
- **Fix:** treat a record of a projection that is not registered as a `ProjectionDiff`. Alternatively, leave unknown `_built` keys in the comparison.

**L2. The recorded version is written and never read, and a forged version is silently overwritten.**
- **Where:** `internal/eventstore/build.go:26-28` and `138-142`.
- **Input:** `_built/leases` set to `{"version":99}` → the start succeeds and the row is rewritten to `{"version":1}`. Bumping a projection's version in a future PR changes nothing.
- **Fix:** refuse a recorded version above the registered one, since that store was written by a newer build. Document that a version bump triggers no rebuild. Or drop the field.

**L3. An undecodable record gets a misleading refusal message.**
- **Where:** `internal/daemon/startup.go:151-152` and `internal/eventstore/build.go:166`.
- **Input:** `('_built','leases','x')` → `store_unreadable: the event log cannot be replayed`. On main this was `ambiguous_state` drift, and the log itself is fine.
- **Fix:** add a sentinel error, e.g. `ErrBuildRecord`, mapped to `store_unreadable` with the detail "the record of built projections cannot be read".

**L4. Two mutations survive.**
- **S1:** skip the `DROP TABLE` at `build.go:144`. The scratch table then stays alive on the writer connection, and every test passes.
- **S2:** remove the `projectionName` check on record keys at `build.go:165`, and every test passes.
- **Fix:**
  - For S1, assert that `temp.proj_rebuild` is gone after a committed build.
  - For S2, add a test row `('_built','Bad Name','{"version":1}')` to `TestBuildProjectionsRefusals`.

**L5. "A refused start keeps nothing" holds only for refusals inside `BuildProjections`.**
- **Where:** `internal/daemon/daemon.go:137-142`.
- **Input:** a store whose `_built` rows were all built at start, then refused by `systemActor` ("holds events or effects but no actor"). The build and the record stay committed.
- **Effect:** harmless, since the kept state equals the log.
- **Fix:** say so in the docs.

**L6. A store started on this build can no longer be opened by an older build.**
- **Where:** `docs/design/m0/03-event-store.md:36-41`.
- **Input:** after one start on this build, main's `compareLive` reads the `_built` rows as drift, so an older binary refuses the store with `ambiguous_state`.
- **Fix:** state in the doc that this is a one-way upgrade.

### Answers to the judge points

1. **Strength of the corruption check:**
   - These are still refused: partial `lease_grants` (one key deleted), a renamed key, rows moved to another projection name, partial or emptied recorded projections, and a damaged projection while `lease_grants` is absent.
   - Beyond the two stated leaks: H2 (one forged row), and L1, which only adds harmless junk.
   - A forged higher version is harmless but rewritten (L2). A version change does nothing.
   - Offline starts run the same check and write only `proj_kv` rows.
2. **The frozen list:**
   - On the PR base it is exact. All 50 projection constants outside tests are covered: 49 in the frozen list plus `lease_grants`.
   - On main it misses `unit_open` and `graph_task_nodes` (H1).
   - A forgotten registration fails closed, but the test catches it only for projections the history writes (M1).
3. **Atomicity:**
   - It is sound. The build, the record and the scratch table all live in one writer transaction. Any error or difference rolls the whole thing back, scratch table included, and `built` is set to nil.
   - Seen in `TestDamagedStoreBeforeLeaseGrantsRefused`, and in the probe after the H2 fix, where `_built` stayed at its forged single row and `capacity_reserved` stayed empty.
4. **Interactions:**
   - The schema is unchanged, and `verify-log` runs inside the transaction before the replay.
   - `RebuildProjections` shares `compareLive`, which now leaves out `_built` (L1).
   - The error classes are kept, apart from the detail in L3.
   - Checks that run before the replay cannot see projections the build creates. H2's fix keeps them away from every projection that existed before the record.
5. **Mutations:** I re-ran M4 and M6; both are red with the PR's rows plus more. The other eight are the PR's own claim and were not re-run. S1 and S2 survive (L4).
