### High

**H1. The child runs the Python guard before the Python guard's `init` has run, so decision A's Python blocks are lost in production.**
- **Where:** `internal/accept/integrity_proc.go:41-44` and `internal/accept/integrity_pyguard.go:43-59`.
- **Cause:**
  - Go runs a package's `init` functions in file-name order. `integrity_proc.go` sorts before `integrity_pyguard.go`.
  - So `os.Exit(child(...))` runs the guard while `pyClass` is still the empty map from `integrity_pyguard.go:43`.
  - `pyClass` holds the exit, subprocess, print, `_pytest` and frame names that the Python guard looks for. In the child it finds none of them.
- **Probe:** a Python base (`newGuardFixture`), run in this process (`guarded`) and in the child (`isolated`):

  | Input | In this process | In the child |
  |---|---|---|
  | `tests/test_money.py` += `def test_exit(): import os; os._exit(0)` | P14c block + "`_exit in test_exit: unverifiable … (decision A)`" | P14c block only |
  | `money.py` += `import subprocess; subprocess.run(['true'])` | P14c block + "`subprocess in module level …`" | P14c block only |
  | `tests/test_money.py` += `print('PASSED')` | P14c block + allowlist block + "`print in module level …`" | P14c block + allowlist block |

  - With `integrity_proc.go` renamed to sort after `integrity_pyguard.go`, the child matched this process exactly. That confirms the cause.
- **Effect:**
  - Today `Accepted()` is unchanged, because every `.py` change still carries the blanket "python integrity not verified (P14c)" block. But the block list is weaker than main's, so the claims "same blocks and warnings" and "the whole guard in a child" are false.
  - When P14c-2b lifts the blanket block, decision A for Python fails open in production.
  - No test would notice. Every Python row uses the in-process `integrity` (through `guarded`). The equality row at `internal/accept/integrity_loader_test.go:75-86` covers only Go inputs.
- **Fix:**
  - Build `pyClass` in a package-level variable initializer: `var pyClass = func() map[string]byte {…}()`. Variable initializers run before any `init`.
  - Better still, move the dispatch out of `init`, for example into an exported `accept.RunChildIfAsked()` that `main` and `TestMain` call. Then no later `init` can be skipped again.
  - Add the three Python inputs above to the `TestIntegrityProcess` equality loop.
  - Add a row that fails if `integrity_proc.go`'s `init` is not the package's only `init`.

### Medium

**M1. The run's copied export data has no overall bound, and it lands in the controller's `os.TempDir`.**
- **Where:**
  - `internal/accept/integrity_proc.go:105`: the run's directory is created in `os.TempDir`.
  - `internal/accept/integrity_loader.go:99-105`: each listing copies out up to `maxExport+maxList` (272 MiB).
  - `internal/accept/integrity_types.go:49`: `maxListRuns` = 64 listings per run.
- **Measured live:** a `-d` file is the whole compiled package archive, not only its type data. One listing of `fmt` copied 60 files, 30 MiB. One listing of `net/http testing` copied 195 files, 86 MiB.
- **Input:** a candidate that adds about 30 small modules, each with a `go.mod` and a file importing `net/http`, makes about 60 listings over both platforms. That is roughly 5 GiB in the controller's `/tmp` for one run. Heavier dependencies approach 64 × 272 MiB ≈ 17 GiB, which is RAM if `/tmp` is tmpfs.
- **Regression:** main's `LocalLister` read from `GOCACHE` and copied nothing.
- **Note:** the typer can read at most `maxExport` (256 MiB) per version, so most of these copies can never be read.
- **Fix:**
  - Copy each `-d` file once per run into a shared `dir/x/`. The cache names them by content hash, so the same name means the same content. Skip names already present.
  - Charge every `CopyOut` against one budget per run (for example 2×`maxExport` + `maxList`×`maxListRuns`). Past it: not loaded.
  - Put `dir` under the sandbox root rather than `os.TempDir`.
  - Add a row: N modules with the same import, total bytes copied stay within the budget.

**M2. The vendoring gap: `GoEnv` pins `-mod=readonly`, but the guard still types vendored packages from `vendor/`.**
- **Where:** `internal/accept/integrity_loader.go:20-28` (`GoEnv` and its comment "so the guard types what the gate builds") and `internal/accept/integrity_types.go:281-306`.
- **Mismatch:** under `GoEnv`, the gate's `go test` builds a vendored repository from the module cache, while the guard types it from the base's `vendor/`. A candidate cannot edit `vendor/`: "a file under vendor/ changed" blocks. So the gap opens only when the base's `vendor/` differs from the cache at the same version.
- **Input:** [INFERENCE] the base's `vendor/example.com/h/h.go` is patched to `func Check(t *testing.T) { t.Helper() }`, while the cached `example.com/h@v1.0.0` has `t.SkipNow()`. The candidate adds `h.Check(t)` to a test. The guard reasons about the helper it read in `vendor/`; the gate runs the cache's version, which skips the test.
- **Not a regression:** main has no gate environment yet. But this PR fixes the gate's environment, and P15 consumes it.
- **Fix (decide before P15 wires it):** follow the gate, the boring choice.
  - When a base has `vendor/modules.txt`, list vendored modules through the loader (module cache), as external packages. Keep the "vendor/ changed" block.
  - Or block such repositories as unverifiable.
  - Pinning `-mod=vendor` instead would make `GoEnv` depend on the repository.
  - Add a row with a base whose `vendor/` differs from the cache.

### Low

**L1. A done context is reported as a verdict, not as the context's error.**
- **Where:** `internal/accept/integrity_proc.go:146-157`.
- **Cause:** the child's context is `Background`. When the controller's context ends during a listing, the child sees only "go list …: context canceled" and returns "not loaded" blocks. If its `done` message arrives before `CommandContext` kills it, `Integrity` returns those blocks with a nil error.
- **Effect:** still a block, never a pass. But it contradicts "a done context returns the context's error, as on main". The row "cancelled while listing" passes only because the kill usually wins.
- **Fix:** on `done`, check `if ctx.Err() != nil { return nil, nil, ctx.Err() }` first.

**L2. The controller trusts the child's `Max` and an empty panic text.**
- **Where:** `internal/accept/integrity_proc.go:177-180` and `:171-174`, `:201`.
- **`Max`:** `serve` passes the child's `Max` straight to the `Reader`. Fix: clamp it to `maxFile`.
- **Empty panic text:** a `panic("")` in the `Reader` or the `Lister` becomes `Panic: ""`. The child then reads that as an ordinary empty reply. It still fails closed, as "over the read bound" or "not listed", but no longer as "the guard failed". Fix: add a `Panicked bool` to the message.
- **Empty error text:** a `Reader` error whose message is empty reaches the child as `nil`.

**L3. The cold-cache fallback runs on any listing error, including the candidate's own.**
- **Where:** `internal/accept/integrity_loader.go:45`.
- **Measured live, arm64 (warm):** `[fmt example.org/none]` took 3.66 s, against 0.42 s for `[fmt]`. Every listing with one bad import is recompiled cold in the container's 256 MiB `/tmp`.
- **Effect:** time and CPU only, bounded by `maxListTime`. Still fail-closed.
- **Fix:** fall back only when the first pass shows cache misses (the error mentions the cache directory, or a read-only file system). Or list again only the packages with errors.

**L4. The child has no memory bound of its own, and its stderr is discarded.**
- **Where:** `internal/accept/integrity_proc.go:126-129`.
- **Memory:** the kernel's OOM killer may choose the controller instead of the child. Fix: after `Start`, write `1000` to `/proc/<pid>/oom_score_adj` (no privilege needed), or set `RLIMIT_AS` on the child.
- **stderr:** a crash shows up only as "ended without its result". Fix: keep a bounded tail of stderr (a few KiB) and log it.
- **`Pdeathsig`:** this is a race window between fork and `prctl`. The child could check `os.Getppid()` once at start.

**L5. Some of the gate pins are never observed by a test.**
- **Where:** `internal/accept/integrity_loader_test.go:222-280`.
- **Gap:** the loader's workspace holds only `go.mod` and `go.sum`, and `localBox` runs in `t.TempDir()`. So dropping `GOWORK=off` or `-mod=readonly` from `GoEnv` leaves every row green. Of the pins, only `GOTOOLCHAIN=local` is killed by a mutation (M3).
- **Fix:** pin `GoEnv`'s exact contents in a row, and have P15's gate row exercise `GOWORK` and `-mod` on a real checkout.

**L6. The worker-slot comment is stale, and the cap across runs is gone.**
- **Where:** `internal/accept/integrity_out3.go:150-153`.
- **Stale:** the comment says "any run's (Astra #280 M5)". `outWorkers`/`outDropped` are now per child.
- **Cap:** `maxOutWorkers = 1` no longer caps type-check workers across concurrent guard runs. N concurrent runs now mean N children, each with a worker. This is acceptable, because dropped workers now die with their process, but say so.
- **Fix:** reword the comment. Note in the residuals that the caller must bound concurrent guard runs.

### Judged and holding

- **Fail-closed:** every way the child or the loader can fail gives a block or an error, never a pass:
  - the child does not start, is killed, crashes, writes past `maxProcOut`, gives an unknown reason, or misses the deadline;
  - no image or no limits (`ErrSpec`);
  - a sandbox refusal, podman's exit, a timeout, or an unsafe attempt (`CopyOut` refuses);
  - another release of go;
  - an unreadable list, or a listing missing a requested package ("not listed");
  - export data not copied out.

  `CopyOut` copies only regular files, opened through an `os.Root` with `O_NOFOLLOW`. Export data is read only from the copy, by base name. The cache names files by content hash, so a matching name means matching content.
- **The child protocol:**
  - The image, the directory and the listing deadline are the controller's own (`req.Dir`, `req.ListEnd`), never the child's.
  - The child chooses only the platform (passed as one `env` argument, so nothing can be injected), `go.mod`/`go.sum` (attacker data already) and paths (checked by `listable`, after `--`).
  - The `Reader` checks the object id's form and is limited to the attempt's repository.
  - The child cannot make the controller run any other container.
  - Replies are never paired to the wrong request. Only an abandoned type check's goroutine can call alongside the main one, and by then the main goroutine sends nothing but `done`. The out3 worker reads export data from disk and never calls back.
- **Deadline and kill:**
  - `CommandContext` on the whole-run deadline, plus `Kill` and `Wait` deferred, so no zombie is left.
  - `os.RemoveAll(dir)` runs after the child is waited for.
  - Containers belong to the controller, and `Start` removes them by name with `WithoutCancel`.
  - Listing deadline (5 min) < whole-run deadline (10 min).
- **The stated relaxation:** with the type check in a process that is killed, a later run no longer inherits an abandoned check's CPU or its fault, so dropping the cap is sound. `TestIntegrityProcess` shows the child exited and a later run accepted.
- **Gate pins:**
  - Raising the `toolchain` line is handled correctly: it is typed by the image's own go, here and live.
  - A raised `go` line is unverifiable.
  - A base `go.work` is never in the loader's workspace, and a changed `*.work` file still blocks.
  - The child's empty environment gives the toolchain's default `goexperiment.*` tags.
- **Tests:** the "never ends" row's limits are relative (deadline 2×baseline+1 s; upper limit maxRunTime+2×baseline+5 s), not wall-clock-fixed. The past-the-deadline, output-bound, raised-toolchain and copy-only rows are adequate. The gaps are H1 (no Python in the equality row) and L5.
