# PR #31 (refs and view fingerprints): Astra reviews

## Review of #31 (Astra, 2026-10-04)

Verdict: NO-GO

1. **High — Set canonicalisation permits multiple identities for the same ref.**  
   **Location:** `internal/knowledge/ref.go:57–65,90`; `schemas/records/ref.json:51–55`.  
   Reproduced with schema-valid refs: `allowed_destinations: ["local-a","local-b"]` versus the reversed list produce different identities, and both pass `CheckRef`. Restrictions sharing `(project, policy_digest)` but having different destinations also compare equal; reversing those restrictions produces two accepted identities. JCS preserves array order, so it cannot repair either case.  
   **Fix:** Canonicalise destination sets recursively. Define a total ordering for distinct restrictions, or reject conflicting entries under an explicitly defined unique key. Make `CheckRef` enforce these rules. Add permutation tests covering nested sets and comparator ties.

2. **High — “One per contributing project” cannot preserve restrictions from multiple policy revisions.**  
   **Location:** `schemas/records/ref.json:32,42–48`.  
   A derivation can combine an older on-prem-restricted input and a newer, less restricted input from the same project. One restriction containing one `policy_digest` cannot faithfully retain both snapshots. Selecting the newer policy loses inherited restrictions; constructing an aggregate leaves its policy digest and provenance undefined. This is a KA1 contract ambiguity with disclosure consequences for a second implementation.  
   **Fix:** Specify that every distinct inherited snapshot is retained and all restrictions apply conjunctively, including multiple snapshots from one project. Alternatively, define a lossless aggregation with explicit provenance. State that resolved empty destinations deny delivery. Also distinguish these immutable snapshots from the live authority/export-approval checks required at initial, lookup and fallback delivery; snapshots alone cannot honour revocation.

3. **Medium — Checked refs and fingerprints need not satisfy their schemas.**  
   **Location:** `internal/knowledge/ref.go:63–75,89–100,110–121`.  
   Reproduced: nil destination lists and duplicate lineage entries survive `Seal` and `CheckRef`, although schema encoding rejects them. Nil destinations also hash differently from `[]`. Even `Seal(types.Ref{})`, followed by `Fingerprint` with an empty renderer, produces a fingerprint accepted by `CheckFingerprint`.  
   **Fix:** Normalise all supported nil sets, reject or remove duplicates consistently, and validate schema constraints at these public entry points—or explicitly require prior validation and expose a combined validation path. “Checked ref” should have an unambiguous meaning.

4. **Medium — `CheckFingerprint` checks internal consistency, not freshness or provenance.**  
   **Location:** `internal/knowledge/ref.go:134–146`; `internal/knowledge/ref_test.go:168–175`.  
   An untouched cached fingerprint still passes after the current finding changes at the same tree. The test detects staleness only because it first replaces the cached inputs. Likewise, resealing supplied refs and recomputing their fingerprint establishes no controller provenance. This is a limitation of the current primitive, not evidence of an existing serving-path exploit; assembly arrives in M1.  
   **Fix:** Document that boundary explicitly. Provide a serving check that compares the recorded digest against a fingerprint computed from independently resolved current inputs and the expected renderer. Test an unchanged cached fingerprint against changed authoritative inputs.

5. **Medium — The portable digest contract is not sufficiently specified.**  
   **Location:** `schemas/records/ref.json:5,25–35`; `schemas/records/view-fingerprint.json:5`; `internal/knowledge/ref_test.go:46–54`.  
   The schemas do not specify set ordering, duplicate handling or the exact fingerprint preimage. The sole golden vector contains no restrictions or non-ASCII lineage. Go sorts lineage strings by UTF-8 bytes; a JavaScript default sort differs for `U+E000` and `U+10000`. Both implementations can reasonably follow the current prose and disagree.  
   **Fix:** Publish the exact preimages and canonicalisation rules: comparator, null handling, duplicate/conflict rules and Unicode preservation. Add language-neutral vectors containing restrictions, Unicode and a complete fingerprint. K10 should not require reading Go implementation details.

6. **Medium — Fingerprints retain aliases into caller-owned inputs.**  
   **Location:** `internal/knowledge/ref.go:131`; `internal/knowledge/ref_test.go:203–211`.  
   `slices.Clone(inputs)` copies only the outer slice. Revision/project pointers, lineage, restrictions and destination slices remain shared. Reproduced: changing a caller’s nested destination changes the saved fingerprint’s inputs and makes its subsequent check fail.  
   **Fix:** Deep-copy the complete input graph and test nested mutations, or explicitly establish immutable ownership instead of promising an independent copy.

All Ref and ViewFingerprint fields listed in note 10 are present. The deferred manifest events and shared-spec draft are outside this PR’s stated scope.

`make ci` passed locally; shellcheck was skipped because it is not installed. Temporary sandboxed probes reproduced the issues above. The working tree remains unchanged.
