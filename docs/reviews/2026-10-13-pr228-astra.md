1. **Low — Held operations escape the request-digest cross-check.** `internal/graph/history.go:111`  
   A node can legitimately receive a hold after `Operate`, retaining its key and claim. Its state then becomes `held`, so CheckHistory skips the digest comparison. Editing only that effect’s `request_digest` leaves both this check and replay satisfied: `operated` checks kind and target, and raising the hold checks neither request identity nor digest. This is an additional “replay cannot see it” case.

   **Fix:** derive the request from the retained claim for both claimed and held nodes at the operation’s key, without relaxing execution eligibility. Add a case that operates, raises a hold, edits the effect digest, verifies replay remains equal, and expects `ErrHistory`. Due before the first graph effect activates.

Missing input-result records have a similar path. These are readable but inconsistent projections, not storage/decode failures. Startup still refuses safely, but the advertised error distinction is incomplete.

   **Fix:** distinguish semantic reconstruction failures from storage/decode errors and classify the former as `ErrHistory`. Add missing-claim and missing-input-result cases while retaining the undecodable-record cases. Due before graph effects activate.
