### 1. Can a patch be accepted while a hidden test did not run or did not pass?
- **The parser holds:**
  - A missing hidden id is rejected ("not reported", `why` case 0).
  - A renamed testcase is a different id, so the declared id is missing: rejected.
  - Duplicates keep the worst outcome (`tests.add`, `max`), so a later pass never hides a failure.
  - A skip is rejected.
  - A stale results file is removed before each run (`root.Remove`), and no file afterwards means unreadable. That gives could_not_run for B or H, and rejected for C.
  - Truncated JUnit is unreadable. My probe: `<testsuite><testcase …/>` at EOF gives "the results are unreadable", so C is rejected. A truncated go test -json stream leaves the unfinished tests as fail, through `internal/results`.

  - The results file is read at its path, without following a final link (`os.Root`, `regularfile.Flags`). A patch cannot pre-write it, because the file is deleted first, and cannot link it, because `accept` refuses symlinks.
