## Review of #122 (Astra, 2026-10-06)

Verdict: GO with changes

1. **R7/P1 — PASS.** Recovery requires the live system issuer and an existing live operator recipient. Schemas exclude plaintext; issuance-profile hashes are enforced. Invalid revocation IDs roll back the entire transaction, including earlier revocations. Actors, proposals and bootstrap state are untouched. Duplicate token IDs are refused; distinct authorized recoveries remain allowed. Ordinary issuance checks are unchanged. `revoked_at = token.created_at` makes replay deterministic.

2. **R8/P2 — PASS at the contract boundary, with caller obligations.** Either bootstrap key prevents renewal. The projector enforces exactly 24 hours and `created_at ≤ ev.At < expires_at`, retaining only the latest projection record. The store supplies `ev.At`; replay preserves it. Recording just before expiry is sound: it does not extend that expiry, and subsequent consumption must check the current time.

   Repeated renewal while a bootstrap is live **is accepted**. The event also accepts reuse of the current hash, so replacement alone does not prove secret freshness. This is acceptable for an explicitly authorized system operation, but PR 4d must generate a fresh secret and prohibit automatic renewal during startup. The projector cannot establish the offline-command conditions by itself.

3. **Naming — PASS.** Keep the approved `identity.*` names. Both kinds are registered with distinct schemas; consistency with older names does not justify departing from the plan.

4. **Redaction — PASS.** Recovery exposes only the listed public token metadata; hash and revocation list are omitted. Renewal produces `{}` with `payload_withheld: false`. Neither payload needs complete withholding under the existing authorized-stream policy.

5. **Tests/size — CHANGES.** CI and race tests pass. The **187** hand-written non-test lines, including **31** schema lines, are correct. However, the claim that tests fail without every guard is not supported.
