### High

**H1. A walrus inside an f-string field binds a name the guard never sees.** (`internal/accept/integrity_pyimport.go:98-103` pyBinds scans `t` only; `integrity_pyguard.go:282` passes `st`, not `l.inner`)

Input, the whole change, `tests/test_money.py`:

```python

def g(fn):
    ...            # C1 A's payload
    return fn

X = f"{(fixture := g)}"

@fixture
def test_add():

```

Trace. The assignment line has three outer tokens; the f-string is one `'s'` token, so `pyAllowed` sees a constant bound to `X`, and `pyBinds` finds no `:=` because the walrus lives in `l.inner` (`( fixture : = g )`). `pyConst(l.inner)` is true (no call). The decorator line `@fixture` is an allowlisted chain. Nothing fires. CPython binds `fixture` to `g` at import and runs `g(test_add)`. The same route binds a dunder: `class Base:` / `    X = f"{(__init_subclass__ := g)}"` / `class T(Base): pass`. It also defeats widening 1's `local` check: `Y = f"{(Path := g)}"` makes an unchanged `HERE = Path(__file__).parent` call `g` while `passes` still sees `Path` as imported only. `pyRebound` and the refs do read `l.inner`; `pyBinds` is the one reader that does not.

Fix: call `pyBinds(slices.Concat(st, l.inner))` at `integrity_pyguard.go:282` (the walrus scan then covers fields; `pyAssign` on the concatenation still yields only `X` as a target). Add rows for the `fixture` and `__init_subclass__` forms.

**H2. The string-condition rule reads a string token only. A name, a parenthesis, `*args`, a literal `**{}` or an `or` operand carries the string past it.** (`integrity_pyimport.go:152-160`; applied at `integrity_pyguard.go:297`)

Input, `tests/test_money.py`:

```python
import pytest
from money import add

COND = "config.pluginmanager.register(type('P', (), {'PYTEST_RUNTEST_MAKEREPORT'.lower(): staticmethod(lambda item, call: __import__('pytest').TestReport(item.nodeid, item.location, {}, 'passed', None, call.when))})) and False"

@pytest.mark.skipif(COND, reason="r")
def test_add():
    assert add(1, 2) == 3
```

Trace. `COND = "..."` is a constant bound to a plain name. The string holds no `pytest_`, `hookimpl`, `_pytest` or `pluggy`, so `isHook` and `pyKind` are silent. The decorator is exactly an allowlisted chain plus one balanced call, and `pySkipString` sees `skipif ( COND` with a name at `t[i+2]`. No finding. pytest's `evaluate_condition` sees a `str` and evals it with `config` in scope: Opus's end-to-end result. Variants that pass the same way, no variable needed: `skipif(("..."), reason="r")`, `skipif(sys.platform == "nope" or "...", reason="r")`, `skipif(*ARGS)` with `ARGS = ("...",)`, `skipif(**{"condition": "..."})` (the `**` rule allows a literal `{`), `xfail(condition=COND)`, `pytestmark = pytest.mark.skipif(COND)`, `pytest.param(1, marks=pytest.mark.xfail(COND))`. An f-string, a concatenation and `from pytest import mark` / `mark.skipif("x")` are caught; `m = pytest.mark` / `m.skipif(...)` is blocked as a call outside the allowlist.

Fix: in a judged file, take the first positional argument of `skipif`/`xfail` (tokens from `(` to the first depth-0 `,` or `)`) and the `condition=` value, and allow it only when it is `True`/`False` or holds a depth-0 comparison or `not` (`== != < > <= >= is in not`) and no string token is a direct depth-0 operand of `and`/`or`; block `*`/`**` there. Keep the string-token rule. A bare name blocks under this rule (`skipif(IS_WINDOWS)`): a later widening may allow a name whose only binding in the file is itself such an expression. Add the rows above.

### Medium

**M1. A parenthesised `for`/`with` target keeps `__name__` unbound in the guard's eyes, and the `__main__` scope reopens in application modules.** (`integrity_pyimport.go:130-131`)

Input, `money.py`:

```python
import os
for (__name__) in ("__main__",):
    pass
if __name__ == "__main__":
    os._exit(0)
```

`for (x) in ...` is valid Python. In `pyRebound`, the token `__name__` sits between `(` and `)` with `for` (a name-kind token) two before it, so the lone-call-argument exemption applies and `rebound` stays false. The guard line opens the `__main__` scope; `_exit` is credited to `__main__`, not top, not tested: the result is the warning `money.py: _exit in __main__`, where #263 promised a block at import. `with X as (__name__):` is the same. In judged files the `for` line is a finding and blocks, so this is application modules only. The exemption is #263's, moved into the pre-pass, so it is not a round-2 regression. Fix: add `&& !slices.Contains(pyKeywords, t[i-2].text)` to the exemption (`for`, `as` and `del` are in `pyKeywords`; `print(__name__)` and `getLogger(__name__)` stay exempt).

**M2. The new `**` rule blocks every `def` with a `**kwargs` parameter, and the test fixture hides it.** (`integrity_pyimport.go:73`, def case `:199-200`; `integrity_pyguard_test.go:45`)

Input, `tests/conftest.py`: `def helper(*args, **kwargs):` / `    return args`. The header tokens `( * args , * * kwargs )` hit the `**` rule (`,` before, `kwargs` not `{` after) and the def blocks as "code run at import outside the allowlist". `pyG`'s own `def g(*a, **k):` is blocked in every a-row, so each a-row carries a second, unnoticed finding; `pyBlocks` passes because it only looks for the expected text. The rows still kill V1 to V5, but the fixture should be `def g(*a):`. This is a round-2 defect in a judged file, not one of widenings 2 to 9, and `**kwargs` helpers are common in conftests; it also enters `pyCalls` (`k`), so such a base def never passes widening 1. Fix: in `pyConst`, a `**` at bracket depth 1 of a `def` header is a parameter: pass a flag from the def case, or strip depth-1 `* * NAME` before the check (about three lines).

**M3. Ledger (2b or 2a-widen): a module added under a test directory shadows the module under test.** (scope rule `integrity_pyimport.go:25-32`)

Input: the base's `tests/test_money.py` has `from money import add`; `tests/` has no `__init__.py`. The candidate adds `tests/money.py` holding `def add(a, b):` / `    return a + b`. The new file is judged and passes (one def, constant header, body not import code); no refs. pytest's prepend mode inserts `tests/` at `sys.path[0]`, so `money` resolves to the shadow unless a conftest imported it first, and the unchanged tests pass against it. Nothing in this PR's promise covers it (no import-time code runs), but the directory scope this PR introduces is where the rule belongs: block a `.py` added, renamed or copied under a test directory whose module name is imported by a base test module or conftest and did not exist in that directory before; adding or removing `tests/__init__.py` moves the basedir and deserves the same treatment.
