### Findings

**Critical / High / Medium:** none.

**Low**
- **L1. The empty-list guard is untested.**
  - **Where:** `scripts/prepare-go-image.sh:37,91`.
  - **What I saw:** mutation X2 (`warm_required=0` on the `auto-dev-cycle` row) passes every test, because no test exercises the build path. The same was true on main for the plain `-s` check.
  - **Fix:** move lines 86-91 into a `warm PROJECT` subcommand that prints the list or fails, and have `build` call it. Then add a row in `internal/profile/gomini_test.go`: `warm auto-dev-cycle` is not empty, and `warm go-mini` is empty. Alternatively, record the gap on #226.
- **L2. go-mini's rule is "may be empty", not "is empty".**
  - **Where:** `scripts/prepare-go-image.sh:38,91`.
  - **What I saw:** go-mini leaves out `go.sum` because it has no dependencies, yet the script accepts any list for it. With the fake `go` that exits 0 and prints nothing, go-mini still builds. If go-mini gains a dependency, `go list -mod=readonly` already fails without `go.sum`, so the actual risk is small.
  - **Fix:** make the rule three-way: `warm_required=1` must be non-empty, `0` must be empty. Die "go-mini lists third-party packages; its lockfiles need go.sum" when go-mini's list is not empty.
- **L3. A line is over-long.**
  - **Where:** `fixtures/m1/images/go/Containerfile:30` (117 characters).
  - **Fix:** rewrap the comment to the file's width, about 78 characters.
