Read-only review of 46d4b0d against `origin/main`. The requested test packages plus `internal/daemon` and `schemas` pass. No Critical or High finding; nothing blocks.

### Answers to the seven questions

1. **Derivation.** Every column comes from the task record's state and approval status and from the nodes' kind, state, round and selected outcome (`internal/api/board.go:149-207`). No branch defaults to a column. Unknown state, unknown approval status, a Ready task with nodes, a deferred kind, a cross-project node, an undeclared wait, a missing selected result and an unreadable hold `since` all return `unplaced`. The reasons cover every path in the code, with one case where an entry disappears instead (M2).
2. **Confidentiality and authorization.** The generated card types carry only the schema's fields. The hold badge has no reason, pages or escalation (`gen/go/types/api_board.gen.go:164-172`), pinned by `TestBoardHoldBadgeFields`. The spec digest, requirement and attachments are not on the placed card type. Errors from the list and project callbacks map to the generic store-unreadable body (`internal/api/reads.go:181-182`), so record text never reaches a reader through an error. Scope is checked on the task's project before derivation and again by the generic read path, which re-reads by id. The `owner_ref` gate uses the task's own project. The documented reach matches the P4b row, which itself names "the hold, signal, owner and age". It is acceptable without a `task` read domain as long as `board` stays a grant kind the operator issues deliberately. Read kinds are open names (`schemas/records/grant.json:26`), so no vocabulary change was needed.
3. **Failure mode.** The remaining whole-read errors are the task key listing, node and result record decode, the task projection get, and the graph task-project decode. All are storage or decode errors. A damaged task record is per-entry.
4. **Latest round.** The latest round is the highest round over unsuperseded nodes of any kind, and a GO counts only when its review's round equals it (`board.go:187-198`). A completed repair with its gate ahead reads `ready`, a superseded GO reads `ready`. No stale GO reads as done under M1(a)'s one-review-per-round template. Two edge cases are Low (L2).
5. **`TaskAdmitted` and the fixture.** Sound as a stand-in. The fixture writes the projection inside a command and the board reads only the projection. It does obligate P22a to specifics that are recorded nowhere yet (M1).
6. **`Resource.List` to `ReadAt`.** Mechanical. The six other resources ignore the argument and the two test helpers thread it through. One cosmetic consequence (L3).
7. **Fault evidence.** The F case is discriminating: eight unit cases, two over real records through HTTP, one on the installed CLI, six named mutations. The authorization evidence has one gap (L1).

### Findings

**Medium**

- **M1. P22a's obligations to the board are not recorded.** `internal/authority/task.go:52` adds the admitted state and `board.go:160-170` makes the board depend on how P22a writes it. The PR lists this as a deviation, but issue #226 has no entry. P22a must: write exactly `"admitted"` into the task record's state; record admission before, or in the same transaction as, the first node, or the task shows transiently as `nodes_before_admission`; add every further task state it introduces to the derivation, or those tasks read `unknown_state`; and replace the fixture's direct projection write (`internal/api/board_test.go:62-79`) with the real fold. Fix: one #226 entry with P22a as owner listing these four points, and a pointer to it in the constant's comment.

- **M2. A damaged task record with no nodes vanishes from every project-scoped board.** `boardTask` (`board.go:127-140`) returns a nil project when the record does not decode and no node pinned one, so only the operator sees the entry. The schema says so, but a supervisor who owns the project sees a task disappear rather than an unplaced entry, which is exactly the damage case the F row targets. Fix: when the record is present but undecodable, decode only its `project` field and use it for the scope check if it names a registered project, else keep nil. Add a case to `TestBoardAroundDamage` that overwrites a task record with a non-decodable state and expects an A-scoped reader to receive `damaged_record`.

**Low**

- **L1. The `owner_ref` gate is not tested per project.** `TestBoardOwnerRef` (`board_test.go:169-170`) grants `board` and `hold` together on A. A mutation checking "any hold grant anywhere" passes. Fix: add a reader with `board` on A and `hold` on B only, expecting null.

- **L2. Done takes any GO in the latest round, and the latest round spans controller nodes.** `board.go:198` is true when one review of the latest round is GO even if another is NO-GO, and `latest` includes `review_requirement` rounds, so a requirement successor without a review supersession hides a valid GO. Both lie outside M1(a)'s template and the second errs conservative. Fix when plural review arrives: require every completed unsuperseded review of the latest round to be GO, and compute the latest round over the kinds with a non-empty column. Record in #226 for P16/P31.

- **L3. Two clocks per read.** `reads.go:85` takes a fresh now for the badge ages while `reads.go:168` took another for the scope. Harmless today. Fix: take now once in `view` and pass it down.

- **L4. `node_in_another_project` tells an A-reader that a node of its task exists outside A** (`board.go:177-178`). No id or project is named, so this is informational, not a leak. No change needed; noted so the automated scan's cross-domain flag has an answer on record.
