## External review of #248 (Mythos, 2026-10-13)

Verdict: GO with changes

No Critical or High. The H1 fix closes the realistic echo (an honest upstream quoting the key in a 401), and every other path I attacked holds. The changes below are Medium and Low, none blocking; the Mediums are a cheap claim gap in the response direction and a flaky piece of fault evidence.

### Medium

**M-1. An unsolicited `Content-Encoding` bypasses the redaction and is silently stripped.** `internal/gateway/gateway.go:162-167`
- The client never sets `Accept-Encoding`, so Go adds `gzip` and transparently decodes it, clearing the header. That covers every honest upstream. But a response with `br`, `zstd`, `deflate` or a second encoding is passed through compressed: the redaction scans ciphertext, and the gateway drops the header, so the adapter receives bytes it cannot name.
- Hostile-only, and a hostile upstream already holds the key, so it does not block. But the package doc at `gateway.go:16-17` promises the replacement unconditionally, and the closure is three lines.
- **Fix.** In `forward`, after `client.Do`: if `resp.Header.Get("Content-Encoding") != ""`, close the body and refuse `{502, "encoding"}`, recording the status. Go has already removed the header for the gzip it asked for, so only unsolicited encodings are refused. Add a case to `TestAnEchoedCredentialNeverReachesTheAdapter` with an upstream that sets `Content-Encoding: br` and writes the key.

**M-2. The H1 split-chunk evidence rests on a scheduling race.** `internal/gateway/gateway_test.go:326-331`, `:343-348`
- The SSE case splits the key across two handler writes with a `Flush` between them. Whether the gateway's `io.Copy` sees two reads depends on the chunked reader: if the second chunk is already buffered when the first is read, one `Read` returns both, and the `keep := 0` mutation passes. The test never fails falsely, but its discrimination is not guaranteed under load.
- **Fix.** Extend the direct `redacting` test: `Write("data: fake-credential-0123")`, then `Write("456789 tail")`, then `Close`; assert the output contains the placeholder and not `0123456789`, and that `hit` is set. That is deterministic and also pins the hold-back length.

### Low

**L-1. `Content-Type` is forwarded verbatim, an unredacted header channel.** `gateway.go:162-164`
- A hostile upstream can put the value in a media-type parameter. Hostile-only.
- **Fix.** Parse with `mime.ParseMediaType` and forward the media type plus `charset` only, or run the value through the same replacement.

**L-2. The tail released at EOF can be up to `len−1` bytes of the key.** `gateway.go:208-215`
- A stream that ends mid-key, by error or by design, hands the adapter all but one byte. Honest upstreams do not truncate inside a key, and a hostile one already holds it, so acceptable for M1.
- **Fix.** In `Close`, if `held` is a prefix of the secret of at least 8 bytes, drop it and set `hit`. A coincidental prefix that long of a random key is negligible.

**L-3. The `credential_in_body` canary runs only in exit runs.** `gateway.go:274-277`
- Outside capture, a body carrying the key is sent. Sending it is harmless, since the upstream owns it. But a sandbox that knows the key is the strongest leak signal the controller can see, and today it is observed only under `--exit-record`.
- **Fix.** Move the check out of the `Capture != nil` branch, refuse as now, and record `credential_in_body` in `Observed.Refusals` so the exit map sees it.

**L-4. An empty value from a third-party `Secrets` store injects `Bearer `.** `gateway.go:263-273`
- `EnvSecrets` and the test store return `ok=false` for an empty value, but the interface only documents that. A store returning `ok=true` with `""` sends an empty bearer.
- **Fix.** In `forward`, refuse `credential_not_held` when `cred.Reveal() == ""`.

**L-5. The redaction matches the raw bytes only.** `gateway.go:188-205`
- A JSON encoder that escapes `/` (PHP's default) or `<>&` (Go's) breaks the match for a key containing those characters. API keys rarely do, and an AWS-style secret with `/` is the one honest case I can name. Base64, URL-encoding and masked echoes need a hostile upstream and are acceptable.
- **Fix.** Scan for the raw value and its JSON-escaped form when the two differ (`json.Marshal` of the value without the quotes, plus `/` as `\/`).

**L-6. No token expiry, and a running attempt can buffer 8 MiB per concurrent request.** `gateway.go:104-114`, `:247`
- A binding lives until `Unbind`; a forgotten one is dead only because the lease check refuses it, and the map entry stays. L6 moved the body read behind the lease check, so this is now the running attempt's own bound, not a stale token's. Acceptable here.
- **Fix.** Record for P22a in #226: `Unbind` on every attempt end, and a per-token concurrency cap on the socket listener.

**L-7. A non-ASCII registered hostname fails closed with a misleading code.** `internal/gateway/egress.go:59-65`
- `dialAddr` uses the host as written; Go's transport dials the punycode form, so the guard refuses the dial and the adapter sees `upstream_unreachable`. Operator configuration only, and closed.
- **Fix.** Either have P7's `endpointOK` refuse non-ASCII hosts, or apply `idna.Lookup.ToASCII` in `dialAddr`.

### The eight questions

**1. Credential exposure.** Nothing must block. The value reaches no log, error, event, refusal or capture: refusals carry fixed codes, `errNoEnvName` quotes nothing, `url.Error` carries no header, the capture is taken before injection, and only `Content-Type` of the response is copied. In the response body, the realistic echo is an honest upstream quoting the header in a 401, and that is now replaced with the hold-back of `len−1` bytes, which I traced as correct on both the match and the tail. Every remaining echo form needs a hostile upstream, and a hostile upstream already holds the key: the gateway cannot stop a party from encoding a secret it owns into a body it controls. So an encoded, base64, URL-encoded, partial or masked echo is acceptable for M1 as a stated residual. Compression: Go decodes the gzip it asked for and clears the header, so the honest case is covered; the unsolicited case is M-1. A mid-stream error: the status has gone, the held tail never holds a full match, and the adapter gets a truncated body with the status in the exit map. Acceptable, with L-2 as the sharpening.

**2. Egress binding.** Holds. The target is built from the registry's endpoint and a fixed path; the request's host, query and headers are never used, and the absolute-form test now proves it. Redirects are refused in `CheckRedirect` before the second request exists, with the 307 and the route refusal recorded, and the dial guard is the second layer. `Proxy: nil` ignores the environment. Pooled connections are keyed by `scheme+host:port`, so no cross-origin reuse, and h2 does not coalesce across authorities. DNS rebinding of a direct API ends at TLS verification with the default config. Local endpoints are IP literals with no zone, IPv4-mapped forms are read as IPv4, and link-local and CGNAT are refused. The entry 37 rule is enforced as written.

**3. Model binding.** Holds for what the gateway asks. The allowlist is exact and case-sensitive; duplicate keys collapse to one by the re-encoding; a `\u`-escaped key or value decodes before the compare; non-JSON, trailing data, null and arrays are refused; no header or query reaches the upstream. Streaming changes nothing, since the check is on the request. What the upstream then serves is its own honesty, which D48 does not claim to verify. If the exit map wants evidence, recording the response's `model` field in `Observed` is a P24 option, not a P11 gap.

**4. Lease and attempt binding.** Holds. Each call reads the lease afresh and requires `active`, a non-nil attempt equal to the bound one, and the executor from the lease, never from the request. A released, settling, superseded or other-unit attempt is refused, and the token is 256 random bits looked up by hash. Lifetime is L-6: it rests on `Unbind` and on the lease check, which is sufficient but should be recorded for P22a.

**5. Holds.** Sound now. `RuleCredentialRef` ties a reference to one origin, `RuleDestination` ties an origin to one destination id, and dispatch reads the reference and the destination from the same executor record it later compares (`boundTo`). It fails closed: an empty argument, a missing value, or a `_` reference gives `false`, and an error becomes a miss in `Observe`. The one wiring condition is that P22a hands dispatch and the gateway the same `Registry` value.

**6. Capture.** Exit-only by configuration, bounded by `maxBody`, taken from the re-encoded body before the request and the injection exist, with no header, under `ExpiresAt = now + P7D`. A failed record blocks the send. The class lives only on the record, which is #226 entry 54. L-3 is the one gap.

**7. Activation.** Nothing. No non-test Go file outside `internal/gateway` imports it; the only mentions are the dispatch doc comments, and `internal/api/sandbox.go` still makes its placeholder socket.

**8. Fault evidence.** The listed mutations discriminate: I traced M1, M3, M5, M6, M9, the redirect pair, the allowlist pair, the `_` collision, and the nil-secrets guard to the asserting lines. The H1 `secret` and tail mutations are deterministic. The split-chunk mutation discriminates in practice but through a race, which is M-2.

Not in this review: `internal/dispatch` comment changes and the registry rule beyond its correctness, which I checked, and the adapter's `base_url` shape (the prepare-params examples end in `/v1`, and the gateway serves `/chat/completions` only), which is P13's and P22a's to reconcile.
