# PR #38 (ContextManifest events): Astra reviews

## Review of #38 (Astra, 2026-10-04)

Verdict: NO-GO

1. **High — Compaction and unverified declarations can disappear into `complete` coverage.**  
   **Location:** `internal/knowledge/manifest.go:116–133,158`.  
   `Coverage` ignores delivery events’ `Compacted` and `Declarations` fields. It trusts the finalized record’s counts of declared-only and unobservable entries. Reproduced independently: a delivery with `compacted=true`, or an unverified declaration, passes `CheckFinalized` with empty coverage arrays and `status=complete`. This contradicts note 10, E0 and G7.

   **Fix:** Derive coverage from delivery evidence and reconcile the finalized arrays against it. Compaction must survive as unobservable coverage; unverified declarations must remain declared-only unless explicitly matched to controller evidence. Specify that matching rule so another implementation produces the same result.

2. **High — Controller-mediated deliveries can introduce unrelated context.**  
   **Location:** `internal/knowledge/manifest.go:84–93`.  
   `CheckDelivery` checks ref integrity and handle uniqueness but never connects the delivered ref to the intent’s inputs. The existing “valid manifest” fixture already delivers `f.x`, which is absent from `Inputs` and has empty lineage. Reproduced: intent, delivery and finalized validation all succeed, including `status=complete`. A correctly hashed ref does not establish the D40/G7 input boundary.

   **Fix:** Require delivered refs to belong to the declared inputs, or define and verify an explicit derivation from those exact inputs when rendering creates a new ref. Reject unrelated refs and update the positive fixture accordingly.

3. **High — Assembly is unconditionally counted as delivery, including refused egress.**  
   **Location:** `internal/knowledge/manifest.go:112–114`; `schemas/records/manifest-finalized.json:5`.  
   Every included input enters `delivered_refs` before any delivery evidence is examined. Reproduced with zero turns, no delivery events and `failed/routing_violation`—a registered reason meaning refusal before egress: `CheckFinalized` accepts the prompt refs as delivered with complete coverage. Recording the truthful `delivered_refs=[]` is rejected. This collapses the assembled/delivered distinction required by KA5/E0.

   **Fix:** Represent initial-prompt delivery evidence separately from intent. Derive delivered refs from evidenced prompt delivery plus controller-mediated tool deliveries. Specify known non-delivery and uncertain delivery separately; uncertainty must not become confirmed exposure.

4. **Medium — Turn consistency depends on whether coverage is already partial.**  
   **Location:** `internal/knowledge/manifest.go:129–138,158`.  
   The early partial return bypasses the delivery-turn bound check. Reproduced: `turns=1`, a delivery for turn 3 and a declared-only entry for turn 99 pass finalization as partial. Finalized declaration and unobservable turn numbers are never checked against the known total.

   **Fix:** Validate all turn references before deriving status. When the total is known, reject references outside `1..turns`, regardless of coverage status.

5. **Medium — Finalization accepts an invalid intent as assembled complete.**  
   **Location:** `internal/knowledge/manifest.go:150–158`.  
   Neither `CheckFinalized` nor `Coverage` calls `CheckIntent`. Reproduced: removing an omitted entry creates a silent cut rejected by `CheckIntent`, yet finalization still accepts assembled and overall coverage as complete.

   **Fix:** Validate the intent in the combined checking path, or require an explicitly validated intent type. Document validation prerequisites for any lower-level derivation helper.

The PR’s contract choices judge as follows:

- **`turns`:** Sound addition; nullable totals preserve unknown coverage. Turn consistency needs finding 4’s fix.
- **Status derivation:** Sound intended rule, but the evidence reconciliation in finding 1 is essential.
- **Delivered refs:** Identity digests and set semantics are appropriate; unconditional inclusion of assembled inputs is not.
- **Role/capability names and destination slugs:** Acceptable provisional choices without a role registry.

All fields explicitly shown in note 10 are represented. KA1’s live policy, destination and revocation checks remain runtime obligations; `CheckRef` establishes integrity, not delivery authorization.

`make ci` passed locally; shellcheck was skipped because it is not installed. Sandboxed scratch-copy probes reproduced all findings. The 23 mutation checks do not cover these missing invariants. The checkout remains unchanged at `e23fb73`.

## Second review of #38 (Astra, 2026-10-04)

Verdict: NO-GO

- **H1 — Fixed:** Compaction marks and declarations must survive into finalized coverage. Allowing supersets is conservative: extra entries cannot promote coverage to complete.
- **H2 — Partially fixed:** Unrelated refs and simple restriction stripping are rejected. The new derivation path still permits restriction loss through duplicate input IDs; see High below.
- **H3 — Fixed:** Assembly no longer implies delivery. `not_sent` requires zero turns and no deliveries; uncertain prompt delivery remains unknown.
- **M4 — Fixed:** Turn bounds are checked before status derivation, including declared-only and unobservable entries.
- **M5 — Fixed:** `CheckFinalized` validates the intent; lower-level helpers document the checked-intent prerequisite.

1. **High — Same-ID inputs can erase inherited restrictions.**  
   **Location:** `internal/knowledge/manifest.go:88–91,123–128`; `schemas/records/manifest-delivery.json:21`.

   `CheckIntent` permits distinct identity digests sharing a `Ref.id`, but `CheckDelivery` stores only the last input under that ID. A later unrestricted identity therefore hides an earlier restricted identity from lineage validation.

   **Reproduced:** Declare restricted and unrestricted refs sharing the same ID, then deliver a derived ref naming that ID without restrictions. `CheckFinalized` accepts `status=complete`. Reversing input order rejects the same delivery. This violates KA1’s restriction inheritance and leaves the schema’s derivation rule insufficiently specified for independent implementations.

   **Fix:** Reject ambiguous lineage IDs, or bind derivation to exact input identity digests. Alternatively, conservatively require restrictions from every input matching the lineage ID. Specify the chosen rule in the schema and add regressions covering both input orders and differing restriction snapshots.

2. **Medium — Possible delivery has conflicting aggregate and prompt-specific meanings.**  
   **Location:** `internal/knowledge/manifest.go:183–185,200–201`; `schemas/records/manifest-finalized.json:5,24`.

   With an uncertain prompt and a confirmed tool delivery of an included ref, validation requires that digest in **both** delivery arrays. Removing it from `possibly_delivered_refs` is rejected. This follows the top-level derivation rule but contradicts the field description, “neither confirmed nor ruled out,” leaving exposure consumers with conflicting semantics.

   **Fix:** Explicitly define this field as uncertainty about **initial-prompt delivery**, document that overlap is allowed and confirmed delivery establishes exposure, and add the overlap regression. If aggregate uncertainty is intended instead, subtract confirmed deliveries from the possible set and update the normative rule.

The High finding remains blocking. Live destination, policy and revocation checks remain runtime obligations; they do not resolve this structural inheritance defect.

`make ci` passed locally; shellcheck was skipped because it is not installed. Both new cases were independently reproduced in a sandboxed scratch copy. The checkout remains unchanged.
