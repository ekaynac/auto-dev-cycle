### Medium

**M1. A testing value reached through a struct field or an embedded `*testing.T` is not counted, and the residual does not say so.** `internal/accept/integrity_go.go:401-406`
- **Input:** `type suite struct{ t *testing.T }` with `func (s suite) check() { if … { s.t.Fatal(…) } }`. Or `type emb struct{ *testing.T }` with `e.Fatal(…)`. Removing the assertion is accepted at head and on main.
- **Cause:** `direct` requires `tval(sel.X)`, which is an identifier bound to a testing value, so `s.t` and an embedded value count as none.
- **Why it matters:** suite-style method helpers are a common shape, and the promise names method helpers.
- **Fix:** resolve the selector's type through `info.Types`. For `s.t`, take the field's type; for an embedding, take the method's receiver through `info.Selections`, to `*testing.T`, `B`, `F` or `TB`. Or state it in the residual.

**M2. A function literal inside a composite literal held by a package `var` is not compared, and that is not stated.** `internal/accept/integrity_helpers.go:102`
- **Input:** `var table = []struct{ name string; f func(*testing.T) }{{"one", func(t *testing.T) { if … { t.Fatal(…) } }}}`, ranged over by `TestTable` as `t.Run(c.name, c.f)`. Removing the assertion is accepted at head and on main.
- **Cause:** only a value that is itself a `FuncLit` is recorded; the walk reads the composite and then discards it.
- **Why it matters:** tables of closures are a standard pattern, and the promise covers "function literals held by package-level vars".
- **Fix:** record a `var`'s whole value as one function, keyed by the var's name and summed over the literals it contains. Or state it beside the residual's local-variable and field line.
