### Answers to the five questions

**1. Fail-open in the reservation: none found.**
- **Rounding:** `fit` = ⌊left × 10⁶ / max(price)⌋, computed in `big.Int` and saturated at `maxAmount`. The ledger prices tokens rounding up, so the price of `fit` never exceeds `left`, and `fit` + 1 does; the 2,401 → 600 row pins this.
- **Overflow:** `mulSat` saturates `context_tokens × expected_turns`. A saturated `attempt_cap` or `fit` is then refused by the group's capacity, or, if priced, by `usdRail`.
- **A price of zero:** it reserves `attempt_cap` at zero cost. The probe reserved 1,000 tokens under rails of 0 and 0, which is correct.
- **A missing or negative price:**
  - No price (nil) is unpriced, as on main.
  - A negative price cannot be loaded: `Amount` has minimum 0, and `registry.Load` validates against the schema. If one did get in, `ledger.priced` would refuse it, which is unaffordable, so `usdRail` would refuse it with the hold.
- **Output-only price:** priced at the higher rate, so it is refused at 0 micros left.
- **A fit exactly at the prior:** granted (the "exactly one turn" row). One token short is refused on the binding rail.
- **Both rails:** `tighter` takes the strictly smaller room and names the task's rail on a tie. `usdRail` then re-checks both rails with the reservation priced, so the two checks are consistent.

**2. Rails: counted as on main.** `spent` is unchanged. A refused launch releases its lease before any call, so it costs nothing, and a refused match records no lease. Liabilities are read as before.

**3. Regressions against main: none.**
- **The I8 change:** `Replaceable` now refuses an active old lease. Its only callers are `SupersedeAttempt`, through `StartNext`, and the fixtures.
  - No production path replaces an attempt under an active lease: the harness and the other fixtures call `StartAttempt`.
  - Replay does not re-check, so an existing history still folds.
- **The golden:** `f16-walk-demand` gains a revoke and a settle inside `nextAttempt`'s steps, and its golden file and test are unchanged and pass.
- **Inactive:** every new decision sits behind `Gates.Evaluates`, so the loop decides nothing new while launch is inactive.

**4. Bounded work: yes per pass, but growing with history (L2).** The loop has no hot spin in the code as written. An inconsistency between the clear and the match would spin it (L3).

**5. Stated false blocks:** incomplete. M1, L1 and L3 are not stated.

### Medium

**M1. A refusal without a hold leaves the build claimed and unheld, retried every pass. With two such builds, both are logged every pass.** `internal/daemon/place.go:47-51`, and `internal/reconcile/reconcile.go:405-441`
- **Cause:** `Place` raises a hold only when `Refused.Hold` is set. Several refusals carry none:
  - `data_floor`: no builder admits the policy, and `card` then falls back to `builders[0]` (`place.go:103`);
  - `destinations`, `capability` (no pinned image) and `independence`;
  - a priced builder under a profile with no USD rail (`usdRail`'s `precondition_failed`);
  - a reservation past the group's limit, refused by capacity.
- **Effect:**
  - The build stays `claimed` with no hold. Observe sees it as unplaced on every pass (every 5 s) and Decides a `Match` again.
  - The operator sees only a log line; the node and task reads show nothing.
  - `Loop.refused` deduplicates only against the last message. Two builds refused for different reasons alternate `l.last`, so both lines are written on every pass, without end.
- **Why it matters:** this is not a fail-open, and it does not reach (a) while launch is inactive. But the body states only "any other refusal is an error the loop logs". It does not state the indefinite wait, nor the log repetition.
- **Fix:** do both:
  - map the configuration refusals to a hold, as the missing-prior case already does: `source_invalid_config` naming the executor or the profile;
  - deduplicate refusals per action and subject (a set per pass), not against the last message.

  Or state both consequences in "Not here" or as a false block.

### Low

**L1. Only the first admitted builder is tried.** `internal/daemon/place.go:96-103`
- **Effect:** when that builder is over a rail or its group's capacity, a second admitted builder with room is never tried. The node is held on the rail, or waits (M1), even though another builder could run it.
- **Fix:** state it as a false block. Or try each admitted builder in id order, and raise the first builder's hold only if all of them refuse.

**L2. `spent` scans every lease in the store, now several times per action and every pass.** `internal/dispatch/usd.go:123`, called through `budget` at `reserve.go:49`, `reserve.go:76` and `usd.go:95`
- **Cause:** `Match` computes `budget` twice, once in `reservation` and once in `usdRail`. `ClearRail` computes it once per day-held node on every pass (`RoomToday`).
- **Effect:** each budget reads all leases ever recorded, so a pass costs O(leases × (unplaced + day-held nodes)) every 5 s, growing with history. Main scanned once per match only.
- **Fix:** pass the `spend` computed in `reservation` into `usdRail`. Index the leases by project and grant day, or by task, rather than scanning `LeaseProjection`.

**L3. The clear and the re-hold have no backoff, so any future disagreement between `RoomToday` and `Match` spins the loop.** `internal/dispatch/reserve.go:71-82`; `internal/reconcile/reconcile.go:386-389`
- **Cause:** each applied action nudges the loop. A `ClearRail` that clears, followed by a `Match` that raises the same hold, therefore runs a new pass at once.
  - The mutation "day room ignores the turn" shows it: `TestTheLoopPlacesTheBuild` reports "the loop never settles".
  - The code as written is consistent. Both sides use the same executor (`card`), the same `budget`, and the same price rule, and `usdRail` can refuse only where the reservation's fit already did.
- **Fix:** have `RoomToday` call `reservation`'s own computation (one function for the day's fit), so the two cannot diverge. Optionally, do not nudge after a pass that applied only `ClearRail` and `Match` raises.

### Judged as sound
- **The reservation's arithmetic:** the rounding, the saturation, the tie rule, the zero price and the one-turn floor.
- **The missing prior:** refused `precondition_failed` with `source_invalid_config` naming the executor. A local endpoint still reserves one slot.
- **I8 admission:** an active old lease is now refused at `SupersedeAttempt`, matching `dispatch.placed`.
- **The launch boundary:** `Observe` runs outside the writer, then `Launch` runs in one system command at the lease's revision read. The executor comes from the lease, not from the card.
- **ClearRail:** it runs only for `budget_rail` holds on the day's signal. A day with no room commits nothing (`errNothing`), and the cleared node is matched on the next pass.
- **Observe:** it walks the task's node index only, behind the launch gate.
