### Medium

**M1. Storage errors are reported as `ambiguous_state`** (`internal/graph/history.go:61`, `:74`, `:104`, `:123`)
- These lines return `errors.Join(err, refuse(...))` even when `err` is a decode or storage error.
- Because `ErrHistory` is in the joined error, `checkGraphHistory` (`startup.go`) matches `errors.Is(err, graph.ErrHistory)` first. A damaged `graph_holds` row, stop-projection row or node params then gives `ambiguous_state` where it should give `store_unreadable`.
- This is the same misclassification that `ErrNoEffect` was added to avoid (pr111).
- The daemon test checks `store_unreadable` only for an undecodable `graph_effects` row, so it misses these paths.
- **Fix:** at each site, return `err` alone when it is non-nil, and call `refuse` only on `!ok` or a mismatch. Add one unit case with an undecodable `graph_holds` value, asserting the result is not `ErrHistory`.

**M2. The attempt-existence rule belongs in the fold, not in CheckHistory** (`history.go:54-64`)
- CheckHistory is meant for links that replay cannot see, which means the effects table. The lease projections are themselves replayed, and graph folds after leases, so a lease projection edited behind replay is already a replay diff.
- `graph_preempted`: the supersede fold already checks `lease.AttemptOf` (`supersede.go:365`), so this half of the rule is redundant.
- `graph_attempt_results`: the `result.recorded` fold (`isolated`, `content.go:88`) does not check that the attempt exists. So CheckHistory refuses at start a history that this build's own fold admitted. That is what the M0 evidence fixtures show.
- It is unreachable in `adcd` today (no graph action is wired, and `Env.Contracts` is empty). It becomes a trap at P8a: if attempt binding (unit = node) admits a result whose attempt is not in `lease_attempts`, a store the controller wrote refuses to start.
- **Fix:** drop the rule from CheckHistory, or keep it for `graph_attempt_results` only and write it into P8a's row. P8a should make the `result.recorded` fold refuse an attempt not started by a lease bound to that node. Replay then covers it. If kept, the rule should check the binding (attempt → lease → unit → node), not only existence.

**M3. Lease holds have a null `id` and `since`, which departs from 15 D2's "one shape (id, owner, paging history)"** (`internal/api/holds.go:99`, `schemas/api/hold.json`)
- The shape is uniform at the schema level, and null is better than an invented id. But 15 D2 names an id, and P5 (`adc holds answer`) will need to address a hold.
- **Fix:** record the deferral in the design rather than only in the PR's open points. Either amend 15 D2, or add to P5's or P8a's row: "a lease hold records an id and since (on `lease.waiting`)".
- Going from nullable to always set is compatible for readers, so the schema can stay as it is.

### Low

**L1. No cross-project leak.** Node holds re-read their project by node id (`graph.ProjectOf`). Lease holds return a nil project, so only an every-project read sees them. One cost: a reader scoped to one project cannot see lease holds of its own work. After P8a, a lease's project is derivable from `Lease.Unit`, which is the node. Add a TODO for that.

**L2. The daemon-level fault evidence tells "skip CheckHistory" apart only by its diagnosis.** The forged `graph_effects` row also differs from replay, so without the check the start is still refused, through replay.
- This is enough to kill the mutation. It also proves the check runs before replay.
- The safety claim, that only CheckHistory sees the problem, rests on the unit test `TestCheckHistorySeesWhatReplayCannot`.
- **Fix (now or with the first wired effect kind):** add a daemon test that edits only the `effects` table, for example its `request_digest`. With CheckHistory skipped, `Start` would then succeed, so the test detects the mutation rather than just a different message.

**L3. The `internal/eventstore/effects.go` change is sound and minimal.** It adds a wrapped sentinel, keeps the message identical (`"eventstore: no effect <id>"`), and nothing else matches the old string. No change requested.

**L4. CheckHistory checks the hold index in one direction only.** It checks node → `graph_holds`, but not stale `graph_holds` entries that point at a node no longer holding the hold. That is acceptable because replay covers the index. A one-line comment would help.
