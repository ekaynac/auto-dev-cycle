# PR #58 (profile effective-change classifier): Astra reviews

## Review of #58 (Astra, 2026-10-05)

Verdict: NO-GO

Review target: `77e50bd`. One High finding blocks merge.

1. **High — Inherited usage can widen without confirmation.** `internal/authority/classify.go:28–40,66`  
   `nil` ranks above every explicit profile. Consequently, changing `usage_profile_override` from `null` to `standard` or `open` returns no class, although the installation may supply `on-prem`. Once connected to `Decide`, this lets a supervisor with `profile.adopt` permission bypass the required human confirmation. Sandbox probes reproduced both omissions using profiles accepted by the current validator.  
   **Fix:** Resolve inherited usage against the installation’s effective policy before comparing. Without that context, conservatively classify null-to-explicit transitions that could widen usage. Add regression tests for inherited `on-prem` → `standard`/`open` and inherited `standard` → `open`.

2. **Medium — Derived destination widening is omitted.** `internal/authority/classify.go:69`  
   With both destination lists empty, `standard` → `open` returns only `policy.widen_data`, even though destinations derive from usage and may expand. First-profile classification has the same omission for derived destinations. Existing human confirmation prevents a separate approval bypass, but the returned effective-change classes are incomplete.  
   **Fix:** Compare resolved destination sets, or conservatively add `policy.widen_destinations` when derived destinations may expand. Test empty-to-empty usage changes and first adoption.

3. **Medium — Unknown routing does not consistently rank widest.** `internal/authority/classify.go:72`  
   `reported_ok` → an unknown routing value returns no protection class, contrary to the PR’s unknown-widest contract. Schema validation rejects such values, so this is non-blocking under validation-before-adoption.  
   **Fix:** Reject invalid classifier inputs explicitly, or rank routing as `verified < reported_ok < unknown`. Uncommitted edits observed during review implement the latter; they are absent from the reviewed commit.

The explicit floor ordering, set comparisons, conservative pattern-by-pattern protection, topology comparison, and strongest-policy selection are sound. Schema constraints ensure switching integration plugins also changes topology. Excluding budget rails matches the stated M0 registry; paid-fallback flags, grants, enrolled agents, and knowledge export are not profile fields. The first-profile baseline is otherwise a defensible conservative choice.

**Validation:** `make ci` passed on an isolated checkout of `77e50bd`; ShellCheck was skipped because it is unavailable locally. Existing classifier tests passed. Temporary regression probes reproduced findings 1 and 2. No review changes were made to tracked files.
