### 2. The retry policy
- **Spin:** none. With the gateway always down, `retryBase` at 20 ms, and an external nudge every 50 ms for 3 s, it placed **5 leases**, then held at `runner: failed`. Unblock of a retry hold whose time has not come changes nothing (`errNothing`), so the loop does not nudge itself.
- **Clear early:** no. `cleared` compares the command's `tx.Now()` with the recorded `until`, and the time has no spaces, so `Sscanf`'s `%s` reads all of it.
- **Never clear:** only `runner: failed`, as stated. A simulated restart (the count reset) leaves `runner: failed` held, because nothing clears it. That matches the body: the count restarts, the hold does not, and the recovery is to revoke the approval.
- **Misclassification:** see L2 and L3 below. Neither spins, and neither releases what should hold.

**L3. A wrong repository URL counts as transient.**

- **Fix:** when profile changes land, let a profile change clear `runner: failed` too.

**L4. The retry count can run ahead of the hold** (`run.go:480`).
- `tries[node]++` happens inside the command's logic. If that command then rolls back, for example on a `graph.Raise` error or a stale write, the count has advanced with no hold written.
- The effect is a shorter retry budget.
- **Fix:** increment after the command applies, or derive `n` from the hold being replaced.
