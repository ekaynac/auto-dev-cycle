### High

**H1. A record whose decisions were edited still qualifies. The report digest checks the file's bytes, but never the decision inside it.** (`internal/qualify/qualify.go:259-265`)
- **Input:** an all-go run's real reports, each saying `"decision":"go"`, recorded with `Decision: c.Expect` for every case. I ran this as a probe: `Check` returned `nil`.
- **The same gap allows a reused report.** A report holds no case or prompt binding, so a no_go report from another case, run or route can fill any slot. `TestCheck`'s fixture reports are fake bytes (`qualify_test.go` `outcomes`), so nothing exercises this.
- **Fix:**
  - In `check`, decode each report strictly as `adc.review-report/v1`.
  - Require `report.decision == rc.Decision`, with `""` standing for `none`.
  - Require the roster to be exactly `[{route.Executor, route.Family}]`.
  - Require `charge_links` to differ between cases.
  - Make `TestCheck` build its reports with `review.Report`, and add rows for "decision edited, report unchanged" and "another case's report".

### Medium

**M1. `PromptDigest` covers the template constant, not how the prompt is rendered.** (`internal/review/prompt.go:54-57`, `:86-87`)
- **Input 1:** I replaced the gate line with a constant and cut the diff to 10 bytes. `PromptDigest` stayed `sha256:879071bd…`, so an old record would still qualify a different prompt.
- **Input 2:** the mutation "digest computed over `""` instead of the template" survives the tests. Nothing pins the digest: `TestPrompt` only checks the `sha256:` prefix (`qualify_test.go:241`).
- **Fix:** compute `PromptDigest` from the rendered output of `Prompt` on a fixed input, once green and once red, together with the bounds. Add a test that pins its value, so any change to the prompt forces a deliberate update.

**M2. The suite digest leaves out the prompt's inputs from go-mini.** (`internal/qualify/qualify.go:105`, `digestDir`)
- Only `fixtures/m1/review-qualification/` is hashed. The requirement (`fixtures/t0/go-mini/tasks/*/task.json`), the base `repo/` and the `visible/` overlay, which decides the gate counts, are not.
- **Input:** I rewrote `go-mini-feature-1`'s requirement to `"Anything at all."`. The digest did not move.
- **Fix, two options:**
  - Hash `repo/`, `visible/` and `task.json` for each task into the suite digest.
  - Or better, put a `prompt_digest` for each case in `suite.json`. `TestPromptWithholds` would check it against `sha256(s.Prompt(c))`, and `QualifiedCase` would record it. Any drift in the prompt then fails CI until `suite.json` moves, which makes every record stale. This also covers M1.

**M3. Any qualifying record wins, so a newer failing run does not take the qualification away.** (`internal/qualify/qualify.go:222-228`)
- **Input:** `2026-10-20-exe.json` qualifies and `2026-11-02-exe.json`, on the same route, prompt and suite, scores 4 NO-GO and 1 GO. `Check` returns `nil`.
- One run per case also lets a reviewer whose decision ignores the case qualify with up to 2.3% chance per run (when it says no_go 61% of the time). Re-running until a record passes defeats the bar.
- **Fix:** among records that match the route, prompt and suite, judge only the latest `ran_at`, so a failing latest run leaves the route unqualified. Add a `TestCheck` row for this.

**M4. `TestPromptWithholds` does not check the diff, which is the prompt's only free-text field.** (`internal/qualify/qualify_test.go:195`)
- The diff is added to `shown`, so any restricted line the diff carries is excluded from the leak check.
- **Input:** I appended `lowstock_hidden_test.go` lines 1-26 (the whole `TestHiddenLowStockExcludesItemsAtThreshold`) to `control-lowstock/candidate.patch` as a new file. The row passed.
  - Appending the whole file trips the row's own control instead ("a restricted file in the prompt goes unseen"), so it is caught only by accident.
- **Fix:** build `shown` from `repo/` and `visible/` only. Separately assert that no patch and no requirement holds a distinctive restricted line.
- Also say in obligation P22a-6 (`docs/design/m1/01-invariant-inventory.md`, the qualification paragraph) that `PromptInput.Diff` is base to candidate, taken before any acceptance overlay. Optionally, `Prompt` could refuse a diff whose `diff --git` header names a withheld path.

**M5. `TestRoute` never checks that the prompt reaches the provider.** (`internal/qualify/route_test.go:61`)
- The scripted upstream reads the user message and ignores it, answering from the case in the loop.
- **Input:** the mutation `Prompt: []byte("Review the change.")` at `route.go:144` survives every test.
- **Fix:** assert that each recorded request's last user message equals `prompts[c.ID]`, or reply from a lookup keyed by the prompt.

**M6. The route's identity leaves out the reviewer-side settings, which the PR says belong to the route.** (`internal/qualify/qualify.go:170-172`, `route.go:143`; `adapters/http-chat/src/adapter.ts:39-44`)
- The reviewer's system message, `defaultDecisionSchema` and the `MaxOutputTokens: 8000` / `MaxTurns: 1` limits are not bound by `QualifiedRoute` or by any digest.
- **Input:** edit the reviewer system message in `adapter.ts:44`. Every record still qualifies.
- **Fix:** add a `reviewer_digest` that covers the system message, the decision schema and the limits. Export them from one place, and bind that digest in the record (or fold it into `PromptDigest`). Make P22a-6 require the same limits.
