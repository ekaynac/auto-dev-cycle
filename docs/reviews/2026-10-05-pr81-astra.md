# PR #81 (conformance kit, part 1): Astra reviews

## Review of #81 (Astra, 2026-10-05)

Verdict: NO-GO

The six existing tests and TypeScript check pass. Additional raw-adapter probes reproduced false greens, false rejections, an uncaught process error, and a deadline escape. Tests ran inside bubblewrap with the checkout read-only; no files were modified.

### High

1. **Adapter-controlled errors can crash the runner.**  
   `adapters/conformance/src/kit.ts:55`, `:58`, `:73`, `:99`  
   Closing stdin while `oversize()` writes causes an unhandled `EPIPE`, terminating Node. Spawn failure similarly produces an unhandled `ENOENT`. Sending the valid JSON value `null` eventually makes `checkSession()` throw instead of returning findings. Event callbacks also inspect unvalidated parameters.

   **Fix:** handle child and stream errors, validate message envelopes before storing or dispatching them, and guarantee cleanup and structured findings on every failure path.

2. **The deadline does not bound session lifetime, and output retention has no memory bound.**  
   `adapters/conformance/src/kit.ts:53`, `:60`, `:70`, `:78`, `:88`  
   The timeout kills only the immediate child. An adapter can spawn a descendant inheriting stdout and exit; the iterator then waits indefinitely because the descendant keeps stdout open. A sandboxed probe remained pending beyond three shortened deadlines. Separately, every message and parsing failure is retained; the 16 MiB *per-message* limit does not prevent a flood from exhausting the runner’s memory before its timeout.

   **Fix:** make deadline expiry settle the session independently of EOF, terminate the process tree, destroy streams, and impose aggregate byte/message/finding limits with bounded diagnostic retention.

3. **Missing RPC correlation and result validation allow fabricated round-trips to pass.**  
   `adapters/conformance/src/kit.ts:65`, `:80`, `:99`, `:140`  
   Reproduced green results for:
   - no `prepare` response and an invalid shutdown result;
   - `jsonrpc: "WRONG"`;
   - two results for id `3`;
   - a shutdown response emitted before shutdown was requested.

   Only the first matching response is examined. `prepare` is never checked; shutdown merely needs a truthy result. Requests are pipelined before preparation succeeds, imposing behaviour the SDK’s serial dispatcher happens to accommodate.

   **Fix:** maintain outstanding-request state; validate JSON-RPC envelopes and every method result; reject unsolicited, duplicate, and contradictory replies; sequence preparation and execution correctly; enforce notification boundaries around the run.

4. **The mediated-tool check accepts invented delivery evidence.**  
   `adapters/conformance/src/kit.ts:152`, `:160`  
   A raw adapter passed with a result naming the wrong tool and no `tool.response` acknowledgement. Another passed after emitting its claimed delivered handle **before** the controller supplied it. The check only finds any request and the first mediated result containing a predictable handle. It does not correlate tool, turn, request, response, ordering, or repeated deliveries.

   **Fix:** track pending tool exchanges, enforce the supplied policy, use distinct delivery handles, and correlate each acknowledgement and result with the actual delivery. Compare handle fields structurally: `JSON.stringify` also falsely rejects an identical handle whose object keys appear in a different order.

5. **Cancellation both changes the contract and accepts an untested cancellation.**  
   `adapters/conformance/src/kit.ts:168`, `:179`; `adapters/conformance/test/kit.test.ts:27`  
   Requiring every cancelled run to return `could_not_run` contradicts 09’s “best effort, never relied on.” A run can complete despite cancellation; 13 requires completion and changes to be determined from observed facts, not inferred from a cancel request.

   Conversely, `cancel()` returned green for an adapter that emitted no event, received no cancel, and returned a schema-invalid object containing only the expected outcome and a forged result. It skips ordinary session validation and never checks the cancel response.

   The alleged “cancel during a tool call” proof supplies no mediated tool policy and cancels on the first non-heartbeat event, rather than establishing a pending tool request.

   **Fix:** verify that cancellation was actually exercised, validate its reply and the complete session, and test completion races and interrupted execution separately. For the tool case, authorize the tool, wait for its request, then cancel while its response is pending. Keep controller completion/partial-work derivation separate from adapter cooperation.

6. **The oversize check can report green without proving rejection.**  
   `adapters/conformance/src/kit.ts:188`  
   It checks only for a **truthy** result at id `7`, discards framing findings, and otherwise accepts the session. A raw adapter answering the oversized request with `result: false` passed. Silently discarding that request and processing subsequent requests also passes without demonstrating the documented error-or-termination behaviour.

   **Fix:** require an observable permitted rejection, reject any successful result regardless of truthiness, preserve output-framing failures, and test the size boundary independently of other request-invalidity causes. Add a deliberately size-blind raw adapter as the red control.

7. **Turn and coverage bookkeeping admits contradictory streams.**  
   `adapters/conformance/src/kit.ts:121`  
   Turns never close, and another start overwrites their counters. Duplicate ends, data after an end, and a second coverage declaration after the end all passed. Consequently, the advertised “one coverage per completed turn” invariant is not enforced.

   The inverse is also too strict: one coverage declaration following `turn.end` is rejected, although 09 and the event schema do not specify that coverage must precede the end.

   **Fix:** maintain explicit turn histories and identities, reject duplicate lifecycle transitions, and check completed-turn coverage totals across the run. Enforce documented ordering; make any additional ordering requirement explicit in the contract before imposing it.

### Medium

8. **The heartbeat check measures arbitrary traffic instead of heartbeats.**  
   `adapters/conformance/src/kit.ts:126`  
   A 12-second run emitting other events but no heartbeat passed. The marks also include traffic after the first run result, and the effective threshold is 11.5 seconds rather than the specified 10 seconds.

   **Fix:** track heartbeat timing over the actual active-run interval with a monotonic clock. Distinguish scheduling tolerance in tests from the adapter’s contractual emission interval.

9. **Valid call-level usage is rejected.**  
   `adapters/conformance/src/kit.ts:116`  
   `UsageEvent.sub_call` explicitly permits `null`. The kit demands that `null` have been announced by `call.sub`, which cannot announce it. This false rejection was reproduced.

   **Fix:** require announcement only for non-null sub-call labels. Keep usage numbering call-wide: the single sequence counter is appropriate for this one-call session, including when sub-calls change.

10. **Ordinary stderr logging can block an otherwise conforming adapter.**  
    `adapters/conformance/src/kit.ts:52`  
    Stderr is piped but never consumed. A synchronous 1 MiB log write blocked a raw adapter until the deadline killed it. Stderr logs are expressly allowed by 09.

    **Fix:** continuously drain stderr, retaining only bounded diagnostics or writing to a bounded sink.

11. **The red-proofs do not establish the advertised check coverage.**  
    `adapters/conformance/test/kit.test.ts:33`, `:37`, `:89`  
    The oversize test has only a green control. There are no targeted red controls for missing/invalid preparation, response correlation, turn ordering, envelope identity, or duplicate coverage. `broken-event → run` proves SDK rejection reaches the kit; the separate raw invalid-event case correctly tests event validation. The cancellation negative control encodes the incorrect cancellation rule.

    **Fix:** add a minimally broken raw adapter for each invariant, paired with a conforming control, and assert the intended finding. Include lifecycle/resource failures and verify that cancellation/tool fixtures actually reach their claimed state. Mutation kills cannot establish correctness when the assertion encodes the wrong contract.

12. **Additional contract checks are absent without being listed as deferred.**  
    `adapters/conformance/src/kit.ts:101`, `:115`, `:123`  
    Beyond the gaps above, the kit accepts a different contract major and does not check the required partial coverage for observed compaction or harness-internal tools. Compaction followed by `observable: "complete"` passed a raw probe.

    **Fix:** implement these checks or explicitly identify their ownership and deferral in the [PR description](https://github.com/ekaynac/auto-dev-cycle/pull/81). Its existing deferrals cover error derivation, ingestion/fencing, patch boundaries, and hostile repositories; they do not cover these omissions.
### Lead notes on round 1 (applied)

**Scope narrowed.** Part 1 is now the round-trip alone, rebuilt for an untrusted adapter. The mediated-tool, cancel and
oversize cases (findings 4–6) move to part 2, where they will be rebuilt on this runner:
- tool: exchanges tracked and correlated by tool, turn and request, with distinct handles compared structurally;
- cancel: the cancel must actually be exercised, its reply and the whole session validated, and completion races
  allowed (09: best effort);
- oversize: an observable rejection required, with a size-blind raw adapter as the red control.

- **1, crashes:**
  - Spawn errors become findings, and writes to a closed stdin are ignored (the missing reply is the finding).
  - Every line is checked as a JSON-RPC envelope before anything reads it: an object, `jsonrpc: "2.0"`, either a
    response (numeric id, exactly one of result and error) or an `adapter.event` notification.
- **2, lifetime and memory:**
  - The adapter runs in its own process group. The deadline kills the whole group, destroys the streams and settles
    every wait, without waiting for end of output.
  - Output has aggregate byte and message bounds; findings are capped at 100 and details at 500 characters.
  - Tested with a descendant holding stdout after the adapter exits: the session settles at the deadline, and the
    descendant is gone afterwards. A flood is cut at the output bound.
- **3, correlation:**
  - Requests are sent one after another (describe, then prepare, then run, then shutdown).
  - Outstanding requests are tracked: a reply to an unasked id or a second reply is `correlation`.
  - Every reply is validated against its schema, prepare and shutdown included; a refused prepare is a finding.
  - Events outside the run window are `run-boundary`.
- **7, turns:**
  - Each turn has an explicit lifecycle. A second `turn.start`, or data after `turn.end`, is `turn-order`.
  - Coverage may come before or after the end, but a completed turn needs exactly one.
  - A turn with a compaction or a harness tool result must declare `partial` with that cause (from finding 12).
- **8, heartbeats:** only heartbeats count, on a monotonic clock, from the run request to its answer. The contract
  interval (10 s) and the scheduling tolerance are separate limits; the test uses 1 s and 200 ms.
- **9:** a `null` sub_call needs no announcement; usage numbering stays call-wide.
- **10:** stderr is drained into a bounded tail. A 1 MiB stderr write passes.
- **11, red controls:** `test/raw-adapter.cjs` is an adapter written without the SDK, with one mode per broken rule.
  Each mode pairs with the clean one and asserts exactly its finding:
  - an invalid event; a bad envelope; an unasked reply; a duplicate reply; an invalid shutdown result;
  - a wrong major; an event after the run;
  - a duplicate start; a duplicate end; data after the end; two coverages; compaction declared complete; a harness
    tool declared complete;
  - a nonzero exit; silence between heartbeats.
  - Resource attacks: no prepare reply, a closed stdin, a descendant, a flood, and a command that cannot run.
- **12:** the contract major is checked (`version`), and partial coverage is enforced as above.
- **Mutation:** 19 points, all killed. They cover every check, the process-group kill, the output bound, stderr draining, the deadline, and shutdown and exit validation. Three first survivors were weak assertions: duplicate replies are now asserted by detail, the byte bound by detail, and the stderr flood is a synchronous write that blocks on a full pipe.

### High

**13. A notification without `params` still crashes the public operation.**  
`adapters/conformance/src/kit.ts:162`, `:228`

During the run, send:
```json
{"jsonrpc":"2.0","method":"adapter.event"}
```
The runner stores `undefined` as the event. Validation fails, but formatting its finding calls `JSON.stringify(undefined).slice(...)`. Reproduced rejection: `TypeError: Cannot read properties of undefined (reading 'slice')`. Outside the run, line 164 has the same unsafe formatting.

**Fix:** validate notification parameters before storing them, make diagnostic formatting safe for every value, and add missing-parameter controls inside and outside the run.

**14. EOF or framing failure disables cleanup, leaving processes and timers alive.**  
`adapters/conformance/src/kit.ts:105`, `:143`, `:146`, `:201`

`read()` sets `closed = true`; every subsequent `stop()` then returns before clearing the timer, killing the group or destroying remaining streams.

Reproduced:

- An adapter completes the RPC exchange, closes stdout and stays alive. With a 300 ms deadline, `roundTrip()` returns after approximately **5 seconds**, with the adapter still alive.
- An adapter emits **16 MiB + 1 byte** without a newline and stays alive. Framing correctly rejects it, but cleanup leaves it running.
- A clean adapter returns `[]`; after its 200 ms deadline, that **same returned array gains a deadline finding**.

**Fix:** separate input completion from cleanup completion. Every terminal path must execute idempotent cleanup, cancel timers and settle waits within the session deadline. Finalize findings before returning. Add EOF, framing-error and post-return stability tests.

**15. An unprivileged descendant can escape the process-group kill.**  
`adapters/conformance/src/kit.ts:80`, `:109`

An adapter spawns a detached descendant inheriting stdout, then exits. The descendant creates its own session; killing `-adapter.pid` cannot reach it. With a 300 ms deadline, the runner returns findings while the descendant remains alive. The otherwise identical same-group control is killed.

**Fix:** use runner-controlled process containment whose membership the adapter cannot escape, such as a supervised PID namespace or appropriately delegated cgroup. Terminate and reap that containment on every completion path. Add a detached-descendant control; killing only the original process group cannot enforce the stated boundary.

### Medium

**16. Signal termination passes the “exit 0” check.**  
`adapters/conformance/src/kit.ts:82`, `:304`

A raw adapter answers shutdown, then terminates itself with `SIGTERM`. Reproduced result: `[]`. The exit handler discards the signal, and the final check accepts `code === null`.

**Fix:** preserve `{code, signal}` and require an observed normal exit with code zero.

**17. Heartbeat timing confuses reader stalls with adapter silence and omits aborted runs.**  
`adapters/conformance/src/kit.ts:163`, `:191`, `:278`

With heartbeats emitted every 30 ms, a 250 ms runner event-loop stall produced a **272 ms heartbeat-gap finding** against an 80 ms test bound. These timestamps measure processing time, not emission time.

Separately, a run that never answers leaves `runWindow.to` null, so heartbeat checking returns immediately. The deadline still makes the session red, but the active interval is not checked.

**Fix:** track reader scheduling delays and distinguish inconclusive timing from adapter silence. Close the run window on termination as well as reply, and test both stalled-reader and unanswered-run cases.

**18. Required partial coverage accepts `none`.**  
`adapters/conformance/src/kit.ts:269`

Both compaction and harness-tool probes pass with:
```json
{"observable":"none","unobservable":["compaction"]}
```
(using `harness_tool` for the second probe). The condition excludes `complete`, rather than requiring `partial`.

**Fix:** require `observable === "partial"` together with the observed cause, and add both negative controls.

The exercised deadline/reply races and a reply arriving after `stop()` did not erase the failure. Findings truncation also retained a red result: 100 existing findings remained, although later diagnostic categories were omitted. These checks add no further blockers.
### Lead notes on round 2 (applied)

- **High 13 (missing params):** an `adapter.event` needs object `params`, or it is an `envelope` finding, inside the run
  and outside it. Every diagnostic goes through `show()`, which formats any value. Controls: no params inside the run
  and before it.
- **High 14 (cleanup):**
  - End of input and cleanup are separate states. `stop()` is the one idempotent cleanup path: it closes the run
    window, cancels the deadline, kills, destroys the streams and settles every wait.
  - A framing error stops the session at once. `end()` never waits past a stop.
  - A case returns a fixed copy of its findings, and nothing is added afterwards.
  - Controls:
    - an adapter that answers, closes stdout and lingers is ended at the deadline;
    - 16 MiB + 1 byte without a newline ends the session in under 2 s with a framing finding;
    - the findings a clean case returned are unchanged 2.5 s later.
- **High 15 (escape):** the adapter runs in its own PID namespace (`bwrap --unshare-pid --die-with-parent`, files and
  network shared). When the adapter exits or is killed, the namespace and everything in it ends, whatever sessions or
  groups its descendants made. Controls: a descendant in the adapter's group and a detached one (`setsid`), each
  holding stdout. The session ends promptly and no descendant survives, checked by a marker on the `sleep` processes'
  arguments. Removing containment lets the detached one survive, and the test is red. Nested bubblewrap works inside
  the test sandbox; without bubblewrap the kit reports `spawn`.
- **Medium 16 (signal exit):**
  - The exit keeps `{code, signal}`, and only a normal exit 0 passes.
  - Under containment, bwrap reports a child killed by a signal as exit code 128+n, so the code check catches it; the
    control is an adapter that SIGTERMs itself after shutdown.
  - The `signal` branch only matters for a direct spawn, so its mutation is equivalent here.
- **Medium 17 (heartbeats):**
  - The run window closes at termination too, so an unanswered run's silence is checked. Control: a run that never
    answers and never beats.
  - An event-loop delay monitor runs during the run. If the kit itself stalled beyond the tolerance, heartbeat gaps
    are reported as `inconclusive`, not as the adapter's fault. Control: the test blocks the kit for 400 ms while the
    adapter beats every 30 ms.
- **Medium 18 (none):** a turn with a compaction or a harness tool must declare exactly `partial` with the cause.
  Controls: `none` for each.
- **Mutation:** 24 points. 22 are killed, including containment, the params check, the framing stop, the run window
  at stop and stall detection. Two are equivalent and recorded: the findings freeze (nothing can add a finding after
  `stop()`, so the copy is defence in depth) and the signal branch (see 16).

All nine tests and the TypeScript check passed. Missing bubblewrap and restricted user namespaces return findings without falling back to uncontained execution. No repository files were modified.

### High

**19. Shared launch services bypass the PID namespace’s lifetime boundary.**  
`adapters/conformance/src/kit.ts:74`, `:138`

The adapter retains the caller’s network namespace and filesystem sockets. It can ask an ordinary same-user service outside its PID namespace to launch work there.

Reproduced using a disposable, unprivileged launch broker on an abstract Unix socket, entirely inside the outer review sandbox. The adapter requested a `sleep` process, completed the protocol, and exited. **`roundTrip()` returned `[]` while the requested process remained alive in the broker’s PID namespace.** The probe then killed it. No elevated privileges or host service modifications were involved.

This fixes direct descendant escape but does not establish the claimed containment against the D43 adversary.

**Fix:** prevent access to local execution brokers outside the controlled lifetime boundary. Isolate abstract sockets with a private network namespace, exclude filesystem service sockets through explicit mounts, and mediate any required external services. Add a same-user delegation regression.

### Medium

**20. One scheduling stall suppresses every heartbeat violation in the run.**  
`adapters/conformance/src/kit.ts:353`

Reproduced a **1,002 ms heartbeat silence** with a **121 ms kit stall**, using a 100 ms heartbeat interval and 50 ms tolerance. The only finding was `inconclusive`, although the stall cannot explain the entire violation. The run-wide maximum also suppresses gaps unrelated to the stall.

**Fix:** track scheduling-delay intervals and evaluate their overlap with each heartbeat gap. Preserve a heartbeat violation when the unexplained interval still exceeds the bound. This remains nonblocking because `inconclusive` does not return green.

**21. Successful exit can beat final output validation.**  
`adapters/conformance/src/kit.ts:188`, `:266`, `:380`

`end()` waits for process exit without waiting for the reader to finish. Cleanup can then suppress the reader’s pending framing error.

A conforming exchange followed by a trailing `{` after the shutdown reply returned **green in 25 of 50 runs**. A trailing invalid UTF-8 byte also intermittently passed. Complete duplicate shutdown replies were consistently rejected in the exercised probes.

**Fix:** on normal completion, await both process exit and reader completion within the existing deadline before finalizing findings. Keep forced cleanup immediate on failure.

**22. Raw output limits permit substantial heap amplification.**  
`adapters/conformance/src/kit.ts:202`, `:214`; `adapters/contract/src/strict-json.ts:42`

Four events containing 4 MiB padding strings—approximately 16 MiB total, below the configured limits—aborted the runner with V8 out-of-memory under a **512 MiB heap limit**, instead of returning findings. The strict parser constructs strings character by character, and the kit retains events before schema validation. This was not reproduced against this host’s approximately 4.2 GiB default heap.

**Fix:** avoid character-by-character string allocation, validate events before retaining them, and budget retained parsed data as well as wire bytes. Add a bounded-heap resource regression.

### Medium

**23. Closing the stall watch discards an overdue final sample.**  
`adapters/conformance/src/kit.ts:135–144`, `:261–263`

If the run reply is processed before the overdue interval callback executes, `watchStalls(false)` clears the timer without recording the outstanding delay.

An in-memory probe injected a 250 ms synchronous reader stall immediately before routing a conforming run reply. With a 150 ms heartbeat bound, the result incorrectly reported `heartbeat`, attributing **0 ms** to the kit’s stall; the recorded stall list was empty.

**Fix:** retain the last sampling timestamp and sample through the run’s closing timestamp before disabling the watch, including on `stop()`. Add a regression where the final reply precedes the overdue timer callback.

**24. Early exit disables deadline settlement while reader completion remains pending.**  
`adapters/conformance/src/kit.ts:280–286`

`this.exited.then(() => clearInterval(poll))` cancels the stop observer, although `done` now also requires `readDone`. If the reader never finishes, deadline cleanup cannot resolve this race; it waits for the shutdown grace instead.

With an intentionally never-settling reader-completion test double, the process exited at approximately **58 ms**, deadline cleanup ran at **305 ms**, but `roundTrip()` returned at **5,056 ms**. It additionally claimed the process had not exited.

**Fix:** race against a promise resolved directly by `stop()`. Keep cancellation effective until both exit and reading finish, and distinguish reader timeout from process-exit timeout.
