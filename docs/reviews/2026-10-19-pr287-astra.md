Reviewed `a2a63b9` against `origin/main` `79c03f6`, the PR description and Round 2, the slice-plan rows, and the requested review records. Read-only; no tests or mutations run. The adversarial child/container inputs below are fault-injection cases, not a claim that candidate source already permits arbitrary execution in either process.

1. **High — The child’s output bound does not bound controller memory.**  
   `internal/accept/integrity_proc.go:163`

   **Input:** a child sends a valid gob message containing `Changes` with `32<<20` zero-valued entries. Gob represents each empty struct compactly, so the message fits comfortably below `maxProcOut`. Decoding nevertheless allocates approximately **3.5 GiB** for those entries, before the controller even examines `Op`. The controller decodes fields that are not legal in a child request.

   `io.LimitReader` bounds encoded bytes, not decoded allocation. Killing the child or raising its OOM score does not protect memory allocated by the controller.

   **Fix:** use bounded, operation-specific messages with counts and lengths checked before allocation. Reject controller-only fields in child messages. Add an allocation-amplification input; the current 64-byte output-limit row tests truncation only.

2. **High — Copied archives and listing errors are trusted without establishing that they describe the requested types.**  
   `internal/accept/integrity_loader.go:174`, `internal/accept/integrity_loader.go:181`; `internal/accept/integrity_types.go:489`

   **Input A:** retain a valid export filename but put `"cache failure"` in that package’s error column. `boxList` returns both `Error` and `Export`; `lookup` ignores the error whenever `Export` is nonempty. The ordinary candidate can pass despite the explicit loader failure.

   **Input B:** for a dependency whose current `Holder` contains a `testing.T` value, supply a valid archive from an older version where `Holder` is empty. Keep the package path and toolchain version consistent. A candidate adding `var h dep.Holder` is then checked against the harmless type, losing the fabrication block that correct exports produce. The controller checks only that the basename names a regular copied file. It neither verifies the claimed content hash nor binds that archive to the requested module version/platform.

   **Fix:** reject error-bearing and contradictory entries, duplicate package entries, and invalid archive names; verify content hashes. Establish a trusted binding between the request and its export manifest—hash verification alone does not prevent substitution of another valid archive. Add both failure inputs to the loader rows.

3. **High — The whole-run deadline does not bound controller-side guard work.**  
   `internal/accept/integrity_proc.go:116`, `internal/accept/integrity_proc.go:165`, `internal/accept/integrity_proc.go:214`

   **Input:** run with `context.Background()` and a Reader that waits for its supplied context to end before returning. Once the child requests a blob, the controller enters `serve` with the original context. At `maxRunTime`, `CommandContext` kills the child, but the Reader remains blocked indefinitely. The deferred `Wait` and directory removal are never reached: the dead child remains unreaped and its run directory remains.

   A stalled `listBase` also occurs before the whole-run timer starts.

   **Fix:** establish the deadline at entry to `Integrity`, propagate its context through base listing and every service operation, and give cleanup a separately bounded completion path. Add a context-cooperative blocked Reader row that asserts return, reaping, and directory removal.

4. **Medium — A terminal message can override failures the controller already observed.**  
   `internal/accept/integrity_proc.go:170`, `internal/accept/integrity_proc.go:177`

   **Input:** after a Reader error or service panic, a lying child sends `procMsg{Op: "done"}`. The controller returns empty blocks and nil error. `readErr` is consulted only when the child sets `Erred`; service panics are not latched. A terminal message with `Panicked:true` is also accepted. Separately, a buffered successful `done` processed after the whole-run deadline checks `ctx`, but not `runCtx`.

   **Fix:** latch controller-observed failures independently of child claims, validate terminal-message fields, and check the whole-run deadline before accepting completion. A completely fabricated clean verdict still requires trusting the guard implementation; document that trust boundary explicitly.

5. **Medium — Blob access is repository-wide, not restricted to this run.**  
   `internal/accept/integrity_proc.go:214`

   **Input:** a child requests the known SHA-1 of a blob from another branch or historical commit that appears in neither `req.Files` nor `req.Changes`. The Reader validates object-ID syntax and reads it from the repository. Nothing checks membership in the run’s permitted blobs.

   **Fix:** construct an allowlist from the base and candidate blob IDs and reject requests outside it. Enforce request counts and cumulative read/list budgets in the controller too.

   The child cannot select the loader’s image or directory through these messages. However, it runs with the controller’s UID and filesystem visibility: process separation here provides lifecycle isolation, not filesystem confinement.

6. **Medium — The shared copy budget replaces, rather than supplements, the listing-size bound.**  
   `internal/accept/integrity_loader.go:145`, `internal/accept/integrity_loader.go:163`

   **Input:** a container leaves a 500 MiB `list` containing syntactically valid records. This fits the initial 1.5 GiB copy budget and the live configuration’s disk limit. The controller reads and parses it whole, although `maxList` is 16 MiB. Main’s loader rejected output beyond that bound.

   Also, repeatedly resending existing archives consumes copy traffic without permanently consuming the budget: duplicate copies are deleted, and the next listing recomputes `used` from retained files.

   **Fix:** retain separate metadata-size and entry-count limits, parse bounded metadata, and maintain monotonic controller-owned copy accounting. Reject unexpected output entries and duplicate archive delivery.

7. **Low — The new rows leave cumulative-budget and timing claims incompletely covered.**  
   `internal/accept/integrity_loader_test.go:321`, `internal/accept/integrity_loader_test.go:147`

   **Input:** remove only subtraction of `used` from the copy allowance. The five identical-import rows still deduplicate successfully, while the reduced-budget row starts with an empty directory and still fails. Neither distinguishes a per-list allowance from a cumulative allowance.

   The whole-run “never ends” row uses relative timing correctly. The separate abandoned-check row still gives startup, listing, and reaching the check a fixed two seconds.

   **Fix:** use several distinct archive sets that individually fit but cumulatively exceed the allowance. Make the abandoned-check deadline relative to a measured baseline or synchronize entry into the intended check.
