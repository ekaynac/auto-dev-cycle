### Answers to the six questions

1. **Is the Q8 envelope exact?** Yes for brokers and governed upstreams (`RuleKind`), `attested` and `reported` (`RuleVerification`), a remote route labelled local (`RuleEndpoint`: loopback or private IP literal only), and a credential in the URL (userinfo, query, fragment, whitespace, backslash). **Not exact for an account split across groups**: see M-1. A redirect is outside the registry's reach and is P11's and P13's obligation (M-3).
2. **Plain http to a private IP.** Acceptable for M1 as a recorded decision, not an unstated default (M-2). The floor `own` names who receives the data; transport is a separate property, and D45's threat model has no LAN attacker with network position. Requiring https off loopback now would exclude Q2's alternative route (Ollama on a LAN GPU host serves plain http, and P11 cannot pin a CA yet). The trigger to revisit is P11.
3. **Families and independence.** A reviewer cannot share a builder's family by name nor by `(destination.id, model)`; `unknown` is refused at start; an unregistered executor's family is `unknown`, which `graph.Roster` and `registered` refuse. The remaining hole is the relabel in M-1. The same model from two different endpoints under two family names stays an operator declaration, which 06 rule 3 accepts.
4. **Fixed text, re-check at Start.** Yes. Every `Rule` is a constant; `Refusal.Error` adds only an index; `Load` never includes the path. `daemon.go:61` runs `Validate`, hence `registry.New`, on every `Start`; the test edits the loaded registry and sees `Start` refuse.
5. **Fault evidence.** Discriminating. The unknown-family test closes the three ways a stranger could pass (`Family`, `Executor`, `graph.Roster`) with a positive control; each widening case flips one field of the positive control. Weakness: the twelve hand mutations are not reproducible from the repo (L-3).
6. **L3 narrowed to named groups.** Acceptable. Every registered executor must be listed by exactly its own group, so an unnamed group cannot hold one; an unnamed group with stranger members is idle capacity. Two notes in L-4.

### Findings

#### Medium

**M-1. The account and route keys use `destination.id`, a free label, so the M1 and M2 fixes are bypassed by relabelling.**
`internal/registry/registry.go:151` (account key), `:177` (route key), `:125` (destination consistency keyed by id).
Scenario: the stub reviewer gets destination `stub2` with the identical endpoint `http://127.0.0.1:18080/v1` and credential `stub`, its own `account_quota` group, model `stub-builder-1`, family `stub-other`. `New` admits it: two ids, two account keys, two routes. One account draws from two limits (Q8 Membership), and the builder's model reviews itself under another name (06 rule 3). Operator misconfiguration only, so not High.
Fix: make the destination id a unique label of an endpoint. In `New`, map the normalised origin (`scheme://host:port`, lower-cased, no trailing slash) to the destination id and refuse a second id for one origin with `RuleDestination`. Key `accounts` by origin plus credential for a direct API, by origin for a local endpoint; key `distinct`'s route by origin plus model. Tests: "one endpoint, two destination ids" → `RuleDestination`; "aliased family across destination ids" → `RuleSameFamily`.

**M-2. Plain http to a private IP is a transport decision no design line states.**
`internal/registry/registry.go:264`; `schemas/config/executor-registry.json` (`kind`, `endpoint` descriptions).
Q8 says "a local endpoint (for example Ollama's OpenAI-compatible API)"; 01 §2.2 says "an owned server through an allowlisted agent". Neither says LAN or cleartext. `netip.IsPrivate` also excludes CGNAT `100.64/10` and link-local, so a Tailscale-reachable host is refused while a cleartext LAN host is admitted.
Fix (no code change for M1): record in Q8 at the reconcile, or in the #236 backlog entry: "a local endpoint may be plain http to a loopback or RFC 1918 / fc00::/7 literal; the data floor is about the recipient, not the transport; P11 revisits when it can pin a CA, after which plain http off loopback becomes an explicit per-destination opt-in or is refused." Say "RFC 1918 or fc00::/7" in `RuleEndpoint` and the schema instead of "private".

**M-3. Redirects are the gateway's obligation; the backlog entry must carry I10 and a trigger.**
`internal/registry/registry.go:255` (the envelope ends at the URL).
A `direct_api` https endpoint may answer 3xx to a broker or to plain http; a local IP literal reaches a name only if the client follows. The PR defers this correctly; 04 §3 asks each entry to name the invariant and trigger.
Fix: one backlog entry: "P11/P13: the http-chat client sets `CheckRedirect` to refuse every redirect, dials only the registered origin, and records any redirect as a route refusal (I10 effect row, trigger P11)."

#### Low

**L-1. `Admits` will refuse `attested` under `verified` routing, against 01 §2.2 (cumulative over verified).**
`internal/registry/registry.go:303`. Harmless in M1 since `New` refuses `attested`, but an M2 trap.
Fix: refuse unless the label is `verified` or `attested`, keeping an unknown label refused.

**L-2. Kind, family and cost basis are declarations the registry cannot verify.**
`schemas/config/executor-registry.json`. A broker's https URL labelled `direct_api`, or a paid API labelled `free`, passes every rule. By design (D45), but the schema reads as if the kind were established.
Fix: one sentence in the schema description and package comment: these are the operator's declarations; the registry checks their consistency with groups and endpoint, the gateway enforces them, neither establishes them.

**L-3. The hand mutations are not reproducible from the repository.**
`internal/mutation/mutation.go:39` already names `UnknownFamilyIndependent`, env-toggled under the `adcmutation` build tag, so no contract fixture is needed.
Fix: make `Registry.Family` honour that mutation (return the id as a family for an unregistered executor) and add a tagged red case with `t.Setenv` to `TestUnknownFamilyIsNeverIndependent`; or commit the mutation script under `scripts/`.

**L-4. L3 narrowing: two notes to carry.**
`internal/registry/registry.go:164`; `fixtures/m1/config/groups.json`.

State that in the P8b handoff. (b) P24 should split `groups.json` per registry or document the sharing in its README.
