# PR #41 (event store effects): Astra reviews

## Review of #41 (Astra, 2026-10-04)

Verdict: NO-GO

1. **High — Caller-supplied effect events bypass the state machine.**  
   `internal/eventstore/store.go:225`, `internal/eventstore/writer.go:267`

   Reserving kind registration does not prevent `Apply` from returning those event kinds. Reproduced: submit `effect.observed/v1` for a pending effect; the event commits and `Verify` passes, but the effects row remains pending. The same path permits fabricated intents and forbidden transitions. M1 cannot trust agreement between the log and table.

   **Fix:** reject all store-owned effect kinds in caller-supplied events. Permit them only through `appendIntents` and `transition`. Add rejection tests for all six kinds, asserting rollback of events, effects, projections and command rows.

2. **High — Effect transitions skip transactional projection updates.**  
   `internal/eventstore/effects.go:201`, `internal/eventstore/effects.go:212`

   `transition` appends the event and updates `effects`, but never invokes `Hooks.Project`. This affects both `RecordEffect` and restart transitions. Reproduced: the projector receives the intent but misses the observation; even a projector configured to fail cannot prevent completion. Dependent projections can remain stale indefinitely, violating note 03’s transaction boundary.

   The “after observation, before projection” fixture checks only the effects row, so it misses this failure.

   **Fix:** project every transition event within the same transaction, propagating projection errors to rollback. Extend fixtures to check dependent projections and rollback, including the entire restart batch.

3. **Medium — Invalid UTF-8 makes the effects table disagree with its events.**  
   `internal/eventstore/effects.go:93`, `internal/eventstore/effects.go:124`, `internal/eventstore/effects.go:213`

   `json.Marshal` replaces invalid UTF-8, while SQL receives the original strings. Reproduced with target `"provider-\xff"`: the table preserves that value, but the intent records `"provider-�"`. Observation strings have the same problem. Rebuilding from events cannot reproduce the live table.

   **Fix:** reject invalid UTF-8 in targets and observations before marshaling or writing. Test refusal without any durable changes.

`make ci` and the sandboxed event-store `-race` suite passed; local CI skipped unavailable ShellCheck. Four isolated review probes reproduced the findings above. The intended API paths otherwise preserve command/intent atomicity, restrict retries to idempotent kinds, implement pending-to-uncertain recovery, and check result publication before reference. The checkout remains unchanged.
### Lead notes on round 1 (applied)

- High (caller effect events): the writer refuses every store-owned effect kind in a command's events; only
  `appendIntents` and `transition` write them. The test forges each of the six kinds with a schema-valid payload, so
  the ownership check (not the payload schema) is what refuses it, and checks that the log, the effect and the
  commands table are unchanged.
- High (projection): `transition` passes every transition event to `Hooks.Project` inside its transaction, and a
  projection error rolls it back, the restart batch included. The tests check a dependent projection sees each
  transition and that a failing projector leaves the effect and the log unchanged.
- Medium (UTF-8): targets must be non-empty valid UTF-8, and observations valid UTF-8, before anything is marshalled
  or written; refusals leave nothing durable.
- Mutation: removing each of the five new checks fails the suite.
