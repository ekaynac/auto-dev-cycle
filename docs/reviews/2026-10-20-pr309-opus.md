### Answers to the six questions
1. **Admission (I22).**
   - **Two admitted tasks: not through admission.** Both commands go through the single writer, and `AdmitTask` re-checks Ready, the approval in force and the `admitted` key.
   - **The fold refuses the same from the log alone,** on append and on replay. A raw second admission and a raw admission of a cancelled task are refused, and so is an operator's admission. A held task keeps the key.
   - **A cancelled task** is refused by both the decision and the command (Opus #298's obligation is met).
   - **But two tasks can still run at once,** through the re-claim path (H1).
2. **`task.done`.**
   - **The slot can be wedged forever.** Only `task.done` frees it, and `task.cancel` refuses an admitted task. A revoked approval or a terminal failure never ends the task (M3).
   - **`task.done` frees the slot even while the task's nodes are still claimed** (M2).
3. **The template.**
   - **The template matches W12:** plan → build r1 → accept → gate, round 1, no merge and no review.
   - **The guard runs first.** `RecordTemplate` runs `CheckSurface` before any `Record`, and adcd's fold refuses kinds outside its allowlist.
   - **Another path exists.** The `node.recorded` fold accepts nodes of an unadmitted, or even unrecorded, task (M5). `AdmitTask` also accepts an empty template (L1).
4. **Claims.**
   - **Covered:** `node.claimed` and `node.reused` are refused when the task is not admitted or its approval is not in force.
   - **Not covered:** a re-claim through `node.invalidated` or `node.renewed` (H1).
   - **Revocation between claim and launch:** the attempt still starts (H1/M1).
   - **Untested:** no row covers the reuse refusal (M4).
5. **Board and inventory.**
   - **The board change is correct.** The fixture now admits through the real fold.
   - **The recount is right:** 15 GAP, 29 kept + GAP, 38 kept, 6 n/a.
   - **I22 admission and fold, kept:** justified, apart from the test gaps in M4.
   - **I22 and I1 consumption, kept:** overstated until H1 is fixed.
6. **Regression and mutations.**
   - **No regression against #298:** its rows pass. `TestSandboxConfig` fails for the environment, the same failure the #298 record documents. The PR touches neither the sandbox nor `daemon/config.go`.
   - **The stack is off by one commit** (L4).
   - **I did not re-run the PR's 14 mutations.** Five mutations of my own all survived (M4).

### High
- **H1. A re-claim skips the task authority, so the "every claim" decision and the I22 consumption row do not hold** (`internal/graph/template.go:113-121`; `internal/graph/lifecycle.go:264`; `internal/graph/renew.go:90`).
  - `taken` checks only `NodeClaimed` and `NodeReused`.
  - `node.invalidated` gives a claimed or completed node a fresh key of the next generation, and it is claimed again. `node.renewed` reopens a completed node's key as claimed. Neither goes through `Tasks.Claimable`.
  - **Input 1:** admit A; claim A's plan; revoke the operator; `graph.Invalidate(plan)` is accepted, and the plan is claimed again under its revoked approval.
  - **Input 2:**
    1. Admit A and claim its plan.
    2. `DoneTask(A)`; `Admit` admits B.
    3. `graph.Invalidate(A's plan)` is accepted.
    4. A lease on `UnitOf(A's plan)` is requested and granted, and `lease.StartAttempt` is accepted.
    
    A done task now runs an attempt while B is admitted.
  - **Fix:**
    - add `*types.NodeInvalidated` and `*types.NodeRenewed` to `taken`;
    - make attempt start the single place every run passes through (see M1);
    - add daemon rows for both inputs.

### Medium
- **M1. A revocation between claim and launch does not stop the launch** (`internal/graph/units.go:82`).
  - `Units.Startable` checks only that the node is claimed. Retry and hold-clear runs also start attempts under the existing claim, with no check.
  - **Input:** admit; claim the plan; revoke the operator; request and grant a lease on its unit; `StartAttempt` is accepted.
  - The plan (§5 row 1) promises only "before the first claim". The lead's fail-closed decision implies this case too.
  - **Fix:**
    - give `graph.Units` a `Tasks` field;
    - `Startable` calls `Tasks.Claimable(rec.Recorded.Task)`;
    - wire `graph.Units{Tasks: authority.Tasks{}}` in `internal/daemon/wiring.go`.
    
    The tasks projector runs before leases, so replay checks it at the same point in the log. Add a row: an attempt start after revocation is refused, and no attempt is recorded.
- **M2. `task.done` frees the slot while the task's nodes are still claimed** (`internal/authority/admit.go:179`).
  - `doneTask` checks only `State == admitted`.
  - The board row "a done task, a node still claimed" (`internal/api/board_test.go`) treats that state as valid.
  - **Input:** the precondition of H1's input 2.
  - **Fix:** either `doneTask` refuses while a current node of the task is claimed or held, or M1's attempt-start check is in place, so a done task's claimed node can start nothing. Record this as a 22a-6 obligation either way.
- **M3. The admitted slot can be wedged forever, with no recovery** (`internal/authority/admit.go:179`; `internal/authority/cancel.go`, which refuses any task not in Ready).
  - **Input:**
    1. Admit a task.
    2. Revoke its operator, for example in a key rotation. The approval is revoked, and every claim is now refused.
    3. The task stays admitted. Nothing ever writes `task.done` for it, and `task.cancel` refuses it, so no task in any project is admitted again.
  - A build held by the round rail, or an admission whose template has no nodes, wedges the slot the same way.
  - Nothing is reachable today: adcd has no admitting command until P22a-4.
  - **Fix, before P22a-4 wires admission:** define how an admitted task ends without a candidate. For example:
    - a `task.done` with `as: abandoned`, written by the reconcile loop when the approval is revoked;
    - or an operator's `task.cancel` of an admitted task once its leases are stopped.
    
    Name it in the plan with a row.
- **M4. The fold-only checks are untested** (`internal/authority/admit.go:136-175`; `internal/authority/admit_test.go:216-246`; `internal/graph/template.go:117`).
