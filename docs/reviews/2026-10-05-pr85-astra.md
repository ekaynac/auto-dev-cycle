# PR #85 (conformance kit, part 2b): Astra reviews

## Review of #85 (Astra, 2026-10-05)

Verdict: NO-GO

### High

**1. Malformed error values pass as observable rejection.**  
`adapters/conformance/src/kit.ts:581–589`; response routing at `:261–269`.

The runner checks only that the correlated response contains `error` instead of `result`. Reproduced `oversize()` returning `[]` for each of:

```json
{"jsonrpc":"2.0","id":3,"error":null}
{"jsonrpc":"2.0","id":3,"error":false}
{"jsonrpc":"2.0","id":3,"error":{}}
{"jsonrpc":"2.0","id":3,"error":{"code":"bad","message":42}}
```

Each adapter subsequently completed shutdown normally. None supplied a valid JSON-RPC error response, so the central rejection proof remains bypassable.

**Fix:** validate error responses before accepting them: a non-null object with an integer `code` and string `message`. Preserve correlation and subsequent session validation. Add these malformed-error red controls.

### Medium

**2. Escape-heavy strings retain the heap amplification.**  
`adapters/contract/src/strict-json.ts:40–76`; `adapters/conformance/test/kit.test.ts:248–256`.

Plain runs are now copied efficiently, but escape decoding still appends individual characters. Alternating plain characters and escapes also defeats the optimization.

Reproduced the full runner aborting with V8 OOM under the regression’s **96 MiB heap** after changing only the fixture’s padding from repeated `"x"` to repeated newline characters. Its escaped messages remain below both the 16 MiB line limit and aggregate output limit. Event validation cannot help because allocation fails during parsing.

**Fix:** decode strings without one retained concatenation node per escape or short run—for example, validate the string’s spelling, then decode its complete slice. Extend the bounded-heap regression with escape-only and alternating strings. This remains Medium, consistent with #81 finding 22; the reproduction uses a constrained heap.

### Other review results

- The boundary control is exactly **16,777,216 UTF-8 bytes excluding the newline**, and otherwise valid. Successful responses—including falsy results—are rejected for the oversized request.
- Wrong-id replies, a success following an error, and malformed trailing output produced findings in additional probes.
- The EOF reasoning is sound within the stated PID-namespace scope: bubblewrap retains the output writer, so merely closing adapter stdout does not produce EOF. Forced cleanup paths already record a failure.
- Slow reading or stdin back-pressure cannot yield green through timeout. However, the grace period starts before the buffered write completes; timeout establishes **no observed rejection**, not that the adapter consumed and ignored the line.
- The parser matched its predecessor on **20,000 differential string cases**, including escapes, controls, surrogates, and unterminated strings.
- Early event validation removes invalid events from retention. Stderr, findings, and queued replies have existing bounds; these are not a precise parsed-heap budget. The new regression meaningfully covers plain-string amplification, but does not establish a general heap bound.

The requested sandbox command passed: **18 conformance tests, TypeScript checking, and 21 contract tests**. No repository files were modified.
### Lead notes on round 1 (applied)

- High 1 (malformed error values passed as a rejection): the kit accepts an `error` only as a JSON-RPC error object (a non-null object with an integer `code` and a string `message`); anything else is an `envelope` finding and is not routed as a reply, so it is no answer. In `oversize()` that leaves no rejection, which is red. Controls: `null`, `false`, `{}` and `{code: "bad", message: 42}` each give `envelope` and `oversize`. The check sits in the response routing, so it holds for every request, not only oversize.
- Medium 2 (escape-heavy strings): the reader appends a plain run of 64 characters or more as one slice; shorter runs and every escape collect as char codes, decoded 4096 at a time. So no input costs a heap node per character. The bounded-heap regression now runs plain, escape-only and alternating `x\n` padding under 96 MiB.
- On the timeout note: agreed. A late finding means no rejection was observed within the grace, which is what the finding says. It is not a claim that the adapter consumed the line.
- Mutation check: removing the error-object check, appending each escape on its own, and slicing short runs each turn their regression red.

## Second review of #85 (Astra, 2026-10-05)

Verdict: GO with changes

- **Round-1 High 1 — Resolved.** Malformed errors (`null`, `false`, `{}`, arrays, incorrect field types) produce `envelope` and `oversize` findings. Valid errors with additional fields or a `data` member still pass.
- **Round-1 Medium 2 — Resolved for the reported string amplification.** Escape-only, alternating, short runs between escapes—including lengths 63/64—and Unicode strings complete under the 96 MiB heap with findings rather than aborting.

The shared error check correctly protects every request. Malformed `describe`, `prepare`, and `run` replies leave their requests pending: probes with a 750 ms deadline settled in approximately 756 ms, with envelope, deadline, and missing-response findings. Shutdown, tool acknowledgements, and cancellation also settle earlier when the session exits. Waiting can therefore consume the default 120-second deadline, but remains bounded and cannot yield green. This is acceptable; immediate termination would be an optional latency improvement.

**Medium — Remaining container allocation amplification.**  
`adapters/contract/src/strict-json.ts:141–148`; parsing precedes event validation at `adapters/conformance/src/kit.ts:243`.

A single invalid event whose padding contains **32,768 elements, each wrapping `"xx"` in 100 nested arrays**, aborts the complete runner with V8 OOM under **96 MiB**, before returning findings. The padding is **6,717,441 bytes**: below the line and aggregate output limits, with nesting below 128. It allocates over three million arrays.

Both the previous and current readers reproduce this failure. This is residual resource-budget debt, not a regression from batched decoding, and remains **non-blocking Medium**, consistent with the earlier constrained-heap finding.

**Fix:** enforce a parsed-node/allocation budget before constructing containers, returning a resource finding when exhausted. Add this dense-container case to the bounded-heap regression; discarding invalid events after parsing cannot prevent this allocation failure.

Validation completed:

- **51,330 differential cases**, with no mismatches against the previous reader: escapes, surrogate pairs crossing batch boundaries, controls, and unterminated strings. The additional 20,000 valid cases also matched `origin/main` and `JSON.parse`.
- Arrays containing up to **2,097,152 short strings** completed under the tested 96 MiB configuration.

No unresolved Critical or High findings.
