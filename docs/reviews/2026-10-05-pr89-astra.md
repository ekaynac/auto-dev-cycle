# PR #89 (ledger and hash-chain fixtures): Astra reviews

## Review of #89 (Astra, 2026-10-05)

Verdict: GO with changes

No Critical/High findings. The fixtures exercise real validators, and all three named mutations turn their intended fixtures red. The findings below are nonblocking coverage gaps.

1. **Medium — Accounting assertions are weaker than `TestDeltas`.**  
   [internal/fixtures/ledger.go:59](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ledger/internal/fixtures/ledger.go:59) checks only input tokens and inconsistency. A regression that preserves input tokens but loses cost, double-counts turns, or clears `Uncertain` still passes these fixtures. `TestDeltas` explicitly checks turns, cost and uncertain liability. The duplicate fixture also lacks two calls sharing a delta sequence, so deduplication by sequence alone would escape it.  
   **Fix:** assert the expected accounting figure and `Uncertain` state per call; add two calls with the same delta sequence and independently expected totals.

2. **Medium — The chain fixture never tests the trusted hash against a consistently rewritten chain.**  
   [internal/fixtures/chain.go:24](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ledger/internal/fixtures/chain.go:24) edits payloads without updating hashes. Removing only the trusted-head hash comparison would leave every current case green: row hashing catches the edits, sequence checking catches middle deletion, and the trusted sequence catches truncation. This is weaker than `TestVerifyDetectsTampering`’s consistently rewritten tail.  
   **Fix:** edit a middle event and recompute its hash and every subsequent link/hash, retaining the original external trusted head. Require `failed/log_integrity_broken`; verify that the rewritten chain is internally consistent without that anchor.

3. **Medium — The post-final case cannot detect dropping all later deltas.**  
   [internal/fixtures/ledger.go:109](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ledger/internal/fixtures/ledger.go:109) sends only an already-counted duplicate after the final. An implementation that stops processing deltas upon seeing a final produces the same result.  
   **Fix:** add a previously unseen delta after the final that raises the delta sum above it—for example, delta 100, final 150, then another sequence’s delta 100. Expect 200 and `inconsistent_usage`, and cover the reverse arrival order.

4. **Low — Add truncation boundary cases.**  
   [internal/fixtures/chain.go:29](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ledger/internal/fixtures/chain.go:29) tests only truncation from four rows to two. It misses an empty-log early return and a one-row truncation boundary error.  
   **Fix:** add deletion of every event and deletion of only the head row, both checked against the original trusted head. Include an unanchored consistent-prefix control that succeeds by design.

The **stale-attempt fixture** exceeds `TestStaleAttemptsCount` by checking both arrival orders, a separate stale call, and real output fencing. Its mutation produces totals 40 and 100 instead of 140 and drops the separate stale call. The author’s concern is valid: “last reporter wins” invents a filter and does not identify the actual current attempt. Nevertheless, it is a small, plausible erroneous accounting filter, and its failure is substantive rather than scripted.

The **duplicate mutation** realistically adds repeated usage at the deduplication site; observed failures include 250 instead of 150. The **chain mutation** removes precisely the recomputed-hash comparison: both edited logs incorrectly verify, while deletion and truncation still fail. Restoring the triggers keeps schema damage from supplying an unrelated rejection.

Under D43, ordinary filesystem write access can be in scope; this fixture assumes that access. It proves detection against an independently retained trusted head, not prevention of writes or detection when both database and trusted head are replaced. Unanchored truncation verifying clean is correct.

Both requested commands passed inside `scripts/test-sandbox.sh` with Go 1.27.1 and `GOTOOLCHAIN=local`. Existing `verify-log` and ordinary-build mutation checks also passed. Ordinary builds select the constant-false mutation implementation. No files were modified.
### Lead notes on round 1 (applied)

- Finding 1 (accounting assertions): every reconciled call is now checked for its whole `ledger.Figure` (tokens in/out/cache, turns, milliseconds, cost) and its `Uncertain` state, as `TestDeltas` does; a counted call that reported nothing is a violation too. A new duplicate-deltas case has calls A and B both reporting delta sequence 0 (B's repeated), with independently expected totals (A 150 tokens over 2 turns, B 70 over 1, both uncertain). Controls: `ledger.deltas-not-deduplicated` now fails on turns and cost as well as tokens (B counts 140); `ledger.stale-attempt-usage-dropped` stays red (40 and 100 instead of 140, and the stale call missing).
- Finding 2 (consistent rewrite): the log is copied after its first event and both copies are carried on by the real writer with different events, so the copy's seq 2 onward is re-hashed and re-linked by the store itself (no hash code in the fixture). The copy verifies clean without an anchor as a four-event chain with another head (asserted), and fails against the original trusted head: a new `failed/log_integrity_broken` step. Control: with the `atTrusted != trusted.Hash` comparison removed by hand (reverted), the fixture is red on exactly that step.
- Finding 3 (unseen delta after the final): delta 100 (seq 0), a final of 150, then an unseen delta 100 (seq 1), and the reverse arrival order; each counts 200 tokens over 2 turns, certain, `found/inconsistent_usage`. An implementation that stops counting deltas after a final gives 150 and is caught.
- Finding 4 (truncation boundaries): against the original trusted head, deleting only the head row and deleting every event each fail `log_integrity_broken`; an unanchored control, the log truncated to two events, is a clean step whose verified head must be seq 2 (03 rule 3: unanchored truncation is undetectable by design).
