### BLOCKING

**H1. Every task's benchmark facts go into every `GET /v1/tasks`, and the client caps that response at 1 MiB. Past a modest history, `adc task show`, `adc dev bench record` and the driver's `--bench` all fail. BLOCKING.** `internal/api/tasks.go:90-92`; `internal/client/client.go:29`, `:218-223`; `internal/cli/tasks.go:72-101`
- **Cause:**
  - `benchOf` runs for every task an operator reads in the list, done tasks included. Each carries every lease, call and measurement.
  - `readTask` (and so `bench record`) reads the whole list and then picks one task.
  - `Transport.Read` refuses a body over `maxResponseBytes` (1 MiB).
- **The arithmetic:** about 1.2 KB per call (three measurements of 389 B, plus ids) caps the readable history at roughly 800 calls across all tasks. A live build of 20–30 turns makes 20–30 calls, so the cap is about 30 tasks.
- **Effect:** after that, the operator's main task read fails with "the controller's response exceeds 1048576 bytes" for every task, including the one being benchmarked. Main's list carried only the cards and `first_attempt`, so this is a regression, and checkpoint (a)'s exit path stops working as the history grows. Even under the cap, every board or list read now walks the ledger of the whole installation.
- **Fix:** serve the facts per task:
  - a filtered read (`GET /v1/tasks?task=<id>`), or a resource of its own (`task_bench`), computed only for the requested task;
  - drop `bench` from the list;
  - add a row that reads one task's facts beside many large tasks.

### Medium

**M1. One task's unreadable benchmark facts fail the read of every task. OBLIGATION.** `internal/api/tasks.go:93-95`, `internal/api/taskbench.go`
- **Cause:** any `benchOf` error returns the error for the whole list. Main shows one task's unreadable record as that task's `damaged_record` card (Mythos chunk 5a L4). The errors that can now do this include:
  - "the closing review has no result.selected time";
  - a lease with no record;
  - a call with no binding;
  - an asker index that names no owed input.
- **Fix:** under H1's per-task read, the failure is that task's alone (the command already treats it as could-not-run). In any list that keeps it, damage must stay per task.

**M2. A lease's liability is dropped when it has no unsettled call, so the benchmark understates what is outstanding. OBLIGATION.** `internal/cli/bench.go:339-354`
- **Cause:** `ledgerOf` passes the lease's liability only on its first unsettled call. A lease with no calls, or with every call settled while the lease itself is not, loses it. Probe 3: 700 µUSD in, 0 passed, no error.
- **How it is reached:** an attempt held or stopped before its first model call, or a held task whose attempt ended before its lease settled.
- **Why it matters:** `internal/bench`'s contract, restated in §2.8, says "zero only when the lease has neither" (settlement nor reservation).
- **Fix:** refuse when a positive liability is left unplaced. Or give `bench.Task` a per-lease liability that `Record` counts outstanding under basis cash.

**M3. The routes' families and destinations come from `--registry` unchecked against what ran. OBLIGATION.** `internal/cli/bench.go:360-386`, with `internal/dispatch/dispatch.go:224`
- **Cause:** `routesOf` checks only each lease's executor id, role and placed price against the file. Each lease's placement checks already name the registry entry's digest (`Destinations`: `"executor <id> <digest(e)>"`).
- **The concrete input:** a registry that keeps the id, role and price but changes `family` or `destination`. The record then names another family, and `--routes stub|live` is judged on the file's destination, not the one the lease used. Family is what the benchmark's routes record (and what review independence is about).
- **Fix:** expose the lease's entry digest in `BenchLease` (from `placement_checks.destinations`), and refuse a registry entry whose digest differs.

### Low

- **Fix:** state which commands count as approvals at (a) and at which stage, or pass them.

**L2. Answers: no production producer, and only the current revision counts. OBLIGATION (state it).** `internal/authority/owed.go:202-220`, `:121`
- **No producer:** `RecordOwed` has no non-test caller, so `answers` is always `[]` in production today. The rows reach it only through `answers_test.go`'s seam.
- **Only the current revision:** a new revision resets `Answer` (`OwedRecord{OwedInput: o}`), so an answer to revision 1 disappears once revision 2 is asked. That contradicts the doc's "an answer given is an intervention either way".
- **Fix:** state both. Or count answers from an append-only index, as the raises are.

**L3. No row covers this PR's projections on an older store. OBLIGATION.** `internal/daemon/startup_test.go`

**L4. A second contract-maximum constant. OBLIGATION.** `internal/api/taskbench.go:133`

- an abandoned task;
