# PR #65 (bearer token credentials): review

## Review of #65 (Astra, 2026-10-05)

Verdict: NO-GO

The High finding blocks approval. The remaining findings are nonblocking.

**Critical**

None found.

**High**

- **Secret formatting can disclose the complete credential — `internal/identity/token.go:49`.** `String` and `GoString` do not cover every formatting verb. Reproduced with a synthetic credential: `%d` produces `{%!d(string=tok_synthetic.review-only)}`; `%f`, `%c`, and `%U` also disclose it, including inside an exported struct field. A logging mistake can therefore expose an unrestricted operator credential, violating 04’s redaction contract. **Fix:** implement `fmt.Formatter` with a value receiver that writes only the placeholder. Test invalid verbs, flags, pointers, and nested fields. Assert safe output, rather than merely searching for `tok_`. This behavior follows Go’s documented [formatting rules](https://pkg.go.dev/fmt#hdr-Printing).

**Medium**

- **The verifier does not enforce salt/key lengths or total input bounds — `internal/identity/token.go:112`.** The schema comment is not an enforced precondition: `verify` accepts an ordinary string. An empty key reaches `argon2.IDKey` and panics; a correctly computed **one-byte key verifies**, reducing the comparison to eight bits. Oversized salt/key strings also allocate outside the advertised memory-cost bounds. These require malformed stored input, rather than merely a wrong bearer, but damaged records are explicitly within this function’s stated threat model. **Fix:** bound PHC length before splitting/decoding and enforce decoded salt/key sizes before hashing—prefer exactly 16/32 bytes for the current profile, or explicitly supported bounded alternatives. Add empty, short, oversized, and no-panic tests. The description’s assertion that another key length “can never match” is incorrect.

- **PHC parsing accepts trailing data, and the supported cost policy is underspecified — `internal/identity/token.go:105`.** Reproduced successful verification after changing `v=19` to `v=19garbage`, appending garbage after `p=4`, or appending a newline to the encoded key. `Sscanf` does not require complete consumption, and strict base64 still ignores CR/LF. Separately, a hash computed with `m=1,t=1,p=1` verifies and passes the record schema, although RFC 9106 requires `m >= 8*p`. **Fix:** parse the entire canonical PHC grammar, reject newline characters, enforce RFC constraints, and define supported issuance/legacy profiles. Test these cases directly. Changing costs on an existing valid hash does not itself bypass authentication; the problem is permissive acceptance of malformed or unsupported profiles. See [RFC 9106 §3.1](https://www.rfc-editor.org/rfc/rfc9106.html#section-3.1).

**Low**

- **Bearer parsing accepts secrets outside the specified alphabet — `internal/identity/token.go:89`.** A valid token ID followed by a dot and **43 newline characters** is accepted. The encoded-length check counts characters that the decoder ignores. This does not authenticate against a normally minted hash, but contradicts the strict bearer contract. **Fix:** enforce `[A-Za-z0-9_-]{43}`, retain strict decoding, and require 32 decoded bytes. Add CR/LF and noncanonical trailing-bit cases. Go explicitly documents that [`Strict()` still ignores CR/LF](https://pkg.go.dev/encoding/base64#Encoding.Strict).

- **The schema pattern checks character counts, not valid encoded values — `schemas/records/token.json:15`.** It accepts impossible unpadded base64 lengths, noncanonical trailing bits, and zero costs. For example, 25 salt characters and 45 key characters pass schema validation but cannot decode. **Fix:** tighten canonical encoding constraints or add a semantic PHC format validator, with negative schema tests. Keep runtime verification checks independent.

- **The uniqueness test compares complete bearers — `internal/identity/token_test.go:43`.** Different IDs make this test pass even if every token receives the same secret. **Fix:** check the second mint error and compare the secret components separately. Add independent expected-parameter/vector assertions; mint/verify round trips alone can share the same mistake. The mutation claims do not establish constant-time execution, although the implementation correctly uses `subtle.ConstantTimeCompare`.

**Decisions reviewed**

| Decision | Assessment |
|---|---|
| `tok_<id>.<secret>` | Sound: public lookup ID plus 256 random secret bits. The time-bearing TypeID contributes no required secrecy. |
| Argon2id cost | Acceptable and matches [RFC 9106’s second option](https://www.rfc-editor.org/rfc/rfc9106.html#section-4). Authentication integration should bound concurrent hashing and request rates; one authentication per command does not bound aggregate resource use. |
| Verification bounds | Useful upper limits, checked before hashing, but incomplete without the size and profile checks above. |
| `tok` prefix | Appropriate and consistently registered in the vocabulary, schema, generated alias, and ID tests. |

The record’s six fields are appropriate: actor binding, hash, issuance metadata, and nullable revocation; additional fields are forbidden and minting stores no plaintext secret. JSON marshalling refusal works. Actor existence, revocation enforcement, bootstrap consumption, and transport authentication remain appropriately in the subsequent integration work.

Focused tests for `internal/identity`, `internal/ids`, and `schemas` passed. Adversarial probes ran through an in-memory overlay. `make ci` was not run; no repository files were changed.
### Lead notes on round 1 (applied)

- **High (formatting):** `Secret` implements `fmt.Formatter` (value receiver), which writes the placeholder for every verb and flag. `%p` of a non-pointer bypasses `Format` and prints fields by reflection, so the value now sits behind a pointer, which reflection prints only as an address.
  - The test runs 22 verbs and flag combinations over a value, a pointer, a struct field, a pointer to a struct, a slice and a map. It asserts that no part of the id or the secret appears, and calls `String` and `GoString` directly.
- **Medium (sizes and bounds):** my claim that "a different length can never match" was wrong: a correctly computed one-byte key verifies. Verification now matches the whole hash against the canonical PHC form of the current profile before anything is decoded.
  - The form is exactly argon2id v=19 with non-zero costs without leading zeros, a 22-character salt (16 bytes) and a 43-character key (32 bytes), each with canonical trailing bits. No other characters are allowed, CR and LF included.
  - The bound checks and RFC 9106's `m >= 8p` follow.
  - Tested: a correctly computed one-byte key, a 16-byte key, a 32-byte salt, `m=1,t=1,p=1` and `m=31,p=4` are refused, and `m=32,p=4` is accepted. An empty key no longer reaches argon2.
- **Medium (trailing data):** `Sscanf` is gone. The anchored regex refuses `v=19garbage`, garbage after `p=4`, newlines in the salt or key, and leading zeros. All are tested.
- **Low (bearer alphabet):** a bearer secret must be exactly `[A-Za-z0-9_-]{42}` followed by a canonical last character. 43 newlines, a CR inside and non-canonical trailing bits are refused and tested.
- **Low (schema):** the record pattern now requires exactly 22 and 43 characters with canonical trailing bits, and non-zero costs. `TestTokenSchemaRefusesMalformedHashes` covers wrong lengths, zero memory, non-canonical bits, argon2i and a trailing newline.
- **Low (tests):** the uniqueness test compares the secret parts, and checks the second mint's error. `TestMint` asserts the exact current profile prefix.
- **Mutation:** 18 points. 17 are killed (the lanes bound after round 2; see below), and 1 is equivalent: loosening the key's canonical form, which strict decoding and the length-checked constant-time compare still refuse.
- **Noted for the integration PR** (Astra's decision table): bound concurrent hashing and request rates at the transport, since one authentication per command does not bound aggregate cost.

## Second review of #65 (Astra, 2026-10-05)

Verdict: GO with changes

No Critical/High findings remain. The change below is nonblocking.

- **High — secret disclosure through formatting: FIXED.** Adversarial verbs, flags, malformed formats, pointers, private fields and nesting revealed no credential.
- **Medium — salt/key sizes and input bounds: FIXED.** Empty, short and oversized fields are rejected before hashing; fixed-size grammar bounds decoding.
- **Medium — PHC trailing data and RFC constraints: FIXED.** Trailing garbage, newline characters, noncanonical costs and `m < 8p` are rejected. Supported boundary profiles verify.
- **Low — bearer alphabet: FIXED.** CR/LF and noncanonical trailing bits are rejected; exhaustive trailing-byte probes agree with canonical base64url decoding.
- **Low — schema canonicality: FIXED.** Invalid lengths, trailing bits and zero costs are rejected. Tested newline suffixes also fail under JavaScript’s regex engine.
- **Low — uniqueness test: FIXED.** It checks the second mint error and compares secret components. Issuance parameters are explicitly asserted.

**New findings — Low**

- **The lanes-bound regression test does not enforce the policy — `internal/identity/token_test.go:169`; incorrect equivalence claim at `docs/reviews/2026-10-05-pr65-astra.md:56`.** Removing `threads > maxArgonThreads` still passes the existing `TestVerify`: changing the PHC parameters without recomputing its key already causes verification to fail. A correctly computed hash with `m=136,t=1,p=17` is rejected by current code but accepted without the guard, disproving equivalence. **Fix:** add that negative case and a correctly computed `m=128,t=1,p=16` positive case; correct the mutation notes.

Focused tests for `internal/identity`, `internal/ids` and `schemas` passed. Additional in-memory probes passed, including an independent libargon2 vector and the mutation counterexample. Full CI was not run. No repository files changed.
