# PRs #123 and #124 (step-9 PR 4a: client transport and token file): Astra review

## Review of #123 and #124 (Astra, 2026-10-06)

- **#124: GO with changes**

No Critical/High findings; nothing blocks merging under the requested threshold.

1. **PASS — #123, peer verification and transport.** `SO_PEERCRED` is checked before the connection reaches HTTP’s writer; mismatched peers receive zero bytes. Socket ownership is never consulted. Proxy is nil, keep-alives are disabled, and redirects are never followed. Every dial uses the configured Unix socket and repeats verification; I found no bypass through reuse, retries, or URL/path manipulation. Limits are 64 KiB headers, 1 MiB command responses, and 5/10/30-second dial/header/command timeouts. SSE retains its verified connection, intentionally without an overall body/time limit.

2. **PARTIAL — #123, codec and status handling.** Requests and responses undergo schema validation; unknown dispositions fail closed. `ParseSecret` returns fixed errors without quoting input. The non-Linux peer implementation refuses verification. However, redirect responses with `Location` bypass command-response decoding—see finding below.

3. **PASS with diagnostic nit — #124, token loading.** Nonempty `ADC_TOKEN` takes precedence. Directory and file guards match the requested checks, including descriptor-based ownership/mode/type validation, no-follow opens, FIFO non-blocking behavior, and bounded reads. Following `~/.config` is acceptable **provided its resolved ancestry is trusted**; this is an assumption, not something this implementation verifies.

4. **PASS — #124, token writing.** The checked directory descriptor anchors creation and rename. Exclusive creation, no-follow, descriptor chmod to 0600, file sync, atomic replacement, and directory sync are present. Destination symlinks are replaced rather than followed. I found no attacker-selected write location within the stated trusted-ancestor/UID boundary.

5. **PASS — #124, CLI wiring.** Transport activates only with `ADC_SOCKET`. Defaulting to the caller’s UID is safe for the private-socket contract. A shared daemon running under another UID is rejected until `ADC_DAEMON_UID` explicitly names that UID; there is no automatic relaxation. Malformed UID configuration produces `could_not_run`. This authenticates an OS UID, not an individual process within that UID.

6. **PARTIAL — regression coverage.** Zero-byte rejection and the owner-check seams are sound. Coverage does not establish that removing every guard makes tests fail; specific gaps follow. The stated non-test sizes, **235 and 257 lines**, are correct.

**Medium findings**

- **#123 — Valid redirect-status command responses are discarded.** `internal/client/client.go:79`: returning `errRedirect` makes `http.Client` close the response body and return an error before schema validation. A local probe confirmed that identical valid refusals produce exit 1 with HTTP 409 but exit 2 with HTTP 302/307 plus `Location`. **Fix:** return `http.ErrUseLastResponse`, then apply the existing bounded body/schema checks. Add valid 3xx-response tests that also assert no second request occurs.

- **#123 — The invalid-request test does not prove validation precedes dialing.** `internal/client/client_test.go:163`: removing `checkRequest` still yields an accepted test error from `/nonexistent/adcd.sock`. The response tests also lack a known disposition with missing required fields, which would distinguish schema validation from union decoding. **Fix:** assert a contract-validation error and zero transport activity; add malformed known-variant responses. Add coverage for header limits, timeout settings, and connection policy.

- **#124 — Write tests do not protect several promised guards.** `internal/client/token_test.go:126` and `:174`: ordinary-umask success does not exercise the chmod requirement; successful reads cannot detect missing syncs; planted symlinks do not independently exercise exclusive creation against an existing regular file. **Fix:** add a restrictive-umask subprocess test, a planted regular-temp-file case, and sync-failure/order coverage.

**Low finding**

- **#124 — Malformed/oversized file errors omit the filename.** `internal/client/token.go:136` and `:139` return the generic `ErrTokenMalformed`. Contents remain protected, but the promised file-specific diagnostic is absent. **Fix:** wrap these errors with `~/.config/adc/token`, retaining `errors.Is` compatibility and never including input bytes.

The requested `CGO_ENABLED=1 go test -race -count=1` suite passed for client, CLI, and identity using the pinned Go executable because `go` was absent from PATH. Guard-removal conclusions above are from source inspection, not mutation runs. No source files changed; the working tree is clean.
