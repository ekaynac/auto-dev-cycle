### High

**H1. A helper's total overflows `int` and wraps, so a real weakening reads as a gain.** `internal/accept/integrity_helpers.go:105-116`
- **Cause:** `total` adds the callees' totals with no bound. Duplicated calls multiply, so a short file can produce totals past 2⁶³.
- **Input (probe):**
  - **The structure** (about 10 KB):
    - `c16` has one assertion;
    - each `c_i` (i = 1…15) calls `c_{i+1}` 16 times, so `c1`'s total is 2⁶⁰;
    - `top` calls `c1` 7 times, then `c2` … `c16` 15 times each, so the duplicated part totals exactly 2⁶³ − 1;
    - `top` then calls `bcheck`, a distinct asserting helper (`if Add(2, 3) != 5 { t.Fatal(…) }`);
    - `TestTop` calls `top`.
  - **The base:** `top`'s total is MaxInt64 + 1, which wraps to MinInt64.
  - **The head:** removes `top`'s `bcheck(t)` call. `top` becomes MaxInt64, which reads as a gain.
- **Result:** accepted, with no block and no warning. A real assertion is lost.
  - Main accepts it as well (it does not compare helpers, and `TestTop`'s own count is unchanged). So this is not a regression, but it is within the promise ("a decrease blocks").
  - The structure can be planted in an earlier change, since adding helpers and tests is clean.
- **Side effect:** past 2⁶³, the same overflow produces nonsense blocks on unchanged helpers, for example "`c1`: (0 → −9223372036854775808)".
- **Fix:**
  - Saturate the sum at `maxAmount`.
  - Make any function whose total saturates, in either version, unverifiable ("test helpers' totals past the guard's bound"), never compared.
  - Add the input above as a row.

**H2. An unchanged deep chain of helpers blocks at random, a regression against main.** `internal/accept/integrity_helpers.go:73`, which reads main's `s.asserting` (`internal/accept/integrity_go.go:622`)
- **Cause:** `asserting` is main's fixed point, capped at 32 iterations. Each iteration walks the `s.same` map and updates it in place, so how many levels a chain gains per iteration depends on the map's order. Base and head are separate scans, so they can stop at different depths.
  - P14d-w reads a call as asserting only when `s.asserting[c]` holds.
  - Helpers past the reached depth therefore record no calls, in one version but not the other, and their totals drop to 0.
- **Input:**
  - **The base:** a test file with `e200`, which has one assertion; then `e_i(t) { e_{i+1}(t) }` for i = 199…0; and `TestE`, which calls `e0`.
  - **The head:** a comment-only change to `pkg/calc.go`.
- **Result:** five runs at head gave 17, 15, 1, 2 and 2 blocks, each "`pkg.e14x`: a helper's assertions weakened (1 → 0)". Five runs on the base accepted every time.
- **Also:** my fan-out-2 chain of 63 blocked unchanged helpers `c10`, `c11` … the same way.
- **Fix:** record a call to a function of the test files whatever `s.asserting` says, and let `total` decide. Keep a second list of the calls `count` counted as one, for the `asserts − len(calls)` subtraction. Or compute a deterministic fixed point for this layer: a worklist over the reverse call edges, charged.

### Medium

**M1. A caller that loses an assertion while a callee gains one is silent. The residual does not state it.** `internal/accept/integrity_helpers.go:111-112`
- **Input:**
  - `mid(t)` has one assertion of its own and calls `leaf(t)`, which has one assertion.
  - `TestMid` calls `mid`.
  - The head removes `mid`'s own assertion and adds a second, unrelated assertion to `leaf`.
- **Result:**
  - `mid`'s total stays 2 → 2, and `leaf`'s gain is clean. The change is accepted, and the base accepts it too.
  - `mid`'s check is lost, and nothing names it.
- **Why it is unstated:** the residual's "replaced by a call to an asserting helper with at least as many" covers a caller that adds a call. Here the caller adds nothing; an existing callee grew.
- **Fix:** when computing the head's totals, expand each callee that exists at the base by min(base total, head total). A new callee (an extraction) still counts its head total, so the `openEffectStore` → `openEffectStoreAt` refactor stays clean. Or state the class.

### Low

**L1. Two unstated false blocks against main.**
- **Inlining:** a helper's assertion moved into its only caller. In the probe, `inl`'s check was moved into `TestInl`, and `inl` blocked "(1 → 0)", although the test runs the same check.
- **An unused helper weakened:** `unused` blocked "(1 → 0)", although no test calls it. Removal blocks only while the name is still used, but weakening blocks even when it is not.

Main accepts both. **Fix:** state both. Or, for the second, compare only helpers that are reachable from a test, or whose name is still used.

**L2. The block messages say "helper" for tests too.** `internal/accept/integrity_helpers.go:178-180`
- **Effect:** in the replay and the probes, `TestTop`, `TestGen` and `TestTwice` are reported as "a helper's assertions weakened". For a `Test*` function, this duplicates main's "fewer assertions in a test" with a second, differently counted figure: `TestRegistryMatchesDesign` is "8 → 5" here.
- **Fix:** skip `Test*` functions here, since main already compares them by the same count with helper calls as one. Or name them "a test's expanded assertions".

### Judged as sound
- **Dead branches:** an assertion under `if false`, `for false` or a dead `switch` clause is removed, each dead subtree is read once and charged, and its asserting calls are not expanded twice.
- **Race variants:** the weakest declaration is taken.
- **Removal:** a removed function blocks only while its name is still used; an unused helper deleted is clean.
- **Cycles:** a call within a component counts one, and the components are deterministic. Main's map-order `asserting` feeds H2 but not Tarjan.
- **The extraction refactors:** they stay clean, and the replay matches the PR's description exactly.
