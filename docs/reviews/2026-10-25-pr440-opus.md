### 2. Can a credential, acceptance byte, hidden name or the canary escape?
**Printed output is handled well:**
- `die` redacts every `known` form, and each live credential is registered.
- `redacted` replaces the acceptance FILE paths and the canary in the run's excerpts.

**Process arguments are not:**
- **H1.** The credentials appear in argv, which is world-readable via `/proc/PID/cmdline`:
  - `scan` runs `grep -rlaF -- "$f" "$@"`, with each form of the secret as an argument (`scripts/lib/secrets.sh:53`). `live_after` calls it for every live credential over the whole work directory, captures and clones included.
  - **Probe:** with a test secret `sk-live-PROBE-…` registered by `known`, `ps -eo args` sampled during `scan` showed `grep -rlaF -- sk-live-PROBE-0123456789abcdef…`.
  - **adcd's start:** `start_adcd` runs `env -i … ADC_CREDENTIAL_X=<secret> …/adcd`, so each credential sits in `env`'s argv until it execs, at both starts.

  The new `root_secret_scan` does it right (`forms | … grep -f -`).
- **M2.** The canary appears in argv for the whole run: `--canary TEXT` in the driver's argv, and in the `node` and `grep` calls that take it.

The sandbox's containers run in their own PID namespace, so this exposure is to the host's other local users and processes, not to the builder or the reviewer.

**Kept files:** `--keep` keeps `out/canary`, `live-expect.json` (the canary), the captures, and the store with the acceptance blob, and the message says only "kept $work" (L1).

**The benchmark** (`benchmark-run`) carries no acceptance, canary or hidden name (I grepped the schema and `internal/bench`).

- **Probe:** that line, `JSON.stringify`'d into a captured body, is **not found** by the driver's `grep -rqaF`. A plain `// ADC-CANARY-…` comment line is found.

**M3:** the live expect requires every round's selected result to match (the checker loops over every node of the kind). A legitimate reviewed candidate after a repair round therefore fails, because round 1's no_go review is `found` and its gate is perhaps `found`. That is fail-closed, but it can fail checkpoint (a)'s live run on a valid path.

### Findings
- **H1** (BLOCKING, High: a security deviation; a real provider credential is exposed to every local user):
  - **Where:** `scan`'s grep argv (`scripts/lib/secrets.sh:53`, reached from `live_after`), and `env -i … ADC_CREDENTIAL_X=<secret>` in `start_adcd`.
  - **Fix for `scan`:** feed the forms on stdin (`forms "$secret" | grep -rlaF -f - -- "$@"`), as `root_secret_scan` already does. That also turns seven greps into one.
  - **Fix for the start:** start adcd from a subshell that unsets the caller's environment and then `export`s the run's variables and the credentials (builtins, so no argv), then `exec`s adcd without `env -i`.
  - **Row:** add one that runs `scan` and `start_adcd` under a fake adcd and asserts that no child's `/proc/*/cmdline` holds the secret.
- **H2** (BLOCKING, High: fail-open of §2.3's confidentiality check): the canary is searched only literally in JSON-encoded captures and reads (`cycle-live.sh` `live_after`; `cycle-expect.mjs`'s `show.json`/`events.jsonl` check).
  - **Fix:** search each of the raw canary, its JSON-escaped form (`JSON.stringify(c).slice(1, -1)`) and its trimmed core (leading whitespace dropped, with the escaped form of that too).
  - Or refuse at setup a canary whose trimmed form holds a character JSON escapes, and search the trimmed form.
  - **Row:** a captured `JSON.stringify` body carrying a tab-and-quote canary must fail the run.
- **M1** (OBLIGATION, Medium): `live_after` installs `--bench` before the final `~/.config/adc` comparison, so a run that then fails (exit 1) leaves a benchmark at `--bench`. Move the `install` to after that check, as the last step before "ok", and pin it in `TestLiveBenchOnlyAfterTheRestart`.
- **M2** (OBLIGATION, Medium; I18 material in the process table): take the canary from a file (`--canary-file`, 0600) or from an environment variable, never from argv. Pass it to `node` and `grep` on stdin or through the environment (`grep -f -`).
- **M3** (OBLIGATION, Medium): the live expect rejects a reviewed candidate reached through a repair round. Either check only the closure's chain (`bench.closure`, the selected round's build, accept, gate and review), or state in §2.3 and the driver's header that the exit run requires a first-round candidate, and that a repaired candidate fails it.
- **L1** (OBLIGATION, Low): on `--keep` in live mode, either remove `out/canary` and `live-expect.json`, or print that the kept directory holds the canary, the acceptance and the captured requests, and must not be shared.
- **L2** (OBLIGATION, Low): `--bench` is checked absent at the start but `install`ed at the end, which overwrites a file created in between (90 minutes). Write it with no-clobber (`set -C` with a redirect, or `ln` of a temporary file).
- **L3** (OBLIGATION, Low): the capture's positive control proves only that a builder request was captured (the requirement). Also require a captured body for each reviewer call, by the review lease's calls in `blob.capture_kept`. Otherwise "the canary in no reviewer request" rests on the reviewer's calls going through the same captured gateway, which is true today but unchecked.
