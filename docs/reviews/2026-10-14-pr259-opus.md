## Opus pre-review of #259

Verdict: NO-GO

One High finding blocks this PR. Its fix is small and stays inside `internal/recovery`. Steps 1 to 4, `Next`, the settlement step and the placement guard are correct for the X3 path. The six-step sequence, the second-restart no-op and the replacement at token 2 all reproduce. I wrote throwaway probe tests in a scratch worktree, outside the PR, and removed them with the worktree; they are labelled A to F below.

### High

**H1. A failure in the orphan stage skips steps 2 to 4, and a hostile adapter can make that failure permanent.** Location: `internal/recovery/recovery.go:85-104`, `internal/recovery/orphans.go:49,68-73`.
- **The code.** `Run` computes the cut set and runs revoke, seal and settle only `if err == nil` after `refuseOrphans`. `refuseOrphans` returns on the first failure from `orphans()`, the refusal command or `os.Rename`. The root is never renamed in that case, so every later start hits the same failure.
- **Scenario.** The adapter outlives the controller. It writes to `out/` as the controller's uid: rootless podman's `--user=0:0`, or a host-side adapter. It runs `chmod 000 out` and the controller is killed.
- **Probe D:** on every restart, `Run` returns "permission denied", L1 stays `active`, A1 stays `lost`, and the 400-token reservation stays held. `dispatch.placed` then refuses the unit forever ("already has live lease").
- **Probe B:** if `out/` is replaced by a symlink or a file, every run fails with ENOTDIR, with the same result.
- **Probe A:** a rename failure (EACCES on the exchanges directory) also skips steps 2 to 4 for that start.
- If P22a treats `Run`'s error as fatal, `adcd` never starts.
- **Why the model misses it.** The model's I6 ("recovery completes") cannot see this, because the model leaves out the orphan stage.

**Fix:**
- Decouple the orphan stage from steps 2 to 4. Step 1 already fences A1, so refusing its output is a record, not a precondition.
- Always compute the cut set and run steps 2 to 4, joining errors.
- In the orphan stage, when `out/` cannot be opened or read, record one refusal for the root: handle `out`, size 0, and the errno in the detail, never the bytes. Then still rename the root.
- Return the cleanup failure separately from `Run`'s error, so P22a can log it without refusing to start.
- Add a test for each of: `out/` at mode 000, `out/` as a symlink, and a failed rename. Each must end with L1 settled.
- Add a "refusal stage fails" action to the model.

### Medium

**M1. A root's attempt is taken from its directory name (the background security review's question).** Location: `orphans.go:41-48`, `adapterhost/exchange.go:50`.
- **Confirmed.** The id is parsed from `exchange-<att>-…` and checked only for TypeID syntax (`ids.Check`). It is never checked against the store.
- **Probe C:** a root named after an attempt id that was never minted got an `attempt.output_refused` event with that id as its subject. Under 09 that makes the id "untrustworthy".
- The reverse also works: A1's adapter can rename its own root after another attempt, so A1's refusal record, which X3 asserts, disappears or lands on the other attempt.
- Each root yields up to 64 events, and the number of roots is unbounded, so a forger can flood the log at every start.
- **Reachability.** It needs write access to the exchange parent (`Host.Root`). `out/`'s absolute path reveals that parent, and a host-side adapter at the controller's uid without a mount namespace can write it. The `out/` grant alone does not give this.
- **Real severity: Medium, not High.** Nothing is ever read or ingested, the fence is not bypassed, and accounting is untouched. Step 1 has already closed every publication, so a forged name cannot make `FenceAttempt` pass. The harm is to the integrity of the record and to start-time volume.
- **Fix:** bind each root through records the controller holds, never through the name.
  - Iterate the attempts the store says were cut: `lost{controller_restart}`, or superseded after such a loss.
  - Look up exactly that attempt's root, either by making the name deterministic (`exchange-<att>`, created with O_EXCL) or by recording the `MkdirTemp` suffix in a host record before `attempt.started`.
  - Before using a root, `lstat`/`fstat` it: a real directory, owned by the controller's euid, mode 0700, opened `O_NOFOLLOW`.
  - Remove any `exchange-*` entry nothing claims without recording an attempt-scoped event; at most, record a host-level diagnostic.
  - Cap the total number of refusals per start.

**M2. Path-based chmod follows symlinks.** Location: `orphans.go:74`; the same pattern already exists at `adapterhost/exchange.go:96`.
- `os.Chmod(<root>/in, 0o755)` follows a symlink. In probe C, a planted `in` symlink to a 0600 file outside the tree left that file at 0755, readable by every local user.
- `orphans()` also follows a symlinked root, because `O_NOFOLLOW` covers only the last path component. It then lists a foreign directory's `out/` names and sizes into the log.
- **Fix:** open the root `O_DIRECTORY|O_NOFOLLOW`. Then `openat(rootfd, "in"/"out", O_DIRECTORY|O_NOFOLLOW)`, `Fchmod` the descriptor, and remove beneath the root's descriptor. Apply the same change to `exchange.remove`.

**M3. A crash between the run's final transaction and `x.remove()` marks an admitted result untrustworthy.** Location: `orphans.go:51-65`.
- **Probe E:** after a `SubmitResult`, A1 is `finishing` and its root still holds the outputs that were ingested. The fence refuses them as `stale_attempt`, and `lease.Untrustworthy(A1)` becomes true.
- **Fix:** record refusals only for roots of attempts in the restart-cut set (this falls out of M1's fix). Remove other roots without recording.

**M4. Some crash points never converge.** Location: `recovery.go:59` (`Next` acts only on `lost{controller_restart}`).
- A crash while A1 is `finishing` (probe E: L1 stays `active`, A1 stays `finishing`), `stopping` (after `graph.Supersede`'s `StopRunning`), or `lost{agent_disconnect|stream_dead}` (adapterhost's final transaction) leaves L1 `active` forever.
- Placement is then refused forever and the reservation is never returned.
- I8's gap row says "nothing revokes and settles a lost attempt's lease", which is not limited to restart losses.
- **Fix:** at restart, extend `Next` so that a `stopping` attempt, or one lost for another reason, is revoked if its lease is active, sealed (`abrupt_loss`), then settled. Hand a `finishing` attempt to the completion path. If this is not done here, record it as an explicit P22a obligation with an F case, and add these as initial states in the model.

**M5. The proposed X3(b) wording is wrong.**
- `ledger.trusted` takes the field-wise maximum of the delta figure and the gateway figure, and `capacity.owed` then sums that maximum's fields. So the liability is not "the larger of reservation, delta sum and count".
- **Probe F:** deltas 350 in / 200 out, floors totalling 8 in / 1064 out. The liability is **1414**, where the proposed wording gives 1072.
- In the installed noquery X3, the floor's output is `max_tokens`, so the liability will typically be Σ delta input + `max_tokens`. That is neither of the sums the wording names. `TestKillMidCall` cannot show this, because its floor (4/64) is dominated by the deltas.
- **Fix:** use this wording: "= max(positive reservation, the token total of the field-wise maximum, as input+cache and output, of the deduplicated persisted delta sum and the gateway's per-request count, floors included at request bytes ÷ 16 input and `max_tokens` output)". Add a test where the field-wise maximum exceeds both sums.

**M6. A crash between the refusal commit and the rename duplicates the refusals.** Location: `recovery.go:153` (`IdempotencyKey: cmd`), `orphans.go:51-69`.
- **Probe A:** the refusal count went from 1 to 2 for the same `out/` entry. This contradicts "without double events" and X3's "a second restart records no event" in that window.
- **Fix:** derive the refuse command's `IdempotencyKey` from the root's name, e.g. `recovery.refuse_output/<basename>`. Its input is the same on each retry, so the store replays the command instead of appending again.

**M7. The settled-lease guard exists only in `dispatch.placed`.** Location: `dispatch.go:155`, `lease/wiring.go:273`.
- In production code, "only placement makes a replacement" holds today: `Match` is the only caller of `RequestGranted` outside tests, and `Launch`'s `StartNext` is the only path to a successor.
- But `SupersedeAttempt` and `StartNext` accept a granted L2 while L1 is still `settling`. A direct `RequestGranted`, a fixture, or a future operator "retry" therefore bypasses step 4.
- The model's I3 also guards and asserts with the same `lease.Ended` predicate.
- **Fix:** in `SupersedeAttempt`, at admission only, refuse when `old.Lease` is not `Ended`. Point the model's start move at that check.

### Low

**L1. The Clock notes a floor only after its commit.** Location: `modelcall/modelcall.go:424-426`. A Reconciler read that falls between the commit and `floored()` relies on wall time alone. **Fix:** call `LoadOrStore` before `SubmitApplied`, and delete the entry on failure. An uncommitted key is harmless.

**L2. Ageing across a restart (#226 entry 77).**
- Monotonic ageing per process is correct, and wall steps backward stay conservative.
- A floor recorded before the restart ages by wall time only. If the wall clock steps forward during the downtime, the floor looks old at once and the provider is queried early.
- That early reconciliation sticks, because no later gateway count triggers a re-ask.
- This residual is acceptable for M1 if it is recorded in #226.
- The 11-minute `FloorGrace` wait is testable in-process (`Reconciler.Now`, `Clock.Now`). The installed X3(a) needs either P24's driver to wait past the grace, or a knob that exists only in a test build. Name it as a P22a/P24 obligation now.

**L3. Cleanup leftovers.**
- `refused-*` directories are never swept again.
- A still-running adapter keeps writing the renamed inode.
- Truncation at `maxOrphans` is silent.
- **Fix:** sweep `refused-*` at each start, record a truncation marker, and have P22a kill orphaned adapter process trees at start.

**L4. Model scope (D62).**
- The model checks §8 item 3's publication, fencing, settlement and replacement sequence. It uses the real `Next`, `ApplyLease`, `ApplyAttempt`, `Supersede`, `Fence` and `Ended`, and mirrors three store rules, which the PR states honestly.
- The state count grows only with the crash counter (169 states at 3 crashes, 279 at 5, all invariants holding), so 114 is an adequate bound.
- All six fault fixtures turn their invariant red. "The lease settles before its attempt" fails at `[]`, which is valid because I6 is a "from any state" check.
- Gaps:
  - the orphan stage (hence H1);
  - start states other than A1 running (M4);
  - an A3 after A2 is cut;
  - liability amounts (I5 is a boolean).

**L5. Two guards have no discriminating test.** Mutations that survived: removing `Next`'s identity clause (`l.ID != a.Lease || …`), and disabling the "may still publish" guard (`orphans.go:57`). **Fix:** add a unit test of `Next` with a mismatched lease, and one internal test where the fence passes.

### Inertness and P22a
- Inertness is confirmed. Nothing outside tests constructs `Recovery` or `Clock`. The only live change is the exchange root's name, which the harness and fixtures pick up.
- The PR's P22a obligations are right. Add:
  - `Run`'s cleanup error, and after H1 its orphan errors, must not block start;
  - `Units` must be `graph.Units`;
  - kill orphaned adapter trees;
  - M4, if it is not fixed here.

### Fault evidence
I reran two of the PR's mutations, and both match what it claims:
- **M4** (`Ended` admits `settling`): red in `TestTheRecoveryModel` and `dispatch.TestMatchAndLaunch`.
- **M3** (orphaned output not refused): red in `TestKillMidCall` and `TestTheOldAttemptPublishingAfterItsReplacementStarts`.

On the clean tree, the recovery, dispatch, capacity, ledger, modelcall, lease and adapterhost packages all pass.

X3(a) as proposed ("≥ the served-usage log, equal under honest usage, otherwise flagged") is sound. Phrase it as "settled = the field-wise maximum of the query's answer and the gateway's bound". With an honest stub, that equals the served log.
