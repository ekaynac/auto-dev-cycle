### BLOCKING

**B1 (High). `gosel.Std` never returns on a rooted import path, and the gate now calls it.**
- **The loop:** `for q := p; ; q = path.Dir(q)` (`internal/gosel/gosel.go:122`) stops only when `q` has no `/`. `path.Dir("/x")` is `"/"`, and `path.Dir("/")` is `"/"`, so `"/x"` and `"/"` loop forever.
- **How the gate reaches it:** `AcceptanceFits` calls `gosel.Std(p, named)` for each unnamed import of every Go file in the acceptance's directories, the base's included (`internal/gate/acceptance.go:334`). It runs synchronously in `overlayOf` (`internal/daemon/gate.go:406`) and never checks `ctx`.
- **Effect:** an acceptance `p/h_test.go` holding `import "/x"` passes `AcceptanceTests`, and then `AcceptanceFits` never returns (probe: it did not return in 5 s for `"/x"` or for `"/"`). In adcd the gate goroutine spins one core forever. The gate node stays claimed with no hold, no result and no retry, and a restart rediscovers the claim and hangs again. Under the rubric, that is a task stuck with no hold.
- **New this round:** the previous round's gate `std` was `slices.ContainsFunc` over a list, with no loop. Go itself refuses the path ("is not a package path").
- **Fix:** in `gosel.Std`, return false for a path that is not an import path: `module.CheckImportPath(p) != nil`, or at least a leading `/`, an empty element, or a trailing `/`. Alternatively, end the loop at `"."` or `"/"`. Add a `gosel` row, a gate row for an acceptance importing `"/x"`, and an accept row; the same fix closes accept's bounded variant.

### OBLIGATION

**M1 (Medium). `gosel.Recv` does not unwrap a parenthesised receiver, so `AcceptanceFits` misses a method the base already declares.**
- **The cause:** `Recv` returns `"(*S)"` for `func (s (*S)) M()` and `"(S)"` for `func (s *(S)) N()`. The deleted gate `recvType` unwrapped `ParenExpr`.
- **Input:** a base with `type S struct{}`, `func (S) M() {}`, and an acceptance helper with `func (s (*S)) M() {}`.
- **What go does:** it fails with "method S.M already declared".
- **What the gate does:** it expects the test, so every candidate gets `found/gate_test_failed`.
- **Why Medium:** it fails closed and is bounded by the rails, but it regresses a check the plan states ("a method the base type has").
- **Fix:** unwrap parentheses in `gosel.Recv`, for instance with `ast.Unparen` on the receiver type and each `StarExpr` before `types.ExprString`, and add a gosel row. This changes accept's keys for parenthesised receivers. Base and candidate are keyed by the same function, so the change is a consistent correction; pin it with an accept row.
