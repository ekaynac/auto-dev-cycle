Each mutation turned exactly its own test red. The fault evidence discriminates.

What holds up under attack:
- **Gateway only.** Every request is `POST …/chat/completions` with only the Bearer gateway token. The adapter reads no credential and sends 7 keys, all on the 20-key allowlist. `model` is always the pinned model.
- **Refusals come from the header only.** Since #248 the gateway forwards only the upstream's parsed Content-Type, so an upstream cannot set `Adc-Gateway-Refusal`. A body shaped like a refusal stays an upstream outcome. The reply is capped at 16 MiB.
- **Fencing.** A stale token, in `run` or as the gateway's `unbound`/`lease_not_running_attempt` refusal, ends the run with nothing in `out/` and no error event.
- **The reviewer's decision.** It is checked with Ajv 2020. The default schema has `additionalProperties: false` at both levels. Output that does not parse or does not match becomes `degenerate_output`, never a decision. A reviewer has no tools.
- **Diff headers.** Control characters, `"` and `\` are refused, so no newline or tab can reach a header. A path containing ` b/`, such as `x b/y` or `a b/c d`, still applies to the right file with `git apply`, including an empty new file that has no `---`/`+++` lines. `..`, absolute paths and `.git` as any component (a `gitdir` file included) are refused.
- **The `/proc/self/fd` check fails closed.** When `realpath` fails it returns `""`, which never matches the root.
- **Install.** `dist-adapters.sh` packages `adapters/http-chat/{package.json,src}` with the same 5-package third-party closure, and no test files. `install-check.sh` makes the installed `main.ts` answer `describe` under `env -i`.
- **Size.** 663 lines against 650 is about 2% over, and comes from the security fixes. Acceptable.

No Critical or High findings.

### Medium

**M1. A refused write can delete a file outside the workspace (the race fix makes things worse).** `adapters/http-chat/src/workspace.ts:137-139`, with the same pattern at `:152-154` and `:58`.
- **The failure.** When the path did not exist at walk time, `write` opens with `O_CREAT` (not `O_EXCL`). If `pin` refuses, it runs `unlink(path)` by name. If a parent is swapped for a symlink between the walk and the open (the race the PR says it covers), the open reaches an existing file outside and `pin` refuses it. The cleanup `unlink` then follows the same symlink and deletes that outside file.
- **Reproduced.** I used the PR's own deterministic walk-then-swap hook, with `outside/victim.txt` already present. `write("sub/victim.txt")` is refused, and `outside/victim.txt` is gone.
- **Same race elsewhere.** `remove` unlinks `real` by path after the pin, so a component swapped in between redirects the unlink. `walk`'s `mkdir` can create directories outside.
- **Why not High.** Exploiting it needs a concurrent writer in the workspace, and no M1 sandbox runs one during the edit loop.
- **Fix.** Pin the parent directory and act relative to it:
  - Open the parent with `O_DIRECTORY|O_NOFOLLOW` and check its `/proc/self/fd/N` real path is under the root.
  - Create, open and unlink through `/proc/self/fd/<dirfd>/<name>`, which is effectively `*at()`.
  - Use `O_CREAT|O_EXCL` when the walk saw no file, so an existing file is never adopted.
  - Unlink after a refusal only a file this call created with `O_EXCL`, again through the dir fd.
  - Add the deletion case to the swap test, with a file already present outside.
  - Correct the PR text that says the race is covered.

**M2. Nothing bounds the number of tool calls in one turn or the size of the message history.** `adapters/http-chat/src/adapter.ts:206` and `:219-223`.
- **The failure.** A reply of up to 16 MiB can hold on the order of 200k `read_file` calls. Each returns up to 256 KiB, and all of it is pushed into `messages` and `JSON.stringify`'d for the next request. That can be tens of GB, so the adapter OOMs. A model steering tool calls, or a hostile upstream, can do this in one turn.
- **Note.** Anything over the gateway's 8 MiB `maxBody` is refused anyway (`body`, 413), so the memory is wasted before a certain refusal.
- **Fix.**
  - Cap the calls handled per turn (for example 64), answering the extra ones with `error: too many tool calls`.
  - Keep a running byte count of `messages`, and end the run as `could_not_run/executor_incomplete` before a request would pass the gateway's 8 MiB.
  - Bound `list`'s `readdir` too (`fs.opendir` with an early stop) instead of reading the whole directory and then slicing.

**M3. #226 entries 55 and 56 are assigned to P13, and the PR drops them without re-routing them.** The ledger lists both as "P13; **blocks P22a activating launch**". The PR says only "not in this PR".
- **Fix.** Either implement them here (hold back a secret prefix of at least 8 bytes in `Close`; also scan the JSON-escaped form), or change both entries' owner in #226 to a named item before P22a, so the launch blocker is not orphaned. In the same edit, move entry 58's `base_url` half to P22a: "P22a must mint a `base_url` with no path." Today a `/v1` `base_url` fails closed as the gateway's `path` 404, which is safe but unenforced.

### Low

**L1. A FIFO or device in the workspace blocks `read_file` forever.** `workspace.ts:103-107` and `:74`.
- **The failure.** `read` never checks `st.isFile()` from the walk before `pin` opens with a blocking `O_RDONLY`. On a FIFO, the open hangs until the wall clock kills the attempt (I reproduced this). Git cannot store a FIFO and the model cannot create one, hence Low.
- **Fix.** Refuse `!st.isFile()` right after the walk in `read`, and add `O_NONBLOCK` to every `pin` open. Then a swapped-in FIFO cannot block either.

**L2. `.git` look-alikes are written to disk, and they make the whole cumulative patch unappliable.** `workspace.ts:31`.
- **The failure.** `segments` refuses only an exact `.git`. `sub/.Git/hooks/pre-commit`, `.git./config` and `git~1/config` are written and enter the patch, and `git apply` (2.43) then rejects the whole patch with "invalid path". The model can poison its own run. On a case-insensitive filesystem, `.Git` would be the real `.git`.
- **Fix.** Follow git's `verify_path` rules: case-fold the component, strip trailing dots and spaces and HFS-ignorable code points, then refuse `.git` and `git~1`.
- Leave `.gitattributes` and `.gitmodules` (filter drivers, `filter=lfs` with a global git-lfs) to P14's protected paths, and note that in P14.

**L3. A malformed tool call from the upstream throws out of `run`.** `adapter.ts:140` and `:222`.
- **The failure.** `tool_calls: [null]` makes `c.function?.name` throw a TypeError, which `serve` reports as an RPC error instead of a typed outcome. Also, upstream `tool_calls` objects are echoed back to the gateway verbatim, with any nested keys.
- **Fix.** Keep only well-formed calls and rebuild each as `{id: String, type: "function", function: {name, arguments}}`, with strings capped, before running it or pushing it into `messages`. Treat a call that is not an object as `degenerate_output`.

**L4. The output-token limit is enforced only from usage the upstream reports.** `adapter.ts:216` and `:228`.
- **The failure.** With no `usage`, or with `completion_tokens` under-reported, `outTokens` stays 0. Then `max_tokens` is never reduced and only `max_turns` ends the loop.
- **Fix.** When a turn reports no usage, count its output as `max_tokens` (or the reply's byte length divided by 4). Record in #226 that the gateway or P12b is the authority on tokens.

**L5. Cost recorded as 0 with `estimate: true` is safe only if the core treats it that way.** `adapter.ts:63-68`.
- **The failure.** A hostile upstream can send `usage.cost: 0`, which is recorded as an authoritative cash amount with `estimate: false`. That is not safe as budget input.
- **Fix.** Add a #226 entry: P30 and P12b must price from the gateway's observation of tokens and never trust an adapter-reported `amount_micros`, whether or not it is marked as an estimate.

**L6. One description does not match the code.** `gateway.ts:92`. The PR says `credential_*` gives `routing_violation`, but `credential_not_held` (503, from the controller) falls through to `executor_incomplete`/`other`. That result is reasonable, so fix the description, or add the code to the set if `routing_violation` is what was meant.

**L7. Directories are left behind.** `workspace.ts:58`. `walk(create)` creates parent directories before the content or pin checks, and does not remove them when the write is refused. The patch does not show them, but they stay in the workspace. Fix: create directories only after the last-component checks, or remove the ones this call created on a refusal.
