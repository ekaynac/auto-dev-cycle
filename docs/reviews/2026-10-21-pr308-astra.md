## External review of #308 (Astra, 2026-10-21)

Verdict: NO-GO

1. **Medium — new false block against main: accounting latency expires the response’s final write.** `internal/gateway/gateway.go:244`, `internal/gateway/serve.go:123`  
   **Input:** a valid HTTP/1.1 request, an immediately completed upstream response containing valid usage, and a final `Counts.Count` commit taking 45 seconds. The adapter continuously reads.  
   The last body flush leaves its 30-second deadline armed while `g.count` waits. After the handler returns, Go writes the terminating HTTP chunk under that expired deadline; the adapter receives an incomplete response. Main’s flushing code introduces no such deadline. This follows from [Go’s response-finalization implementation](https://go.dev/src/net/http/server.go#L1714). The slow-count test reads only response headers, so it misses this variant.  
   **Fix:** scope the idle deadline to actual writes and flushes, and provide a fresh bounded deadline for HTTP finalization. Verify complete client-side EOF with a count delayed beyond `writeIdle`. **This regression blocks approval under the requested rule.**

2. **Medium — capture and intent checks still race with `Unbind`.** `internal/gateway/gateway.go:448`, `internal/gateway/gateway.go:456`  
   **Input:** suspend a request immediately after either successful `g.live` check; let `Unbind` return; resume it with a capture or intent implementation that does not reject cancellation. `Keep` or `Intend` can then record after unbinding. `BlobCapture.Keep` itself writes blob bytes without consulting the context.  
   The original blocked-lease probe is addressed, but these nearest variants remain. The documented exception covers floors already decided, not capture or intent.  
   **Fix:** synchronize side-effect admission with unbinding and have `Unbind` await already admitted capture/intent operations before returning. Another standalone context check does not close the race.

3. **Medium — refusal writes bypass deadline enforcement.** `internal/gateway/gateway.go:555`  
   **Input:** an unbound request, or a third request at the cap, through a `ResponseWriter` lacking deadline support. `refuse` still calls `WriteHeader` and `Write`; it never reaches `flushing.Write`. An unsupported writer therefore receives output, and a blocking writer can hold the handler. On `Server()`, these writes have only the longer server timeout.  
   **Fix:** apply deadline enforcement before every response-writing path, including refusals and headers; abort without writing when deadline setup fails. The current unsupported-deadline test covers only forwarded response bodies.

4. **Medium — the cap’s no-body-read guarantee depends on `Expect: 100-continue`.** `internal/gateway/gateway.go:222`, `internal/gateway/serve_test.go:98`  
   **Input:** hold two requests upstream; send a third HTTP/1.1 request with `Content-Length: 1000`, no `Expect` header, and withhold its body. The handler selects 429, but Go’s normal HTTP/1 response path drains the unread body before emitting that response. The client can wait until the one-minute read timeout. [Go documents this automatic consumption](https://go.dev/src/net/http/responsecontroller.go#L119).  
   **Fix:** explicitly prevent draining before an early refusal and close the rejected connection. Cover the same withheld-body case without `Expect`.

No Critical/High or new accounting undercount was found. `Mint` is pathless; cap admission is atomic; repeated `Unbind` is harmless. Original M1, L2 and L3 are addressed.
