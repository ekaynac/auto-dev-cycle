1. **High — Negated tool tags recreate the original H1 failure.** `internal/gate/gate.go:581`

   Concrete input: on linux/arm64, attach `p/hidden_test.go` containing:
   ```go
   //go:build !arm64.v8.0

   package p
   import "testing"
   func TestHidden(t *testing.T) {}
   ```
   The constructed build context has no `ToolTags`, so it includes this file. The pinned toolchain’s default arm64 feature tag excludes it. `AcceptanceFits` repeats the same mistake at `internal/gate/gate.go:635`.

   Production calls this validation at `internal/daemon/gate.go:347`; `gate.Run` then expects `TestHidden` at `internal/gate/gate.go:226`. Its absent result becomes `Missing` at `internal/results/gotest.go:270`, then `found/gate_test_failed` at `internal/gate/gate.go:380` and `:397`. The task’s impossible acceptance is recorded as the candidate’s failure.

   The N2 comment describes only false refusals; negation makes the consequence materially different.

   **Fix:** share the platform build-context rule already implemented by `internal/accept/integrity_types.go:436`, which supplies toolchain experiments and architecture feature tags. Validate positive and negative constraints against the pinned environment before measuring the base.

2. **High — Ordinary Go files in the overlay bypass package and redeclaration validation.** `internal/gate/gate.go:653`

   Concrete input: attach these two new files in an otherwise valid package:
   ```go
   // p/hidden_test.go
   package p
   import "testing"
   func TestHidden(t *testing.T) {}
   ```
   ```go
   // p/helper.go
   package p
   func TestHidden() {}
   ```
   `AcceptanceTests` finds the test, but `AcceptanceFits` skips `helper.go`. Both files are subsequently written, compilation fails with a redeclaration, and the gate records the candidate’s failure. Changing the helper’s package to `q` similarly bypasses the promised package-clause refusal.

   These are acceptance-authored conflicts, independent of anything the candidate adds.

   **Fix:** validate every active Go source file the overlay introduces, including helpers. Collect base packages for every affected Go directory and check the combined package clauses and declarations before `gate.Measure`.

3. **High — Acceptance rejection and read-error paths leak through daemon stderr.** `internal/gate/gate.go:691`; `internal/daemon/gate.go:341`

   Concrete inputs:
   - Two hidden files declaring `TestSecretCanary` produce an error containing that hidden test name.
   - An acceptance blob whose stored bytes no longer match its digest produces an error containing the digest through `internal/daemon/accept.go:277`.

   These errors return through `internal/daemon/gate.go:163` and are printed verbatim by `internal/daemon/run.go:210`. Production connects that writer to stderr through `internal/daemon/wiring.go:164`, `internal/daemon/daemon.go:252`, and `internal/daemon/cmd.go:45`.

   Thus acceptance information escapes through operator-visible diagnostics even though the API reads remain sanitised. The new `noLeak` coverage does not exercise this channel: `internal/daemon/candidate_test.go:163` iterates CLI read commands.

   **Fix:** return safe, fixed diagnostics from the acceptance boundary, preserving error classification without printing hidden identifiers, blob digests, or underlying blob-store paths. Include daemon stderr in confidentiality checks, including refusal and host-fault cases.

4. **Medium — A valid, runnable test is refused as “no test.”** `internal/gate/gate.go:609`

   Concrete input:
   ```go
   package p
   import . "testing"
   func TestHidden(t *T) {}
   ```
   Go runs this test, but `goTest` requires an `ast.SelectorExpr`; a dot-imported `T` is an identifier. An acceptance containing only this file receives terminal `runner: failed`. The added test at `internal/gate/gate_test.go:350` deliberately preserves this incorrect refusal.

   **Fix:** implement Go’s accepted test-signature forms, including unqualified `*T`, while checking imports/types as needed. Keep runnable-test discovery separate from any explicitly documented authoring restriction.

5. **Medium — An upload-valid acceptance exceeds the overlay bound only after the base runs, then receives the wrong hold.** `internal/gate/gate.go:744`

   Concrete input: one valid hidden test plus sixteen 1 MiB data attachments. This satisfies the attachment-count and upload limits, but exceeds `maxOverlay`.

   `overlayOf` accepts it and `gate.Measure` runs. `writeFiles` subsequently returns `ErrSpec`; `internal/daemon/gate.go:190` converts this task-content problem into a profile hold. Changing the profile cannot reduce the immutable acceptance’s size.

   **Fix:** enforce the shared aggregate overlay bound in `overlayOf`, before measurement, and classify excess acceptance as `errContent`.

6. **Medium — New Go-selection rules duplicate existing repository rules.** `internal/gate/gate.go:572`, `:581`, `:600`, `:635`

   The reuse searches found existing equivalents:
   - Directory/file exclusion: `goSkipDir` and `goByName`, `internal/accept/integrity_go.go:113` and `:118`.
   - Test-name prefix/case handling: `goTest`, `internal/accept/integrity_go.go:252`.
   - Platform build selection: `builds`, `internal/accept/integrity_types.go:436`.

   Concrete consequence: the new build-selection copies disagree with `builds` on `arm64.v8.0`, producing finding 1. The new collection logic also lacks accept’s explicit `package documentation` exclusion at `internal/accept/integrity_go.go:283`.

   **Fix:** extract shared pure selection rules, parameterised where accept intentionally needs broader analysis. Avoid maintaining separate approximations of what Go collects.
