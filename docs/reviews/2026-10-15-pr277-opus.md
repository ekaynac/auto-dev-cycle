Verdict: NO-GO

**Method.** The reviewer read head e8a6b31 against main 7b6d37d, together with the #275 records (Astra r2, r3 and r4, and Opus). About 100 probe rows ran on both trees through `newFixtureWith`, `f.guarded` and `pyOwn`. The results leave out P14b's blanket block. Most rows use Astra r3's layout: a `setup.cfg` with `package_dir = =lib` and `where = lib`, a decoy `feature/flags.py`, the real `lib/impl/flags.py` reading `cfg`, a test with `skipif(feature.flags.SKIP)`, and a candidate that changes only `cfg.py`. The redirect in H1 and in H2's def-default form was confirmed under CPython 3.12.3. Main's `integrity_pyguard_test.go` was also run on the PR's code. The scratch worktrees are removed.

**The core problem.** Part 1 only tightens: it adds unread verdicts. Part 2 removes main's blanket verdict, "an install key → unread". That blanket also covered every gap that the non-install analysis still has. Plainness closes the forms in a package's own `__init__.py`, but it does not close code that runs because something is **imported**. So for a base with an install key, each such gap becomes a case where main blocks and the PR passes. This is exactly the combination that Astra #275 r3 called a regression.

**Checked, no issue (plainness; with install keys, so the PR's verdict is the one that counts):**
- **Refused, so not plain:**
  - a decorator, a class, walrus (value and statement), a subscript or attribute on a literal;
  - `def __getattr__` and `async def __getattr__`;
  - `__all__ +=`, `del`, `global`, `try`/`import`, an annotated dunder, a tuple target, a `for` or `with` target, `type X = …`;
  - PEP 695 type parameters, a lambda, call or `print()` default (keyword-only and after `*a`), `def …: pass; <stmt>`;
  - `F'…'` and `Rf'…'`, `"doc"; __path__ = …`, `from cfg import SKIP as __path__`, `from . import *`;
  - `sys.modules[…] =`, `importlib.import_module(…)`.
- **Accepted, correctly:**
  - an f-string annotation or return annotation under `from __future__ import annotations` (not evaluated);
  - a late `__future__` import (CPython rejects the file);
  - bytes, dict defaults, `__version__` and `__all__` literals.
- **Candidate side:** a candidate that adds a redirect to the init, to an imported helper or to a star source is blocked on the PR (P30b–P30d), by the existing "import path bound at import" rule or by `hit`.
- **`pyLex` against CPython:** form feed, a lone CR, CRLF, U+2028, U+0085, a BOM, VT, a nested PEP 701 f-string with quotes, a backslash in a comment, a backslash-newline in a string, and a def body followed by a module-level statement all give the same statements as CPython. Inconsistent tabs against spaces (L03) are read as a def body, but CPython raises `TabError`, so the import fails: there is no fail-open.
- **Part 2 readers:**
  - `setup(**kw)`, `pyproject` `package-dir` with `setup.py`, and a `.pth` give unread on both trees.
  - An install root that names a root package (A10) gives unread for the two roots.
  - Combined `setup.cfg` and `pyproject` keys only add shadow roots.
  - `Setup.py` and `__init__.pyi` are not used by pip or the import system.
  - Case sensitivity: no collision on Linux, and CPython checks case on macOS.
