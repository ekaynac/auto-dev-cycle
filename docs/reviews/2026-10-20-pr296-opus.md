### Findings

**M1 (Medium). Only one of the "three false blocks" is a false block of the verdict.** `docs/reviews/2026-10-20-p14c-widen-b-baseline.md:32-36`, `:50`
- `corpusCustom` (`internal/accept/integrity_pycorpus_test.go:410-450`) returns only the first reason, in sorted path order. `pyproject.toml` sorts before `pytest.ini`, and `python/pyproject.toml` before `python/setup.cfg`.
- **setuptools:** its `pytest.ini` is custom regardless (`norecursedirs`, `consider_namespace_packages`, `--doctest-modules`, `--import-mode`, `--doctest-glob`).
- **arrow:** `python/setup.cfg` `[tool:pytest]` has `addopts = --ignore=scripts`, which is custom.
- Only **networkx**, whose `pyproject.toml` is its only configuration file, is a false block of the verdict. Even there, fixing `pyConf` would not change networkx's verdict, because its closure is still unread (`networkx/__init__.py` star import).
- **The defect is wider than `:50` says** ("a pyproject.toml without a pytest table").
  - `pyConf` reads a whole TOML file whenever the letters `pytest` appear anywhere in it (`internal/accept/integrity_pyguard.go:257-258`), for example in a test extra.
  - `pyCustom` then rejects any word starting with `-` that is not in `pyOpt`, and any `pyCollect` substring, anywhere in that file (`:200-201`).
  - So a file with a real `[tool.pytest.ini_options]` table holding only `addopts = "-q"` also blocks if it has a classifier.
- **Minimal input on main.**
  - Base: `pyproject.toml` =
    ```toml
    [project]
    name = "x"
    classifiers = ["Development Status :: 5 - Production/Stable"]

    [project.optional-dependencies]
    test = ["pytest"]
    ```
    plus `tests/test_y.py`.
  - Change: add a comment line to `tests/test_y.py`.
  - Result: `tests/test_y.py: unverifiable: a pytest configuration of the base moves collection off its defaults or is unread`.
  - Controls: without the `pytest` dependency the change passes, and with the dependency but no classifier it also passes.
  - With `git_describe_command = "git describe --dirty --tags"` (setuptools-scm) instead of the classifier, it blocks the same way.
  - The defect fails closed: it is a false block, not a bypass.
- **Fix, runner:** have `corpusCustom` report every configuration file's reason.
- **Fix, report:** say networkx is the one false-block verdict, and that setuptools and arrow hit the same reader defect but are custom anyway. In `:50`, describe the trigger as "a TOML that mentions pytest anywhere is read whole".
- **Fix, guard:** this needs the lead's decision, as the report says. A precise version would be a real TOML parse: take `tool.pytest` and `tool.pytest.ini_options` only, and fail closed on a parse error, an escape, or a quoted or dotted `tool` key.
