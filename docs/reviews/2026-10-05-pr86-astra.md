# PR #86 (knowledge contract fixtures): Astra reviews

## Review of #86 (Astra, 2026-10-05)

Verdict: GO with changes

No Critical/High findings under D43.

- **Medium — `restriction_dropped` conflates missing restrictions with undeclared provenance.** `internal/knowledge/manifest.go:109` wraps every `derivedFrom` failure, including an unrestricted ref with empty or foreign lineage. No restriction necessarily disappeared. Moreover, `schemas/vocab/reasons.yaml:66` describes “not a declared input” as sufficient for refusal, although valid derived refs are accepted. **Fix:** reserve this code for an actual missing inherited restriction; distinguish undeclared provenance, and correct the description to acknowledge permitted derivations. This matters because registered meanings cannot later be repurposed.

- **Medium — The lineage fixture does not prove that both source restrictions are required.** `internal/fixtures/knowledge.go:140` tests `{A}` being refused and `{A,B}` being accepted, but never `{B}` being refused. A realistic regression retaining only the last input for a shared ID would require only B and still pass this fixture—including its identity, restriction-preservation and stale-view assertions. **Fix:** add a B-only derived ref expecting `failed/restriction_dropped`, and update the golden. Existing unit tests cover input-order loss, so this is a nonblocking gap in the installed contract fixture.

The remaining contract choices are sound:

- `view_stale` with `could_not_run` correctly requests regeneration. No external hold is needed for this internal retry. The knowledge domain and source `"10"` are appropriate.
- `coverage_claim_contradicted` with `failed` correctly covers omitted declarations and compaction marks: observed delivery evidence contradicts those omissions, even when the claimed status is already partial.
- Both fixtures exercise real validators without reproducing their algorithms. The declared-only fixture checks rejection of complete coverage, acceptance of partial coverage, and the actual delivered-ref set.
- Both mutations model plausible bugs and fail for the intended reasons. The ordinary-build implementation returns constant false, and its mutation-disable tests pass.
- `Refusal.Error()` preserves existing text; `Unwrap()` preserves `errors.Is(…, ErrMismatch)`. Existing callers retain their acceptance/refusal behavior, and the stale-view sentinel tests pass.

Validation passed with **Go 1.27.1**, `GOTOOLCHAIN=local`: `make vocab-check gen-check`, all three requested package test suites, and `make fixtures-contract` using the repository sandbox. Both new named mutations turned their fixtures red. No source files changed; working tree clean.
