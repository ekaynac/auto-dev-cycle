# PR #130 (step-9 PR 6b: seat handlers): Astra reviews

## Review of #130 (Astra, 2026-10-07)

Verdict: NO-GO

1. **Tx.Now — FAIL.** Proposal creation breaks with the production clock. Serialization prevents a long command alone from reordering events, but a backward clock step can produce decreasing timestamps. Hashing still covers the recorded timestamps; projection replay remains deterministic. Lease/capacity folds do not use event timestamps for deadline checks. Proposal approval and bootstrap-renewal expiry checks now use transaction-start time, while grant authorization still reads a later clock.
2. **Tx.Bound — PASS.** Returns an immutable subject string from the transaction’s binding. `BindObject` prevents replacement; the real Authorizer binds the derived, authorized seat before logic runs. The getter introduces no additional mutation capability.
3. **Multiplexing — PASS with caveats.** Matches the registered `seat.take` contract. A new command can take a seat that became free; identical-key retries replay instead. Forcing requires the caller’s own pending request and its recorded deadline. No dedicated action is necessary unless request-only semantics or named handover are required. Wall-clock jumps and precommit delays can shorten the elapsed grace visible to the holder.
4. **Guards/schema/proposals — PARTIAL.** Exemption only for take, supervisor release guard, operator release, closed schemas and server-derived `force_after` are correct. `ObjectType: "seat"` is correct, but tightened grants cannot successfully create proposals because of finding 1.
5. **Committed refusals — PASS.** Appropriate under N2, with the requested reasons and stable replay. These store **command-result rows, not refusal events**; they neither advance the event sequence nor change seat state.
6. **Expectations/first identity — PARTIAL.** Version zero, first bound/emitted `sea_` identity, and `{id, holder, request}` digests work. Version-only expectations miss changes caused by actor revocation.
7. **Verification/size — PASS, with coverage gaps.** `make ci` passed; shellcheck was unavailable and skipped. The complete requested race suite passed outside the sandbox using the pinned Go toolchain. All 17 independently constructed mutation categories caused test failures. The 212 hand-written non-test-line count is correct. Source files remain unchanged.

**High — Transaction-start stamping rejects production-clock proposals.**  
[internal/eventstore/writer.go:521](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-s9-6b/internal/eventstore/writer.go:521)

`Authorizer.propose` calls `a.Now()` after the transaction timestamp was captured. Consequently, `Proposal.CreatedAt > Event.At`, and `createProposal` rejects it as created after its event. I reproduced this with a live supervisor, a valid human-tightened `seat.take` grant, and `Authorizer.Now = time.Now`. Existing tests conceal it through their older fixed clock.

**Fix:** Use one authoritative transaction clock for proposal creation and command authorization, with clock injection at that boundary for tests. Preserve the projector’s future-date guard. Add a production-clock tightened-seat proposal regression.

**Medium — Version-only expectations overlook seat changes caused by revocation.**  
[internal/authority/seat_handlers.go:61](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-s9-6b/internal/authority/seat_handlers.go:61)

The handler binds the seat subject, whose version is its latest seat-subject event. Revoking its holder clears the holder/request through an actor-subject event, leaving that version unchanged. Reproduction: take at version 11, revoke the holder, then submit another supervisor’s take expecting version 11. It applies `seat.taken` instead of refusing stale state. Requester revocation similarly changes the record without advancing its version. Digest expectations catch these changes.

**Fix:** Track a seat revision covering every holder/request change, including revocations, and use it for expectations and proposal state. Add holder- and requester-revocation expectation tests.

**Medium — Non-decreasing event time is claimed but not enforced.**  
[internal/eventstore/writer.go:428](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-s9-6b/internal/eventstore/writer.go:428), [internal/eventstore/store.go:488](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-s9-6b/internal/eventstore/store.go:488)

Neither timestamp acquisition nor append compares against the previous event’s time. An injected backward clock step produced decreasing timestamps in a chain that passed `Verify`. This clock limitation predates the PR; transaction serialization does not resolve it.

**Fix:** Define and enforce a rollback policy across command and effect timestamps—for example, refuse writes while the clock trails the recorded head—or explicitly withdraw the monotonicity guarantee. Test backward steps and mixed command/effect ordering.
## Review of #130, round 2 (Astra, 2026-10-07)

Verdict: GO with changes

No Critical/High findings remain. The remaining issues are nonblocking under the requested threshold.

- **Round 1 — High, proposal/event clock mismatch: FIXED.** Production-clock proposals commit with `CreatedAt == Event.At`. Authorization and confirmation revalidation use `Tx.Now()`.
- **Round 1 — Medium, revocation missed by version-only expectations: FIXED.** Holder/requester revocation advances `SeatVersion`; both expectations and proposal state use it. Existing-seat proposals are invalidated correctly.
- **Round 1 — Medium, decreasing event time: PARTIALLY FIXED.** Command/effect append paths prevent decreasing timestamps, but `Verify` still accepts them.

1. **Medium — Bootstrap still decides expiry using a different clock.**  
   [internal/daemon/bootstrap.go:220](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-s9-6b/internal/daemon/bootstrap.go:220) passes `b.now()` to `ConsumeBootstrap`. After clock correction, this can accept a secret expired at the transaction’s clamped time, or reject one still valid there. Issuance also computes its expiry before the transaction at line 145. **Fix:** consume using `t.Now()` and construct issuance timestamps inside the transaction. Keep expensive credential minting outside it. Migrate `TestBootstrapExpiresWhileWaiting` to advance the **store** clock; it currently tests the separate bootstrap clock.

2. **Medium — Fresh-seat proposals have unstable object identities.**  
   [internal/authority/seat_handlers.go:57](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-s9-6b/internal/authority/seat_handlers.go:57) mints another candidate on every derivation until a seat event exists. I reproduced two identical operations under different idempotency keys creating different pending proposals; subsequently taking the seat leaves both proposals open. Re-derivation also cannot reproduce their original binding. **Fix:** establish a stable singleton seat identity before proposal binding, while preserving version-zero absence semantics. Test deduplication, first-seat creation invalidation, and later confirmation.

3. **Medium — Verification does not enforce the new timestamp invariant.**  
   [internal/eventstore/verify.go:478](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-s9-6b/internal/eventstore/verify.go:478) validates hashes without comparing adjacent event times. A hash-consistent decreasing-time tail passed my reproduction, including with a trusted preceding head. **Fix:** parse and compare timestamps during verification; reject malformed/decreasing times with `ErrChainBroken`. The existing backward-clock test proves append behavior, not this rejection.

4. **Medium — A transient forward jump permanently advances the logical clock.**  
   [internal/eventstore/store.go:330](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-s9-6b/internal/eventstore/store.go:330) preserves a future head timestamp after wall-clock correction. Existing grants/proposals can expire prematurely; proposals and handover requests subsequently created at that timestamp receive deadlines that stop approaching until wall time catches up. Restart preserves this condition. **Fix:** document and implement a clock-health/recovery policy for excessive skew, with forward-jump/correction/restart tests. Avoid a simple maximum gap between events, since legitimate idle periods also create gaps. This is operational hardening, not a demonstrated caller-controlled exploit: command timestamps are overwritten by the writer.

5. **Low — Command effect intents escape the transaction timestamp.**  
   [internal/eventstore/effects.go:124](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-s9-6b/internal/eventstore/effects.go:124) appends intents without `At`; append samples the clock again. My advancing-clock reproduction observed **three clock reads**, with `Tx.Now = 01:00` and the same command’s intent at `03:00`. Append also unnecessarily reads the clock for already-stamped events. **Fix:** pass the command timestamp into `appendIntents`, and sample the clock only when append actually needs a timestamp.

**Ruling on open point (a):** missing `Applier` support is a fail-closed integration limitation, acceptable as deferred work for this staged 6b PR. Seat proposals cannot currently apply: independent-review confirmation eventually reaches [confirm.go:185](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-s9-6b/internal/authority/confirm.go:185), while human confirmation is separately deferred. Adding `Apply` alone will not suffice: seat projection currently interprets `Event.Actor` as the taking/requesting supervisor, whereas confirmation stamps the confirmer. Integration needs explicit proposer attribution and confirmed-path tests. The fresh-seat identity defect above already affects proposal persistence and should be corrected independently.

**Clock/version audit:** confirmation consistently propagates `Tx.Now()` through expiry, review validity, grant revalidation, and approval timestamps. Lease/capacity and restart-recovery paths contain no independent wall-clock decisions. Offline identity-recovery helpers accept caller-supplied timestamps but currently have no production callers. Read authorization and transport/watchdog clocks are outside command transactions. Custom `Version` preserves legacy `SubjectVersion`/`Command.Expected` semantics; object expectations and proposal bindings consistently use the override. I found no digest invariant broken by the override itself.

**Validation:** `make ci` passed; its Makefile skipped unavailable `shellcheck`. The requested CGO race suite passed outside the sandbox using the pinned Go binary.

Nine memory-only revert mutations each made the relevant existing regression fail: proposal clock, authorization clock, expectation version, proposal version, revocation invalidation, clamping, explicit-time rejection, command stamping, and confirmation clock. Additional memory-only tests reproduced findings 2, 3, and 5. No repository source files were changed.
