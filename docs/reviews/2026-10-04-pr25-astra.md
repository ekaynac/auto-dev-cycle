# PR #25 (event store core): Astra reviews

## Review of #25 (Astra, 2026-10-04)

Verdict: NO-GO

`make ci` and the full sandboxed `go test -race -count=1 ./...` passed. Additional probes in an isolated copy reproduced the issues below. The checkout remains unchanged.

### High

1. **Unescaped database paths defeat process exclusivity.**  
   `internal/eventstore/store.go:116,125` — The filesystem path is concatenated directly into a SQLite URI. I opened directories `state?a` and `state?b`, acquired both locks, and observed the second store reading the first store’s events. Both resolve to the same database outside their locked directories; URI parsing also changes connection options. **Fix:** construct properly escaped file URIs for both pools, and test paths containing `?`, `#`, and `%`.

2. **`INSERT OR REPLACE` bypasses the immutability triggers.**  
   `internal/eventstore/store.go:47–50,68–71` — The writer reports `recursive_triggers=0`. Without dropping any trigger, I successfully replaced an existing event and the `format` metadata entry. UPDATE/DELETE triggers alone therefore do not enforce append-only events or immutable genesis metadata. **Fix:** add BEFORE INSERT guards rejecting existing event sequences/IDs and metadata keys. Test replacement conflicts on every unique key; relying solely on a connection-local pragma leaves other connections unprotected.

3. **Publish-before-reference depends on an unchecked caller-supplied list.**  
   `internal/eventstore/store.go:308` — Only `Event.Blobs` is checked. A schema-valid instrument-contract payload referencing an unpublished `payload_schema` blob appended successfully with `Blobs` omitted. The store never establishes that the list covers the payload’s references. **Fix:** derive blob references through registered, kind-specific extraction from the validated payload, or enforce completeness against such extraction.

4. **Lossy string encoding permits undetected column edits.**  
   `internal/eventstore/store.go:269` — `json.Marshal` substitutes U+FFFD for invalid UTF-8, while the original string bytes are inserted into SQLite. I appended a subject containing byte `0xff`, changed it to `0xfe`, and `Verify` still succeeded against the original trusted head. Distinct stored values therefore have identical hash encodings. **Fix:** reject invalid UTF-8 in every text column before hashing, including during verification, and use an encoder that refuses replacement.

5. **A hardlinked lock file causes destructive truncation.**  
   `internal/eventstore/lock.go:49,62` — `O_NOFOLLOW` rejects symlinks but accepts hardlinks. Pointing `adcd.lock` at an existing file through a hardlink caused `AcquireLock` to overwrite that file with the PID record. Existing file type, ownership, permissions, and link count are not checked. **Fix:** validate the opened descriptor before modifying it; require an appropriately owned, private regular file with one link, and refuse unsafe existing files without changing their contents.

### Medium

6. **Actor and subject identifiers are not validated.**  
   `internal/eventstore/store.go:288` — Nonempty values such as `Actor: "not-an-actor"` and `Subject: "not-an-id"` append successfully. Note 03 requires an `act_…` actor and a primary entity ID; note 02 defines their TypeID requirements. **Fix:** check actors through `ids.Check(..., "act")` and subjects against registered entity prefixes and UUIDv7 syntax.

7. **Canonicalization hides inputs forbidden by the contract runtime.**  
   `internal/eventstore/store.go:301–305` — `{"n":-0}` is rejected by `contract.Validate` but accepted by append because canonicalization first changes it to `{"n":0}`. **Fix:** validate the original payload before canonicalization, retaining the safe-integer check before any float64 conversion.

8. **Verification accepts noncanonical stored payloads.**  
   `internal/eventstore/verify.go:69` — Replacing stored `{"n":0}` with `{ "n" : -0 }` leaves verification successful against the trusted head. Recanonicalizing for hashing conceals edits that violate the canonical-payload storage contract. **Fix:** require stored payload bytes to equal their canonical encoding before checking the row hash.

9. **An empty trusted head does not anchor genesis.**  
   `internal/eventstore/verify.go:26–27,84,92–93` — Empty stores return `{Seq:0, Hash:""}`, and verification ignores sequence-zero anchors. Replacing the genesis record and hash, reopening, and verifying against the original empty-store head succeeds. **Fix:** represent an empty head as sequence zero plus the genesis hash, and verify that anchor.

10. **Lock ownership is not tied to the store’s lifetime.**  
    `internal/eventstore/store.go:104,120`; `internal/eventstore/lock.go:97` — A second `Open` using the same lock creates another writer pool. Releasing the lock also leaves the original store operational: I acquired a replacement lock and still appended through the old store. `Held` and `Release` additionally access mutable state without synchronization. **Fix:** enforce one active store per lock and coordinate release with closure of its database connections and outstanding operations.
## Second review of #25 (Astra, 2026-10-04)

Verdict: NO-GO

Reviewed `1fddb4b` against design notes 03, 02 and 01. Independently reran `make ci` and the full sandboxed race suite: both passed. Additional probes reproduced the findings below, including under `-race`. Working tree remains clean.

**First-review findings**

1. **High — URI paths: fixed.** Both pools use escaped file URIs; the `?`, `#`, `%` regressions pass.
2. **High — INSERT OR REPLACE: partially fixed.** Event sequence/ID conflicts and metadata-key conflicts are guarded. Metadata’s implicit `rowid` remains exploitable; H1 below.
3. **High — Caller-supplied blob list: fixed in the append interface.** Registered extraction covers the current scalar `payload_schema` and nested `evidence[].blob` shapes, including arrays of objects and nullable references. The registration remains caller-mutable after opening; M3 below.
4. **High — Lossy UTF-8 hashing: fixed.** Row encoding rejects invalid UTF-8 during append and verification.
5. **High — Hardlinked lock: fixed.** Descriptor checks enforce regular-file type, ownership, private permissions and one link before truncation.
6. **Medium — Actor/subject IDs: fixed.** Actors require `act`; subjects require a registered prefix and valid UUIDv7 TypeID.
7. **Medium — Hidden negative zero: fixed.** Original payload validation precedes canonicalization.
8. **Medium — Noncanonical stored payloads: fixed.** Verification compares stored bytes with their canonical encoding.
9. **Medium — Empty-head genesis anchor: fixed.** Sequence-zero heads carry and verify the genesis hash.
10. **Medium — Lock/store lifetime: partially fixed.** Ordinary duplicate opens and premature release are refused, but repeated closure and outstanding transactions bypass coordination; M1–M2 below.

**High**

**H1. Metadata can still be replaced through its implicit `rowid`.**  
`internal/eventstore/store.go:47,55`

`meta` is a rowid table. Its insertion guard checks only `key`, leaving another replacement conflict unguarded. With every trigger intact, this succeeds:

```sql
INSERT OR REPLACE INTO meta(rowid, key, value)
SELECT rowid, 'moved_format', 'x'
FROM meta WHERE key = 'format';

INSERT INTO meta(key, value)
VALUES ('format', 'adc.eventstore/v99');
```

The original metadata row is deleted through replacement, and its key becomes available again. The same technique targets genesis entries. In the format probe, verification against the original trusted head also succeeded.

**Fix:** eliminate the implicit conflict surface with a `WITHOUT ROWID` metadata table, or guard explicit rowid conflicts too. Handle existing databases and add regressions for `rowid`, `_rowid_` and `oid` replacement paths.

**H2. Database aliases bypass directory-lock exclusivity.**  
`internal/eventstore/store.go:140–151`

Escaping the URI does not establish that `adc.db` belongs exclusively to the locked directory. I created `B/adc.db` as a symlink to an already-open `A/adc.db`: acquiring B’s separate lock and opening B succeeded, read A’s events, and appended to A’s database.

A hardlinked database also opened under separate locks. After an append through the second store, the first store’s read failed with SQLite `disk I/O error (522)`.

**Fix:** reject symlinked and multiply linked database files before SQLite opens them. Bind database identity to the locked directory and preserve that identity across connection creation; apply corresponding protections to SQLite sidecar files. Add two-directory symlink and hardlink regressions.

**Medium**

**M1. A stale `Close` clears a successor store’s lock claim.**  
`internal/eventstore/store.go:170–172`; `internal/eventstore/lock.go:132–135`

Reproduced: close store A, open store B using the same lock, call `A.Close()` again, then release the lock. Release succeeds while B remains operational; another lock holder can enter, and B still appends.

The failed-`Open` path also unclaims twice: once through `s.Close()` and again through the deferred cleanup. A concurrent successor can claim between those calls.

**Fix:** make store closure execute once, associate each claim with its owning store/token, and release it exactly once—including initialization failures.

**M2. Pool closure does not drain outstanding transactions.**  
`internal/eventstore/store.go:170–172`

I began a writer transaction, called `Store.Close()`, released the lock, acquired a replacement lock, then successfully appended and committed through the original transaction. `sql.DB.Close()` does not make an already checked-out transaction unusable.

**Fix:** track active operations and transactions. Shutdown must prevent new work and wait for completion—or cancel, roll back and await termination—before unclaiming the lock.

**M3. The copied kind registry shares caller-owned blob-field slices.**  
`internal/eventstore/store.go:156–158`

The map copy is shallow. After opening with `BlobFields: []string{"payload_schema"}`, changing the original slice element to a nonexistent field caused an unpublished `payload_schema` reference to append successfully.

**Fix:** clone each `BlobFields` slice when constructing the store’s registry. Add a regression that mutates the original configuration after `Open` and confirms publication checks remain enforced.
### Lead notes on round 2

- All five findings fixed with regressions; 12 new fixes mutation-tested, plus the round-1 set rerun.
- One mutant survives as equivalent: removing the close-once guard. With claim tokens, a repeated `Close`
  closes already-closed pools (a no-op in `database/sql`) and passes a stale claim, which is ignored.
- Residual, documented: the identity check runs before each operation; a file swapped between that check and
  SQLite's next file open would need write access to the 0700 state directory, which is outside the threat model
  of note 03 (an attacker with that access can rewrite the log, which Verify against a trusted head detects).

## Third review of #25 (Astra, 2026-10-04)

Verdict: GO with changes

- **H1 — Fixed.** `WITHOUT ROWID` removes all three rowid aliases. `Open` rejects the previous rowid table; `Verify` checks the format and exactly three metadata keys.
- **H2 — Fixed within the stated scope.** Persistent database/sidecar symlinks and hardlinks are refused, and operations reject a changed database inode. Checks remain pathname-based; SQLite’s lazy connection creation leaves a check-to-open window. This requires concurrent directory mutation and is nonblocking under the lead’s stated scope.
- **M1 — Fixed.** Closure is serialized and idempotent, claims identify their owners, and failed initialization closes its pools before the single deferred unclaim.
- **M2 — Partially fixed.** Normal and error-returning transactions finish before closure. Panic unwinding bypasses transaction cleanup; finding 2 below.
- **M3 — Fixed.** Each `BlobFields` slice is cloned.

Reviewed `a484d0b` against design notes 03, 02 and 01. Independently reran `make ci` and the full sandboxed race suite: both passed. Additional isolated probes reproduced both findings below under `-race`. The checkout remains unchanged.

### Medium

**1. A read inside a transaction can deadlock with concurrent `Close`.**  
`internal/eventstore/lifecycle.go:62,79,94`

Reproduced: enter `inTx`, start `Close`, then call `Head` from the transaction callback. The transaction holds `ops.RLock`; `Close` waits for that reader; the nested `Head` waits behind the pending writer. Neither operation can finish, and context cancellation cannot release this mutex wait. This contradicts the package’s stated support for reads inside writer transactions.

**Fix:** avoid recursive lifecycle locking. Provide an operation-scoped read interface that uses the transaction’s existing admission, or replace the long-held RWMutex with explicit operation tracking that rejects new admissions during shutdown without blocking nested calls. Document that callbacks cannot synchronously call `Close` or nest writer transactions. Add the concurrent-close/nested-read regression.

**2. A callback panic leaves its transaction alive after the operation lock is released.**  
`internal/eventstore/lifecycle.go:80`

`inTx` rolls back only when `fn` returns an error. If it panics, `do` releases its read lock during unwinding, but the transaction retains the sole writer connection. A caller recovering the panic can encounter permanently blocked subsequent writes.

The probe also captured that transaction, recovered, closed the store, released and reacquired the directory lock, then successfully appended and committed through the old transaction. Thus M2’s lifetime guarantee still fails on this path.

**Fix:** install `defer tx.Rollback()` immediately after successful `BeginTx`, retaining commit on success. Cleanup must execute before `do` releases its operation lock. Add a recovered-panic regression proving the transaction is finished and the writer connection remains usable.

No Critical or High finding remains; these Medium changes are nonblocking under the requested threshold.
### Lead notes on round 3

- Both Medium findings applied before merge: operation tracking (an admission counter and a condition variable)
  replaces the RWMutex, so once Close begins new operations, nested ones included, get ErrClosed instead of
  blocking; inTx defers a rollback that finishes a panicking callback's transaction before the operation ends.
- Regressions for both; mutation-tested (the close-once guard remains the equivalent mutant noted in round 2).
- H2's check-to-open window stays documented as out of scope (it needs concurrent mutation of the 0700 state
  directory).
