### High

**H1. A rebound `__name__` reopens the `__main__` scope: import-time code is credited to `__main__` and warns.** (`internal/accept/integrity_pyguard.go:272-274`, `:304-309`)

`pyMain` checks the guard's shape, not whether `__name__` still means the module's name. Python lets module code rebind it.

- Input (application module, Opus H2's first probe with one line added), `money.py`:
  ```python
  import os
  __name__ = "__main__"
  if __name__ == "__main__":
      os._exit(0)
  ```
  Trace: line 2 has no classified token and does not end in `:`; line 3 is exactly `pyMain` → scope `__main__`; `_exit` keyed `e\x00_exit\x00__main__` → `top` false, `money.py` not tested → **warning only** (`money.py: _exit in __main__`, the same text as the control row). pytest exits at import with no junit file.
- Other bindings with the same effect: `for __name__ in ("__main__",):` then the guard inside it; `class C:` / `__name__ = "__main__"` / the guard in the class body (class-local lookup makes it true); `_ = (__name__ := "__main__")`; `from __main__ import __name__` (an import, so it also warns at `(import)`, but the guard body still goes to `__main__`).
- In a test module the gain is the 'o' class only (`print`, a `Thread`) since 'f'/'e' block anywhere in tested files; in a conftest the allowlist blocks the `if` line. In application modules the gain equals the stated "same-file function called at top level" residual, but the PR's promise and its end-to-end table say these forms block, and they do not once `__name__` is rebound.
- Fix (about three lines in `pyScan`): keep a per-file flag `named` that is set by any line, other than a `pyMain` line, holding the token `__name__` not enclosed as a lone call argument `( __name__ )` (that keeps `logging.getLogger(__name__)` clean); once set, `pyMain` never opens a scope for the rest of the file (the body is import code). Add the row "H2 __name__ rebound" (block `_exit in module level`) and keep the `getLogger(__name__)` form as a control.

**H2. H3's `name=` check reads only a bare, directly written literal: a string prefix or a constant defeats it.** (`internal/accept/integrity_pyguard.go:258-259`)

- Input 1 (a conftest, Opus H3 input 1 with one character added):
  ```python
  import pytest

  @pytest.fixture(name=r"capsys")
  def _c():
      return None
  ```
  `strings.Trim(`r"capsys"`, "\"'")` leaves `r"capsys`, which is not in `pyFixtures`; the def's name `_c` is not builtin; the allowlist accepts a fixture under a fixture decorator. No block. `u"capsys"` is the same. (In `pyMain` the same `Trim` errs in the safe direction; here it errs open.)
- Input 2 (a conftest, no normalisation involved):
  ```python
  import pytest
  NAME = "capsys"

  @pytest.fixture(name=NAME)
  def _c():
      return None
  ```
  `NAME = "capsys"` is plain data under `pyPlain`; the decorator line holds no builtin-fixture string. No block. `@pytest.fixture(**KW)` with `KW = {"name": "capsys"}` is the same route (the literal `**{"name": "capsys"}` form is caught today because the string sits on the decorator line).
- Input 3 (a test module or `tests/helpers.py`, not a conftest): `fx = functools.partial(pytest.fixture, name="capsys")` then `@fx` on `def _c()`. The literal and `fixture` share a logical line, but it is not a decorator line, so the check never runs. 2a-allow's test-module allowlist would likely refuse the `partial` call at import; the `name=` promise is this PR's, so I count it here.
- Fix: on any line (not only `@` lines) that names `fixture` and is at import or in a decorator, read a `name` `=` pair; the value must be exactly one string token, read with its prefix stripped (`pyPlain` already computes the prefix slice; lift it into a `pyStr(k)` helper and use it in `pyMain` too); any other value, and any `**` on a fixture decorator line, blocks as "a fixture name not a literal". Rows: `name=r'capsys'`, `name=NAME`, `**KW`, and `functools.partial(pytest.fixture, name='capsys')` in a test module.

### Medium

**M1. A builtin fixture is defined by assignment, not `def`, and the any-file H3 rule misses it.** (`internal/accept/integrity_pyguard.go:287-288`)

- Input (test module):
  ```python
  import pytest
  from money import add

  def _c():
      class R: out = "hello\n"
      class C:
          def readouterr(self): return R()
      return C()
  capsys = pytest.fixture(_c)

  def test_out(capsys):
      add(1, 2)
      assert capsys.readouterr().out == "hello\n"
  ```
  pytest's `parsefactories` registers the fixture under the *attribute* name (`capsys`), both in pytest 9 and in older releases. `capsys = _c` with `_c` decorated, and the same in a test class body, register too. Nothing here is a `def` named `capsys` or a `name=` string, so neither H3 rule fires. In a conftest the allowlist refuses the line (`_c` is not a constant); in test modules and test-directory helpers it passes. 2a-allow's allowlist will probably refuse a call at import, but the "defined as a fixture in any changed file" promise is this PR's.
- Fix (one condition): in `pyScan`, a line at fn `""` whose first token is a `pyFixtures` name followed by `=` (not `==`) blocks as "a builtin fixture overridden by assignment" when the file is tested or the line names `fixture`. Row: "H3 a builtin fixture by assignment".

**M2. M3's aliasing rule reads `as` only; `from X import pytest` binds `pytest` to anything.** (`internal/accept/integrity_pyguard.go:325-328`)

- Input (conftest): `from helpers import pytest` then `@pytest.fixture` on `def db()`. `named(t, "pytest")` is true but `named(t, "as")` is false, so the import is plain; the decorator is counted as a fixture decorator, so the def passes. `from . import pytest` and `from tests import pytest` are the same spelling. The decorator then runs arbitrary helper code at conftest import; the gain is bounded by the other PRs' sets (the helper's body warns under decision A), exactly as Opus rated M3.
- Fix: in a conftest, an import line may name `pytest` only as `import pytest` (exactly two tokens) or as `from pytest import …`; replace the `as` test with that shape. Rows: `from helpers import pytest`, `from . import pytest`.

### Low

- **L1. 2a-allow note: implicit class-creation calls.** A def body named `__init_subclass__` or `__set_name__`, or a metaclass's `__new__`/`__init__`, runs at import when a later `class C(Base): pass` or `d = D()` line executes, yet it is credited to that function (`:270-271`) and warns. This is the stated "same-file call" residual in another form, but `class C(Base): pass` looks inert to an allowlist; 2a-allow should treat those method bodies as import code (a def named `__init_subclass__`/`__set_name__`, and every method of a class whose bases name `type`).
- **L2. 2a3 note: an aliasing import hides an 'e'/'f' reference in application code.** `from os import _exit as z` warns at `(import)`; `z(0)` at module level is unseen (`:201-215`). `import os as o; o._exit(0)` and `sp = subprocess` are caught. Fix in 2a3 (rewritten references): on an import line, a classified name followed by `as NAME` adds `NAME` to the file's class map. Same family: `from pytest import main` then `main([...])` in a fixture body is not `pytest.main`.

Also a `#` comment line inside an `addopts` continuation counts as positional (false custom); state it or skip comment lines.
- **L4. 2a3 note: escaped hook strings.** `"pytest\x5fplugins"` passes `isHook` (`:195-198`); every known use of such a string also needs `globals`/`setattr`/`type()`/`register`, which 2a3 covers, so string normalisation there should include escapes.

Mutation and row notes.** R1–R9 each discriminate as stated: I traced R1 against the two MD rows and the exact-guard control, R2 against "a decorator at import" and the two fixture rows (their expected text changed from `in capsys` to `in module level`), R9 against the `build/` control.
