### High

**H1. A whole test file can be skipped or uncollected with no signal** (`internal/accept/integrity.go:32-47`, `:70`, and the marker lists at `:23-24`).
- **Scenario A: build constraint.** A builder adds `//go:build ignore` at the top of a `_test.go` file, or any tag that is never set. Every test in that file stops running. The guard counts text markers, which are unchanged, so it sees nothing.
- **Scenario B: uncollected rename.** `isTest` treats any file under `tests/`, and any `*.test.*`, as a test. The "renamed to a non-test path" rule uses that same predicate. So `tests/test_money.py → tests/money_cases.py` is "test → test", though pytest never collects it. `calc_test.go → calc.test.go` is the same case for Go. The counts are equal, so it passes.
- **Why it blocks the PR.** 01 §2.5 says a skipped or deleted test is conclusive and blocks. These are the most common ways a model "fixes" a failing test. No reviewer warning is produced either.
- **Fix:**
  - Add a `collected(path)` predicate per recipe: Go only `_test.go`; pytest `test_*.py`, `*_test.py`; JS `.test.`/`.spec.` only for js/ts extensions. Use it for the deleted/renamed rule; the broad `isTest` can stay for counting.
  - Block when a `_test.go` file gains or changes a `//go:build` or `// +build` line. If that is too strict, block only when its constraint set grows.
  - Add `importorskip` and `pytest.mark.skipif` explicitly to `skipMarkers`.
  - Add the three probes as test rows.

### Medium

**M1. Aggregate marker counting can be gamed** (`integrity.go:24-26`, `:97-105`).
- **Scenario.** A test is deleted and the comment `# def test` is added. Or an assertion is removed and an unrelated `assert True` test is added anywhere among the changed files. Both pass, because "fewer" is a substring count across files.
- **Fix.** Compare sets of test *names* before and after: line-anchored `^\s*def (test\w*)` and `^func (Test|Fuzz|Example)\w*\(`, outside comments. A name that disappears and is not found again in another changed collected file is "a test deleted". For assertions, count per test name rather than in aggregate, so an added test cannot pay for a removed assertion.
- **The false-block question.** Blocking on fewer assertions matches 01 §2.5's "an assertion was removed", so it is acceptable, with D55's false-block ledger as the outlet. Per-name counting also cuts false blocks when a refactor moves a test between files.

**M2. Confirmed: the guard fails open on its read bounds** (`integrity.go:80-82` with `:119`).
- **Scenario.** A test file over `maxFile` (4 MiB), or past the 64 MiB total budget, is left out of both tallies and only warned. Padding `tests/test_money.py` to 5 MB with its assertions removed was accepted with a warning only. Spreading changes over many files exhausts the budget the same way.
- **Fix.** Fail closed: block with `test_integrity_violation` and the reason "unverifiable: over the guard's read bound" when the unread file is a *collected* test source (from H1's predicate). Keep a warning for large non-source files under `tests/`, such as fixtures and data, so legitimate fixtures are not blocked.

**M3. Partly confirmed (I18): `BuilderIntent` follows lineage only one level** (`internal/accept/intent.go:30-36`).
- **Scenario.** Acceptance blob A, then a ref R1 with lineage `[A]`, then a summary S with lineage `[R1.ID]`. If S is in the build context, `check(S)` looks at `S.ID`, `S.ContentDigest` and `[R1.ID]`. None of these is a restricted digest, so the intent passes. This holds whether or not R1 is also in the context, because there is no closure. `knowledge.restrictedIDs` already computes the closure "at any depth" for exactly this reason.
- **Fix.** Seed a set with the restricted digests. Grow it to a fixpoint over all of `ctx.Included` and `ctx.Omitted`: add `r.ID` whenever `r.ID`, `r.ContentDigest` or any lineage id is already in the set. Then refuse if any input is in the set. Add a two-hop test.
- **Refuted sub-claims:**
  - Not checking `IdentityDigest` is not a gap. It is the sha256 of the ref record (type, id, scope, lineage, restrictions, content digest), so it can never equal an acceptance blob's content digest. For blob refs, `r.ID` is the content digest by convention, which the check does compare.
  - The `call` record's own fields carry no refs. `Inputs`, `Included` and `Omitted` are all reset before filling, and the rest are ids or digests.
- **Severity.** Medium, not High: the code is inert, and P16/P22a still owe the fold-side refusal. It should be fixed here, because the PR names this as the build-time refusal.

**M4. The likely fourth issue: a hostile output tree turns `Diff` into a controller fault, not a candidate refusal** (`internal/accept/result.go:31`).
- **Scenario.** `CopyTree` skips only entries named exactly `.git`. A builder writes `.GIT/config`, `sub/.Git/x` or `GIT~1/…` into its workspace. `git add --all` then hits git's `verify_path`, which refuses `.git` case-insensitively. git exits 128, and `Diff` returns a plain error. Callers cannot tell that error from "git is broken", because `errFailed` is unexported. Per §2.5's repair routing, infrastructure faults go to hold and page. So a builder can force an operator page and hold instead of `failed/unsafe_output`.
- **Not executed.** I did not run this probe. The operator's shell guard refuses commands that name git control paths, so this is from git's documented `verify_dotfile` behaviour. `TestRefusesUnsafeOutput` agrees with it: `git apply` refuses `.GIT/config` there.
- **Fix.** Either have `Diff` return a typed `ErrUnsafeTree` when `add` fails with `errFailed`, so the caller records `failed/unsafe_output`. Or, better, have `CopyTree`/`Diff` refuse any component for which `gitControl` is true before git runs.
- **Related: `Diff` vs apply.** `Diff` uses `--no-renames` and accept re-derives renames with `-M`. Checks run on the index's own raw diff, and `write-tree` writes that same index, so there is no checked-vs-applied gap. Rename pairing cannot hide a protected path, because both `src` and `dst` are checked.

**M5. Confirmed in substance: NTFS short-name coverage is incomplete** (`internal/accept/paths.go:59`).
- **Scenario.** `gi7eba~1` (hashed short name of `.gitmodules`) and `gi7d29~1` (`.gitattributes`) were accepted. git's `is_ntfs_dot_generic` matches both the `gitmod~N`/`gitatt~N` forms and the hashed `<prefix>~N` forms (N 1-9).
- **Real impact.** It needs a Windows checkout with 8.3 names. The sandbox, gate and controller are Linux, and git itself refuses these only as symlinks. On impact this is Low. I list it as Medium only because the PR explicitly claims 8.3 coverage.
- **Fix.** Add `gi7eba~` and `gi7d29~`. Better, mirror `is_ntfs_dot_generic` exactly: first 6 characters plus `~[1-4]`, hashed prefix plus `~[1-9]`. Add test rows.

### Low

- **L1. `.gitignore` silently drops output** (`result.go:31`). `git add --all` honours the tree's and base's `.gitignore`, so a new file the builder wrote that matches an ignore pattern never reaches the diff. This is omission only; it cannot smuggle anything, because tracked files and deletions are still staged. Fix: record ignored-but-present files as a warning (`ls-files --others --ignored --exclude-standard`, bounded), or document it as intended.
- **L2. The report blob is unbounded** (`result.go:46-52`). `Detail` is capped at 4000 bytes, but `Report()` serialises every block and warning. A 64 MB patch of tiny files gives a report of tens of MB. When there are no findings, `Blocks` and `Warnings` serialise as `null`. Fix: cap the lists (for example 1000 each, plus `truncated: n`) and emit `[]`. Elapsed time is correct: it is set in a defer from the injected clock and covers the early returns.
- **L3. `Diff` buffers its whole output before the size check** (`result.go:34`). Memory is bounded only by the caller's `CopyTree` `maxBytes`. Fix: document that bound, or read through a `LimitedReader`.
- **L4. A zero `Policy` silently drops profile protections** (`paths.go:14-38`). `PolicyOf` returns a usable-looking `Policy` together with an error. Fix: return `Policy{}, err`, and make `Accept` refuse a `Policy` that `PolicyOf` did not build (for example with an unexported `ok` flag).
- **L5. A missing input size is recorded as 0** (`intent.go:46`). A size missing from `bytes` is silently recorded as `Bytes: 0`. Fix: return an error.
- **L6. Protected globs are case-sensitive.** `Conftest.py` is accepted. That is harmless on Linux, where pytest does not load it, but worth a comment.

### On the brief's questions

1. **Hostile output tree.**
   - **Code execution.** None found. The diff is computed from the copied tree in the controller's `Repo`, never from the adapter's patch. `GIT_DIR` is the controller's clone, and its snapshot is checked on every call. Attributes come from the empty tree (`GIT_ATTR_SOURCE`), so in-tree `.gitattributes` cannot pick a filter. `core.attributesFile`, `hooksPath` and `fsmonitor` are neutralised, and there is no user or system config. `includeIf`, lfs and sparse-checkout cannot apply because nothing reads tree config.
   - **Smuggling.** Symlinks (`dstMode` 120000) and gitlinks are refused. Paths beyond a symlink are refused by `git apply`. Mode-only changes still list the path, so protected checks apply. The only gaps are M4 and M5.
2. **Hardened git.** Every call goes through `sandbox.Repo.Git`. `write-tree`, `read-tree`, `apply`, `add` and `cat-file` are on merged P9's allowlist. This is the controller's own git, not an operator-shell command, so the operator's guard does not apply. `diff` gets `--no-ext-diff --no-textconv`. Accept never clones or fetches, so `file://` and protocol helpers are unreachable.
3. **Integrity guard.** See H1, M1 and M2. A process exit in a non-test file (`init(){os.Exit(0)}`) and `TestMain` returning early are not caught; the latter gets a warning only when `TestMain` is newly added. That fits "heuristic" under §2.5, but the warning should also cover `.go` non-test files in a package that has tests.
4. **`BuilderIntent`.** It refuses one-hop refs, whether included or omitted. Multi-hop refs escape (M3).
5. **D55.** The elapsed time and the blocks are correct. The report blob is not bounded (L2).
6. **Inert?** Yes. No reference to `internal/accept` exists outside the package. The `produces` row `accept → tree` is the only shared change, and it is minimal.
7. **Fault evidence.** I reran three mutations:
   - `Protected` returning false turned `TestRefusesProtectedPaths` and `TestResultAndReport` red.
   - Disabling the skip comparison turned `TestIntegrityGuard` red ("skip added", "go skip added").
   - Disabling `gitControl` turned `TestRefusesProtectedPaths` and `TestCheckPaths` red.

   All three discriminate. The full `go test` of accept, profile and graph is green at 27d00ce.
8. **Size.** 620 against about 600, under the 800 ceiling. Acceptable. The H1 and M1 fixes add roughly 40-60 lines and stay under the ceiling.
