# PR #61 (command envelope and OpenAPI document): review

## Review of #61 (Astra, 2026-10-05)

Verdict: NO-GO

**Critical:** None.

**High**

1. **The OpenAPI document’s transitive schema references do not resolve for a standard consumer.** `internal/apidoc/apidoc.go:76`, `schemas/api/command-request.json:3`, `internal/apidoc/apidoc_test.go:75`.

   The initial `api/command-request.json` reference resolves locally, but that schema’s absolute `$id` changes the base URI. Its reference to `../records/approval.json` therefore resolves to `https://github.com/ekaynac/auto-dev-cycle/schemas/records/approval.json`, which returns **404**. The response’s reference to `common/defs.json` has the same problem. This follows [OpenAPI 3.1’s schema-reference resolution rules](https://spec.openapis.org/oas/v3.1.0.html#relative-references-in-uris).

   I reproduced the external lookup with a standard JSON Schema resolver. The Go validator succeeds because it preloads every embedded schema under its canonical ID; ordinary OpenAPI consumers lack that catalog. `fs.Stat` on the two component references does not test this.

   **Fix:** provide a supported resolver/catalog mapping canonical IDs to embedded files, or generate a consumable bundle. Add an offline test resolving the entire reference graph, including fragments, through the intended OpenAPI consumer.

**Medium**

2. **Refusals permit result triples forbidden by the vocabulary contract.** `schemas/api/command-response.json:58`, `schemas/api/command-response.json:60`.

   A refusal with `detail: ""` validates, despite note 02 requiring non-empty detail for both permitted outcomes. The schema also accepts `could_not_run/stale_expected_state`, although the reason registry permits that reason only with `failed`. Checking that a reason is registered does not check its permitted outcomes; `internal/vocab.Registry.Check` already distinguishes these rules.

   **Fix:** add `minLength: 1` to refusal detail and enforce outcome/reason compatibility at the response validation/emission boundary. Test empty detail and incompatible registered pairs.

3. **The claimed union round-trip test only decodes.** `schemas/api_test.go:72`.

   The test marshals the fixture map and unmarshals into `CommandResponse`; it never encodes that union, checks the selected variant, or compares the output. A decoder dropping fields or a broken union marshaler could pass. Positive coverage also omits `could_not_run`, `independent_review`, and the ordinary applied response with null approval and empty effects.

   **Fix:** decode through `contract.Decode`, assert the concrete variant, encode through `contract.Encode`, and compare JSON values. Include those positive cases so rejecting valid alternatives cannot survive unnoticed.

**Low:** No additional findings.

**Contract and implementation assessment**

The envelope otherwise captures 08’s required request fields and the exclusive applied/proposed/refused union. Reusing `ExpectedState` preserves version-only, digest-only, both-present, and version-zero semantics. The ASCII restriction makes the 256-character limit compatible with the writer’s byte bound.

The applied fields represent `eventstore.Outcome`, including current effect states on replay. Proposal ID, policy, and binding digest match authority’s proposal records. Transport adaptation remains necessary: normalize absent effects to `[]`, supply an object result and approval reference, and enforce digest expectations inside the transaction—the writer’s built-in expectations check versions only.

The command exit codes are derivable: applied → 0; proposed → 3; the three named stale refusals → 4; other `could_not_run` refusals → 2; other failed refusals → 1. Read results and CLI usage exit 64 belong to their later contracts.

**The three decisions**

- **HTTP 200 for decided dispositions:** acceptable. The body carries the decision; clients must inspect it. Authentication failure can remain 401.
- **Object identity in action-specific scope:** acceptable. Each action must define its target unambiguously. The eventual writer adapter must include the path action in the idempotency input digest.
- **Defer reads and events:** acceptable for this explicitly scoped part 1. It does not complete step 9 as a whole.

**Verification**

`make gen-check` and the focused Go tests passed using the pinned toolchain. The document passed the official OpenAPI 3.1 structural meta-schema. The existing 20-run determinism test passed; endpoint enumeration, deprecation, and registry-key mismatch checks are present. Structural validity does not resolve finding 1.

No repository files were modified.
