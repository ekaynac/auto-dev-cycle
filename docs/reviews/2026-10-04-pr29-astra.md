# PR #29 (project profile schema): Astra review

## Review of #29 (Astra, 2026-10-04)

Verdict: GO with changes

No Critical or High findings. All fields from note 07 are represented; I found no generated Go type mismatch or unintended loss of explicit nulls.

1. **Medium — `Argv` rejects legitimate empty arguments.**  
   `schemas/config/project-profile.json:291` requires every argument to be non-empty. Commands such as `["git","-c","core.hooksPath=","config","example.value",""]` require an empty argument; omitting it changes their meaning. `schemas/config_test.go:82` entrenches this restriction. **Fix:** permit empty strings after the executable. Within the current generator grammar, retain `minItems: 1`, allow string items, and require a non-empty executable in the loader. Reject embedded NULs there too. Keep ordered package commands and shell-free execution.

2. **Medium — Git naming restrictions reject valid project conventions while accepting invalid refs.**  
   `schemas/config/project-profile.json:22` rejects `refs/heads/release+hotfix`; line 281 rejects `team/adc/` and `ADC/`. Conversely, the patterns accept `refs/heads/main.lock` and `adc../`, which cannot produce valid refs. I checked these examples with local `git check-ref-format`. **Fix:** keep the `refs/heads/` and trailing-slash requirements, remove the unnecessary character and single-component restrictions, and validate actual Git ref syntax in the loader. Test both valid unconventional names and invalid components.

3. **Medium — An empty image map bypasses the pinned-toolchain requirement.**  
   `schemas/config/project-profile.json:89` accepts `"images": {}`. Plan §2.10 requires containerized dependency preparation and build/gate execution, but this profile supplies no pinned execution image. **Fix:** add `minProperties: 1` and an empty-map refusal test. This keyword is supported by the generator’s typed-map grammar. The loader must additionally validate image-reference syntax and execution-image selection.

4. **Low — Tests do not substantiate “a refusal for each rule.”**  
   `schemas/config_test.go:71` tests only one missing field, one missing nullable field and a top-level unknown key. It omits malformed topology revisions/digests, invalid policy enums, nested unknown keys, several nullable states and encode round trips. **Fix:** add representative security-field refusals and decode/encode round trips covering populated and null values. These should protect the contract independently of successful generation.
