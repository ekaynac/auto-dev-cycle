**Claim-design assessment:**

- **Zero values:** An empty claim, nil transaction, or zero transaction cannot satisfy `Holds`. Claiming a zero-value `Store` cannot produce a usable database transaction.
- **Copying:** A copied claim retains the same authority and store binding. Issuance is once-only; the capability is intentionally reusable and transferable by its holder. Daemon startup keeps it private.
- **Second open:** The existing lock ownership check rejects another `Open` using the same lock; `flock` rejects independent acquisitions in either the same process or another process. Database symlink/hardlink aliases are refused. After closing, reopening legitimately creates a fresh claim; the old principal fails the new store’s pointer-identity check.
- **View versus writer:** Both transaction paths set `owner`. Creating the principal in a `View` works, while writer-side `Recheck` validates ownership and current actor liveness before replay or execution.
- **Test constructors and reflection:** No production test-constructor escape was found. Ordinary reflection cannot populate the unexported claim pointer or principal fields. This is an application capability boundary, not protection against `unsafe`, malicious controller code, or direct database access by its owner.
- **Refused startup:** Claiming before verification does not leak authority. The claim remains local, no daemon is returned, and deferred cleanup closes the store before releasing its lock. The claim changes only memory and does not persist across reopening.

The **typed-nil reflection check is sound**: it handles a nil interface first and calls `IsNil` only for supported kinds, covering legal nil-valued handler implementations. Non-nil value handlers remain valid.

**Size is acceptable.** The diff contains 370 non-test changed lines, or 364 excluding fixture helpers. The ~300 figure is the step estimate; the documented general limit is ~400. Identity construction, writer rechecking, authorization derivation, and daemon wiring form a cohesive change. No split is warranted.
