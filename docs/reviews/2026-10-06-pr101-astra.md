# PRs #101 and #103 (adapter host schemas, TS exchange): Astra reviews

## Review of #101 and #103 (Astra, 2026-10-06)

Verdict: NO-GO

#101: **NO-GO**. #103: **GO with changes**. Only the High findings block.

1. **High — #101: post-exit ingestion conflicts with controller-mediated tools.**  
   `docs/design/m0/09-executor-adapter-contract.md:26` prohibits ingesting any output until the process tree exits, explicitly including tool-request blobs at line 43. But line 78 requires the controller to read a request and respond during `run`; the fake waits for that response at `adapters/fake/src/fake.ts:274`. Following both rules deadlocks until cancellation or timeout. **Fix:** define a safe live-transfer mechanism for tool requests, or explicitly defer/reject mediated tools in this slice. Preserve post-exit ingestion for final outputs.

2. **High — #101: the specified open can block before rejecting a FIFO.**  
   `docs/design/m0/09-executor-adapter-contract.md:31` specifies resolution restrictions and `O_NOFOLLOW`, followed by `fstat`. Those flags do not prevent a normal read-open from blocking indefinitely on a FIFO without a writer. Process-tree exit does not solve this. **Fix:** specify the lead plan’s `O_PATH|O_NOFOLLOW` inspection, reject nonregular files before opening for reading, then reopen and verify descriptor identity. Require equivalent safety in the fallback.

3. **Medium — #103: cleanup is skipped when close fails.**  
   `adapters/contract/src/exchange.ts:38` awaits close before unlinking; a close rejection bypasses cleanup and masks the original failure. The successful-path close at line 42 also sits outside cleanup handling. Fault injection reproduced a remaining output after sync and close failures. **Fix:** guarantee an unlink attempt after every post-create failure, independently of close success, while preserving the original error. Add failure-path tests.

4. **Medium — #103: mutable input can produce an incorrect returned digest.**  
   `adapters/contract/src/exchange.ts:31` retains the caller’s `Uint8Array`, then hashes it after asynchronous writing, syncing and closing. Mutation during those awaits can make the returned digest describe different bytes from the file. An isolated probe reproduced this mismatch. **Fix:** copy the input before the first await and use that snapshot for writing, hashing and size.

5. **Medium — #101: shared parity coverage omits the new refusal schema.**  
   `schemas/lease_test.go:182` tests refusal constraints only in Go. `fixtures/contract/cases.json` contains **zero** refusal cases. The prepare updates preserve existing coverage, but the new reason/check conditional has no shared behavioral coverage. **Fix:** add valid stale, foreign-handle and path refusals, plus invalid reason/check combinations and shape/boundary cases, to the shared corpus.

The separate refusal record is appropriate: it preserves 05’s terminal-state immutability, and the lease projector correctly ignores it as a transition. Deriving untrustworthiness from refusal events is sound and queryable through the subject-indexed log; readers should derive it in the same snapshot as the attempt. The reader itself is not implemented here.

The reason/check mapping and intended ordering are coherent, including the second transactional fence. The 64/16/1 MiB result bounds and 16 MiB auxiliary bound are reasonable M0 per-blob limits.

For #103, exclusive creation, final-component symlink refusal, fsync, and exact schema-pattern equality check out. The fake scenarios produce their claimed filesystem conditions. `unsafe-replaced` is honestly documented as a shutdown-time replacement caught by **digest**, not the during-copy `replaced` check.

Validation passed under `scripts/test-sandbox.sh`: both requested Go packages, `make ts-deps`, contract **23/23**, fake **23/23**, and the additional shared-validator `.mjs` tests **2/2**. No tracked files changed.
### Lead notes on round 1 (applied)

- High 1 (#101, post-exit ingestion and mediated tools): lead decision. "Ingest only after the process tree exits"
  applies to final outputs: the run result and every handle it or the run's events declare. A controller-mediated tool
  request's handle is ingested live, when its `tool.request` arrives, with the same steps and a separate 1 MiB bound.
  09 states that a live read cannot rely on process exit, so the pinned inode, the regular-file, link-count and mount
  checks, the size and digest checks and the post-copy `statx` are its only guarantees. That is acceptable because the
  request is the adapter's own input to the controller. A refused request is not executed. The contradiction between
  the ingestion rule, the bounds and the `tool.request` row is gone.
- High 2 (#101, FIFO-safe open): 09 now resolves with `O_PATH | O_NOFOLLOW` under the `openat2` restrictions and
  `statx`es the `O_PATH` descriptor. Anything that is not a regular file with link count 1 and an in-bound declared
  size is refused before any read-open. The pinned inode is reopened through `/proc/self/fd/<n>` (never the name
  again). Device, inode, mount id and link count are checked on the reopened descriptor and again after the copy. The
  `openat` fallback walks components with `O_PATH | O_NOFOLLOW` and checks mount ids. It must be equivalent or fail
  closed: a host without `STATX_MNT_ID` or `/proc/self/fd` reopening ingests nothing, and the attempt is
  `could_not_run`.
- Medium 5 (#101, shared parity): `fixtures/contract/cases.json` gains 21 refusal cases, run by both validators:
  - valid: digest, stale, foreign-handle, path (recording a bad name), FIFO, and a detail at its bound;
  - invalid: the reason/check combinations, an unregistered check or reason, detail and name bounds, a NUL in the
    name, the handle's shape, a missing attempt and an unknown field.
- Medium 3 and 4 (#103, cleanup on close failure; mutable input) are applied in #103.
