## External review of #260, round 2 (Mythos, 2026-10-14)

Verdict: GO

I reviewed 8897aef read-only: the round-3 diff, the PR body's round-3 table, both earlier reviews, `pyField`, `pyString`, the recover, the cookie gate, and the new rows, bodies, goldens and panic test. I traced the scanner by hand against CPython 3.12's `tok_get_fstring_mode` and the punctuation block of `tok_get_normal_mode`, and confirmed seven literal inputs with this host's CPython 3.12.3 (`compile` plus `tokenize`). I ran no repo tests.

**H1 is closed.** `single` is a parameter of every `pyField` frame, set once at `integrity_py.go:266` from the enclosing quote and forwarded unchanged at `:286` and `:297`. A nested string in a field reaches `pyString` through `pyToken` at `:304` and derives its own value from its own quote. There is no path by which an inner string's quote reaches an outer frame or an outer quote reaches an inner one. Traced and confirmed with CPython:
- nested f-string in a field of a spec: `f"{x:{f'''{y:d\n}'''}}"` reads the newline as spec text in the inner triple frame and refuses nothing; `f"""{f"{x:d\n}"}"""` refuses in the inner single frame, as the new row expects;
- a plain string in a field: `f"{'''a\n'''}"` reads, `f"{'a\n'}"` refuses at `:268`, both as CPython;
- `\`+newline in a single-quoted spec: refused (see L1, a false block, not a bypass);
- a newline in a field, a comment then `}` on the next line, `=`, `!r` then `:`, `:=` and `lambda` at the top of a field, `{x:{w}\n}` (CPython's `in_format_spec` stays set after a nested field, so the newline switches mode; Go refuses): all consistent.

**No other mode change is missed.** CPython changes mode in an f-string at `{` (to code), `}` at the field's depth (to text), `:` at the field's depth (to spec), a quote (end), and the spec newline. `pyField` mirrors the first three, refuses the fourth's single-quoted form, and a premature quote in a spec always leaves CPython's replacement field unclosed, so no such input compiles. `{{` and `}}` are not escapes in a spec in either implementation. The `\` peek in CPython's text mode consumes one byte except before `{` or `}`, which Go reproduces for `\{`, `\}`, `\"`, `\\` and `\`+newline in the literal part.

**No regressions.** The backslash-at-line-start check, `pyNumber`, the bracket limit, both recursion bounds (64 fields; a `{a:` chain costs two levels, so 32 through specs, matching `specDeep(32)`/`specDeep(33)`) and the cookie gate are untouched except the BOM strip, which is a prefix strip only, as CPython's.

### Low

**L1. `\`+newline in a single-quoted spec is a false block the ledger text does not name.**
- **Where:** `integrity_py.go:287-289`. `\` is text at `:292`, then the newline is refused.
- **Input:** `x = 1\ny = f"{x:\\\n}"\n`. CPython 3.12.3 compiles it and emits `FSTRING_MIDDLE '\\\n'`: the newline is consumed as the backslash's peek and never reaches the mode check.
- **Fix:** For the P14c-2 ledger, say "a newline, escaped or not". Or mirror CPython in one line before `:287`: `case spec && c == '\\' && i+1 < len(s) && s[i+1] != '{' && s[i+1] != '}': i += 2`. Either is fine; the block costs nothing.

**L2. The single-outer, triple-inner form has no read control.**
- **Where:** `integrity_py_test.go:338-339`. The refuse list has triple-outer/single-inner; the read list has only the flat triple case.
- **Input:** `x = 1\ny = f"{f'''{x:d\n}'''}"\n` compiles and CPython reads `FSTRING_MIDDLE 'd\n'` in the inner string. Go reads it (traced), but nothing pins that an inner triple quote resets `single`.
- **Fix:** Add it to the read list. It is the only one of the five H1 attack shapes without a row.

**L3. Size: two lines of duplication worth removing.**
- **Where:** `integrity_py.go:82` and `:118` compute the same normalised source (BOM strip, CR and CRLF to LF); `:67-70` spell out `errLex`'s own message.
- **Why:** If the two normalisations ever drift, the gate and the lexer see different lines 1 and 2, and that is the class of bug the gate exists to prevent.
- **Fix:** A `pyNorm(src []byte) string` used by both, and `else if err != nil { return nil, err.Error(), nil }` alone, since `errLex.Error()` is the same text. Saves about three lines of the 309. Nothing else in the file is unnecessary.

### Refuted or clean

- `\N{` inside a spec has no special case in `pyField`, but Go's nested-field reading ends at the same `}` as CPython's text reading for every Unicode name, and every mismatch involves a quote or newline inside the braces, which CPython rejects at decode.
- A `t` prefix in 3.12 is a name followed by a string in CPython and an f-string in Go, but no 3.12 program with a name directly before a string compiles, so there is no reachable differential. The doc comment already says this.
