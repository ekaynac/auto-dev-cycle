# PR #27 (containment tests alone): Astra reviews

## Review of #27 (Astra, 2026-10-04)

Verdict: NO-GO

The isolation approach is sound, but package selection can silently omit tests.

- **High — Makefile:102: the suffix filter excludes unrelated packages.**  
  `grep -v '/test/sandbox$'` also removes a future package such as `internal/example/test/sandbox`. The first invocation runs only `./test/sandbox/`, so that new package’s tests run in neither invocation. `make ci` can remain green: vetting/building a package does not execute its tests.  
  **Fix:** exclude exactly `github.com/ekaynac/auto-dev-cycle/test/sandbox`, using literal equality or `grep -Fvx`. Preserve every other package, including descendants of the containment package.

- **Medium — Makefile:102,106: discovery errors are discarded, and an empty list changes the command’s meaning.**  
  Bash’s `pipefail` detects failure, but Make’s `$(shell …)` does not propagate it to the target. A controlled probe returning one package and exit status 1 produced a successful Make invocation selecting only that package. With no output, the recipe becomes `go test -count=1`, which tests the current directory instead of all remaining packages. This currently fails because the repository root has no Go files; adding a root package could turn it into a misleading success.  
  **Fix:** capture discovery output in a checked shell assignment and abort on failure before filtering. Handle a successfully discovered empty remainder explicitly; never invoke bare `go test` accidentally.

- **Medium — Makefile:102: host discovery and sandbox execution use different Go environments.**  
  Host-side `go list` inherits settings such as `GOOS`, `GOARCH`, `GOWORK`, and user Go configuration, while the wrapper clears the environment and supplies its own configuration. For example, host `GOOS=windows` can omit a future Linux-only package that the sandbox’s original `go test ./...` would include. Host discovery itself does not violate “every test process tree runs inside a sandbox,” but it can reduce coverage.  
  **Fix:** discover and filter packages inside the second sandbox, then execute `go test` there with a quoted Bash array. Check discovery before populating the array; process substitution alone does not propagate discovery failure.

The diagnosis is supported by the implementation. `TestNoForeignProcessEnv` scans every readable process environment without distinguishing Go tooling. The installed Go source adds `GOOS`, `GOARCH`, and other settings for child tools, plus `TOOLEXEC_IMPORTPATH`; test binaries receive the original environment. Existing `internal/schemagen` tests also spawn Go tooling. These variables are consistent with sibling tooling, rather than evidence of host credentials leaking. The supplied incident itself was not independently reproduced.

Running containment alone preserves the unchanged allowlist, namespace isolation, mounts, network restrictions, refusal behavior, and wrapper breach checks. It matches the self-test’s existing invocation. The PR body overlooks bubblewrap’s init process, but its environment is explicitly sanitized.

With the current default environment, discovery selects all 13 other packages. Both invocations remain sandboxed; `make ci`, the containment self-test, both CI architectures, and the separate fixtures job remain wired as before. Ordinary import-path splitting is not the principal quoting problem; a checked array makes argument handling explicit.

Validation used source inspection, Make dry runs, and controlled discovery/filter probes. Full `make test` and `make ci` were not run.
