**On the four questions**

1. **Confinement.** Equal to the batch start's. `Interactive` builds its argv through the same `args()` (`internal/sandbox/run.go:129-148`); the six additions are `--interactive`, `--detach-keys=`, `--cidfile`, the two exchange mounts and one static env. `TestInteractiveIsStartPlusTheExchange` pins the whole argv, so a later drift in either direction fails CI. The adapter cannot reach: the network (`--network=none`, the loopback row with its host control, the probe's route and interface count); host files outside the workspace and exchange (only `workspace/`, `results/`, `in/` ro, `out/` and the gateway socket are mounted; the cid file is a sibling of `workspace/` in the attempt directory, outside every mount, and `..` of a mount point is the container's own root); another attempt's container (private storage root, no `--ipc=container:`, per-attempt exchange roots under `runs/exchange`, and `mounts()` refuses an exchange that is not `exchange-<this attempt>` directly under the root, a symlinked root, or a symlinked `in/`/`out/`). `Start` refuses an exchange, so a batch run cannot pick one up by accident.

2. **Lifetime.** I found no path where `Remove` returns nil while this run's container runs. The decisive fact from the man page: podman removes the cid file along with the container. So "no cid file" means one of three things: no container was created, it was removed, or the client died in the window between creation and the cid write. The first two are safe; the third is caught by the name check (`removeRun`'s `fs.ErrNotExist` branch), which fails closed and leaves the container to conmon's `--timeout` or the sweep. A cid file that outlives its container (a crash between the two removals) gives `rm --ignore` plus an empty `id=` listing, which is correct. The early removal's result is never used (`container.go:108-110`), so L1 is closed. After a crash the sweep removes every `adc-att_<valid id>` not held and every `adc-<24 hex>`; the storage root is private to this `Host`, so everything it lists is ours, and the `ids.Check` plus `batchName` gate skips any other name. The only leftover that survives the sweep is one whose attempt `keep` holds, which is the contract.

3. **Rows.** The CI rows prove argument shape, the by-id removal, the no-cid branch, the bound on `out/`, and the session's ordering (early removal once, fresh removal once, removal before drain, failed removal is `ErrUnverified`). The live rows prove what they claim, with real controls: `State.Running` before the sweep, the host dial before the container dial, the container still listed before `DoubtIsUnverified`'s sweep. Two things the rows do not prove, neither material: that `--detach-keys=` does anything (podman's `CopyDetachable` only matches a key on a one-byte read, and the wire's JSON escapes U+0010/U+0011 anyway), and the design's extra live rows (a routable-address dial, a second decoy socket, canary files), which the probe's route count, socket enumeration and `Forbidden`/`Home` checks cover equivalently.

4. **Opus's findings.** M1, M2, M3, L1, L2, L3 are all closed as the PR describes. M2's closure has one residual edge, below.

### Medium

**M1. A pre-existing cid file in the attempt directory makes `Remove` kill a previous run's live container.**
- **Where:** `internal/sandbox/interactive.go:64-89` (`Interactive` sets `a.unsafe = true` at line 78 but never looks at `cidFile(a.Dir)`), read at line 97.
- **Input:** call `Interactive(r, att)` twice on the same `*Attempt` while the first run's container lives, and start the second. podman 4.9.3 does not refuse an existing cid file (no such message in the binary; `os.Create` overwrites), but the name clash fails at creation, before the cid is written. The first run's cid file is still there, because its container still exists. The second's `Remove` reads it and runs `rm --force` on the first's live container. The first's `Wait` then passes its fresh removal (cid file gone with the container, name free) and returns an exit error rather than `ErrUnverified`.
- **Who can hit it:** only a caller that reuses an `Attempt` for a second start of the same attempt id. `NewAttempt` gives a fresh directory each time, and `TestLiveInteractiveSecondRunLeavesTheFirst` uses two attempts, so today's rows pass this edge by construction, not by a guard.
- **Fix:** in `Interactive`, refuse with `ErrSpec` when `cidFile(a.Dir)` exists ("the attempt's directory holds a cid file: a run of it may still exist"). Add a CI row: a second `Interactive` on an attempt whose directory holds a cid file is refused and podman never runs.

### Low

**L1. conmon's `--timeout` equals the session's deadline, so the end's kind depends on timing at a tie.**
- **Where:** `internal/sandbox/run.go:133` and `interactive.go:89` (`Deadline: r.Limits.Timeout`); classified at `internal/adapterhost/session/session.go:238`.
- **Input:** `Limits.Timeout` of 90 s. The session's timer fires at 90 s from the client's spawn; conmon's at 90 s from the container's start, so normally the session wins by the start latency. If the Go timer is late by more than that, conmon kills the container first, the client exits, `read()` sees EOF with `Expired()` false and reports `KindExited` ("output ended before shutdown") for what was a deadline.
- **Fix:** give conmon a margin: `--timeout` = ceil(Timeout) + `removeTimeout` (or a named grace constant). conmon is the backstop for a dead controller, not the deadline, and the live deadline row already uses a shorter session deadline than the limit.

**L2. The start sweep shares one 30 s budget across every leftover.**
- **Where:** `internal/sandbox/interactive.go:141-142`.
- **Input:** a crash that leaves many containers, or one `rm --force` that stalls. The sweep errors part-way, and the start fails with containers still running.
- **Fix:** a per-container `removeTimeout`, and continue past one failure, returning the joined errors with the attempts removed so far.

**L3. A bound breach after a clean removal surfaces as `ErrUnverified`.**
- **Where:** `interactive.go:87` returns `ErrLeft`; `container.go:109-110` maps any removal error to `ErrUnverified`, and the cause is dropped.
- **Input:** an adapter that writes `Limits.Disk + 1` bytes to `/exchange/out`. The container is gone and the attempt is safe, yet the operator sees "the process tree was not seen to end".
- **Fix:** keep the cause: `p.waitErr = errors.Join(ErrUnverified, err)`. `within`'s text names only counts, and `removeRun`'s names only the container, so nothing adapter-chosen leaks. If the package's no-wrapping rule is deliberate, log the cause on the sandbox side instead.

**L4. `Teardown` of an unsafe attempt deletes the cid file and loses the by-id handle.**
- **Where:** `internal/sandbox/run.go:379-394` is not gated on `unsafe`; `Probe` guards it at `probe.go:98`, `Interactive`'s caller must too.
- **Input:** a caller tears the attempt down after `Wait` returned `ErrUnverified`. The later sweep still removes the container by name, so it fails closed, but the attempt's own `Remove` can no longer succeed.
- **Fix:** either refuse `Teardown` while `unsafe` (a one-line check, with the sweep as the owner of what is left) or state the ordering in `Interactive`'s doc for 5d-3.
