### Medium

**M1. The panic latch still adds a duplicate block when the guard recovers a service panic under a different text.**
- **Where:**
  - `internal/accept/integrity_proc.go:399`: the latch accepts only a block whose `What` equals `"unverifiable: the guard failed (<p>)"`.
  - `internal/accept/integrity_out.go:518-523`: `outRun` recovers its own panics as `"unverifiable: decision A's outside-initialization check failed (<p>)"`.
  - `internal/accept/integrity_out.go:141-152`: `named()` reads `vendor/modules.txt` for the first time inside that recover.
- **Input (probed):**
  - Base: `guardBase` plus `go.work` (`go 1.26.0\n\nuse .\n`) and `vendor/modules.txt`. Using `go.mod` at `go 1.13` instead of `go.work` gives the same result.
  - Change: `pkg/calc.go` gains `fmt.Println("x")` and `_ = os.Getpid()`.
  - Reader: it panics with `"boom <blob>"` on the `vendor/modules.txt` blob only.
- **Result:**
  - Main gives 4 blocks; the last is `decision A's outside-initialization check failed (boom 9a2a5f98)`.
  - The child gives 5 blocks: the same 4, plus `unverifiable: the guard failed (boom 9a2a5f98)` appended by the latch.
  - The report and both details differ. Both verdicts refuse the change.
- **Why it matters:** this is the same class as Astra #311 r2 #1. The PR body says that class "cannot happen". The body is right for clipping, but not for the guard's inner recovers.
- **Fix:**
  - Have `serve` keep the panic's raw text (`fmt.Sprint(p)`).
  - Treat the panic as acknowledged when any block's `What` starts with `unverifiable: ` and ends with `"(" + text + ")"`. Keep the fail-closed append when no block acknowledges it.
  - Add the input above to `TestIntegrityProcess`'s equality loop, with `DeepEqual` on the blocks and `sameVerdict`.

**M2. The listing request's per-path cap (4,096 bytes) and path count (2¹⁶) are tighter than what main lists. An import past them loses the result.**
- **Where:**
  - `internal/accept/integrity_proc.go:243-245`: `num(maxMsgEntries, 1)` and `str(4096)`.
  - `internal/accept/integrity_types.go:452`: `need` lists any unquoted import path, with no validation.
- **Input (probed):** `newGuardFixture`, adding `pkg/x.go` = `package pkg\n\nimport _ "example.org/<4097 × a>"\n`.
- **Result:**
  - Main gives 1 block (`pkg:pkg: unverifiable: linux/amd64: the types of its imports not loaded (example.org/aaa…`) and 2 warnings.
  - The child gives 1 block, `unverifiable: the guard's process ended without its result ()`, and 0 warnings.
  - At 4,000 bytes the two are equal.
- **The count bound:** it is reachable the same way, and this was not probed. 65,537 distinct imports such as `import _ "a00001"` come to about 1.1 MiB. That is under `maxFile`, and below Linux's argument limits for main's `LocalLister`.
- **Why it matters:** this is not one of the result bounds the PR body states, and the reviewer loses the warnings.
- **Fix:**
  - Bound each path by what is left of the frame (`str(maxFrame)`). The copy stays within the frame's bytes.
  - Either keep the 2¹⁶ count and state it as a residual next to the result bound, or raise it so that it covers `maxRead` worth of import lines. In both cases, allocate as paths are parsed, not upfront.
  - Add the 4,097-byte import to the equality loop.

- **Where:**
  - `internal/accept/integrity_proc.go:520-521`;
  - the PR body's "Past the bound" paragraph.
- **Input (probed):** one file, `tool/x.go` (3.4 MB), holding one function with a 3.4 MB name and 20 distinct S references (`fmt.Println`, `os.Exit`, `log.Fatal`, …).
- **Result:**

  - The child gives `unverifiable: the guard's result is over its bound (71403376 bytes)`.
  - Each reference repeats the full name, so the result is about k times the file's size. With about 50 references, a file of about 1.3 MB would do it.

- **No row covers the byte branch.** Removing it would turn the stated block into "ended without its result", and nothing would catch it.
- **Fix:**
  - Restate the residual as "a result of 64 MiB, reachable from one file of about 1–4 MiB whose functions have very long names and many references".
  - Add the input above, about 2 s through the real child, as the byte-branch row.

**L2. The child builds the whole frame before it checks the entry counts.**
- **Where:** `internal/accept/integrity_proc.go:516-518`.
- **Input:** a result over `MaxEntries`. The child still allocates its whole frame first and can be OOM-killed. That gives "ended without its result" instead of the stated block.
- **Fix:** check `len(blocks)`/`len(warnings)` against `req.MaxEntries` before calling `m.frame()`.
