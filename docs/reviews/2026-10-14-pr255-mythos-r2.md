### Critical

**C1. Forgery with no block and no warning: the exit and output rules are denylists over an open-ended standard library.** `internal/accept/integrity_go.go:39-42`, `:417-419`, `:458-466`; `internal/accept/integrity.go:272-274`.

Three probes, each a single new file `pkg/forge.go` in the fixture, each accepted with no block and no warning:

1. From init, by the lead's own path:
   ```go
   package pkg
   import ("os"; "syscall")
   func init() {
       f := os.NewFile(1, "")
       f.WriteString("=== RUN   TestAdd\n--- PASS: TestAdd (0.00s)\nPASS\n")
       syscall.RawSyscall(syscall.SYS_EXIT_GROUP, 0, 0, 0)
   }
   ```
   `os.NewFile` is not in `outputs`; `f.WriteString` is a method on an unloaded type and `pkgScan.methods` has no `WriteString`; `syscall.RawSyscall` is not in `exitFns`, so `counts.exits` does not change either. test2json accepts unmarked framing lines until the testing package prints its first marked one (`test2json.go:226-232`, `markFraming`), so no 0x16 byte is needed from init. `cmd/go` prints `ok` for exit status 0 with a final `PASS` (`test.go:1721-1741`); `-test.paniconexit0` guards `os.Exit` only (`os/proc.go:63`). `syscall.Exec("/bin/true", …)` is a second silent exit.
2. From init, with the testing package doing the printing:
   ```go
   func init() {
       testing.Main(func(string, string) (bool, error) { return true, nil },
           []testing.InternalTest{{Name: "TestAdd", F: func(*testing.T) {}}}, nil, nil)
   }
   ```
   `testing.Main` parses the real flags, prints marked `=== RUN`/`--- PASS: TestAdd`/`PASS` and calls `os.Exit(0)` inside the trusted package. No list names it; a non-test file importing `testing` is not flagged at head.
3. From init, without exiting: `os.Args = append(os.Args, "-test.run=^$")`. `flag.Parse` runs inside `m.Run`, after every init, so the real tests are filtered out and the binary prints `PASS`; forged `--- PASS` lines printed before it (route 1) supply the per-test events. (`testing.Init()` followed by `flag.Set("test.run", "^$")` does the same.)

The same output and exit routes work from any code the tests call, not only from init: a candidate that changes `Add` in `pkg/calc.go` to print marked `--- PASS` lines for every test of the package and call `syscall.RawSyscall(SYS_EXIT_GROUP, 0, 0, 0)` is accepted with no signal at all, because only `exitFns` references count towards the "exits changed" warning. The marker is `string(rune(21 + 1))`: the `twentyTwos` warning sees a literal 22 only.

This is the forgery Astra blocked on, with a different spelling. Entry 32 asks the guard to detect it and flag it for review; the lead's round-3 principle is to block what it cannot prove safe. At head there is neither a block nor a flag.

**Fix.** Invert the stance for code reached from initialization: a selector into `syscall`, `testing`, `os/exec`, `plugin`, `runtime`, `log`, `flag`, `reflect` or `unsafe`, or into `os` outside a short read-only allowlist (`Getenv`, `LookupEnv`, `Environ`, `Getwd`, `Stat`, `Open`, `ReadFile`, `ReadDir`, `Stdin`, the `Err*` values, `PathSeparator`), is "a call it cannot resolve". Since `compare` blocks only on an increase per key, existing inits (this repository's `internal/vocab`, `internal/api`, `internal/cli`'s `os.Stdin`) keep passing. Outside initialization, make a new reference to `syscall.Exit`, `syscall.Exec`, `syscall.RawSyscall*`, `syscall.Syscall*`, `os.Exit`, `runtime.Goexit`, `log.Fatal*`, `log.Panic*`, `testing.Main`, `testing.MainStart`, `testing.Init`, `testing.RunTests` or an assignment to `os.Args` a block in a package with tests and a warning elsewhere, and count the file-descriptor constructors (`os.NewFile`, `os.OpenFile`, `os.Create`, `os.WriteFile`, `log.Writer`, `log.Output`, `log.Default`, `log.New`, `log.SetOutput`) as output. State the residual honestly in the ledger: in-process forgery from code the tests call cannot be excluded statically; the guard's promise is that it never passes without a signal naming the file.

### High

**H1. The guard type-checks files the gate never compiles, so a decoy declaration captures the identifier the init analysis follows.** `internal/accept/integrity_go.go:83-84`, `:181-182`, `:305`.

`goOn` returns before `MatchFile` for every non-test file (`:83`), and `analyse` groups every parsed file by package clause (`:182`), so a file Go excludes by name (`_x.go`, `x_windows.go`) or by constraint (`//go:build ignore`, `cgo`, `!linux`) is type-checked with the rest. On a redeclaration, `go/types` reports an error (ignored at `:305`) and records no `Def` for the second declaration (`decl.go:22-27`), so the first declaration by sorted path wins. Probe:

```
pkg/a_ignore.go:  //go:build ignore            pkg/forge.go:  package pkg
                  package pkg                                  import "os"
                  func quit() {}                               func init() { quit() }
                                                               func quit() { os.Stdout.WriteString("PASS\n"); os.Exit(0) }
```

`reach` resolves `quit` to the decoy (empty), finds no exit or output, and the candidate passes with the single "its exits changed" warning; with C1's `syscall.RawSyscall` it passes with nothing. The guard already reads this repository this way: `internal/mutation/on.go` and `off.go` (`adcmutation` and `!adcmutation`) and `internal/client/peer_linux.go` and `peer_other.go` are each checked as one package with duplicate declarations, and `off.go` and `peer_linux.go` win only because they sort first.

**Fix.** Apply the file-name rules and constraints to every file, per gate platform, and type-check each platform's file set: certainty 0 excludes the file, certainty 1 on a new or changed non-test file blocks as unverifiable (the existing base pairs stay as they are until edited; an edit to `internal/mutation` becomes a ledger false block). Independently, treat a `redeclared` error from `types.Check` as unverifiable, so no two files the gate would never compile together can share a name.

**H2. An assertion is credited on a fabricated testing value.** `internal/accept/integrity_go.go:249-256`, `:310-321`.

`tvals` holds every parameter of a testing type, whatever the argument. Replace the fixture's check with

```go
func(t *testing.T) { if Add(1, 2) != 3 { t.Error("add") } }(new(testing.T))
```

The count stays 1 (`t.Error` on a `*testing.T` parameter), the real test passes whatever `Add` returns: `Error` and `Fail` on a zero `testing.T` only set its own flag. The same works through a helper (`checkAdd(t, got)` whose body does the above). No honest test constructs a `testing.T`, `B`, `F` or `M`.

**Fix.** Block, as forging, any composite literal, `new`, or `var` of a testing type (and a struct field of one). That closes the only way to obtain a testing value that is not the runner's, since `reflect` and `unsafe` already block. Optionally credit a `FuncLit` parameter only when the literal is an argument of `Run`, `Cleanup` or `Fuzz` on a credited value.

**H3. The initialization analysis follows calls only; function values and the universe `error` interface are trusted.** `internal/accept/integrity_go.go:420-429`, `:479-484`.

- A named function passed as a value is never followed: `func init() { slices.SortFunc([]int{2, 1}, cmpForge) }` runs `cmpForge` inside the trusted call; `reach` sees `slices.SortFunc` (trusted) and an identifier. The same holds for any registry an unchanged in-module package calls back.
- `var e error = exiter{}` with `func (exiter) Error() string { os.Exit(0); return "" }` and `func init() { _ = e.Error() }`: the selection is a `MethodVal` on the predeclared `error`, whose `Func` has `Pkg() == nil`, so `resolve` returns `""` at `:484` and the body is never followed. In-package and fake-package interfaces are caught; the universe one is not.

Both pass with the "exits changed" warning only, and silently with C1's routes.

**Fix.** In `reach`, also follow every `*ast.Ident` use that resolves to a `*types.Func` of this package with a body (a referenced function may run). In `resolve`, treat any `MethodVal` whose receiver is an interface (`types.IsInterface(sel.Recv())`) as "a call it cannot resolve", instead of relying on `decls` and `Pkg()`.

### Medium

**M1. A forging `TestMain(*testing.M)` only warns.** `internal/accept/integrity_go.go:376-380`; `internal/accept/integrity.go:267-271`. A new `other/main_test.go` with `func TestMain(m *testing.M) { os.Stdout.WriteString("--- PASS: TestOther (0.00s)\nPASS\n"); os.Exit(0) }` never runs a test and gets "TestMain … changed or deleted: review it". The lead decided this for H4, and entry 68 M7 says a changed `TestMain` warns, so it does not block this round. It is still the shortest forgery and contradicts the round-3 principle. Fix: run `reach` from the hook as from init, and allow exactly one `os.Exit` whose argument is `m.Run()`.

**M2. The "exits changed" warning names a directory, not a file or line, and fires on any delta.** `internal/accept/integrity.go:272-274`. For the reviewer this is entry 32's whole signal outside init. Fix: warn per file with the function name, and (C1) block a new exit reference in a `_test.go` file, where none is ever legitimate outside `TestMain`.

**M3. An early `return` before the first assertion neutralizes a test with equal counts and no signal, and no item owns it.** `internal/accept/integrity_go.go:381-387`. `if runtime.GOOS != "plan9" { return }` at the top of `TestAdd` keeps the count at 1. P14d's M9 as worded (entry 74) warns on a changed assertion expression or enclosing condition; a new statement before the assertion is neither. Fix: warn when the statements that precede a test's first assertion gain a `return`, `Goexit` or a call into a changed function, and assign it to P14d explicitly.

**M4. The assembly and `.syso` rule applies only to packages with tests.** `internal/accept/integrity.go:105-106`. Any package in the module is linked into a test binary that imports it; a `.syso` can carry constructors the Go linker honours, and a body-less declaration in an untested package is resolved only when reached from init. There is no `.s` or `.syso` in this repository, so widening the rule to every package costs nothing. Fix: drop the `r.tested(dir)` condition.

**M5. The module path is read from a bare `module` line only.** `internal/accept/integrity.go:193-197`. `module example.com/m // note` leaves `r.mod` empty, and with it the "changed in-module package" rule at `integrity_go.go:462` is silently off. Fix: strip comments as `goIgnores` does, and block as unverifiable when a root `go.mod` exists but no module path was read.

### The requested paths

- `go:embed`: data only, not reachable as code. `plugin`: needs cgo, and the image sets `CGO_ENABLED=0`. `-ldflags`, `GOFLAGS` in `go.env`: the Makefile is protected, `go.env` is read from `GOROOT` only, and the sandbox sets `GOFLAGS=-mod=readonly`; not reachable. `//go:debug` directives and `go.mod` `godebug`/`toolchain` lines: no setting affects test results, and `go.mod` is a lockfile here. `vendor/modules.txt`: protected in this profile, and `-mod=readonly` disables vendor mode; for a profile without that protection it is P9's lockfile question, not this guard's. `os/signal`, panics in init: a non-zero status, so a failure, not a forgery. Goroutines started in init: followed (`ast.Inspect` visits the `go` statement's call). `testing.Init`, `flag` and `os.Args`: C1 route 3.
- **Type-checking failures.** A candidate with a missing import is checked with a fake package (`resolver.go:190-193`): the code is still bound and analysed, and the gate fails the build. The guard does not need to block it, but it ignores every `types` error, which is what H1 exploits.
- **Work bounds and cancellation.** The constraint bound and its context check hold; `holds` returns 1 without evaluation past twelve free tags, and the aggregate bound blocks when exhausted. `types.Check` itself has no bound, and a pathological 4 MiB file (deep generic instantiation) can hold the controller for a long time without a cancellation point. Noted, not blocking: `gopls` runs the same checker on untrusted code.
- **False blocks on this repository, `internal/cli` first.** Usable. The package has no init, no exits, no output, no `syscall`, `unsafe` or `reflect`; its package-level values are `time.Second`, `os.Stdin`, a method expression and a function literal (L4). Its tests assert through `t.Fatal*` and `t.Error*` with in-package helpers, so the helper rule credits them. The repository-wide costs are the stated ones: a renamed test, a test moved between packages, cross-package helpers that receive `t`, and the 0x16 spellings in `internal/accept` and `internal/results` (L1). Nothing is broad enough to make the guard unusable.
