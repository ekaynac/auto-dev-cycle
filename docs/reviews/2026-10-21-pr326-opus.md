### Medium

**M1. The M0 harness records any `Prepare` error as a refused start, which is a regression.** `internal/harness/harness.go:273-279`
- **Input:** the exchange root cannot be written, or the attempt id is malformed. `newExchange` then returns `ErrExchange` (`internal/adapterhost/exchange.go:54-55`).
- **What happens:** the harness records `lease.start_refused{precondition_failed}` and reports "the host's prelaunch capability check failed".
- **Before (#325):** the same failure was a host error: nothing was recorded and the reason was `executor_incomplete`. Only a failed probe recorded a refusal.
- **Fix:** refuse the start only when `errors.Is(perr, ingest.ErrUnsupported)`. Return any other error as is. Add a row with an unwritable `Host.Root`.

**M2. In a hostile tree, the workspace differs from `AttemptBase.Tree`, and nothing reports it.** `internal/daemon/workspace.go:83-99`, `internal/sandbox/git.go:176`
- **Input:** a base commit whose tree has `sub/.git`, `.git`, `.GIT` or `git~1` next to `ok`. Probe: `openWorkspace` succeeds, the workspace holds only `ok`, and `w.Base` still names the full tree.
- **A second input:** a tree with both a symlink `a` pointing outside and a directory `a/pwn`. Nothing is written outside the workspace, but the symlink is dropped without notice.
- **Why it matters:** the patch the builder makes, and the base the gate measures against, would then be computed against a tree the adapter never saw.
- **Fix:** clone with `-c transfer.fsckObjects=true` (or `fetch.fsckObjects`). Git's fsck refuses `.git` entries and duplicate entries at clone time, so the workspace fails closed. Add these trees as rows.

**M3. Most of the I16 check is untested.** `internal/adapterhost/attempt.go:187,190`
- **Input:** X1 (no lease check), X2 (no status check) and X4 (`token: 1`) all survive the whole adapterhost suite. Only "not started" has a row (`attempt_test.go:382`).
- **The behaviour itself is right.** Probes show that an attempt on another lease, a lost attempt and a stopping attempt each get `ErrNotStarted`, and nothing is launched.
- **Fix:** add rows for:
  - an attempt started on another lease;
  - an attempt that is lost, and one that is stopping;
  - a superseded unit, where the replacement runs with token 2 and the adapter's `prepare` receives `fencing_token: 2`.

**M4. The base is looked up by name each time, never pinned.** `internal/daemon/workspace.go:83,93`
- **Within one call it is safe in practice.** `rev-parse BaseRef^{tree}` and `checkout BaseRef` read the same local clone, and nothing fetches into it in between.
- **But the code never ties the checkout to the id it measured.** And each attempt re-clones `repo.base_ref`. A supersession (`StartNext`), or a retry after the branch moved, gets a different tree from its predecessor's and from the tree the gate measured.
- **Fix:**
  - Check out the measured id: `checkout <tree> -- .`.
  - Give `openWorkspace` an optional pinned `types.GitID`, the unit's first `AttemptBase.Tree`, and refuse if the fresh clone does not contain it.

### Low

**L1. Several doc lines are stale.**
- `docs/design/m1/01-invariant-inventory.md:234` still says "`lease.StartAttempt` (which `adapterhost.Host.Run` calls directly)". It also says there is no caller of `StartAttempt` outside fixtures, but `internal/harness/harness.go:281`, which ships in `adc-harness`, now calls it.
- `docs/design/m1/00-slice-plan.md:81` and `internal/adapterhost/host_test.go:497` still name `Host.Run`.
- **Fix:** update all three. Name the harness as a controller of its own, with a private store and no rails.

**L2. The host no longer reads `Spec.Base`.** `internal/adapterhost/attempt.go:81`
- **Input:** a probe started the attempt with base `ffff…/9` and passed a Spec with `0123…/7`. `Run` launched without complaint.
- **Fix:** remove `Base` from `Spec`, and let the harness and fixtures pass it to `StartAttempt` separately. Or refuse when `a.Base != spec.Base`.

**L3. A `Prepared` can be run more than once.** `internal/adapterhost/attempt.go:173`
- **Normally this is harmless.** Every unsuccessful end records `attempt.lost` (`submit.go:250`), so a second `Run` gets `ErrNotStarted` (probe).
- **The gap:** if the finish transaction itself fails (`submit.go:268`), the attempt stays `running`. A controller that retries with `Prepare` and `Run` would then run the adapter again under the same token, without `dispatch.Launch`, and so outside `rail:attempts_per_round`.
- **Fix:**
  - Make `Prepared` single-use, with a flag that `Run` and `Discard` set.
  - Document that on a host error the caller loses the attempt (`LoseRunning`) and starts again through `Launch`.

**L4. An empty base cannot get a workspace.** `internal/daemon/workspace.go:93`
- **Input:** a base that is an empty commit. Probe: `ErrGit: … pathspec '.' did not match any file(s)`.
- **Fix:** skip the checkout when the tree is the empty tree `4b825dc…`, or use `read-tree <tree>` followed by `checkout-index -a`.

**L5. The attempt id is not checked before it becomes a path.** `internal/daemon/workspace.go:60`
- **Input:** an empty attempt id. Then `dst` is `clones` itself. The clone fails because the directory is not empty, and `RemoveAll(dst)` deletes every other attempt's clone.
- **Fix:** `ids.Check(string(attempt), "att")` first, as `newExchange` already does.

**L6. Leftovers after a crash are never swept.**
- **Input:** adcd dies between `openWorkspace` and `Close`. `clones/<att>` (a full repository) and `runs/a*` stay. Nothing in `recovery` sweeps either one.
- **A smaller case:** a cancelled `ctx` kills only the direct `git` child, so the processes it spawned can keep writing into `dst` after `RemoveAll`.
- **Fix:** 22a-5c adds a sweep of both directories at restart, before launch turns on.

**L7. ssh URLs never clone.** `internal/daemon/workspace.go:8`, `internal/sandbox/git.go:32`
- **Input:** `ssh://host:1/r.git`. Probe: `ssh variant 'simple' does not support setting port`. Without a port, `core.sshCommand=false` fails the clone anyway.
- **Mismatch:** the profile schema allows "Any git URL", and the doc comment says "an https or ssh URL".
- **Fix:** say https only, or design a controlled ssh command (BatchMode, a pinned known_hosts file).

**L8. The origin check can never fail today, and nothing tests it.** `internal/daemon/workspace.go:70`
- **Probe:** a local path, the same path without `.git` (git resolves it), and a bare repository all record exactly the given URL as origin. X5 survives.
- **Keep it.** It is cheap, it reads only the clone's own config with no includes, and it would catch a later `Clone` that uses a mirror or a cache.
- **Fix:** add a `clone = sandbox.Host.Clone` seam, so a row can return a clone whose origin differs and assert `ErrRemoteMismatch` with nothing left behind.

**L9. Nothing tests the failure path of `ProjectProfile`.** `internal/authority/project.go:83-97`
- **The code is right:** a profile that no longer loads returns an error and `ok == false`, and `Load` runs `Check`.
- **But X6 survives:** no row stores a record that fails to load.
- **Two cheap extra checks are missing:** `rec.ProfileDigest == ContentDigest(rec.Profile)` and `p.ID == id`.
- **Fix:** add a row that writes such a record straight into the projection, and add both checks.

**L10. The git version floor is not a security floor.** `internal/sandbox/git.go:44`
- **Input:** a local-path URL to a partial-clone repository that has a promisor remote with `remote.<x>.uploadpack` set.
- **On this host it is refused.** Ubuntu's patched 2.43.0 answers "lazy fetching disabled" (CVE-2024-32465). But a stock git between 2.41 and 2.45.0 passes the 2.41 floor and would run that command during the clone.
- **Fix:** document that a local-path repository must be owned by the controller and trusted. Or refuse a local source whose config has `extensions.partialClone` or a promisor remote, read with `git config --file … --no-includes`.

### Answers to the four questions

1. **I16:**
   - **No path in the host starts an attempt.** `decideStart` and `startAttempt` are gone. The host uses `lease` only for reads, the fence, `SubmitResult` and `LoseRunning`.
   - **Who starts attempts now:** `dispatch.Launch` (`StartNext`) in adcd, the harness on its private store (`harness.go:281`), and the fixtures (`fixtures/adapterhost.go:374`).
   - **Retry:** a failed run ends lost, and `Run` refuses a lost attempt. The exception is L3.
   - **Supersession:** the token comes from the attempt record, so token N is correct. But nothing tests it (M3, X4).
   - **Another lease, a lost or stopping attempt:** refused, shown by probe. Untested (M3).
   - **Sealed attempts:** also refused; this follows from the code, since `Run` requires `running`. I did not probe it.
   - **A stale token:** it cannot reach `Run`, because the token is read from the record. Staleness that arises during the run is caught by `fenceAttempt` and `SubmitResult`.
   - **X3:** a running attempt is always its unit's current one, because supersession requires a sealed attempt. So the `current` check is redundant, and that is harmless.
2. **The workspace:**
   - **Base lookup:** see M4.
   - **No `.git` in the workspace:** `.git`, `.GIT`, `sub/.git` and `git~1` are all absent. `GIT_DIR` points at the clone, so no gitfile or worktree link is written. A gitlink becomes an empty directory, and there is no recursion. The only problem is that this happens without notice (M2).
   - **Hostile repository:** no code ran on the controller. The probe set `core.fsmonitor`, `core.hooksPath`, `uploadpack.packObjectsHook`, `core.alternateRefsCommand` and `filter.*` in the source's config, put hooks in both the source and a hooks directory, and added a `.gitattributes` filter and a `.gitmodules`. The in-tree `.gitattributes` is ignored because of `GIT_ATTR_SOURCE`. Symlinks are never followed. The one gap is L10.
   - **Cleanup:** every error path removes both the clone and the run, and the mutations show `Close` removes both. The gaps are L5 and L6.
   - **Origin check:** see L8; keep it, with a test.
3. **`ProjectProfile`:** it fails closed, but nothing tests that (L9).
4. **Regressions:** one, M1. Otherwise the 7 named mutations are caught and the contract fixtures are unchanged.
