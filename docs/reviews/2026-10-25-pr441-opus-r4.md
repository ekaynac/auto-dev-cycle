### 2. The code before the re-exec, and the marker
**Before the re-exec,** the only commands are:
- `set +o xtrace +o verbose`;
- the `[[ ]]` test (a keyword);
- `exec 3< <(… printf …)`;
- `exec env -i … bash --noprofile --norc`.

`exec`'s program is found by `PATH`, never as a function, so an `env` function does nothing. A function named `exec`, `set` or `printf`, `BASH_ENV`, and `PATH` itself can subvert this part. That matches the stated boundary, except that `printf` is missing from it (N3).

**The marker (`ADC_CLEAN_SHELL=1`)**, run from a clean base with one hostile item each:
- `SHELLOPTS=xtrace`, `BASHOPTS`, and an exported `boot` are refused (exit 2) by `clean_shell`;
- the `grep` function is refused ("a shell function is defined");
- `TMOUT` is unset, and the run proceeds normally.

`clean_shell` therefore catches everything the re-exec removes, **except functions that shadow its own checks**. With the marker plus exported functions `declare` (an empty `declare -F`) and `printf` (forging only `env_extra`'s status line), the run passed both checks. Adding a `set` function and `SHELLOPTS=xtrace` then **printed 8 secret lines**.

That is operator code, the same class as the stated `exec`/`set` boundary. But with the marker, the boundary covers the whole run, not "the caller's shell up to this re-exec", so "a caller that sets the marker itself gains nothing" is inaccurate (N3).

### 3. The fd-3 path
**What holds:**
- **Writing:** the credentials are written by `printf`, a builtin inside the process substitution, so no argv carries them.
- **Reading:** they are read back by `read -d ''`.
- **Closing:** fd 3 is closed (`exec 3<&-`) before any process the run keeps: adcd showed no fd 3, and no extra environment name.
- **The window:** `dirname` and `env -0` (`clean_shell`) inherit fd 3 between the re-exec and the read loop, and neither reads it.
- **Redaction:** each value is `known_text`, and only names are printed.

**[INFERENCE: read from the code; my content probe failed in my own harness]:**
- an unterminated last entry (a writer killed mid-print) is dropped silently, because `read` fails on it;
- an entry with no `=` is printed whole as a "name";
- on the normal path the driver itself writes fd 3, so either case needs the marker plus a crafted fd 3.

### Findings
- **N1** (entry 202's line, for the lead: the outcome is fail-open, but no in-script fix exists).
  - **The input:** `SHELLOPTS=noexec` in the caller's environment.
  - **The effect:** bash imports it and executes nothing.
  - **Probe:**
    - the driver: exit 0, no output;
    - `installed-cycle-set.sh run`: exit 0, no output;
    - a Makefile with `SHELL := /usr/bin/env bash` (this repository's): its recipe printed nothing and exited 0.

    So `make installed-cycle-stub` and `make ci` themselves "pass" having run nothing. It is repo-wide and predates #441, and no line of a bash script can guard it, since none runs.
  - **The cheap guard** for the operator's entry points: `unexport SHELLOPTS BASHOPTS` in the Makefile. Probe: with it, the same recipe ran and failed properly (exit 2).
  - **Add** `SHELLOPTS`/`BASHOPTS` to the stated trust boundary for direct driver invocation.
  - **Ruling:** I'd call it an OBLIGATION that is best landed in this PR. If the lead reads entry 202 strictly, it is BLOCKING.
- **N2** (OBLIGATION, Low; for PR 2's live route): validate each fd-3 entry. The name must match `^ADC_CREDENTIAL_[A-Z0-9_]+$` and hold an `=`, and `read`'s final status must show a clean EOF (no unterminated tail). Otherwise refuse (exit 2), naming no content. Today an unterminated entry is dropped silently, and an entry without `=` would be printed as a name. Both need the marker path and a crafted fd 3, and both fail closed once the live route checks the registry's credentials, but the "names only ever printed" promise should not rest on that.
- **N3** (OBLIGATION, Low): make the trust-boundary statement exact (both drivers' headers):
  - before the re-exec, functions named `set`, `exec` and `printf` are operator code;
  - with the caller's own `ADC_CLEAN_SHELL`, any exported function shadowing a builtin `clean_shell` uses (`declare`, `printf`, `set`, `local`, `unset`) is operator code for the whole run: my probe printed secrets that way;
  - `SHELLOPTS`/`BASHOPTS` with `noexec` (N1) are operator input too.

  Alternatively, drop the marker shortcut: always re-exec unless `$(</proc/$$/environ)` (a redirection, which no function can shadow) holds exactly the re-exec's allowlist. That closes the marker case for every name except `exec`.
