### Findings

**Low 1. The index-equality check refuses a legitimate base whose tree git canonicalizes.** `internal/daemon/workspace.go:133-136`
- **Input:** a branch commit whose root tree holds an empty subtree (`040000 tree 4b825dc… sub`, as `git mktree` and some importers write). fsck accepts it; the checkout writes nothing for `sub`; `write-tree` omits it, so the id differs from the measured tree and the workspace is refused with `ErrBaseMismatch`. (A non-canonical file mode such as `100664` is the other canonicalization, but index-pack's strict fsck already refuses it at the clone, which the M2 statement covers.)
- **Why it matters:** an unstated false block, on a repository the operator adopted. Fail-closed, so not blocking under decision A.
- **Fix:** replace the `write-tree` equality by `git diff --cached --quiet <tree>` (`diff` is allowlisted and `Repo.Git` adds `--no-ext-diff`), which compares entry by entry with git's own canonicalization, and keep `ls-files --deleted`. State the refusal in the PR's residual either way.

**Low 2. "A repository the controller owns and trusts" is a sentence, not a check.** `internal/sandbox/git.go:175-179`, `internal/daemon/workspace.go:8`
- **Input:** an absolute path to a repository owned by another uid, outside the sandbox root and the forbidden paths. `refused` passes it; the controller's `git-upload-pack` then reads that repository's config. On a stock git before 2.45.1 a partial clone's promisor command runs (L10, documented). On any git, if the client fell back to protocol v0, `core.alternateRefsCommand` with an `objects/info/alternates` file runs a shell command on the controller; under the default protocol v2 that advertisement is not made, so the path is dormant today.
- **Fix:** before cloning a local path, `os.Stat` it and refuse an owner other than the controller's uid; refuse a source that has `objects/info/alternates`, `extensions.partialClone` or a `remote.*.promisor`, read with `git config --file … --no-includes`. The controller's own repositories never have these, so the false block is acceptable under decision A.

**Low 3. A cancelled context stops only the direct `git` child.** `internal/sandbox/git.go:77`, `internal/daemon/workspace.go:87-89`
- **Input:** adcd's shutdown cancels `ctx` during a clone. `exec.CommandContext` kills `git clone`; its `index-pack` (and, for a local source, `upload-pack`) keep running and can re-create files under `dst` after `RemoveAll(dst)` returns. This is Opus L6's smaller case, left to 22a-5c's sweep.
- **Fix:** in `sandbox.git`, set `SysProcAttr{Setpgid: true}`, a `cmd.Cancel` that signals the process group, and a `cmd.WaitDelay`; then the sweep is for crashes only.

**Low 4. The hostile-tree row does not prove where the refusal happened.** `internal/daemon/workspace_test.go:129`
- **Input:** the row accepts any `sandbox.ErrGit`, and the checkout's failure wraps `ErrGit` too (`workspace.go:128`). A future change that lets a hostile tree through the clone but fails the checkout would keep the row green, against its comment ("refused at the clone, by its object checks").
- **Fix:** assert the error names the clone (`strings.Contains(err.Error(), "clone:")`), or assert that `host.NewAttempt` was never reached.
