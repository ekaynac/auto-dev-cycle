## External review of #260 (Mythos, 2026-10-14)

Verdict: NO-GO

I reviewed 78153b6 read-only: the pre-review, the full diff, the PR body, the twelve goldens and both test functions. I traced the Go scanner by hand against CPython 3.12's `tokenizer.c` (`tok_get_normal_mode`, `tok_get_fstring_mode`, the number scanner, `decode_str`, `check_coding_spec`), and confirmed the one candidate differential with this host's CPython 3.12.3 on literal strings. I ran no repo tests.

### High

**H1. A newline inside the format spec of a single-quoted f-string: CPython returns to code mode, `pyField` stays in spec mode. Code after it can be hidden from the guard.**
- **Where:** `internal/accept/integrity_py.go:277` (in spec mode every byte but `{` and `}` is skipped, newline included) and `:282` (the spec descent does not know the enclosing quote size; `:256` does not pass it).
- **Cause:** In `tok_get_fstring_mode`, when `f_string_quote_size == 1 && c == '\n'` and the scanner is in a format spec, CPython backs up the newline, emits the spec so far as `FSTRING_MIDDLE` and switches to `TOK_REGULAR_MODE`. From there the field is code until the matching `}`: comments, strings and brackets count. `pyField` in spec mode treats `#`, quotes and brackets as spec text and closes the field at the first `}`, even one inside what CPython reads as a comment. Triple-quoted f-strings are unaffected: there the newline stays spec text in both (checked: `f"""{x:d\n}"""` gives `FSTRING_MIDDLE 'd\n'`).
- **Input** (compiles under 3.12.3, and after `exec` the name `test_zero` is `None`):
  ```
  x = 1
  def test_zero():
      assert 1 == 2
  y = [f"{x:d
  #}"
  }"]; test_zero = None  # "
  ```
  CPython's tokens for line 4 onward: `y = [`, `FSTRING_START f"`, `{ x :`, `FSTRING_MIDDLE d`, `COMMENT #}"`, `}`, `FSTRING_END "`, `]`, `;`, `test_zero = None`, `COMMENT # "`.
  `pyTokens`' one logical line: `n:y o:= o:[ s:f"{x:d\n#}" o:} s:"]; test_zero = None  # "`. The rebinding is inside a string token. The `[`/`}` pair balances `depth` because bracket types are not matched (the review's L3), so nothing is refused.
- **Impact:** This is the H6 "uncollection with the name kept" bypass P14c-2 exists to catch, and it works on any statement that fits on the rest of the line (`pytest_plugins = ...`, a `hookimpl`, a `del`). The nested form `f"""{f"{x:d\n#}"\n}"}"""]; test_zero = None  # """` compiles too, so the rule is per enclosing string, not per outermost string.
- **Fix:** Pass the enclosing quote length into `pyField` (for example `single bool`, from `len(q) == 1` at `:256`, forwarded on both descents at `:274` and `:282`, and through `pyToken` for nested strings' own value). Then either:
  - fail closed, which I recommend: in spec mode `need(!(single && c == '\n'))`, a negligible D55 cost; or
  - mirror CPython: on `single && spec && c == '\n'`, set `spec = false` and continue, so the loop's `#`, string, bracket and `:` cases apply until `}` (a later top-level `:` re-enters spec mode in CPython too).

  Add the input above, `x = 1\ny = f"{x:d\n}"\n` and the nested triple/single form to `TestPyTokensRefuses`, and add a `{x:d\n}` body to the generated bodies at `integrity_py_test.go:266` so the differential covers single and triple quotes for all prefixes (triple must match, single must be refused). Add a mutation that removes the check.

  Note for P14c-2: the pre-review's L3 says CPython rejects "a quote or newline in a single-quoted spec". That is true of the quote, false of the newline.

### Medium

**M1. The corpus and the mutations have no newline inside a format spec.**
- **Where:** `integrity_py_test.go:264-277` (no body with `\n` in a spec; the only multi-line f-string cases are fields, not specs) and the 13 mutations (none flips spec-mode scanning of `#`, quotes or newlines).
- **Cause:** `pyField`'s spec mode is the one place where the scanner deliberately ignores quotes and comments, so it is the highest-value place for a differential, and it is untested beyond `{`/`}` nesting.
- **Fix:** The rows in H1, plus a mutation "spec mode respects nothing" (drop the `spec && c == '{'` case) to prove the nested-field rows discriminate.

### Low

**L1. A BOM hides a line-1 cookie from the gate.**
- **Where:** `integrity_py.go:76-79`. The BOM is stripped in `pyLex` (`:108`) but not before the cookie regex, so `\ufeff# coding: latin-1\n` is not refused. Benign: CPython raises "encoding problem: iso-8859-1 with BOM" (checked), and a BOM with a utf-8 cookie decodes the same in both. Strip the BOM in `pyCookie` too so the gate's reason stays accurate.

**L2. Every panic becomes "not tokenizable".**
- **Where:** `integrity_py.go:98-102`. The recover turns a runtime error (a future index bug) into a refusal, and a non-`error` panic value would make `r.(error)` panic inside the deferred function. Fail-closed, so not blocking; distinguish `errLex` and `ctx.Err()` from anything else, and at least log the latter.

**L3. The documented f-string nesting limit is off.**
- **Where:** `integrity_py.go:49` and the PR body ("f-string nesting past 65 levels"). Since the `:` descent now counts a level, a chain through specs is refused at about 32 levels. CPython refuses spec nesting far earlier, so there is no differential; fix the doc comment.

**L4. The linearity assertion may flake.**
- **Where:** `integrity_py_test.go:358`. 8× the 1 MiB time plus 250 ms on a loaded runner; consider measuring the ratio over the median of three runs, or widening the slack.

### Refuted or clean

- **H1 (pre-review) evasion:** none. Every path from a line start to its first token passes `need(s[i] != '\\')` at `:124`, after the full whitespace loop, so a backslash after spaces, tabs or a form feed, and a backslash on an otherwise blank line, are all refused. Inside brackets the start block is not entered, which matches CPython ignoring indentation at `level > 0`.
- **Numbers:** traced `pyNumber` against CPython's scanner and `verify_end_of_number` for `1if`, `1.0else`, `1e5and`, `0x1for`, `0xfor`, `1_000or`, `1jif`, `1.else`, `1.and`, `0else`, `0o7or`, `0x1_for`, `.5e1`, `1..real`. All agree. Every disagreement I found (`1_or`, `0b1_or`, `1e+and`, `1.real`, `0x1else`) is a CPython SyntaxError.
- **Strings and f-strings:** `\{`, `\}`, `{{`/`}}` in literal and spec, `\N{}` raw and non-raw and inside a spec (same end position), quote reuse, `=`, `!r`, `!=`, `:=` and `lambda` at the top level of a field (spec in both), comments in fields, `\`+newline in a field, triple-quote end counting, `''''`. The `\N{` scan to the next `}` is linear overall and its only mismatches are CPython decode errors.
- **Encoding gate:** the regex equals `get_coding_spec` (whitespace and form feed before `#`, case-sensitive `coding[:=]`, `[A-Za-z0-9_.-]+`, first non-empty name), lines split after CR and CRLF normalization as `translate_newlines` does, line 2 checked unconditionally, invalid UTF-8 and NUL refused before CPython would even look. `utf-8-sig`, `u8` and `latin-1` on line 2 after code are false blocks, not bypasses.
- **Bounds:** recursion is bounded at every entry (`pyString`, `pyField`, both descents), 3 frames per level, so about 200 frames at 4 MiB. Work is linear: each byte is consumed once by exactly one of the loops, comments and `\N{` jump forward and never rescan. A context check at every physical line end, inside brackets and continuations.
- **Line endings and whitespace:** CRLF, lone CR, BOM, tabs to multiples of 8, form feed resetting the column, U+2028 and U+0085 in strings and comments all match. U+2028, vertical tab and other controls outside strings are refused or are CPython errors.
- **Goldens and converter:** `golden()` is sound (character to byte columns, OPs split to bytes, f-strings folded, `ERRORTOKEN` and unknown types fatal). The differential's filter by `compile()` in the same process removes the liberal-mode risk the pre-review's M1 had.
- **Inertness:** confirmed. No production caller, and P14b's Python rule stays.
