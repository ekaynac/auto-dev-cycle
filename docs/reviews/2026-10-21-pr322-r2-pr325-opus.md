### #322 round 2: Low

**L1. Nothing tests that a later end retries a failed settlement.** `internal/daemon/egress.go:128`
- **Input:** the mutation `settled = err == nil` → `settled = true` survives. `TestEgressEndSettlesUnderACancelledContext` only covers a first end that succeeds.
- **Fix:** make the first settlement fail, for example through a settle hook or a runner already holding the call's lock. Assert that the first end returns the error and a second end settles the call.

**L2. Nothing tests the capture lock.** `internal/daemon/egress.go:79`, `internal/daemon/daemon.go:280`
- **Input:** removing the lock from `Keep` survives (L1a), and so does removing it from the purge loop (L1b).
- **Fix:** add a row that holds `d.capturing`, starts `captureOf(d).Keep` in a goroutine, and checks that it neither stores nor records until the lock is released.

**L3. `ErrToolRefused` hides `session.ErrUnverified`.** `internal/adapterhost/attempt.go:227`
- **Input:** an adapter reports a `run_command` result, and its PID namespace is not seen to empty. `out.Session` is then `ErrToolRefused` alone.
- **Why it matters:** a caller that skips cleanup on `errors.Is(out.Session, session.ErrUnverified)` would clean up a tree that may still be writing. The harness does exactly this (`internal/harness/harness.go:190`). The harness sets `AnyTool`, so it is safe today; 22a-5c's launch would not be.
- **Fix:** check `ErrUnverified` first, or return `errors.Join(fmt.Errorf("%w: %q", ErrToolRefused, t), waitErr)`.

**L4. A body that is never sent can now be recorded as a capture.** `internal/gateway/gateway.go:449-453`
- **Input:** a request waits on `d.capturing` while the purge holds it, and `Unbind` runs during that wait.
- **What happens:**
  - The lock wait ignores the context, so `Unbind` cannot cut it short.
  - Once the lock is free, `Keep` records the capture under `WithoutCancel`.
  - Then `g.live` refuses the request as `unbound`.
  - Before this round, the record would have failed and the request would have been refused `capture_failed`.
- **Effect:** the capture store holds an extra body, purged after 7 days. Nothing is lost.
- **Fix:** check `g.live(r, f)` just before `Keep`, or reword the schema's "sent" as "about to be sent". The purge holds the lock across one commit per expired capture and a walk of the whole capture store. Keep that bounded, or note it in the docs.

**L5. The settlement's bound equals the query's.** `internal/daemon/egress.go:90` vs `internal/modelcall/reconcile.go:46`
- **Input:** once 22a-5c configures `Queries`, a provider that takes the full `QueryDeadline` uses up `settleBound` too. The record that follows then fails.
- **Effect:** this is safe. The effect stays uncertain behind its fence, and only a later end settles it.
- **Fix:** set `settleBound = QueryDeadline + time.Minute`.

### #325: Low

**L6. `needs` checks only the consuming node's kind, not the kind of result the input takes.** `internal/daemon/wiring.go:93`
- **Input:** when 22a-6 adds review and repair, a round-2 build input that takes a `review` result gets no requirement and no refusal.
- **Effect:** none in this PR, because the template has no review. A missing requirement is also correct for receipts, since only gate and evidence results carry one.
- **Fix:** key `needs` on the pair (node kind, input result kind), as an allow-list: plan → none; build ← plan; accept ← patch; gate ← tree. Everything else refuses. 22a-6 then has to add review inputs explicitly.
