**High — H1. Case-variant JSON fields bypass the output floor.**  
Location: `internal/gateway/count.go:105`, `:168`, `:90`.

A hostile upstream can return this structure, replacing the placeholder with 1,600 ASCII content bytes:

```json
{
  "choices": [{"message": {"content": "<1600 bytes>"}}],
  "Choices": [],
  "usage": {"prompt_tokens": 300, "completion_tokens": 0}
}
```

Go’s struct decoder maps both spellings onto `reply.Choices`; the later empty array replaces the content-bearing array. This follows its documented case-insensitive matching and empty-array behavior. [Go JSON documentation](https://pkg.go.dev/encoding/json#Unmarshal).

The gateway therefore calculates zero content bytes and commits an observed count of `300/0`, superseding the request’s floor. The adapter’s JavaScript reads lowercase `res.choices` and receives the full content. A final of `300/0` settles despite violating the required 100-token output floor. The same ambiguity exists in nested content and tool-call fields.

**Concrete fix:** decode accounting fields using exact JSON names at every relevant level, rejecting ambiguous duplicate fields or retaining the floor when interpretation is uncertain. Adding lowercase struct tags alone does not disable case-insensitive matching. Add an integration fixture proving this response cannot settle at zero output, including a tool-arguments variant.

**High — H2. Skipped stream content does not prevent an observed count.**  
Location: `internal/gateway/count.go:151`, `:163`.

`tally.event` treats each physical `data:` line as an entire JSON event and silently ignores decoding failures. Valid SSE can contain multiple `data:` lines joined into one event. [SSE parsing specification](https://html.spec.whatwg.org/multipage/server-sent-events.html#event-stream-interpretation).

For example:

```text
data: {"choices":[
data: {"delta":{"content":"<1600 bytes>"}}]}

data: {"usage":{"prompt_tokens":300,"completion_tokens":0}}

data: [DONE]

```

Neither content line individually decodes, so both disappear from the tally. The later usage frame succeeds. `result` returns success, and `count` commits `Observed: true`, `Out: 0`. A matching adapter final settles the call below the content floor. An ordinary single-line content event containing an incompatible typed field also gets silently discarded without invalidating subsequent usage.

**Concrete fix:** assemble bounded SSE events before decoding, support the permitted line endings, and retain a permanent “accounting incomplete” flag when any relevant event cannot be interpreted. A later usage event must not clear that flag. Keep the durable floor on incomplete accounting. Add multiline and malformed-content-then-valid-usage fixtures through the real Recorder and settlement path.

**Medium — M1. The matcher still misses complete JSON spellings of some accepted credentials.**  
Location: `internal/gateway/gateway.go:277`.

For a credential containing one literal backslash, such as `abc\def0123456789`, the JSON spelling `"abc\u005cdef0123456789"` leaks. When matching the backslash, `unit` takes the raw-byte branch before examining `\u005c`; the following credential byte then mismatches. Conversely, greedily consuming `\\` as one byte misses some raw credentials containing consecutive backslashes.

The byte-oriented matcher also does not recognize Unicode escapes representing non-ASCII credential runes. No credential admission check currently restricts the alphabet.

**Concrete fix:** preserve both raw and escaped matching possibilities where backslashes are ambiguous. Either support Unicode scalar spellings or explicitly reject unsupported credential characters before injection. Extend `TestEveryJSONSpellingIsRedacted` with backslashes, consecutive backslashes and the chosen Unicode policy, using whole-buffer and single-byte writes.
