## External review of #411, A-pre (Astra, 2026-10-23)
Verdict: NO-GO

1. **High — A settlement fault can block every reconcile pass and shutdown.** `internal/daemon/egress.go:275`

   **Concrete input:** a live unbound effect, as exercised by this PR’s fault row, while adcd’s stderr is a full pipe whose reader has stopped consuming. A failed effect write for an ended call reaches the same path.

   `settleOne` holds `e.mu` while `logf` synchronously writes to the sink at line 287. Production supplies `os.Stderr` directly. The next pass blocks acquiring that mutex in `Settle` at line 176, before checking whether settlement already runs. Neither context cancellation nor `settleBound` interrupts the write or mutex acquisition. Shutdown consequently waits indefinitely on `<-reconciled` or `eg.wait()` (`internal/daemon/daemon.go:300`). Listing-fault logging at `egress.go:219` has the same problem.

   This violates the promised nonblocking pass and bounded settlement behavior. Main has other synchronous logging, but this adds a path from a settlement-only fault to stopping otherwise healthy passes.

   **Fix:** commit retry/deduplication state and release `e.mu` before logging. Give the driver bounded, cancellation-aware log delivery so its worker and shutdown never await a blocked sink. Moving the write outside the mutex alone fixes the pass obstruction, but leaves shutdown blocked.

2. **Medium — The retry-state and cause-deduplication rule is implemented twice.** `internal/daemon/egress.go:281`

   **Concrete input:** successive failed tries with the same cause, including errors containing newly minted IDs. This block independently increments tries, computes the next deadline, redacts IDs, compares the previous cause, and decides whether to log—the existing rule in `internal/daemon/sweep.go:296`.

   Sharing `endRetry` and `retryAfter` preserves the delay formula, but leaves the state-update and logging rule duplicated. `egress.logf` also copies `runner.logf`. I found no current incorrect delay calculation; this is Medium under the requested reuse rule.

   **Fix:** extract the retry-state update and “cause changed” decision into one helper used by both callers, with logging performed outside their state locks.
