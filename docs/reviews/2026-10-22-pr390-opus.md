Verdict: GO. Nothing is Critical or High. The two Medium and four Low findings below are obligations for the next PR in the chunk.

The fix removes the 2.5 h hang. Skipping the emulated platform's Node start lets no skew through, because that Node's bytes are still pinned from end to end. The gaps are in how much the rows prove (M2) and in a failed run leaving a list the lead's push command would publish (M1).

### Medium: OBLIGATION

**M1. A run that fails or is cut after the build leaves NAME in podman's storage, and the header's next command pushes it.** `scripts/prepare-go-image.sh:249-290`
- **Input:** any check after the build fails or is cut: `pod manifest inspect`, the native Node run, or `pod create`, `cp`, `rm`, or the copied-out digest. The script exits 1, but the list `NAME` stays in podman's storage, with checks not done or failed.
- **Effect:** the header lists `podman manifest push --all … NAME` as the next step, with no `&&` chaining. A lead who pastes the block publishes the list, and `--digestfile` records it as the pin.
- **A later build is not affected:** the `exists` check refuses the name.
- **Pre-existing:** a failed check left the list before this PR too. This PR adds new ways to fail after the build (the cuts).
- **Fix:**
  - After the build, set a trap so that any failure runs `pod manifest rm "$name"` (bounded) and says so.
  - Or print "do not push NAME" on failure and chain the header's commands with `&&`.

**M2. The rows prove the bound only for `podman run`.** `cmd/adc/adapter_test.go:273`
- **Mutants that survive `TestPrepareBuild`:**
  - P1–P5: each of `create`, `cp`, `rm "$c"`, `manifest inspect` and the two `exists` calls switched from `pod` back to bare `podman`.
  - K1: `--kill-after=10` dropped. The fake's `sleep` dies on SIGTERM, so the kill path is never used.
  - K2: rc 137 not reported.
  - V1: `PREPARE_GO_IMAGE_TIMEOUT` not validated.
- **Fix:**
  - Let the fake hang on any subcommand named in `STATE/hang` (`exists`, `inspect`, `create`, `cp`, `rm`), and expect "did not finish within" and a failed build for each.
  - Add a hang that traps TERM (`trap "" TERM; sleep …`) to pin `--kill-after` and rc 137.
  - Add a row that sets `PREPARE_GO_IMAGE_TIMEOUT=abc` and expects a refusal before podman runs.

### Low: OBLIGATION

**L1. A hang mutant hangs the test until `go test -timeout`, and leaves its processes behind.**
- **Observed:** two orphaned `bash prepare-go-image.sh build …` + `sleep 100000` pairs, about 20 and 27 minutes old, from another worktree's `cmd/adc` test run with `PREPARE_GO_IMAGE_TIMEOUT=1`, consistent with a hang mutant's run. Their cwd is `wt-pit/cmd/adc`, not this review. I left them alone; they need cleaning up.
- **Fix:**
  - Run `build` with `exec.CommandContext` (a deadline of about 30 s), `Setpgid`, and a `Cancel` that kills the process group.
  - Make the fake's hang `sleep 60`, not `100000`.

**L2. A cut `pod create`, or a failed `pod rm "$c"`, leaves an unnamed container.** `scripts/prepare-go-image.sh:277,280`
- **Effect:** the container is only created, never started, and a later build or push does not use it. But it holds the image, so `podman rmi` on it fails.
- **Fix:** name it (`--name=adc-prepare-$$-create-ARCH`) and `rm --force --ignore` it by name on any failure, as the run path does.

**L3. The native platform is the kernel's (`uname -m`), not podman's.** `scripts/prepare-go-image.sh:121,226`
- **Remote podman:** with `CONTAINER_HOST`, `podman --remote`, or a podman machine of another architecture, the native image is skipped and the emulated one is run. That run is now bounded and fails closed, so the cost is time only.
- **Native platform not in `PLATFORMS`:** for example `build … linux/amd64` on an arm64 host. No Node start is checked at all; only the skip is printed.
- **Fix:** take the native platform from `podman info --format '{{.Host.OS}}/{{.Host.Arch}}'` (bounded). Then either refuse a `PLATFORMS` without it, or print that no start was checked.

**L4. A container killed by SIGKILL is reported as a cut.** `scripts/prepare-go-image.sh:90`
- **Cause:** `podman run` returns 128+9 = 137 when Node itself is SIGKILLed (by the OOM killer, say). `pod` then prints "did not finish within 300s".
- **Effect:** it still fails closed; only the message is wrong.
- **Fix:** distinguish the cases by elapsed time, or word the message "was cut or killed".

### The four questions
1. **Can a skew pass now the emulated start is skipped?** No.
   - **The bytes:** the emulated platform's `node/bin/node` is checked against `node-pins` field 5 in the context. The label's digest for that platform is computed over the context (`context`), and the `/opt/adc/lib` copied out of its image must equal it. So the image holds the pinned Node, byte for byte. The version (field 2) comes from the same pins line, so it follows.
   - **What is lost:** proof that Node starts on that platform's libc and CPU. The base image is pinned by digest, and bookworm's glibc 2.36 meets Node 22's floor [INFERENCE]. 5d-3's live row on that architecture would catch a start failure.
2. **Can a cut call leave a container or a partial list that a later build or push uses?**
   - **A later build:** no. The `exists` checks refuse an existing name.
   - **A later push:** yes (M1).
   - **Containers:** a cut run's named container is removed with `--force --time=0`. A cut or failed `create`/`rm` leaves an unnamed created container that nothing uses (L2).
3. **Is the native platform detected correctly on both arm64 and amd64 hosts?** Yes on a local podman: `x86_64` → amd64, and `aarch64` or `arm64` → arm64. Both hosts have rows. Remote podman and a `PLATFORMS` without the native platform are the edges (L3).
4. **Do the fake-podman rows prove it?** They prove three things:
   - the native-only run on both hosts;
   - the skip message;
   - the cut and removal of a hung run.

   They do not prove the bound on the other five calls, the kill-after path, or the validation of the timeout value (M2).
