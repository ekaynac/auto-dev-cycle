## Opus review of #373 (2026-10-22)

Verdict: GO with changes

The digest, the check and the context assembly do what the PR says. The one finding that matters is in the lead's rebuild commands (M1): run as written on the lead's host, they would put the old images back into the new pins. It fails closed, but it needs a two-line fix in the script before the commands are run.

**Checks run**, in a `/tmp` copy without `.git` and with `TMPDIR` unset (deleted afterwards). No image was built.
- `go test -count=1 -race` passed on `internal/sandbox`, `internal/cli`, `internal/profile` and `internal/gate`, plus `cmd/adc`'s `TestDevAdapterDigest` and `TestPrepareContext`.
- **Probes on `AdapterDigest`:** a link inside the closure that points outside it is accepted. When the target's bytes change, the digest stays the same (L1).
- **Probes on the label:**
  - A duplicate key inside `adapter` is accepted; the last value wins.
  - A second `Adapter` key in another case overrides the first.
  - Two `adapter` objects are merged into one map.
  - A `null` value is refused, and so is a missing platform.
- **Read-only look at the local podman storage:** `podman manifest exists` is true for both `ghcr.io/ekaynac/adc-prepared-go-mini` and `ghcr.io/ekaynac/adc-prepared-go`. Each list already holds an amd64 and an arm64 image.

### Medium

**M1. As written, the rebuild adds the new images to the old lists.** `scripts/prepare-go-image.sh:179`
- **Cause:** `podman build --manifest NAME` adds to the list if one with that name exists, and creates one only if it does not. Both lists exist locally today, from the current pins.
- **Input:** the lead runs the header's commands on this host.
- **What happens:**
  - Each list ends up with four entries: the old arm64 and amd64 images first, then the new ones.
  - `push --all` publishes all four, and `--digestfile` records that index as the pin.
  - A pull by platform can pick the old image, which has no `adapter`. `CheckAdapter` then refuses every launch.
  - The gate still passes, because the old image keeps a valid lockfile label.
- **Fix:**
  - In `build`, refuse when `podman manifest exists "$name"` or `podman image exists "$name"` is true, and say to run `podman manifest rm NAME` first. Or remove the list explicitly.
  - After the build, check that `podman manifest inspect "$name"` lists exactly one entry for each platform in `PLATFORMS`.
  - Put `podman manifest rm` (or the check) in the header's commands.

### Low

**L1. A link may point outside the closure, and its target's bytes are not digested.** `internal/sandbox/adapter.go:93`
- **Input:** `node_modules/ajv -> ../adapters/fake`, or an absolute target such as `/etc`. `AdapterDigest` accepts both, and changing the target's bytes leaves the digest unchanged.
- **Today:** `dist-adapters.sh` allows only the two `@adc` links, so no dist has such a link.
- **Fix:** refuse any absolute target, and any target whose lexical resolution (`path.Join(path.Dir(p), target)`) falls outside the closure's paths. "The digest covers everything the adapter runs" is then true by construction.

**L2. Duplicate or case-folded keys in the label are not refused.** `internal/sandbox/image.go:93`
- **Cause:** Go's `json.Unmarshal` lets the last duplicate win, matches field names regardless of case, and merges repeated objects into one map (probes above).
- **Exposure:** the label is ours, and the image is pinned by digest, so this is defence in depth only.
- **Fix:** decode the label strictly (`contract.Decode`, or a decoder that refuses duplicate keys), or validate it against a small schema before `CheckManifest` and `CheckAdapter`.

**L3. An adapter refusal reports the wrong cause.** `internal/sandbox/image.go:35`
- `CheckAdapter` wraps `ErrManifest`, whose text is "does not match the pinned toolchain and the base's lockfiles". An adapter mismatch therefore reads as a lockfile mismatch.
- **Fix:** add "or the adapter" to the fixed text, or give the adapter its own sentinel that wraps `ErrManifest`.

**L4. The Node binary is checked only against the dist's own sums.** `scripts/prepare-go-image.sh:114`
- `SHA256SUMS` is written by the same `make dist`, so this check only shows the dist was not changed afterwards.
- **Fix:** also compare `node/bin/node` with field 5 of `scripts/node-pins` for the platform. This is cheap, and the image then holds the pinned Node by its own pin.

**L5. No test covers `build`'s gates.**
- `TestPrepareContext` exercises only `context`. A mutation that removes the clean-checkout check, or the `(commit HEAD,` / `-dirty` check, would survive.
- **Fix:** run `build` against a fake `podman` on `PATH` (and a fake checkout). Assert that a dirty tree and a mismatched `adc version` are refused before `podman` is called.

**L6. Nothing shows Node starts inside the image.**
- The hand run used the host. The bookworm base has glibc 2.36 and libstdc++ (apt depends on it), so it should work.
- **Fix:** after the build, run `/opt/adc/lib/node/bin/node --version` once per platform, or leave this to 5d-3's live row and say so in the PR.

### The five questions
1. **Is the digest over everything the adapter runs?**
   - **What it covers:** the bytes of Node and their execute bit, the http-chat adapter, the contract package, `gen/ts`, and the whole production `node_modules` (`ajv` and its dependencies, plus the two `@adc` links by target).
   - **The lockfile:** it is not hashed, but the installed bytes it produced are, which is the stronger pin.
   - **Module resolution stays inside the closure:** the nearest `package.json` of each source file is inside the closure (`lib/adc` has no root `package.json`), and Node 22.23.3 strips types by default.
   - **Outside the digest:** the base image's libc and libstdc++, pinned by the image's own digest.
   - **Can a skew pass?** Only through L1's out-of-closure link, which no dist contains today.
2. **Does `CheckAdapter` fail closed?**
   - A missing label, a missing entry for the image's own platform (another platform's only, or a key with an `/v8` variant), a `null` value, a different digest, and a `want` that is not a `sha256:` digest are all refused.
   - A malformed label is refused at `Resolve`.
   - Duplicates are not refused (L2).
3. **Is the recipe reproducible?**
   - The base is pinned by its index digest.
   - The new layer is a `COPY` from the build context: no network.
   - `--timestamp=0`, and the dist's modes are normalised.
   - The only network step is the existing `go mod download`, verified against `go.sum`.
   - Directories the script creates take the umask's mode. Only the layer bytes can differ; the adapter digest cannot.
4. **Are the commands correct?**
   - `podman manifest push --all … --digestfile FILE` writes the digest of the index covering both platforms, which is the right pin.
   - The header gives `--digestfile` only as a note; it should be spelled out in both push lines.
   - M1 must be fixed before they are run.
5. **Any regression for today's gate?** None. `CheckManifest` is unchanged. A label without `adapter` parses (`omitempty`). `internal/gate` and `internal/profile`, whose rows use the old pins, pass.
