### Medium

**M1. A capture whose record fails is never purged, so the 7-day limit (P7D) does not hold.** `internal/gateway/capture.go:53-57`
- **Cause:** `Keep` stores the bytes with `Put` first. It then calls `Record` with the request's context, which `Unbind` cancels. A crash between the two steps has the same result.
- **Input:** an attempt ends, or adcd crashes, while a request is in `Keep`. This is probe 2: the bytes stay in `<state>/captures` with no `blob.capture_kept` record. `PurgeCaptures` (`internal/api/captures.go:121`) only reads the projection, so those restricted bytes are kept forever.
- **Fix:**
  - Record with `context.WithoutCancel(ctx)`.
  - Have `PurgeCaptures` also remove any blob in the capture store that no kept capture names and that is older than a grace period. The capture store is a store of its own, so such a sweep is safe.
  - Add a row: Keep with a cancelled context, then the purge leaves no bytes.

**M2. The end remembers a failed settlement and never retries it.** `internal/daemon/egress.go:92-96`
- **Input:** 22a-5c calls `end(runCtx)` after `runCtx` is cancelled, for example on a stop or shutdown. This is probe 3.
- **What happens:** `Unbind` and the socket close still run. But `settle` fails on `View(ctx)`, and `once` keeps that error for good, so `Reconciler.Ended` never runs for an intended call. Its effect stays `pending` until the next restart, and `Reconcile` leaves pending effects alone.
- **Fix:**
  - Settle under `context.WithoutCancel(ctx)` with a bounded timeout.
  - Or keep only `Unbind` and the close inside `once`, and retry `settle` on later calls until it succeeds.
  - Add a row: end with a cancelled context on an intended call, then a second end settles it.

### Low

**L1. A purge can remove bytes that a capture kept a moment earlier still needs.** `internal/api/captures.go:121-150`
- **Cause:** the purge decides which digests are still live (`live`) from an earlier `View`. `Keep` takes no lock against it, and `Put` skips the write when the digest is already present.
- **Input:** an exit run sends the same body again (a fixed first prompt) about 7 days later, while the purge loop runs. The new capture's record points at bytes that are already gone.
- **Fix:** take one mutex in both `captureOf`'s Keep and `PurgeCaptures`, around the liveness read and `Remove`.

**L2. Entry 65 is checked only when the adapter describes its tools.** `internal/adapterhost/attempt.go:375`
- **Input:** an adapter describes `read_file`, then emits `tool.result{tool:"run_command", mediated_by_controller:false}`. `onEvent` accepts it.

- **Fix:** name P24's driver in the I10 row as the owner that scans `<state>/captures` before the exit record. Optionally, refuse the body using the redaction's `spell` matcher.

### Answers to the five questions

1. **Session end:**
   - **Order:** the end runs `Unbind`, then the socket close (the socket file is removed), then the settlement, once. A cancelled context still unbinds and closes (probe 3); only the settlement is lost (M2).
   - **Crash or restart:** bindings are only in memory, so a restart drops every token. The pending effect is then handled by `MarkPendingUncertain` at start.
   - **Panic:** this depends on 22a-5c deferring the end. Nothing in this PR calls it, so 22a-5c needs that row.
   - **Can a token outlive its attempt?** It can stay in memory if no one calls the end, but it cannot send anything. Every request rechecks that the lease is active and its attempt running.
   - **Undercount (#226 entry 69):** no. `<-served` does not wait for handlers to return, so a count can commit after `Ended`. But a floor is refused once the effect has left `pending` (`modelcall.sends`, `internal/modelcall/modelcall.go:439-447`), so such a request is never sent. Late counts only raise the standing.
2. **Captures:**
   - The body is captured before injection, which touches only headers.
   - A body holding the raw credential is refused before it is captured.
   - The secrets scan is not wired (L3).
   - Captures are on only with the flag (L5).
   - **Restricted:** the capture store is separate, and no route serves it. The read API's resources do not include captures, and the board does not either.
   - **`/v1/events`** carries only digest, lease, attempt, call, class and expiry, never the body.
   - The TTL is 7 days (P7D).
   - **Purge:** bytes are removed before the event, a crash in between replays under the same key, and bytes another capture still holds are kept. The exceptions are M1 and L1.
3. **Entry 65:**
   - At `f656b87` it fails closed: nil refuses every tool, and only the harness and fixtures set `AnyTool`.
   - The refusal comes before `Prepare`, and the attempt ends `lost`.
   - It is checked only at describe time, not on each tool call (L2).
   - The adapter cannot describe a tool later, because `describe` is called once per session.
4. **System principal:**
   - The Recorder's intent and count and the Reconciler's reconciliation all carry `Principal`, and all are in `systemActions`, so they go through `authorizeSystem`.
   - Probe 1 confirms this for the Recorder.
   - The capture actions are exercised by the PR's own tests.
   - The Reconciler's single command was not exercised. Its code path is the same as the Recorder's.
5. **Regressions:** none found against #320. All 10 mutations were caught. The race runs pass, apart from the host-caused `TestSandboxConfig` failure above.
