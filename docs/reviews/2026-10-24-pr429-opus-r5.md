### 2. Is the std rule a proof? Not quite: C1
- **For go.mod files at `go 1.17` and later, yes.** Go's rule is that with `-mod=readonly`, a dot-free import resolves from GOROOT unless a module in the build list provides it. Such a module can only enter the build list through the main module's go.mod (the go command refuses to download a dot-free path), and from go 1.17 it must also be listed in `require`. A path that is not `require`d and is dot-free is therefore std or does not build. For std, the name is the last element (or the one before a vN), as the GOROOT scan shows.
- **For go.mod files at `go 1.16` and earlier, no.** A module needed only by a dependency may be absent from `require` and present only in a main-module `replace`. The code reads replacements for exactly this reason (`goModules`, `internal/gate/acceptance.go:408-421`). It reads them through `modfile.ParseLax` (`:409`), which by design keeps only `module`, `go`, `require` and `retract`. A probe confirms it: `ParseLax` gives 0 replaces where `modfile.Parse` gives 2, and `goModules` returns `[m dep]`.

### BLOCKING

**C1. The gate refuses an acceptance that go runs: a `replace`-only module path is read as std.**
- **Input:**
  - the base's go.mod: `go 1.16`, `require dep v0.0.0`, `replace dep => ./third/dep`, `replace foo => ./third/foo`;
  - `dep` imports `foo/bar`, whose package is `baz`;
  - the base package `p` declares `var bar`;
  - the acceptance `p/h_test.go` imports `"foo/bar"` and uses `baz.X`.
- **What go does:** `go test ./...` runs `TestHidden`.
- **What the gate does:** `goModules` drops the `replace`, so `std("foo/bar")` holds. `importNames` then counts `bar`, and `AcceptanceFits` refuses (`errRedeclared`).
- **Why it is narrow but blocking:** it needs a pre-1.17 go.mod, a dot-free `replace`d module, and a package named unlike its path. Under the boundary, a refusal of an acceptance go runs still blocks. The code also claims a reading it does not do.
- **Fix:** in `goModules`, use `modfile.Parse`, which keeps `replace`. A go.mod that strict parsing rejects then gives `nil` modules, so no import is counted: the safe direction. Add the probe above as an `AcceptanceFits` row.
