**High H1 — Assignment parsing discards a lambda and its executable default.**

Location: `internal/accept/integrity_pyimport.go:249`; truncation at `internal/accept/integrity_pyimport.go:416`.

```python
# conftest.py — unchanged
import cfg
import feature.flags

PARK = 0, lambda x=[0 for feature.flags.SKIP in [cfg.SKIP]]: 0
```

`pyAssign` truncates the statement immediately before `lambda`. Consequently, `pyStmt` checks only `PARK = 0,`, whose value passes as an inert tuple with a trailing comma. Main’s `pyConst` accepts the complete statement: the comprehension contains no prohibited call. The write recognizer likewise sees only `PARK`.

Python evaluates the lambda’s default while constructing the function. That comprehension writes `cfg.SKIP` onto `feature.flags.SKIP` during import. Neither closure rejects the conftest, and the test’s condition changes silently. [Python expression semantics](https://docs.python.org/3.12/reference/expressions.html#lambdas)

This directly defeats the positive grammar: both a lambda and a comprehension are accepted despite being expressly excluded.

**Fix:** reject `lambda` before using this splitter, or use assignment parsing that preserves the entire RHS and requires complete consumption. Cover trailing-comma prefixes and lambda defaults containing list, set and dict comprehensions.

**High H3 — Class-private imports follow the wrong module name.**

Location: `internal/accept/integrity_pyshadow.go:337`.

```python

    import __writer

# __writer.py — decoy
X = 1

# _C__writer.py — actual imported module
import cfg
import feature.flags
feature.flags.SKIP = cfg.SKIP
```

The class and import pass the grammar. `__writer` does not end in `__`, so the dunder-binding rejection does not apply. Import collection records the literal `__writer`, and both closures inspect only the decoy.

Python mangles this private module name inside class `C` to `_C__writer`. The actual writer therefore executes outside the modeled closure. Private names in `from … import` statements also require this handling. [Python private-name mangling](https://docs.python.org/3.12/reference/expressions.html#private-name-mangling)

**Fix:** reject imports requiring class-private mangling, or retain class scope and apply Python’s transformation before recording module and member names.

**Fix:** require a resolved inert provenance for every dotted decorator argument, including intermediate attributes and re-exports. Reject external or unresolved attribute chains unless separately proved safe.

**Medium M2 — Named Unicode escapes can import code while compiling an “inert” string.**

Location: `internal/accept/integrity_pyimport.go:268`.

Its module body executes before capsule validation; the Go tokenizer and closure record no such import. This also applies to strings inside otherwise ignored function or `__main__` bodies, because compilation precedes execution. [CPython escape decoding](https://github.com/python/cpython/blob/v3.12.0/Objects/unicodeobject.c#L5607), [capsule import](https://github.com/python/cpython/blob/v3.12.0/Objects/capsule.c#L205)

This is initialization-dependent; the minimal shadow above subsequently fails capsule validation, so I am **not** claiming a successful pytest bypass from this example alone. It nevertheless disproves unconditional string inertness.

**Fix:** conservatively reject potentially active named Unicode escapes throughout reached source, or explicitly model and constrain their implicit import.
