# PR #90 (concurrent conflicting approvals fixture): Astra reviews

## Review of #90 (Astra, 2026-10-05)

Verdict: GO with changes

No Critical/High findings. The following are nonblocking.

- **Low — Fixture setup uses an inconsistent confirmation policy.** `internal/fixtures/approvals.go:195` pairs `policy.widen_destinations` with `IndependentReview`, although D32 requires human confirmation for supervisors. Constructing `authority.Decision` directly bypasses that selection. This does not invalidate the concurrency proof, but makes its example unrealistic. **Fix:** use an action/class that legitimately requires independent review, such as `install.self`, ideally obtaining its decision through `authority.Decide`.

- **Low — Expiry is a cheap missing boundary case.** `internal/fixtures/approvals.go:118` exercises rejection only; confirmation always uses a time before expiry. **Fix:** add a confirm-versus-expiry variant using `authority.Close(...Expired)`, and a deterministic confirmation at `ExpiresAt` asserting `proposal_expired` and unchanged projection/head. Stale binding coverage is less urgent: `unrelated-go-reuse` and `TestConfirmByReview` already exercise it.

The principal contract is sound:

- **Real concurrency:** eight goroutines call the actual `Store.Submit`, following the existing `TestConcurrentConflictingCommands` pattern. Proposal reads, authority decisions, event append and projection updates occur inside the writer transaction. A start barrier could strengthen contention, but this is not sequential submission.
- **Deterministic assertions:** the winner’s identity may vary; sorting the outcomes makes the golden independent of scheduling. Exact golden comparison requires one success and seven stale refusals. The projection must match the winning command, and the final head must remain at 2. Multiple successes cannot silently pass despite `winner` retaining only the last successful index.
- **Both enforcement layers:** version-1 losers establish writer expected-state enforcement. Direct confirmation of the closed proposal and fresh version-2 confirm/reject commands independently establish authority’s non-open refusal.
- **Realistic mutation, correct red:** removing the status guard models trusting expected state alone. I observed both subsequent confirmations succeed, the late rejection become stale, and head advance to 3. Failure is the intended contract violation, not a setup error.
- **Honest scope:** the [PR description](https://github.com/ekaynac/auto-dev-cycle/pull/90), runner comment and golden accurately disclose the missing production command path. The allow-all authorizer is acceptable for this focused composition test because real confirmation/close validators still execute transactionally. It provides no evidence about supervisor grants, operator authorization, or production command wiring; the fixture should migrate when that path exists.

Both requested test commands passed under Go 1.27.1 with `GOTOOLCHAIN=local`, through `scripts/test-sandbox.sh`. The race run required `CGO_ENABLED=1` inside the sandbox. Normal and mutated fixture JSON confirmed the results above. No source files changed; the working tree remains clean.

### Lead notes on round 1 (applied)

- Finding 1 (inconsistent confirmation policy): the proposals are now what `authority.Decide` makes of a supervisor's `knowledge.change_protected_document` change under a grant for it on project A (the action is itself a class whose default is `independent_review`, D32/K5); the fixture refuses to run unless Decide proposes it for an independent review, and `NewProposal` records Decide's own decision (classes and grant). The golden gains that step: `[empty/completed_clean, failed/stale_expected_state ×7, failed/proposal_not_open ×3, failed/proposal_expired]`. `authority.confirm-ignores-status` stays red (the direct and late confirmations of the closed proposal apply; the expiry step is unaffected, since that proposal is open).
