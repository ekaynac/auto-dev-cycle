# PR #24 (vocabulary check): Astra reviews

## Review of #24 (Astra, 2026-10-04)

Verdict: NO-GO

### High

1. **Unregistered reasons bypass the check through generics and conversions.** `internal/vocab/check.go:169`

   The scanner requires a constant string expression whose concrete type is `vocab.Reason`. This misses:
   ```go
   func bad[T ~string]() T { return "typo_generic" }
   r := vocab.Result{Reason: bad[vocab.Reason]()}
   ```
   It also misses `vocab.Reason([]byte("typo_bytes"))`, pointer conversions, and literals assigned inside generic methods—even when those methods are invoked through method values.

   **Reproduced:** the checker returned exit 0 with zero findings, and a program using the actual repository types serialized the unregistered reasons without calling `Registry.Check`. The documented dynamic-string exception does not enforce its claimed runtime fallback.

   **Fix:** cover generic reason-producing expressions and require validation at the result-emission boundary for paths the scanner cannot establish statically. Add regression tests that demonstrate both rejection and prevention of unchecked emission.

2. **Existing contract reason fields are excluded.** `internal/vocab/check.go:77`, `internal/vocab/check.go:185`

   `types.Receipt.Reason` and `types.Predicate.Reason` use `ReasonCode`, an alias for `string`. Consequently, ordinary handwritten code such as `types.Predicate{Reason: "typo_field"}` passes. This is a literal in an actual result field, not merely a dynamic-input limitation.

   **Reproduced:** zero findings and successful serialization of `"reason":"typo_field"` using the real generated `Predicate` type.

   **Fix:** recognize the schema-defined reason fields in literals and assignments, or generate a distinguishable semantic reason type that the checker recognizes. Require runtime vocabulary validation when emitting these records. Add tests using the actual generated types; the synthetic `Result` alone cannot prove this coverage.

3. **A package type-check failure can pass.** `internal/vocab/check.go:99`

   Directory exclusion happens before collecting `pkg.Errors`. Additionally, the checker ignores `pkg.IllTyped`, which can reflect dependency failures.

   **Reproduced:** `gen/bad/bad.go` containing `var X int = "s"` yielded exit 0 and zero findings, including when a scanned package imported it and referenced `bad.X`. This directly contradicts “fails, never passes” on type-check failure.

   **Fix:** validate package-loading/type-checking completeness before applying source-scanning exclusions. Reject ill-typed packages and missing required type information; inspect dependency errors as necessary. Add excluded-package and imported-dependency failure tests expecting exit 2.

### Medium

4. **Generated constants bypass deprecation checks.** `internal/vocab/check.go:177`, `tools/vocabgen/main.go:45`

   Generation includes deprecated entries, and using a generated name skips registry inspection entirely. After marking `stale_attempt` deprecated in a loaded registry, `CheckSource` still accepted its generated constant in a result; `Registry.Check` correctly rejected the same result.

   No currently registered reason is deprecated, so this is a lifecycle gap rather than a current bad value.

   **Fix:** preserve historical constants for readers, but enforce non-deprecation for writers through mandatory emission validation and appropriate source checks. Test a deprecated generated constant at a write site.

5. **Load failures produce no JSON under `--json`.** `internal/entry/entry.go:86`, `internal/entry/entry.go:92`

   Registry/module failures return exit 2 with stderr text and empty stdout. A nonexistent `--root` reproduces this. Note 08 specifies one JSON document on stdout in JSON mode.

   **Fix:** produce a structured `could_not_run` error document when JSON mode is selected, retaining diagnostics on stderr. Add CLI tests for module and registry failures, checking exit code and both output streams.

6. **Text output failures can report success.** `internal/entry/entry.go:106`

   Both text-output writes ignore errors. With stdout directed to `/dev/full`, a clean check returned 0; JSON mode correctly returned 2.

   **Fix:** propagate text-write failures as `ExitCouldNotRun`. Test with a failing `io.Writer`.

### Low

7. **The “cover the registry exactly” test does not establish exact coverage.** `internal/vocab/check_test.go:207`

   It checks two reason values, one hold value, and membership of one additional reason. It never compares complete generated and registry sets. `gen-check` verifies regeneration consistency, but is not an independent completeness assertion.

   **Fix:** compare all generated reason/hold names and values against the registries, including missing and extra entries. Correct the PR’s test claim until then.

The focused vocabulary and CLI tests pass, and I reproduced the repository’s **33 reasons, 14 holds, zero findings** report. Direct untyped constants assigned to `Reason`, ordinary struct fields of that type, and arguments passed through instantiated method values were caught. The existing tests do not cover the blocking counterexamples above.

Excluding test files is reasonable for deliberately malformed fixtures. Deferring TS checking is acceptable while there is no **product** TS emitter; “no TS code exists” should be qualified because fixtures and research TS exist. Hold checking can likewise be deferred for this incremental M0 step while no hold-emitting path exists, but this does **not** complete note 02’s hold rule: the first emitter must bring build-time checking, runtime validation, and startup enforcement. The reported hold count establishes registry loading, not hold-source enforcement.
## Second review of #24 (Astra, 2026-10-04)

Verdict: NO-GO

- **First #1 — High, generics/conversions:** Partially resolved. Generic instantiations are caught and contract validation rejects unregistered reasons, but unchecked result serialization remains possible.
- **First #2 — High, contract reason fields:** Partially resolved. Direct literals and contract encode/decode are covered; typed string constants and conversions still escape the scanner.
- **First #3 — High, type-check failures:** Resolved. Errors are checked before exclusions; ill-typed packages fail.
- **First #4 — Medium, deprecated constants:** Partially resolved. Static detection works, but contract encoding still permits deprecated reasons.
- **First #5 — Medium, JSON `could_not_run`:** Resolved.
- **First #6 — Medium, text write errors:** Resolved.
- **First #7 — Low, exhaustive constants test:** Resolved.

Independent verification: `make ci` passed locally, reporting **34 reasons, 14 holds, zero findings**; shellcheck was unavailable and skipped. Review probes ran in isolated sandbox copies. No tracked files changed.

The installation mechanism fails closed through `contract.Validate`, `Decode`, and `Encode`: removing the callback rejects both receipt-level and nested predicate reasons. Registry loading avoids recursive reason validation because registry entries use their separate `Code` definition.

Remaining and new findings, ordered by severity:

1. **High — The emission boundary remains optional for results.**  
   `internal/vocab/vocab.go:157`, `internal/entry/entry.go:92`, `internal/vocab/boundary_test.go:57`

   This still passes `adc dev vocab check` with zero findings and serializes successfully:

   ```go
   r := vocab.Result{
       Outcome: vocab.Failed,
       Reason:  vocab.Reason([]byte("typo_bytes")),
       Detail:  "probe",
   }
   b, err := json.Marshal(r)
   ```

   The output contains `"reason":"typo_bytes"` with no error. `Result` has neither automatic emission validation nor a contract schema that connects it to `adc-reason`. The CLI itself writes `Result` through `json.NewEncoder` without `Registry.Check`; its current constant is valid, but the claimed mandatory writer check does not exist.

   A complete generated receipt likewise serialized an unregistered nested reason through ordinary JSON encoding. The new test calls `Registry.Check` explicitly, proving the helper works rather than proving unchecked emission is prevented.

   **Fix:** provide and enforce a validated emission path for results and records, route production writers through it, and test the actual write without a separate test-side validation call. Marshal-time validation or a source rule enforcing the validated writer are possible approaches.

2. **Medium — Contract encoding accepts deprecated reasons.**  
   `internal/vocab/vocab.go:48`, `internal/contract/contract.go:389`

   The installed callback checks membership only and serves both readers and writers. After marking `completed_clean` deprecated in the loaded registry, a valid receipt still decoded **and encoded successfully**, while `Registry.Check` rejected that reason. Reading historical records and re-emitting them therefore bypasses the static deprecation check.

   **Fix:** distinguish read validation from write validation. Encoding must reject deprecated reasons at every schema-defined reason field, including predicates; decoding must retain historical compatibility. Add a deprecated-record round-trip test that accepts decoding and rejects encoding.

3. **Medium — String-typed expressions still evade reason-field scanning.**  
   `internal/vocab/check.go:194`, `internal/vocab/check.go:252`

   Independently reproduced zero findings for all three:

   ```go
   types.Predicate{Reason: string("typo_explicit")}

   const code string = "typo_typed"
   types.Predicate{Reason: code}

   type Why = types.ReasonCode
   types.Predicate{Reason: Why("typo_alias")}
   ```

   Because `ReasonCode` aliases `string`, checking only the expression’s type loses the destination’s reason semantics. Contract encoding catches these values when used, but note 02’s source-check requirement remains unmet.

   **Fix:** inspect reason destinations in assignments, literals, and arguments, or generate a distinct semantic type. Preserve alias chains when identifying reason types and add these regressions.

4. **Medium — Deprecation scanning also rejects legitimate historical readers.**  
   `internal/vocab/check.go:135`, `internal/vocab/check.go:310`

   After deprecating `stale_attempt`, the scanner reports this reader-only comparison as an illegal writer:

   ```go
   func IsHistorical(r vocab.Reason) bool {
       return r == vocab.ReasonStaleAttempt
   }
   ```

   The assumption that scanned code contains only writers is incorrect. This prevents historical-code handling from passing CI once deprecation begins.

   **Fix:** permit historical constants in read/comparison contexts; enforce non-deprecation at emission and any statically identifiable write sites. Add separate reader-acceptance and writer-rejection tests.
## Third review of #24 (Astra, 2026-10-04)

Verdict: NO-GO

- **Second #1 — High, optional emission boundary:** Partially resolved. Ordinary `vocab.Result` marshaling now validates; generated records still escape both enforcement layers.
- **Second #2 — Medium, deprecated contract encoding:** Resolved. `contract.Encode` rejects deprecated reasons while decoding preserves historical readability.
- **Second #3 — Medium, string-typed expressions:** All three reported examples are fixed. Another reason destination remains uncovered below.
- **Second #4 — Medium, legitimate readers rejected:** Partially resolved. Direct comparisons, switch cases and lookup arguments pass; reader-local assignments and lookup tables still fail.

Independent verification: `make ci` passed with **34 reasons, 14 holds, zero findings**. Shellcheck was unavailable and skipped locally. Additional probes ran in an isolated copy through the repository’s test sandbox. No tracked files changed.

1. **High — Record serialization still bypasses the mandatory boundary.**  
   `internal/vocab/check.go:293`, `internal/vocab/check.go:319`, `internal/vocab/check.go:329`

   Starting with a valid, decoded receipt, this passes the source scan and successfully emits the unregistered nested reason:

   ```go
   r.Predicates[0].Reason = string([]byte("typo_bytes"))
   var doc any = r
   b, err := json.Marshal(doc)
   ```

   **Reproduced:** zero source findings and successful emission through seven forms: an `any` variable, an `any` helper parameter, a containing struct, a function variable, an encoder method value, a dot-imported `Marshal`, and `jsonv2.MarshalWrite(&buf, r)`. The last bypass occurs because the scanner checks argument zero—the writer—instead of the encoded value. Historical receipts containing deprecated reasons likewise serialize through the interface path.

   The record guard recognizes only certain direct calls and static argument types; generated records themselves provide no mandatory reason validation.

   **Fix:** enforce validation during generated-record marshaling, including nested reasons, or confine raw serialization to a vetted codec with enforcement independent of argument type. Add end-to-end regressions for these ordinary serialization forms. Patching only the direct-call cases leaves interface helpers unchecked.

2. **Medium — Historical readers still fail deprecation scanning.**  
   `internal/vocab/check.go:393`, `internal/vocab/check.go:402`

   After deprecating `stale_attempt`, this reader-only function produces a “writers may not emit it” finding:

   ```go
   func IsHistorical(r vocab.Reason) bool {
       old := vocab.ReasonStaleAttempt
       return r == old
   }
   ```

   **Reproduced:** the local assignment, a historical lookup table keyed by the deprecated constant, and a helper returning that constant are all rejected. Assigning a local value does not establish that it will be emitted.

   **Fix:** distinguish actual emission from local computation. Permit historical constants in reader storage and helpers; enforce deprecation at the mandatory emission boundary and only statically proven writer destinations.

3. **Medium — Marshal-time validation suppresses registry-failure JSON.**  
   `internal/vocab/vocab.go:170`, `internal/entry/entry.go:92`

   When `vocab.Load()` fails, the CLI constructs its `could_not_run` result. Encoding that result now calls `Load()` again and returns the same cached failure before writing anything.

   **Reproduced:** introducing an unresolved hold reference in the isolated registry produced exit **2**, empty stdout, and a second stderr diagnostic reporting the `MarshalJSON` failure. This regresses note 08’s JSON error document; the existing missing-root test uses a healthy registry and cannot detect it.

   **Fix:** provide a narrowly scoped bootstrap error encoder whose fixed `check_unloadable` reason is validated independently of full registry loading. Test an actual registry-load failure and require one JSON document on stdout.

4. **Medium — Channel sends omit reason-destination checking.**  
   `internal/vocab/check.go:358`

   This unregistered reason literal passes with zero findings:

   ```go
   func send(c chan types.ReasonCode) {
       c <- string("typo_channel")
   }
   ```

   `reasonDestinations` never handles `ast.SendStmt`; the expression’s string type hides the channel element’s reason semantics. Contract encoding still rejects the value, but note 02’s source-check requirement remains unmet.

   **Fix:** inspect channel sends using the channel element type as the destination, including aliases, and add a regression for typed string constants and conversions.
## Split after three NO-GOs (04 §2)

#24 was closed and split in two:
- **this PR: `adc dev vocab check`**, the static source check:
  - the round-1 and round-2 static fixes are kept;
  - deprecated constants are now reported only where they are written into a result or record field, so locals, tables, helper returns and arguments of readers pass (round 3, Medium 2);
  - channel sends are reason destinations (round 3, Medium 4);
  - the encoding/json record-call check is dropped, because the emission boundary below replaces it;
- **the emission boundary**, a separate PR that follows:
  - the adc-reason format with reader and writer registries;
  - `vocab.Result` validation with a bootstrap JSON error document (round 3, Medium 3);
  - generated contract records validating themselves when marshalled, however they are marshalled (round 3, High 1).
