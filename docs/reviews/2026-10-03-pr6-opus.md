# PR #6 review (fresh Opus reviewer, 2026-10-03)

Verdict: NO-GO

Two High findings, both in `scripts/bootstrap-go.sh`, both with small fixes. Everything else is solid. The smoke check
passes as written on linux/arm64: fresh install into a temporary `ADC_GO_PREFIX`, second run prints "already installed",
`make ci` is green (shellcheck was skipped locally because it is not installed), `adc version --json` reports all five
fields, `adcd` with no arguments exits 2, and `adc bogus` and `adc version --x` exit 64. `make dist` produces exactly
the 10 expected artefacts. The checkout pin `3d3c42e5…` matches the `actions/checkout` v7.0.1 tag (checked through
the GitHub API).

Acceptance criteria: AC3, AC4 and AC5 met. AC6 and AC7 met as written (but see M1). AC1 and AC2 are not met in the
upgrade path (H1). AC1's idempotency is unsafe for a non-Go prefix (H2).

## High

### H1. The version probe lets `go` switch toolchains, so a pin bump is never installed and `go` downloads a toolchain (breaks AC1 and AC2)
- **Where:** `scripts/bootstrap-go.sh:27` (`"$prefix/bin/go" env GOVERSION`), and the same call at `:72`.
- **Problem:** the script does not set `GOTOOLCHAIN=local`. The Go tarball's `go.env` defaults to `GOTOOLCHAIN=auto`.
  The script runs in the caller's working directory, which is the repo root for `make toolchain` and CI. There, `go`
  reads `go.mod`'s `toolchain` line, and when that line is newer than the installed Go, it downloads the newer
  toolchain into the module cache and runs it. `go env GOVERSION` then reports the new version.
- **Verified:** in a directory whose `go.mod` says `toolchain go1.27.9`, `~/.local/go/bin/go env GOVERSION` printed
  `go: downloading go1.27.9 (linux/arm64)`. With `GOTOOLCHAIN=local` it printed `go1.27.1`.
- **Failure scenario:** a developer has go1.27.1 in `~/.local/go`. A later PR bumps the pin to `toolchain go1.27.2`.
  1. `make toolchain` runs the probe, which downloads go1.27.2 into `~/go/pkg/mod/golang.org/toolchain@…`. This
     download skips the go.dev index check the script exists to enforce.
  2. The probe gets back `go1.27.2`, so the script prints "already installed" and never updates the prefix.
  3. `make build` runs with `GOTOOLCHAIN=local` using the go1.27.1 in the prefix. The `go 1.27.0` line still
     accepts it, so binaries silently carry `go_version: go1.27.1`. CI (a fresh install) builds with go1.27.2, so
     local and CI builds diverge without any error.

  A second failure mode: when the toolchain is unreachable (offline or behind a proxy), the probe fails, `|| true`
  sets `have` to empty, and the script prints "replacing unknown". That is misleading but harmless.
- **Fix:** set `export GOTOOLCHAIN=local` near the top of the script, or prefix both probes with `GOTOOLCHAIN=local`.
  Optionally read `$prefix/VERSION` (first line) instead of running `go`.

### H2. Any existing directory at `ADC_GO_PREFIX` is moved into the temp directory and deleted, with no check that it is a Go install
- **Where:** `scripts/bootstrap-go.sh:66-69` (`mv "$prefix" "$tmp/old"`, then `trap 'rm -rf "$tmp"' EXIT`).
- **Problem:** the only test before replacing is whether `$prefix/bin/go` is executable (line 26). Otherwise
  `$prefix`, whatever it holds, is moved under `$tmp`, and the EXIT trap removes it.
- **Verified:** I created `scratchpad/victim/notes.txt` and ran `ADC_GO_PREFIX=…/victim scripts/bootstrap-go.sh`. The
  script printed "installed go1.27.1". `notes.txt` was gone and the directory held only the Go tree.
- **Failure scenario:** a user mistakes the variable for GOPATH and sets `ADC_GO_PREFIX=~/go`, or sets it to `~/.local`
  or `$HOME`. The script silently and permanently deletes their module cache and `~/go/bin`, or worse. No prompt
  appears and nothing remains to recover.
- **Fix:** before replacing, refuse unless the existing prefix looks like a Go install: `$prefix/VERSION` exists and
  its first line matches `^go[0-9]`, and `$prefix/bin/go` exists. An empty directory is also safe to replace. Keep
  the old tree until the new one is in place and verified. Also require `prefix` to be an absolute path, since a
  relative one resolves differently under `make -C` and when run by hand.

## Medium

### M1. shellcheck may be missing on the `ubuntu-24.04-arm` runner, which would fail CI there
- **Where:** `Makefile:69-71` and `.github/workflows/ci.yml:29-33`.
- **Problem:** with `CI` set, `make lint` fails when `shellcheck` is absent. The arm64 hosted runner uses a partner
  image whose tool set is not guaranteed to match the x64 image. I could not confirm shellcheck is preinstalled there.
- **Failure scenario:** the first PR run is red on arm64 only, for a reason unrelated to the code.
- **Fix:** add an explicit step, `sudo apt-get install -y shellcheck` (or a checksum-pinned download), before
  `make ci`. Or check the arm64 log of this PR's first run. A pinned shellcheck version would also make lint results
  reproducible across runners.

### M2. `make` does not check the installed toolchain against the pin
- **Where:** `Makefile:10-11` and `:40-41`; `--print-goroot` at `scripts/bootstrap-go.sh:21-24`.
- **Problem:** `$(GO)` is a file target, so it is only checked for existence. With `GOTOOLCHAIN=local`, any installed
  Go that still satisfies the `go 1.27.0` line builds without complaint. This is the second half of the H1 scenario:
  even with H1 fixed, a developer who never reruns `make toolchain` after a pin bump builds with the old Go.
- **Fix:** make `--print-goroot` (or a separate `--check`) fail when `$prefix/VERSION` does not match `want`. Then have
  the `$(GO)` rule, or a phony `toolchain-check` that `build`, `dist` and `lint` depend on, say "run make toolchain".

### M3. Interrupted or cross-filesystem replacement is not atomic
- **Where:** `scripts/bootstrap-go.sh:51` (`mktemp -d`, under `$TMPDIR` or `/tmp`) and `:66-69`.
- **Problem:** when `/tmp` is a tmpfs or a different filesystem from `$HOME`, `mv "$tmp/unpack/go" "$prefix"` is a
  recursive copy, not a rename. If it is interrupted (Ctrl-C, full disk), `$prefix` is left partly populated. The old
  tree sits in `$tmp/old` and the trap then deletes it. If `bin/go` was already copied, the next run's probe can
  report the right version over a broken tree and say "already installed".
- **Fix:** create the staging directory beside the prefix (`mktemp -d "$(dirname "$prefix")/.go-bootstrap.XXXXXX"`)
  so both moves are same-filesystem renames. Swap with `mv old aside; mv new into place` and delete the old tree only
  after the post-install check passes.

### M4. The README says macOS is supported, but the tooling assumes GNU/Linux
- **Where:** `README.md:11`, `Makefile:7-8`, `scripts/bootstrap-go.sh:47`.
- **Problem:** macOS ships GNU make 3.81, which ignores `.SHELLFLAGS`. Recipes there run without `-euo pipefail`, so a
  failing `go build` inside the `for` loops would not stop `make ci`. Older macOS releases also lack `sha256sum`
  (they provide `shasum -a 256`).
- **Failure scenario:** on macOS, `make dist` can report success with a missing binary. On a Mac without `sha256sum`,
  bootstrap dies with "required tool not found".
- **Fix:** either say "Linux (macOS: GNU make ≥ 4 and coreutils required)" in the README, or make the loops stop on
  error explicitly (`|| exit 1`) and fall back to `shasum -a 256`. Requiring make ≥ 3.82 with a guard on
  `MAKE_VERSION` also works.

## Low

### L1. The bootstrap script ignores unknown arguments
- **Where:** `scripts/bootstrap-go.sh:21`.
- **Problem:** `scripts/bootstrap-go.sh --help`, or a typo such as `--print-gorot`, runs a full install. That
  contradicts the PR's own "unknown flags are refused" rule.
- **Fix:** exit 64 with a usage line for any argument other than `--print-goroot`.

### L2. Downloads are not restricted to HTTPS
- **Where:** `scripts/bootstrap-go.sh:54` and `:59`.
- **Problem:** `curl -L` follows redirects (go.dev → dl.google.com) without a protocol restriction. Integrity also
  rests on the checksum served by the same origin as the tarball, which is acceptable for M0 but worth stating.
- **Fix:** add `--proto '=https' --tlsv1.2`. Optionally record the expected SHA-256 per platform in the repo next to
  the pin, so a bump is a reviewed diff.

### L3. No-argument exit code and help path against the 08 exit-code table
- **Where:** `internal/entry/entry.go:25-35`.
- **Problem:** "no arguments" is arguably "bad arguments", which the 08 table maps to 64 rather than 2. The PR states
  2 explicitly as AC4, so this is a design judgement for the operator, not a bug. Also, `adc --bogus` is reported as
  "unknown command" rather than "unknown flag", and `adc help --json` prints text even though 08 says every command
  supports `--json`.
- **Fix:** confirm AC4's choice of 2 in 08, or switch to 64. Report leading `-x` arguments as unknown flags.

### L4. `concurrency` cancels in-progress runs on `main`
- **Where:** `.github/workflows/ci.yml:12-14`.
- **Problem:** two quick merges to `main` cancel the first run, so that commit never gets a CI result.
- **Fix:** `cancel-in-progress: ${{ github.event_name == 'pull_request' }}`.

### L5. `GOFLAGS` and other user environment can leak into the build
- **Where:** `Makefile:12-13`.
- **Problem:** a developer's `GOFLAGS` (for example `-mod=mod` or `-race`) or `GOEXPERIMENT` changes local builds but
  not CI builds.
- **Fix:** `export GOFLAGS :=` (empty), or set the values you want explicitly. Consider `export GOENV := off` for
  reproducibility.
