## Review of #102, #104 and #105 (Astra, 2026-10-06)

Verdict: NO-GO

#102: GO with changes. #104 and #105: NO-GO on the High findings below.

1. **High — #104: successful `Spawn` can lack the proof that `Wait` needs.**  
   [process.go:151](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah3c/internal/adapterhost/session/process.go:151) accepts `openChild` returning `-1`; the waiter then skips `awaitExit`. Reaping bubblewrap and draining stderr do not establish an empty namespace. Bubblewrap can report the adapter’s exit through an eventfd before its namespace init exits. [Bubblewrap source](https://github.com/containers/bubblewrap/blob/v0.9.0/bubblewrap.c#L457-L524)

   **Reproduced:** a scratch-only test simulated failed init-pidfd acquisition, started 100 descendants with redirected stdio, then called `Kill` and `Wait`. At return, **33 descendant pidfds were still non-readable**. This breaks the prerequisite for safe output ingestion.

   **Fix:** require a verified init pidfd before returning a usable `Process`; synchronize startup and deadline handling around acquisition. Acquisition or polling failures must not silently produce the normal “namespace empty” completion guarantee.

2. **High — #105: unexpected reply IDs disclose adapter-controlled secrets in errors.**  
   [session.go:225](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah3c/internal/adapterhost/session/session.go:225) interpolates the received ID into `Detail`. An adapter can put a numeric secret into this field; safe-integer validation does not make its contents safe to log.

   **Reproduced:** an unsolicited reply with ID `7123456789012345` returns:
   ```
   adapter session protocol: a reply for request 7123456789012345, which is not pending
   ```
   A 16-digit numeric gateway token fits both the token schema and the wire integer range.

   **Fix:** use fixed text such as “a reply for a request that is not pending.” Extend the secret-regression tests to numeric IDs, inspecting both the error string and exported fields.

3. **Medium — #105: cancelling a caller bypasses validation of its eventual reply.**  
   [session.go:227](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah3c/internal/adapterhost/session/session.go:227), [session.go:341](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah3c/internal/adapterhost/session/session.go:341): the reader only correlates and queues replies. Method-specific validation runs in the waiting caller, which has already returned after cancellation.

   **Reproduced:** cancel `Describe` before a delayed `result:{}` arrives. The malformed reply is consumed, and `s.Err()` remains nil. The same arrangement bypasses the version check and other method-result checks. Shutdown/run state also changes before result validation.

   **Fix:** retain method and validation information in each pending entry. Validate replies in the reader before changing lifecycle state or delivering them, including replies whose callers abandoned their waits.

4. **Low — #102: the advertised allocation bound is too precise.**  
   [framing.go:49](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah3c/internal/adapterhost/wire/framing.go:49) claims memory is bounded by 16 MiB plus one chunk, but ordinary `append` growth can allocate capacity beyond that and temporarily retain both backing arrays. Parsing also allocates maps, slices and values separately.

   **Fix:** describe framing storage as proportional to the message bound, or implement and measure the stricter allocation budget. Include densely structured messages in memory tests; whitespace padding does not exercise parser amplification.

The remaining requested judgments:

- **#102 parity:** I found no acceptance mismatch between Go and the SDK’s default strict parser/classifier. The corpus is useful but not complete: it compares verdicts, not decoded contents, and should add mixed object/array/scalar depth boundaries, prototype-like keys, split multibyte UTF-8, and valid input following each terminal framing failure. Go’s reader correctly retains its first failure. The conformance kit additionally imposes a 100,000-value limit, which this corpus does not exercise.
- **`contract.Validate`:** keeping its existing limits is safe for this adapter slice: incoming messages already pass `ReadStrict`, and the outgoing adapter schemas are shallow and bound their integers. I would keep this broader compatibility change separate from #102, while documenting that this does not establish global Go/TS contract parity.
- **#104 pidfds:** the successful acquisition path verifies parentage before starting the reaper; signals use pidfds, and descriptor closure is serialized against `Kill`. The missing-pidfd fallback is the blocker. Improve the tree test with readiness synchronization, descendants that close stdio, and retained descendant pidfds checked immediately after `Wait`. Removing one redundant kill route need not fail an outcome test; removing the namespace-exit barrier must.
- **#105 behavior:** concurrent correlation, event schemas and stamps work in the tested paths. Heartbeat silence and normal session deadlines produce the intended reasons. Best-effort cancel retains an independent process deadline. The documented synchronous `onEvent` trade-off is acceptable for M0 provided callbacks return promptly; arbitrary callback blocking is not covered by a guarantee that every waiter settles.

### Lead notes on round 1 (applied)

- High 1 (#104): `Spawn` no longer returns a `Process` without a verified pidfd on the namespace's init. If it cannot open the pidfd, or the pid's parent is not bubblewrap, `Spawn` kills bubblewrap through its pidfd and kills its process group, which holds the init. This is the one numeric signal, and it is sent before the waiter starts: bubblewrap leads the group and is not yet reaped, so the group id is still its own. Killing bubblewrap alone left the init running, which is how the test below first hung. `Spawn` then waits and returns an error. The init's pidfd is published under the mutex the deadline's `Kill` takes, and the waiter starts only after that. A missing pidfd, a failed poll, or a poll without `POLLIN` makes `Wait` return `ErrUnverified` and never the normal completion.
  - Tests: `TestSpawnWithoutTheInitFails` replaces the acquisition (`openInit`) and asserts that `Spawn` fails. The tree tests wait for the stub's `ready` line. The stub starts 100 descendants, each in its own session with `/dev/null` stdio. The tests hold a pidfd on each descendant and assert that every one is readable at the instant `Wait` returns, both after `Kill` and at the deadline.
  - Control: removing the namespace-exit barrier (in the working tree, then reverted) turned both tests red in every run, with 1 to 34 descendants still running.
- High 2 (#105): a reply to a request that is not pending is reported with fixed text ("a reply for a request that is not pending"). Every `Detail` was audited. What remains interpolated is the core's own: the method and schema names, the contract major and the heartbeat gap. `Error.Code` keeps the adapter's JSON-RPC code only inside the reserved range −32768..−32000, and 0 otherwise.
  - Tests: `TestNoSecretLeaksIntoErrors` adds a numeric secret (`7123456789012345`), sent as an unsolicited reply id and as an error code. It checks the error string and every exported field (`%#v`). Against the previous code it failed on the id.
- Medium 3 (#105): each pending entry keeps its method and a check. The reader decodes the result against its schema and runs the method's own check (`describe`'s version, `tool.response`'s empty acknowledgement). It does this before it clears the run, marks shutdown or delivers. An invalid reply ends the session, including one whose caller has stopped waiting.
  - Tests: `TestALateReplyIsStillChecked` cancels `describe` and then receives a malformed reply, and separately a reply of another major. `s.Err()` becomes a protocol error and a version error respectively. Against the previous code the malformed reply was consumed unchecked.
- Low 4 and the #102 corpus notes are applied in #102.

**High — #104: deadline expiry can miss the init permanently.**  
[process.go:144](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah3c/internal/adapterhost/session/process.go:144), [process.go:157](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah3c/internal/adapterhost/session/process.go:157)

The timer can run after `openChild` verifies the fd but before `p.initFD` is published. `Kill` sees only bubblewrap’s fd. Publication subsequently succeeds, and nothing repeats the kill. Bubblewrap’s init installs its parent-death signal later in startup, so killing the parent alone does not close this window. [Bubblewrap 0.9.0 source](https://github.com/containers/bubblewrap/blob/v0.9.0/bubblewrap.c#L2755-L2784)

**Reproduced 5/5 times:** an in-memory test hook acquired the real verified fd, paused init startup, allowed the deadline to expire, then resumed and published it. `Spawn` returned a process with `Expired()==true`; init survived and `Wait` remained blocked. The waiter, stderr drainer and descriptors consequently remained outstanding until the probe explicitly killed the process.

**Fix:** make publication honor an already-fired deadline, ensuring the newly published init is killed. Prefer returning an error after cleanup when startup has already expired. An in-memory control that reissued `Kill` after publication when expired passed **3/3** runs.

**Medium — #105: a JSON-RPC prepare refusal retains the previous prepared fence.**  
[session.go:255](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah3c/internal/adapterhost/session/session.go:255), [session.go:457](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-ah3c/internal/adapterhost/session/session.go:457)

Prepare clears or replaces `s.prepared` inside its successful-result validator. A JSON-RPC error bypasses that validator, preserving the prior stamp despite the documented “nil … after one it refused” invariant.

**Reproduced 3/3 times:** successful prepare → RPC-refused prepare → cancel using the old stamp. Cancel was sent and succeeded instead of returning `ErrForeignParams`.

**Fix:** clear prepared state on a prepare RPC refusal before delivering it. Given the one-process-per-attempt contract, also define and enforce whether repeated or overlapping prepares are allowed.

### Lead notes on round 2 (applied)

- High (#104), the deadline between acquisition and publication: `Kill` now records that it was asked, under the mutex it signals under. The init's pidfd is published under that same mutex. If a kill was already asked (during startup only the deadline can ask), publication signals both pidfds at once. Bubblewrap's death alone is not enough, because the init sets its parent-death signal late. `Spawn` then waits, so the init has exited and the namespace is empty, releases everything and returns an error.
  - `TestADeadlineDuringStartupKillsTheInit` uses a test hook (`startupHook`) that runs between acquisition and publication. The hook keeps a duplicate of the init's pidfd and pauses until the deadline has fired. The test asserts that `Spawn` fails, that the init has exited at the moment `Spawn` returns, and that no descriptor or goroutine leaks.
  - Control: ignoring a fired deadline at publication (in the working tree, then reverted) made the test fail in 5 of 5 runs.
- Missing #104 tests:
  - `TestWaitWithoutTheInitsExitIsUnverified` covers a missing pidfd (`verified(-1)`), a failing poll and a poll without `POLLIN`. The poll is replaced through a package variable, and in each case `Wait` returns `ErrUnverified`.
  - `TestTheInitsParentIsVerified` covers a pid that is not the given parent's child, a pid that cannot exist, and `Spawn` with an init of another parent. Each is refused, and the test checks that no descriptor or goroutine leaks.
  - `TestRepeatedSpawnsReleaseEverything` runs ten failed spawns and ten killed ones, then checks that descriptors and goroutines are back to where they started.
- The barrier is now deterministic: the tree tests add two descendants that each hold 512 MiB, beside the 100 sleeps. The kernel populates the memory (`MADV_POPULATE_WRITE`), so a race-instrumented stub is as quick as a plain one. Tearing that memory down at death is slow enough that bubblewrap is already reaped while the namespace's init still waits for them. With the barrier removed (in the working tree, then reverted), the two tree tests failed in 20 of 20 plain runs and 10 of 10 under `-race`.
- Medium (#105), prepared state: a session now serves one attempt and prepares it once.
  - A prepare is admitted, under the session's lock, only when no prepare is pending, none was accepted and no run is open. Anything else returns `ErrSequence` and nothing is sent.
  - In the reader, before delivery, an RPC refusal or an outcome other than empty or found leaves the session unprepared. An accepted prepare fixes the attempt and fencing token.
  - Run, tool.response and cancel are admitted under the same lock: `ErrSequence` before a prepare was accepted, `ErrForeignParams` for another attempt, token or call.
  - `TestASessionPreparesOnce` covers an RPC refusal (a cancel afterwards is refused, not sent), a declined outcome, an overlapping prepare, a run overlapping a prepare, and a second prepare.
  - Controls: dropping the refusal's settlement, or the admission (in the working tree, then reverted), made the test fail.
- Missing #105 tests:
  - Run completion against tool.response: `TestAToolResponseRacingTheRunsEnd`.
  - Late malformed run and shutdown replies and an invalid tool acknowledgement leave the run open and shutdown unmarked: `TestRejectedRepliesChangeNothing`, plus `TestARejectedReplyChangesNothing` on the transport. Updating the lifecycle before the check (in the working tree, then reverted) failed it.
  - RPC-code boundary values: `TestOnlyReservedRPCCodesAreKept` (−32768, −32000, −32769, −31999, 0, a 16-digit number).
  - A schema-valid version carrying a secret in its prerelease: `TestAnotherContractMajorIsRefused`.

  - #105 keeps the transport, reader, lifecycle and heartbeat (`session.go`, 341 code lines). Its tests use a scripted raw stub that answers requests concurrently.
  - `feature/m0/adapterhost-methods` adds the typed methods and the attempt and handle fence (`methods.go`, 174 code lines), each check with its tests and the fake-adapter round trips.

### Lead notes on round 3 (applied)

- Medium (#104), the startup regression test now isolates the publication's signal to the init.
