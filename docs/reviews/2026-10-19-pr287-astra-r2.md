## External review of #287, round 2 (Astra, 2026-10-19)
Verdict: NO-GO

Reviewed `8ebd7e3` against `a2a63b9` and main `79c03f6`, both review records, and the PR’s Round 3 description. Read-only; no tests or probes run. Inputs below are derived from code inspection.

Blocking findings are **1**, within the lifecycle promise, and **2**, a regression against main.

1. **High — Abandoned services accumulate without a bound across runs.**  
   `internal/accept/integrity_proc.go:329`

   **Input:** use a Reader that ignores its context and waits forever. Run `Integrity` repeatedly, sequentially. Each deadline returns and reaps its child, but leaves another service goroutine holding the service state, including the run’s file map and changes. A stuck Lister has the same problem.

   Bounding concurrent guard calls does not bound these leftovers: the caller’s slot becomes available after each timeout. This reintroduces accumulating controller work outside the killable child.

   **Fix:** impose a controller-wide service limit whose slots remain occupied until the underlying calls actually return. Refuse further work when exhausted, or move these services behind a killable process boundary. Add a repeated-run row that keeps earlier services stuck.

2. **Medium — The frame loses “absent go.mod,” causing an ordinary-input regression.**  
   `internal/accept/integrity_proc.go:179`; `internal/accept/integrity_loader.go:138`

   **Input:** a base without `go.mod`, containing ordinary Go code and tests importing standard-library packages; add a harmless helper. Main passes `gomod == nil` to the loader, which supplies `module adc.invalid/guard`.

   The new frame encodes nil as an empty string and decodes it as a **non-nil empty byte slice**. Both loaders consequently write an empty `go.mod` instead of supplying the fallback. Go rejects its missing module declaration, producing “not loaded” blocks that main would not produce.

   **Fix:** encode presence separately from length for optional module files. Preserve absent versus present-but-empty; treating every empty payload as nil would introduce the opposite regression. Add equality rows for both cases.

3. **Medium — Metadata still permits large controller allocations before rejection.**  
   `internal/accept/integrity_loader.go:173`; `internal/accept/integrity_loader.go:190`

   **Input A:** leave otherwise valid outputs, but make `version` contain the correct version followed by 768 MiB of spaces. This can fit the live 1 GiB disk allowance and the run’s copy budget. `os.ReadFile` allocates for it, followed by the string conversion, before `TrimSpace` accepts it. There is no version-file size bound.

   **Input B:** make `list` a single line containing nearly 16 MiB of tabs. It passes the byte and newline-count checks. `strings.Split` allocates roughly 256 MiB of string headers on a 64-bit controller before discovering that there are more than three fields.

   **Fix:** check a small version-file limit before reading it; parse listing fields with bounded cuts or `SplitN(..., 4)`. M6’s original oversized-list input is fixed, but its nearest metadata variants remain.

4. **Medium — An explicitly present empty listing error is accepted.**  
   `internal/accept/integrity_loader.go:195`

   **Input:** a valid listing row:
   ```text
   fmt<TAB>/cache/<valid-sha256>-d<TAB>""
   ```
   with the matching archive copied out.

   `Unquote` returns an empty string, so `case why != ""` does not fire. The loader retains the export and returns no `Error`. The strengthened `lookup` cannot detect the error because its presence has already been discarded.

   **Fix:** track whether the error column is present independently of its decoded text. Any present error must suppress the export and produce a non-nil `Error`, including an empty message. H2(A) is not fully closed.

5. **Medium — A clean terminal result still overrides a controller-observed listing failure.**  
   `internal/accept/integrity_proc.go:366`

   **Input:** the child requests a listing; the Lister returns `nil, errors.New("copy-out failed")`; the child then sends an empty successful `d` frame.

   `serve` forwards the error but does not latch it. Neither `s.readErr` nor `s.failed` is set, so `converse` accepts the clean result. This contradicts the stated guarantee that failures observed by the controller cannot be overridden.

   **Fix:** latch service-level listing failures as well as Reader errors and panics, and enforce them at completion. Add the failed-listing/clean-result variant to `TestProcService`. M4’s original Reader-error and panic cases are closed; this adjacent case is not.

6. **Medium — Invalid terminal boolean values decode as success.**  
   `internal/accept/integrity_proc.go:193`

   **Input:** the complete frame:
   ```text
   00 00 00 05 64 00 00 00 02
   ```
   Its payload is `d`, zero blocks, zero warnings, an empty error string, and an invalid error flag of `2`.

   `flag() == 1` turns every value other than `1` into false. The malformed frame therefore becomes a clean result.

   **Fix:** reject flag values above `1` before converting to bool. Reject contradictory terminal error fields too, such as nonempty error text with a false flag.

7. **Low — The listing entry cap misses an unterminated final record.**  
   `internal/accept/integrity_loader.go:185`

   **Input:** 16,385 distinct, syntactically valid records, with no newline after the last. The newline count is 16,384, so the listing passes the cap and all 16,385 entries are parsed.

   **Fix:** count records during bounded parsing, or require and validate the final newline.
