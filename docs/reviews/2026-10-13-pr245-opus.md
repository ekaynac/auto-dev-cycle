### Medium

**M1. I15 and the activation rule (`docs/design/m1/00-slice-plan.md` §1, lines 92–97 and 104).**
- §1 says a capability is registered only when every listed row is **kept**. `answers` lists I15, and I15's admission row is kept + GAP (P22a).
- In practice nothing opens. adcd wires no action that builds a graph event or `owed_input.recorded` (that is P16's). So `input.answer` can only fail: `stale_expected_state` for an operator, `action_not_granted` for a supervisor. The template-guard gap can't be reached through it.
- Still, this breaks the "one source of truth" rule, and §1's "adcd holds this table in code" guard doesn't exist yet. Removing the entry from `deferred` is the whole activation.
- **Fix:** before merge, the lead records a decision. Either amend §1's `answers` row to "I15 except admission (no template is reachable through `answers`)", or note the exception in the inventory summary (`01-invariant-inventory.md:69`).

**M2. A raw `awaiting_input` hold can block its node forever.**
- `answerWaitEnds` (`internal/graph/eligible.go:200-202`) refuses any `hold_cleared` for an `awaiting_input` wait whose signal matches no declared answer. That covers a signal and a `revised` retirement, so the wait has no way out. `holdsFor` also carries it over to a replacement.
- The raise fold (`holdRaised`, `holds.go:210`) is not part of `eligible`, so a raw `node.hold_raised` with such a signal is still accepted.
- **Fix:** add a `*types.HoldRaised` case to `eligible` that refuses an `awaiting_input` raise whose `SignalInstance` is not `awaitSignal` of a declared answer input. Add a mutation and test for it.
- With that in place, the second tightening holds up. The evaluator (`evaluate.go:248`) only raises waits on declared answers, so it blocks no legitimate flow.

**M3. The reading of "answer removal" (deviation 2).** The PR's reading is correct. 13:206 says "Removing an answer is deferred to M1", which is the supersession removal. But #226 entry 46 assigns "operator withdrawal of a supervisor's answer" to P6, and this PR drops it.
- **Fix:** add a #226 entry, or a slice-plan line, that gives the withdrawal act an owner (P16/P28 or a new item). Without one, the requirement is lost.
