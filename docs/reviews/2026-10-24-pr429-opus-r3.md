### BLOCKING

**N1 (High). Two acceptances go test never runs are expected; the candidate is charged.**

**(a) A Go test file that imports `"C"`.** `gosel.Builds` passes it under `CgoEnabled: false`, because `go/build.MatchFile` does not look at imports. `active` (`internal/gate/acceptance.go:74-95`) therefore expects its tests.
- **What go does:** under the image's `CGO_ENABLED=0`, go fails the package: `use of cgo in test …/h_test.go not supported`, `FAIL m/p [setup failed]`.
- **What the gate records:** fed that real stream, `results.ParseGoTestJSON` gives `{TestHidden: missing}`, `m/p: fail`. That is `found/gate_test_failed` against every candidate, the same consequence as Astra's H1.
- **Collateral:** a second, runnable test in the same package (`TestOther`) is lost too.
- **A missed reuse:** accept already holds this rule in its typer (`internal/accept/integrity_types.go:419`: a file that imports `"C"` is not built). M6 did not extract it.

**(b) A malformed test name beside a real test:** `Testfoo`, `Benchmarkfoo` or `Fuzzfoo`.
- **What the gate does:** `testKind` (`acceptance.go:157`) reads each as "not a test" and ignores it.
- **What go does:** go1.27's `go test` runs vet's `tests` analyzer, so the package's build fails: `Testfoo has malformed name: first letter after 'Test' must not be lowercase`. `TestHidden` never runs, and it is Missing.
- **The same applies to examples:** `Examplefoo` fails with "refers to unknown identifier: foo".

**Fix:**
- Move accept's cgo rule into `gosel`, one copy that accept's typer and `active` both call. For a `_test.go` that imports `"C"`, the gate returns `errNeverRun`. A non-test file that imports `"C"` becomes data, since go ignores it with cgo off.
- In `testKind`, refuse with `errSignature` a top-level function named `Test`, `Benchmark`, `Fuzz` or `Example` + a lower-case letter. Go test's vet refuses these.
- Add both rows to `TestAcceptanceTests`-style tables, plus a daemon row for (a).

### OBLIGATIONS

**M1 (Medium). Redeclaration has three forms `AcceptanceFits` does not see.** `topNames` (`acceptance.go:271`) collects package-scope functions, types, variables and constants only. Each of these never compiles, whatever the candidate does:
- **An import name colliding with a package-scope name:** one acceptance file has `import "os"` and `var os = 1`, and go fails.
- **A dot-import exporting a name the package declares:** the base declares `F` and the acceptance has `import . "testing"`. Go fails with "F already declared through dot-import". `T`, `B`, `M` and `F` are ordinary names.
- **A method an acceptance helper declares on a base type that already has it.**

**Fix:** either add the first and third to the check (import local names; methods keyed by receiver type), or state all three among the plan's residuals (`docs/design/m1/00-slice-plan.md:202`).

**M2 (Medium). The general class is not stated: an acceptance that does not compile or vet on its own.** The differential shows these forms pass the gate but always fail the package:
- an unused import;
- a type error;
- a printf vet error (`t.Logf("%d", "s")`);
- an example naming an unknown identifier.

A gate cannot tell some of these from what the candidate must add (an undefined name may be the task's API). The plan's residual list names only two cases. Its count, "Two residuals", is also stale: the list now has four bullets.

**Fix:** state that a hidden test that fails to compile or vet on its own fails every candidate (`found/gate_test_failed`). Its recovery is a new task, since the acceptance is immutable. Make the count match the list.

**L1 (Low). `gosel.Walked` (`internal/gosel/gosel.go:31`) is accept's `walked(p, skip)` (`internal/accept/integrity.go:465`) with `skip` fixed to `SkipDir`.** These are two copies of one walk rule.

**Fix:** make `gosel.Walked` take `skip` and have pyguard call it with its own skip, or keep `walked` and define `gosel.Walked` through it.

**Also noted, no action needed:** `errAcceptanceRead` drops the store's cause entirely. An operator diagnosing a failed blob read sees only the fixed text. The cause could be logged under a fixed prefix without the digest, for example only its error class (`fs.ErrNotExist` versus a digest mismatch).
