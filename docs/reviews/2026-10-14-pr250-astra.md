## External review of #250 (Astra, 2026-10-14)

Verdict: GO with changes

Reviewed `84365b9` against `origin/main`, the PR’s Round 2 description, pre-review, contracts, gateway, and requested issue entries. Read-only; no tests or mutations run. No Critical/High finding established on M1’s current edit loop, whose four tools cannot execute repository code or create links.

1. **Medium — Cleanup can unlink a file this call never created.** `adapters/http-chat/src/workspace.ts:200–202`

   The catch covers both `open()` failure and post-open validation failure. `!existed && error !== EEXIST` does **not** establish successful exclusive creation. For example, after the initial absent-file check, another writer can create the entry; an `EMFILE` failure before pathname resolution then reaches `unlink()` and removes that entry. Held directory descriptors prevent parent-symlink redirection, but do not establish ownership of the final entry.

   **Fix:** Separate exclusive creation from validation. Never unlink when `open(O_CREAT|O_EXCL)` failed. Track successful creation explicitly; preserve the created inode’s identity through cleanup, and avoid deleting a replacement. Add a fault case where the open fails with a non-`EEXIST` error while another file occupies the name.

2. **Medium — Hard-link confinement covers changes, but not reads.** `adapters/http-chat/src/workspace.ts:136,145`

   `readText()` calls `pin(..., false)`, bypassing the link-count check. Given the hard-link arrangement already constructed in `test/workspace.test.ts:67–70`, `read_file("h")` returns the outside file’s contents, which can enter the next model request. An alias to `.git/config` similarly bypasses the lexical `.git` prohibition.

   This requires a pre-existing filesystem alias: Git does not preserve hard links in a checkout, and these tools cannot create one. That limits present M1 reachability, but the claimed confinement does not hold for the hostile filesystem case posed in this review.

   **Fix:** Require `nlink === 1` for reads as well as changes, including reads used to capture originals and construct patches. Extend the existing hard-link case to assert refusal of `read()`.

3. **Medium — The held-directory residual also permits access inside `.git`.** `adapters/http-chat/src/workspace.ts:57–59,91–100,205–218`

   A held directory moved outside the root after `within()` remains usable for writes and unlinks. Additionally, moving it beneath `.git` can pass `within()` even **before** that check: the predicate checks only the root prefix, while `.git` rejection applies to the original requested spelling.

   **M1 judgment:** Acceptable only for the current isolated edit loop with no concurrent repository process. It is not a general confinement guarantee against D43’s concurrent adversary. Adding another real-path check alone cannot close the check/use window.

   **Fix:** Make exclusive filesystem mutation an enforced launch invariant before introducing executable or concurrent tools. Reject forbidden components in resolved directory paths as additional protection. Document both relocation cases, rather than describing only movement outside the workspace.

4. **Medium — Ambiguous reviewer JSON can become a GO.** `adapters/http-chat/src/adapter.ts:263–268`

   Ajv validates the object after `JSON.parse()` has discarded duplicate keys. For example:

   ```json
   {"decision":"no_go","decision":"go","summary":"x","findings":[]}
   ```

   becomes a schema-valid GO and is written without evidence of the conflicting decision. Escaped lone surrogates likewise survive this parsing step. Ordinary syntax errors and schema mismatches fail closed, but the decision boundary is not strict in the same sense as the adapter protocol.

   **Fix:** Reject duplicate keys and malformed Unicode before schema validation. Use a bounded strict decoder appropriate to the supplied schema; the SDK’s integer-only parser needs consideration if custom decision schemas permit fractional numbers. Add a conflicting-decision rejection case.

5. **Medium — Conversation bounds do not bound retained originals or the cumulative patch.** `adapters/http-chat/src/workspace.ts:76,190,223–230`

   Deleting a file saves its entire original content while returning only `"ok"`. Consequently, short deletion requests can grow `originals` substantially without approaching the conversation limit. Five turns deleting 64 distinct 256 KiB text files retain approximately 80 MiB and can produce a patch exceeding the controller’s 64 MiB patch bound. Larger allowed turn counts increase memory exposure.

   **Fix:** Bound retained original bytes and cumulative patch bytes independently of request history. Refuse further changes before exceeding those budgets, and stop patch construction before allocating an inadmissible result.

6. **Low — Malformed usage bypasses the new missing-usage fallback.** `adapters/http-chat/src/adapter.ts:77–85,234–242`

   `usage: {}` or `usage: []` counts as a report, with missing counters converted to zero. The full-`max_tokens` fallback therefore does not run, and the adapter can eventually declare a complete zero-token measurement. Turn and request bounds still constrain the loop.

   **Fix:** Require valid mandatory token counters before treating usage as complete. Treat incomplete reports as unknown and apply the conservative allowance. Keep adapter measurements subordinate to controller accounting.

7. **Low — R3 does not compensate for surviving mutation R3b.** `adapters/http-chat/test/workspace.test.ts:110–118`

   R3 proves the helper’s predicate, not that workspace operations invoke it. R3b’s survival leaves that integration unproved. The existing post-walk swap hook cannot exercise a check that has already completed.

   **Fix:** Add a deterministic synchronization point before the final containment check, move the held directory outside the root, and assert that the real operation refuses without effects. Dropping the `within()` call should then turn that case red. Retain the documented post-check limitation separately.

The other requested boundaries look sound by inspection:
