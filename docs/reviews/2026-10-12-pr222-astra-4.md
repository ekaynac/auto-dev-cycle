## Review of #222 reshape (Astra, 2026-10-12)

Verdict: NO-GO

Two High findings block. The overall reshape follows the replan: separate (a)/(b)/(c) exit specifications, a dependency map with five detailed items, three further deliveries for (c), the board and `match()`, launch readiness, D58 enforcement columns, and D63/D55 in (c). Reviewed `e0b7e9d` against `origin/docs/plan/d49-replan`; no files changed or tests run.

1. **High — P27 does not implement expected-base CAS.** [00-slice-plan.md:520][cas], [01-invariant-inventory.md:205][icas]. GitHub’s `force: false` checks fast-forward ancestry, not equality with the generation’s expected base. Suppose ADC observes B and prepares C with parent B; another writer rewinds the unprotected branch to ancestor A before `Apply`. Updating A→C still fast-forwards, silently restoring the removed commits without a new generation, review or approval. The preliminary `Holds` read cannot close that race. Require a server-enforced exact-old-SHA update, retain the single-parent prospective-commit constraint, and add a rewind-between-read-and-update fixture. [GitHub’s documented parameters](https://docs.github.com/en/rest/git/refs#update-a-reference) confirm that this endpoint has no expected-old-SHA parameter.

2. **High — the admission guard enables concurrent admitted tasks before their safeguards.** [00-slice-plan.md:97][wip]. Allowing another admitted task when the previous task is *held* contradicts D51: held tasks retain admitted WIP. Task A can hold, B can start, then A’s resume signal can arrive while B runs. This reaches the concurrency explicitly deferred pending D62. Separate creation/Ready backlog from admission; retain the one-admitted-task limit through M1, including held tasks. Add a held-A → request-B → resume-A fixture.

3. **Medium — capability gating has conflicting sources of truth.** [00-slice-plan.md:93][guards], [00-slice-plan.md:518][register], [01-invariant-inventory.md:53][inventory]. The activation table omits inventory dependencies: launch’s I6/I12, review’s I5, merge’s I1 effect check, and I15 across capabilities. P18 also says it registers `merge`, while P22b owns activation and I20 remains unfinished until P28. Make one row-level dependency table authoritative; land effect implementations inert until activation. Checkpoint (a)’s negative assertions are sound, but “merge disabled” is not unambiguous until this contradiction is removed. Its benchmark and reused fault cases should explicitly select candidate-only expectations.

4. **Medium — the next five items are not all independently startable as written.** [00-slice-plan.md:488][details]. All estimates fit D46 numerically; they are estimates, not demonstrated implementation sizes.

   | Item | Assessment |
   |---|---|
   | P1 — 450 | Startable using existing inline scope, but its advertised smoke needs P2’s `--scope-file`. Record that dependency or change the smoke. |
   | P2 — 400 | Needs pinned upload bounds, expiry/ownership semantics, and an exact upload/reference smoke command. |
   | P3 — 400 | Depends on P1/P2; “parallel now” is inaccurate. Separate intake acceptance from first-claim integration, which P22a owns. |
   | P4 — 450 | History wiring is startable. Pin board derivation examples and its task-record dependency; history validation and the board are independently reviewable if the estimate grows. |
   | P9 — 600 | Implementation can start, but “a probe run through installed `adcd`” names no runnable interface before launch activation. Specify that interface and distinguish forbidden controller sockets from the permitted gateway socket. |

5. **Medium — live scratch faults need discriminating synchronization.** [00-slice-plan.md:228][scratch]. The local fixtures have receive-hook barriers; the GitHub cases only name outcomes. Specify how the driver proves the update landed before killing ADC, and how it creates a definitely-not-sent case. A timed kill or missing trailer alone cannot prove non-delivery. If landing cannot be established, preserve `uncertain` and its fence.

For **direct updates to `main`**, I support a narrowly approved M1(b) path after the CAS repair. D52 brings delivery forward; it does not require weakening existing branch protection. Pin repository/ref, keep the repository-scoped credential exclusively with the controller, and explicitly record the exception to the development workflow’s no-direct-main rule. Prefer a configuration admitting the delivery identity over globally unprotecting `main`. Run disruptive fault cases only on the scratch ref, with assertions that `main` remains unchanged.

For **D55**, keeping P30’s read model in (c) is reasonable, but explicitly assign first-attempt ledger recording—including catches, false blocks and later annotations—to the earlier producers. For **D59**, name P22a as owner of pure snapshot reconciliation, execution-time rechecks and periodic resynchronization.
