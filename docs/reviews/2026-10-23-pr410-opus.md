### High

**H1 (BLOCKING). A host fault in the guard now repairs the build as the candidate's fault, at the candidate's cost.**
- `graph.AcceptRefused` (`internal/graph/repair.go:35`) is "any `failed` tree result". The guard turns these host failures into `failed/test_integrity_violation`:
  - `unverifiable: go list failed (<sandbox error>)` (`accept/integrity_proc.go:492`);
  - `the guard failed (<panic>)`;
  - `the guard's process did not start`;
  - `this binary does not dispatch the guard's process`;
  - the type-check or whole-run deadline under host load.
  
  Chunk 1 stated this misattribution as the residual P14e-attr. Before this PR, its effect was a gate refusal. Now `reconcile.Observe` (`reconcile.go:448`) decides a repair, review active or not.
- **Probe:** `goTestWorld` with a `go list` that always fails with `podman: the sandbox failed`, run under the loop for 60 passes:
  - **6 build rounds, 5 accepts "refused"**, then the build held `budget_rail` on `rail:rounds_per_task`;
  - round 2's builder prompt reads: "It refused it: accept refused the candidate; test_integrity_violation \".:a\": unverifiable: linux/amd64: the types of its imports not loaded (testing: podman: the sandbox failed) …".
- In production that is five paid builder runs on a broken sandbox, then the task stuck behind a rail an operator would raise in vain. The builder is also told to fix a fault that is not its own, which wastes the rounds and the money. The rubric names this class ("a host or infrastructure fault recorded as the candidate's result"), and this PR makes it act.
- **Fix:** separate the guard's host failures from its findings before a refusal can repair.
  - **The narrow fix:** the guard returns the failures it saw itself as an error, not a block. These are `go list` failing in its sandbox, the child not starting or not dispatching, and a panic in the service. adcd's accept run already turns an error into `could_not_run/controller_run_failed` with a bounded runner retry (`couldNotRun`).
  - Or tag those blocks (for example a `Host` field on `Block`), so that `accept.Result` records `could_not_run`.
  - Keep the candidate-attributable ones (a deadline driven by the candidate's size, its code's shape) as refusals, and state that line.
  - Rows: a failing `go list` gives `could_not_run` and a retry hold, with no repair round. `TestAFailedGoListRefusesTheCandidate` must change accordingly.

### Low (OBLIGATION)

**L1. `AcceptRefused` is applied to a result rebuilt from `Outcome` alone** (`reconcile.go:448`, `types.Result{Kind: ResultKindTree, Outcome: *n.Outcome}`). It is the one rule only while the rule reads nothing else. Once H1's fix makes the rule read the reason or the detail, the loop and `Repair` will diverge.
- **Fix:** pass the selected result itself (`NodeView` carries `Reason`; or load the result record).

**L2. `oneSource` (`daemon/reviews.go:241`) is a third walk over a node's result inputs**, beside `producerOf` (same file) and `graph.TakesGate` (rubric: reuse).
- **Fix:** use `producerOf(tx, gate, ResultKindTree)`, which also states which input it means; "first result input" is fragile once a gate takes an overlay.

**L3. A task whose rounds rail is reached on a refused accept shows "waiting" gates on the board, and nothing names the refusal.** The board shows the build held on its rail and the refused round's gate as waiting.
- **Fix:** a coarse badge on the refused round's gate ("its tree was refused"), or state it as #408's board work.
