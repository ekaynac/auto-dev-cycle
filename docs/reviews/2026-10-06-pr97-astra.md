# PRs #97–#99 (grant events, /v1/events, fixture): Astra reviews

## Review of #97, #98 and #99 (Astra, 2026-10-06)

Verdict: NO-GO

1. **High — Slow clients can postpone revocation checks indefinitely (PR #98).**  
   [internal/api/events.go:189](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-sse/internal/api/events.go:189): writes and flushes have no deadline, and authority is checked only before loading each batch. A blocked client prevents further checks; when it resumes, remaining buffered events are sent under the stale authorization. A focused probe blocked one write, committed revocation, waited beyond `MaxPoll`, then observed **two additional event frames** before closure. These were buffered, pre-revocation events; the snapshot correctly excludes later log entries.

   **Fix:** bound writes and flushes, interrupt stalled output when authority ends, and revalidate before continuing buffered delivery. Apply the same protection to expiry. Add slow-client and expiry cases to #99.

2. **Medium — The supplied projector composition can admit histories that cannot rebuild (PR #99; also #97/#98 test setup).**  
   [internal/fixtures/stream.go:64](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-sse/internal/fixtures/stream.go:64): identity processes the entire batch before grants. Consequently, `grant.created` followed by its supervisor’s `actor.created` in one command is accepted: the grant projector sees the later actor. Rebuild processes events individually and rejects that same grant because the actor does not yet exist. A focused probe reproduced this.

   **Fix:** compose projectors in event order, running all applicable projectors for each event before advancing. Test mixed identity/grant batches and require every admitted history to rebuild successfully.

3. **Low — Storage failures can be reported as revocation (PR #98).**  
   [internal/api/events.go:168](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-sse/internal/api/events.go:168) treats every `StillLive` error as `failed/authority_revoked`. [internal/identity/identity.go:391](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-sse/internal/identity/identity.go:391) also collapses actor-loading failures into authentication failure.

   **Fix:** preserve storage/decoding errors and route them to `could_not_run/store_unreadable`; reserve revocation for actual authority loss.

The six reported fail-open fixes are present. Project and kind checks remain server-side and cannot be widened by filters or `?after=`. Resume authenticates against current authority. The domain mapping is consistent with 08; client filters cannot spoof stored kinds. Current allow-listed payload fields contain no credential material, token hashes are excluded, and unlisted kinds have their payload withheld. Global sequence gaps remain observable by the documented cursor design.

The grant schema correctly distinguishes creation from revocation. Ordinary HTTP refusals and SSE frames are consistent with the contract, apart from finding 3. #99 exercises real authentication, storage, projectors and HTTP streaming, and its mutation is realistic; its existing coverage misses the stalled-output case.

Both requested test commands passed under Go **1.27.1**, with `GOTOOLCHAIN=local` and `CGO_ENABLED=1` for race tests. Schema tests also passed. The two focused probes failed as described, using temporary sandbox overlays. Checkout unchanged.

### Lead notes on round 1 (applied)

- **High, slow clients (#98; fixture steps in #99):** every frame write and flush has a deadline of at most the poll bound (one second), set through `http.ResponseController`; authority (token, actor, grants, expiry) is re-checked before each frame, not only before loading a batch; a write that stalls past its deadline ends the handler and closes the connection. Unit tests cover a revocation and an expiry during delivery and a stalled client; #99 adds the same steps to its golden.
- **Medium, projector composition (#97, used in #98 and #99):** `eventstore.ProjectEach` runs every projector on each event in order, as a rebuild does; every composition uses it. #97 tests a mixed identity/grant batch (a grant before its grantee is refused) and checks that every admitted test history rebuilds without differences.
- **Low, storage errors read as revocation (#98):** `identity.StillLive` returns `ErrUnauthenticated` only for actual authority loss (token or actor missing or revoked) and passes storage and decoding errors through; the stream closes those with `could_not_run/store_unreadable`. Tests cover both.

## Second review of #97, #98 and #99 (Astra, 2026-10-06)

**Verdict: GO with changes.** No remaining Critical/High finding under D43. The fixes remove the indefinite stale-batch delivery, but the one-second bound and HTTP/2 behavior still need correction.

Round-one findings:

- **High — slow clients (#98/#99): original exploit fixed; timing gaps remain below.** Stalled-write and mid-delivery revocation/expiry probes pass: buffered events do not continue under stale authority.
- **Medium — projector composition (#97/#98/#99): fixed.** Grant-before-actor is rejected; actor-before-grant succeeds and rebuilds without differences. The existing capacity batch/rebuild regression also passes; no conflicting batch semantics found.
- **Low — storage errors reported as revocation (#98): fixed for open streams.** Token and actor decoding-error probes produce `could_not_run/store_unreadable`.

New findings, by severity:

1. **Medium — Healthy idle HTTP/2 streams reset after one poll interval (PR #98; coverage missing in #99).**  
   [internal/api/events.go:147](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-sse/internal/api/events.go:147), also `send`: the write deadline remains armed after a successful flush. HTTP/2 actively resets the stream when it expires, including while idle. A healthy authenticated stream with `Poll=100ms` ended after **100.4 ms** with `INTERNAL_ERROR`, without any authority change. The equivalent HTTP/1.1 probe stayed open.

   **Fix:** clear the write deadline after each successful header/frame flush, before idle waiting; retain a separate authority-check schedule. Add real HTTP/2 idle-then-delivery/revocation coverage. An expired deadline cannot reliably be extended afterward. [Go documentation](https://pkg.go.dev/net/http#ResponseController.SetWriteDeadline)

2. **Medium — Successful slow writes extend the authority-check interval beyond one second (PR #98; coverage missing in #99).**  
   [internal/api/events.go:264](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-sse/internal/api/events.go:264): after the last frame in a partial batch, the handler sleeps a full poll interval regardless of time spent writing. A **750 ms** successful write followed by the default poll delayed revocation and expiry detection to **1.76 seconds**. No additional event frame escaped, so this is a bounded timing violation rather than the original indefinite leak.

   **Fix:** schedule the next check relative to the preceding authorization check, accounting for delivery time. Do not give terminal-frame delivery an unchecked additional full interval.

3. **Medium — TLS shutdown can exceed the write deadline by five seconds (PR #98).**  
   [internal/api/events.go:214](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-sse/internal/api/events.go:214): returning from a timed-out write is not always bounded by that deadline. Go’s HTTP/1.1 chunk writer can synchronously close TLS; `close_notify` installs its own five-second deadline. A real stored grant frame over TLS and a deadline-supporting `net.Pipe` held the handler for **5.99 seconds** with a one-second write budget.

   **Fix:** provide a transport-level hard-abort mechanism at the cutoff, closing the underlying HTTP/1.1 connection without waiting for graceful TLS shutdown. Keep HTTP/2 cancellation stream-specific. The HTTP/2 backpressure probe released its handler on time and preserved the reusable connection; no permanent leak was observed.

4. **Low — Five-millisecond transport deadlines make race tests unreliable (PR #98).**  
   [internal/api/events_test.go:131](/tmp/claude-1000/-home-mega/d7e41cde-3883-4e5c-8d98-04b890c5f4c4/scratchpad/wt-sse/internal/api/events_test.go:131): accelerating polling now also reduces real write deadlines to 5 ms. The required race suite repeatedly lost expected closure frames. A temporary test-only overlay increasing this to 100 ms passed the API race suite.

   **Fix:** give ordinary network tests scheduling headroom; reserve deliberately short deadlines for controlled timeout probes.

**Validation:** The requested race suite failed in `internal/api`; authority, identity, eventstore and fixtures passed. The separately executed `go test -tags adcmutation ./internal/fixtures` passed. Focused probes used external temporary overlays with Go 1.27.1. Checkout remains unchanged at `0e303b0`.

### Lead notes on round 2 (applied)

- **Medium, idle HTTP/2 streams reset (#98):** the write deadline is cleared after each successful header or frame flush, before any idle wait; authority checks keep their own schedule. Real HTTP/2 tests cover idling for several polls, then a delivery, then a revocation.
- **Medium, slow writes stretch the check interval (#98):** each check is scheduled from the previous one, and a frame's write deadline is that next check, so the gap between checks never exceeds the poll bound, whatever the write takes; a terminal frame is followed by nothing. A test with a slow but successful write checks the revocation is seen within the bound.
- **Medium, TLS shutdown outlives the deadline (#98):** servers register each connection through `api.ConnContext`; at a write cutoff on HTTP/1.1 the handler closes the raw connection beneath TLS (no `close_notify` wait). HTTP/2 keeps its stream-specific cancellation. A test over TLS HTTP/1.1 on an unbuffered pipe checks the handler returns within the budget.
- **Low, five-millisecond deadlines in tests (#98):** ordinary network tests poll at 100 ms; only the controlled timeout tests use short deadlines. `go test -race -count=3 ./internal/api` passes.
