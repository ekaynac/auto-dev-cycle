# PR #59 (lease and attempt wiring): Astra reviews

## Review of #59 (Astra, 2026-10-05)

Verdict: NO-GO

Seven High findings block approval. The revision increments and event-by-event rebuild work, but several invalid histories are accepted and faithfully rebuilt.

1. **High — Raw starts bypass token minting and cross-record identity checks.** `internal/lease/wiring.go:290–299` checks only that the attempt ID is new and running/open, then overwrites `unit_attempts`. I reproduced a second token-1 attempt while the original remained running. A start also accepted an arbitrary token, another unit, a nonexistent attempt lease, and a different `lease.attempt`; `FenceOutput` subsequently accepted it. **Fix:** validate the unit’s current attempt, first-token/replacement-token rules, reciprocal supersession references, and `attempt.Lease == lease.ID`, `attempt.Unit == lease.Unit`, `lease.Attempt == attempt.ID` before updating either projection.

2. **High — Lease termination leaves a running attempt able to publish.** `internal/lease/wiring.go:105–115,269–279` permits active-lease revocation, preemption, expiry and completion without examining its attempt. Each succeeded through `ChangeLease`, and `FenceOutput` still accepted the running attempt afterward. **Fix:** enforce stop/publication closure before revocation, preemption or expiry, and require a terminal attempt for completion. Enforce these conditions for raw events too. Any combined command changing the attempt must compare its revision as well as the lease’s.

3. **High — Supersession is atomic only when callers preserve the helper’s returned slice.** `internal/lease/wiring.go:159–168,303–306` accepts a standalone `attempt.superseded`; a replacement start can arrive in another transaction or never arrive. I committed the pair in separate commands, and rebuild accepted it. Reciprocal IDs are also unchecked. **Fix:** add mandatory writer-transaction validation requiring the complete matching pair, the current predecessor, and the next token. Keep that batch validation separate from the projector’s individually replayable fold.

4. **High — Projectors accept records the state machines cannot produce.** `internal/lease/wiring.go:277–281,303–313` compares selected fields rather than the complete derived record. Reproduced examples include a grant rewriting reservations, a stop changing the attempt’s lease and base, and supersession changing its unit and token. An unregistered hold also passes. Later snapshots can replace retained checkpoint/history fields. **Fix:** reconstruct each transition from the projected record and permitted transition inputs, run the full validator, and compare the complete resulting record with the payload. Apply invariant checks to supersession too.

5. **High — Restore and settlement publication guards can be bypassed.** `internal/lease/wiring.go:105,270–275` accepts the union of ordinary and evidence-target settlement tables; the helper takes the classification from a caller boolean. A raw settlement from `settling` accepted an invented restore receipt, publication reference, and a call listed as both settled and uncertain. Separately, the helper accepted publication of a nonexistent result from `settling_verified` without a companion publication event. **Fix:** derive the restore obligation from authoritative reservation/group facts, enforce the appropriate table and settlement validator, and require publication of the accepted draft in the same controller transaction. Until publication is implemented, reject publication-bearing settlements.

6. **High — Deferred result submission remains writable without its result.** `internal/lease/wiring.go:173–183` accepts `ResultSubmitted` with no submitted token or result input and closes publication without recording an accepted draft. Recovery cannot identify the promised result. **Fix:** require exact current-attempt/token fencing and the durable companion result event in one transaction, including validation of raw submissions. Otherwise disable this transition until that wiring exists.

7. **High — Deferred checkpoint validation allows invalid durable seals.** `internal/lease/wiring.go:178–183,307–313` accepts any published blob as a checkpoint. I sealed an attempt with non-JSON bytes. Schema validity, attempt/token/base/project/task/contract identity, and nested blob availability are unchecked. **Fix:** validate the immutable AttemptRecord and its referenced blobs, then bind it to authoritative projected state inside the writer transaction. Reject sealing until these checks are available; publish-before-reference alone is insufficient.

8. **Medium — `RequestLease` updates existing records without an expected revision.** `internal/lease/wiring.go:95–97,267–269` allows this supposedly creation-only helper to re-request a waiting lease using caller-supplied fields. I changed its priority without supplying any revision. **Fix:** make `RequestLease` require absence; route waiting → requested through `ChangeLease` with the expected revision and a derived record.

9. **Medium — Restart recovery remains unwired.** `internal/lease/wiring.go:187–203` accepts the previous running attempt after closing and reopening the wired store. `LoseOnRestart` is only a pure helper. **Fix:** add a recovery operation that durably records `lost/controller_restart` before scheduling or accepting outputs, with reopen tests preserving lease restore obligations. Production startup integration can remain in M1, but the fake scheduler must exercise this ordering; replay itself must not synthesize recovery transitions.

`make ci` and the specified sandboxed `Wired|Raw|Minting` smoke test passed. Local CI skipped unavailable shellcheck. Temporary adversarial tests confirmed the findings above and were removed; the checkout is unchanged. The three stated deferrals are **not safely deferred while their incomplete transitions remain writable**.
### Lead notes on round 1 (applied)

The projector is now the one place that accepts lease and attempt events; the helpers only propose them. Each event is
checked on its own, so a rebuild replays it the same way.

- 1 (raw starts): `attempt.started` must carry exactly `Start(id, lease.unit, lease.id, base)` (token 1, no
  predecessor) for a unit with no current attempt, a new attempt id, and the lease the state machine derives
  (granted → active, naming this attempt). A second token-1 attempt, a token-2 first attempt, another unit, another
  lease, or a lease naming another attempt is refused.
- 3 (supersession): one event, `attempt.superseded`, carries the retired attempt, its successor and the lease
  (`successor` joins the payload schema). The retired one must be the unit's current attempt and both records exactly
  what `Supersede` derives (next token, reciprocal references); the successor id must be new. Atomic by construction.
- 2 (lease termination): a lease leaves `active` only once its attempt's publication is closed, and completes only
  after its attempt completed.
- 4, 8 (derived records): every carried lease and attempt record must equal the state machine's result from the
  projected record (inputs rebuilt from the payload: hold, receipt, settlement, reason, stop/lost reasons, checkpoint,
  completion), with the registered holds. Reservations rewritten, an unregistered hold, a re-request rewriting the
  lease, a first request carrying a non-fresh lease: refused. `RequestLease` creates only; re-requests go through
  `ChangeLease` with the revision.
- 5 (restore and publication): restore transitions are refused until the resource-group projection says which leases
  hold an evidence target (`ChangeLease` no longer takes a caller's boolean); a plain settlement cannot publish or carry
  a restore receipt.
- 6 (result submission): refused, helper and raw, until its companion result record exists.
- 7 (seals): the projector reads the checkpoint blob: a valid AttemptRecord of this attempt, token, base tree and
  contract revision, with every blob it names published. (Project and task bind when units are projected.)
- 9 (restart): `RecoverAfterRestart` turns every unit's running attempt `lost/controller_restart` in its own command,
  tested across a store reopen; replay never synthesizes it. The fake scheduler will call it first.
- Mutation: 26 points, all killed. Size: `wiring.go` is about 470 lines with comments, over the ~400 guideline; the
  findings had to land together.

## Second review of #59 (Astra, 2026-10-05)

Verdict: NO-GO

Two first-round High findings remain partially unresolved, and the rework introduces a High replay-independence problem.

1. **Raw starts — Resolved.** First-attempt identity, token, lease linkage and unit uniqueness are checked.
2. **Lease termination — Resolved.** Publication must close before termination; completion requires a completed attempt.
3. **Supersession atomicity — Resolved.** One event carries the predecessor, successor and activated lease, with complete derivation checks.
4. **Partial record derivation — Resolved.** Existing records are compared against complete state-machine outputs; retained fields cannot be rewritten.
5. **Restore and publication — Partially resolved, High remains.** Publication and fabricated receipts are refused, but unknown restore obligations default to ordinary settlement.
6. **Result submission — Resolved by disabling admission.** Both helper-generated and raw submissions are refused.
7. **Checkpoints — Partially resolved, High remains.** Schema, attempt/token/base/contract and referenced blobs are checked; project/task identity is not.
8. **RequestLease — Still open, Medium.** An unchanged waiting lease can still be re-requested without an expected revision.
9. **Restart recovery — Resolved at the wiring layer.** Explicit recovery durably closes running attempts; reopen tests exercise recovery before output acceptance. Startup integration remains deferred as agreed.

### High — Remaining findings

- **Unknown restore obligations are treated as absent.** `internal/lease/wiring.go:334` passes `false` to `ApplyLease` unconditionally; the helper does likewise at line 126. Disabling restore transitions does not prevent bypassing restore through ordinary `settling → settled`. An adversarial test committed a raw settlement for an unclassified slot reservation, although the evidence-target state machine rejects that transition. **Fix:** derive classification from authoritative group facts and reject settlement when classification is unavailable. Until that exists, admit only leases demonstrably free of restore obligations.

- **Seals still accept arbitrary project/task identities.** `internal/lease/wiring.go:452` omits both bindings. I successfully sealed a schema-valid checkpoint carrying arbitrary project and task IDs while preserving the checked attempt/token/base fields. The lead’s stated deferral leaves this part of finding 7 writable. **Fix:** bind both fields through authoritative unit/task state inside the transaction, or refuse sealing until that binding exists.

### High — New finding

- **Replay depends on external state rather than the recorded history alone.** `internal/lease/wiring.go:424` re-executes checkpoint admission during replay, including `Open` at line 439 and `Has` at line 462. After a valid seal and successful rebuild, removing only its nested trail blob made the unchanged log fail rebuild. Documented retention permits purging blob contents, so historical projections become unrebuildable even though their records are fully present in events. The mutable `Holds` map at line 334 introduces another external dependency: removing a previously accepted hold also broke rebuild.

  **Fix:** separate mandatory transactional admission checks from the deterministic replay fold. Record any metadata needed for replay in durable events; keep historical hold validation tied to immutable, versioned vocabulary. Preserve blob validation for new admissions without requiring historical blob availability to reconstruct projections.

### Medium — Remaining finding

- **`RequestLease` still lacks its promised absence check.** `internal/lease/wiring.go:112` merely proposes an event. The projector legitimately permits waiting → requested, so calling `RequestLease(tx, requested())` after waiting succeeds and advances the revision. The new test only tries a rewritten priority, which fails for a different reason. **Fix:** check absence inside `RequestLease`; require revision-bearing `ChangeLease` for re-requests. Add the unchanged-record regression case.

Sandboxed lease, event-store and schema tests passed. Temporary adversarial tests confirmed the remaining issues; the checkout is unchanged.
### Lead notes on round 2 (applied)

- High (restore obligations): a lease with a slot reservation does not settle. Evidence targets are one-slot groups
  (12, 13), so only a lease with no slot reservation is known to owe no restore; the others settle once the
  resource-group projection exists. Decided from the lease record alone, so replay is deterministic.
- High (seal identity): the projector takes a `Units` binding (unit → project and task, from authoritative state);
  the AttemptRecord's project and task must match it, and with no binding no seal is admitted. Production supplies it
  when units are projected; until then seals are refused, which the lifecycle's tests cover with a test binding.
- High (replay independence): `eventstore.Tx.Replaying()` marks a rebuild's replay. Admission checks that read
  state outside the log run only on admission: the checkpoint blob and its named blobs, the unit binding, and the
  hold registry (on replay the recorded hold is accepted as it was admitted). Purging a sealed record's trail blob and
  retiring its hold, then reopening, still rebuilds with no difference.
- Medium (RequestLease): it checks absence again; an unchanged waiting lease is not re-requested without
  `ChangeLease` and its revision.
