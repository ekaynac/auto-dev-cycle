# PR #54 (authority decision core): Astra reviews

## Review of #54 (Astra, 2026-10-05)

Verdict: NO-GO

1. **High — Protected changes can authorize forbidden widening.**  
   [internal/authority/decide.go:106](/tmp/adc-pr54-review-AI0qFP/internal/authority/decide.go:106): supplying either protected-document or topology action with its class plus `policy.widen_data` returns **Allow** for operators/system actors and **Propose(Human)** for a covered supervisor. Reproduced for both actions and all three actor kinds. Note 04 explicitly requires refusal: these operations cannot widen authority or data policy, even with confirmation.

   **Fix:** enforce this prohibition before the operator/system shortcut and supervisor policy selection. Refuse protected changes containing forbidden widening, using a registered reason. Add regression tests across both actions and all actor kinds. This checks already-computed classes; implementing the classifier can remain deferred.

2. **High — Self-grant refusal depends on the endpoint name.**  
   [internal/authority/decide.go:124](/tmp/adc-pr54-review-AI0qFP/internal/authority/decide.go:124): a covered `profile.adopt` request whose effective classes contain `grant.create` or `grant.extend`, with the acting supervisor as grantee, returns **Propose(Human)** instead of `self_grant_refused`. An omitted grantee also passes this check. All four cases reproduced. Confirmation must not make a prohibited self-grant permissible.

   **Fix:** apply the self-grant prohibition whenever the effective change creates, extends or widens a grant, irrespective of action name. Require a reliably derived grantee and fail closed when it is missing or ambiguous. Retain the direct grant-action checks and add cross-action regression cases.

3. **Medium — Weaker overrides are ignored rather than refused.**  
   [internal/authority/decide.go:141](/tmp/adc-pr54-review-AI0qFP/internal/authority/decide.go:141), with the behavior explicitly asserted at [internal/authority/decide_test.go:137](/tmp/adc-pr54-review-AI0qFP/internal/authority/decide_test.go:137): an `independent_review` override for an effective `policy.widen_data` change produces **Propose(Human)**. This preserves the stronger default, so it is not an authorization downgrade, but contradicts #51’s carried-forward requirement to **refuse weaker overrides**.

   **Fix:** compare each applicable override against the class-derived default and refuse weaker values with a registered reason. Then take the strongest valid override across covering grants. Change the existing test to expect refusal.

Only findings 1–2 block.

The remaining core checks are sound for a validated registry and authoritative request data: unknown/deprecated actions and unknown classes refuse; empty classes mean no sensitive change; supervisor grants require matching ownership, project and action, nonrevocation, and `valid_from ≤ now < expires_at`. Malformed timestamps fail closed. Strongest defaults and overrides win, and KA1 requires human confirmation for every supported actor kind. The five new reasons and generated constants are consistent.

The PR’s contract choices are acceptable with explicit boundaries:

- **System as operator:** reasonable for adcd’s own components, but document this extension to note 04. Authentication must prevent callers from selecting system identity.
- **Future actor revocation:** the timestamp interpretation is consistent, including refusal at equality. `Now` must come from the controller; an immediate revocation command must not accept a caller-selected future effective time.
- **Revoked-grant set:** reasonable as a projection input. Supply it transactionally with current grants. Strongest confirmation does not implement scope supersession: projections must remove superseded wider grants and refuse conflicting authority with `ambiguous_state`.

The later classifier, proposal and hook PRs must still enforce:

- Server-computed effective changes and grantees; classification failure must never become empty classes. Reject unknown/deprecated actions before classification.
- Authenticated actor/token resolution, grant provenance, current projections and seat ownership.
- `Propose` records pending work without applying the requested mutation.
- Exact proposal/state binding, expiry, independent-review applicability, dashboard-only WebAuthn and atomic challenge consumption.
- Transactional apply-time revalidation of proposer, original grant, scope, policy and confirmer; invalidate stale authority rather than substituting another grant.
- Read scopes, blob-reference authorization and stream revocation/expiry handling.
