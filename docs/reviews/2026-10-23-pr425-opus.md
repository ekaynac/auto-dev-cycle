### Obligations

Correct `docs/design/m0/02-vocabulary.md:97` and the PR text to match. Or have the scan treat an expression whose free identifiers include a parameter as unattributed, and state `ni.SignalInstance()`. Better still, check each row's sample through the site's own formatter, not a hand-written string.
- **L2** (OBLIGATION, Low): `IsImageSignal` refuses every rune ≤ `' '` and 0x7f (`internal/dispatch/launch.go:257`). `PinnedImage` refuses only `@`, `\t`, `\n`, `\f`, `\r` and space (`schemas/config/project-profile.json:316`). So a pin with `\v` or another C0 control passes the profile and is held `wrong_owner`, but is never offered. That is harmless today, because such a pin never resolves and M1 profiles do not change, but it is not "one rule with imageSignal". Align the schema's set with the parser's, or refuse such pins at profile load.
