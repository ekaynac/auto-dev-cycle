## External review of #259 (Astra, 2026-10-14)

Verdict: NO-GO

1. **High — The Clock ages time spent waiting to commit as though the request had already been sent.**  
   **Location:** `internal/modelcall/clock.go:43`, `internal/modelcall/modelcall.go:420`.

   `noting` saves the monotonic timestamp before `SubmitApplied`, and a successful commit never updates it. The gateway starts its ten-minute upstream timeout only afterward, at `internal/gateway/gateway.go:471`.

   Concrete sequence: note the floor at minute 0; wait two minutes for the writer; commit and send at minute 2. At minute 11, the Clock considers the floor old although the request can run until minute 12. A forward wall-clock step makes the persisted-time check pass too. Once the run has ended, reconciliation can therefore query prematurely, discard the floor’s output allowance, and settle against incomplete usage. If the response yields no readable gateway count, that underestimate can persist. This leaves entry 77’s accounting failure reachable.

   **Fix:** keep an uncommitted note unconditionally young, then establish its monotonic timestamp on successful commit. Also enforce the assumed bound between that timestamp and sending. Add a deterministic delayed-commit case with a forward wall step and an outstanding request.

2. **Medium — A failed concurrent floor submission can delete another submission’s committed note.**  
   **Location:** `internal/modelcall/clock.go:43–46`.

   For the same `(call, sequence)`: submission A inserts the note; B finds it already present and commits successfully; A’s failure callback then deletes it because A originally had `loaded == false`. The committed floor now has only wall-clock protection. The sequential failure cases in `clock_test.go` do not cover this ordering.

   Normal gateway requests receive distinct sequences, which limits present exposure, but neither `Recorder.Count` nor `Clock` enforces serialization for repeated keys.

   **Fix:** track pending owners and committed state per key, or serialize the entire note/commit/callback operation for that key. A failed owner must not delete protection retained by a successful owner. Add the overlapping success/failure case.

3. **Medium — The model’s settlement oracle shares the implementation predicate it should check.**  
   **Location:** `internal/recovery/model_test.go:173`, `internal/recovery/model_test.go:282`.

   Placement, `Replaceable`, the `StartedEarly` assertion, and recovery completion all depend on `lease.Ended`. If that predicate incorrectly admits `settling`, the model can start A2 while L1 remains settling and still label that start timely. Its completion check can also accept the stranded L1 after A1 becomes superseded.

   The listed fault fixtures discriminate their explicit faults, but the baseline invariants do not independently establish settlement-before-replacement against this mutation.

   **Fix:** assert the expected terminal lease states directly, independently of `Ended`, and require L1’s reservation to have transferred or returned before A2 starts. Add a fault fixture for an erroneous terminal-state predicate.
