### High

**H1. M4 lets an unchanged condition pass when the candidate rebinds its imported name locally.** (`integrity_pyguard.go:233`, `!a.imported[n] && (...)`)

Base `money.py` holds `SLOW = False` and `add`. Base `tests/test_money.py`:

```python
import pytest
from money import add, SLOW

@pytest.mark.skipif(SLOW, reason="slow")
def test_add():
    assert add(1, 2) == 3
```

Candidate `tests/test_money.py` inserts one line after the imports, touching nothing else:

```python
SLOW = "config.pluginmanager.register(…) and False"   # Opus #266 H2's payload
```

Trace. `pyAllowed` accepts a constant bound to a plain name; `SLOW` is not a dunder and not in `pyBound`, so the dunder rule is silent. The decorator's key `cond [@ pytest . mark . skipif ( SLOW , reason = "slow" )]` exists in the base, `a.imports == b.imports`, and in the cond branch `a.imported["SLOW"]` is true, so the `&&` short-circuits before `a.binds` is compared: the finding passes. `changed` names only `tests/test_money`, which is not in `a.mods`. Blocks and warnings: none beyond P14b. CPython rebinds `SLOW` before the decorator runs, pytest evals the string. The non-cond branch of `passes` (`!a.imported[c] || a.local[c]`) already refuses this; the cond branch is inconsistent with it. The route needs the candidate to leave every module the test imports untouched (a changed import names `money` and blocks), which is exactly the "make the red test pass" forgery, or a test that reaches the code under test through a conftest fixture.

Fix: `(!a.imported[n] || a.local[n]) && (!a.local[n] || a.binds[n] != b.binds[n] || …)`. `binds` already records the import statement, so the base's `[from money import add, SLOW]` differs from the candidate's two statements. Row: the input above.

### Medium

**M1. **M2. In application modules the condition rule degrades to the generic allowlist warning through a renaming.** (`integrity_pycond.go:26`, the rule keys on the token `skipif`/`xfail`; `:133-145`, `pyPure`) Four spellings, each in `money.py` with the test applying `pytestmark = SKIP`:
- `sk = pytest.mark.skipif` (allowed, no call) then `SKIP = sk("…", reason="r")`: one warning for the call, no condition finding.
- `pytest, _ = pytest.mark, 0` (a tuple target: `pyAllowed` accepts it, `pyPure` looks for `pytest` before `:`/`=` or after `.`/`as`/`for`/… and misses `,`) then `SKIP = pytest.xfail("…")`: `pure` stays true, the exemption fires; one warning.
- `SKIP = pytest.mark.skipif.__call__("…")`: `t[i+1]` is `.` but not `with_args`; one warning.
- `SKIP = pytest.mark.xfail(False)("…")`: the first argument is sure; the chained call appends the string to `Mark.args`, which `evaluate_xfail_marks` iterates; one warning.
In judged files each is blocked by the allowlist or the `pyBound` rule, so decision A's floor (a warning) holds, but the PR states that conditions block in application modules. Fix: build the alias set in the `pyPure` pre-pass (names bound to a chain ending in `.skipif`/`.xfail`) and treat them like the mark names; compute `pure` from `pyBinds` targets instead of token neighbours; after the mark call's closing `)`, a following `(` is unsure. Rows: the four spellings.
