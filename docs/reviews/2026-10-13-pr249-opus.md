## Opus pre-review of #249

Verdict: GO with changes

This review covers commit 326bb0a. Under the race detector, `go test -race` passes for `internal/modelcall`, `internal/gateway` and `schemas`. I reran mutation M2 (the `pending` check dropped) and mutation M3 (the groups dropped). Both turn the tests the PR names red: M2 fails the crash test with "re-sent after its crash: 200, upstream saw 1", and M3 fails the commit test and the crash test. A temporary probe sent 16 concurrent first requests on one token. All 16 returned 200, the store held exactly 1 binding, and the effect was `pending` and bound at every upstream receive. The same probe found H1. Nothing in adcd imports `internal/modelcall` or constructs a gateway, so the item is inert. `markPending` runs at adcd's start today (`daemon.go:148`).

H1 must be fixed before merge. The other findings are for this PR or for the P22a/P20 follow-ups, as noted.

### High

**H1. The gateway skips the intent for a call already intended under another binding. A second binding then sends under the first binding's intent.** (`internal/gateway/gateway.go`, `intend`, around +340; `intended map[types.CallID]bool`, around +92; `Bind`, around +121)
- **What happens:** the cache of intended calls is keyed by the call id only. The check `slices.Contains(maps.Values(g.bound), b)` runs only when the flag is set. On later requests, `intend` returns early on `intended[b.Call]` without comparing the binding.
- **Probe:** the probe bound `cal_X` to (L, A1) and sent, which recorded the intent for A1. It then left that token bound, moved the lease to A2 and bound `cal_X` again to (L, A2) with a second token. The second token's request returned **200 and reached the upstream**. `Intend` never ran, so the `ErrBound` check in `modelcall.Intend` never saw it.
- **Effect:** the durable binding says the call belongs to A1, but the bytes were sent for A2. With the lease varied in the same way, they could be sent for another lease or another unit's lease. Usage would then be charged to the wrong attempt, lease and groups (I9). This is exactly the "superseded attempt or other lease binds a call" case the row forbids.
- **Gap in the gateway:** `Bind` accepts any non-empty `Call`, with no `cal_` format check and no uniqueness check. Today only P22a's correct call minting prevents this, and the gateway is meant to be the enforcement point.
- **Fix:** key the cache by the whole binding (`map[Binding]bool`, or by the token's hash). Alternatively, make `Bind` refuse a call that is already bound under a different `Binding`. Have `Bind` also run `ids.Check(call, "cal")`. Make `Unbind` forget only its own entry: today `delete(g.intended, b.Call)` also clears the flag for any other token on the same call.
- **Test:** two tokens on one call with different attempts. The second must get `intent_unrecorded`, and the upstream must see nothing from it.

### Medium

**M1. The fold accepts a `model_call.intended` that has no effect and no running lease.** (`internal/modelcall/modelcall.go`, `Project`, around +134)
- **What it checks:** `Project` checks only that the subject is the call and that the call is bound once.
- **Proof:** the PR's own `TestTheRequestAndTheFold` appends a bare `model_call.intended` with no `eff_` intent and no lease in the projection, and the fold accepts it.
- **Scenario:** once P22a registers the kind, any applied command that may append it can create a binding that recovery (`OfLease`) trusts. That binding can name groups that are not the lease's, or name a lease that never ran the attempt. Nothing on replay refuses it.
- **Fix:** in `Project`, require `tx.LoadEffect(EffectOf(m.Call))` to exist, with kind `model_call`, target equal to `m.Destination`, and a request digest equal to the payload's digest. Also refuse any `model_call.intended` whose command is not `model_call.intend`, if the hooks expose that. Checking the lease state on fold is optional, because the effect check already ties the event to `Intend`.
- **Test:** an orphan event is refused, and an event whose payload differs from the effect's request is refused.

**M2. The safety of the `pending` no-op rests on an assumption that is recorded only in prose.** (`modelcall.go`, the package doc and `Intend`'s `e.State != EffectPending` branch)
- **The assumption:** re-intending a `pending` call is a no-op, so the call is sent. That is safe only if every process that builds a gateway over this store ran `MarkPendingUncertain` first.
- **True today?** Yes for adcd: `daemon.go:148` runs it, though it is skipped for `offline` and for a freshly created store. But the obligation appears only in the PR body and a code comment. It is not in the P22a row of the slice plan, and no test fails if a gateway host skips it.
- **Scenario:** an exit-run harness constructs `Gateway` + `Recorder` over a reopened store without the restart rule. A call left `pending` by a crash is then re-sent, which is a double send and a double charge.
- **Fix:**
  - Record it as a P22a obligation in `00-slice-plan.md`, for example: "a gateway is constructed only after `MarkPendingUncertain`".
  - Better, make it structural: have `Recorder` refuse (or `New` panic) unless the store reports that the restart rule ran in this open. A store-level `RestartMarked()` flag would do. Alternatively, have the no-op require that this `Store` instance created the effect.

**M3. The effect's target is the shared destination slug, which conflicts with I6's "one live operation per target".** (`modelcall.go` `check`/`Intend`; `schemas/records/model-call.json` "destination")
- **Scenario:** after a crash, A1's call is `uncertain` on target `stub`, and A2's new call is `pending` on `stub`. That makes two live `model_call` effects on one target. `Tx.LiveEffect("model_call", "stub")` would then return `ErrAmbiguousEffect`. Any generic I6 guard, or P20's one-runner-per-effect lookup by target, would either block A2 or fail ambiguously.
- **Fix:** either state in the I6 rows of `01-invariant-inventory.md`, and in the kind's doc, that `model_call` is exempt from one-live-per-target (its exclusivity is per call, via `EffectOf`), or make the target call-unique and keep the destination only in the request.

### Low

- **L1. `groups` has no `minItems: 1`** (`schemas/records/model-call.json`, `groups`). A lease with no reservations produces a binding that charges nothing, which silently breaks I9's "charged once". Add `minItems: 1` (and a `maxItems` bound matching the registry's group count). Alternatively, have `Intend` refuse a lease with no reservations.
- **L2. An in-flight request can send after its token is unbound.** The `bound` check in `intend` only guards the cache. A request that passed `intend` before `Unbind` still sends; this is P11 behaviour and not new. When P20 moves the effect from `pending` to `observed` at run end, that request's usage arrives after the effect left `pending`. Record for P20/P12b that late usage on a non-pending `model_call` is expected, not an error.
- **L3. `Intend` re-derives the groups from the lease's current reservations on a re-intend.** If P12b changes reservations mid-lease, a re-bind of a pending call is refused with `ErrBound`. This fails closed, but the cause looks misleading. Consider comparing only call, attempt, lease and destination on the no-op path. Alternatively, document the behaviour.
- **L4. The `model_call.intend` action is not yet wired into authority.** It has no matrix entry and no Identify/Authorize rules. A proposal disposition already maps correctly to `intent_unrecorded`, because `SubmitApplied` errors on a non-applied outcome. List the action in the P22a row so the authority wiring is not forgotten.
- **L5. Usage measurements are not checked against the binding.** `usage-measurement` carries its own `attempt` and `lease`, and nothing checks them against the `model_call` binding of the same `cal_`. That belongs to P12b, which should check measurement lease and attempt against `modelcall.Of(call)`. Note it in the P12b row.

### What holds

- **Intent before egress:** the intent is checked and committed inside one writer transaction, under WAL with `synchronous=FULL`, before the request is built, so nothing is sent without a durable intent.
- **Refused requests:** a request refused before the intent leaves no intent. An intent whose send then fails stays `pending` and becomes `uncertain` at restart, which is the intended semantics.
- **Crash test:** it discriminates. The restarted gateway refuses with `intent_unrecorded`, and `retried` on the uncertain effect is refused.
- **Gateway contract change:** it does not weaken P11's checks. The lease is still read before the body, and causes are never echoed. P13 does not construct a gateway, so the now-required `Intents` and `Call` break nothing outside `internal/gateway`.
- **One effect per call:** consistent with the usage ledger keyed by `(call, sequence)` and with X3's per-call reconciliation.
- **Size:** 315 of 400.
