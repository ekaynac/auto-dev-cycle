## Opus pre-review of #246

Verdict: NO-GO

One High finding blocks the PR: the launch readiness check fails open. I confirmed it by running a probe test. The fix is small. The rest of the PR holds up:
- **Request and grant are atomic.** A capacity refusal leaves no lease and nothing reserved.
- **A miss is one command:** `start_refused`, then `released`, then `hold_raised`.
- **Fencing is right.** `lease.StartNext` takes the unit's current attempt from `unit_attempts`. A first attempt gets token 1, `Supersede` accepts only a sealed attempt and gives it the next token, and the projector refuses a second first attempt.
- **`Admits` runs before any reservation.** The node is checked as claimed and in the card's project before the reservation.
- **Nothing outside `internal/dispatch` imports the package, so `launch` stays inert.**
- **Tests pass.** `go test` passes on dispatch, lease, graph, registry and capacity, and `make fixtures-contract` passes.

### High

**H1. Launch readiness fails open. A zero `Readiness` says yes, even with no image store and no credential implementation** (`internal/dispatch/launch.go:34-36`, `:80-91`, `:128-136`)
- **What happens.** `Launch` trusts whatever `Readiness` the caller passes in. A nil error means ready.
- **Probe result.** `Dispatcher{Registry: reg}` (no `Images`, no `Credentials`) with `Launch(..., Readiness{})` gave:
  `err <nil> miss <nil> lease active out 1000 attempt true`
  The credentialed `stub` destination launched with no gateway and no image check. This breaks question 4: P11's seam is fail-closed only if the caller remembers to call `Observe`.
- **Readiness is not bound to anything.** It records no executor, destination, credential reference or image. So `Observe(ctx, card, X)` followed by `Launch` on a lease for executor Y also passes.
- **What is compared in the command:** only the four placement digests (policy, registry entry, image string, roster). Nothing ties what `Observe` saw to the lease.
- **Fix:**
  - Make `Readiness` opaque. Give it unexported fields that only `Observe` sets: an `observed` flag, the executor, the destination id, the credential reference and the image reference. Its zero value must mean not ready.
  - In `miss`, require that binding to match `l.Executor`, the current registry entry's destination and `credential_ref`, and `card.Image`.
  - Independently, `miss` should fail closed when `d.Images == nil`, or when `e.CredentialRef != nil && d.Credentials == nil`.
  - Add two tests: `Dispatcher{}` with `Readiness{}` must give a miss, and readiness observed for another executor must give a miss.
- **Fault evidence gap.** The PR's mutation evidence goes through `Observe`, so it cannot detect this hole.

The TOCTOU gap between `Observe` and the command is otherwise acceptable. Image and credential state live outside the log, and P9's sandbox refuses a digest mismatch when it creates the container. That only holds once the observation is bound to what it observed.

### Medium

**M1. A second live lease per unit is allowed (deviation 5), and it double-reserves** (`internal/dispatch/dispatch.go:95-122`)
- **Probe result.** Two `Match` calls on one claimed node granted two leases, with 2000 tokens outstanding.
- **What does not go wrong.** There is no double rail spend and no race. `StartNext` refuses the second lease while the first attempt runs (`Supersede` needs a sealed attempt), and P17 counts attempts.
- **What does go wrong.** The second lease holds capacity until something expires it.
- **Answer: yes, `match` should refuse it.** It is the one entry point, and leaving this to the reconcile's discipline is weaker than enforcing it in the command.
- **Fix:** refuse when the unit already has a lease that is requested, waiting, granted or active, or a running attempt. Either add a small `unit → live lease` projection to the lease projector, or scan the leases (`tx.Keys` already exists). This must land no later than P22a. If it is not fixed here, record it on #226.

**M2. A zero-token reservation is granted** (`dispatch.go:109`)
- **Probe result.** `Card.Tokens = 0` granted a lease that reserved `{Amount:0 Unit:tokens}` on a direct API. The schema allows `minimum: 0`.
- **Why it matters.** This bypasses Q8's sizing and the capacity limit.
- **Fix:** refuse `card.Tokens <= 0` for a tokens reservation before reserving, as a refusal from the placement checks or as an error.

**M3. Any `Placement` error becomes "no longer claimed"** (`launch.go:116-117`)
- **What happens.** Store read errors, JSON decode errors and `registered`'s other errors (for example nil families, or a broken roster) all turn into a refusal and release with **no hold**. The error is swallowed.
- **Result.** A claimed node is left with no lease and no hold.
- **Fix:** have `Startable` return a typed refusal (for example `ErrNotStartable`). Map only that refusal, and `ErrNotIndependent`, to a miss. Propagate every other error.

### Low

**L1. The miss reason can exceed the schema's limit** (`launch.go:124`)
- **What happens.** The reason concatenates `now[i].check.Detail`, which may be up to 4096 characters (`Admits`'s error text). The free-text `lease.start_refused` reason allows at most 1024 (deviation 3).
- **Result.** An overlong reason fails the whole command, so the lease is neither refused nor released and no hold is raised.
- **Fix:** truncate the reason, or name only the check. Deviation 3 is otherwise acceptable.

**L2. The hold kind for a roster change** (`launch.go:113-115`)
- **What happens.** `ErrNotIndependent` gets the hold `source_invalid_config`. The graph evaluator holds the same condition on `reviewer_unavailable` (signal `probe`).
- **Fix:** use `reviewer_unavailable`, or justify the choice. The credential and image hold kinds match I21.
- **Evidence.** This case was not hand-mutated, so run its mutation.

**L3. The placement digests use Go's JSON form** (`dispatch.go:135-138`, `:181-188`)
- **What happens.** The digests are `json.Marshal` output of generated types. A generated-type change at an upgrade would make every granted lease miss with `source_invalid_config`.
- **Replay is not affected.** The fold never recomputes these digests; they are compared only at launch.
- **The policy digest covers the caller's `Card.Policy`,** not a profile revision. I10's fold/replay row asks for "registry or profile revisions".
- **Fix:** acceptable for M1. Either digest the canonical registry entry bytes and a profile revision, or note the limitation in I10.

**L4. A project mismatch at `Launch` returns an error with the lease still granted** (`launch.go:118-119`)
