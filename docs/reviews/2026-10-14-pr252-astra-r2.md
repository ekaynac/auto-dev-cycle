1. **High — H4 remains open: ancestry resolution loses content identity and can skip a required lookup.**  
   `internal/accept/intent.go:25`, `:70`, `:75`, `:83`

   `restricted` contains content digests, but `Ancestry` returns only parent IDs. Consider a valid ancestor `R` whose ID is `"acceptance-ref"`, whose `ContentDigest` is restricted digest `A`, and whose lineage is empty. A summary with lineage `[R.ID]` passes: the honest resolver returns an empty lineage for `R`, and nothing checks `R.ContentDigest`. The tests hide this distinction by making every ref’s ID equal its content digest (`intent_test.go:31`).

   There is also a skipped-lookup case: if an input’s content digest equals an ancestor’s ID, that ID is already in `seen` before its lineage entry is visited. Its recorded parents—including restricted ancestors—are never resolved.

   Finally, neither starting identifier is resolved. An input with empty lineage passes with a nil resolver, contrary to the stated unconditional missing-resolver refusal.

   **Fix:** resolve authoritative records carrying both content identity and complete lineage, including the starting input. Separate checking a digest from marking a ref’s ancestry fully visited. Refuse missing/incomplete records and a missing resolver. Add valid-sized cases with non-digest IDs and an ancestor ID equal to the input’s content digest.

   A resolver that falsely reports incomplete ancestry as complete remains a trusted-controller defect; this function cannot discover withheld records independently. That trust requirement must be explicit.

2. **Medium — M6 still leaves stderr unbounded, regressing diagnostic capture.**  
   `internal/accept/accept.go:264`, `:273`

   Only stdout passes through `LimitReader`. Stderr accumulates in an unrestricted `bytes.Buffer`, including while stdout remains empty. The previous `cmd.Output()` used bounded prefix/suffix stderr capture. [Go implementation](https://github.com/golang/go/blob/go1.25.0/src/os/exec/exec.go#L950)

   A concrete hostile-tree source is many nested `.gitignore` symlinks with long paths: Git’s ignore-file reader refuses following them and emits path-bearing diagnostics. These arrive during `Diff`, before `Accept` rejects symlinks. [Git ignore-file reader](https://github.com/git/git/blob/master/dir.c), [diagnostic implementation](https://github.com/git/git/blob/master/wrapper.c)

   **Fix:** bound both streams while draining them concurrently. On either overflow, kill and reap git and return `ErrTooLarge`. Do not merely stop reading stderr and then wait. Add a stderr-heavy case with little stdout.

3. **Medium — The ancestry cap bounds visited identities, not queued work or memory.**  
   `internal/accept/intent.go:70`, `:79`, `:94`

   Every resolved parent list is appended wholesale; duplicates are removed only when dequeued. A dense, acyclic graph of fewer than 10,000 ancestors can therefore enqueue tens of millions of entries without exceeding the visited-node cap.

   Cycles terminate through `seen`. The cap also fails closed when another unseen ID is encountered; it does not silently truncate and accept. However, `len(seen) > maxAncestors` permits 10,001 seen identifiers, counts the starting identifiers, and may finish successfully at that size.

   **Fix:** deduplicate before enqueueing, enforce the intended inclusive node limit, and bound edges/work and identifier bytes separately. Add cycle, exact-boundary, beyond-boundary, and dense-graph cases.

4. **Medium — Oversized output is not consistently converted into an unsafe-output verdict.**  
   `internal/accept/accept.go:135`, `:167`

   The raw-diff call maps `ErrTooLarge` correctly. The final `cat-file tree` does not. A sufficiently wide base tree, even with an empty patch, can exceed the output bound here and return an error with no refusal blocks. The code also computes `TreeDigest` from the returned nil bytes before returning that error.

   **Fix:** consistently translate candidate-size failures into `unsafe_output`, including final tree serialization, and populate accepted-tree fields only after successful reads. Add a lowered-bound case where the raw diff fits but the tree object does not.

5. **Low — M6’s mutation proves overflow rejection, not bounded reading.**  
   `internal/accept/accept_test.go:387`

   Removing both the read limit and overflow check makes the deletion test fail. But replacing the implementation with unbounded buffering followed by the same typed size check would pass this test while restoring the original memory problem.

   **Fix:** distinguish the streaming limit, termination, and error-classification mutations. Use a controlled subprocess case that verifies bounded consumption and prompt reaping, with a short deadline.
