## Opus pre-review of #308 (2026-10-20)

Verdict: GO with changes

The required command fails on this head. `go test -count=1 -race ./internal/gateway/...` failed with a data race in `TestInFlightCap` in 5 of 6 runs. Excluding that test (`-skip TestInFlightCap`), the race run passes in 12.9 s. The accounting holds: no undercount was found. One race lets a request write an intent and a floor after `Unbind` returns (M2). All 7 mutations are killed, but one only by the 10-minute `go test` timeout. Three extra mutations survive.

### Medium

**M1. `TestInFlightCap` races and is flaky.** `internal/gateway/serve_test.go:98-103`
- **Input:** `go test -race -run TestInFlightCap`. It failed 5 of 6 runs with a race report at `serve_test.go:101`: the test reads `g.inflight` while the deferred `leave` (`serve.go:92`) is still running. Without `-race` it failed 2 of 200 runs: "in flight after every request ended", once with a populated entry and once with an empty inner map.
- **Cause:** the client sees the end of the response before the handler has run `g.count` and `leave`. The same gap can also make the post at line 98 ("the slots are free again") come back 429 `in_flight_cap`. That case was not observed, but nothing prevents it.
- **Fix:**
  - Pass a `done` channel to `serveOn` and wait for `MaxInFlight+1` handler ends before line 98.
  - Read `len(g.inflight)` under `g.mu`, as `TestUnbindWithARequestInFlight` already does at :223.

**M2. A request admitted before `Unbind` still records an intent and a floor after it.** `internal/gateway/gateway.go:452-466`
- **Input (probe):** a `Leases` reader that blocks and ignores `ctx`. Admit a request, call `Unbind(token)`, then release the reader.
- **Result:** after `Unbind` had returned `Observed{}`, the request recorded `intents 1` and a floor (`seq 0 {In:5 Out:0 Observed:false}`). The upstream saw 0 requests: the transport refuses a cancelled context before it dials.
- **Why it matters:** this is not an undercount but an overcount. A floor for a request that was never sent leaves the call owing its reservation until a provider reconciliation, and the intent and floor become durable after the attempt has ended. That contradicts the PR's "nothing they do afterwards". Readers that honour `ctx` refuse earlier, so the outcome depends on 22a-5's readers.
- **Fix:**
  - Pass `f` into `forward`.
  - Under `g.mu`, where `seq` is taken (`gateway.go:459-462`), refuse `unbound` when `f` is no longer in `g.inflight[key]` (or `ctx.Err() != nil`). Do the same before `intend` (:452).
  - Document that a floor decided before `Unbind` may still commit just after it, or have `Unbind` wait for the floors already decided.

### Answers to the five questions

1. **Accounting:**
   - **Cap refusals:** a request refused by the cap is never sent: `enter` runs before `forward`.
   - **Cut, cancelled or stalled requests:** a request cut by `Unbind`, a write deadline or a failed flush ends with `whole=false`, so its floor stands. Flush errors now end the copy, where main ignored them, which is more conservative.
   - **Floors:** every request's floor is committed before `client.Do`, so no path leaves less than the floor.
   - **Unbind:** cancellation is asynchronous, so a request already writing when `Unbind` runs may finish writing just after it returns. That request's floor is already durable. The only post-`Unbind` writes are M2's.
2. **The cap:**
   - **Two requests at the limit:** the binding check, the cap and the insert in `enter` all happen under `g.mu`, and `Unbind` takes the same lock, so two requests racing for the last slot are decided atomically.
   - **Slot leaks:** none. The deferred `leave` also runs on a panic (net/http recovers it), and every early return comes after the defer.
   - **A token unbound mid-request:** `Unbind` cancels its requests and drops its in-flight entry; a later `leave` on the deleted entry is harmless.
3. **Timeouts:**
   - **30 s per write:** the deadline is reset before each write, so upstream pauses do not count. Only an adapter that stops reading for 30 s on one write of at most 32 KiB is cut.
   - **The 1 min `ReadTimeout`:** it does not cut long requests. Go's net/http clears the read deadline when it starts its background read at the end of the body (`startBackgroundRead`).
   - **Probe:** an 80 s SSE stream with a chunk every 2 s, through `Server()` over the socket, was forwarded whole (200, usage present) and counted `{In:700 Out:30 Observed:true}`.
4. **The adapter:** it reads `in_flight_cap` by its header as `could_not_run/executor_incomplete`, never as the upstream's 429 or `rate_limited`. It sends one request per turn and does not retry: a non-2xx reply ends the run.
5. **Regressions:**
   - **Against main:** none found.
   - **The 7 mutations:** all 7 are KILLED; "no cap" only by the timeout (L2).
   - **`TestCountsKeepTheirRequestsSequence`:** the change to 8 calls × `MaxInFlight` keeps 16 concurrent requests on distinct sequences, and the ordering half of the test is unchanged.

The probes and mutations ran in a copy under `scratch/`, which has been deleted. No process is left running.
